# 粒子、着色器与音频

> 本篇把三样「让画面与声音有反应」的手段放在一起，因为它们常常要配合着用：命中那一下是**火花加白闪
> 加震屏加声音**同时发生，缺一样就读成别的意思。
>
> 一条贯穿的约束：**像素风对这三样都有额外要求** —— 不许出半透明像素、不许非整数采样、一个采样重复
> 响就是机器味。前置是[坐标、像素与相机](./坐标像素与相机.md)。总纲在[本目录索引](./README.md)。

---

## 一、三样手段各管什么

| 手段 | 适合 | 本项目用在哪 |
| --- | --- | --- |
| **粒子** | 很多个短命的小东西 | 雨雪风沙、打击火花、尘土 |
| **着色器** | 改一个已有东西的画法 | 命中白闪、压暗、将来的染色 |
| **音频** | 声音 | 打击音、受击音、挥空音、环境音、音乐 |

判据：**要新增很多个小东西** → 粒子；**要改已有东西怎么画** → 着色器。

## 二、粒子：`GPUParticles2D`

```
Rain                (GPUParticles2D)
    ProcessMaterial = ParticleProcessMaterial   ← 粒子怎么动
    Texture         = 一张雨滴图                 ← 每个粒子长什么样
```

### 节点上那几个参数

| 属性 | 作用 |
| --- | --- |
| `Emitting` | 总开关。**按天气标识整批开关就是改它** |
| `Amount` | 同时存在多少个粒子 |
| `Lifetime` | 每个粒子活多久（秒） |
| `OneShot` | 只放一轮（爆炸、火花用它），还是一直发（雨雪用） |
| `Explosiveness` | 0 是均匀持续发，1 是一次全放出来 |
| `Randomness` | 随机程度 |
| `SpeedScale` | 整体快慢 |
| `Preprocess` | 开场时先「预跑」多少秒，免得刚进场景时雨还没铺满 |
| `LocalCoords` | 关掉的话粒子不跟着节点走（雨雪要关，火花通常要开） |
| `DrawOrder` | 粒子之间谁画在上面 |

`ParticleProcessMaterial` 里是「粒子怎么动」：发射形状、方向、扩散角、初速、重力、缩放曲线、颜色渐变。
**这些格子全是你的活**，本篇不给值。

⚠️ **`Preprocess` 对雨雪很重要。** 不设它的话进场景第一秒天上是空的，然后雨慢慢铺下来 —— 看起来像
「刚开始下雨」，而设定是「今天一整天都在下」。

⚠️ **粒子的颜色渐变很容易带出半透明。** 像素只许全透明或全不透明，所以渐变要做成阶梯而不是平滑淡出，
或者干脆让粒子突然消失。这一条只能你看。

### 天气那一套的形状

天气是**一天一种、一天之内不变、全世界共享同一种**。所以那套表现**不能按场景各存一份** —— 基地、城区、
关卡三处同一天要取到同一种。

做法是一个「天气标识 → 一套表现」的映射：每种天气声明它要开哪些粒子节点、什么参数、什么音效。形状与
作物「阶段 → 素材」那个映射同源（见[资源与内容数据](./资源与内容数据.md)）。

⚠️ **天气改不了视野。** 天气的修饰只许引用派生表里**已经有的量**，而「能见度」不在那张表里。所以
下雨可以让画面变暗、可以加粒子，但不许让敌人的视野距离变短 —— 那会让天气成为往战斗里塞新轴的后门。
这一条是设计约束，写在这里免得你做雨天效果时顺手加一层雾就以为可以改玩法。

## 三、`CanvasModulate`：给整个画面染一层色

一个 `CanvasModulate` 节点会把它所在画布层的**所有东西**乘一个颜色。用途是昼夜、天气压暗、区域氛围。

⚠️ **它是乘法。** 乘白色等于不变，乘深蓝就是整体偏蓝变暗。**乘不出「变亮」** —— 要变亮得用着色器或者
加一层。

⚠️ **别用它做半透明遮罩。** 像素画上的半透明会在屏幕上产生插值像素。压暗用不透明的乘色，不用铺一层
半透明黑。

## 四、着色器：本项目第一个（也是目前唯一一个）

### 为什么白闪必须走着色器

命中时角色整个变白那一下，**`Modulate` 做不到**：

> `Modulate` 是**乘法**，白色乘彩色贴图等于原样，精灵不会变白。

这是实测踩过的。木桩能靠换颜色变白是因为它本来就是几何图形（`Polygon2D` 的颜色就是它的全部颜色），
而精灵是一张彩色贴图。

所以本项目写了一段着色器（在 `src/World/PlayerActor.cs` 里）：

```glsl
shader_type canvas_item;

uniform bool flash = false;

void fragment()
{
    if (flash)
    {
        COLOR.rgb = vec3(1.0);
    }
}
```

三条口径值得记住：

- **只改 RGB、不动 alpha。** 像素只允许全透明或全不透明，动 alpha 会造出半透明边。
- **不闪时一个字都不写 `COLOR`** —— 于是默认采样与 `Modulate`（无敌青、奔跑黄）照旧生效，两个通道不抢。
- **着色器共享、开关各自一份**：`Shader` 是那段代码，`ShaderMaterial` 是「这段代码加这一份参数」。
  每个角色各有自己的 `ShaderMaterial`，但指着同一个 `Shader`。

### 写在代码里还是写成 `.gdshader` 文件

**判据是「里面有没有可替换的美术内容」。**

白闪那段只有三行、没有任何美术可替换，落成资源文件只是多一类要管的东西（还要管导入与纹理过滤）。
写在代码里正好落实「闪白由代码持有」那条 —— 而那条本身是有理由的：**烧进图里会让闪白时长改不了**，
而它是手感量。

反过来，如果一段着色器有你要调的参数（水面波幅、描边颜色），那它就该落成 `.gdshader` 文件并把参数
导出成 `uniform`，让你在检查器里拖。

### 像素风与着色器的一条硬约束

**不做非整数采样。** 动态水那一条就是为此定的：**取静态水面瓦片加引擎原生的逐格帧动画，不写噪声
扰动着色器** —— 扰动采样会落在非整数像素上，与最近邻过滤和整数缩放冲突，表现是水面「糊」着动。

同一条推论适用于任何「让画面轻微晃动／波动」的着色器：想要那种效果，**整像素地移动**，不要用连续
偏移。

## 五、音频：三个层次

### 节点

| 节点 | 什么时候用 |
| --- | --- |
| `AudioStreamPlayer` | **没有位置**的声音：音乐、界面音、单人视角的打击音 |
| `AudioStreamPlayer2D` | **有位置**的声音，会按距离衰减与左右声道分布 |

**本项目现在的打击音刻意用不带位置的那个。** 理由写在 `src/World/CombatAudio.cs` 里：训练房是单人侧视、
镜头跟着主角走，声源与听者基本重合，位置音剩下的只有左右声道漂移那点噪声。**同屏多敌人要区分远近时
再换。**

### 播放器上那几个参数

| 属性 | 作用 |
| --- | --- |
| `Stream` | 声音文件 |
| `VolumeDb` | 音量，单位是分贝（0 是原样，负数变小） |
| `PitchScale` | 音高倍数。**本项目拿它做抖动** |
| `Bus` | 送到哪条总线 |
| `Autoplay` | 进场景就播 |
| `MaxPolyphony` | 同一个播放器最多同时响几个 |

`AudioStreamPlayer2D` 另有 `MaxDistance`、`Attenuation`、`PanningStrength`。

### 总线：音量设置的落点

音频面板（底部那个「音频」页签）里可以建**总线**：主总线加若干子总线（音乐、音效、语音）。每条总线
可以单独调音量、加效果。

**设置界面里那几个音量滑条最终就是改总线音量**，不是改每个播放器。

### 一条实测的手感结论：一个采样重复响就是机器味

```csharp
// src/World/CombatAudio.cs：两个变体随机取一个，再加音高抖动
_hit.Stream = _hitStreams[GD.RandRange(0, HitClips.Length - 1)];
LastPitch = 1.0 + GD.RandRange(-jitter, jitter);
player.PitchScale = (float)LastPitch;
```

**两个变体加音高抖动才像打了两下**，同一个采样原样重复响听起来像程序在响。

**声音是打击感的承重件，不是装饰。** 顿帧单独存在会被读成「卡顿／延迟」—— 命中当帧必须同时有视觉爆点
与声音才读成力量。实机反馈过重击「像多延迟了一会」，那正是顿帧「裸」着的表现。

### 缺文件怎么处置：这里刻意与界面相反

```csharp
private static AudioStream? Load(string name)
{
    var path = $"{Dir}/{name}.wav";
    return ResourceLoader.Exists(path) ? GD.Load<AudioStream>(path) : null;
}
```

**缺了返回 null 而不抛。** 这与「缺素材就抛」的通用口径相反，理由是那批测试用 wav 不进发行包 ——
发行时拿到 null 是**正常情形**而不是缺陷。抛异常会让训练房在发行包里直接打不开。

**缺了就不响，顿帧、白闪与打击特效照旧。**

⚠️ **这是一个窄例外，不是通用做法。** 判据是「这个文件在发行包里本来就该不存在吗」。玩法素材缺了
要抛。

### 一类声音一个播放器的代价

现在每类声音只有一个播放器，所以连段打得快时**后一下会掐掉前一下**。占位阶段接受这个代价 —— 真要叠响
得做播放器池与叠加上限，那属于混音口径（`ART-1`），现在做等于先猜一遍。

### 暂停时要不要响

```csharp
ProcessMode = ProcessModeEnum.Always;
```

**顿帧期间战斗推进停住，但这一下的声音正是那一刻要听到的**，所以音频节点设成一直跑。

## 六、音频文件怎么导入

- **短音效用 `.wav`**：无损、解码开销小。导入设置里能设**循环点**，做环境音时要用。
- **音乐用 `.ogg`**：体积小得多。
- ⚠️ **循环设置在导入选项里，不在播放器上。** 改了要重新导入（同[编辑器与场景](./编辑器与场景.md)
  那条）。

## 七、动手练习：把命中那一下的四件套凑齐

目标是让粒子、着色器、音频、震屏在同一帧发生，并亲手看出「少一样就读成别的意思」。大约一小时。

1. **新建场景**，根节点 `Node2D` 改名 `JuiceLab`，加一个 `Sprite2D`（拖一张角色图）与一个 `Camera2D`。
2. **白闪**：给 `Sprite2D` 新建一个 `ShaderMaterial`，着色器代码照第四节那段写。先在检查器里手动把
   `flash` 勾上再取消，确认它真的会变白。
3. **先试 `Modulate`**：把 `flash` 关掉，改成把 `Modulate` 设成白色，跑一下 —— **什么都不会变**。
   这一步是重点，亲手看到这条实测。
4. **按键触发白闪**：脚本里按一个键时把着色器参数设成真，并记下截止帧号
   （`Engine.GetPhysicsFrames() + 4`），过了就设回假。跑一下，感受 4 帧的白闪。
5. **火花**：加一个 `GPUParticles2D`，`OneShot` 打开、`Amount` 给十几个、`Explosiveness` 调到 1，
   `ProcessMaterial` 里把扩散角设大。按键时调 `Restart()`。跑一下。
6. **声音**：加一个 `AudioStreamPlayer`，随便挂一个 wav，按键时 `Play()`。跑一下。
7. **震屏**：按键时给相机的 `Offset` 一个几像素的位移，几帧后归零。**注意位移要是整数世界像素。**
8. **现在逐个关掉再体验**：只有白闪没有声音、只有声音没有白闪、四样都有。**记住三者的差别** —— 这就是
   「声音是承重件」的意思。
9. **雨**：另建一个 `GPUParticles2D`，`OneShot` 关、`LocalCoords` 关、发射形状设成一条横线摆在屏幕
   上方、重力朝下。先不设 `Preprocess` 跑一次（看到天上是空的），再设成两三秒跑一次。
10. **音高抖动**：给第 6 步那个播放器加上 `PitchScale = 1 + 随机(-0.1, 0.1)`，连按十下，对比不抖动时
    的感觉。

做完你会有三个直觉：`Modulate` 为什么不行、四件套缺一样的差别、抖动对重复音的作用。

## 八、这一篇里只能你实机看／听的

- **白闪几帧。** 太短看不见，太长像闪光灯。
- **火花的量与扩散。** 太多会盖住角色，太少看不出打中了。
- **粒子有没有出半透明边。** 渐变淡出最容易出这个，放大看。
- **雨雪几种天气在画面上分不分得出来。** 这是天气那一套的主要验收项。
- **压暗压到什么程度还读得清地形。** 太暗玩家就找不到路了。
- **打击音与画面爆点是不是同一帧。** 差一两帧就会读成「延迟」。
- **连段打快时声音被掐掉碍不碍事。** 这一条决定要不要做播放器池。
- **音高抖动幅度。** 太小没效果，太大像调错了。
- **水面动起来有没有糊。** 糊了就是某处做了非整数采样。
