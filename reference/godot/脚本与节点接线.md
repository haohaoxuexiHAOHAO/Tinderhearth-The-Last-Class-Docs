# 脚本与节点接线

> 本篇写**代码与你搭的节点树在哪里接上**：脚本怎么挂、`[Export]` 有哪些写法、检查器里那些格子
> 是怎么长出来的、脚本怎么找到你搭的子节点、找不到时该怎么报错。
>
> 这是分工线本身的说明书。你不必自己写脚本，但看懂这一篇之后，检查器里每一个格子你都知道它
> 从哪来、量纲是什么、留空会发生什么。C# 语法本身查[C# 学习](../学习CSharp-Java程序员向.md)，
> 本篇不重复。总纲在[本目录索引](./README.md)。

---

## 一、脚本挂在节点上

一个脚本就是一个 C# 类，它**继承自它要挂的那个节点类型**：

```csharp
// src/World/PlayerActor.cs
using Godot;

namespace Tinderhearth.World;

public partial class PlayerActor : CharacterBody2D
{
    // ...
}
```

四条硬规矩：

1. **必须写 `partial`。** Godot 的 C# 源生成器会生成这个类的另一半（信号绑定、属性登记那些），
   两半靠 `partial` 合并。漏了它编译器会直接报错并点名。
2. **继承的类型必须与你挂它的节点类型兼容。** 把一个 `: CharacterBody2D` 的脚本挂到 `Node2D` 上，
   编辑器会拒绝。
3. **一个节点最多挂一个脚本。** 想给一个东西加两套行为，就加一个子节点。
4. **旁边那个 `.cs.uid` 文件要进 git。** 它是引擎给这个脚本发的稳定标识，场景文件靠它引用脚本
   （`scenes/training_room.tscn` 里就是 `uid://...`）。删掉它，场景与脚本的关联会断。

**本项目的落点**：碰引擎的脚本一律在 `src/` 下，命名空间跟着目录走。判定与结算那一层在 `rules/`，
它**不引用 Godot**，所以那一层的类不是节点、不能挂到任何东西上 —— 这条由编译器强制，理由在代码仓
`ARCHITECTURE.md`。

## 二、脚本什么时候被调用

按发生顺序：

| 回调 | 什么时候 | 本项目拿它做什么 |
| --- | --- | --- |
| `_EnterTree()` | 节点进入场景树时（**父先、子后**） | 很少用 |
| `_Ready()` | 这个节点与它**全部子节点**都就绪时（**子先、父后**） | 取子节点、校验导出属性、订阅事件 |
| `_PhysicsProcess(delta)` | 每个物理帧，固定 60 次每秒 | 玩法推进（运动、判定、状态机） |
| `_Process(delta)` | 每个渲染帧，次数不固定 | 纯表现（不影响判定的东西） |
| `_Input(event)` | 有输入事件时 | 不直接用，走输入门面 |
| `_Draw()` | 需要重画时（`QueueRedraw()` 触发） | 调试辅助线、缺图时的占位框 |
| `_ExitTree()` | 节点离开场景树时 | **解绑在 `_Ready` 里订阅的东西** |

三条本项目的口径：

- **玩法一律在 `_PhysicsProcess` 里推进，不在 `_Process` 里。** 物理帧是固定步长的，同样的输入
  在任何机器上走出同样的结果；渲染帧不是。时间与帧那一篇会细说。
- **订阅必须在 `_ExitTree` 里解绑，成对出现。** 漏了不报错，表现是节点已经释放、回调还在跑
  （口径在代码仓 `CONVENTIONS.md`）。
- **`_Ready` 是校验的地方。** 缺子节点、缺导出值，在这里当场抛，不要拖到用的时候。

## 三、`[Export]`：检查器里那些格子是怎么来的

给属性加一个 `[Export]`，它就出现在检查器里，**并且它的值会存进 `.tscn`**。这就是交界面。

```csharp
[Export]
public int DoorFacing { get; set; }
```

### 能导出什么

| 写法 | 检查器里长什么样 |
| --- | --- |
| `[Export] public int N { get; set; }` | 一个数字输入框 |
| `[Export(PropertyHint.Range, "0,64,1")] public int N { get; set; }` | 一根滑条，范围 0 到 64、步长 1 |
| `[Export] public Season S { get; set; }`（枚举） | 一个下拉框，选项就是枚举的取值名 |
| `[Export] public Texture2D? Icon { get; set; }` | 一个可以拖图进去的格子 |
| `[Export] public PackedScene? Enemy { get; set; }` | 一个可以拖 `.tscn` 进去的格子 |
| `[Export] public Marker2D? Spawn { get; set; }` | 一个可以从场景树里挑节点的格子 |
| `[Export] public Godot.Collections.Array<Texture2D>? Stages { get; set; }` | 一个列表，可以从文件系统一次拖多张进去 |
| `[Export] public Godot.Collections.Dictionary<string, int>? Table { get; set; }` | 一张键值表 |
| `[Export(PropertyHint.File)] public string Path { get; set; }` | 一个文件选择框 |

⚠️ **集合只能用 `Godot.Collections.Array<T>` 与 `Godot.Collections.Dictionary<K,V>`**，不能用 C# 的
`List<T>`／`Dictionary<K,V>` —— 后者不是引擎认得的类型，导不出去。C# 原生数组（`Vector2[]` 这种）
在元素类型是引擎认得的类型时可以导出。

### 分组：格子多了要分堆

```csharp
[ExportGroup("占地与门")]
[Export] public Vector2I FootprintCells { get; set; }
[Export] public int DoorFacing { get; set; }

[ExportGroup("室内")]
[Export] public Vector2I InteriorCells { get; set; }
```

`[ExportGroup]` 之后的每一个导出属性都归进那一组；用 `[ExportGroup("")]` 跳出来。组里还要再分用
`[ExportSubgroup]`。**格子超过五六个就该分组** —— 你要在里面找东西，而一长串平铺是找不动的。

### 按钮：在检查器里点一下就跑一段

```csharp
[Tool]
public partial class PlotGrid : Node2D
{
    [ExportToolButton("重画网格")]
    public Callable Redraw => Callable.From(RedrawGrid);

    private void RedrawGrid() { /* ... */ }
}
```

这会在检查器里放一个真的按钮。**要求两条**：类上必须有 `[Tool]`（因为它在编辑器里跑），属性必须
写成表达式体（`=> Callable.From(...)`，不能是带存储字段的普通属性）。这两条编译器都会报，报错码
在官方 [C# 诊断](https://docs.godotengine.org/en/4.7/tutorials/scripting/c_sharp/diagnostics/GD0110.html)
里查得到。

本项目会拿它做什么：**在编辑器里就能验一遍这个场景摆得对不对**。例如建筑摆位那几条判定，你按一下
就知道门前那格有没有被占，不用跑起来试。

## 四、「不留默认值」到底怎么落

这是本项目与通用做法差别最大的一条，值得单独一节。

**普通教程**：`[Export] public float Speed { get; set; } = 200f;` —— 给个能用的默认值，作者想改就改。

**本项目不许这么写。** 理由在 [ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md)：一个值
如果既有代码默认值、又能在场景里存，场景那份会**静默胜出**。然后画面上的表现与代码里那个数不一致，
而没有任何东西报错 —— 排查它的时间远超写一行校验的时间。

落地有两种形状，按这个值是引用类型还是数字来分。

### 引用类型：`null` 天然就是「没填」

素材、场景、节点、集合这些导出属性的默认值**本来就是 `null`**。所以「忘了填」是表达得出来的：

```csharp
[Export] public Texture2D? WitheredSprite { get; set; }

public override void _Ready()
{
    if (WitheredSprite is null)
    {
        throw new InvalidOperationException(
            $"{Name}：枯死素材没填（检查器里的「枯死素材」那一格）");
    }
}
```

**报错文案要说清是哪个节点的哪一格**，否则你在二十个实例里找不到是谁。

### 数字：没有「没填」这个取值，所以要一个非法初值加一道校验

数字类型没有 `null`，`0` 往往是合法值。做法是给一个**确定非法**的初值，再在 `_Ready` 里判：

```csharp
/// <summary>顿帧时长，单位是物理帧（60 帧每秒）。合法范围 1 到 30。</summary>
[Export] public int HitstopFrames { get; set; } = -1;
```

检查器里于是显示 `-1`，你会看到它没填。**比留一个「看起来正常」的值好**：`8` 让人以为定过了。

### 更好的形状：一组手感量打包成一个资源

一个节点要调的数往往是一组，逐个导出既难分组也难复用。把它们装进一个自定义 `Resource`，节点只导出
一个可空的引用：

```csharp
[Export] public CombatFeelAsset? Feel { get; set; }
```

这样「忘了挂」就是 `null`，一句校验搞定；而那一组数存成一个 `.tres` 文件，可以在多个角色之间复用，
也能存两份对比着试。资源怎么定义与怎么建，写在[资源与内容数据](./资源与内容数据.md)。

**这一半代理会替你写好。** 你要知道的是：**检查器里看到 `-1`、空格子或者「无」，就是在等你填**，
不是坏了；而填之前跑起来会当场抛异常并在底部输出里点名。

## 五、脚本怎么找到你搭的子节点

三种写法，本项目按下面的优先顺序选。

### 首选：`[Export]` 一个节点类型，让你在检查器里挑

```csharp
[Export] public AnimatedSprite2D? Sprite { get; set; }
```

**为什么它最好**：你在编辑器里重排层级、改名字，它都不会断 —— 引用是拖进去的，不是用路径拼的。
代价是多一个要填的格子。

### 次选：唯一名 `%`

在编辑器里右键那个节点 → 作为唯一名称访问，代码就可以：

```csharp
var sprite = GetNode<AnimatedSprite2D>("%Sprite");
```

**它对层级不敏感**（挪到哪一层都找得到），但对**名字**敏感：改名会断。适合那些名字本身就是契约的
节点。

### 末选：写路径

```csharp
var sprite = GetNode<AnimatedSprite2D>("Visual/Sprite");
```

**对层级与名字都敏感**，改任何一样都会断。只在层级确实固定时用。

### 找不到的时候必须报错说清缺谁

`GetNode<T>` 找不到会抛，但它的报错只说路径，不说「你该在哪里补一个什么」。本项目要求脚本报出
**你能照着改的信息**：

```csharp
private T Require<T>(T? node, string whatToAdd) where T : class =>
    node ?? throw new InvalidOperationException(
        $"{Name} 缺子节点：{whatToAdd}");
```

**脚本不许自己补建缺掉的节点。** 那会让「忘了摆」被静默兜底成一个位置在原点、参数全是零的东西，
而它跑得起来。

## 六、信号：节点之间怎么通知

Godot 的信号就是观察者模式，引擎内建。C# 里它长成事件：

```csharp
// 订阅引擎内建的信号
button.Pressed += OnPressed;
area.BodyEntered += OnBodyEntered;

// 在 _ExitTree 里成对解绑
button.Pressed -= OnPressed;
area.BodyEntered -= OnBodyEntered;
```

自己声明一个信号：

```csharp
[Signal]
public delegate void HarvestedEventHandler(int count);

// 发出去
EmitSignal(SignalName.Harvested, count);
```

名字有个规矩：**声明时叫 `XxxEventHandler`，用的时候叫 `Xxx`**。源生成器据此生成 `SignalName.Xxx`
这些常量，所以别拼字符串。

### 自动解绑靠不靠得住：一半靠得住，而那一半不是你要的那一半

引擎在一个对象被释放时会**自动断开与它有关的连接**。但官方文档点明了两种**不会**自动断开的情况
（[C# 信号](https://docs.godotengine.org/en/4.7/tutorials/scripting/c_sharp/c_sharp_signals.html)）：

1. 用 `+=` 接了一个**捕获了变量的 lambda**；
2. 接的是**自定义信号**（`[Signal]` 声明的那种）。

机制是 C# 的 `Delegate.Target`：不捕获变量的 lambda，它的 `Target` 就是创建它的那个对象，引擎因此
认得出该跟谁一起清；一旦捕获了变量，`Target` 变成编译器生成的那个装变量的类型，关联就断了。

**后果**：接收方节点已经释放、回调还在被调，表现是 `System.ObjectDisposedException` —— 而报错点
离真正原因（某处漏了一次 `-=`）很远。所以本项目的纪律不是「为了整齐」：

- **订阅与解绑成对出现**，订阅在 `_Ready`／`_EnterTree`，解绑在 `_ExitTree`。
- **处理器用具名方法，不用 lambda。** lambda 要解绑就得保存同一个委托实例；在 `-=` 那里临时再写一个
  外观相同的新 lambda 是**解不掉的**，而解不掉不报错。
- 自定义信号还有一条替代路：用 `Connect(X.SignalName.Y, Callable.From(...))` 而不是 `+=`，那条路
  对自定义信号会自动断开。本项目仍然选显式 `-=`，理由是「谁在听谁」要在代码里看得见。

### 另外两条

- **编辑器里也能连信号**（选中节点 → 节点面板 → 信号页签）。本项目**不走这条路**：那样的连线只
  存在于 `.tscn` 里，读代码看不出来谁在听谁。连线一律写在脚本里。
- **规则层没有信号。** `rules/` 不引用 Godot，所以那一层要往外通知时用 C# 自己的 `event`
  （例子见 `src/UI/InputRouter.cs`）。判定与结算基本不需要「过一会儿有事发生」这种形状，所以规则层
  现在一个事件都没有。

⚠️ **新加的自定义信号要构建一次编辑器才看得见**，官方文档专门提了这一条。

## 七、`[Tool]`：让脚本在编辑器里也跑

加了 `[Tool]` 的脚本在**编辑器里**就会执行 `_Ready`、`_Process` 与 `_Draw`。用途只有一个：让你在
编辑器里看得见东西，而不是跑起来才知道。

```csharp
[Tool]
public partial class DepthBandGuide : Node2D
{
    public override void _Draw()
    {
        if (!Engine.IsEditorHint())
        {
            return;   // 只在编辑器里画这条辅助线，跑起来时不画
        }
        // 画纵深带的上下边界
    }
}
```

**`Engine.IsEditorHint()` 用来区分「现在是编辑器」还是「现在是游戏」。**

⚠️ **`[Tool]` 脚本里的异常会打在编辑器上。** 写得不小心可以让编辑器卡住或刷一屏错误。所以本项目
只在**画辅助线与校验按钮**这两件事上用它，不拿它做任何会改数据的事。

⚠️ **刚加上 `[Tool]` 时，已经打开的那个场景可能不认。** 关掉那个场景页签再打开一次。

## 八、打印、报错与断言

| 写法 | 去哪 | 什么时候用 |
| --- | --- | --- |
| `GD.Print(...)` | 输出面板 | 诊断信息、启动日志 |
| `GD.PushWarning(...)` | 输出面板（黄） | 不影响继续跑的问题 |
| `GD.PushError(...)` | 输出面板（红） | 有问题但决定继续跑 |
| `throw new ...` | 调试器面板，游戏停住 | 缺配置、缺节点这类必须当场停的 |

**本项目的口径**：缺配置与缺子节点一律**抛**，不打警告继续跑。警告会被滑过去，而滑过去的后果是
画面上少一块东西、你以为是自己没摆。

排缺陷时允许临时加诊断输出让你实机复现并贴回结果，**事后要删掉**。

## 九、改了 C# 之后

- **要重新构建。** 编辑器右上角那个锤子图标是手动构建；按 `F5`／`F6` 跑之前会自动构建一次。
- **新加的 `[Export]` 属性要构建完才会出现在检查器里。** 没看到新格子，先看一眼构建过没有、
  底部有没有编译错误。
- **编译不过时场景照旧能打开**，但脚本那一半是失效的，检查器里的导出格子会消失。看到一堆格子突然
  没了，先看编译错误，别急着重摆。
- **完整验收跑 `python tools/verify.py`**（在代码仓根目录）。它把行尾、构建、测试、导出、跑产物
  串起来。日常改场景不用跑它。

## 十、节点的释放

- **`QueueFree()`** 是标准做法：这一帧结束时释放。不要在遍历子节点的循环里立刻释放。
- **资源不用手动管**：它们是引用计数的，没人用了自己就走。
- **`GodotObject.IsInstanceValid(node)`** 判一个引用还指不指着活着的对象。持有**别处**节点的引用时
  用之前判一次 —— C# 那一侧的引用还在，底下的原生对象可能已经没了，碰它会抛
  `System.ObjectDisposedException`。
- **释放会先调 `_ExitTree`**，所以解绑写在那里是安全的。

## 十一、C# 与引擎之间那道边界

这一节整节是代码侧。它解释的是一批「为什么不能那么写」的根源：**引擎内核是 C++，C# 那一侧是包在
外面的一层壳**，凡是跨过这道边界的东西都要能被引擎表示。

### `partial` 的另一半是源生成器写的

你写的那一半只有逻辑；源生成器补上的那一半做三件事：把 `[Export]` 属性登记给引擎（检查器据此画
格子、`.tscn` 据此存值）、把 `[Signal]` 变成真的信号，以及生成 `SignalName`／`PropertyName`／
`MethodName` 这几个嵌套类。

所以 `EmitSignal(SignalName.Harvested, count)` 里那个 `SignalName.Harvested` 是**生成出来的常量**，
不是字符串字面量。用它而不是拼字符串：拼错字符串不报错，写错常量名编译不过。

### `Variant`：能跨过边界的类型是有限的

引擎内部所有动态值都是一个叫 `Variant` 的东西。C# 这一侧只有**引擎认得的类型**能跨过去：

- 数字、`bool`、`string`
- 引擎自己的结构（`Vector2`、`Rect2`、`Color`、`Transform2D` 这些）
- 继承自 `GodotObject` 的类（`Node`、`Resource` 都在里面）
- `Godot.Collections.Array<T>` 与 `Godot.Collections.Dictionary<K,V>`
- 元素类型是上面这些的 C# 数组

**这一条解释了三件先前只是「规矩」的事**：导出集合为什么只能用 `Godot.Collections`；信号参数为什么
不能随便传一个自定义类（要传就让它继承 `GodotObject`）；以及为什么**规则层那些 `record struct` 不能
直接当信号参数或导出属性** —— 它们是纯 C# 类型，引擎表示不了。跨界的时候得先摊成数字。

日常写法上一条建议：**能写具体类型就别用 `Variant`**。官方文档的措辞是只在不得不对接无类型 API 时
才用它，理由是 `Variant` 的类型转换在不匹配时行为很杂（可能给一个像样但意外的值、可能给默认值、
可能给空数组、也可能抛）。

### `StringName`：名字要存成静态字段

引擎里的名字（信号名、属性名、动画名、着色器参数名）类型是 `StringName`，不是 `string`。从字符串
造一个 `StringName` 有代价，所以**会反复用到的名字存成静态字段**，别每帧现造：

```csharp
// src/World/PlayerActor.cs：着色器里那个白闪开关的名字，写一次，读写两处都引它
private static readonly StringName FlashParam = "flash";
```

### `CallDeferred`：这一帧不方便做的事推到帧末

在物理回调里增删节点、改场景树结构，引擎会警告甚至出错（它正在遍历那棵树）。做法是推迟：

```csharp
CallDeferred(Node.MethodName.AddChild, spark);
```

### `async` 在这里怎么用

引擎给了一个等信号的写法：

```csharp
await ToSignal(GetTree(), SceneTree.SignalName.ProcessFrame);
```

**本项目几乎不用它。** 两条理由：玩法推进按物理帧数，用帧号算比用 `await` 串起来的时序更好读也更好
测；而 `async void` 里抛的异常会被吞掉，表现是「这段逻辑就是不跑」，查不出来。演出脚本那种天然是
「一步一步等」的东西将来可能用到，到时候在那一篇里定。

## 十二、动手练习：做一个「缺配置就报错」的节点

目标是把 `[Export]`、取子节点、校验、报错这一条链走一遍。大约三十分钟。

1. **新建场景**，根节点 `Node2D`，改名 `Lamp`，加一个 `Sprite2D` 子节点改名 `Glow`。
2. **写一个脚本挂在 `Lamp` 上**，导出三样东西：一个 `Texture2D?`（灯的图）、一个
   `[Export(PropertyHint.Range, "1,60,1")] public int BlinkFrames { get; set; } = -1;`、
   一个 `Sprite2D?`（指向 `Glow`）。
3. **在 `_Ready` 里逐个校验**：图为 `null` 就抛、`BlinkFrames` 小于 1 就抛、`Sprite2D` 为 `null` 就抛。
   每句报错都写清是**哪个节点的哪一格**。
4. **`F6` 跑一下**。什么都没填，应该当场停在第一条校验上，底部调试器里能看到那句话。
5. **只填图，再跑**；**再填帧数，再跑**；**最后把 `Glow` 拖进那个格子**。三次报错应该分别指向三个
   不同的格子 —— 如果有一次的报错让你不知道该改哪里，那句文案就得改。
6. **把三个导出属性用 `[ExportGroup]` 分成两组**（外观／手感），构建一次，看检查器里分组的样子。
7. **加一个 `[ExportToolButton]`**，按一下在输出面板打一行「三项都填齐了」或者缺了哪一项 —— 记得
   类上要加 `[Tool]`，属性要写成 `=> Callable.From(...)`。

做完你会有两个直觉：**空格子不是坏了、是在等你填**；以及一句好的报错能省掉十分钟乱翻。

## 十三、这一篇里只能你实机看的

- **导出格子的名字读不读得懂。** 代理写完之后你打开检查器看一眼：每一格你都知道填什么、单位是
  什么吗？读不懂就说，那是文案问题、改起来很便宜。
- **留空跑一下会不会报错，报错说不说得清是哪一格。** 这一条值得专门试：故意空一格跑起来，看底部
  输出那句话能不能让你直接找到该填哪里。说不清就是缺陷。
- **分组顺不顺手。** 调一个东西要在检查器里上下滚三屏，就该重新分组。
