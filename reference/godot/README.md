## 版本基线

引擎是 Godot 4.7.2 的 .NET 版，目标框架 `net10.0`，见 [ADR-0005](../../decisions/ADR-0005-技术基线.md)。本机装了哪个版本，跑 `python tools/setup_godot.py --check` 看。

**官方文档一律查 4.7 那一版**：<https://docs.godotengine.org/en/4.7/>。网上大量答案是 4.0 到 4.2 的，节点名与属性名都变过 —— 最典型的是瓦片地图，老教程里的 `TileMap` 已经弃用，现在是 `TileMapLayer`（[类参考](https://docs.godotengine.org/en/4.7/classes/class_tilemaplayer.html)）。照老文章做而它不报错，是本项目最容易浪费时间的一类。

## 分工线：这批文档教的是你那一半

[ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md) 把工作切成两半：**代理写业务逻辑**（状态机、判定与结算、数据加载、把节点接到规则上的胶水代码），**作者管场景与节点树、碰撞区域、素材裁切与导入、动画帧、检查器里的参数值、摆位**。交界面是 `[Export]` 属性与 `Resource`：代理定义并写清每一项是什么、量纲、合法范围，你填值。

所以每篇文档里有两种段落，都标着：

- **你要做的**：在编辑器里点哪里、填什么、填错了画面上会怎样。
- **代理会写成什么样**：好让你知道那个导出格子是从哪来的、为什么长这样。

**搭游戏框架那一阶段有一个例外：灰盒场景先由代理搭。** 代理照这批文档里写的节点名搭好、标明是临时的，好让玩法先跑起来；美术画好之后你照自己的眼光重搭，节点名照旧，脚本报错时点的名才对得上。文档照旧写全，重搭时照着做。哪几件算这一阶段：基地里检查器 Editor Description 那一格写着「灰盒」的那几个节点，与[待办台账](../../spec/issues/README.md)里 `GP-175` 起依次卡着的那几行。

## 贯穿全部文档的口径

1. **`[Export]` 不许留能用的默认值。** 缺配置当场报错。一个值如果既有代码默认值、又能在场景里存，场景那份会**静默胜出**（ADR-0009）。
2. **内容定义走数据文件，不走 `Resource`。** 作物、物品、技能、敌人这类「一张表」的东西落 `res://data/` 下的 JSON（[ADR-0022](../../decisions/ADR-0022-内容清单的家是数据文件.md)）。`[Export]` 只用在场景几何与素材那一层。
3. **脚本不自己建场景树。** 脚本挂在你建好的节点上；缺子节点就报错说清缺谁，不自己补建。
4. **游戏内时间不靠 `Timer` 节点表达。** 按天的事挂在每日结算那串固定步序上；打开界面时世界暂停，由导航栈整体决定。

## 两条边界写在最前面

**代码现状分两半。** 经营那一侧已经是目标形状：`src/World/Base/` 下那几个脚本就是「你搭树、脚本读 `[Export]`」，跟着上面三篇跟着做的走就是。战斗那一侧还是撤掉的侧视即时战斗那一套代码，没有哪个场景用它，等俯视格子回合制开工时重写（[ADR-0035](../../decisions/ADR-0035-战斗改成俯视的格子回合制.md)）。所以工程里只有基地这一个场景（`res://scenes/base/base.tscn`），看不到战斗场景 —— 那不是你装错了。

**表现与手感没有机器判据。** 图形探针那一套已随 ADR-0009 删除，所以动画切得顺不顺、读条被取消那一下看不看得出来，全靠你实机看。每篇末尾都有一节写**该看什么**，不写怎么调。
