# 随机与种子

> 本篇回答：**随机数该从哪里来**、**为什么「同一个种子必须拼出同一张图」是一条硬约束**、**什么时候
> 存种子、什么时候存结果**。
>
> 这一篇作者几乎没有活（随机全在规则层），但它有一条**很容易踩进去的坑**：随手用引擎的全局随机会让
> 关卡拼装不可复现，而那**不报错** —— 它只表现为「续玩之后地图变了」。前置是
> [时间与帧推进](./时间与帧推进.md)。总纲在[本目录索引](./README.md)。

---

## 一、两种随机源，别混用

| 来源 | 写法 | 特点 |
| --- | --- | --- |
| **全局随机** | `GD.Randi()`、`GD.RandRange(a, b)` | 全项目共用一条序列，谁都能抽 |
| **自己持有一个** | `new RandomNumberGenerator()`，设种子 | 序列独立，给它同一个种子就走出同一串数 |

**判据只有一句**：**这次随机的结果需要能复现吗？**

- **不需要** → 全局随机够用。音高抖动、粒子扰动、待机动画的微小差异都属于这一类。
- **需要** → 必须自己持有一个带显式种子的生成器。关卡拼装、天气抽取、装备副词条掷定都属于这一类。

## 二、全局随机：只用在表现

```csharp
// src/World/CombatAudio.cs：音高抖动，抖成什么样不需要复现
LastPitch = 1.0 + GD.RandRange(-jitter, jitter);
```

⚠️ **`Array.Shuffle()` 与 `Array.PickRandom()` 用的是全局随机。** 这两个方法很顺手，所以很容易在需要
复现的地方随手用上 —— 而用了之后那段逻辑就再也不可复现了。**要复现的地方自己写洗牌**（见第八节）。

## 三、自己持有一个：种子与状态

```csharp
var rng = new RandomNumberGenerator();
rng.Seed = someSeed;          // 同一个种子 → 同一串数

int i = rng.RandiRange(0, 9);        // 整数，两端都含
float f = rng.RandfRange(-1f, 1f);   // 浮点，两端都含
float u = rng.Randf();               // 0 到 1
float g = rng.Randfn(mean, dev);     // 正态分布
int idx = rng.RandWeighted(weights); // 按权重抽一个下标，见第七节
rng.Randomize();                     // 按时间取一个种子（要复现时不能用）
```

两条官方文档点明的坑：

⚠️ **设 `Seed` 会顺带改内部状态**，所以要**先设种子再设状态**，顺序反了会把恢复出来的状态又覆盖掉。

⚠️ **这个生成器没有雪崩效应** —— 相似的种子会走出相似的序列。官方建议：**种子来自外部时先过一次
哈希。**

**这一条对本项目很具体**：如果关卡种子是「第几天加第几关」这种连续数，相邻两天的关卡会长得很像，而
你只会觉得「怎么老是这几块片段」。先哈希一次就没事了。

### 状态能存能恢复

`State` 属性可以读出来存下来、之后再写回去，让生成器回到那一刻。**用途是「抽了一半要存档」** ——
但本项目基本不需要它，理由见第六节。

## 四、一条架构边界：规则层用不了引擎的随机

`RandomNumberGenerator` 是一个 Godot 类，而**规则层不引用 Godot**（编译器强制）。所以**拼装逻辑、
天气抽取、词条掷定这些都不能用它** —— 它们全在规则层。

规则层的选项是 .NET 自带的随机（`new Random(seed)`，同一个种子可复现），或者**自己写一个几行的
生成器**。

**如果「同一个种子拼出同一张图」要跨引擎与运行时版本都成立，自己写那个更稳**：引擎文档明确写着
「底层算法是实现细节，不应被依赖」，也就是说引擎升级之后同一个种子可能走出另一串数。自己写的那几行
由本仓的代码决定行为，升级引擎不影响它。

⚠️ **这一段是推断，没有实测。** 真要确认「换个引擎版本同一个种子还拼同一张图吗」，办法是升级前后各
跑一次拼装并比对结果。落地时该不该自己写生成器，那一刻再定。

## 五、「同一个种子必须拼出同一张图」

这是关卡系统的承重约束。它要求**拼装是一个纯函数**：输入只有种子与片段清单，输出是那一串片段。

**所以拼装规则不许读任何会变的外部状态。** 点名禁止的有这些：

- **当前时刻**（真实时间或游戏内时间）
- **引擎的全局随机**
- **玩家当前位置**
- **事件触发记账**（哪些事件已经触发过）

⚠️ **「抽」与「判」是两个时点。** 关卡里会出现哪些事件**在拼装那一刻由种子定下来**，关卡内不再抽 ——
否则「同一个种子拼出同一张图」会被静默绕掉（图一样、事件不一样）。

⚠️ **拼装读不到记账。** 这是上一条的直接推论：如果拼装要问「这个事件触发过没有」，它就读了会变的状态。

**这条约束的反证形式是**：拿同一个种子拼两次，结果逐项相同。那是一条写得出来的单元测试。

## 六、存结果，不存种子

这一条与直觉相反，所以写清理由。

**天气**：今天与明天各是什么天气，**存的是结果**（「今天是雨」），不是「种子加第几次抽取」。

**装备副词条**：实例产生那一刻掷定，此后不变，**存的是掷出来的那几条**，不是种子。

**为什么**：抽法将来会改（权重调整、加一种天气、加一条词条）。**存种子的话，改了抽法之后所有旧存档
里的结果都会静默变成另一个样子** —— 玩家昨天看到的预报是雨，今天读档变成晴，而这不报错。存结果则
是「过去发生的事就是发生了」。

**关卡种子是例外，它确实要存** —— 因为玩家可能在关卡中途退出续玩，而那一关的地图必须还是同一张。
但注意它存的是**关卡进度那一片**（进临时续玩点），不是正式存档；一关打完它就没用了。

## 七、按权重抽取

天气按季节权重抽、事件按权重抽、掉落按权重抽 —— 这是本项目最常见的随机形状。

引擎给了一个现成的：

```csharp
// 权重数组：越大越容易被抽到，0 表示永远不会
var weights = new float[] { 0.5f, 1f, 1f, 2f };
int index = rng.RandWeighted(weights);   // 返回下标
```

⚠️ **空数组时它打印一个错误并返回 −1。** 所以调用方要么保证非空，要么判返回值 —— 拿 −1 去索引数组会
抛一个跟真正原因无关的异常。

**规则层用不了它**（第四节那条边界），所以规则层要自己写一个：累加权重、抽一个 0 到总和之间的数、
找它落在哪一段。那是五六行代码，而且能被单元测试盯住。

## 八、要复现的洗牌自己写

洗牌的标准做法（Fisher–Yates）是：从最后一项往前，每次与前面随机一项交换。

关键是**那个「随机一项」必须来自你自己持有的生成器**，而不是全局随机。引擎数组自带的洗牌方法用的是
全局随机，所以它在需要复现的地方用不了。

## 九、随机在本项目里都用在哪

| 场合 | 要复现吗 | 存什么 |
| --- | --- | --- |
| 关卡拼装（片段顺序、关卡事件） | **要** | 种子进临时续玩点 |
| 天气抽取 | 不要（抽完就定了） | **结果**进正式存档 |
| 装备副词条掷定 | 不要 | **结果**跟着那件实例 |
| 考试成绩的小幅浮动 | 不要 | 结果 |
| 品质分布 | 不要 | 结果跟着那一件 |
| 音高抖动、粒子 | 不要 | 不存 |

**一条规律**：**要复现的只有关卡拼装那一处**，其余全是「抽完就定了、存结果」。所以「自己持有一个带
种子的生成器」这件事在本项目里只有一个使用者。

## 十、动手练习：让同一个种子走出同一串数

目标是把两种随机源的差别、种子质量、可复现性走一遍。大约三十分钟。

1. **新建场景**，根节点 `Node` 改名 `RngLab`，挂脚本。
2. **全局随机**：在 `_Ready` 里打印十个 `GD.RandRange(0, 9)`。跑两次 —— 两次结果不一样。
3. **自己持有一个**：`new RandomNumberGenerator()`，把 `Seed` 设成 `12345`，打印十个
   `RandiRange(0, 9)`。跑两次 —— **两次结果应该完全一样**。这是这个练习的地基。
4. **换种子**：把种子改成 `12346`（只差 1），跑一次，把两串数并排看 —— 你会发现它们**很像**。这就是
   「没有雪崩效应」。
5. **先哈希再用**：把种子改成 `"关卡-1".GetHashCode()` 之类哈希出来的值，再试相邻的两个输入
   （`"关卡-1"` 与 `"关卡-2"`），对比两串数 —— 这回应该完全不像了。
6. **状态存取**：抽五个数，把 `State` 存下来；再抽五个；把 `State` 写回去，再抽五个 —— 后五个应该与
   第二组一模一样。
7. **按权重抽**：用 `RandWeighted(new float[] { 1, 1, 1, 10 })` 抽一百次，数一下每个下标出现多少次，
   确认最后那个大约是别人的十倍。
8. **空数组**：给 `RandWeighted` 传一个空数组，看它打错误并返回 −1。**记住这个返回值。**
9. **纯函数练习**：写一个方法 `拼一串(int 种子)`，用自己持有的生成器从一个固定列表里挑五项返回。
   调它两次（同一个种子），断言两次结果逐项相同。然后**故意在里面加一句
   `GD.Randi()` 参与决策** —— 再断言一次，这回会失败。**这一步就是「拼装是纯函数」那条约束的样子。**

做完你会有三个直觉：种子决定序列、相似种子不够用、混进全局随机就不可复现了。

## 十一、这一篇里只能你实机看的

- **同一个种子拼出来的地图真的一样吗。** 进关卡记下片段顺序，退出续玩再看一次。
- **不同种子拼出来的地图够不够不一样。** 连开五关，如果老是那几块片段，可能是种子质量问题（第四节
  那条）。
- **天气看起来随机吗。** 连开十天，如果连续五天都是雨，那是权重问题而不是缺陷 —— 但那个感觉只有你玩
  得出来。
- **词条掷出来的差距合不合理。** 单条副词条的波动不得大到跨出一个品质级差，这是设计约束；但「拿到一件
  装备时有没有惊喜」只能玩出来。
