# 物理与碰撞

> 本篇回答：**哪个物理体用在哪**、**碰撞形状怎么摆**、**层与掩码那一排勾选框到底在说什么**、
> 以及本项目最特殊的一处 —— **命中判定不靠引擎的区域重叠信号**。
>
> 侧视战斗有三个轴，而 Godot 2D 只有两个，所以这一篇有几段是别处查不到的。前置是
> [坐标、像素与相机](./坐标像素与相机.md)。总纲在[本目录索引](./README.md)。

---

## 一、四种物理体先分清

| 节点 | 谁推动它 | 它挡不挡别人 | 用在哪 |
| --- | --- | --- | --- |
| **`StaticBody2D`** | 不动 | 挡 | 地形、墙、木桩、场景障碍物 |
| **`CharacterBody2D`** | **你的代码**（设速度再调 `MoveAndSlide`） | 挡 | 角色、敌人 |
| **`RigidBody2D`** | 物理引擎（受力与重力） | 挡 | **本项目不用** |
| **`Area2D`** | 不动或跟着父节点 | **不挡**，只知道谁进来了 | 判定框、受击框、交互点、触发区 |

另有一个 `AnimatableBody2D`，是「会动但不受物理影响」的静态体，适合移动平台。本项目现在没有。

**为什么不用 `RigidBody2D`**：动作游戏要的是「按住方向就以这个速度走」，而刚体给的是「施加一个力
之后它自己算」。后者的手感调不出来 —— 想让角色立刻停下就得跟摩擦力与质量搏斗。`CharacterBody2D`
把位置控制权交回代码，这正是本项目要的。

## 二、形状是子节点，不是属性

物理体自己没有形状，形状挂在它下面：

```
Player            (CharacterBody2D)
└── Body          (CollisionShape2D)  ← 这里才有形状
        Shape = RectangleShape2D (Size = 18 × 28)
```

所以有两层：**`CollisionShape2D` 是节点**（有位置，可以偏移），**`Shape` 是资源**（只有尺寸）。

常用形状：`RectangleShape2D`（`Size`）、`CircleShape2D`（`Radius`）、`CapsuleShape2D`（胶囊）。
像素游戏基本只用矩形与圆。

⚠️ **形状资源是共享的。** 两个 `CollisionShape2D` 指着同一个 `RectangleShape2D`，改一个会改到两个。
要单独改先「使其唯一」（同[资源与内容数据](./资源与内容数据.md)那条）。

### 本项目的两个框，尺寸各有出处

| 框 | 尺寸从哪来 | 落点 |
| --- | --- | --- |
| **实体碰撞框** | 贴角色实测轮廓（主角站立姿 18×28 世界像素），底边落在节点原点 | `src/World/PlayerActor.cs` |
| **受击框** | **按角色各给一个**，取该角色自己的实测本体高度 | `src/World/Hurtbox.cs` |

**受击框那条「按角色各给」有一段来历值得记住。** 它曾经写死 32，而 32 是**木桩柱子**的高度，主角
实测本体只有 28。于是同一个仓里对「主角多高」有两份真相，受击框那份高出 4 像素 —— 表现是从头顶
一到四像素掠过的攻击照样判命中，玩家读到「我明明躲过了却被打到」，而这**不报错**。现在它写成必填
属性，新角色接进来时编译器逼着回答「它多高」。

**逐帧自适应刻意不做**：整帧不透明边界含四肢，高度会在 26 到 30 之间脉动，而受击框脉动会让命中
学不会 —— 同一招有时中有时不中且读不出原因。按**状态**分（站立／滞空／闪避）才是常规做法，归
`GP-18` 与 `GP-6`。

## 三、层与掩码：那一排勾选框在说什么

每个碰撞体有两组勾选框，读法是：

- **层（Layer）**：**「我是谁」** —— 我出现在哪几层里。
- **掩码（Mask）**：**「我看谁」** —— 我会跟哪几层发生碰撞。

**A 撞得到 B，条件是 A 的掩码里有 B 的层。** 注意这是**单向**的：A 看得见 B 不等于 B 看得见 A。
`CharacterBody2D` 的 `MoveAndSlide` 只看**自己的掩码**，所以「角色会被木桩挡住」取决于角色的掩码里
有没有木桩那一层，而不是木桩的掩码。

### 检查器里是勾选框，代码里是位

检查器里那一排勾了第几格，代码里就是第几位：

| 勾第几格 | 代码里的值 |
| --- | --- |
| 第 1 格 | 1 |
| 第 2 格 | 2 |
| 第 3 格 | 4 |
| 第 4 格 | 8 |

所以 `CollisionLayer = 4` 是「第 3 格」，不是「第 4 层」。**这一点很容易看错**，看代码时留意。

**建议在项目设置里给层起名**（项目设置 → 层名称 → 2D 物理）。起了名之后检查器里那一排勾选框会
显示名字而不是编号，配错的概率明显下降。本项目还没起名 —— 这是一件你可以顺手做掉的事。

### 本项目现在的层分配

| 值 | 装什么 | 备注 |
| --- | --- | --- |
| 1 | 地形**与角色**（两者混用同一层） | 混用有代价，见下 |
| 2 | 受击框（`src/World/Hurtbox.cs`） | 与实体层分开，所以打不到的东西也能被打 |
| 4 | 木桩与场景障碍物（`src/World/SceneObstacle.cs`） | |

⚠️ **层 1 混用地形与角色，这是一个已知的账。** 影子那条向下的射线取 `Mask = 1`，于是一个角色跳过
另一个角色时射线先打到对方顶面、把它当地面 —— 影子跳到对方头顶，**不报错**。修法是给地形一个专属层
并收窄射线掩码，记在 `ENG-19`。**你在编辑器里配层时知道这件事就够了，别顺手改** —— 改它要动木桩那条
「击退被主角挡住」的碰撞关系。

## 四、`MoveAndSlide` 与 `CharacterBody2D` 的参数

用法就三步：**设速度 → 调一次 `MoveAndSlide()` → 问它撞到了什么。**

```csharp
// src/World/PlayerActor.cs
Velocity = new Vector2((float)Combat.Motor.HorizontalVelocity, (float)Combat.Motor.VerticalVelocity);
MoveAndSlide();
Combat.AfterMove(IsOnFloor(), IsOnCeiling(), IsOnWall(), Velocity.X);
```

**`Velocity` 的单位是像素每秒**，不是「每帧走多少」。`MoveAndSlide` 内部按帧时长换算。

检查器里那些参数（完整列表查
[类参考](https://docs.godotengine.org/en/4.7/classes/class_characterbody2d.html)）：

| 属性 | 默认 | 作用 | 本项目 |
| --- | --- | --- | --- |
| `MotionMode` | 接地 | **接地**模式有地板墙壁天花板的概念；**浮空**模式没有，一切碰撞都报成撞墙 | 侧视用接地；**俯视应当用浮空** |
| `UpDirection` | `(0, -1)` | 哪个方向算「上」，决定什么算地板 | 侧视用默认 |
| `FloorMaxAngle` | 45 度 | 斜坡超过这个角度就算墙而不是地板 | 默认 |
| `FloorSnapLength` | 1 | 贴着下坡走的吸附距离。为 0 时走下坡会一跳一跳 | 有斜坡时要调 |
| `FloorStopOnSlope` | 开 | 站在斜坡上静止时不下滑 | 开 |
| `FloorBlockOnWall` | 开 | 不许沿着墙往上走 | 开 |
| `FloorConstantSpeed` | 关 | 开了之后上下坡速度一致 | 关（有斜坡时再看） |
| `MaxSlides` | 4 | 一帧里最多改几次方向 | 默认 |
| `SafeMargin` | 0.08 | 碰撞的安全余量 | 默认 |
| `SlideOnCeiling` | 开 | 撞天花板时滑开 | 默认 |

**俯视场景记得把 `MotionMode` 改成浮空。** 接地模式会让俯视角色把「往上走」当成跳、把地形当地板，
表现是移动卡顿而不报错。

调用之后能问这些：`IsOnFloor()` / `IsOnWall()` / `IsOnCeiling()`（以及 `...Only()` 三个变体）、
`GetFloorNormal()`、`GetRealVelocity()`（**实际**走出来的速度，撞墙后与 `Velocity` 不同）、
`GetSlideCollisionCount()` 与 `GetLastSlideCollision()`。

## 五、`Area2D`：两种用法，本项目各用在不同地方

`Area2D` 不挡任何东西，它只回答「有没有人在我里面」。两种问法：

### 用法甲：等信号（被动）

```csharp
area.BodyEntered += OnBodyEntered;     // 有物理体进来
area.AreaEntered += OnAreaEntered;     // 有另一个 Area 进来
area.BodyExited  += OnBodyExited;
```

要开 `Monitoring`（我要知道谁进来了）；被别人监测到要开 `Monitorable`。

**适合什么**：交互点、触发区、门口 —— 那些「走进去就该发生一件事」的东西。交互点那一篇会细说。

### 用法乙：主动查一次（本项目的命中判定）

```csharp
// src/World/Hitbox.cs
var query = new PhysicsShapeQueryParameters2D
{
    Shape = _shape, Transform = GlobalTransform, CollisionMask = Hurtbox.Layer,
    CollideWithAreas = true, CollideWithBodies = false,
};
foreach (var item in GetWorld2D().DirectSpaceState.IntersectShape(query))
{
    // ...
}
```

**为什么命中不用信号**：`Area2D` 的重叠状态是**上一帧的缓存**，引擎在物理步之后才更新。而判定框只在
攻击的「命中窗」那几帧开着 —— 用缓存会晚一帧，表现是明明打空了却判中、或者贴着边缘时时中时不中。
主动形状查询问的是**这一帧此刻**的真实重叠。

**判定框节点本身的层与掩码都设成 0、监测也关掉**，因为它不靠引擎的重叠机制工作，只借用它的形状。

## 六、命中要两个条件：横向查询加纵深容差

这一节是本项目与任何通用教程都不同的地方。

侧视战斗有三个轴：**横向**、**跳跃高度**、**纵深**（往屏幕里走的那个方向）。而 Godot 2D 只有两个轴，
已经被前两个占满了 —— **纵深在引擎那边没有位置量，也没有碰撞体**。

所以形状查询压根看不见纵深。命中判定因此分两步：

1. **横向那一半**：形状查询拿到候选（它只覆盖横向与跳跃高度）。
2. **纵深那一半**：在规则层再筛一遍双方的纵深差（`rules/Combat/DepthOverlap.cs`）。

两个条件都成立才算命中。代码里这件事只有一处（`src/World/Hitbox.cs` 里那个 `Connects`），而且两边
的纵深都经同一个接口取 —— 参数类型写成接口，本类就**没有第二份纵深可用**，想另存一份得先改签名。

**去重排在纵深判定之后**：打空不是打过。反过来做的话，同一次挥击里先错开一排、再挪回同一排就永远
打不中了 —— 而横向那一半本来就是这个口径（框外的候选压根不会出现在查询结果里）。

## 七、阻挡：用纵深去门控引擎碰撞

命中要的是一个是非答案，阻挡要的是**位置真的被挡住**。而算这件事（贴着走、沿墙滑、脱插）是
`MoveAndSlide` 的活，规则层重写一遍就是第二份事实。

所以阻挡走反方向：**让引擎照常做碰撞，由纵深决定哪些对参与。**

### 为什么是「碰撞豁免」而不是层与掩码

层与掩码是按**类**开关的，表达不了「这一对挡、那一对不挡」，更表达不了纵深。**碰撞豁免是 Godot 里
唯一按对生效的开关**，所以纵深门控只能落在它上面：

```csharp
// src/World/DepthBlocker.cs
a.AddCollisionExceptionWith(b);
b.AddCollisionExceptionWith(a);
// 反过来
a.RemoveCollisionExceptionWith(b);
b.RemoveCollisionExceptionWith(a);
```

⚠️ **两个方向都加。** 引擎那边是不是对称本项目没有实测依据，加两次的代价是一次哈希查找。

### 两条实测结论，都只体现在画面上

**一、逐帧增删豁免是稳的。** 专门量过：静止 60 帧零切换，纵深跨过阈值时那一对恰好切换一次。

**二、阻挡是「不许走进去」，不是「把已经在里面的推出去」。** 两具身体已经横向叠着时才让阻挡生效，
Godot 的脱插是**一帧到位**的 —— 实测单帧位移 17.77 像素（约等于整个本体宽 18 像素），而且两具都在
`MoveAndSlide` 的角色此后还会锁步一起漂。所以代码里有一条迟滞：**已经横向重叠着就先不挡，等分开了
再挡**，改完实测单帧位移 0.00 像素。

### 纵深那一半引擎帮不上忙

上面那套只是**横向**那一半。纵深上没有碰撞体，`MoveAndSlide` 物理上拦不住纵深移动。

**漏了这一半的后果是实机撞到的**：左右走过去被挡住，改用上下方向键在纵深上走进去却直接穿过 —— 于是
「绕行」形同虚设。所以纵深那一半要自己夹：把在纵深上挤进来的一方夹在阈值边界上。三条约束值得记住，
因为它们各挡一种过紧或过松的实现：

- **只对横向重叠的对生效。** 正好贴住时纵深必须自由，否则玩家走到物件跟前就再也挪不动纵深 —— 而那
  恰恰是「绕行」要用的那一步。
- **只拦往里、不拦往外。** 否则会把已经在里面的角色永久关住。
- **夹的是边界，不是「上一帧位置加位移」**，所以某一帧位移再大也不会穿到另一侧。

**阻挡由场景显式装配，不是所有实体自动带上。** 谁该挡谁是场景的事，所以这件事按
[ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md) 归你在编辑器里配。

## 八、射线：能用，但视野遮挡刻意不用它

`RayCast2D` 是一条射线，问「沿这个方向第一个撞到的是什么」。本项目现在只有一处用它：影子往下探地面。

**视野遮挡刻意不走射线**，改成读你在片段里摆的**声明式遮挡区域**。三条理由：

- **射线取错层不报错。** 影子那条射线就撞上了（第三节那个 `ENG-19`）：层 1 既是地形也是角色，于是
  一个角色被当成地面。
- **带纵深之后要在三个轴上判**，而射线只认两个。
- **声明式区域在编辑器里看得见哪里能躲**，射线看不见。

所以感知那一篇（还没写）教的是怎么摆遮挡区域，不是怎么打射线。

## 九、看得见碰撞形状：调试怎么开

- **编辑器里**：碰撞形状默认就画出来（那些青色的框）。看不见就检查节点有没有被隐藏。
- **跑起来之后**：菜单 → 调试 → **可见碰撞形状**，跑起来时也画出来。**排查「明明该挡住却穿过去」时
  先开这个。**
- **判定框与受击框**：本项目自己有一个调试叠层（`ENG-6` 交的），它读的是与命中查询**同一份**形状，
  所以画出来的框就是命中真正用的那个，不会各算一份而漂移。配合帧步进能逐帧看。

## 十、动手练习：让一个角色被挡住

目标是把物理体、形状、层与掩码走一遍，并亲手制造一次「配错了但不报错」。大约四十分钟。

1. **新建场景**，根节点 `Node2D`。加一个 `CharacterBody2D` 改名 `Walker`，给它一个
   `CollisionShape2D` 子节点，形状 `RectangleShape2D`、尺寸 18×28。
2. **加一个 `StaticBody2D`** 改名 `Wall`，同样给它一个矩形形状，摆在 `Walker` 右边一点。
3. **写脚本挂在 `Walker` 上**：在 `_PhysicsProcess` 里读左右方向，设 `Velocity.X`，调 `MoveAndSlide()`。
4. **`F6` 跑一下**，往右走 —— 应该被挡住。
5. **把 `Walker` 的掩码清空**（一格都不勾），再跑 —— 它会穿过墙，**而且什么都不报**。这就是层与掩码
   配错的样子。勾回第 1 格。
6. **打开调试 → 可见碰撞形状**再跑一次，看那两个框。
7. **把 `Wall` 挪到只与 `Walker` 差一像素的位置**，跑起来贴上去 —— 观察有没有抖动。这是 `SafeMargin`
   在起作用。
8. **加一个地面**（另一个 `StaticBody2D`，横着的长条），给 `Walker` 加重力（每帧给 `Velocity.Y` 加一点），
   跑起来落到地面上，打印 `IsOnFloor()` 确认它变成真。
9. **把地面做成 15 度的斜坡**（旋转那个形状），再跑：先用默认参数，然后把 `FloorSnapLength` 设成 0，
   对比走下坡时是不是变成一跳一跳的。
10. **加一个 `Area2D`** 罩在墙前面，接 `BodyEntered` 打一行字。跑起来走进去，确认它只报告、不阻挡。

做完你会有三个直觉：掩码配错是静默的、`MoveAndSlide` 与地板判定怎么配合、`Area2D` 与物理体的分工。

## 十一、这一篇里只能你实机看的

- **该挡住的有没有挡住。** 四个方向各走一次。侧视记得**也用上下键在纵深上走进去试** —— 那一半引擎
  帮不上忙，是最容易漏的。
- **贴着墙走有没有抖。** 抖了看形状有没有落在半像素上。
- **绕行走得通吗。** 走到物件跟前，在纵深上挪开，再往前走 —— 这条路必须是通的，否则阻挡写得过紧了。
- **命中容差与阻挡阈值合不合手。** 两个数各自可调，但有一条不变量：**阻挡阈值不得大于命中容差** ——
  反过来会出现「被挡住却打不着」，玩家贴着一个够不到的东西、读不出原因。
- **判定框与画面对不对齐。** 打开帧步进与调试叠层逐帧看，拳脚伸到最远那一帧框应该开着。
- **受击框高度对不对。** 从头顶掠过的攻击不该判中。这一条曾经错过，而它不报错。
