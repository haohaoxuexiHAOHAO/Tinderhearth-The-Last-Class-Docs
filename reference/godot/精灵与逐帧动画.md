# 精灵与逐帧动画

> 本篇回答：**一张横排的帧图怎么变成能播的动画**、**谁决定现在显示第几帧**、**朝向怎么处理**。
>
> 最要紧的一条与通用教程相反：本项目**攻击与闪避的帧不由引擎的播放时钟决定**，由规则层的相位
> 决定。理由与做法在第五节。前置是[编辑器与场景](./编辑器与场景.md)与
> [坐标、像素与相机](./坐标像素与相机.md)。总纲在[本目录索引](./README.md)。

---

## 一、三个节点先分清

| 节点 | 是什么 | 本项目用在哪 |
| --- | --- | --- |
| **`Sprite2D`** | 画一张静态图。也能把一张图切成网格只画其中一格 | 静态物件、图标、掉落物 |
| **`AnimatedSprite2D`** | 拿一份 `SpriteFrames` 播逐帧动画 | 角色、敌人、打击火花 |
| **`AnimationPlayer`** | 一条时间轴，能动**任意属性**（位置、颜色、缩放、调用方法） | 演出、界面动效 |

判据：只是「一串图轮着放」→ `AnimatedSprite2D`；要同时动别的东西（位移、透明度、触发一个调用）
→ `AnimationPlayer`。两者可以并用：`AnimationPlayer` 里也能写「切到 `AnimatedSprite2D` 的哪个动画」。

**本项目角色一律用 `AnimatedSprite2D`**，因为角色的动作切换由状态机决定，而不是由一条预排好的时间
轴决定。`AnimationPlayer` 留给演出与界面。

## 二、`SpriteFrames`：动画帧的那份表

`AnimatedSprite2D` 自己不存图，它指着一份 `SpriteFrames` 资源。那份表的结构是：

```
SpriteFrames
├── "idle"   ← 一个动画名
│   ├── 第 0 帧（一张 Texture2D，各自可带时长倍数）
│   ├── 第 1 帧
│   └── ...
├── "walk"
└── "light"
```

所以一个角色的全部动作**装在同一份 `SpriteFrames` 里**，切动作就是改 `Animation` 那个属性。

### 在编辑器里建（你要做的）

选中 `AnimatedSprite2D` → 检查器里 `Sprite Frames` 那一格点「新建 SpriteFrames」→ **底部会弹出
「SpriteFrames」面板**，在那里：

1. 左边那一列是动画名，加一个、改名、设**循环**与**帧率（FPS）**。
2. 中间工具栏里那个「从精灵表添加帧」，选一张横排图，填**横向几格、纵向几格**，它会自动切开。
3. 切开后可以逐帧调顺序、删帧、给某一帧单独设时长倍数。

⚠️ **切图时填的是格数，不是像素。** 一张 44 像素宽一帧、共 6 帧的横排图，要填「水平 6、垂直 1」。
填错了不报错，只是每帧都歪一点 —— 预览窗里一眼看得出来。

### 在代码里建（代理会写的）

`src/World/PlayerActor.cs` 现在是这么做的：读一张横排图，按帧宽切成若干 `AtlasTexture` 挂进
`SpriteFrames`。

```csharp
var texture = GD.Load<Texture2D>($"{SheetDir}/{name}.png");
var count = texture.GetWidth() / FrameWidth;
Sprite.SpriteFrames.AddAnimation(name);
for (var frame = 0; frame < count; frame++)
{
    Sprite.SpriteFrames.AddFrame(name, new AtlasTexture
    {
        Atlas = texture,
        Region = new Rect2(frame * FrameWidth, 0, FrameWidth, FrameHeight),
    });
}
```

**`AtlasTexture` 是「一张大图里的一块矩形」**，所以切帧不产生新纹理、不额外占显存。

**这段代码将来会被你在编辑器里建的 `SpriteFrames` 取代**（`ENG-21` 那条）。留在这里是因为它解释了
「一张横排图 + 帧宽」这个模型 —— 编辑器里那个切图对话框做的是同一件事。

### 帧宽帧高按角色各自声明，不是全项目一个常量

现在代码里的帧宽帧高是主角那一套的常量，**并且有一条载入时的一致性校验**：按纹理实测尺寸核（高必须
等于帧高、宽必须是帧宽的整数倍），对不上就当缺图走占位分支并打日志。所以「表重新生成后帧框变了而
代码没跟着改」不会静默错位。

⚠️ **这条校验管得住宽高，管不住帧内地面行。** 地面行只影响精灵往上抬多少，改错一像素的表现是
「脚底离地」或「陷进地面」，而纹理尺寸照样对得上、日志照样干净。**它只能你实机看。**

按角色各带一份帧框的目标形状归 `ENG-24`。

## 三、`AnimatedSprite2D` 参数逐条

| 属性 | 作用 | 本项目怎么用 |
| --- | --- | --- |
| `SpriteFrames` | 指着那份帧表 | 你在编辑器里建 |
| `Animation` | 当前播哪个动画。**改它会把帧号与帧内进度归零** | 由状态机写入 |
| `Autoplay` | 场景载入时自动播哪个 | 角色不用（状态机决定）；装饰件可以用 |
| `Frame` | 当前第几帧。**设它也会把帧内进度归零** | 攻击与闪避由规则层相位算出来写入 |
| `FrameProgress` | 当前帧到下一帧的进度（0 到 1） | 不常用 |
| `SpeedScale` | 播放速度倍数。负数倒放，0 停住 | 不用（本项目不靠它调节奏） |
| `FlipH` / `FlipV` | 水平／垂直镜像 | **不用**，见第六节 |
| `Centered` | 图以节点原点为中心画 | 见第八节那条坑 |
| `Offset` | 绘制偏移 | 用来把脚底对到节点原点 |

常用方法与信号：`Play(名字)` / `PlayBackwards(名字)` / `Pause()` / `Stop()`；
`SetFrameAndProgress(帧, 进度)` 改帧而**不**重置进度；信号 `AnimationFinished`（循环动画不发）、
`AnimationLooped`、`FrameChanged`。

## 四、两种控帧方式，本项目两种都用

| 方式 | 谁在数时间 | 适合什么 |
| --- | --- | --- |
| **引擎播放时钟**：`Play("walk")` 之后引擎按帧率自己推进 | 引擎 | 待机、行走、奔跑、跳跃这类循环动作 |
| **显式写 `Frame`**：每帧由代码算出该显示第几帧 | 你的代码 | **攻击、闪避、受击** |

## 五、为什么攻击帧不能让引擎自己跑

这是本篇最要紧的一条。

攻击分三段：**前摇**（还没打到）、**命中窗**（判定框开着）、**后摇**（收招）。每一段有多少帧是
玩法数值，由规则层持有。而画面上「拳脚伸出去」的那一帧必须**落在命中窗里**。

**如果让引擎的播放时钟自己跑**，两条时间线就各走各的：命中姿可能在判定框开之前先亮出来。后果是
**玩家学到的时机是错的** —— 他看到拳头到了就以为该打中了，而判定还没开。这不报错，只体现在手感上。

所以本项目的做法是：**规则层说现在是第几个相位帧，引擎层把它换算成第几张图。**

```csharp
// src/World/PlayerActor.cs：把「相位内第几帧」等分映射到「这一段有几张图」，单调不回头、不越界
private static int PhaseFrame(int frameInPhase, int phaseFrames, int spriteFrames) =>
    Math.Clamp(frameInPhase * spriteFrames / Math.Max(1, phaseFrames), 0, Math.Max(0, spriteFrames - 1));
```

**对你的要求只有一条**：每段攻击的**第一张图是静止起手姿**，**第二三张才是拳脚伸出的命中姿**。代码
按这个约定取帧（前摇只用第 0 张、命中窗只用第 1 到 2 张），判定框的尺寸也是从那两张的实测伸展量
出来的。裁图时顺序排错，画面与判定就会停在两处。

**循环动作不受这条约束**：待机、行走、奔跑、跳跃让引擎自己播，或者按一个「每张图停几个物理帧」的
简单计数走。那几个数是占位值，归 `GP-6` 实机收敛。

## 六、朝向：每向各一套，代码不翻转

**决定在 [ADR-0021](../../decisions/ADR-0021-每个朝向各画一套不做水平翻转.md)，三句话：**

- 每个朝向各有自己的一套素材：侧视左右两向，俯视四向。
- **代码按朝向取对应那一套，不做水平镜像，也没有「这个角色翻不翻」的开关。** 缺哪一向就报错说清缺谁。
- **你想省，就在绘图软件里镜像后导出。** 那是一次绘制决定，逐个角色甚至逐个动作都可以不同 ——
  代码看到的只是两套长得镜像的图，它不关心。

**为什么不用 `FlipH`**：主角缺一条手臂，镜像会让空袖子每次转身换一边，而他是玩家全程盯着的那一个。
被否决的折中方案是「按角色开一个翻不翻的开关」—— 那个开关的值是一句判断（「他对称吗」），**没有
任何东西验得了**，新角色忘了填就落到默认翻转，于是某个不对称角色悄悄换边而不报错。

⚠️ **代码现状还在翻转。** `src/World/PlayerActor.cs` 里那句按朝向设 `FlipH`、以及
`rules/Combat/DepthRendering.cs` 里那个镜像方法，都是为翻转存在的路。改成按朝向取表归 `ENG-24`。

**有一条能自动判的**，而且正是这条决定的承重处：**缺某一向的素材时载入报错**，跟着 `ENG-24` 落地。
镜像了好不好看只能你实机看 —— 那正是这条决定要交回给你的判断。

## 七、锚点：把脚底对到节点原点

角色的节点原点应该在**脚底**，理由是判定与摆位都按「站在哪里」算。而图是一整个矩形，脚底像素在图里
的位置由你决定。

做法是给精灵一个**绘制偏移**，把「帧内的地面那一行」对到节点原点：

```csharp
// src/World/PlayerActor.cs：帧居中绘制，行 r 的上沿在精灵局部 y = r - 帧高/2
Sprite.Position = new Vector2(0, -(GroundRow - FrameHeight / 2));
```

**所以你交付逐帧素材时要同时给出「帧内第几行是地面」。** 这个数改错一像素的表现是脚底离地或陷进
地面，纹理尺寸校验抓不到（第二节那条警告）。

## 八、像素对齐的两个坑

**第一个坑：`Centered` 与半像素。** 官方类参考专门提了这一条 —— 像素风游戏里 `Centered` 为真时纹理
可能显得变形，原因是位置落在了像素之间。两个处理方向：把 `Centered` 关掉自己算偏移，或者打开项目
设置里那两项像素吸附（`rendering/2d/snap/snap_2d_vertices_to_pixel` 与
`snap_2d_transforms_to_pixel`）。

**本项目现在两项吸附都没开**，靠的是相机恒为整数像素加节点位置尽量填整数。**如果你实机看到角色
边缘在走动时轻微变形，这两项是第一个该试的地方** —— 试完把结论告诉我，那属于「只能实机看」的一类，
我这边判不了。

**第二个坑：不要缩放精灵。** 侧视与俯视各画一套、按各自需要的大小直接画出来
（[ADR-0020](../../decisions/ADR-0020-侧视不拉近而把角色画大一档.md)）。`Scale` 一旦不是 1，一个源
像素就会跨到两个目标像素上。

## 九、闪白由代码持有，不许烧进图

命中时角色整个变白那一下（`ART-6`），**由代码用着色器做，你不要在受击表里塞一张整帧白的图。**

三条理由，都是实测或结构性的：

- **`Modulate` 做不到。** `Modulate` 是**乘法**，白色乘彩色贴图等于原样，精灵不会变白。所以只能走
  着色器（现在那段着色器写在 `src/World/PlayerActor.cs` 里，只改 RGB 不动透明度）。
- **烧进图会让时长改不了。** 闪几帧是手感量，归实机调；进了图就固定死了。
- **这在第三方素材里是常见做法**，所以裁图时要特意避开：下载来的受击表第一帧常常就是整张白的。

## 十、`AnimationPlayer`：动的不只是帧

第一节那张表说了判据：只是「一串图轮着放」用 `AnimatedSprite2D`，**要同时动别的东西**才用
`AnimationPlayer`。这一节说清后者。

### 它是什么

一条**时间轴**，上面可以放很多**轨道**，每条轨道动一样东西：

| 轨道类型 | 动什么 |
| --- | --- |
| 属性轨 | 任意节点的任意属性：位置、旋转、颜色、透明度、`Visible` |
| 方法调用轨 | 到了某一帧调一个方法 |
| 动画播放轨 | 到了某一帧让另一个节点播某个动画（可以切 `AnimatedSprite2D` 的动画） |
| 音频轨 | 到了某一帧播一个声音 |

编排好的时间轴存成 `Animation` 资源，一个 `AnimationPlayer` 可以持有很多个、按名字播。

### 本项目用它做什么

| 用 | 不用 |
| --- | --- |
| 演出：镜头移动、角色走位、淡入淡出、到某一刻触发一件事 | **角色的动作切换** —— 那是状态机的事，见第五节 |
| 界面动效：面板滑入、提示淡出 | 攻击帧的推进 —— 那要与判定相位对齐 |

**判据是「这段动画有没有一条固定的时间线」**。演出有（脚本写好了先做什么后做什么），战斗没有（下一刻
做什么取决于玩家按了什么）。

### 三条要留意的

- **它有一项设置决定在物理帧还是渲染帧推进。** 演出与界面动效放渲染帧没问题；要与玩法帧对齐的东西
  别用它（见上面那张表的右列）。
- **轨道上有「插值方式」那一项。** 连续插值会算出分数位置，而那在像素风里就是半像素
  （[坐标、像素与相机](./坐标像素与相机.md)第四节）。动位置的轨道要避开连续插值。
- **`Tween` 与它的分工**：`Tween` 是代码里临时建的一次性补间（「把这个东西在 0.2 秒里挪到那儿」），
  `AnimationPlayer` 是编辑器里编排好、能反复播的。**编排得出来的用 `AnimationPlayer`**，那样你能在
  编辑器里调；只有代码才知道目标值的用 `Tween`。

## 十一、动手练习：把一张横排图变成能播的动画

目标是走通「切帧 → 播 → 显式控帧」这条链。大约四十分钟。

1. **新建场景**，根节点 `Node2D` 改名 `Dummy`，加一个 `AnimatedSprite2D` 子节点。
2. **新建 `SpriteFrames`**，在底部面板里加一个动画叫 `idle`，用「从精灵表添加帧」导入
   `res://assets/self-drawn/test-role/idle.png`，按它的实际帧数填格数。
3. **故意把水平格数填错一格**（比如该 6 填 5），看预览里帧怎么歪的。然后改回来。
4. **把 `Autoplay` 设成 `idle`**，`F6` 跑一下 —— 应该自己动起来了。
5. **调帧率**：把那个动画的 FPS 从默认改成 4，再改成 20，各跑一次。记住「太慢像卡住、太快像抖」
   分别是什么样。
6. **再加一个动画 `walk`**，导入对应的图。在脚本里按左右方向键切 `Animation` 属性，跑起来切换看看。
7. **显式控帧**：加一段代码，按住某个键时**不**调 `Play`，而是每个物理帧手动把 `Frame` 加一（到末帧
   停住）。对比一下这两种控帧方式在手上的差别 —— 这就是攻击帧那条约束的由来。
8. **给精灵填一个纵向 `Position` 偏移**，让脚底正好落在节点原点（在场景里画一条水平线当地面参考）。
   故意差一像素，跑起来看看「陷进地面」长什么样。

做完你会有三个直觉：切图格数填错长什么样、帧率快慢的手感、显式控帧与自动播放的差别。

## 十二、这一篇里只能你实机看的

- **脚底有没有贴地。** 站着、走动、跳起落地各看一次。差一像素就看得出来。
- **切图有没有切歪。** 逐帧过一遍，看角色有没有在某一帧整体偏移半个身子。
- **命中姿落在哪一帧。** 帧步进工具（`ENG-6` 交的那个叠层）打开之后能同时看到判定框与画面 ——
  拳脚伸到最远的那一帧应该正好在判定框开着的那几帧里。
- **循环动作的帧率。** 待机太快会像抽搐，行走太慢会像滑步。这几个数就是让你拖着调的。
- **转身那一下自然不自然。** 每向各一套之后，两套之间的过渡是你决定要不要加转身帧。
- **边缘在走动时有没有变形。** 有就试第八节那两项像素吸附，结论贴回来。
