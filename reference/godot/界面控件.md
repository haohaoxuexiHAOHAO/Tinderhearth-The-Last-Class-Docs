# 界面控件

> 本篇回答：**界面为什么要跟世界分层**、**控件怎么定位而不写死坐标**、**手柄怎么在界面里移动**、
> **打开界面为什么暂停世界**。
>
> 界面是分工线上你占比最大的一块：本项目的界面系统**给参数表加零个量、给存档加零个字段**，它持有的
> 全是控件形状、间距、颜色、图标与摆位 —— 那一整块都是你的。前置是
> [脚本与节点接线](./脚本与节点接线.md)与[坐标、像素与相机](./坐标像素与相机.md)。总纲在
> [本目录索引](./README.md)。

---

## 一、界面和世界分层：`CanvasLayer`

`Control` 节点如果直接挂在世界里，它会跟着相机走、跟着缩放变。界面要的是「钉在屏幕上」，所以它挂在
**`CanvasLayer`** 下面 —— `CanvasLayer` 默认不受相机变换影响。

顺带解决了一个坑：[坐标、像素与相机](./坐标像素与相机.md)那一篇提到，位图字体在相机缩放下会糊，
除非它所在的 `CanvasLayer` 忽略相机缩放。本项目界面一律在 `CanvasLayer` 上，所以这条自然满足。

## 二、本项目的六层，一处定义

层号写死在 `rules/UI/UILayer.cs` 一个枚举里，**各场景不许自己挑层号**：

| 层 | 值 | 装什么 |
| --- | --- | --- |
| `World` | 0 | 世界本身：瓦片、角色、场景物件（它不是 UI 层，就是场景） |
| `WorldSpace` | 10 | 跟着世界走的 UI：读条、精英血条、气泡、伤害数字、当前操作格那个框 |
| `Hud` | 20 | 常驻抬头显示：资源、技能位、目标进度、队友状态 |
| `Panel` | 30 | 面板：背包、手环、名册、角色面板。可叠放，由导航栈管 |
| `Dialog` | 40 | 弹窗：确认、每日结算摘要、错误提示。永远在面板之上 |
| `Curtain` | 50 | 遮罩层：淡入淡出与场景切换时盖住一切 |

**为什么钉死**：不钉的话每个界面自己挑一个号，迟早出现「弹窗被 HUD 挡住」，而排查时你要翻遍所有场景
才知道谁用了哪个号。

**值之间留 10 的间隔**，将来插一层不必给全部层重新编号。

⚠️ **不要在检查器里手填 `CanvasLayer` 的 `Layer` 数字。** 层由 `src/UI/UIRoot.cs` 按那个枚举统一建好，
你的界面挂到对应层上就行。

### `WorldSpace` 为什么单独成一层

因为正典要求**读条画在执行者身上而不是界面角落**，血条只给精英与首领 —— 这些东西必须跟着角色在世界
里移动并随相机缩放。所以那一层开了 `FollowViewportEnabled`，其余层不开。

**混进 HUD 层的表现是「读条钉在屏幕左上角」。** 这个错不报错。

## 三、`Control` 的定位：锚点与偏移

`Control` 不用 `Position` 定位（那是 `Node2D` 的事），它每条边各有一个锚点与一个偏移。

- **锚点**（`AnchorLeft/Top/Right/Bottom`）是 0 到 1 的比例，表示「我的这条边挂在父容器宽高的百分之
  几上」。左上角是 0，右下角是 1。
- **偏移**（`OffsetLeft/Top/Right/Bottom`）是在锚点基础上再挪多少像素。

举例：左右锚点都设 1、偏移设 −64 与 0，这个控件就永远贴着父容器右边、宽 64 像素 —— **不管父容器多宽**。
这就是「不写死坐标」的意思。

**预设是锚点的快捷方式。** 2D 视图顶上那个「布局」菜单（或检查器里的 `Layout` 一栏）能一键设成
「贴左上」「贴右下」「铺满」等等。常用的：

| 预设 | 效果 |
| --- | --- |
| `TopLeft` / `TopRight` / `BottomLeft` / `BottomRight` | 贴四个角 |
| `CenterTop` / `CenterLeft` / `Center` … | 贴边中点或正中 |
| `LeftWide` / `TopWide` / `BottomWide` / `RightWide` | 贴一条边并撑满那条边 |
| `FullRect` | 铺满父容器 |

**本项目要求界面一律用锚点与容器，不写死绝对像素坐标。** 理由不是洁癖：`expand` 下逻辑宽度会随窗口
宽高比变（[坐标、像素与相机](./坐标像素与相机.md)那条实测），写死坐标的界面在宽窗口上会错位。这同时
是其他宽高比适配的零成本前提。

## 四、一个必须知道的坑：两个预设方法不一样

**对已经在场景树里的 `Control` 调 `SetAnchorsPreset(FullRect)` 不会让它铺满。**

2026 年那次实测的现象是：引擎会把偏移改写成**负的父尺寸**，以保住当前那个 0×0 的矩形 —— 锚点确实变
成了铺满，尺寸还是 0×0。于是贴下边与贴右边的子节点落到负坐标、画在屏幕外，**而且不报错**。那个
`keepOffsets` 参数的含义与名字给人的印象相反。

**要铺满就用 `SetAnchorsAndOffsetsPreset`**，它与调用顺序无关：

```csharp
// src/UI/UIRoot.cs
control.SetAnchorsAndOffsetsPreset(Control.LayoutPreset.FullRect);
```

**还有一条相关的**：预设按**内容最小尺寸**算偏移，而控件的实际尺寸按「内容最小尺寸与
`CustomMinimumSize` 取大」定。所以你算出来的块尺寸与容器的实际排法（间距、内边距）必须逐项对上 ——
差 4 像素就会让整块偏出安全边距。

## 五、容器：别自己算坐标

`Container` 是一类会**自动摆布子节点**的 `Control`。用它，而不是手算每个子控件的位置。

| 容器 | 怎么摆 |
| --- | --- |
| `VBoxContainer` / `HBoxContainer` | 竖着／横着排一列 |
| `GridContainer` | 按固定列数排格子（背包、图鉴用它） |
| `MarginContainer` | 给里面的东西加一圈内边距 |
| `PanelContainer` | 画一个背景框，里面放一个子节点 |
| `ScrollContainer` | 内容超出时可滚动（列表用它） |
| `TabContainer` | 标签页（手环用它） |
| `CenterContainer` | 把唯一的子节点居中 |
| `FlowContainer` | 排到边就换行 |
| `AspectRatioContainer` | 保持宽高比 |
| `SplitContainer` | 两栏可拖分隔 |

⚠️ **容器会覆盖子节点的位置与尺寸。** 在容器里的子控件上改 `Position` 是白改 —— 容器下一次重排就抹掉
了。要调位置就调容器的参数（间距、对齐、内边距）或者给子控件设尺寸标志。

⚠️ **容器里的控件做「滑入」「缩放淡出」这类动效，以前要绕一圈**（容器一重排就把变换抹掉了，常见办法
是外面再套一层非容器的 `Control`）。**4.7 给 `Control` 加了偏移变换**（`OffsetTransform*` 那一组），
它专门解决这个 —— 做动效优先用它，别去改 `Position` 或 `Scale`。

## 六、尺寸标志与最小尺寸

容器里每个子控件有两个尺寸标志（横向与纵向各一个），告诉容器「多余的空间怎么分给我」：

| 标志 | 意思 |
| --- | --- |
| 收缩起始（`ShrinkBegin`） | 靠上／靠左，只占自己需要的大小（等于不设任何标志） |
| 填充（`Fill`） | 撑满分给我的那块空间，但不多抢 |
| 扩展（`Expand`） | **多抢**空间。多个兄弟都扩展时按各自的拉伸比例分 |
| 扩展填充（`ExpandFill`） | 上面两个一起 |
| 收缩居中（`ShrinkCenter`） | 在分给我的空间里居中 |
| 收缩末端（`ShrinkEnd`） | 靠下／靠右 |

配合两个属性：

- **`CustomMinimumSize`**：这个控件至少要多大。文字控件不设它时会按内容缩到最小。
- **`SizeFlagsStretchRatio`**：多个扩展的兄弟之间按这个比例分空间。

**本项目的一个实例**：HUD 里的条比行矮，靠「收缩居中」在行里居中 —— 不用纵向偏移，就不会有半格。

## 七、主题与主题覆盖

控件的字体、字号、颜色、边框、间距都来自**主题**（`Theme`）。两个层次：

- **一份 `Theme` 资源挂在根控件上**，往下继承。本项目的像素字体主题在 `src/UI/PixelTheme.cs`。
- **单个控件想改一项**，用主题覆盖（检查器里 `Theme Overrides` 那一栏，代码里是
  `AddThemeConstantOverride` / `AddThemeColorOverride` / `AddThemeFontSizeOverride` /
  `AddThemeStyleboxOverride`）。

```csharp
row.AddThemeConstantOverride("separation", UIMetrics.ItemGap);
```

**优先改主题、少用覆盖。** 覆盖散在各处之后，「为什么这一处间距不一样」要翻遍场景才查得到。

### 像素字体那条坑

字体的渲染参数在 `.ttf.import` 里（不是在主题里）。**改了那个文件一定要重新导入**，否则游戏读到的
还是上一次烘出来的产物 —— 抗锯齿仍是灰度，12 像素中文多一圈半透明脏边，**一句报错都没有**。这条在
[编辑器与场景](./编辑器与场景.md)导入那一节里也写了，因为它是同一个机制。

期望的渲染参数在 `rules/UI/PixelFont.cs`。它与 `.ttf.import` 里的设置、引擎自报的实际值是**三份独立
来源**，所以能互为量具。

## 八、排版量从哪来：界面里不写数字字面量

**除 0 与 1 之外，界面代码里一个数字字面量都不该有。** 排版量从 `rules/UI/UIMetrics.cs` 取，颜色从
`rules/UI/HudPalette.cs` 取，字体参数从 `rules/UI/PixelFont.cs` 取。

`UIMetrics` 里现在有这些（值在那个文件，本篇不抄）：基础单位、逻辑分辨率、正文字号与行高、排版栅格、
面板内边距、元素间距、安全边距、两档图标尺寸、侧视相机缩放。

**为什么这几个数在规则层**：它们之间有**可以判死的关系**（栅格整除基础单位、逻辑分辨率整除栅格、
边距是栅格的整数倍）。放规则层就有单元测试盯着 —— 有人为了「看着好一点」改了一个数，测试当场失败，
而不是等到某个界面对不齐才被发现。

⚠️ **色值不带透明度。** 像素只允许全透明或全不透明，所以半透明遮罩画上去就是屏幕上的插值像素。
**冷却用不透明色遮，不用压暗。** 色板定稿归 `DOC-2`，那是你在编辑器里看着定的事。

## 九、导航栈与暂停

### 栈做三件事

`rules/UI/NavigationStack.cs` 管「压入、弹出、按返回键回到哪」。三条行为值得记住：

- **`Push` 已经在栈里的层会被提到栈顶，不重复压。**
- **`Clear` 在场景切换时用。**
- **栈空时返回键不消费这次输入**，交还给上层（在关卡里那通常意味着打开暂停菜单）。**吞掉的表现是
  「按了没反应」，玩家会以为卡死。**

### 暂停由栈整体决定，不给任何一页开关

```csharp
// rules/UI/NavigationStack.cs
public bool WorldShouldPause => _stack.Count > 0;
```

引擎层只负责把它翻译成 `GetTree().Paused`（`src/UI/UIRoot.cs` 里那个 `Sync`）。

**不给任何一页留「要不要暂停」这个开关** —— 一个恒为真的开关等于给人一个设错的机会。

**判据落在「界面接管输入」上，不落在「玩家操作不了」上。** 这一条分清了才不会写错：

| 情形 | 暂不暂停 | 为什么 |
| --- | --- | --- |
| 打开背包、手环、日记 | **暂停** | 界面接管了输入 |
| 硬直、失衡、被击倒 | **不暂停** | 玩家操作不了，但那是战斗本身 |
| 用道具、采集、施放技能（带读条的） | **不暂停** | 它们是世界里的动作，走各自的读条与后摇 |
| 命中顿帧 | **不是暂停** | 那是「当帧不推进」的闸门，另一套机制 |
| 每日结算 | **不是暂停** | 世界本来就不在跑，那是一次转场 |

后两行值得单独记：**顿帧与暂停是两套东西**。顿帧在 `src/World/Hitstop.cs`，它让战斗推进当帧不走，而
渲染与物理帧号照常。关卡里翻包要暂停世界，复用的是**顿帧那个闸门**而不是自造一套。

### 关卡里哪些界面能用

界面按三类分（`rules/UI/UISurface.cs` 里那个取值）：查看类关卡内可用但只读，操作类关卡内禁用，
随身物可用且可操作。**不发明第二套分类**，判定只读代码里那一个。

被拒时**要说明原因，而不是静默不动** —— `src/UI/UIRoot.cs` 的 `Open` 会打一行日志说清是哪一页、
为什么。

## 十、手柄怎么在界面里移动：两种范式，写死的二选一

`rules/UI/PanelNavigation.cs` 定了两种，**按面板形状选，不由各面板自己发明**：

### 甲：焦点移动（列表、标签页、按钮组）

**几乎不写代码。** Godot 内置了 `ui_up` / `ui_down` / `ui_left` / `ui_right` 四个动作，配上控件的
`FocusMode`（`None` / `Click` / `All`），方向键就能把焦点在控件之间挪。

- 想让一个控件能被聚焦：`FocusMode` 设成 `All`。
- 邻居关系引擎自己按位置算；算得不对时用 `FocusNeighbor*` 那几个属性手指。
- 代码里让某个控件拿到焦点：`GrabFocus()`。**面板打开时要主动给第一个控件焦点**，否则手柄玩家按方向
  键没反应。

### 乙：光标移动（网格摆放）

方向键挪一个**格子光标**，确认键才落子。建造摆位用它。

**为什么网格不用焦点导航**：那得为**每个格子**各建一个可聚焦控件并连好邻居链，而格数由配置给、可以
很大；更要紧的是**摆放需要的是一个坐标而不是一个控件** —— 建筑占多格时落点是左上角那一格，而「焦点」
这个概念表达不了一个坐标。

**光标钳制在边界内，不环绕。** 环绕会让镜头突然横跨整张地图，而正典要求相机行为可预期。

⚠️ **贴边时继续推方向应该没有反馈音也不推镜**，否则玩家会以为镜头卡住了。规则层那个光标的 `Move`
返回「有没有真的动」就是给这件事用的。

## 十一、鼠标过滤，以及「手柄没有悬停」

`MouseFilter` 三个取值，决定鼠标事件怎么传：

| 取值 | 行为 |
| --- | --- |
| `Stop` | 我收下并**标记已处理**，不再往别的控件传 |
| `Pass` | 我收下，没处理的继续往父控件冒泡 |
| `Ignore` | 我完全不收，也不挡别人 |

⚠️ **纯装饰的控件（背景图、边框、标签）要设成 `Ignore`。** 默认值会让它们挡住底下按钮的点击，而
表现是「这个按钮点不动」—— 排查时很容易怀疑到按钮自己身上。

**一条更要紧的设计约束：手柄没有悬停。** 所以「只在鼠标悬停时出现」的信息**等于对手柄玩家藏起来了**。
本项目由此否掉了几种具体实现：专长三选一的说明**不许折叠、不许省略号、不许只在悬停时出现**。

通用教程把提示气泡（tooltip）当标配，这里不行。

## 十二、世界空间 UI

挂在 `WorldSpace` 那一层的东西（读条、时机条、精英血条、伤害数字、气泡、当前操作格那个框）有三个共同点：

- **跟着角色或物件走**，随相机缩放。
- **不接管输入**，所以不进导航栈、不暂停世界。
- **形状上要与别的东西分得开**：气泡与引导提示不许只靠颜色区分（丢弃语义相反 —— 气泡可以被丢掉，
  引导提示不许被丢掉）。

排版量在 `rules/UI/WorldUILayout.cs`，引擎层在 `src/UI/WorldSpaceUI.cs`。

## 十三、动手练习：搭一页在任何窗口宽度下都不错位的面板

目标是把锚点、容器、尺寸标志、焦点导航走一遍，并亲手制造一次那个 0×0 的坑。大约一小时。

1. **新建场景**，根节点 `Control` 改名 `TestPanel`，用布局菜单设成**铺满**。
2. **加一个 `PanelContainer`**，再往里加一个 `MarginContainer`，再往里加一个 `VBoxContainer`。
   给 `PanelContainer` 设成贴右上角、`CustomMinimumSize` 给一个值。
3. **往 `VBoxContainer` 里加三个 `Button`**。`F6` 跑一下 —— 它们应该自动竖排。
4. **把窗口拉得很宽再很窄**，确认那个面板一直贴在右上角、没有错位。然后**试着给某个按钮改
   `Position`** —— 跑起来会发现白改了（容器重排抹掉了）。
5. **改 `VBoxContainer` 的 `separation` 主题覆盖**，看间距变化；再给一个按钮设「扩展填充」，看它抢走
   多余空间。
6. **加一个 `ColorRect` 当背景**盖在按钮上面，跑起来点按钮 —— 点不动。把它的 `MouseFilter` 设成
   `Ignore`，再点，这回能点。**记住这个症状。**
7. **手柄或方向键导航**：把三个按钮的 `FocusMode` 设成 `All`，在脚本 `_Ready` 里给第一个
   `GrabFocus()`，跑起来用方向键上下移动。然后**去掉那句 `GrabFocus`** 再跑 —— 方向键没反应，这就是
   「忘了给初始焦点」。
8. **制造那个 0×0 的坑**：在脚本里对一个已经 `AddChild` 过的子 `Control` 调
   `SetAnchorsPreset(Control.LayoutPreset.FullRect)`，打印它的 `Size` —— 看到 0×0。改成
   `SetAnchorsAndOffsetsPreset`，再打印。
9. **把这一页挂到 `Panel` 层上**（照 `src/UI/UIRoot.cs` 的登记方式），开关一次，确认打开时世界暂停、
   关掉时恢复。

做完你会有四个直觉：锚点与容器怎么配合、容器会抹掉手改的位置、`MouseFilter` 配错的症状、那两个预设
方法的差别。

## 十四、这一篇里只能你实机看的

- **把窗口从最窄拉到最宽，每一页都看一遍。** 错位只在某些宽度下出现。
- **12 像素中文读不读得清。** 一屏文字量、行距、对比度都靠看。
- **只用手柄能不能走完每一页。** 这是硬要求：进页要有初始焦点、每个可操作项都到得了、返回键有反应。
