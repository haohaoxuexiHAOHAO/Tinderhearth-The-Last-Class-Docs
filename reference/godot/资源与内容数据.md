# 资源与内容数据

> 本篇回答一个每加一种新东西都要重答的问题：**这一坨数据该做成 Godot 资源让你在检查器里填，还是
> 写成 JSON 文件？** 本项目对这件事有明确分界，而分错了的代价不是报错，是过几个月发现「同一件事
> 有两个家」。
>
> 前置是[编辑器与场景](./编辑器与场景.md)与[脚本与节点接线](./脚本与节点接线.md)。总纲在
> [本目录索引](./README.md)。

---

## 一、两种「数据」，先分清

| | **Godot 资源** | **内容数据文件** |
| --- | --- | --- |
| 长什么样 | `.tres` 文件，或者直接挂在节点的导出格子里 | `res://data/` 下的 `.json` |
| 谁填 | 你，在检查器里 | 写在文本编辑器里，代理与你都改得动 |
| 适合装什么 | **场景几何与素材**：占地几格、门朝哪、用哪张图 | **一张表**：作物、物品、技能、敌人、天气 |
| mod 能不能加 | 不能（它在场景里） | **能**，这是 mod 的唯一入口 |
| 规则层读不读得到 | 读不到（它是 Godot 类型） | 读得到（它是字符串与字典） |

**分界线的判据只有一句**：这坨数据是**摆在某个场景里的一份配置**，还是**一个可以有很多份的内容
条目**？门朝哪只对这一栋建筑有意义 → 资源；萝卜长几天是「萝卜」这个条目的属性，而萝卜是内容清单里
的一行 → 数据文件。

判据的出处是 [ADR-0022](../../decisions/ADR-0022-内容清单的家是数据文件.md)。

## 二、Godot 资源怎么做

### 自定义一个资源类型

```csharp
using Godot;

namespace Tinderhearth.World;

[GlobalClass]
public partial class BuildingFootprint : Resource
{
    /// <summary>外观占地，单位是格（一格 16 世界像素）。</summary>
    [Export] public Vector2I Cells { get; set; }

    /// <summary>门朝哪个方向。它决定哪一格是「门前那一格」。</summary>
    [Export] public GridFacing DoorFacing { get; set; }
}
```

四条规矩：

1. **继承 `Resource`**，而不是 `Node`。资源没有位置、不进场景树，它只是一坨数据。
2. **加 `[GlobalClass]`**，否则编辑器不认得它 —— 加了之后它才会出现在「新建资源」对话框里，
   而且导出这个类型的格子会**只接受这个类型**（官方
   [全局类](https://docs.godotengine.org/en/4.7/tutorials/scripting/c_sharp/c_sharp_global_classes.html)）。
3. **文件名必须与类名逐字符一致**（大小写也要一样）。`BuildingFootprint` 就得放在
   `BuildingFootprint.cs` 里，否则注册不上。
4. 想给它一个图标：`[GlobalClass, Icon("res://assets/icons/footprint.svg")]`。

### 在检查器里用它

一个节点导出这个类型：

```csharp
[Export] public BuildingFootprint? Footprint { get; set; }
```

检查器里那一格会给你两个选择：**新建一个**（就存在这个场景里，跟着 `.tscn` 走）或者**拖一个
`.tres` 文件进来**（存成独立文件，多个地方可以共用）。

**什么时候存成 `.tres`**：这组值要在多个场景之间共用，或者你想存两份对比着试。手感那一批就是这种
—— 存两个 `.tres`，在检查器里换着挂，跑起来立刻比得出来。

### `.tres` 是共享的，所以「改一个」要先使其唯一

两个节点挂同一个 `.tres`，内存里只有一份。改它会同时改到两处。想只改这一处，点那一格旁边的菜单 →
**使其唯一**（Make Unique），引擎会给你一份拷贝。代码里对应的是 `resource.Duplicate()`。

⚠️ **资源里不要存运行时状态。** 资源会被存回 `.tres`，而且是共享的 —— 把「这一格今天浇过水没有」
放进资源里，结果是所有地块共享一个「浇过没有」，而且退出游戏时被写进文件。运行时状态归节点或规则层。

## 三、本项目为什么内容定义不走资源

这是与通用教程差别最大的一处，值得把理由写全。通用教程的第一反应是「做一个 `CropData : Resource`
让作者在检查器里填」，本项目刻意不是。

三条理由，各自独立：

1. **mod 加不了 `.tres`。** 内容外置的目的是让 mod 能追加内容，而 mod 是玩家丢进 `user://mods/` 的
   一个目录 —— 那里放 `.tres` 要引擎去认，而 `.json` 谁都写得出来。
2. **规则层读不到 Godot 类型。** 判定与结算在 `rules/` 下，那一层**不引用 Godot**（编译器强制）。
   作物的阶段天数要进判定，所以它不能是一个 `Resource`。
3. **缺字段要能当场报错。** JSON 那条路上，缺键由反序列化器直接报（`rules/Economy/CropDefinition.cs`
   用 `required` 属性做这件事）。资源那条路上缺字段拿到的是类型默认值 —— 一个合法但全零的东西，
   不报错。

**所以 `[Export]` 在本项目的用途是收窄的**：只装场景几何与素材，不装内容。你在检查器里找不到
「萝卜长几天」不是漏了，它在数据文件里。

## 四、内容数据那条路

### 两个根，后者叠在前者上

`src/Platform/ModPaths.cs` 定了三个位置：

| 常量 | 路径 | 是什么 |
| --- | --- | --- |
| 基础内容 | `res://data` | 随游戏发布，打进发行包 |
| mod | `user://mods/<名字>/` | 玩家自己装的，叠在基础内容之上 |
| 存档 | `user://saves` | 见[文件读写与存档](./文件读写与存档.md) |

现在 `data/` 下有三份：`data/config/game.json`、`data/characters/ember.json`、`data/text/zh-CN.json`。
一种新内容类型进来就多一个子目录。

**为什么 mod 不放在 exe 同级目录**，理由写在 `src/Platform/ModPaths.cs` 的注释里，三条都是实测或
发行现实：exe 同级目录不按用户区分；`C:\Program Files` 下要提权，而 Steam 的「验证文件完整性」会
清掉不在清单里的文件（玩家的 mod 会莫名消失）；Steam 云存档要一个可预测的按用户位置。

⚠️ 顺带纠正一条流传很广、也曾写在本项目文档里的说法：**「导出后 `res://` 只读」是错的。** 实测往
`res://` 写文件会成功，文件落在可执行文件同级目录 —— 只有已经打进 `.pck` 的条目才真正改不了。

### 读文件只能用引擎的 `FileAccess`

```csharp
// src/Platform/GodotContentSource.cs
using var handle = FileAccess.Open(absolute, FileAccess.ModeFlags.Read);
```

**不能用 `System.IO.File`**：导出后 `res://` 的内容打进 `.pck` 包里，只有 Godot 自己的 `FileAccess`
读得到。`user://` 两种读法都行，但统一走 `FileAccess` 免得两套路径两种行为。

一个 C# 侧的小坑值得记：`ImplicitUsings` 会引入 `System.IO`，于是 `FileAccess` 在
`Godot.FileAccess` 与 `System.IO.FileAccess` 之间歧义、编译报 `CS0104`。本项目的处理是在用到它的
那个文件顶上显式取别名：

```csharp
using FileAccess = Godot.FileAccess;
```

## 五、两种覆盖语义，别统一成一种

这一条是实测撞出来的，不是设计时想到的，所以写全。

| 内容形状 | 语义 | 例子 |
| --- | --- | --- |
| **一个文件一个实体** | **整文件覆盖**：同名文件由后登记的来源整份替换 | 角色、宝物、配方、敌人 |
| **一个文件很多条目** | **逐条目合并**：只覆盖同键条目 | 文本表 |

代码上是两个方法（`rules/Foundation/Content/ContentCatalog.cs`）：`Resolve` 整文件覆盖，
`ResolveAll` 不去重、由调用方决定怎么合并；文本走 `rules/Foundation/Text/TextCatalog.cs` 的逐键合并。

**为什么必须分开**：最初文本也走整文件覆盖，结果一个只提供三条文本的 mod 把基础文本从五条顶成三条，
`boot.title` 直接消失 —— 界面上会冒出一片缺文本占位。这个错**不报错**，只在画面上看得出来。

### 每条内容记得自己来自哪个来源

`ContentEntry` 带一个 `SourceName`。这不是为了诊断好看：卸载 mod 之后要能列出「因缺少 mod 而不可用」
的角色与物品（`ENG-7`），那件事只能靠来源信息做，事后补要翻遍整条加载路径。

## 六、枚举按名字读写，不按序号

`rules/Foundation/Content/ContentJson.cs` 给 JSON 装了一个按名字读写枚举的转换器。理由两条：

- 序号在手写数据文件里读不出含义 —— `"seasons": [0, 1]` 要去查 0 是哪个季节。
- 往枚举中间插一个取值会**静默改掉全部旧数据的含义**。按名字则是解析失败，而失败查得出来。

所以数据文件里季节写成 `"Spring"` 而不是 `0`。

## 七、文本一律按键取

界面上一句写死的中文都不许有。文本表是 `data/text/zh-CN.json`，代码里拿到的是一个键（`boot.title`
这种），渲染时才查表。

**缺键报错，不退化成显示键名。** 退化的表现是界面上出现一串英文点号路径，玩家读不懂而程序不报错。

## 八、`PackedScene` 也是资源

一个 `.tscn` 在代码里的类型就是 `PackedScene`，所以它能被导出、能被装进
`Godot.Collections.Array<PackedScene>`。这就是关卡片段那一批的接法：一关声明「可以用哪些片段」，
每个片段是一个 `PackedScene`，你在检查器里往那个列表里拖。

```csharp
[Export] public Godot.Collections.Array<PackedScene>? Segments { get; set; }
```

⚠️ **导出的是模板，不是实例。** 要用得 `Instantiate<T>()` 造一份出来，见
[编辑器与场景](./编辑器与场景.md)里加载与实例化那一节。

## 九、代码侧：加载、保存、引用计数

```csharp
// 读一个资源。找不到返回 null，不抛 —— 所以路径别写死，见下
var tex = GD.Load<Texture2D>("res://assets/self-drawn/test-role/idle.png");

// 与上面等价，写法更啰嗦但能带参数
var tex2 = ResourceLoader.Load<Texture2D>("res://assets/self-drawn/test-role/idle.png");

// 存一个资源（编辑器工具里才用得上，游戏运行时不写 res://）
ResourceSaver.Save(footprint, "res://data/footprints/barn.tres");
```

三条口径：

- **资源是引用计数的**，没人用了自己就走，不用手动释放。这与节点不同（节点要 `QueueFree()`）。
- **路径不写死**，改成导出属性让你在检查器里拖。`GD.Load` 找不到时返回 `null`，然后在下一行炸出
  一个跟真正原因无关的空引用。
- **游戏运行时不写 `res://`。** 玩家侧的写入一律去 `user://`。`ResourceSaver.Save` 只在编辑器工具
  脚本里用。

## 十、动手练习：做一张「一组手感量」的资源

目标是把自定义资源、`[GlobalClass]`、`.tres` 共享与「使其唯一」走一遍。大约三十分钟。

1. **新建一个 C# 文件 `JumpFeel.cs`**，内容是一个 `[GlobalClass] public partial class JumpFeel : Resource`，
   导出三样：峰高（世界像素）、初速（像素每秒）、重力（像素每二次方秒）。
2. **构建一次**（右上角锤子），然后在文件系统里右键 → 新建资源，搜 `JumpFeel` —— 能搜到说明
   `[GlobalClass]` 生效了。建两份，存成 `res://data/feel/jump-floaty.tres` 与 `jump-snappy.tres`，
   两份填不同的数。
3. **在上一篇那个 `Lamp` 场景里**（或新建一个节点）加一个 `[Export] public JumpFeel? Feel { get; set; }`，
   构建，把其中一个 `.tres` 拖进那一格。
4. **在 `_Ready` 里把三个数打出来**，`F6` 跑一下确认读到了。
5. **换挂另一份 `.tres`**，再跑 —— 数应该跟着变，而你一行代码都没改。这就是「参数的唯一来源是
   场景与资源」的样子。
6. **把同一份 `.tres` 挂到两个节点上**，在一个节点里改一个数，看另一个是不是也变了。然后对其中一个
   点「使其唯一」，再改一次，确认这回不互相影响。
7. **故意把那一格清空再跑**，确认报错说得清是哪个节点的哪一格在等你填。

做完你会有三个直觉：资源是共享的、`.tres` 可以换着挂来试手感、空格子是在等你填。

## 十一、这一篇里只能你实机看的

- **导出格子该不该在这里。** 打开检查器扫一遍：出现了「萝卜长几天」这类**内容**，就是分错了 ——
  它该在数据文件里。看到就说。
- **换一份 `.tres` 跑起来有没有真的变。** 这是「参数唯一来源」那条约束唯一的验证方式：改了数、
  跑起来没变，说明代码里还留着一个默认值在偷偷胜出。
- **装一个 mod 进 `user://mods/` 之后基础内容有没有被整份顶掉。** 文本那一类必须是逐键合并 ——
  界面上冒出一片缺文本占位就是撞上了这个。
