# 从哪里开始

> 别篇回答「怎么做一件事」，本篇回答**先做哪一件**。
>
> 它给的是一串**里程碑**：每一步做完，你能玩到的东西比上一步多一样。**经营侧优先**，战斗侧那一支
> 排在后面。总纲在[本目录索引](./README.md)。

---

## 为什么需要这一篇

仓里现有的顺序都不是这个：

| 现有的 | 回答什么 | 为什么不够 |
| --- | --- | --- |
| [待办台账](../../spec/issues/README.md)的「系统深化顺序」 | 接下来该深化哪个系统的**设计** | 它自己写明那不是实现顺序 |
| 台账里每条编号备注的「落地顺序」 | 一个系统**内部**的步骤 | 不管系统之间 |
| [本目录索引](./README.md)的「按任务查」 | 做某件事该读哪几篇 | 不回答先做哪件 |

**里程碑是台账里没有的东西** —— 台账是按系统分的编号表，答不出「第一个能玩的版本长什么样」。那个
答案的家就是本篇。

**依赖与进度不在本篇。** 「这一条卡在谁身上」「做到哪一步了」全在台账那一格，本篇只写链接。要看进度
就去那里，不要指望这一篇是最新的。

## 三条贯穿的原则

1. **每个里程碑都要能玩。** 不是「代码写完了」，是「打开游戏能做一件上一步做不到的事」。判据写在每个
   里程碑的「怎么算做完」那一格，而那些判据基本都要你实机看。
2. **先小后大。** 同一套做法，第一次在最小的场景上试 —— 错了在那里发现比在大场景上发现便宜得多。
   所以第一个里程碑只要一小块地，不是整个基地。
3. **不设日期。** 这不是排期。顺序可以改，改顺序不用改任何设计文档 —— 它们之间的依赖是台账那几格
   管的，本篇只是给了一条走得通的路线。
4. **按名引用，不按序号。** 下面的里程碑刻意不编号 —— 插一步或换个顺序会让「第三步」这种说法静默
   指到别的东西上。要引用某一个就写它的名字。

## 里程碑

### 一块地能种出东西

**这一格有一份跟着做的逐步指南：[一块地能种出东西](./一块地能种出东西.md)。** 下面这张表是它的摘要。

**做完能玩到**：走到一格地上，锄它、播种、浇水，看到它一天天变样，最后收上来一筐菜。

| | |
| --- | --- |
| **你搭** | 基地俯视场景（**先一小块地就行**，不用整个可建造区）、两层瓦片图层（天然地形 ＋ 耕地叠加）、俯视角色节点树、作物各阶段素材加枯死那张 |
| **我写** | **已经写了** —— 把地块状态机接到瓦片层（`src/World/Farm/FarmField.cs`）、当前操作格那个框（`FarmCellCursor.cs`）、俯视走动（`FarmWalker.cs`）、作物素材那份资源与缺图报错（`CropArt.cs`） |
| **读哪几篇** | 跟着[一块地能种出东西](./一块地能种出东西.md)走就行，它在每一步指到该查的那一篇 |
| **怎么算做完** | 四个动作各做一次都看得见结果；一格锄过没锄过扫一眼分得出来；**一屏之内分得出哪几格浇过水**；成熟与它前一阶段关掉颜色也分得开 |
| **台账** | `GP-87` 剩下那一半、`UI-27`（当前操作格）、显示层归 `GP-86` |

⚠️ **原先这一格的验收里有「对着没锄的地按播种被拒且看得出为什么」，那一条挪走了。** 落地时用的是
「一个键按当前格状态派发」，所以你没有办法主动选一个不该用的动作 —— 那条拒绝路径由规则层单元测试
守着，实机要试到它得等工具栏（`GP-23`）。改口径的理由写在 `FarmField.cs` 的类注释里。

**三条实现建议**（不是设计决定，你可以否掉）：

- **地形先用引擎内置的四边拼接，双网格留到后面。** 双网格能把一种地形的画量从约 47 块降到 16 块，
  但它 Godot 不原生支持、要先写一段把数据层翻译成显示层的代码（`ENG-25`）。第一块地用内置拼接能更快
  看到东西；等你确定要画多少种地形了再上双网格。
- **俯视角色的 `MotionMode` 要设成浮空**，不是接地。接地模式会把「往上走」当成跳，表现是移动卡顿而
  不报错（[物理与碰撞](./物理与碰撞.md)那张表里有）。
- **这一步正好是画第一批正式素材的时候**，所以试片那一轮（`ART-17`）与它同批做最省 —— 试片没过就批量
  画，错的口径会乘以地形种类数。

### 睡一觉能推进一天

**做完能玩到**：走到床边睡觉，作物长一阶段，弹一份摘要说清发生了什么；退出游戏再进来，进度还在。

**这一步是经营循环真正闭合的地方。** 在它之前，种地是一次性的演示；在它之后，是一个循环。

| | |
| --- | --- |
| **你搭** | 床的交互点、摘要弹窗的排版、转场遮罩 |
| **我写** | 每日结算那串固定步序、日期推进、作物按天推进、存档写入与原子替换 |
| **读哪几篇** | [时间与帧推进](./时间与帧推进.md) → [文件读写与存档](./文件读写与存档.md) → [界面控件](./界面控件.md) |
| **怎么算做完** | 睡一觉作物长了；摘要说得出发生了什么；退出重进进度还在；**把存档目录临时设成只读再睡一次，提示要说清「这一天没有推进」** |
| **台账** | `GP-56`（结算）、`GP-54`（存档）、`UI-20`（那两处界面） |

⚠️ **最后那条判据是这一步最要紧的一条。** 存档写坏了玩家丢进度，那是唯一无法挽回的缺陷。原子替换那套
做法在[文件读写与存档](./文件读写与存档.md)第七节，里面那个练习专门练这件事。

### 东西能拿在手上

**做完能玩到**：收上来的菜进背包，背包满了再收看得出被拒、而地上那一份还在。

| | |
| --- | --- |
| **你搭** | 背包界面的格位网格、物品图标、品质角标 |
| **我写** | 两个容器与堆（堆的标识是「种类 ＋ 品质」）、满载只拒不丢的四条路径、排序筛选与一键整理 |
| **读哪几篇** | [界面控件](./界面控件.md) → [资源与内容数据](./资源与内容数据.md) |
| **怎么算做完** | 满载时四条拒绝路径各试一次；同名不同品质分得出来（一屏同名多行要读得下去）；16 像素图标上的数量与品质角标分得清 |
| **台账** | `GP-23`、界面归 `UI-13` |

### 能盖一栋房子

**做完能玩到**：在基地上摆一栋建筑，等它建成，走到门前进室内。

| | |
| --- | --- |
| **你搭** | **一类**建筑的外观场景与室内场景（正典要求先做一类当样板）、工地美术件、摆位预览的高亮 |
| **我写** | 两套网格与同一份冲突判定、四条拒绝路径、施工状态机、升级／拆除／移动三条路径 |
| **读哪几篇** | [瓦片地图与地形](./瓦片地图与地形.md) → [交互点与站位点](./交互点与站位点.md) → [界面控件](./界面控件.md) |
| **怎么算做完** | 四条拒绝各触发一次**且各说得出是哪一种**（尤其「门前那一格被占」）；施工中就占地（下单那一刻就冲突，不是建成那天）；走到门前直接进室内、不按键不读条 |
| **台账** | `GP-44`、尺寸落配置在 `ENG-22`、界面归 `UI-26` |

⚠️ **建筑的三项导出字段不给默认值**（外观占地、门的朝向与位置、室内网格尺寸）。有默认值的后果是
「忘了摆」被静默兜底成一栋摆在原点、门朝上的楼。

### 有人买东西

**做完能玩到**：走出基地到一张城区图，把一筐菜卖给商店拿到钱，再走回来。

| | |
| --- | --- |
| **你搭** | 一张城区图、边界点、商店门面、订货送达点 |
| **我写** | 钱包与那条唯一的支出管道、三层定价与每层的原因读口、商店上架与惰性刷新、城区切换 |
| **读哪几篇** | [交互点与站位点](./交互点与站位点.md) → [瓦片地图与地形](./瓦片地图与地形.md) → [界面控件](./界面控件.md) |
| **怎么算做完** | 卖一筐拿到钱；价格明细每层报得出当前值加一条原因；钱不够时只拒不赊**且说得出缺口**；朝边界持续走切图，回来落在入口那个边界点上 |
| **台账** | `GP-43`（经济）、`GP-59`（城区图与导航）、界面归 `UI-26` |

⚠️ **边界点两边各声明一次，载入时对账，不成对就报错。** 这是这一步唯一能自动判的东西。

### 战斗侧那一支

到这里经营循环已经闭合，可以转战斗侧了。**它排在后面不是因为不重要，是因为它的前置更重**：关卡片段
要你一屏一屏搭，而那套做法在前面几步已经练熟了。

**这一支的第一件是训练房换血。** 它现在是个空 `Node2D` —— 整个训练房在 `_Ready()` 里 `AddChild`
出来，编辑器里什么都看不见（那个文件自己的注释写着它在等这次重写）。

| | |
| --- | --- |
| **你搭** | 地面、主角节点树、碰撞区域、两个沙包、障碍物、检查器里那些参数 |
| **我写** | `src/World/TrainingRoom.cs` 改成读你搭的节点与导出属性，不再自己 `AddChild`；缺子节点就报错说清缺谁 |
| **怎么算做完** | 在检查器里改一个数，跑起来看到变化；删掉一个子节点跑一次，报错说得清缺谁；实机打两下手感与改之前一致 |
| **台账** | `GP-14`，它是 `ENG-21` 的第一块；纵深带够不够宽随它一起看（`ENG-16`）|

⚠️ **这一步刻意不动手感数值。** 手感变成检查器里可调是 `ENG-20`，它排在战斗手感真正开始调的时候。

**它原先排在全部里程碑之前，理由是「这套分工的第一次实跑放在最小的场景上」。那个理由已经用掉了** ——
经营那一片地就是第一次实跑，而且它同时产出了能玩的东西。所以训练房回到它本来的位置：战斗侧的第一件。

接下来大致这个顺序：

| 大致顺序 | 做完能玩到 | 台账 |
| --- | --- | --- |
| 手感数值变成检查器里可调 | 你能拖着调顿帧、前后摇、无敌窗 | `ENG-20` → `GP-6` |
| 关卡片段与拼装 | 出征打一串手工搭的片段，同一个种子拼出同一张图 | `GP-42` |
| 敌人与 AI | 有会还手的东西 | `GP-36`、`GP-51` |
| 状态载体扩容 | 异常状态、装备加成、天气修饰都要它 | `GP-18` |

## 不进里程碑的那几件，什么时候插进来

有几条不属于任何一个里程碑，但会被某一步逼出来。**别提前做，撞上了再做：**

| 这件事 | 什么时候插 |
| --- | --- |
| 手感数值变导出属性（`ENG-20`） | 战斗手感真正开始调的时候。经营侧用不到它 |
| 状态载体扩容（`GP-18`） | 第一个要「按天生效的增益」的系统碰到它时。天气、装备、教育都等它 |
| 双网格（`ENG-25`） | 你确定要画多少种地形、而画量成为问题的时候 |
| 试片（`ART-17`） | 与「一块地能种出东西」同批。它卡着全部正式美术 —— 试片没过就批量画，错的口径会乘以地形种类数 |
| 界面色板定稿（`DOC-2`） | 有三四页界面之后一起定，单页定不出一套色板 |

## 怎么用这一篇

- **一个里程碑一次。** 别并着做 —— 并做的后果是出问题时分不清是哪一半的。
- **每个里程碑做完跑一次代码仓 `python tools/verify.py`**，再照那个里程碑的「怎么算做完」实机走一遍。
  完整的走查清单在[调试与实机验收](./调试与实机验收.md)。
- **顺序你说了算。** 想先做战斗侧就把那一支提上来 —— 现在这么做的代价比原先小了，因为「作者搭树、
  代理接线」那套做法已经在一片地上实跑过一次。
- **碰到新的事就说。** 它会变成台账里一个新编号 —— 那样三个月后你想起「那件事后来怎么了」时查得到。
