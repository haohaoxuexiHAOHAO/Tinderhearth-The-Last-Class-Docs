# 交互点与站位点

> 本篇把一个反复出现的活儿写一次：**在场景里摆一个「走过去会发生事」的地方**，或者**摆一个空位让
> 代码往上填人**。
>
> 这件事在很多系统里都要做 —— 工位与投料口、建筑的门、商店门面与订货送达点、节日入口与站位点、床、
> 课堂站位。**三种触发形状的规则刻意长得不一样**，混用会让玩家读不出规律。前置是
> [物理与碰撞](./物理与碰撞.md)与[输入](./输入.md)。总纲在[本目录索引](./README.md)。

---

## 一、三种触发形状，判据不同

| 形状 | 怎么触发 | 接管输入吗 | 用在哪 |
| --- | --- | --- | --- |
| **点一下它** | 站在范围内点一下，当帧生效、不读条 | 不 | 进出建筑室内 |
| **朝边界持续移动** | 朝那个方向走够久；中途转向或停下**重新开始** | 不 | 城区之间切换 |
| **按键加读条** | 按一次键，然后读条 | 不 | 关卡片段转场、采集、开箱 |

**为什么刻意做成三种**：它们要挡的东西不一样。

- **进出室内要挡误触，不用挡脱离。** 基地摆满建筑之后门就在动线上，走过去会被拖进屋；但基地里没人
  追你，所以读条在这里买不到「可被打断」这件事，只剩纯等待。点一下正好只买防误触这一样。判据与被
  放弃的几条在 [ADR-0027](../../decisions/ADR-0027-进出室内改成点一下门.md)。
- **城区之间要一个「他真的是想走过去」的证据**，而边界是一条线，所以「朝那边走够久」就是那个证据。
  规则在[`地图与导航系统`](../../design/地图与导航系统.md)。
- **关卡片段转场要挡两样**：按键挡误操作，读条让脱离变慢 —— **它受击时只延长、打不断**。规则在
  [`关卡系统` · 片段之间是转场，不是无缝滚动](../../design/关卡系统.md)，本篇不复述。

⚠️ **别把这三种混着用。** 玩家会从前几次交互里学到规律，混用之后他学到的规律在下一个地方不成立。

## 二、交互点：一个 `Area2D`

最常见的形状是**一个 `Area2D` 加一个 `CollisionShape2D`**：

```
Workbench           (Node2D)          ← 工位本体（带一张图）
├── Sprite          (Sprite2D)
└── Reach           (Area2D)          ← 可交互范围
    └── Shape       (CollisionShape2D)
```

### 你要做的

- **摆位与范围。** 范围是你在编辑器里画的，**不是一个要给值的数**。判据：站在看起来"应该能用"的地方
  就该能用，而站在一眼看就够不着的地方不该能用。
- **给节点起一个稳定的名字**，因为脚本要按名字找它（或者用唯一名，见
  [脚本与节点接线](./脚本与节点接线.md)）。
- **让它在画面上看得出来是可交互的。** 这是纯表现，归你 —— 高亮、图标、轮廓光都行。

### 层与掩码怎么配

交互点只需要**看见角色**，不需要挡任何人：

- **层**：给它一个自己的层（比如「交互」层），这样别的东西不会误撞它。
- **掩码**：勾上角色所在的层。
- **`Monitoring` 开着**（我要知道谁进来了）；`Monitorable` 通常可以关。

⚠️ **层与掩码在项目设置里起个名**，否则半年后你看到一排勾选框认不出第 5 格是什么。

## 三、两种问法：等信号还是自己查

### 等信号（管「够不够得着」的那一类）

**没有一种交互是「走进去就发生」的**（上面那张表）。所以信号在本项目里**不负责触发**，它负责的是
**开关状态**：玩家进了范围就把提示显示出来、把「现在点得动」这件事记下来；出了范围反过来。

```csharp
public override void _Ready()
{
    _reach.BodyEntered += OnBodyEntered;
    _reach.BodyExited  += OnBodyExited;
}

public override void _ExitTree()
{
    _reach.BodyEntered -= OnBodyEntered;
    _reach.BodyExited  -= OnBodyExited;
}
```

⚠️ **订阅与解绑成对**，理由在[脚本与节点接线](./脚本与节点接线.md)那一节（自动解绑对自定义信号与
捕获变量的 lambda 不成立）。

### 自己查（按键或点一下那一类）

按键与点击触发的交互都该在**按下的那一刻**问「我现在够得着什么」，而不是等信号：

```csharp
if (_router.IsJustPressed(InputActions.Interact))
{
    foreach (var body in _reach.GetOverlappingBodies())
    {
        // ...
    }
}
```

⚠️ **`Area2D` 的重叠状态是上一帧的缓存**（[物理与碰撞](./物理与碰撞.md)那一节说过）。对交互这种
「慢」的事够用；对命中判定不够用，那里要主动形状查询。

⚠️ **输入一律经门面问**，不直接调 `Input.IsActionPressed`（[输入](./输入.md)第九节那条实测）。

## 四、多个交互点同时够得着时怎么办

这件事**不要留给引擎的返回顺序**。引擎给你一个数组，顺序不保证稳定 —— 表现是「同一个位置有时用这个
有时用那个」，而它不报错。

做法是**规则层挑一个**，判据显式写出来（离得最近、朝向对着的那个、优先级最高的那个）。挑法属于规则，
所以它可以被单元测试盯住。

## 五、站位点：`Marker2D`

节日场景里谁站哪、上课时学生站哪、演出里角色走到哪 —— 这些位置**由你在编辑器里摆**，代码往上填人。

`Marker2D` 就是为此存在的：它是一个只在编辑器里画一个十字、运行时什么都不画的 `Node2D`。

```
Festival            (Node2D)
└── Stands          (Node2D)
    ├── Stand1      (Marker2D)
    ├── Stand2      (Marker2D)
    └── Stand3      (Marker2D)
```

### 三条口径

- **数量与位置由你定**，规则层只管「把第几个人放到第几个位」。
- **命名要与规则层期望对得上。** 脚本按名字或按顺序取它们，名字是契约的一部分。
- **脚本缺站位点就报错说清缺谁，不自己补建。** 自己补建的后果是「忘了摆」被静默兜底成一堆叠在原点的
  角色 —— 而那看起来像个显示缺陷，查半天才发现是漏摆。

```csharp
[Export] public Godot.Collections.Array<Marker2D>? Stands { get; set; }

public override void _Ready()
{
    if (Stands is null || Stands.Count == 0)
    {
        throw new InvalidOperationException(
            $"{Name}：站位点没填（检查器里的「站位点」那个列表）");
    }
}
```

**导出一个列表让你在检查器里拖，比按名字查更好** —— 理由同[脚本与节点接线](./脚本与节点接线.md)那一节：
你重排层级或改名时它不会断。

## 六、交互提示画在哪

「按 E 使用」这类提示是**世界空间 UI**：它跟着那个物件走、随相机缩放，所以挂
`UILayer.WorldSpace`（见[界面控件](./界面控件.md)）。

⚠️ **不要挂进 HUD 层。** 表现是提示钉在屏幕角上，而玩家不知道它说的是哪个东西。

⚠️ **按键图标要随设备族换。** 键鼠玩家看到的是 `E`，手柄玩家看到的是面键 —— 门面已经在跟踪当前设备族
（[输入](./输入.md)第十二节），提示读它。

## 七、几种具体的交互点，各自的特别之处

| 交互点 | 特别之处 |
| --- | --- |
| **建筑的门** | **站在门口范围内点一下门**才进出（键鼠是鼠标右键、手柄是交互键），**不读条**；进与出同一条规则；两侧都是俯视，所以**不是视角切换**。判据在 [ADR-0027](../../decisions/ADR-0027-进出室内改成点一下门.md) |
| **城区边界** | 朝边界**持续移动**够久才切；不接管输入，所以不暂停；**两边各声明一次，载入时对账，不成对报错** |
| **关卡转场点** | 按键加读条；**往前那个方向在还有活着的敌人时被拒**，往回与撤离不锁 |
| **资源点与箱子** | 按键加读条；**受击中断且不消耗** |
| **工位与投料口** | 按键；产物堆满时**只拒不丢**，产出留在工位 |
| **商店门面** | 按键开界面 → 那是界面，所以**暂停世界** |
| **订货送达点** | 货到了就出现在这里，**不自动入库**，等玩家来取 |
| **床** | 按键触发每日结算 —— 那是一次转场，不是暂停 |

**这张表里每一行的规则都不在本篇**，它们各在自己那份系统文档里。本篇只负责「摆一个 `Area2D` 或
`Marker2D`」这件通用的事。

## 八、「当前操作格」不是交互点

俯视经营侧还有另一套东西：**当前操作格** —— 角色脚下那一格加上下左右四格（**不含斜角**），锄地、播种、
浇水都作用在那一格上。

它与交互点是两回事：

| | 交互点 | 当前操作格 |
| --- | --- | --- |
| 是什么 | 场景里摆的一个区域 | 一个算出来的格坐标 |
| 谁摆 | 你 | 没人摆，由角色位置与朝向算 |
| 表现 | 提示图标 | **一个框跟着角色走**，不是每格顶一个图标 |

**为什么不含斜角**：理由不是距离，是**俯视只有四个朝向** —— 指斜角时角色没有朝向可转。

**表现上两条硬约束**：够不到的格**照样画框、画成不可用**（而不是不画）；框**只勾一格边、不做整格
高亮**（高亮会盖住作物）。

## 九、动手练习：一个工位、一个门、三个站位

目标是把 `Area2D`、信号、`Marker2D`、缺配置报错走一遍。大约五十分钟。

1. **新建场景**，根节点 `Node2D` 改名 `InteractLab`。加一个 `CharacterBody2D` 当角色（照
   [物理与碰撞](./物理与碰撞.md)那个练习，能左右走就行）。
2. **摆一个「工位」**：`Node2D` 改名 `Bench`，下面一个 `Sprite2D` 与一个 `Area2D` 改名 `Reach`，
   给 `Reach` 一个矩形形状。
3. **配层与掩码**：在项目设置里给第 5 格起名「交互」，把 `Reach` 的层设成它、掩码勾上角色那一层。
4. **接信号**：脚本里订阅 `BodyEntered` / `BodyExited`，进出时打印一行。**记得在 `_ExitTree` 里解绑。**
   跑起来走进去、走出来，看日志。
5. **加一个提示**：在 `Bench` 下面加一个 `Label` 写「按 E 使用」，进区域时显示、出区域时隐藏。
   跑一下确认它跟着 `Bench` 走。
6. **按键那一半**：加一个「交互」动作绑 `E`，按下时用 `GetOverlappingBodies()` 查一次，打印查到了谁。
   对比第 4 步的信号写法 —— 两种都能用，但按键那一半必须在按下那一刻查。
7. **摆一个「门」**：另一个 `Area2D` 当门口范围。**进出这个区域只切换「现在点得动」这个状态**，
   真正进门要点一下鼠标右键 —— 站在范围外点**没反应**。**这一步是重点**：区域与触发是两件事，
   区域答「够不够得着」，点击答「他要不要」。
8. **三个站位点**：加一个 `Node2D` 改名 `Stands`，下面放三个 `Marker2D` 摆成一排。在脚本里导出一个
   `Godot.Collections.Array<Marker2D>`，把三个拖进去，在 `_Ready` 里把三个小方块（`ColorRect` 或
   `Sprite2D`）放到那三个位置上。
9. **故意把那个列表清空再跑** —— 应该当场抛，且报错说清是哪个节点的哪一格。**这一步是重点。**
10. **再故意只填两个**，看代码怎么处理「人比位多」。想清楚该报错还是该拒绝第三个人 —— 这个判断属于
    规则，不该在引擎层随手兜底。

做完你会有三个直觉：信号与主动查各自适合什么、`Marker2D` 是怎么把摆位交给你的、缺配置报错该长什么样。

## 十、这一篇里只能你实机看的

- **范围合不合手。** 站在看起来该能用的地方能不能用；站在明显够不着的地方会不会误触发。
- **提示看不看得出说的是哪个东西。** 两个交互点挨得近时尤其要看。
- **按键图标有没有随设备族换。** 插拔手柄各试一次。
- **两个交互点重叠时选的是哪一个。** 应该是可预期的（最近的那个），不该跳。
- **点门那一下顺不顺。** 三件事各看一遍：门口那个范围站在看起来该进得去的地方点不点得动、
  门看不看得出来「它是点得动的」、**两栋楼挨着时点到的是不是想点的那一栋**。最后那条是
  [ADR-0027](../../decisions/ADR-0027-进出室内改成点一下门.md)的主要风险 —— 消歧挑错不报错。
- **城区边界像不像出口。** 玩家要看得出「往这边走就出图了」，否则他会在边上来回走。
- **站位摆得好不好看。** 节日场景里九个人站成一排还是围成一圈，这是你的活。
