# 瓦片地图与地形

> 本篇回答：**一张地形图集怎么变成能刷的瓦片**、**怎么让瓦片挡住角色**、**边角怎么自动拼**，以及
> 本项目要用的**双网格**是什么、为什么 Godot 不原生给。
>
> ⚠️ **老教程在这一篇会害人**：4.3 之前用的 `TileMap` 节点**已经弃用**，现在是 `TileMapLayer`，
> 一个节点一层。搜到的答案里出现 `TileMap` 就要当心。前置是
> [坐标、像素与相机](./坐标像素与相机.md)。总纲在[本目录索引](./README.md)。

---

## 一、两个东西，一个是节点一个是资源

| | `TileMapLayer`（节点） | `TileSet`（资源） |
| --- | --- | --- |
| 是什么 | 一层瓦片。它记「第几行第几列放了哪块瓦片」 | 那套瓦片本身：图、碰撞、地形规则 |
| 一个场景里有几个 | 每层一个（地面一层、耕地一层、装饰一层……） | **一份就够，多层共用** |
| 谁改 | 你在 2D 视图里刷 | 你在底部的 TileSet 面板里配 |

**多层是常态。** 本项目基地那块地至少要两层：天然地形一层，已锄的耕地叠在上面一层 —— 于是「荒置退化」
就是把上层那一格清掉，底下那层自己露出来，**不必记「这格原来是什么」**。

## 二、建一个 `TileSet`

1. 选中 `TileMapLayer` 节点 → 检查器里 `Tile Set` 那一格新建一个 `TileSet`。
2. **先填瓦片尺寸**。本项目是 **16×16 世界像素**（基础单位，`rules/UI/UIMetrics.cs` 里那个
   `BaseUnit`）。这个数定了就不要改，整个经营侧的网格都按它算。
3. 底部会出现 **TileSet 面板**。把你的图集图片**拖进面板**，它会问「要不要自动建瓦片」，答要。
   引擎按你填的瓦片尺寸自动切，**完全透明的区域不会生成瓦片**。
4. 不想要的瓦片用面板顶上那个橡皮擦点掉，或者右键删除。

### 图集那几个属性

| 属性 | 作用 | 本项目 |
| --- | --- | --- |
| ID | 这个图集在本 `TileSet` 里的编号 | 引擎给，不用管 |
| 名称 | 给人看的名字（`terrain`、`decoration` 这种） | **起个名**，多图集时靠它认 |
| 边距（Margins） | 图片边缘不参与切片的像素 | 图集带署名边框时才用 |
| 间隔（Separation） | 瓦片之间的间隙像素 | 图集带分隔线时才用 |
| 纹理区域尺寸 | 每块瓦片多大 | 16×16 |
| 使用纹理内边距 | 给每块瓦片加一圈 1 像素透明边，防过滤渗色 | **保持开着** |

⚠️ **改了边距、间隔或区域尺寸之后瓦片可能丢**（有些跑到图片外面去了）。重新生成用面板顶上那个三点
菜单里的「在非透明纹理区域创建瓦片」。

## 三、`TileMapLayer` 参数逐条

| 属性 | 默认 | 作用 |
| --- | --- | --- |
| `TileSet` | — | 指着那套瓦片 |
| `Enabled` | 开 | 关掉这一层就不画也不碰撞 |
| `CollisionEnabled` | 开 | 这一层的物理层生不生效 |
| `CollisionVisibilityMode` | 默认 | 调试时画不画碰撞形状 |
| `NavigationEnabled` | 开 | 寻路（本项目不做寻路，可以关） |
| `OcclusionEnabled` | 开 | 光照遮挡（本项目视野遮挡不走这个，见下） |
| `YSortOrigin` | 0 | 开了 Y 排序时，这一层的排序基准点偏移 |
| `XDrawOrderReversed` | 关 | 横向绘制顺序反过来 |
| `UseKinematicBodies` | 关 | 瓦片碰撞用运动体而不是静态体 |
| `PhysicsQuadrantSize` | 16 | 碰撞按多大一块合并（性能项） |
| `RenderingQuadrantSize` | 16 | 绘制按多大一块合并（性能项） |

⚠️ **`OcclusionEnabled` 说的是光照遮挡**，与本项目的「视野遮挡」不是一回事。本项目的视野遮挡读的是
你在片段里摆的声明式区域，刻意不走引擎的射线与光照遮挡，理由在[物理与碰撞](./物理与碰撞.md)那一篇。

**性能提示**：瓦片更新是**批量到帧末**才生效的。刚 `SetCell` 完立刻去读碰撞可能还是旧的；真要立刻
生效调 `UpdateInternals()`。

⚠️ **坐标范围有上限**：`TileMapLayer` 序列化的格坐标是 16 位有符号整数，也就是 −32768 到 32767。
本项目可建造区 80×60 格，离这个上限很远，不会撞到。

## 四、格与世界坐标怎么换算

两个方法，方向相反：

```csharp
// 格坐标 → 本地坐标（那一格的中心）
Vector2 center = layer.MapToLocal(new Vector2I(3, 5));

// 本地坐标 → 格坐标
Vector2I cell = layer.LocalToMap(ToLocal(actor.GlobalPosition));
```

⚠️ **`MapToLocal` 给的是格中心，不是左上角。** 一格 16 像素，所以 `(0,0)` 那一格的中心是 `(8, 8)`。
把它当左上角用会让所有东西偏半格 —— 而半格偏移在像素图上很容易被当成「素材画偏了」。

⚠️ **`LocalToMap` 吃的是本地坐标**，所以要先 `ToLocal(全局坐标)`。这一层挪过位置时忘了转换会整体
偏移。

**别自己写 `位置 / 16` 这种换算。** 用这两个方法：将来如果瓦片尺寸或图层偏移改了，它们跟着变，而
手写的除法不会。

## 五、让瓦片挡住角色：物理层

1. 选中 `TileMapLayer` → 检查器里的 `TileSet` → **物理层**（Physics Layers）→ 添加一层。
   在那里填这一层的碰撞层与掩码（读法见[物理与碰撞](./物理与碰撞.md)）。
2. 回到 TileSet 面板，切到**选择模式**，点一块瓦片 → 中间那列展开「物理」→ 给它画一个碰撞多边形。
   面板会给一个默认的方形，拖顶点改形状，也可以加顶点做斜坡。
3. **一块一块画很慢**，用「瓦片属性绘制」（Tile Property Painting）批量刷：选好要刷的属性，然后像
   刷颜色一样在图集预览上刷过去。

⚠️ **没有物理层的瓦片不挡人，而且不报错。** 角色穿过地形时第一个该看的就是这里。

## 六、自定义数据层：给瓦片挂游戏数据

`TileSet` → **自定义数据层**（Custom Data Layers），可以给每块瓦片挂任意命名字段（比如「这是什么
地形」、「能不能锄」）。代码里读法是拿到那一格的 `TileData` 再按名字取。

三条要点：

- **数据挂在 `TileSet` 上，不是挂在放下去的那一格上。** 同一块瓦片的所有实例共享同一份数据。
- 要让某几格有不同的数据，得建**替换瓦片**（Alternative Tile）。
- **重排自定义数据的顺序不会弄坏已有数据**，编辑器会自己跟上。

**本项目的口径**：地块状态（未清理／可耕／已锄／已播种／待收／待清）**不存在瓦片里**，它在规则层。
自定义数据层适合装「这块瓦片本身是什么」这类不随游戏进程变的东西。判据与[资源与内容数据](./资源与内容数据.md)
那一篇的分界同源：**会变的是状态，不会变的才是数据。**

## 七、地形集：边角自动拼

这是让地形看起来像手画的那个功能。老名字叫「自动瓦片」（autotile），4.x 改成了**地形**（Terrain），
比自动瓦片强：**它支持一种地形过渡到另一种**，因为一块瓦片可以同时声明多种地形。

### 怎么配

1. `TileSet` → **地形集**（Terrain Sets）→ 新建一个，**选一个匹配模式**。三种：
   - **匹配角与边**（Match Corners and Sides）：最精细，对应老的 2×2 位掩码
   - **匹配角**（Match Corners）：对应老的 3×3
   - **匹配边**（Match Sides）：对应老的 3×3 最小集
2. 在这个地形集里建一个或多个**地形**（草、土、石各一个）。
3. TileSet 面板切到选择模式，点一块瓦片 → 中间那列展开「地形」→ 填**地形集 ID** 与**地形 ID**。
   `-1` 表示「没有」，所以要先把地形集设成 0 或更大，才能设地形。
4. 填完之后中间那列会多出**地形对接位**（Terrain Peering Bits）。这些位决定「周围是什么的时候用这
   一块」。`-1` 是特殊值，表示**空**。

**对接位怎么读**：一块瓦片如果八个方向的位都设成 0 或更大，它只在八个邻居都是同一种地形时出现；
如果左上、上、右上三位设成 `-1`，它就只在上方（含斜角）是空的时候出现 —— 那就是「草地的上边缘」
那一块。

⚠️ **地形集 ID 与地形 ID 互相独立，都从 0 开始而不是 1。**

**配好之后怎么用**：2D 视图里的瓦片绘制面板会多出一个地形模式，用它刷，引擎自动挑正确的那一块。
一块带地形数据的瓦片**既能当地形刷，也能当普通瓦片单独放**。

### 本项目的地形口径

- **交接用配对法**：会挨着的每一对地形各画一套过渡。已经定了哪几对要画、哪一对靠「隔一圈草」省掉。
- **耕地要干与湿两套**：形状相同，只换色带。
- **动态水是「静态水面瓦片 + 引擎原生的逐格帧动画」**，不写噪声扰动着色器 —— 扰动采样会落在非整数
  像素上，与最近邻和整数缩放冲突（那条在[坐标、像素与相机](./坐标像素与相机.md)里）。
- 画法本身在设计仓 [场景绘制约定](../../production/场景绘制约定.md)与[像素绘制原则](../../production/像素绘制原则.md)，
  本篇不复述。

## 八、双网格：本项目要用，而 Godot 不原生支持

### 它解决什么

普通地形拼接里，**一块显示瓦片对应一格数据**。要让所有边角都好看，一种地形得画到 47 块左右（十六种
基本情况乘上各种角的组合）。画量大，而且改一笔要改一堆。

**双网格**换个想法：**让显示层整体偏移半格**，于是每一块显示瓦片正好压在**四格数据的交叉点**上。
它只需要回答「我压着的这四格里，哪几格是草」—— 四格各有两种可能，一共 **16 种情况**，也就是 16 块图。

画量从约 47 降到 16，而且过渡自动就是对的。**代价是显示层与数据层不是同一个网格**，所以要一段代码
把数据层翻译成显示层。

### 落地状态与一条硬要求

**Godot 不原生支持双网格**，社区有现成实现可以参照。落地记在[待办台账](../../spec/issues/README.md)
的 `ENG-25`，它卡在场景本体（`ENG-21`）。

**那条硬要求是**：**要在编辑器里就看得出效果。** 否则你刷地形时是盲刷 —— 数据层长得跟画面完全不一样，
改一格看不出结果对不对。这一条会决定那段翻译代码写成 `[Tool]` 脚本还是别的形状。

⚠️ **功能性的格状态那一套不走双网格**，它用引擎内置的四边拼接模式就够（`ENG-25` 那条备注里写着）。

## 九、场景瓦片与 4.7 的 2D 场景画笔

`TileSet` 除了图集，还能装**场景集合**（Scenes Collection Source）：放下去的不是一张图，而是一整个
场景实例 —— 商店、环境音、粒子这类。

⚠️ **场景瓦片比图集慢得多**，每放一个都要单独实例化一遍。官方建议只在必要时用。

**4.7 给了一个更适合摆零碎件的东西**：**2D 场景画笔**（Scene Paint Mode，2D 视图里默认按 `B`）。
它像刷瓦片一样把场景实例刷进场景，但刷出来的是**真正的节点** —— 事后能在编辑器里单独选中和修改，
也**不受网格限制**。

**判据**：要**贴着网格**、而且这一格「就是地图的一部分」→ 场景瓦片；只是**撒一些东西**（装饰、收集物、
敌人初始位）→ 2D 场景画笔。

## 十、背景分层：`Parallax2D`

瓦片图层管的是**可以站上去的地面**。侧视片段还有另一半：**背景** —— 远处的山、天上的云、后面那排建筑。
它不参与碰撞，但它决定一块片段看起来在哪里。

**本项目的背景口径是「按组件分层拼」**：不整片手工画，而是把背景切成可复用的组件，同类地形跨片段复用。
理由是整片手工画会让片段数量变成瓶颈，而片段不重复是关卡不重复的唯一来源。画法在设计仓
[场景绘制约定](../../production/场景绘制约定.md)。

⚠️ **老教程在这里也会害人**：4.3 之前用的是 `ParallaxBackground` 加 `ParallaxLayer` 两个节点套着用，
现在是**一个 `Parallax2D`**，它自己就是一层。

### 参数逐条

`Parallax2D` 是一个 `Node2D`，把背景图当它的子节点放进去：

| 属性 | 作用 |
| --- | --- |
| `ScrollScale` | **最要紧的一个**：滚动倍数。1 是与相机同速；小于 1 更慢（看起来更远）；**0 完全不动**；大于 1 更快（看起来更近） |
| `RepeatSize` | 让子节点的纹理按这个间距重复。**比屏幕宽就得到无限滚动的背景**；某一轴填 0 就不重复那一轴 |
| `RepeatTimes` | 重复几份。相机拉远时不够铺满就加它 |
| `Autoscroll` | 自动滚动速度（像素每秒）。云自己飘用它 |
| `ScrollOffset` | 这一层的偏移，**不会被相机覆盖**（想手动挪就改它） |
| `ScreenOffset` | 也是偏移，但**会被相机自动更新**（除非关掉下面那项） |
| `IgnoreCameraScroll` | 关掉「跟着相机」。想完全自己驱动这一层时用 |
| `FollowViewport` | 是否被相机位置偏移。这一层放在独立的画布层里时，要与那一层的「跟随视口」设成一致 |
| `LimitBegin` / `LimitEnd` | 相机出了这个范围就停止滚动 |

⚠️ **进树之后改它的 `Position` 会被覆盖**（除非开了 `IgnoreCameraScroll`）。要挪位置改 `ScrollOffset`。

### 一条像素风要留意的事

背景偏移大致是「相机位移 × 滚动倍数」，所以**倍数不是整数的倒数时，偏移会落在半像素上** —— 而半像素
加最近邻采样就是那条会让画面发脏的组合（[坐标、像素与相机](./坐标像素与相机.md)第四节）。

⚠️ **这一条我没有实测**，是从「相机恒为整数世界像素」那条推出来的。**实机看背景滚动时有没有轻微抖**；
抖了就试把倍数改成 `0.5`、`0.25` 这类能整除的值，结论贴回来我记下。

## 十一、代码侧

```csharp
// 放一格。参数是：格坐标、图集 ID、图集里的格坐标、替换瓦片编号
layer.SetCell(new Vector2I(3, 5), sourceId: 0, atlasCoords: new Vector2I(1, 0));

// 清一格
layer.EraseCell(new Vector2I(3, 5));

// 读一格是什么
int source = layer.GetCellSourceId(new Vector2I(3, 5));
TileData? data = layer.GetCellTileData(new Vector2I(3, 5));

// 按地形连通性批量刷：引擎自动挑正确的边角块
layer.SetCellsTerrainConnect(cells, terrainSet: 0, terrain: 1);

// 这一层用了哪些格、占多大范围
Godot.Collections.Array<Vector2I> used = layer.GetUsedCells();
Rect2I rect = layer.GetUsedRect();
```

三条口径：

- **`SetCellsTerrainConnect` 是代码侧刷地形的入口**，别自己算该用哪一块边角。
- **图集 ID 与图集内格坐标别写死在代码里。** 需要按名字取某一块时，让它成为一个导出属性由你在检查器
  里填，或者走自定义数据层。
- **规则层碰不到这些。** 地块的状态机在 `rules/Economy/` 下，它不知道瓦片、图集、格坐标这些东西存在；
  引擎层负责把「这一格现在是已锄状态」翻译成「在耕地层放这一块瓦片」。

## 十二、动手练习：刷出一块能站上去的地

目标是走通图集 → 物理层 → 地形集这条链，并亲手看一次「忘了配物理层」。大约一小时。

1. **新建场景**，根节点 `Node2D`，加一个 `TileMapLayer` 改名 `Ground`。
2. **新建 `TileSet`**，瓦片尺寸填 16×16，把一张地形图集拖进底部面板，答「要」让它自动切。
3. **在 2D 视图里刷一片地**（选中节点后底部会切到瓦片绘制面板，选一块瓦片，在视图里拖）。
4. **加一个 `CharacterBody2D`** 站在那片地上面（照[物理与碰撞](./物理与碰撞.md)那个练习的做法，给它
   重力与左右移动）。**`F6` 跑一下 —— 它会穿过地面掉下去**，因为还没配物理层。
5. **配物理层**：`TileSet` → 物理层加一层；TileSet 面板切选择模式，给那块瓦片画一个方形碰撞。再跑，
   这回应该站得住。
6. **打开调试 → 可见碰撞形状**再跑，看那些方块碰撞。
7. **建一个地形集**，模式选「匹配角与边」，建一个地形叫「草」。给三到四块瓦片填上地形 ID 与对接位
   （至少配出「中间」「上边缘」「左上角」三种）。
8. **用地形模式刷一片**，看边角是不是自动挑对了。故意把某一块的对接位改错，再刷一次 —— 记住配错的
   样子（会出现一块明显不搭的瓦片）。
9. **加第二个 `TileMapLayer`** 叫 `Tilled`，共用同一个 `TileSet`，在 `Ground` 上面刷几格耕地。然后
   把其中一格擦掉 —— 底下的地面应该自己露出来。这就是「叠加层」。
10. **在脚本里打印 `LocalToMap(ToLocal(角色全局位置))`**，走动时看格坐标怎么变；再打印
    `MapToLocal(那一格)`，确认它给的是格中心。

做完你会有四个直觉：自动切片怎么工作、忘配物理层是静默的、地形对接位配错长什么样、叠加层怎么让退化
变简单。

## 十三、这一篇里只能你实机看的

- **边角拼得像不像手画的。** 这是地形集唯一的验收方式。
- **背景滚动有没有抖**，以及几层的远近感对不对。
- **两块地形交接处顺不顺眼。** 配对法要求会挨着的每一对各画一套 —— 漏了哪一对，那个交接就会生硬。
- **地形有没有挡住人。** 每种地形都要走一遍，漏配物理层不报错。
- **耕地那一层的干湿两套色带看不看得出差别。** 一屏之内要能分出哪些浇过。
- **半格偏移。** 所有东西整体偏了 8 像素，通常是把格中心当左上角用了。
- **双网格在编辑器里看不看得出效果。** 这是 `ENG-25` 落地时最要紧的验收项 —— 看不出来就等于盲刷，
  那条实现要重做。
