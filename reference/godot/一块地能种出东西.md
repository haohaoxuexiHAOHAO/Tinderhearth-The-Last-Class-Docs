# 一块地能种出东西

> **这一篇是跟着做的，别篇是查的。** 它带你把[从哪里开始](./从哪里开始.md)里同名那一格的里程碑
> 从头做到能玩：走到一格地上，锄它、播种、浇水，看它一天天变样，最后收上来一筐菜。
>
> **做出来的东西留下来，是游戏本体。** 不是练手样例，没有「做完删掉」这一步。
>
> **谁做哪一半**：节点树、素材、检查器里的值归你；把节点接到规则上的代码已经写好了（`ADR-0009`
> 的分工）。所以你要做的是**搭与填**，而每一步搭错了会得到一条说清缺谁的报错，不是静默不工作。
>
> **预计三到五小时，可以分几次做。** 第七步要画四张图，那一步的时间取决于你。

---

## 做完是什么样

一块地摆在屏幕上，你走过去，鼠标指的那一格被一个框勾着。**点一下鼠标左键**：

| 那一格现在的状态 | 按下去发生什么 | 你该看到 |
| --- | --- | --- |
| 未清理 | 清掉石头杂草 | 耕地层还没出现，但下一次按就能锄了 |
| 可耕 | 锄开 | 那一格变成犁开的土 |
| 已锄 | 播种 | 一颗种子出现在格子里 |
| 已播种 | 浇水 | 那一格的土变湿，逐格看得出来 |
| 待收 | 收获 | 作物消失，输出面板打出收了几件 |
| 待清 | 清掉枯株 | 枯株消失，回到已锄 |

按 `N` 推进一天，作物长一个阶段。

**一个键管六件事，不是简化。** 六个状态各自恰好对应一个玩家动作，所以「按下去做什么」由那一格
自己的状态答得出来 —— 这是[`地块系统`](../../design/地块系统.md)那台状态机形状的直接读法。
**代价写明**：这样你试不到「对着可耕地按播种被拒」那条路径，因为你没法主动选一个不该用的动作。
那条路径由规则层单元测试守着（`tests/Economy/PlotTests.cs`），实机要试到它得等工具栏（`GP-23`）。

## 开工前先确认三件事

1. **引擎跑得起来**：在代码仓根目录跑 `python tools/setup_godot.py --check`，它该报 4.7.2 的 mono 版。
2. **工程构建过**：跑一次 `dotnet build`，该是 0 错 0 警。**C# 脚本必须构建过一次，Godot 才认得出
   那些类** —— 没构建就在编辑器里找不到 `FarmWalker` 这些脚本，而那个症状看起来像文件放错了地方。
3. **打开工程**：用 Godot 打开代码仓根目录。左下角文件系统面板里能看到 `src/`、`rules/`、`data/`。

**已经替你配好、这一篇里不要再动的：** 逻辑分辨率 640×360、整数缩放、最近邻纹理过滤，三项都在
`project.godot` 里（理由在代码仓 `ARCHITECTURE.md`）。**尤其不要在场景或代码里覆盖纹理过滤** ——
覆盖成线性会让像素糊掉，而那不报错。

**一格 16 像素。** 这是全项目的基础单位（[玩法定位 · 像素基准](../../canon/gameplay/玩法定位.md)），
图块、背包图标、小型动物都占一格。相机不缩放，所以一屏正好看到 40×22.5 格 —— 这一篇要的一小块地
放得进一屏，**所以不需要相机**，走出一屏才需要，那是后面的事。

## 你会搭出来的节点树

先看终点，后面每一步往里加一样：

```
Farm                 Node2D              ← 场景根
├── InputRouter      Node                ← 挂 src/UI/InputRouter.cs
├── TerrainData      TileMapLayer        ← 天然地形，你刷。它不显示
├── TerrainDisplay   TileMapLayer        ← 天然地形，代码画。玩家看这一层
├── Tilled           TileMapLayer        ← 耕地，代码刷，你别手刷
├── Actors           Node2D              ← 勾 Y Sort Enabled
│   └── Player       CharacterBody2D     ← 挂 src/World/Farm/FarmWalker.cs
│       ├── Body     AnimatedSprite2D    ← 四向动画，你建 SpriteFrames
│       └── Shape    CollisionShape2D
├── Cursor           Node2D              ← 挂 src/World/Farm/FarmCellCursor.cs
├── Terrain          Node                ← 挂 src/World/Terrain/DualGridPainter.cs
└── Field            Node                ← 挂 src/World/Farm/FarmField.cs
```

**六个脚本已经写好了**，你不用写它们，但每一步都会讲它在读你搭的哪一样、为什么要读。

⚠️ **天然地形是两层，耕地是一层。** 这不是不对称的疏忽：天然地形走双网格（边界落在格子中线），
需要一层存数据、一层显示；耕地走四边拼接（边界落在格子边线），引擎原生支持，一层就够。
判据是「这一格是不是玩家单独操作的对象」，展开在[场景绘制约定](../../production/场景绘制约定.md)。

⚠️ **作物精灵不另开容器，它们与 `Player` 平级挂在 `Actors` 下。** 这一条有个必须知道的引擎行为：
父节点开了 Y 排序而某个子节点没开时，那个子节点参与排序，但**它自己的孩子会按它那一个 y 位置整体
渲染**（[官方说明](https://docs.godotengine.org/en/4.7/classes/class_canvasitem.html#class-canvasitem-property-y-sort-enabled)，
内容为合规做过改写）。所以要是给作物开一个单独的 `Node2D` 容器，整片作物会一起压在角色前面或后面，
而这**不报错** —— 只表现为「走到作物后面却压在它上面」。

## 第一步：新建基地场景

**目标**：有一个空场景能按 `F6` 跑起来，窗口是 1280×720 而里面是 640×360 的世界。

**做什么**：

1. 场景菜单 → 新建场景。
2. 点「其他节点」，选 `Node2D`，双击。它成为根节点。
3. 在场景面板里双击节点名，改成 `Farm`。
4. `Ctrl+S` 存成 `res://scenes/farm.tscn`。**节点名大写、文件名小写** —— 理由在
   [编辑器与场景 · 三、一个场景从零到能跑](./编辑器与场景.md)那一节末尾。

**为什么不直接改 `main.tscn`**：那一份是启动脚手架（内容加载、界面根、手环、HUD 都挂在它上面），
而你现在要的是一个能单独按 `F6` 跑、跑起来只有这一片地的场景。两件事分开，你改这一片地时不会
连带动到启动流程。等有了正式的开局流程再把它们接起来。

**跑起来该看到什么**（按 `F6`）：一个 1280×720 的空窗口，什么都没有。输出面板没有报错。

**看不到就是**：按 `F5` 而不是 `F6` 会跑 `main.tscn`（那是项目主场景），你会看到 HUD 与启动日志 ——
那不是错，只是跑错场景了。`F6` 跑的是当前打开的场景。

## 第二步：铺天然地形（双网格）

**目标**：你刷一片草、土、浅水和深水，边缘自动拼好，而且刷的时候完全不用管边缘。

素材已经在 `assets/self-drawn/tiles/` 下了，**一对地形一套，一套 64×64 = 4×4 共 16 张**：

| 文件 | 哪一对 |
| --- | --- |
| `grass-dirt.png` | 草 与 裸土 |
| `grass-shallow.png` | 草 与 浅水 |
| `shallow-deep.png` | 浅水 与 深水 |

**四种地形却只要三套，不是六套。** 会挨着的对才画：深水四周总是浅水、水与裸土之间总隔一圈草，
于是「草对深水」「裸土对任意水」几对靠地图纪律省掉（[场景绘制约定 · 基地要画哪几套](../../production/场景绘制约定.md)）。
**违反纪律不会静默画错** —— 四个角涉及的地形没有哪一套覆盖时代码当场报错，并指出是哪一格。

**文件名是「`<地形A>-<地形B>`」**，所以看名字就知道一套管哪一对。

⚠️ **这几张是从你放在工作区根目录那些缩回来的** —— 原图放大了 10 倍（640×640），直接导入的话
一格就是 160 像素而不是 16。缩回来是无损的（你用的是最近邻放大，像素没被破坏）。
**根治办法是导出时按 1:1**：Aseprite 的「导出精灵表」里把 Scale 设成 100%。放大只该发生在显示上。

### 先建数据层

1. 选中 `Farm`，加子节点 → `TileMapLayer` → 改名 `TerrainData`。
2. 给它新建一个 TileSet，**Tile Size 设成 16 × 16**。
3. 这一层需要四块「标记瓦片」——**它们不会被玩家看到**，只用来让你刷「这一格是哪种地形」。
   把三张图都拖进这个 TileSet（每次都让它自动创建瓦片），各取**四角全是同一种地形**的那一张：

| 标记 | 取哪张 | 在图集里 |
| --- | --- | --- |
| 草 | `grass-dirt.png` | 第 12 格（第四行第一格） |
| 裸土 | `grass-dirt.png` | 第 6 格（第二行第三格） |
| 浅水 | `grass-shallow.png` | 第 6 格（同样是第二行第三格） |
| 深水 | `shallow-deep.png` | 第 6 格（同样是第二行第三格） |

   规律是：**每套的第 12 格是四角全 A，第 6 格是四角全 B。** 按文件名就知道谁是 A 谁是 B。
   草在两套里都出现、而且颜色相同（实测都是纯色 `(163,179,64)`），浅水同理 —— 跨套同色这一条
   由 `tools/check_dualgrid.py` 判，所以你不用自己比。
4. 在这个 TileSet 里加一个**地形集**，模式随便（数据层不用拼接），加四种地形：**草、裸土、浅水、深水**。
   记下它们的编号——**从 0 起算**，所以草=0、裸土=1、浅水=2、深水=3。
5. 在 TileSet 面板的「绘制」标签里，把那几张标记瓦片各标上对应的地形。

⚠️ **这一层最后要关掉显示，但现在先别关。** 关掉它的 `Enabled` 之后引擎就不让你编辑这一层了，
而你还得往上刷地形。那一下放在「刷一片地」的末尾。

### 再建显示层

6. 选中 `Farm`，加子节点 → `TileMapLayer` → 改名 `TerrainDisplay`，**排在 `TerrainData` 后面**。
7. 给它新建 TileSet，Tile Size 同样 16 × 16。
8. 把三张图**各拖进去成为一个图集源**。记下各自的源编号（第一个是 0）。
   拖进去时它会问要不要自动创建瓦片，**三个源都要点是**，各该出现 4×4 共 16 格。
   `Texture Region Size` 不用改，默认的 16 × 16 正好切出这 16 格。
9. ⚠️ **不要给这一层配地形集。** 它的每一格由代码直接指定，不走引擎的拼接。

⚠️ **图集源只有纹理、没有瓦片的话，显示层一格都画不出来。** 代码按「源编号加图集格坐标」往显示层
写格子，那一格在图集里不存在时就写不进去。**这一条的表现会骗你**：你在数据层刷的标记瓦片还在，
看着像是「地面有了」，要到关掉数据层才发现底下什么都没有。

### 接上代码

10. 选中 `Farm`，加子节点 → `Node` → 改名 `Terrain`，附加 `res://src/World/Terrain/DualGridPainter.cs`。
11. 检查器里填：

| 格子 | 填什么 |
| --- | --- |
| `Data Layer` | 拖上 `TerrainData` |
| `Display Layer` | 拖上 `TerrainDisplay` |
| `Data Terrain Set` | 数据层那个地形集的编号，只有一个就是 `0` |
| `Pairs` | 数组大小填 `3`，每项新建一个 `DualGridPair` |

12. 三项按下表填，每项的 `Atlas Origin` 都是 `(0, 0)`：

| 第几项 | 哪一对 | `Terrain A` | `Terrain B` | `Display Source Id` |
| --- | --- | --- | --- | --- |
| 0 | 草与裸土 | `0`（草） | `1`（裸土） | `grass-dirt.png` 那个源 |
| 1 | 草与浅水 | `0`（草） | `2`（浅水） | `grass-shallow.png` 那个源 |
| 2 | 浅水与深水 | `2`（浅水） | `3`（深水） | `shallow-deep.png` 那个源 |

⚠️ **`Display Source Id` 要的是显示层那个 TileSet 里的源编号。** 三张图在数据层也各有一个源，
编号很可能不一样。拿错了画出来的是另一套交接，而**它不报错**。

**`Terrain A` 与 `Terrain B` 谁是谁不能填反。** 判法：图集里**四角全是 A** 的那一张编码为 0000，
也就是每套的第 12 格。按文件名就知道 —— `shallow-deep.png` 的 A 是浅水，所以那一项填 `2` 而不是 `3`。
填反了整套图会镜像地拼错，而**不报错**。这一条有机器判据（`tools/check_dualgrid.py` 会报出每套的
A 是哪种地形），拿不准就跑一下。

### 刷一片地

13. 选中 `TerrainData`，切到 TileMap 面板，用「草」那块标记瓦片刷一片 **10×8 格** 左右。
14. 再用「裸土」那块在中间刷几格。
15. 用「浅水」那块在草地边上刷一小片（三四格宽即可），**与裸土之间留出至少一圈草**。
16. 用「深水」那块在那片浅水的**中间**刷一两格，**四周留出至少一圈浅水** —— 深水不许直接碰到草。
17. 刷完之后，在检查器里把 `TerrainData` 的 **`Enabled` 取消勾选**。它只存数据，不该显示。

**刷水那两步里的「留一圈」不是美观建议，是省素材换来的代价。** 违反了代码会报
「四个角涉及地形 [...]，没有哪一对素材同时覆盖它们」并指出是哪一格 —— 补那一套，或者改地图。

**这一下必须排在刷完之后。** `Enabled` 管的是「这一层在编辑器里和运行时可不可见」
（[官方说明](https://docs.godotengine.org/en/4.7/tutorials/2d/using_tilemaps.html)，内容为合规做过改写），
所以关掉它之后 TileMap 面板会说这一层已禁用、不让你画。**以后要改地形就先勾回来，改完再关。**

刷的时候数据层开着不碍事：显示层排在它后面、画在它上面，而显示层四边各比数据区宽出半格
（往左上挪的那半格，加上右下多出来的一行一列），正好盖住那些纯色标记。**所以这一下顺带是个判据：关掉数据层之后地面还在，说明显示层真的画出来了。**
关掉之后整片地都没了，就是显示层还是空的，往下看那张表。

**该看到什么 —— 而且不用按 `F6`，编辑器里就看得见。** 你在 `TerrainData` 上刷一笔，`TerrainDisplay`
跟着变：草地里那几格土，**边缘是有机的曲线、从格子中间穿过去**，不是贴着格子边的直角。
你刷的时候一笔都没管边缘。

**编辑器里实时更新是刻意做的**，不是附带好处：双网格的显示层是算出来的，看不见就等于盲刷地形。
所以那个脚本带 `[Tool]` 标注、订阅数据层的变化信号。**改了 `Pairs` 或图集之后信号不会发**，
那时点检查器里那个「**重画显示层**」按钮。

**这就是双网格换来的东西**：一种交接只要 16 张，而同一网格上做八邻域自动拼接要 47 张。

**看不到就是**：

| 症状 | 原因 | 怎么办 |
| --- | --- | --- |
| 报「四个角涉及地形 [...]，没有哪一对的素材覆盖」 | 你让两种不成对的地形挨上了：水直接贴着土，或者深水直接贴着草 | 只画了会挨着的那几对。**让水与裸土之间总隔一圈草、深水四周总隔一圈浅水** —— 这是一条用地图约束换素材的纪律 |
| 报「`TerrainA`／`TerrainB` 是 -1／-1」 | 那两格没填。地形编号从 0 起算，-1 是「没填」 | 回「接上代码」那张三项的表 |
| 地面整体错开半格 | 你手动改了 `TerrainDisplay` 的 `Position` | 别改，代码会设成负半格。那不是摆位，是算出来的 |
| 边缘拼错、某几张位置不对 | 素材里 16 张的位置被调换过 | 那张映射表是从素材量出来的。调换素材位置要跟着改 `DualGridPainter` 里的表，**而它不报错** |
| 关掉数据层之后整片地都没了 | 显示层那几个图集源只拖了纹理、没创建瓦片，所以整层是空的 | 选中源点「自动创建瓦片」补齐 16 格，再点「重画显示层」 |
| 深水那片画出来是镜像拼错的 | 那一项的 `Terrain A` 填成了深水 | A 是浅水（填 `2`）。跑 `python tools/check_dualgrid.py` 会报出每套的 A 是哪种地形 |
| TileMap 面板是灰的，说这一层已禁用或已隐藏 | `TerrainData` 的 `Enabled` 关了，或者它被那只眼睛隐藏了 | 勾回来再刷，刷完再关 |
| 刷完之后还看得到那些标记瓦片 | `TerrainData` 的 `Enabled` 没取消 | 「刷一片地」的最后一步 |
| 关掉 `Enabled` 之后地面也跟着没了 | 关到了 `TerrainDisplay` 上 | 该关的是数据层。玩家看的是显示层 |
| 地面发虚、像素糊 | 纹理过滤被覆盖成线性 | 项目级已经是最近邻，场景与导入设置里都不要覆盖 |
| 地面在窗口外 | 刷的位置离原点太远 | 相机还没有，只看得到原点附近那一屏 |

## 第三步：让角色走在上面

**目标**：方向键按下去有东西在动，斜着按不会更快，而且朝哪一向走就显示那一向的图。

### 先把素材放到位

**四个方向各一套，代码不做水平翻转。** 主角缺一条手臂，镜像会让空袖子每次转身换边，而他是你
全程盯着的那一个（[ADR-0021](../../decisions/ADR-0021-每个朝向各画一套不做水平翻转.md)）。
**「各一套」不等于手画两遍** —— 想省就在绘图软件里镜像后导出，那是一次绘制决定，代码看到的只是
两套长得镜像的图。

素材放这里：

```
assets/self-drawn/player_topdown/
├── idle/   down/  up/  left/  right/
└── walk/   down/  up/  left/  right/
```

**逐帧 PNG，一个动作一个目录、目录里按朝向再分一层，文件名 `<动作名><序号>.png`、序号从 1 连续
不跳** —— 也就是 `idle/left/idle1.png`、`walk/left/walk1.png`、`walk2.png` 这样。这个形状与它的
理由在[像素绘制原则 · 逐帧交付与脚底锚点](../../production/像素绘制原则.md)，那一份写明了**朝向
为什么是目录层而不是文件名后缀**：少一整个目录一眼看得出，而后缀漏一个只是少一张图。

**俯视的精灵格是 32×32**（一格 16 像素，所以是两格高），四个方向都按这个画
（[玩法定位 · 像素基准](../../canon/gameplay/玩法定位.md)）。

⚠️ **目录名里的 `topdown` 是承重的。** 主角将来还要一套**侧视**的（关卡里打斗那一套，本体另一档、
只有左右两向，见同一张像素基准表），两套长得完全不同、不能混在一个目录里。

### 搭节点

1. 选中 `Farm`，加子节点 → `Node2D` → 改名 `Actors`。**在检查器里勾上 `Y Sort Enabled`**
   （在 Ordering 那一组下）。
2. 选中 `Actors`，加子节点 → `CharacterBody2D` → 改名 `Player`。
3. 给 `Player` 加子节点 **`AnimatedSprite2D`** → 改名 `Body`。
4. 选中 `Body`，检查器里 `Sprite Frames` 那一格点「新建 SpriteFrames」，**底部会弹出一个面板**。
   在那里按下表加动画，名字就是「动作_朝向」，一个字母都不能差：

   | | `down` | `up` | `left` | `right` |
   | --- | --- | --- | --- | --- |
   | 待机 | `idle_down` | `idle_up` | `idle_left` | `idle_right` |
   | 行走 | `walk_down` | `walk_up` | `walk_left` | `walk_right` |

   每个动画用面板里那个「添加帧」把对应目录里的图按序号拖进去，**勾上循环**，帧率先填一个数
   （待机慢、行走快，具体几帧实机调）。
5. 给 `Player` 加子节点 `CollisionShape2D` → 改名 `Shape`。它的 `Shape` 那一格新建
   `RectangleShape2D`，尺寸填 `12 × 8`。
6. **把 `Player` 的原点放在脚底。** 做法是调 `Body` 的 `Offset`：让图的底边落在 `Player` 的
   原点上（图高 32 就填 `Offset.y = -32`，并把 `Centered` 取消勾选）。
7. 选中 `Farm`，加子节点 → `Node` → 改名 `InputRouter`。给它附加脚本：右键 → 附加脚本 →
   **不要新建**，选「加载」，指到 `res://src/UI/InputRouter.cs`。
8. 选中 `Player`，同样附加 `res://src/World/Farm/FarmWalker.cs`。
9. `Player` 的检查器里现在多出三格：`Router` 拖上刚建的 `InputRouter` 节点、`Body` 拖上那个
   `AnimatedSprite2D` 节点、`Speed Pixels Per Second` 填一个数（先填 `60`，之后实机调）。

⚠️ **上表里每个动画名都必须逐字符对上。** 代码按「动作_朝向」现拼名字去取，缺哪一个在场景一跑
起来就被点名报出来 —— 这是 ADR-0021 唯一能自动判的那一条，所以它故意不拿另一向凑。

**代码一个字都不读上面那几个目录名。** 它只认 SpriteFrames 里那几个动画名；文件怎么分目录是给你
自己找图方便的，改目录不会把代码弄坏。分工就在这儿：**素材裁切、导入、动画帧与帧率归你在编辑器里
配，代码只决定此刻该播哪一个**（[ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md)）。

**为什么原点要在脚底**：俯视的前后遮挡按脚底的纵向位置排
（[场景绘制约定 · 前后遮挡按脚底位置排序](../../production/场景绘制约定.md)），而「当前操作格」
也要靠角色站在哪一格算。原点在图的中心时，他站的格会比看起来的高半格 —— 而这不报错。

**为什么碰撞形状比图小**：`12 × 8` 是他脚下占的地方，不是他整个人。俯视场景里挡住他的是地面上的
障碍，不是他的头。形状与图一样大会让他卡在门口过不去。

**为什么输入要经一个节点**：`InputRouter` 是输入门面。玩法代码一律经它问输入，不直接调
`Input.IsActionPressed` —— 理由是实测出来的：拦下事件之后轮询**仍然返回 true**，所以任何直接轮询的
代码都会在某些组合下看到不该看到的按键，而那不报错。展开在[输入](./输入.md)。

**动作名从哪来**：`move_left`、`move_right`、`move_up`、`move_down` 已经存在了 —— 它们由
`src/UI/InputMapInstaller.cs` 在运行时装进引擎，所以**编辑器里的输入映射面板是空的，那是对的**。
⚠️ **不要在那个面板里手加动作**，那是造出第二份来源，而两份漂移不报错。

**跑起来该看到什么**（按 `F6`）：

- 方向键（或 WASD）让角色移动，斜着按不比直着按快。
- 朝哪一向走就显示那一向的图；松开方向键，他停在那一向的待机上，不转回正面。
- 斜着按时朝向保持上一个，不会在两向之间来回跳。

**看不到就是**：

| 症状 | 原因 |
| --- | --- |
| 报「`Router` 没接上」 | 接线那一步里 `Router` 那一格没拖 |
| 报「`Body` 没接上」 | 同一步里 `Body` 那一格没拖。要拖的是**节点**，不是文件系统里那张图 |
| 报「还没有 SpriteFrames」 | `Body` 的 `Sprite Frames` 那一格是空的 |
| 报「缺这几个动画：……」 | 动画名拼错或漏建。名字是「动作_朝向」，朝向只认 `down`／`up`／`left`／`right` |
| 报「`SpeedPixelsPerSecond` 是 0」 | 速度那一格没填。它刻意没有默认值 |
| 走起来动画停在第一帧 | 那个动画没勾循环 |
| 纵向移动一卡一卡 | `MotionMode` 被改成了接地模式。脚本会设成浮空，别在检查器里改回去 |
| 完全不动 | 构建没过，或 `InputRouter` 那个节点没挂脚本 |
| 转身那一下角色横向挪了一点 | 四向素材的脚底不在同一列。**`Offset` 帮不上** —— 它是整个节点一个值，切不了单向，所以这个只能回改素材 |

## 第四步：加耕地那一层

**目标**：多一层空的瓦片图层，专门给锄过的地用。这一步还看不到东西，下一步接上状态机才看得到。

素材已经在 `assets/self-drawn/tiles/tilled.png`（240×240），从你那张 `arableland2.png` 缩回来的。

⚠️ **这一套的排布特殊，得靠 TileSet 的间隔参数切。** 你把 16 种情形画成了 16 个**十字**：每个十字
3×3 格，中心那一格才是真正要用的瓦片，四条臂是标注「这种情形下四个邻居各是什么」。十字之间隔 1 格。

**好消息是不用改图** —— Godot 的图集支持「边距 + 间隔」，正好能跳过四臂只取中心格。而且你那 16 个
中心格**逐像素互不相同**，说明 16 种收边你真的都画了（我核过）。

**做什么**：

1. 选中 `Farm`，加子节点 → `TileMapLayer` → 改名 `Tilled`。**把它排在 `TerrainDisplay` 后面**
   （场景面板里在下方，于是画在上面）。
2. 给它新建一个 TileSet，Tile Size 同样 `16 × 16`。
3. 把 `tilled.png` 拖进去成为图集源。**先别点「自动创建瓦片」**，先改参数。
4. 选中那个图集源，在检查器里填三项：

| 参数 | 填 | 为什么 |
| --- | --- | --- |
| `Texture Region Size` | `16 × 16` | 一格的大小 |
| `Margins` | `16 × 16` | 跳过第一个十字的左臂与上臂 |
| `Separation` | `48 × 48` | 跳过「右臂 + 间隔 + 下一个十字的左臂」 |

   算一下就知道为什么：第 0 格在 (16,16)，第 1 格在 16+16+48 = (80,16)，第 2 格 (144,16)，
   第 3 格 (208,16) —— 正好是四个中心格。第 5 个要 272 > 240，所以每行恰好 4 格。

5. 现在点自动创建瓦片，你该得到 **4×4 = 16 格**，每格都是一块耕地、没有十字的臂。
6. 在那个 TileSet 里点「地形集」（Terrain Sets）→ 加一个地形集 → 模式选 **Match Sides**。
7. 在这个地形集里加**两种地形**：第一种叫「干」，第二种叫「湿」。

⚠️ **湿那一套你还没画。** 干湿两套形状完全相同、只换色带，所以第二套是复制第一套改配色，画量很小。
在它画出来之前，第六步可以先把 `Wet Terrain` 也填成干那一种的编号 —— 那样浇水看不出变化，
但别的都能跑通。**这一条是这一步唯一欠的东西。**

8. 切到 TileSet 面板的「绘制」标签，选属性「Terrains」，把每一张瓦片标上它属于哪种地形、
   以及它的哪几条边是「连接」的。**16 张各对应一种邻居情形** —— 你画的十字四臂正好告诉你是哪一种。

**为什么是两层而不是一层**：已耕地是**叠在天然地形之上的独立一层**
（[场景绘制约定 · 地面分几层](../../production/场景绘制约定.md)）。这样荒置退化时清掉这一层，
底下那层自己就露出来了 —— 于是「这格原来是草还是裸土」根本不用存。存它就是给同一个事实开第二个家。

**为什么耕地是 16 张而不是 47 张**：它走**四边拼接** —— 只问「上下左右四个邻居里哪几个也是耕地」，
四条边两种答案，合起来 16 种。引擎原生支持这一种（内置地形模式里的 Match Sides），所以不需要写
任何代码。那 16 张各是什么在[场景绘制约定 · 四边拼接](../../production/场景绘制约定.md)那张表里。

⚠️ **天然地形那一层本该走另一套（双网格，边界落在格子中线）**，但 Godot 不原生支持它，要两层图层
加一段映射，归 `ENG-25`。**现在先让天然地形也用普通瓦片或四边拼接**，等你确定要画多少种地形
了再上双网格 —— 那时换的只有天然地形那一层，耕地这一层一个字不用改。

**为什么干湿是两种地形而不是一张图换色**：湿的**必须逐格看得出来**，否则你会重复浇或漏浇。两种
各自做四边拼接，所以一格湿的被干的围着时它显示成「孤立一格」那一张湿的 —— 那是对的，不是拼接错了。
两套形状完全相同、只换色带，所以第二套是复制第一套改配色，画量很小。

**跑起来该看到什么**：什么变化都没有（这一层还是空的）。但不该有报错。

## 第五步：框出当前操作格

**目标**：角色脚边那一格被一个框勾着，够不到的格框成另一个颜色。

**做什么**：

1. 选中 `Farm`，加子节点 → `Node2D` → 改名 `Cursor`。**排在 `Actors` 后面**，于是框画在角色之上。
2. 附加 `res://src/World/Farm/FarmCellCursor.cs`。
3. 检查器里填五格：
   - `Grid Layer` → 拖上 `Tilled`（或 `Terrain`，两层共用同一套网格，但**必须与下一步 `Field`
     接的是同一层**）
   - `Player` → 拖上 `Player`
   - `Router` → 拖上 `InputRouter`
   - `Reach In Cells` → 填 `1`
   - `Usable Color` 与 `Blocked Color` → 各挑一个颜色，**alpha 拉满**

**这一格的规则不是我随手定的**，它在[`界面系统` · 世界里那一层：当前操作格，两个设备族共用一个读口](../../design/界面系统.md)，
落成代码是三条：

- **键鼠取指针那一格，手柄取角色身前那一格，但对外只有一个读口。** 锄、播、浇、收以及将来的建造
  摆位都读同一个。分成两条调用路径之后，每加一个逐格动作就要在两侧各接一次，而漏接哪一侧不报错 ——
  表现只是「手柄玩家用不了这个动作」。
- **够不到的格照样画框，只是画成不可用。** 指针能指到屏幕任何地方，完全不画框的话你按下去没反应
  而找不到原因。
- **只勾一格的边，不做整格高亮。** 高亮会盖住那一格上的作物，而作物正是你要判断的东西 —— 你要看的
  往往正是「这一格能不能收」。

**可及范围是十字形，斜角够不到。** 理由不是距离，是**朝向只有四个**：指向斜角时角色没有对应的朝向
可转，表现就是他身子朝正面而手在斜着锄。`Reach In Cells` 填几由你实机试 —— 太紧则鼠标指偏一点就
够不到，太松则他看起来手伸得过长。这个量归 `GP-6`，所以它刻意没有默认值。

**alpha 为什么要拉满**：像素只许全透明或全不透明。半透明的框画上去就是屏幕上的插值像素，与最近邻
过滤和整数缩放三条纪律直接打架。

**跑起来该看到什么**：

- 动鼠标，框跟着鼠标跳格（一格一格跳，不是平滑跟随）。
- 把鼠标移到离角色两格以上、或斜角上，框变成另一个颜色。
- 插上手柄推一下摇杆，框跳到角色身前那一格并跟着他转向。

**看不到就是**：

| 症状 | 原因 |
| --- | --- |
| 报「`GridLayer` 没接上」或「还没有 TileSet」 | 第 3 步那一格没拖，或那层图层没建 TileSet |
| 报「`ReachInCells` 是 0」 | 那一格没填。它至少要 1 —— 设计定的形状是「脚下那一格**加**上下左右四格」 |
| 框与地面错开半格 | `Cursor` 接的图层与地面那层格大小不一样 |
| 框被地面盖住 | `Cursor` 在场景面板里排得太靠上。把它排到 `Actors` 后面 |
| 手柄推了框不动 | 门面要收到一次手柄事件才认定「最后用的是手柄」。推一下摇杆或按个键 |

## 第六步：接上地块状态机

**目标**：点鼠标左键真的能锄、能种、能浇、能收。这一步之后它就是个能玩的东西了。

**执行那一下是鼠标左键。** 经营侧的操作以鼠标为主：当前操作格在键鼠上取的就是「指针所在那一格」，
指针已经在指格子，执行也用鼠标才不用两只手换位。键盘 `F` 也绑着同一个动作、仍然可用，
但它是战斗侧的主键（那边右手在 `J`／`K` 上，腾不出来去点鼠标）。手柄上是右肩键。

**做什么**：

1. 选中 `Farm`，加子节点 → `Node` → 改名 `Field`。（是 `Node` 不是 `Node2D` —— 它不画东西。）
2. 附加 `res://src/World/Farm/FarmField.cs`。
3. 检查器里那一长串格子，按组填：

**接线那四格**（拖节点上去）：

| 格子 | 拖谁 |
| --- | --- |
| `Tilled Layer` | `Tilled` |
| `Crops Container` | `Actors` ← **不是新建一个容器**，理由见上面那条 ⚠️ |
| `Cursor` | `Cursor` |
| `Router` | `InputRouter` |

⚠️ **`Cursor` 那个节点的 `Grid Layer` 必须也接 `Tilled`，不能接 `TerrainDisplay`。** 显示层刻意往
左上偏了半格，拿它算格坐标会让框在这一格、锄的是旁边那一格。接错了会当场报错（我加了一条守卫），
但知道为什么比撞一次快。

**这一片地在哪那三格**：

| 格子 | 填什么 |
| --- | --- |
| `Field Origin` | 这片地左上角那一格的**格坐标**。在 TileMap 面板里把鼠标移到那一格，左下角会显示它的坐标 |
| `Field Size In Cells` | 几格宽几格高，先填 `8 × 6` |
| `Initial State` | 先选 `Uncleared`，这样你能从清理一路走到收获 |

**耕地图层那三格**（对上你在第四步配的地形集）：

| 格子 | 填什么 |
| --- | --- |
| `Tilled Terrain Set` | 那个地形集在 TileSet 里的序号，只有一个的话是 `0` |
| `Dry Terrain` | 「干」那种地形在这个地形集里的序号 |
| `Wet Terrain` | 「湿」那种地形的序号 |

**数值那四格** —— **它们都刻意没有默认值**，填 0 会当场报错：

| 格子 | 它是什么 | 先填 |
| --- | --- | --- |
| `Fallow Revert Days` | 已锄的空格连着几天没作物就退回可耕 | `3` |
| `Harvest Base Count` | 浇满水时一次收几件 | `3` |
| `Min Water Factor` | 一次没浇时的产量系数，**必须大于零** | `0.4` |
| `Max Water Factor` | 浇满时的系数，不得低于下限 | `1.0` |

**这四个数不是配置，是还没有值的量。** 它们归[数值模型](../../design/数值模型.md)的尚未给值表、跟
`GP-7` 走，所以代码里不留「看起来还行」的默认值 —— 有默认值的后果是场景那份会静默胜出，之后两边
都要花时间在「为什么跟常量不一样」。上面那几个数是让你先跑通用的，**不是平衡过的值**。

**下限为什么必须大于零**：一次没浇也不能颗粒无收。它挡的是「出征十天回来白干」，与「家畜不死只
停产」是同一条纪律。填 0 会报错并把这句理由打出来。

**最后一格**：`Planting Crop Id` 填 `test-turnip`。工程里已经有这条作物定义
（`data/crops/test-turnip.json`），它的字段旁边都带着说明。

⚠️ **「按下播种时播哪种作物」现在是检查器里填一个标识，这是脚手架。** 正式的选法要你手上有东西可选，
而「玩家怎么选一个逐格动作」在全库还没有编号持有 —— 那是一处已知的设计空白。最近的两个是 `GP-23`
（背包与仓库）与 `UI-27`（当前操作格，它只答「作用在哪一格」、不答「作用是什么」）。

**跑起来该看到什么**：现在还会报错 —— 它会说这几种作物有定义但没有素材。**那正是下一步要做的事，
报错说明接线是对的。**

**看不到那条报错、而是别的**：

| 报错说 | 意思 |
| --- | --- |
| `TilledLayer` 没接上 | 接线四格里漏了 |
| `FieldSizeInCells` 是 (0, 0) | 尺寸那一格没填 |
| `MinWaterFactor 必须大于零` | 那一格是 0。它没有默认值 |
| `data/crops/ 下没有作物定义` | 工程里那个 json 被删了或改坏了 |
| `PlantingCropId 是「」` | 最后那一格没填 |

## 第七步：画作物，配素材

**目标**：种下去能看到东西，而且一眼看得出哪一格能收了。

`test-turnip` 声明了 `stageDays: [1, 1]` —— 两个计时阶段加成熟 = **三个阶段**，所以：

**你要画四张图**：

| 第几张 | 是什么 | 画成什么样 |
| --- | --- | --- |
| 1 | 阶段 0：种子刚下地 | 土里一个小点或两片芽 |
| 2 | 阶段 1：幼苗 | 一小簇叶子 |
| 3 | 阶段 2：成熟 | **必须靠轮廓与上一张分开** |
| 4 | 枯死 | 读得出「这一株没了」，不是变个颜色 |

**尺寸**：宽 16（一格宽），高随你 —— 往上长出格子是对的，受约束的是它占几格、不是那张图多大。
**宽取偶数**，否则横向居中会差半像素（代码会取整吃掉它，但你画的时候心里有数更好）。

**成熟那一张是这一步唯一的硬要求，而且它是承重的。** 判法是[像素绘制原则](../../production/像素绘制原则.md)
里那条「关闭颜色后，剪影与负形仍能表达用途」。做法上一个向内收、一个向外张最省事：成株让茎叶向上
聚，成熟让植株高出一档并在顶端鼓出果实。

**为什么「能不能收」只能靠这张图**：刻意**不做**悬在格子上方的状态图标 —— 一屏几百格耕地各顶一个
图标会糊成图标海，而图标是界面语言，贴在世界里既不接地也不遵守光源那条投影规则。也刻意**不给**成熟
的植株做循环动效（那要给每种作物多画几帧，画量与回报不成比例）。所以你扫一眼田读不出哪几格能收时，
回头改的是这张素材，不是加一层提示。

**枯死那张为什么要认真画**：枯株会停在地里直到你清掉，所以它是一个会被盯着看的状态，不是一闪而过的
过场。让它自动消失的路被否掉了 —— 那样你说不出自己损失了什么。

**做什么**：

1. 四张 PNG 存到 `assets/self-drawn/crops/` 下（目录自己建）。名字随你，比如 `turnip-0.png`。
2. 拖进 Godot 一次让它导入。**导入设置不用改** —— 项目级已经配好无损、不生成 mipmap、不检测 3D。
3. 文件系统面板里右键那个目录 → 新建 → 资源 → 搜 `CropArt` → 存成 `turnip.tres`。
4. 双击 `turnip.tres`，检查器里填三格：
   - `Crop Id` → `test-turnip`（**必须与那个 json 里的 `id` 逐字符一致**）
   - `Stage Textures` → 点开，数组大小填 `3`，按顺序拖进三张生长阶段图
   - `Withered Texture` → 拖进枯死那张
5. 回到 `Farm.tscn`，选中 `Field`，把 `Crop Arts` 数组大小填 `1`，把 `turnip.tres` 拖进去。

**为什么素材走 `Resource`（`.tres`）而作物的天数走 JSON**：切线是「它进不进判定」。阶段天数、季节
列表、收获后退回哪一阶段会被规则层读去算，所以它们是数据文件（`ENG-5`：内容外置，mod 能换）；
而**长什么样**归你在 Godot 里配。所以「缺哪个字段报错」在规则层，「缺哪张图报错」在引擎层 ——
规则层一行都看不见素材路径。这条分线以后每个内容类型都会遇到，理由在代码仓 `ARCHITECTURE.md`。

**为什么靠标识配对而不是靠数组顺序**：顺序对不上不报错，只表现为「萝卜长出了土豆的样子」。

**跑起来该看到什么**（按 `F6`，站到地里用鼠标指一格、点左键）：

1. 第一下：那一格清掉了（还看不出变化，因为天然地形没变）。
2. 第二下：**那一格变成犁开的土**。四边拼接开始工作 —— 锄第二格时两格之间的收边会自动合起来。
3. 第三下：一颗种子出现在格子里。
4. 第四下：那一格的土变湿，逐格看得出来。
5. 按 `N` 两下：作物长到成熟。
6. 再点一下：作物消失，输出面板打出「收上来 N 件 test-turnip-root」。

**看不到就是**：

| 症状 | 原因 | 怎么办 |
| --- | --- | --- |
| 报「声明了 3 个阶段，所以要有 3 张」 | `Stage Textures` 数组大小不对 | 阶段数 = `stageDays` 项数 + 1 |
| 报「第 N 阶段那一张是空的」 | 数组里有一项没拖图 | 按报错说的那个序号补上 |
| 报「缺 `WitheredTexture`」 | 枯死那张没配 | 第 4 步 |
| 报「素材配的作物「x」没有对应的作物定义」 | `Crop Id` 与 json 里的 `id` 不一致 | 逐字符对一遍 |
| 报「这几种作物有定义但没有素材」 | `Crop Arts` 里没把 `.tres` 拖进去 | 第 5 步 |
| 作物出现但沉在土里或飘在格子上方 | 图的高度与定位对不上 | 代码按「底边贴格子底边」摆，检查图里有没有多余的透明边 |
| 作物永远压在角色前面 | `Crops Container` 接了一个单独的容器 | 改接 `Actors` 本身 |
| 土没变湿 | `Wet Terrain` 序号填错，或那几张瓦片没标地形 | 回第四步第 5、6 步 |

## 第八步：把这一天走完

**目标**：理解那个 `N` 键推的是什么，以及它为什么是临时的。

`N` 是**开发期的调试键**，它调的是 `FarmField.AdvanceDay()`。三件事在那一下发生：正在长的作物往前
推一天、已锄的空格荒置计时加一天、当天那个浇水标记被清掉（所以湿的表现每天早上回到干）。

⚠️ **这个键刻意不过输入映射。** 它是工具键不是玩法绑定 —— 混进去会让「玩家能重绑的键」那份清单里
多出一个他根本不该看见的条目。侧视那个训练房里的三个调试键同一条理由。

**正式的一天推进是睡觉那条路**，走每日结算那串固定步序（`GP-56`，就是[从哪里开始](./从哪里开始.md)
里「睡一觉能推进一天」那一格）。两件事现在还不在：

- **换季枯死**。`Plot` 已经有那个方法，但**它必须排在按天推进之前** —— 反了的话换季那天的作物会先
  白长一天再枯死。季节本身还没有代码。
- **下雨算浇过**。降雨类那天这一格按浇过算，而且**算满**不算一半。天气那一侧归 `GP-93`。

**按天推进为什么不新开一个结算步骤**：那串步序一步不增是正典的硬约束，而上面那三件事都是「地块上的
东西按天推进」，属同一步的内部工作。

**跑起来该看到什么**：

- 种下去按 `N` 两下到成熟（`stageDays: [1, 1]` 就是每阶段一天）。
- 浇过水的格子按一下 `N` 之后变回干的。
- 锄一格空着不种，按 `N` 三下（`Fallow Revert Days` 填的那个数），它退回可耕 —— 犁开的土消失了，
  底下的天然地形露出来。**这一条顺带证明了两层图层是对的**：退化不需要记得「这格原来是什么」。

**想试循环收获**：把 `data/crops/test-turnip.json` 里的 `regrowFromStage` 从 `null` 改成 `1`，
重跑。收获之后它退回阶段 1 再长，**素材一张都不用加**。填 `2`（成熟那一阶段）或更大会在载入时被拒，
因为退回去立刻又待收，等于一次收获就能无限收下去。

## 跑一遍验收

**机器判得出的那一半**：在代码仓根目录跑 `python tools/verify.py`，每一步都该过。它判的是命名、
行尾、构建、规则层测试、导出包里有没有不该有的东西、产物跑不跑得起来 ——
**一条都不判你这一片地好不好玩。**

**这一篇里只能你实机看的**，照[从哪里开始](./从哪里开始.md)里同名那一格的「怎么算做完」：

- [ ] 四个动作（锄、播、浇、收）各做一次，每一次都**看得见结果**。
- [ ] 一格锄过没锄过，站在田边扫一眼分得出来。
- [ ] **一屏之内分得出哪几格浇过水。** 这一条是干湿两套素材的验收。
- [ ] 成熟那一阶段与前一阶段在实际尺寸下分得开，**关掉颜色也成立**。
- [ ] 走到作物后面，他被作物挡住；走到作物前面，他压在作物上。（Y 排序那一条。）
- [ ] **四向各走一遍再停下**：朝向认得出来，转身那一下他不横向挪，空袖子也不换边。
      （[ADR-0021](../../decisions/ADR-0021-每个朝向各画一套不做水平翻转.md) 交回给你的那个判断
      就是这一条 —— 镜像了好不好看只有眼睛判得了。）
- [ ] 待机与行走的帧率：待机太快像抽搐，行走太慢像滑步。
- [ ] 框跟着鼠标跳格，够不到的格框成不可用的样子。
- [ ] `Fallow Revert Days` 那个值合不合适 —— 太短会罚出征的你，太长则荒置这条规则形同虚设。
- [ ] 角色走动速度与可及范围那两个数，拖着调到手上舒服为止。

**最后两条是这一步真正的产出。** 那几个量本来就没有值，你实机调出来的数才是它们的第一版 —— 调完
把结果说一声，它们会登进[数值模型](../../design/数值模型.md)。

## 卡住了：按症状查

**先看输出面板。** 这一批脚本的报错都写清了缺哪一样、要的是什么、以及为什么它没有默认值 ——
所以「报错说什么」通常就是答案。展开怎么排查在[调试与实机验收](./调试与实机验收.md)。

| 症状 | 最可能的原因 |
| --- | --- |
| 编辑器里找不到 `FarmWalker` 这些脚本 | C# 没构建过。跑一次 `dotnet build`，或在编辑器里点右上角的构建 |
| 附加脚本时它让我新建 | 选「加载」而不是「新建」，指到 `src/` 下那个 `.cs` |
| 检查器里看不到那些导出格子 | 脚本没挂上，或构建之后没重新选一下节点 |
| 一按 `F6` 就报一长串 | 从上往下看第一条 —— 后面的往往是第一条的连带 |
| 报错说「没接上」但我明明拖了 | 拖的是场景里的节点还是文件系统里的文件？这几格要的是**节点** |
| 框与作物都在，但按键没反应 | `Field` 的 `Router` 没接，或那一格够不到（框的颜色会告诉你） |
| 像素发虚 | 有人覆盖了纹理过滤。项目级已经是最近邻，场景与代码里都不要动它 |
| 移动时角色抖动 | 位置落在了非整数像素上。展开在[坐标、像素与相机](./坐标像素与相机.md) |

## 接下来

这一片地能玩之后，经营循环还差一步才闭合：**睡一觉能推进一天，而且退出再进来进度还在。**
那是[从哪里开始](./从哪里开始.md)里「睡一觉能推进一天」那一格。

**在那之前你可以先把这一片地做厚**，下面这些互不依赖：

- **把天然地形画好**（现在可能还是占位图）。要画哪几套、哪两对可以靠地图约束省掉，在
  [场景绘制约定](../../production/场景绘制约定.md)。
- **把角色的劳作动作画出来** —— 锄、播、浇、收各一套四向。现在这四个动作按下去地块真的变了，
  但角色本人没有动作，所以**反馈全在地上、人是静止的**。接动画的做法与「为什么攻击帧不让引擎
  自己跑」那条约束在[精灵与逐帧动画](./精灵与逐帧动画.md)；**要先有编号再接代码**，因为那几个
  动作的帧数是手感量。
- **多加一种作物**。写一份 json 加一份 `.tres`，代码一行不用改 —— 这一条顺带验证了「内容按声明扩展」
  真的成立。起步要有几种在[内容规模基准](../../canon/gameplay/玩法定位.md)那张表里。

**碰到新的事就说。** 它会变成[待办台账](../../spec/issues/README.md)里一个新编号 —— 那样三个月后你
想起「那件事后来怎么了」时查得到。
