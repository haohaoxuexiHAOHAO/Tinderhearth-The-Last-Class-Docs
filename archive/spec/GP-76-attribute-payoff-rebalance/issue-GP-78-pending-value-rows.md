# GP-78：尚未给值表补上新增量，并把它们接进那条配对要求

> **历史背景·非依据。只读归档件，不得作为现行依据。** 现行事实见同目录 [`prd.md`](./prd.md) 的「归档三问」；待办见[待办台账](../../../spec/issues/README.md)。

## 目标

新增的每个派生量在尚未给值表里各有一行，写明为什么不给、怎么校准、归谁；那条「不得出现某一项属性严格优于另一项」的配对要求把新增的量算进去。

## 来源

- PRD：同目录 [`prd.md`](./prd.md) 的 `US-002` 后半

## 依赖

`GP-76` —— 登记哪几个量取决于正典最后定的分法。

**与 `GP-77` 分开是因为验证方式不同**：那一条改完要跑推演才知道对不对，本条加的是登记行，没有任何工具判得了，只能人读。合成一条会让「脚本跑过了」被当成两半都通过。

## 验收标准

- [x] [数值模型 · 尚未给值的量，各自写明校准办法](../../../design/数值模型.md) 里为新增的每个量各有一行，三格（为什么不给、校准办法、归属）都填了
- [x] 那条「不得出现某一项属性在任何构筑下都严格优于另一项」写明给值那一轮要把新增的量一起算进去 —— 它们都不进战力公式，所以 C1 看不到它们
- [x] 力量那份精力折扣那一行写了两条配对要求：接进 P1 并写明按哪一级属性当基准；幅度不得大到让「派谁去」有唯一答案
- [x] 体力条回复速度那一行写了配对要求：要与 `resources.sp_dodge` 和 `resources.sp_guard_per_second` 一起看，否则体力条不再是预算
- [x] 「攻速能缩到的下限」那一项写明它现在挡的是天赋与状态叠起来的总量，不再是「敏捷堆满」
- [x] 韧性上限那一行写出失衡值增量的基底来自攻方的力量、韧性上限来自受方的体质，所以校准的是两个系数的比
- [x] `python tools/simulate_week.py --check-doc` 通过
- [x] `python tools/check_docs.py` 0 FAIL

## 实现笔记

### 设计决策

- **模糊点**：这三个量到底登记成「一行一个」还是并进已有的行。
- **选择**：失衡值增量并进已有的韧性上限那一行；另两个各占一行。
- **理由**：失衡值增量与韧性上限**必须一起校准**（校的是两者的比），分两行会让人以为可以各自定；另两个各有自己的配对对象（一个配 SP 的花费项，一个配各渠道的精力收益），并到别人那一行会让那一行有两套校准办法。

### 偏离

无。

### 权衡

考虑过给三个量各配一个未校准起步值，那样它们在参数表里看得见。放弃了，理由在 `GP-77` 的「偏离」那一节：没有判据读得到的值就是没人看着的值。

### 待确认

无。
