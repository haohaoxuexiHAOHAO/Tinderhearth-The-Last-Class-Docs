# ENG-12：发行包不得含占位素材的导出守卫

## 目标

发行包里出现任何非作者自绘的素材时导出验收判失败，使"开发期随便用、发行时只用自己画的素材"这条约束有执行体。

## 来源

- 作者 2026-08-30 定的工作方式与前提：代码仓是私有单人仓库，私有持有不构成再分发；**真正的分发行为是发行包**。
- 因此守卫落在导出而不是入仓。落点已存在：`verify.py` 的导出那一步本来就解 `.pck` 逐条看清单（`ENG-3`，见[踩坑记录 33](../../reference/踩坑记录.md)）。
- PRD：[`spec/prd-ui-framework.md`](../prd-ui-framework.md) 第 8 节

## 依赖

`ART-4`（要有登记表才知道哪些是占位件）。

## 验收标准

**分两档，否则这条守卫会从第一天起一直红。** 2026-08-30 撞出来的：`ART-4` 落地后包内条目从 15 涨到 63，占位件本来就该在开发期的包里。如果"包里有占位件就判失败"，门禁会红到所有素材替换完为止 —— 那种守卫的实际后果是大家学会绕过它，连真失败一起绕。

日常导出（默认）：

- [x] **未登记的素材判失败**，报出是哪几个文件 —— `audit_release_assets` 报未登记清单，`manifest_report` 判失败；自证 `case_unregistered_in_pack`
- [x] 占位件与下载件**不判失败**，但报出剩余数量 —— 日常实测报「还有 28 个待替换成自绘件」，`verify.py` 5/5 过
- [x] 自报覆盖量：包内素材总数、登记命中数、未登记数、待替换数 —— 实测「登记域素材 29：命中 29、未登记 0、待替换 28」

发行导出（`--release` 或等价开关）：

- [x] **包内出现任何非作者自绘的素材即判失败**（占位件与下载件一视同仁）—— `verify.py --release` 实测在导出步判失败、列出 28 个非自绘素材；字体按「可进发行包」字段放行、不在内

## 判据 2026-08-31 收窄过一次，理由记下来

原先写的是**"许可证明确允许作为游戏的一部分分发"，不是"必须 CC0"** —— 那是 2026-08-30 撞出来的：作者下载的侍武士素材允许商业使用与随游戏分发，只禁止把素材本身转售或做成 NFT，按 CC0 一刀切会误杀它。所以当时登记表记的是**许可证依据原文**加一个判定，不是一个布尔值。

**作者 2026-08-31 收窄成"发行包只允许自己画的素材"**，下载件只在开发阶段缺素材时顶一下。收窄不是因为原判据错了，而是因为它**贵**：每换一个素材包都要重读一次法律文本，而那个判断没有执行体，只能靠人每次做对。收窄之后判据变成"是不是作者画的" —— 机器判得死。

两条后果要记住：

- **许可证仍然要读、要登记。** 它不再决定能不能进包，但决定**开发期能不能放心用**（有些素材连开发期使用都受限）。登记表的许可证依据原文字段保留。
- **收件箱按桶分**（`self-material/` 与 `other-material/`，作者 2026-08-31 定），所以"是不是作者画的"在接仓那一刻就有依据，不必事后追溯。`tools/inspect_art_inbox.py` 按桶判并对下载包强制要求许可证文件。

**字体不在这条之内**（`UI-8` 落地时定的，2026-08-31）。素材登记表新增的「字体」一节里
`可进发行包: true`，依据写在那一栏：本条针对的是**美术素材**（占位件与下载件），而字体是
[ADR-0008](../../decisions/ADR-0008-中文像素字体选型.md) 选定的**永久依赖**而不是占位件，
SIL OFL 1.1 明确允许随软件分发与出售，且没有字体游戏就没有文字。所以本条实现时**必须按登记表的
「可进发行包」字段判，不能按「在不在 `assets/placeholder/` 或 `assets/downloaded/` 下」判** ——
后者会把字体一起拦掉。**作者 2026-08-31 确认：字体算例外，`可进发行包: true` 成立。** 于是本条实现
时按登记表字段判这条从推断变成已定的实现约束；「只许自绘覆盖字体、需自造两万字像素字体」那条路不走。
例外不取消 OFL 义务 —— 字体随发行仍附 `LICENSE-OFL.txt`（`ART-3` 已做）。

共同：

- [x] 检查接在 `verify.py` 已有的解包清单那一步里，不新增一条并行门禁 —— 落在 `manifest_report`，由导出步 `step_export` 调用
- [x] 自证：往包里塞一个未登记素材确认拦得住；`--release` 下塞一个占位件确认拦得住；还原后复验通过 —— `--release` 用真包端到端（真包本就含 28 占位件与下载件）；未登记与「字体按字段」用合成清单直接撞审计函数（真包里没有未登记素材，也不该为自证往仓库塞）；`selfcheck_verify.py` 还原后复验通过、仓库干净
- [x] 改了 `verify.py` 就跑 `python tools/selfcheck_verify.py` —— 20/20 全绿

## 实现笔记

### 设计决策

- **按登记表「可进发行包」字段判，不按路径**：issue 已把这条从推断定为实现约束，实现照做。理由：字体在 `assets/fonts/` 下却是永久依赖（可进发行包=true），按「在不在 placeholder/ 或 downloaded/」判会误杀字体。实测字体两档都放行。
- **枚举包里 `assets/**.import` 作为素材源**：模糊点是「包里素材怎么数」—— 纹理导入成 `.godot/imported/*.ctex`（内容哈希名、不带源路径），字体成 `.fontdata`。选择：数 `assets/` 下的 `.import`（每个源素材一个，去 `assets/` 前缀与 `.import` 后缀正好是登记路径）。理由：`.import` 带完整源路径、与登记表一一对应；`.ctex` 哈希名要反查、文件名可能撞。
- **分两档（日常／`--release`）**：日常放行占位件只报数、拦未登记；`--release` 一律不许非自绘。理由见 issue「分两档」—— 占位件本就该在开发期的包里，若「有占位件就失败」门禁会从第一天红到替换完，实际后果是大家学会绕过它。
- **落在 `manifest_report` 里、不新增并行门禁**：导出步本来就解 `.pck` 逐条看清单（`ENG-3`），加一条按登记表审即可。
- **读不出登记表就判失败**：审不了素材不能当没这回事（同 `parse_pck` 空清单的失效方向）。

### 偏离

- 方案无偏离：判据、落点、两档、字体例外 issue 都写死了，实现照做。
- **一处超边界的顺带修复（记账于此）**：跑 `selfcheck_verify.py` 时发现 `case_wrong_root` 一直红 —— 它只拷 `verify.py` 到假目录、没拷同目录依赖 `loglib.py`，导致 `ModuleNotFoundError` 崩在 `check_root` 之前，测不到它本该测的东西。根因确认（`verify.py` 有 `from loglib import ...`）：回归来自 `loglib` 那次提交（`9332f30`）没同步更新这条用例。补拷 `loglib.py` 并加注释提醒「新增 `verify.py` 同目录依赖要跟着加」。属修守卫本身，不是本条范围，但不修 `selfcheck` 就一直红。

### 权衡

- **枚举 `.import` vs 枚举 `.ctex`/`.fontdata`**：`.import` 带源路径、一一对应登记表；`.ctex` 是实际数据但哈希名要反查。选 `.import` —— 它是源素材清单，且 `.ctex` 必与 `.import` 成对，不会有孤立 `.ctex` 源自 `assets/`。
- **未登记检查：函数级自证 vs 端到端注入**：`--release` 拦占位件用真包端到端（真包就含 28 占位件），比注入更强；未登记与「字体按字段」用合成清单直接撞审计函数 —— 真包里没有未登记素材，也不该为自证往仓库塞一个（同 `selfcheck` 造垃圾的教训）。

### 待确认

- **`icon.svg`（应用图标）不在本守卫范围**：它在根目录、不在 `assets/` 树也不在登记表，本守卫按 `assets/**.import` 枚举自然排除它。它现在是 Godot 默认图标（995 字节），发行前应换成自绘图标。要不要把应用图标也纳入守卫（登记它或单开一条）？（作者定，本条不扩范围）
- **`--release` 目前不改导出命令、只收紧审计**：导出仍是 `--export-release` 产同一个 `.pck`。若将来发行导出要用不同预设（图标／签名等）另议。
- **未新增踩坑记录条目**：核心坑（打包资源哈希名不带源路径、要靠 `.import` 反查；按路径判会误杀字体）已写进 `verify.py` 的 `audit_release_assets` 与 `parse_pck` docstring（永久留在代码仓），归档不会丢，故不另开踩坑条目。
