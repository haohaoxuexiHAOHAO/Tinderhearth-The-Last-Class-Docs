# ART-4：占位素材生成器与素材槽位登记表

## 目标

有一条可重跑的入口按最终规格产出占位素材，并有一份登记表记住每个槽位的规格与来源，使作者用自己的像素资源替换时不需要改任何代码。

## 来源

- 作者 2026-08-30 定的工作方式：占位素材先跑通逻辑，最终由他用自己的像素资源替换。他画图需要时间，不可能一次性提供全部素材。
- PRD：[`spec/prd-ui-framework.md`](prd.md) 第 8 节「占位素材」三条约束

## 依赖

无。但它阻塞 `UI-8`（HUD 要素材才摆得出来）与 `ENG-10`（守卫要登记表才能比对尺寸与槽位）。

## 实现笔记

> 实现落在更早的窗口（代码仓 `tools/gen_placeholders.py` 与 `asset-registry.json` 已提交），本节据代码、登记表与验收标注、2026-08-31 复验重建。

### 设计决策

- **PNG 用 zlib 手写、不引 Pillow**：模糊点是生成占位件通常用图像库。选择手写 RGBA8 PNG（约 40 行）。理由：本机无 Pillow，为几个纯色几何件加依赖不值，且生成器要 clone 完直接能跑；读素材图那一处（`check_assets`）才破例装 Pillow。
- **输出逐字节确定**：固定 zlib 压缩级别、不写时间戳块。理由：重跑不产生 diff，否则每次跑都污染提交。本轮实测重跑「内容有变化的 0 个」且 `git status` 干净。
- **一眼假是设计目标**：洋红描边 + 左上角标。理由：洋红在废土低饱和暗色盘绝不出现，占位件不会被误当成品。
- **每个占位件带 1px 细节**：两条理由 —— 像素绘制原则要求描边；纯色大块会被 `ENG-10` 的「2×2 同色＝放大件」误判（一个反向约束逼出的做法）。
- **尺寸／帧数／锚点即最终规格**，登记表锁死；**登记表放 `tools/`（有 `.gdignore`）**，因它是开发期元数据，进 `.pck` 只会泄漏本机信息（同 `ENG-3` 泄漏教训）。
- **校验不在生成器里、delegate 给 `check_assets`**：理由是两处各写一套判据会分叉、没人知道信哪个。生成器只保证「生成物与自己规格一致」，其余四类（半透明、放大件、双向比对、导入参数）归 `ENG-10`。
- **顺带关掉 `detect_3d/compress_to` 默认**（改项目级 `[importer_defaults]`）：它会把像素图静默重导成 VRAM 压缩，见[踩坑记录 43](../../../reference/踩坑记录.md)。

### 偏离

- 无重大方案偏离，实现与 PRD 第 8 节三条约束一致（开发期不限授权／发行包只自绘、能生成的优先生成、占位件即最终规格）。
- 一处实现修正（非偏离方案）：登记表写回初版每次重拼完整 payload，会静默抹掉手工维护的节（可进包判据说明、`UI-8` 加的「字体」节）。2026-08-31 在 `UI-8` 轮改成**只重写「生成槽位」一节、保留其余**。

### 权衡

- **生成 vs 下载**：能几何生成的（面板、条、槽、图标、剪影、图块）一律生成 —— 零授权风险、一眼假；只有需手感与 32px 剪影可读性的角色精灵动画才用下载件（`samurai`）。依 PRD §8 第 2 条。
- **一眼假的洋红 vs 好看的占位**：选一眼假。占位件「变成成品」是真实风险，丑是特性不是缺陷。
- **登记表放 `tools/` vs `assets/`**：放 `tools/`（已有 `.gdignore`）避免进包泄漏；放 `assets/` 要额外挡，更易漏。
