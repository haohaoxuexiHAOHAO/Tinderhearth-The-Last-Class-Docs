# UI-11：不暂停的面板打开时玩法动作该不该屏蔽

## 目标

定清楚「关卡内打开背包（不暂停世界）时，手柄的跳跃与闪避该不该被遮」，并让这条裁定有执行体。

## 裁定

**面板打开时屏蔽跳跃与闪避，仅手柄。**

理由：面板打开时玩家的意图是操作界面，不是战斗。背包不暂停世界让玩家保留了移动与攻防能力，能一边整理背包一边走位、防御；但跳跃与闪避在手柄上与 UI 确认、返回共用同一个键，**「按下去到底是哪个」本身就是歧义**，歧义里选玩家正在做的那件事更合理。

代价是面板打开期间手柄玩家不能跳跃与闪避。可接受：正典已为失衡结束设了逃生窗口，而玩家在整理背包时本身就不该处于需要立即闪避的战斗压力下。

键鼠不受影响 —— 键鼠的确认与返回用 Enter／Escape，这两个键没绑玩法动作。

## 设计决策

**一、规则落在 `rules/Ui/PanelInputBlock.cs`，不散在调用方。** `BlockedByOpenPanel` 是一份清单，改动有一个地方。与修饰键遮挡（`SkillModifierState.ShouldSuppress`）对称：两层遮挡都在规则层定义，`InputRouter` 只是执行者。

**二、`InputRouter` 通过 `Nav` setter 注入 `UiRoot` 拥有的导航栈。** 它不需要知道面板是谁打开的，只需要知道「现在有没有面板」——`NavigationStack.Depth > 0` 就够。不注入时用自己的空栈（`Depth` 恒为 0），所以不接线时行为与没有本条之前一致。

**三、连线在 `Main.BuildInputRouter()`**，它在 `BuildUi()` 之后跑，所以 `_ui` 一定有值，不存在空引用的时序风险。

## 权衡

`IsJustReleased` 不加面板遮挡。松开事件不触发跳跃或闪避的动作效果，只影响「停止跳跃」这类持续型动作的收尾，而跳跃与闪避都是单次触发 —— 多遮一层只增加迷惑性。

## 执行体

规则层单元测试覆盖两层遮挡，并把被遮清单与内置补丁的面键钉在一起：面键分配改了会先在测试里失败。
