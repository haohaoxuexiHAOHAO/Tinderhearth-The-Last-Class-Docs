# ENG-10：假像素守卫（半透明像素、错误缩放与槽位登记比对）

## 目标

代码仓有一条守卫能自动检出三类机器可判的素材缺陷：半透明像素、放大得来的假像素、与登记表不符的尺寸或槽位。

## 来源

- 台账已有条目，原文写明"**须在第一张素材进仓前就位**"，理由是这类缺陷静默累积、第 1 张免费第 200 张就是审计。
- 时机现在到了：`UI-1` 的 HUD 样板就是放第一批素材的地方（作者 2026-08-30 确认插进本轮）。
- 规则来源：[像素绘制原则 §9](../../../production/像素绘制原则.md)「透明度只使用完全透明或完全不透明」，以及 §11 明确只给这一条立守卫的理由。

## 依赖

`ART-4`（登记表比对那一半需要登记表存在）。前两条检查不依赖它，可以先落地。

**工具链依赖 Pillow**（代码仓 `tools/requirements.txt`，钉 `11.3.0`，许可证 MIT-CMU）。作者 2026-08-30 拍板加入。理由不是"方便"：下载来的素材可能是调色板、16 位、灰度带 alpha 或隔行扫描，手写解码器只认 RGBA8，遇到认不出的文件会**静默跳过** —— 而本条的全部价值就是不漏检。**所以本守卫在 Pillow 缺失时必须报错退出，不许跳过检查。**

## 验收标准

- [x] 检出 alpha ∉ {0, 255} 的像素，报出文件与坐标（实测报出 `panel.png` 的 `alpha 出现 [128]；位置 (3,3)`）
- [x] 检出"全图每个 2×2 块同色"的整图放大件，报出文件与该用的源尺寸
- [x] **误判方向也守住**：纯色图天然满足"每个 2×2 同色"，不能被判成放大件 —— 否则守卫会拦下自己生成的占位件，然后被绕过。判据加两个前提：宽高都是偶数、且图里至少有两种颜色
- [x] 与 `ART-4` 的登记表**双向**比对：多了、少了、尺寸不符、帧数除不尽都判失败
- [x] 顺带纳入纹理导入参数三项（无损压缩、不生成 mipmap、关掉 `detect_3d` 转 VRAM 压缩）—— 同属"失效时只表现为画面有点花、不报错"那一类
- [x] 自报覆盖量：登记几条、磁盘几个、实际逐像素扫过几个、每个查了哪四类。**扫到 0 个必须判失败**（空转的检查也会全绿）
- [x] 接进 `tools/verify.py` 成为第一步（`STEPS` 首位），门禁仍只调那一条。排最前的理由：它最快，且坏素材不该有机会被打进包
- [x] 判定不只看退出码：认不出 `check_assets.py` 的输出形状同样拒绝判过
- [x] **校验只有一份实现**：`gen_placeholders.py` 不再自己判，改为调 `check_assets.run_checks()`。两处各写一套的下场是判据分叉、没人知道该信哪个
- [x] 自证六条，全用真实缺陷形状，2026-08-30 实测 **16/16 条用例按预期拦下**、还原后完整复验通过：半透明像素、漏登记、帧数不符、`detect_3d` 被改回 1、放大件被认出、纯色图不被误判
- [x] 阈值类检查（亮部比例、对比、色数、孤点）**不做** —— 理由见[像素绘制原则 §11](../../../production/像素绘制原则.md)
- [x] Pillow 缺失时报错退出，不跳过检查
