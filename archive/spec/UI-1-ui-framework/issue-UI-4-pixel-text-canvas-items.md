# UI-4：`canvas_items` 下 12px 像素字的实测与结论回写

## 目标

确认 12px 中文在 `stretch/mode="canvas_items"` 下仍是块状像素而不是被按屏幕尺寸重新光栅化成平滑字形，并把结论写回 [ADR-0008](../../../decisions/ADR-0008-中文像素字体选型.md)。

## 来源

- PRD：[`spec/prd-ui-framework.md`](prd.md) 的 `US-002`
- 起因：ADR-0008 的十项字体属性与整数网格实测是在 `stretch/mode="viewport"` 下做的（2026-08-30，`tools/font_preview.py`），而工程用 `canvas_items`。两者的文字光栅化路径不同。

## 依赖

`UI-3`（要先有 640×360 与整数缩放才谈得上验它）。

**这是本轮唯一的技术未知项**，且不成立会推翻整套渲染配置，所以排在相机与界面之前。

## 验收标准

- [x] 同一段中文在 ×2／×3／×4 下量出的最小同色跑长恰为 2／3／4，与缩放倍数相等 —— 字形整块摊开
- [x] 不出现 1 物理像素宽的笔画
- [x] 判据做成机器可判的量而不是看图：`--measure` 扫全图统计非背景连续同色段，取最短那段
- [x] 所用的字体属性取值逐项记进日志（十项全部存在并设上）
- [x] 结论写回 [ADR-0008](../../../decisions/ADR-0008-中文像素字体选型.md)「未验证（一）」段
- [x] 成立，**不需要**回退 `viewport` 模式
- [x] **反证两次**，确认承重项是哪个：不钉 `oversampling=1.0` 结果逐字节不变；纹理过滤改线性则三档最小跑长全塌到 1、非背景段数从 7982／15972 涨到 31458／125652
- [x] 作者实机确认（作者 2026-08-31 实机确认：动态下 12px 中文块状可读，未发现问题）

复现：`python tools/font_preview.py --measure --canvas-items`，反证加 `--linear-filter` 或 `--loose-oversampling`。

## 实现笔记

> 由 `/note-it` 填写。

### 设计决策

- **模糊点**：立项时把"块状字形"当成目测项。
- **选择**：改成量最小连续同色跑长，与缩放倍数比对。
- **理由**：目测分不出"3 像素块"和"2 像素块加一圈渐变"，而这正是失败形态。跑长是整数，能判死。

### 偏离

- **方案怎么说**：PRD 第 8 节推测承重项是字体的 `oversampling=1.0`。
- **实际怎么做**：实测承重项是**最近邻纹理过滤**。
- **为什么**：`canvas_items` 下字形先按 12px 光栅化进图集，再由画布变换放大 —— 放大用的是纹理过滤。两次反证已验（见验收标准）。PRD 与 ADR-0008 都已按实测改写。

### 权衡

无。结论成立，回退路径（`viewport` 模式）不必启用。

### 待确认

- 「导出产物里字体能正常加载」这一半仍未验，跟着字体进代码仓时验（`UI-8` 之前）。
- 本轮量的是 `temp/` 里的 GDScript 工程。字体光栅化不经过 C#，但真实工程还有主题继承这一层 —— 已记 `ENG-13` 立守卫。
