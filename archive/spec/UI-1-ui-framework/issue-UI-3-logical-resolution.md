# UI-3：逻辑分辨率与缩放链路落进工程

## 目标

工程以 640×360 为逻辑分辨率、只按整数倍放大到窗口、所有纹理最近邻过滤，使像素素材与 12px 中文进去就是清晰的。

## 来源

- PRD：[`spec/prd-ui-framework.md`](prd.md) 的 `US-001`
- 分辨率取 640×360 由作者 2026-08-30 定；判据见 [ADR-0008](../../../decisions/ADR-0008-中文像素字体选型.md) 与[玩法定位 · 像素基准](../../../canon/gameplay/玩法定位.md)

## 依赖

无。它是本轮的第一件事，其余 `UI-*` 条目都依赖它。

- [x] `project.godot` 有 `window/size/viewport_width=640`、`viewport_height=360`
- [x] `project.godot` 有 `window/stretch/scale_mode="integer"`
- [x] `project.godot` 有 `rendering/textures/canvas_textures/default_texture_filter=0`
- [x] `window/stretch/mode="canvas_items"` 与 `aspect="expand"` 未被改动（正典要求保持不动）

## 实现笔记

> 实现落在更早的窗口（代码仓已提交），本节据验收标注、PRD §8 与 2026-08-31 收尾轮复验重建。

### 设计决策

- **逻辑分辨率取 640×360**：正典像素基准把 480×270 与 640×360 并列可用、未定死。选 640×360（作者 2026-08-30 定）。理由：ADR-0008 给了 12px 字号下限，640×360 在侧视 ×2 下有效视野 320×180（20×11 格），够放正典要求的同屏内容。
- **缩放判据守不变量而非定值**：验收初稿按「各窗口缩放恰为 2／3／4／6」写。实现改判「整数、两轴相等、逻辑尺寸不小于 640×360」。理由：`aspect="expand"` 把高锁 360、宽按窗口比例撬，4K 档实测逻辑 649×360、缩放 ×5，定值假设不成立。已回写验收框 5、6，机制教训进[踩坑记录 42](../../../reference/踩坑记录.md)。
- **文字清晰的承重项是最近邻纹理过滤**：立项 §8 推测靠字体 `oversampling=1.0`；实测（`font_preview --measure --canvas-items`）是 `default_texture_filter=0` 在起作用，改线性则 12px 中文最小同色跑长从 2／3／4 塌到 1。此发现推出 `ENG-13`。

### 偏离

- **PRD `US-001` 的「缩放倍数分别是 2、3、4、6」未按字面实现，是有意偏离。** 方案写定值；实际改成守不变量，且 4K 档在本机为 ×5（屏幕装不下 4K，系统裁成 3840×2130）。偏离理由：定值假设与 `expand` 行为矛盾，按定值会误判。已在验收框 5、6 记录并修正判据。

### 权衡

- **守不变量 vs 守定值**：定值判据实现简单、读着直观，但错。不变量判据正确且对任意窗口成立，代价是多写两个条件。选不变量 —— 正确性压倒简单。
- **canvas_items vs 回退 viewport**：ADR-0008 字体实测在 viewport 下做、工程用 canvas_items，两者文字光栅化路径不同，是本需求唯一技术未知项。实测 canvas_items 下 12px 字仍块状（`US-002` 归 `UI-4` 验证），故保留 canvas_items 不回退。若不成立会推翻整套渲染配置。

### 待确认

- **PRD §4 `US-001` 与 §10 成功判据 1 曾写「缩放倍数为 2／3／4／6」**，与本条的不变量判据（及 4K 档实测 ×5）不一致。**已解决**：作者 2026-08-31 定方案 A，本轮同一提交把两处都对齐成不变量判据。
- 其余无新增。两个跟进已各自立项：非 16:9 比例与其他设备归 `UI-2`（低，明确后置）；界面节点局部覆盖 `texture_filter` 会静默毁字的守卫归 `ENG-13`。×6 及更高整数倍在本机无法验证，需 4K 屏或 `--fullscreen`，已在验收框 5 记为已知局限，不阻塞。
