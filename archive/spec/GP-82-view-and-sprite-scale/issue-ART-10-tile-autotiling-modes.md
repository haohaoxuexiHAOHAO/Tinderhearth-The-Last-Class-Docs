# ART-10：两种拼接机制与地面分层判据

> **历史背景·非依据。只读归档件，不得作为现行依据。** 现行事实见同目录 [`prd.md`](./prd.md) 的「归档三问」；待办见[待办台账](../../../spec/issues/README.md)。

## 目标

让作者知道一种地形要画多少张、每张回答什么问题，以及一样东西该走哪种拼接 —— 判据一句话，不靠背清单。

## 来源

- PRD：同目录 [`prd.md`](./prd.md) 的 `US-003`

## 依赖

## 验收标准

- [x] 写明自然地形走**双网格**：数据层一格一个地形、显示层整体偏移半格，每张显示贴图管四个角的组合，因此一套 16 张
- [x] 写明作者刷的是数据层、显示层由代码生成，以及「**画的是四格交汇处那一小块，不是一格地面**」这句心态转换
- [x] 写明半格偏移因此落在整数像素上（这是双网格能和整数缩放共存的前提），格边长写链接不复述
- [x] 写明**两种 16 张的分工与判据**：判据是「这一格是不是玩家单独操作的对象」；是就走同一网格上的四边拼接（边界落在格边线，引擎原生模式），不是就走双网格（边界落在格中线）
- [x] 写明四边拼接那 16 张各对应什么邻居组合（四边都有、三边、两边相邻、两边相对、一边、四边都没有），并写明它的收边只画本地形自己的东西、因此不必配对
- [x] 点名哪几样走四边拼接，理由是它们的边界必须与玩家的操作对齐
- [x] 写明地面分层的判据落在**谁决定它在哪**：作者画在地图里的走双网格，玩家自己改出来的走四边拼接
- [x] 写明**一套瓦片的排列顺序定下来之后不许再调换** —— 映射表要跟着改而它不报错，表现只是边缘拼错
- [x] 写明交付的是**合并后的单张 PNG**，绘图软件里的分层不进仓，并写明它与引擎里的图层是两回事
- [x] 双网格与引擎原生模式各附来源链接
- [x] `python tools/check_docs.py` 0 FAIL

**一处与验收措辞不同的地方**：分层那张表里**没有列施工占地与可摆放高亮**。它们按同一条判据确实归四边拼接，但那两样是界面性质的即时高亮、不是作者要交的地面素材 —— 列进一份给作者看的绘制约定里只会让人以为还要画两套。判据自己回答得了它们，需要时按判据问一次即可。
