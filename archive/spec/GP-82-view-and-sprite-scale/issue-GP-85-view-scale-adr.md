# GP-85：一份 ADR 记这一轮的取舍

> **历史背景·非依据。只读归档件，不得作为现行依据。** 现行事实见同目录 [`prd.md`](./prd.md) 的「归档三问」；待办见[待办台账](../../../spec/issues/README.md)。

## 目标

把「取消侧视拉近、两种视角各一套素材、本体高度按视角分、俯视取不缩放」这四条记成一份 ADR，连同那笔纵向预算的账一起 —— 让「纵深为什么不再深一点」以后有个查得到的答案。

## 来源

- PRD：同目录 [`prd.md`](./prd.md) 的 `US-006`

## 依赖

无。它排在本轮最前面，因为正典那几句要指着它改 —— 与 `GP-46`、`GP-49` 同一个顺序。

## 验收标准

- [x] 新增 [ADR-0020](../../../decisions/ADR-0020-侧视不拉近而把角色画大一档.md)，四条取舍各写候选与被放弃的理由
- [x] 记下**纵向预算那笔账**：逻辑分辨率的高度要分给角色带与上方余量两份，所以「纵深再深一点」是拿背景与 HUD 的余量去换
- [x] 写明拉近倍数与本体高度是**同一个取舍的两半**（角色在屏上够不够大、一屏装得下多少活动区域），不是两条独立决定
- [x] 写明被放弃的那两条路各自的代价：保留拉近而把角色画大（活动区域装不下满编），以及不拉近而本体不变（角色在屏上比现在更小）
- [x] 写明「同一套素材两处复用」为什么本来就名不符实（俯视要四向、侧视要一整套动作，没有一张图真能共用）
- [x] 外部参照附链接，社区来源的标「待验证」并给验证办法（星露谷缩放条下限那一条）
- [x] 进[ADR 索引](../../../decisions/README.md)
- [x] `python tools/check_docs.py` 0 FAIL

**一处刻意的做法**：那几个数（本体高度、纵深倍数）**没有写进 ADR 正文**，只写「值的家在像素基准」—— 与 [ADR-0013](../../../decisions/ADR-0013-战斗片段就是一屏.md) 同一处理。代价是 `GP-82` 落地之前，那个家还是空的。
