# ART-9：新建场景绘制约定，写俯视 45 度那一节

> **历史背景·非依据。只读归档件，不得作为现行依据。** 现行事实见同目录 [`prd.md`](./prd.md) 的「归档三问」；待办见[待办台账](../../../spec/issues/README.md)。

## 目标

让作者照着一份文档就能画出能拼到一起的俯视地面、建筑与角色 —— 这一节回答「45 度到底怎么画」。

## 来源

- PRD：同目录 [`prd.md`](./prd.md) 的 `US-003`

## 依赖

依赖 `GP-82` —— 格边长与本体高度的家在正典，本文写链接不复述。

**两种视角合成一份文档**，因为瓦片与拼接那套做法两边共用；分两份要把同一套解释写两遍。俯视 45 度的投影规则是其中只管一侧的那一节。

## 验收标准

- [x] `production/` 下新增一份场景绘制约定，文件头齐全、被设计仓 [README](../../README.md) 的文档地图链着
- [x] 写明俯视的地面格是**正方形，不是等距菱形**，并给出格边长的来源（写链接，不复述那个数）
- [x] 写明俯视的立面**不做纵向压缩** —— 一格高的墙、树干这类竖直面按整格高度画
- [x] 写明**建筑贴图允许高于占地**（屋顶往上伸出），占地仍按既有规则取整数格；并写明这与[像素绘制原则 · 动作帧可以超出精灵格，本体不行](../../../production/像素绘制原则.md)是同一个形状
- [x] 写明俯视角色画**四个方向**，以及为什么不做八向（画量翻倍而玩家分辨不出）
- [x] 写明俯视的前后遮挡**按脚底位置排序**，并与[战斗与关卡 · 战斗关卡的空间模型：带纵深的横版](../../../canon/gameplay/战斗与关卡.md)那条按纵深排序的规则互相指认
- [x] 光源方向、描边、硬 alpha 这些既有规则写链接不复述
- [ ] 作者实机确认：照这一节画一块地面、一栋楼与一个角色，三样拼在一起没有视角冲突
- [x] `python tools/check_docs.py` 0 FAIL

**多写了一条不在验收里的**：**俯视左右两向各画一套、不靠水平翻转省**。理由是主角身上有不对称的识别标志（空右袖那几样，见[人物](../../../canon/characters/人物.md)），翻转会让它们换边，而那几样正是记忆点。补它是因为「四向」这个说法本身答不了「左右能不能翻」，不写清楚作者会按最省的那种理解去画。

**顺带留下一处排序陷阱的说明**：树冠画得比接地点更靠下会被排错，而那**不报错** —— 表现只是「角色走到树后面却压在树上」。
