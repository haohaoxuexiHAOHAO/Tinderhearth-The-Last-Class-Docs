# ART-13：帧框口径改成按角色各自一个

> **历史背景·非依据。只读归档件，不得作为现行依据。** 现行事实见同目录 [`prd.md`](./prd.md) 的「归档三问」；待办见[待办台账](../../../spec/issues/README.md)。

## 目标

让胖角色、高角色与各类怪物各用自己的帧框 —— 体型不同的角色不必挤进同一个框，也不必为此重新讨论一次做法。

## 来源

- PRD：同目录 [`prd.md`](./prd.md) 的 `US-004`

## 依赖

依赖 `GP-82` —— 体型三档的口径在正典，本条只写「按角色各自一个」这件事怎么落。

**没有并进 `ART-6`**：那一条是主角那一套的进行中条目、还挂着作者的实机确认；帧框口径是全项目的事，混进去会让两件事共用一个进度。

## 验收标准

- [x] [像素绘制原则 · 动作帧可以超出精灵格，本体不行](../../../production/像素绘制原则.md)改成「**每个角色一个帧框**」，并说明当前值按角色取、本文不抄
- [x] 同一节写明帧框由该角色自己的素材实测算出，**缺声明时应当载入报错、不给默认值**，并指 [ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md)
- [x] 同一节写明**判定框与帧框是两份独立声明** —— 角色画大了不会自动让打击范围变大
- [x] 同一节把「帧框宽 = 2×max(左伸, 右伸+1)」那条**整条删掉**：它唯一的目的是让水平翻转不甩偏，而 [ADR-0021](../../../decisions/ADR-0021-每个朝向各画一套不做水平翻转.md) 之后没有翻转了。删的理由已写出来，免得被当成漏了
- [x] 同一节写明帧框可以取**紧框**，并写明这是上一条换来的；**代价是多声明一个锚点列**，而那个数导入器本来就量得到，不增加作者的活
- [x] 同一节写明一个动作的**两向怎么交付与命名**（朝向放成目录层，理由是少一整个目录一眼看得出），以及**缺一向时载入报错**
- [x] 同一节写明这条做法与 LF2 那套「精灵格按文件声明、每帧另带锚点」是同一招，本项目只是在导入时就把锚点解析成一个统一帧框；附来源链接
- [x] 作者那一侧的要求仍然只有一条：**画完不截**
- [x] 代码那一半不在本条 —— 落点记在 `ENG-24`
- [x] `python tools/check_docs.py` 0 FAIL

**顺带扫掉同一节里两处按旧本体高写的句子**：「本体仍守 ≤32px 高」与「别为了塞进 32×32 而截掉」——侧视本体已经不是那个数了，两处都改成指像素基准那张表、不复述档位。

**刻意没改的一处**：节名「动作帧可以超出精灵格，本体不行」保留原样。「精灵格」现在主要是俯视的说法，但节名本身不算错，而改它要连带动四处引用（场景绘制约定、本轮两个条目文件、PRD）—— 收益不抵那一串改动。

**多出来的一项发现**：取紧框之后**锚点列必须跟着声明**。原先它被那条对称要求钉死在正中，所以只要三项（宽、高、地面行）；现在是四项。这一条已补进 `ENG-24` 的验收。
