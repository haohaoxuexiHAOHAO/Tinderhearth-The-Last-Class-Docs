# ART-12：侧视片段的背景拼接与动态水

> **历史背景·非依据。只读归档件，不得作为现行依据。** 现行事实见同目录 [`prd.md`](./prd.md) 的「归档三问」；待办见[待办台账](../../../spec/issues/README.md)。

## 目标

让一屏 640×360 的侧视片段不必整片手工画，并给动态水一条不写着色器就能做的路。

## 来源

- PRD：同目录 [`prd.md`](./prd.md) 的 `US-003`

## 依赖

依赖 `ART-9`（那份文档）与 `GP-83`（一屏那两个数从几何账来）。

## 验收标准

- [x] 写明侧视片段的**背景按组件分层拼**，同类地形在片段之间复用；并给出一屏的世界像素尺寸来源（写链接，不复述那两个数）
- [x] 写明为什么不整片手工画 —— 片段数量正是关卡不重复的唯一来源，整片手工画会让它变成能不能做完的瓶颈
- [x] 写明动态水的做法：**静态水面瓦片 ＋ 引擎原生的逐格帧动画**，岸线那几张保持静止或只做很轻的一两帧
- [x] 写明为什么不用噪声扰动着色器 —— 扰动出来的采样落在非整数像素上，与最近邻、整数缩放、只许全透明或全不透明三条硬规则冲突；要用就得把位移量化到整像素，而且在瓦片图层上还要先塞进子视口
- [x] 写明那条路留作以后的润色项，不是被永久否决
- [x] 动态水与引擎逐格动画各附来源链接
- [ ] 作者实机确认：一屏背景按组件拼出来之后，重复感能不能接受
- [x] `python tools/check_docs.py` 0 FAIL

**多写了一条压重复感的办法**：同一类地形多备几个变体组件，点睛物放在视线最先落到的那一层（角色带附近），远景允许明显复用 —— 玩家注意力在角色身上，远景重复的容忍度比俯视高得多。不写的话「按组件拼」只是个做法，答不了「拼出来会不会看着很假」。
