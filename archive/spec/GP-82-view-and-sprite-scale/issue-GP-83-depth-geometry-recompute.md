# GP-83：侧视几何账按新本体尺寸重算

> **历史背景·非依据。只读归档件，不得作为现行依据。** 现行事实见同目录 [`prd.md`](./prd.md) 的「归档三问」；待办见[待办台账](../../../spec/issues/README.md)。

## 目标

按新的本体尺寸把「一排装得下几个、几排、纵深多宽」那笔账整条重算一遍，结论仍然自己算得通。

## 来源

- PRD：同目录 [`prd.md`](./prd.md) 的 `US-002`

## 依赖

依赖 `GP-82` —— 本体尺寸与相机缩放是这笔账的输入。

## 验收标准

- [x] [战斗与关卡 · 可行走纵深是怎么算出来的](../../../canon/gameplay/战斗与关卡.md)那一节整体重写，**节名不再带旧带宽那个数**，并把全库指向它的引用一起改指新节名
- [x] 表里每一行都给出算式与依据，且逐行算得通：本体尺寸 → 同深度相邻间距 → 一排装得下几个 → 相邻两排纵深差 → 可行走纵深 → 可读排数与站位总数
- [x] 纵向那笔账也给出来（最近的脚、最远的脚、最高的头、角色带高度、上方留给背景与 HUD 的余量），**各数加起来等于逻辑分辨率的高度**
- [x] 站位总数容得下同屏敌人上限加一支满编队伍，并留得出互动物件的位置
- [x] 命中的纵深容差写明它是半个排距，与新排距对得上
- [x] 那一节仍然写明**这是几何账不是好玩账**，密度成不成立归实机；`ENG-16` 的验法照旧、条目不关闭
- [x] [`关卡系统`](../../../design/关卡系统.md)那条按「一屏」给的片段宽度复看一遍 —— 它写的是「那个数的家在正典，本页不复述」，没有第二份副本，只改了节名
- [x] `python tools/check_docs.py` 0 FAIL

**顺带扫掉的那批复述**：原先「48px」这个数散在同一份文件的好几处散文里（空间模型那条项目符、不因远近缩放那条的理由、基础 AI 那条「排位白做了」、打击反馈那条容差、片段宽度统一那句）。现在只有几何账那张表里有它，别处改成指那一节 —— 否则下次改带宽要在五处各改一遍，而漏掉哪一处没有任何东西会报。

**改了一份已接受 ADR 的指针**：[ADR-0013](../../../decisions/ADR-0013-战斗片段就是一屏.md) 的背景里那条链接指着旧节名。**只改了链接文字，论点与理由一个字没动** —— 让引用解析得到是维护，不是用今天的理由改写当时的背景。
