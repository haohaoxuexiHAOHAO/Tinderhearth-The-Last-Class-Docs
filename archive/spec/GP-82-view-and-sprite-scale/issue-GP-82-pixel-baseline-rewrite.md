# GP-82：正典的像素基准改口径

> **历史背景·非依据。只读归档件，不得作为现行依据。** 现行事实见同目录 [`prd.md`](./prd.md) 的「归档三问」；待办见[待办台账](../../../spec/issues/README.md)。

## 目标

让作者从正典一处就查到两种视角各自的相机远近与人物本体尺寸，不用翻代码也不用问人。

## 验收标准

- [x] [玩法定位 · 像素基准](../../../canon/gameplay/玩法定位.md)写明**俯视相机不缩放**，并给出由它算出的可见格数；这个数在设计仓里只有这一个家（原先它只是代码里一个字面量）
- [x] 同一节写明**侧视相机同样不缩放**，原先那句 2 倍拉近及其「同一套素材两处复用、不另画战斗素材」一并删除
- [x] 同一节写明两种视角的人物本体高度各是多少，并写明它们不相等的理由
- [x] 同一节给出体型三档（小、人、大）的本体高度口径，并写明大型按素材实测、在站位账上按占两个算
- [x] 同一节写明素材分两套，以及哪几类角色只需要其中一套（敌人与怪物只要侧视，城区 NPC 只要俯视）
- [x] [玩法定位 · 内容规模基准](../../../canon/gameplay/玩法定位.md)加一行**基地的天然地形种类**，写明这个量要撑起什么，并写明城区与侧视关卡的地面材质不在其内
- [x] 全库搜不到「同一套素材两处复用」这一类说法（搜两个仓加 `.kiro`）
- [x] `python tools/check_docs.py` 0 FAIL

**顺带在本页范围内扫掉的两处**（都在[玩法定位](../../../canon/gameplay/玩法定位.md)自己身上，所以不是超边界）：分辨率那一节「改它的代价」原先写着「除以侧视 2 倍缩放」；系统清单相机那一行原先写着「侧视 2 倍缩放」且「两种视角各一套」，现在是两种视角共用同一套行为、没有分叉。

**另外删掉了两个会过期的实测数字**：原文抄了「重拳伸到锚点右侧 22px、本体最高 30px」，那是 32px 测试件量出来的，素材一换必然过期 —— 现在只写「帧框的当前值不在本页」并指[像素绘制原则](../../../production/像素绘制原则.md)。

**范围外记账**：`rules/Ui/UiMetrics.cs` 图标两档那句注释指着[人物](../../../canon/characters/人物.md)那个即将改名的节名，而代码注释没有守卫查得到 —— 已记进 `ART-14` 的备注，本条不顺手改。
