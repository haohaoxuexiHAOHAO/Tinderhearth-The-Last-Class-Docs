# PRD：删掉重攻击，只留轻攻击

> **历史背景·非依据。只读归档件，不得作为现行依据。** 现行事实的落点列在[待办台账](../../../spec/issues/README.md)「已归档编号」里 `GP-138` 那一行；勾选框与偏离在同目录 [`issue.md`](./issue.md)。**本页里描述「现在是什么样」的那些句子说的是改之前**，它们是立项理由，不是现状。

## 1. 概述

战斗里现在有两个普攻键：轻攻击打一条连段，重攻击是一招单打。重攻击要删掉，只留轻攻击；**轻击打中才续段的那条连招照旧**。

重攻击不只是一个键，它还牵着这几样（出处写在对应的用户故事与技术考虑里）：

- 正典里一条循环的理由：力量的回报写的是「打崩 → 补重击」。
- 打击反馈的轻重两档：击退、硬直、顿帧、震屏、火花与受击表，现在都按「按的是轻还是重」取值。
- 手柄的技能位：按住扳机时面键各对一个技能位，重攻击那个面键是其中一个。
- 数值模型里一组倍率，以及一条判据里的比较项。

**为什么现在做**：敌人回到技能那张表之后，普攻改成按角色声明段数、敌我同一套。重攻击是只有主角与学生才有的第二种普攻，删掉之后每个角色的普攻只剩「几段、打中才续」这一种形状。

**排在另外两份需求前面**：[界面素材基线](../../../spec/prd-ui-art-baseline.md)与[作物素材表](../../../spec/prd-crop-sheet.md)在本份收尾之前不动代码（[spec · 一次只做一个需求](../../../spec/README.md)）。

**分工**（[ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md)）：文档、规则层、引擎侧接线与测试由我改；作者实机按一遍，并决定测试角色那张重击帧（代码仓 `assets/self-drawn/test-role/heavy.png`）留不留。

## 2. 目标

- 战斗里只有轻攻击一个普攻键，按它的手感与删之前的轻击一样。
- 正典、系统文档、数值模型、代码与测试里不再有重攻击这个动作。
- 「打崩之后补什么」有一个不靠重击的答案，写进正典。
- 命中反馈的轻重不再取决于按了哪个键，而是这一招自己声明的一格。
- 手柄上的技能位一个不少。

## 3. 上游约束

- [战斗与关卡 · 按键与连击](../../../canon/gameplay/战斗与关卡.md)：按键清单含重攻击；连击构成是固定连段、空中连击与倒地追打。**本需求只改按键清单，连击构成一个字不动。**
- [战斗与关卡 · 打击反馈](../../../canon/gameplay/战斗与关卡.md)：击退随攻击轻重变化，震屏写的是只给重击与特定事件。**约束轻重那一档要有去处，见 US-004。**
- [战斗与关卡 · 防御与失衡](../../../canon/gameplay/战斗与关卡.md)：体力条耗尽时进入「可被重击的失衡状态」。**这句措辞要跟着改。**
- [角色与成长 · 四项属性的作用方向](../../../canon/gameplay/角色与成长.md)：力量的回报「不是又一份伤害」，而是「打崩 → 补重击」那条循环，后面另有一段写它的代价。**约束新落点不能是一份额外伤害。**
- [`角色动作状态系统` · 受击链：受击 → 失衡 → 击倒 → 起身](../../../design/角色动作状态系统.md)：失衡中再挨任何一下就被击倒，倒地可被追打。**这就是力量那条循环的新落点。**
- [`角色动作状态系统` · 动作叠加层：互斥的主动动作，给运动层一个"定身/忙"标志](../../../design/角色动作状态系统.md)：普攻按角色声明段数，续段靠命中确认，敌我同一套。**删掉重击之后主角的普攻就是一条轻击连段，这条规则不变。**
- [`键鼠技能位挪到右手`](../../../design/proposals/键鼠技能位挪到右手.md)：技能键排在两个攻击键周围，那份布局还等作者实机按（`UI-14`）。**约束空出来的那个键先不挪别的东西过去。**
- [`数值模型` · 减伤用软化分母，因为堆防御必须递减](../../../design/数值模型.md)：招式倍率那张表有重攻击一列，判据 C4 还比较两边的重攻击倍率是否同值。**约束删参数时推演入口要同一次改。**

## 4. 用户故事

### US-001：文档里不再有重攻击

**描述**：作为作者，我想要正典与系统文档只描述轻攻击，以便读到的规则就是游戏里的规则。

**验收标准**：

- [ ] 可核对：正典按键清单里没有重攻击；力量那条循环改成「打崩 → 击倒 → 倒地追打」—— 失衡中再挨一下就被打飞到地上（受击链原本就是这样），倒地照样能打；它的代价那一段跟着改。改过的节逐条核过引它的上游约束之后 `--repin`。
- [ ] 可核对：系统文档、提案、参考与制作规格里提到重攻击的地方都改掉，清单在 [`GP-138` 的条目文件](./issue.md)里。
- [ ] 可核对：命中反馈的轻重写成一招自己的一格，落在[`伤害系统`](../../../design/伤害系统.md)、[`技能系统`](../../../design/技能系统.md)与[`角色动作状态系统`](../../../design/角色动作状态系统.md)。
- [ ] 可核对：设计仓 `python tools/check_docs.py` 0 FAIL。

### US-002：输入里没有重攻击

**描述**：作为玩家，我想要战斗键位里只有一个普攻键，以便不用记一个已经没用的键。

**验收标准**：

- [ ] 可测试：动作清单里没有重攻击那个动作；键鼠上原来那个键不绑任何动作。
- [ ] 可测试：手柄按住任一扳机时，上面键照旧发出那一组对应的技能位；不按扳机时它不发出任何战斗动作。
- [ ] 可测试：修饰键按住时面键到技能位的映射一个不少，原来那条映射测试改写后照样钉住它。
- [ ] 可核对：代码仓 `python tools/verify.py` 全过。
- [ ] **作者实机确认**：键鼠按原来那个键没反应，按轻攻击照旧出连段。

### US-003：连段机只有轻击一种

**描述**：作为玩家，我想要按轻攻击时的连段与删之前一样，以便手感不因为删了一个键而变。

**验收标准**：

- [ ] 可测试：规则层没有重攻击那一种连段；轻击连段照旧 —— 某段打中才开续段窗、打空走完后摇不续、末段不再续、空中起手落地打断，现有那批连段测试改写后全绿。
- [ ] 可核对：重攻击那一组手感常量（前摇、命中、后摇、衔接窗、段数与判定框）从代码仓 `rules/Combat/CombatFeel.cs` 删掉，轻击那一组一个数不变。
- [ ] 可测试：引擎侧不再载入重击那张精灵表，轻击各段放的仍是各自那张。

### US-004：命中反应的轻重由这一招决定

**描述**：作为玩家，我想要「这一下重不重」由出手的那一招决定、而不是由按了哪个键决定，以便以后技能与敌人的重招打在身上有分量。

**验收标准**：

- [ ] 可测试：命中反应（击退、硬直、顿帧）按这一招的轻重取值；轻的那一组等于现在轻击那一组，重的那一组等于现在重击那一组，各一条测试。
- [ ] 可测试：轻击连段的每一段都是轻。
- [ ] 可测试：震屏、火花与受击表按同一个轻重取；重的那一套保留且有测试，在有一招声明为重之前游戏里看不到。
- [ ] **作者实机确认**：训练房里轻击连段打木桩，击退、震屏与火花与删之前的轻击一样。

### US-005：数值模型里没有重攻击

**描述**：作为作者，我想要参数表与判据只描述存在的招，以便推演结果不依赖一组没人用的倍率。

**验收标准**：

- [ ] 可核对：招式倍率那张表只剩轻攻击；设计仓 `design/numeric-model-params.json` 里没有重攻击那两个倍率。
- [ ] 可测试：判据 C4 的「倍率两边同值」只比轻攻击，设计仓 `tools/simulate_week.py` 跑通、C4 的实测比值不变。
- [ ] 可核对：设计仓 `python tools/simulate_week.py --check-doc` 通过。

### US-006：只用轻攻击打完一轮的端到端

**描述**：作为作者，我想要从按键到命中反馈整条链路只用轻攻击走一遍，以便确认删掉重攻击没有把别的东西带坏。依赖其余全部故事。

**验收标准**：

- [ ] 自动化：规则层一条集成测试走完主路径 —— 连按轻攻击 → 各段依次出手、每段命中 → 每段的命中反应都是轻的那一组。
- [ ] 自动化：失败路径各一条 —— 第一段打空则不续；键鼠上原来重攻击那个键不绑任何动作；手柄上面键不按扳机时不对应任何技能位，按住扳机时发出那一组的技能位。
- [ ] 测试独立可重复，自己准备与清理状态。
- [ ] **作者实机确认清单**：打开训练房；按 `J` 连打木桩，每一段都出、都有命中反馈；对着空气按 `J`，第一段打完不续；按 `K` 什么都不发生。

## 5. 功能需求

- FR-1：战斗动作清单必须只有一个普攻动作，即轻攻击。
- FR-2：按轻攻击时，系统必须照旧起手轻击连段。
- FR-3：轻击某一段打中时，系统必须开续段窗。
- FR-4：轻击某一段打空时，系统必须不续段。
- FR-5：键鼠按原来重攻击那个键时，系统必须不产生任何战斗动作。
- FR-6：手柄按住任一扳机时，上面键必须发出那一组对应的技能位。
- FR-7：手柄不按扳机时，上面键必须不产生任何战斗动作。
- FR-8：命中反应的轻重必须取自出手那一招，不取自按的是哪个键。
- FR-9：轻击连段的每一段必须是轻。
- FR-10：参数表必须没有重攻击的倍率。
- FR-11：判据 C4 的倍率比较必须只比轻攻击。
- FR-12：正典里力量的那份回报必须落在「打崩 → 击倒 → 倒地追打」上。

## 6. 非目标

- **不给轻攻击改名。** 动作名 `attack_light` 在代码与测试里到处被引用，改名只多一轮改动、不改任何行为。
- **不改轻击本身**：段数、帧数、判定框与击退都不动，那些归 `GP-6` 实机调。
- **不加新的连段，不做取消与派生**（`GP-4`）。
- **不动受击链本身**（失衡 → 击倒 → 起身），只改正典里那条循环的理由。
- **不给空出来的键派新动作**：键鼠的 `K` 空着；手柄那个面键只在按住扳机时当技能位。手柄那一套的按键提示与适配后置在 `UI-54`，键鼠布局还等作者实机按（`UI-14`）。
- **不删素材文件**：测试角色那张重击帧留不留由作者定，整套测试角色换正式美术时一起处理（`ART-6`）。
- **不做技能**（`GP-31`）。「重」那一档在技能与敌人的招上怎么填，跟技能表与普攻声明的落地走（`GP-31`、`GP-18`）。
- **不改手柄技能位的方案**：扳机分组、面键各对一个位，照旧。

## 7. 界面与表现考虑

- **没有要撤的界面件**：代码里读两个攻击动作的只有输入那一侧，HUD 上不显示普攻键的提示。
- **按住扳机时被遮住的动作要看得出来**（[`界面系统`](../../../design/界面系统.md)那一条）。上面键不按扳机时本来就没有动作，所以那一条对它没有可遮的东西。
- **作者实机确认**：只剩轻攻击之后连段的手感。

## 8. 技术考虑

- **手柄技能位跟着一份动作清单走。** 按住扳机时被遮住的动作，同时决定面键对哪个技能位（代码仓 `rules/UI/InputActions.cs`），重攻击是其中一个。只删动作而不补位，那两个技能位在手柄上就发不出来；代码仓 `tests/UI/InputMappingTests.cs` 里那条映射测试钉着它。所以上面键改成一个只在修饰键组合里用的动作：不按扳机时没有人读它。
- **命中反应现在由连段类型直接决定**（代码仓 `rules/Combat/HitResolution.cs` 按轻重两种连段取值），所以轻重要从连段类型里拆出来、成为这一招的一格；重的那一组反应量、震屏、火花与 `heavy_hit` 受击表都留着。
- **精灵表按名字载入**（代码仓 `src/World/PlayerActor.cs`），重击那张从清单里去掉，受击那张 `heavy_hit` 留着。
- **推演入口直接读重攻击倍率**：设计仓 `tools/simulate_week.py` 的 C4 读那两个参数路径，只删参数不改脚本会让它当场失败，两边要同一次改。
- **代码仓 `CONVENTIONS.md` 拿重击写过一个三元的示例**，要换一个例子。
- **搜的时候分清两件事**：要删的是重攻击这个动作，受击那一档的「重」留着；按字面搜 heavy 会把两者混在一起。
- **收尾时把「重攻击」登进设计仓 `tools/retired-names.json` 的退役术语**，往后活文档里再出现就报错。现在登会让本份与它的条目文件当场报错，所以等它们进 `archive/` 那一刻登。
- **与另外两份需求的交叠**（动手前按两份的条目文件核过）：界面那份的 `UI-46` 要在格子上显示按键提示，它经代码仓 `rules/UI/InputHints.cs` 读本份要改的那份面键清单 —— 本份不改清单的顺序与技能位映射，手柄提示又后置在 `UI-54`，所以不冲突。`UI-43` 要让目标报自己的高度，可能要动 `src/World/PlayerActor.cs`（推断，那一条还没开始）。作物那份不碰战斗与输入。
- **依赖**：没有编号依赖。
