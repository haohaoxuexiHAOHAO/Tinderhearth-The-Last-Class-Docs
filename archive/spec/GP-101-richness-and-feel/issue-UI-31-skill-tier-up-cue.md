# UI-31：技能升档当场给一条提示

> **只读归档 · 历史背景，不是现行依据。** 现行事实在本页正文点到的那几份活文档里；状态与剩余动作在[待办台账](../../../spec/issues/README.md)，不在本页。

## 目标

玩家在关卡里练出一个新档位时当场知道，而世界不因此暂停。

## 来源

PRD：`spec/prd-richness-and-feel.md` 的 `US-018`。

立项理由：实战值到档位会解锁技能孔，而[角色与成长](../../../canon/gameplay/角色与成长.md)写明**升档那一刻不弹界面**（理由是对的：弹界面等于给玩家一次免费暂停）。结果是升档在关卡里**完全不可见** —— 而它是全作唯一的解锁式成长反馈。

作者已定：给一条不接管输入的提示（气泡或屏幕边缘），**不做角色闪光**。选择照旧攒到手环里做。

## 依赖

无强依赖。与 `UI-30` 口径一致（那一屏给的是结算里的汇总，本条给的是关卡内的当场提示）。

## 验收标准

- [x] [角色与成长](../../../canon/gameplay/角色与成长.md)那条「升档那一刻不弹界面」**不动**，另写明它给的是什么表现
- [x] 提示落在[`界面系统`](../../../design/界面系统.md)世界那一层，形状与气泡、引导提示**分得开**（那条要求已经在那份文档里）
- [x] 明确不做角色闪光
- [x] 可测试：升档时世界不暂停，角色仍可操作
- [x] 停留时长登记进[数值模型](../../../design/数值模型.md)的尚未给值表；若它与引导提示同侧就并进那一行、不新开
- [ ] **作者实机确认**：打斗中间这条提示看得见但不挡视线
- [x] `python tools/check_docs.py` 0 FAIL

## 实现笔记

### 设计决策

- **模糊点**：「升档」在界面那一份里**已经有一个方向相反的结论** —— 角色面板那一行战斗评级下面写着「升档不推送任何提示，也不弹窗」，而那一条说的是**队友那两个行为档号**（[`战斗AI系统`](../../../design/战斗AI系统.md)那两条轴）。本条要给的提示说的是**角色自己练出来的那一档**。同一个词两个所指，而其中一处禁的正是另一处要的。
- **选择**：两处都补定语，并在那一份的「同名不同物」里给「升档」立一条。队友那一条的验收也跟着补上「**也不出那条升档提示**」。
- **理由**：不补定语的话，这两条在同一份文档里字面相反 —— 而读者没有办法判断哪一条管哪一种，落地时只会各按一半实现，**且两种实现都说得出依据**。

- **它只给主角自己练出来的那一档**，队友练出一档一条都不出。判据不是「队友不重要」：满编一屏下队友各自升档会同时飘好几条，而那正好撞上本条唯一那条实机风险（看得见但不挡视线）；而队友那一侧已经有自己的答案 —— 新开的技能孔在角色面板技能与镶嵌子页上查得到（**关卡里换宝石一律被拒**，所以那一刻提示了也没有能做的动作），两个行为档号在手环队伍页（`UI-32`）。
- **上报对每个角色都发，筛在呈现这一侧**：出征结束那一屏列全队，关卡里这一条只给主角。这样 `UI-30` 与本条读的是**同一下**（[`成长系统`](../../../design/成长系统.md)「它给谁」表上那一行，`UI-30` 那一轮加的），而不是两份记录 —— 那条「口径一致」的落点就在这里。
- **一条，不排队堆叠**：新的盖掉旧的，同时升两档时先到的不排队等。**漏掉一条不丢任何东西**（技能孔在角色面板上、欠着的那次选择在专长选择页上、这一趟升过的那几档在出征结束那一屏上）。**「同时显示几条」因此不是一个要给值的量** —— 它是「不排队」的后果。

### 偏离

- **方案怎么说**：停留时长「若它与引导提示同侧就并进那一行、不新开」。
- **实际怎么做**：**新开了一行**，并在那一行里写明为什么不并。
- **为什么**：那个条件不成立。两者是**同一类量**（都归本表、不归 `GP-6` 的逐帧手感），但**不同侧**：[`事件系统`](../../../design/事件系统.md)写明**引导提示不参与任何丢弃**（它是必要信息），而这一条可以被下一条盖掉 —— 丢弃语义相反的两样东西共用一条呈现通道就得二选一。落地也跟着不同的编号走（引导那一行跟事件那一侧，本行跟 `UI-31`）。**并进去的代价是具体的**：那一行的「为什么不给」是「要等真有事件与引导条目才估得出来」，而本条不等任何内容 —— 合进去之后这半条理由就没有对象了。

- **方案怎么说**：提示落在世界那一层，形状与气泡、引导提示分得开。
- **实际怎么做**：照此写了，另外**明确它挂在角色身上、跟着世界走**（世界那一层的定义就是这个），并写出它与气泡在语义上的差别：气泡是「他在说话」，这一条是「他身上刚发生了一件事」。
- **为什么**：这一层里已经有两样东西挂在角色头顶附近（气泡与引导提示），只说「形状分得开」而不说它凭什么不是气泡，落地时最省事的做法就是直接复用气泡那条通道 —— **而那条通道带着额度闸门与冷却池**，于是升档提示会被闲聊挤掉，且它不报错。

- **它不止关卡里给。** 验收与 `US-018` 都只说关卡内，而实际写成**不分场景**：基地里种地、烹饪、加工练出一档同样给。理由是同一条机制、同一层、同一个上报 —— 而生活技能大半是在基地里练上去的，只在关卡里给等于把它最常发生的地方漏掉。

### 权衡

- **没做角色闪光**（作者已定），而本轮给它写了依据：战斗里那套反馈语言已经被命中、打断与精准防御各占一份（界面那一份抬头显示那一节的两条），再加一次全身闪光就挤进同一条通道 —— 它出现在打斗中间，玩家会把它读成一次受击或一次触发。
- **提示只给「哪一项升到哪一档」，不给「新开了什么」。** 档位解锁的是技能孔（战斗技能那一侧）或一次三选一（生活技能那一侧），把这些写进提示等于在一条飘过去的文字里复制一份会跟着档位表变的内容；而那两样各有自己的页。
- **代价写明**：玩家在一次交锋里既要看敌人又要看这条提示，所以它注定要在「看得见」与「挡视线」之间取一个值 —— 而那个值只能实机试。停留时长那一行因此明写它**不接任何平衡判据**。

### 待确认

- **同时升两档到底有多常见，现在是推断。** 一次交锋里同时练成两档需要两项技能的实战值同时跨阈值，量级要等阈值有值（`GP-7`）才估得出来。若实测发现它其实很常见，「不排队」这条要回头复核 —— 那时改的是这一条，不是丢弃语义那一条。
- **提示挂在角色身上还是屏幕边缘，本条只定了「世界那一层」。** 逻辑分辨率下角色头顶那块地已经有气泡与引导提示，摆不摆得开归作者实机；**若实机发现挤不开，改的是摆位而不是层**（换成屏幕边缘就变成常驻那一层的东西，而那一层的判据是「动作进行中需不需要它」，这一条答不出「需要」）。
