# GP-110：推演里那条渠道判据换成两条，并解决 `C10`

> **只读归档 · 历史背景，不是现行依据。** 现行事实在本页正文点到的那几份活文档里；状态与剩余动作在[待办台账](../../../spec/issues/README.md)，不在本页。

## 目标

「每条渠道各有长处」这件事是推演算得出来的，不是散文里的一句纪律。

## 来源

PRD：`spec/prd-richness-and-feel.md` 的 `US-010` 后半（数值模型与推演那一侧）。

立项理由：`GP-109` 把结构改完之后，旧那条不等式在[数值模型](../../../design/数值模型.md)里就没有对象了。两条新判据是：**不许严格支配**（不存在一条渠道在三维上都不劣于另一条）与**每条渠道至少在一维上最强**。

顺带解决一直挂着的 `C10` —— 它正是那条「新渠道的每点精力收益不得高于种植」，它的配对要求写在尚未给值表里、等给值那一轮才接得上判定，所以判据表里一直没有它那一行。

## 依赖

`GP-109`（渠道要先声明优势维，判据才有可读的输入）。

**判定要等产量进来**：六条渠道的产量与耗时现在一个值都没有（跟 `GP-88` 与 `GP-7` 走）。本条交付的是判据的形式与推演里的实现，**不是它第一次通过**。

## 验收标准

- [x] [数值模型](../../../design/数值模型.md)的判据表里旧那条换成两条新的：`C13`（**在它声明的那一维上取到那一维的最大值**，并列算取到）与 `C14`（**不许严格支配**）。编号只增不复用
- [x] `C10` 随本条解决 —— **处置是退役，不是补一行**：它的内容已被 `C13` 吸收（那句话现在是 `C13` 的推论），补一行就是同一件事两个家。判据表那段「编号只增不复用」改写成写明它退役、为什么退役、以及它当初「没有行」的那个理由现在由谁接走。尚未给值表里那条配对要求跟着改写
- [x] `python tools/simulate_week.py` 里这两条接上了、在输出里各自点得出名字，**但它们判不到数** —— 见下面「偏离」第一处。脚本顺带把「每点精力的钱」那一维的尺子算出来并报出（种植那一侧现成）
- [x] 那条「必须与新渠道的产量数值同一轮落地」按新判据重写，而且**方向反过来了**：判据这次是先到的，所以给值那一轮不是「补判据」而是「把这两条从等值未判变成真判」，原先要防的那个窗口在这一处不存在
- [x] `python tools/simulate_week.py --check-doc` 通过（路径 68/68、20 处路径旁的数字都对得上）
- [x] 判据在产量还没有值时的表现写明 —— **取的是验收给的两个选项之外的第三种**：「等值未判」，摘要里单独点名、不计入通过、退出码仍是 0，另配一条空转守卫（判定全是等值未判时判失败）。理由见下面「偏离」第二处
- [x] `python tools/check_docs.py` 0 FAIL 且摘要各项覆盖量都不是零

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：`C10` 该怎么「解决」—— 给它补一行，还是退役。
- **选择**：**退役。** 判据表那一段写明它被 `C13` 与 `C14` 取代、编号不复用、也不再有对应的行。
- **理由**：它的内容（每点精力的钱不得高于种植）现在是 `C13` 的**推论** —— 种植声明的优势维就是那一维，而一维只归一个声明者。补一行等于让同一条约束有两处判定，而两处迟早会不一致；更坏的是它会让读者以为那是一条独立约束，于是「一维一个声明者」这条结构被绕过时反而看不出来。
- **第二处（两条判据谁先判得到）**：`C13` 只要各渠道在**自己那一维**上的值，`C14` 要每条渠道在**每一维**上都有值 —— 所以 `C14` 必然比 `C13` 晚一步。写进文档，免得给值那一轮有人以为两条会同时亮。
- **第三处（尺子的口径）**：`C13` 报的那把尺子按 `farm.crops` 里的 `sell_copper` 折钱（那就是基础价），**与 `C12` 刻意不同** —— `C12` 把自产的粮食折成买价，因为它量的是两条路的收入比；这一维量的是「每点精力换得到多少钱」。两处口径各写在各自那一条的注释里，免得以后有人把它们统一掉。
- **第四处（结构那一半归谁）**：在册、不撞维、有主那几条判的是**数据形状**，归载入校验（反证在[`生产系统`](../../../design/生产系统.md)的验收）；推演判的是**数**。两份文档各写明自己不判哪一半，否则会各自以为对面在判。

### 偏离

- **方案怎么说**：验收写「`python tools/simulate_week.py` **算得出这两条**」。
- **实际怎么做**：脚本把这两条接上、在输出里各自点名、并报出「每点精力的钱」那一维的尺子，**但它算不出这两条的结论**。
- **为什么**：六条渠道里只有种植有值，其余渠道的产量与耗时一个都没有。本条的来源段本来就写明「交付的是判据的形式与推演里的实现，**不是它第一次通过**」，所以这是那句话在验收措辞上的一次收紧，不是缩水。

- **第二处（「跳过还是判失败」两个选项都没取）**：验收把表现限在这两个里选一个，实际加了**第三种**。两个原选项各有具体后果：**判失败**会让这个入口长期红着，而长期红着的门禁训练人忽略红字 —— 那比没有判定更坏；**跳过**让「跑过了、没报错」看起来像通过，而那正是「退出码 0 不等于成功」要挡的错觉。第三种的形状抄的是脚本里已有的「局部范围未判」（`C9`／`C11` 在带 `--plan` 时走它），所以不是新发明一套。另补一条守卫：**判定全是等值未判时判失败**，否则这个状态本身会变成新的静默通过口子。
- **第三处（脚本的摘要措辞变了）**：结果那一行从「X/X 条通过」改成「X/X 条**判得到的**通过」，后面另接「另有 N 条等值未判：…」。**这会改到每一个读那几行的人**，包括 `DOC-130` 那条端到端验收 —— 它现在写着「全部判据通过」，而那句话按字面已经达不到了（有两条不参与「通过」）。**没有替 `DOC-130` 改它**，那是它自己那一条的事；这里写下来免得它到时候把这当成一次回归。
- **第四处（`GP-111` 那一句留着没写）**：`GP-111` 的验收里有一条「`GP-110` 那条「每点精力的钱」按**整条链的终点**算、不按每一步算，这一句写进判据」。**本条没写它** —— 两级链还不存在，而那一句是 `GP-111` 的验收项；提前写会让它在一条还没有的链上先立规矩。

### 权衡

**也可以先不接进推演，只把两条判据写在文档里，等产量进来再实现。** 少动脚本、也不必发明第三种状态。否决理由是它把同一件事拆成两轮，而中间那段没有任何东西提醒「这两条还没人判」—— 文档里一条判据躺着不进入口，正是原先 `C10` 那个形状，而它一直挂着没人动就是证据。接进来并报「等值未判」之后，每次跑推演都会把这个缺口念一遍。

代价写明：脚本现在有一个不判事的判定，**读摘要的人要分得清三种状态**（通过、不成立、等值未判），而原先只有两种。这笔代价换到的是缺口有声音。
