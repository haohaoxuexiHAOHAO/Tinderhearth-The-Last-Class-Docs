# GP-107：对话涨关系加一个节流阀

> **只读归档 · 历史背景，不是现行依据。** 现行事实在本页正文点到的那几份活文档里；状态与剩余动作在[待办台账](../../../spec/issues/README.md)，不在本页。

## 目标

「顾不上所有人」这件事是真的 —— 走过去按一下键不能对全队每人吃满当日关系上限。

## 来源

PRD：`spec/prd-richness-and-feel.md` 的 `US-007`。

立项理由：[`人际系统`](../../../design/人际系统.md)把全部压力押在每对每日涨幅上限上（因为关系只升不降，没有别的压力来源），而送礼按件、个人请求按次、教学一天一次都各有自己的节流阀 —— **只有对话那条涨法没有**。一条零成本可重复的涨法就足以让那条唯一的压力失效，而它是这套系统的全部张力。

作者已定的形状：**每人每天第一次对话涨关系，之后是普通聊天、每人每天最多三次**；超出之后他不再回应新的闲聊。

## 依赖

无。文档侧可以现在就改；落地跟 `GP-38` 走。

## 验收标准

- [x] [`人际系统`](../../../design/人际系统.md)多一节「对话那条涨法每对每天只兑现第一次，之后是普通聊天」，形状与教学那条一天一次同源；那句「每条涨法另有自己的节流阀」的例子里补上对话，并写明**一条都不许缺**
- [x] 普通聊天写明它**根本不调那条管道**，理由是管道只收正值且每次提交必须答得出「它为什么涨了」—— 零增量的提交两头都答不上，还在一条承重管道上开一条无副作用的路径
- [x] 反证进[`人际系统`](../../../design/人际系统.md)的验收：当天第一次对话产生增量、**第二次不产生**（标成承重项的反证 —— 它挡的正是「对话没有节流阀」那种实现）
- [x] 拒绝那条反证也进去了，但**保证不放在气泡上**（见下面「偏离」）：拒绝产出的结果与「聊了一句」不是同一个取值，且**把气泡额度压到零时那个结果照旧产出**
- [x] **载体一个都没新建**：普通聊天那句话走[`气泡对话系统`](../../../design/气泡对话系统.md)（那一份的时机表多一行），而拒绝那一下的保证落在**角色的反应**上 —— 它是表现不是界面件，归作者实机
- [x] 顺带把当日那几个计数器的家定下来：**临时续玩点**（跨不过一次睡眠）。不定这一格的话退出再续玩就把计数清零，节流阀换个入口照旧被绕过 —— 反证一起写了
- [x] 上限的量纲与两条约束形式登记进[数值模型](../../../design/数值模型.md)关系那一行；**值不在本轮给**（见下面「偏离」）
- [x] `python tools/check_docs.py` 0 FAIL；动了[数值模型](../../../design/数值模型.md)所以另跑 `python tools/simulate_week.py --check-doc`，也过

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：「每人每天最多三次」这个计数记在哪一侧。立项时没问这一格。
- **选择**：当日那几个计数器（这一对今天涨了多少、今天对话过没有、今天聊了几次）**家在临时续玩点**。
- **理由**：按[`存档系统` · 进哪一侧：判据一句话](../../../design/存档系统.md)那条判据它们跨不过一次睡眠（新的一天全部归零），所以家不在正式存档。**这一格是整条节流阀的前提**：计数器只在内存里的话，退出再续玩就清零，于是节流阀换个入口照旧被绕过 —— 而那正是本条要挡的东西。`GP-106` 刚把「续玩点是全量快照」写死，所以这一格现在答得干净。
- **另一处**：那条既有的每日涨幅上限**本来也欠这一格**（同一个形状、同一个漏法），所以一起答了，不是另起一条。

### 偏离

- **方案怎么说**：「那个『看得见的表达』走[`气泡对话系统`](../../../design/气泡对话系统.md)已有的管道，不新建载体。」
- **实际怎么做**：**保证不放在气泡上。** 他说的那句话走气泡（可以被丢弃），而「玩家知道自己被拒了」这份保证落在**角色的反应**上 —— 表现，归作者实机。
- **为什么**：气泡按正典**不承载必要信息**、且在额度紧张时**按设计会被丢弃**（[玩法定位 · 对话：气泡与正式对话是两套东西](../../../canon/gameplay/玩法定位.md)）。把保证放在一个允许静默的通道上，等于把「不是静默无反应」写成一句没有兑现处的话。**载体仍然一个都没新建**：那份保证不是界面件，形状照[`界面系统`](../../../design/界面系统.md)那条「打断反馈由预备帧动画本身承担，不是一个界面件」走，要求的原句照[`伤害系统`](../../../design/伤害系统.md)那条免疫走。
- **第二处**：验收原话是「第五次闲聊被拒」，实际写成**「点到声明的上限之后再搭话被拒」**。按字面写的反证会在调值那天静默失效，而那个值按本页纪律归[数值模型](../../../design/数值模型.md)。
- **第三处**：PRD 给了「最多 3 次」这个数，本轮**没写进任何文档**。[`人际系统`](../../../design/人际系统.md)自己那条「不定任何数值」与本轮 PRD 的「不在本轮给任何值」都指向同一处：量纲与约束形式进[数值模型](../../../design/数值模型.md)、值跟 `GP-7` 走。**校准方向写进去了**（够玩家听出这个人今天有话说，不够他把这个人的语料一天听空），所以给值那一轮不是从零开始猜。

### 权衡

普通聊天那几次也可以**与对话共用同一个载体**（都是接管输入的正式对话，只是后几次不涨关系）。否决理由：那样玩家每天第四次按下去还要暂停一次世界，只为了听一句闲话 —— 而正式对话接管输入、按判据就得暂停（[`剧情演出系统`](../../../design/剧情演出系统.md)）。分开之后**玩家按下去就看得出今天这一次是哪一种**，而这个分别本来就该看得见：它是「涨不涨关系」唯一的即时线索（另一条是爱心的填充量，但那要打开面板才看得到）。

### 待确认

无。

**两处核过但没改**：

- [`气泡对话系统`](../../../design/气泡对话系统.md)那条「额度挡下的那一次不进冷却池」在新增的搭话时机下仍然成立，一个字不用改 —— 搭话与进场景、姿态变化走的是同一条路，本轮只在它的时机表上加一行。
- 正典[角色与成长](../../../canon/gameplay/角色与成长.md)那份增长途径清单里「对话」照旧成立（当天第一次那一次），**节流方式是第 5 级的事**，所以正典一个字未动，也没有上游指纹要复核。
