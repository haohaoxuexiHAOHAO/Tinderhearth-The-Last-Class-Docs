# GP-116：图鉴改成按存档位各记一份

> **只读归档 · 历史背景，不是现行依据。** 现行事实在本页正文点到的那几份活文档里；状态与剩余动作在[待办台账](../../../spec/issues/README.md)，不在本页。

## 目标

开第二个存档位时敌人与物品重新变成未知的，重玩有东西可以重新发现。

## 来源

PRD：`spec/prd-richness-and-feel.md` 的 `US-021`。

立项理由：[`图鉴系统`](../../../design/图鉴系统.md)那份记录现在跨全部存档位，而它自己写明了后果 —— **第二个存档位从第一天起就有上一位见过的全部条目与对策**，二周目的「重新发现」被提前消掉了。而那正是重玩理由本来可以放东西的位置：[`多周目系统`](../../../design/多周目系统.md)已经逐条排掉了世界线继承、难度继承与内容解锁条件，二周目的差异全部来自玩家自己的兑换选择。图鉴跨位记这一条还在反向扣它。

## 依赖

无强依赖；跟 `GP-54`（存档）同侧落地。**它改的是 `GP-58` 已经写下的一条结论**，所以那一条的备注要跟着改。

## 验收标准

- [x] 那份记录改成存档位内的一个分片，跟着正式存档走
- [x] 原先「不按存档位各记一份」那段论证连同它写下的代价一起替换
- [x] 可测试：新建存档位时图鉴为空
- [x] 那条「不给以未收录量为分母的计数」**不动**
- [x] [`多周目系统`](../../../design/多周目系统.md)那批跨存档位的东西（积分与已解锁）不受影响，且写明图鉴为什么不在其内
- [x] 那条「两级收录重判」的欠账跟着复述一次现状（它依赖的敌人内容与对策声明都还不存在）
- [x] `python tools/check_docs.py` 0 FAIL

## 实现笔记

### 设计决策

- **模糊点**：改「哪一侧」要先说清依据在哪。`GP-115` 那一轮定下的形状是两层判据（[`存档系统`](../../../design/存档系统.md)）：外层问「它跨不跨存档位」，跨的是玩家级偏好；**只有不跨的才轮到内层那条「跨不跨一次睡眠」**。原先图鉴停在外层「跨」这一格上，所以它根本没走到内层。
- **选择**：外层答**不跨**（一位就是一条世界线，而「第一次见到」是那条世界线里发生的事），内层答**跨一次睡眠**（见过就是见过）—— 所以它是那一位正式存档里的**一个分片**。两层逐层答，写成了[`图鉴系统`](../../../design/图鉴系统.md)里一节加一张两行的表。
- **为什么它不在[`多周目系统`](../../../design/多周目系统.md)那批之内，判据写出来了**：**「它是谁挣来的」** —— 星火积分与已解锁是元进度（通关换来、拿到下一位去花），而图鉴是一张查询表在这一位里填到哪儿了，它换不到任何东西、也不是下一位的起点。**那一份一格未动**：积分与已解锁照旧跨位。
- **正典零改动，这是核过的**：[玩法定位 · 查询与图鉴](../../../canon/gameplay/玩法定位.md)只写「挂手环、已见过的才收录」，而「那份记账进哪一侧」那一句**明确委托给了图鉴那一份**。所以本条一个字的正典都不用改，也没有上游指纹要复核。

### 偏离

- **方案怎么说**：只点了[`图鉴系统`](../../../design/图鉴系统.md)与[`多周目系统`](../../../design/多周目系统.md)两份。
- **实际怎么做**：还改了[`教育系统`](../../../design/教育系统.md)**三处**。
- **为什么**：那一份拿「侧不同」当过两份账的分界 —— 「这本典籍出现过没有」在本存档位，图鉴那份跨存档位，连**验收都写成「换一个存档位之后前者清空而后者不变」**。改侧之后那条用例直接判错。现在两份都按位记，所以分界换成一条**查得出来的形状**：一本典籍投放了但没被捡起时，「出现过」已置位而图鉴那一侧没有它（前者写在放进容器的那一刻，后者写在实例进玩家侧容器的那一刻）。

- **`多周目系统` 那条上游约束原先把一句话记在了正典名下**：它写着「[玩法定位 · 查询与图鉴]：图鉴那份记录跨存档位」，而正典那一节**没有这句** —— 它把「进哪一侧」委托给了图鉴那一份。**本轮顺带改对**：那一行现在写的是「正典不定它，那一份答的是按存档位各记一份」，并写明本页因此没有一个可以照抄的归属。

- **多写了一条「没选」**：不做「跨位一份、位内一份」两层记录。验收没点它，但那是这条改动之后最自然的折中提案 —— 不写下来它迟早被当成兼顾两头的好办法，而它要回答「条目按哪一份显示」，那个问题没有答案能同时满足两头。

### 权衡

- **重复劳动那份代价照旧要付**：同一批东西在下一位里要再见一遍。换来的是那一位真的从零开始 —— 而图鉴是查询表，它换不到战力，所以「再见一遍」的成本就是翻一遍图鉴。
- **「重置图鉴」那条出口现在更不必要了**：新开一位本来就是空的，而正典写明二周目开新位。原先排掉它的理由（能清就等于它还是按某一位记的）已经没有对象，换成了「清了之后已收录条数算什么」这个没人答得上的问题。
- **两级收录（见过／摸透）那笔欠账没有被推进，也没有被撤**：它原先有一条加速理由（下一位从第一天就有全部对策），**改成按位记之后那条加速理由没有对象了**；而重判条件本身一个字不改 —— 它等的是敌人内容与对策声明，两样都还不存在。

### 待确认

- **存档体积**：那份记账从一份（跨位）变成每位一份，所以最坏情况下它乘存档位份数。**是推断，不是实测** —— 它存的是标识集合，量级由内容条数定；真要量就走[`存档系统` · 存档位摘要与体积实测](../../../design/存档系统.md)那个既有入口（写入之后报得出按分片分摊的字节数）。**本条不给那个数**，它跟日记那一行同侧（`GP-7`）。
