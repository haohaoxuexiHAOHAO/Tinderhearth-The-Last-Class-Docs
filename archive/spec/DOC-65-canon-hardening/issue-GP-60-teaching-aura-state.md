# GP-60：「薪尽火传」落成状态载体上的一条永久项

> **只读历史归档，不得作为现行依据。** 现行事实：角色约束在[人物 · 战斗中的位置：教练，而非输出核心](../../../canon/characters/人物.md)，结构在[`状态效果系统` · 薪尽火传：一条状态，两侧各一项](../../../design/状态效果系统.md)，学生那一半的出口是[`成长系统`](../../../design/成长系统.md)派生表。**这个编号还没做完** —— 文档已交付而代码一行没写，落地并进 `GP-18`，状态在[待办台账](../../../spec/issues/README.md)。

## 实现笔记

### 设计决策

- **模糊点**：「同时改两侧」在一份**按角色各存一份**的载体上落成什么 —— 是一项挂在主角身上然后由结算去找队友，还是两侧各挂一项。
- **选择**：两侧各挂一项，来源字段填同一个来源。
- **理由**：载体本来就是按角色各一份，所以「各挂一项」不加任何结构；而「一项管全队」要让结算知道「队伍里有谁」，等于给载体加一个它现在没有的概念，还要为解除、恢复、存档与缺 mod 认不出来源各写一次例外。**代价写明**：它在载体里看起来是多项而不是一条队伍光环，不如后者直观。

### 偏离

- **方案怎么说**：旧名在两个仓与 `.kiro` 里都不得出现（[PRD](./prd.md) 的 FR-16）。
- **实际怎么做**：活文档里 0 处；本批过程件（PRD、本条目、`DOC-72` 条目）里还有，那几处写的是「旧名是什么、为什么不用它」。
- **为什么**：过程件归档之后就不在活文档里了。而那条**理由**要留下来 —— 它已经改写成不含旧名的形式，写进[`状态效果系统`](../../../design/状态效果系统.md)的「理由与取舍」（「没选用『授课』给那条状态命名」），所以半年后有人再提「叫它战斗授课不是更直白」时，答案查得到。

### 权衡

- **「玩家不能关它」没有做成载体上的一个新字段。** 载体已有「可否解除」那一格，但它答的是「有没有道具或技能解得掉」；而这条状态的真正约束是**玩家手里没有那个入口**，那是内容侧的事实，不是载体要表达的属性。做成新字段会多一格只有一个用户的结构。
- **[`教育系统`](../../../design/教育系统.md)那条理由刻意自己写、没有抄[人物](../../../canon/characters/人物.md)。** 正典说的是「它不占额度、不降失衡」这个结论，而教育系统要答的是「为什么它不算一条产出渠道」—— 按那一页自己的渠道形状（花掉额度、对一个确定对象、产生一次可结算的事件）逐条对，三样它都不满足。

无。
