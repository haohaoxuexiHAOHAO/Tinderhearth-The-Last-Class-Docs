# GP-128：播种取随身栏选中那一格的种子

> **历史背景·非依据。只读归档件，不得作为现行依据。** 现行事实见同目录 [`prd.md`](./prd.md) 的「归档三问」；状态与剩余动作在[待办台账](../../../spec/issues/README.md)，不在本页。

## 目标

一块地里种得下两种以上作物，全程不改配置、不重启。

## 来源

- PRD：同目录 [`prd.md`](./prd.md) 的 `US-003` 与端到端那一条 `US-007`
- 现状：`src/World/Farm/FarmField.cs` 上那个写死作物标识的导出属性是脚手架，
  它的存在理由与要换掉的原因都在那个类的注释里

## 依赖

`UI-34`（随身栏那条六格）—— 没有「选中哪一格」这个读口，本条无从取值。

## 验收标准

- [x] 选中作物 A 播一格、换成 B 播另一格，两格长出来的是各自那一种
- [x] 选中的那一格**不是种子**时，对已锄的地按下去被拒**且说得出是这一种原因**
- [x] 选中的那一格是**空的**时，同上被拒且原因与上一条**分得开**
- [x] 那一格状态不允许播种时被拒，原因与前两种**都分得开**
- [x] `src/World/Farm/FarmField.cs` 里那个写死作物标识的导出属性**被删掉** ——
      换来源不是两条路并存
- [x] 端到端走完主路径：选中第 N 格 → 那一格是种子 → 对已锄的格播种 → 地里长的是那一种
- [x] 端到端测试独立可重复，自己准备与清理数据（规则层，不启动引擎）
- [x] 代码仓 `python tools/verify.py` 五步全绿
- [ ] **作者实机确认**：换一种种子再播，这一下顺不顺手
- [ ] **作者实机确认**：三条被拒路径各撞一次，分不分得出是哪一种 ——
      **其中一条撞不到**，见下面「偏离」
- [ ] **接进一个真场景**：本条改的是 `FarmField`，而俯视经营场景还不存在。
      **卡在 `ENG-21`／`GP-87` 的作者那一半**，与 `UI-34` 同一个处境

## 实现笔记

### 设计决策

- **模糊点**：三条被拒原因该由谁答。`Plot.Plant` 只返回 `bool`，它答得了「这一格许不许播」，
  答不了「他手上那样东西能不能播」—— 而后者是两种不同的情况（空手，与拿着一样不是种子的东西）。
- **选择**：新开 `rules/Economy/Planting.cs`，一个枚举加一个函数。`Plot` 一行不改。
- **理由**：把两条手上的原因塞进 `Plot` 会让它知道「玩家手上有什么」，而那是界面侧的事；
  而让 `FarmField` 自己判会把规则放进引擎层，测不到。

- **模糊点**：经营那一侧的规则层要不要引用界面那一侧的 `CarrySlot`。
- **选择**：**不引用**。`Planting.TryPlant` 收的是一个物品标识（空手传 `null`），
  由调用方把随身栏那一格翻译过去。
- **理由**：两者在同一个程序集里，引用编译得过 —— 但那会让 `rules/Economy` 依赖 `rules/Ui`，
  而依赖方向一旦反过来，以后「谁能改谁」就说不清了。

- **模糊点**：判的顺序是先看手上还是先看地里。
- **选择**：**先看手上。** 两者同时不满足时报「空手」。
- **理由**：玩家按下去那一刻，动作是按**格子状态**派发的（已锄的格才派发到播种），所以「这一格
  不许播」在游戏里到不了。把手上那两条排前面，他拿到的就是他真能改的那一条。配了一条用例钉住
  这个顺序。

- **模糊点**：「这个标识是不是种子」怎么查。
- **选择**：由调用方给一个解析器（`Func<string, CropDefinition?>`），答不出来就是「不是种子」。
- **理由**：物品定义是内容、会被 mod 换掉（[ADR-0022]），规则层不许持有一张「标识对种子」的表。

### 偏离

- **方案怎么说**：验收里要求三条被拒路径各在实机撞一次。
- **实际怎么做**：**其中「这一格不许播」那条实机撞不到**，它只有规则层用例。
- **为什么**：动作键按格子状态派发，玩家**没有办法主动选一个不该用的动作** —— 这个代价
  `GP-87` 落地时就写明了，本条没有改那条派发。要在实机撞到它得先有一套「先选工具再用」的操作，
  而项目明确不做工具系统。**用例里写明了这一条为什么只在规则层**，免得后来的人以为它是漏测。

- **方案怎么说**：`FarmField` 的作物来源从写死改成随身栏。
- **实际怎么做**：改了，但**格子里先装什么仍然是脚手架** —— 由 `FarmField` 把已载入的作物按标识
  排序塞进随身栏。
- **为什么**：正式来源是背包（`GP-23`），它还不存在；换来源归 `UI-35`。**但这与原先那个导出属性
  形状完全不同**：那个属性让玩家在游戏里换不了作物，而现在换格、播种与那三条被拒路径都已经是
  正式的 —— 换来源不改本条任何行为。

### 权衡

**`Planting.TryPlant` 成功那一下真的改了地块状态**，它不是一个只判不做的检查。分成「先问能不能、
再真的播」两步看着更干净，代价是两处判据会分叉，而分叉时只表现为「按了没反应」。

**件数为零的那一格算空手，不算「拿着一样不是种子的东西」。** 「有标识没件数」是刚用完，
玩家看到的是空格 —— 报「不是种子」会把他引到换东西上去，而他该做的是换一格。
