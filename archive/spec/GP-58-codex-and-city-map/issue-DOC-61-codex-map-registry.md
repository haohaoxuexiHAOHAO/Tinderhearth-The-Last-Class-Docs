# DOC-61：这一批的新量登记与规模基准复看

> **只读历史归档，不得作为现行依据。** 现行事实在[数值模型](../../../design/数值模型.md)的尚未给值表与[内容规模基准](../../../canon/gameplay/玩法定位.md)那张表里 —— 逐样判过的结论就在那两处，本文只留当时的判断过程。

## 目标

让本批出现的每个量都在该在的地方登记着，而不是散在两份新文档的正文里；并逐样重判内容规模基准要不要补行。

## 来源

- PRD：[`prd-codex-and-city-map.md`](./prd.md) 的 `US-007`
- 起因：值的唯一来源是参数表（[`数值模型` · 尚未给值的量，各自写明校准办法](../../../design/数值模型.md)），而**接口常量与派生量刻意不进那张表** —— 分不清就会有量被当成数值搬走，也会有数值没人给。

## 依赖

`GP-58` 与 `GP-59`（要先有那两份文档才知道出现了哪些量）。

## 验收标准

- [x] 进那张表的每一项都写明校准办法与归属，**并在同一处写明给值那一轮必须同时把判据接上**；判不出判据的写成约束形式。

## 实现笔记

### 设计决策

- **模糊点**：本批出现的那些量各归哪儿。
- **选择**：**参数表加零个量**，一项进[`数值模型`](../../../design/数值模型.md)的尚未给值表且归属是 `GP-6`（并进那一行、不新开行），其余全部不是数值。
- **理由**：逐样判的结果（判据与结论都写在这里，两份文档的「下游同步」里各写自己那一半）：

| 量 | 判成什么 | 家在哪 |
| --- | --- | --- |
| 收哪几类 | **接口常量** | [玩法定位 · 查询与图鉴](../../../canon/gameplay/玩法定位.md) |
| 图鉴条目数 | **派生量** —— 它是[内容规模基准](../../../canon/gameplay/玩法定位.md)各行的投影 | 那张表各行 |
| 已收录多少条 | **派生量** —— 数出来的 | 读口，不存 |
| 存档体积 | **不是一个要给值的量** | 走[`存档系统` · 存档位摘要与体积实测](../../../design/存档系统.md)那个既有入口 |
| 城区图张数 | **接口常量** | [玩法定位 · 场景规模](../../../canon/gameplay/玩法定位.md) |
| 地点数 | **内容量**，跟着正典点名的设施走 | [世界观 · 主要设施](../../../canon/world/世界观.md) |
| 边界点数 | **派生量**，跟着拓扑走 | 内容 |
| 边界切换要持续多久 | **手感量** —— 它压的是误触防护，好不好只能实机走一遍 | 并进[`数值模型`](../../../design/数值模型.md)尚未给值表那条 `GP-6` 行；**量级在正典，表里不复述** |
| 接近时显示目的地名的范围 | **作者摆的区域**，不是数值 | 场景里的导出字段（[ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md)） |

- **模糊点**：那段切换时长该进[`数值模型`](../../../design/数值模型.md)的表，还是只记在 `GP-6` 的台账行里。
- **选择**：进那张表，**并进已有那条 `GP-6` 行**。
- **理由**：照既有做法 —— 俯视移动速度就是这么进去的（那一行本来就是「只能实机逐帧调」那一类的集合）。新开一行会让同一类量有两处登记。同一格另写明**它与转场读条是两个数**（一个压误触、一个压脱离），免得给值那一轮有人顺手共用一个值。

### 偏离

- **方案怎么说**：动了数值那两份就跑两个入口。
- **实际怎么做**：照做，但 `--check-doc` **第一次跑是失败的**：它把同一行上两个反引号链接之间那段不含空白的带点文本认成了假路径候选。
- **为什么**：那个脚本的候选切法是「一对反引号之间不含空白且带点」。**改法是在两个链接之间加空格**，不是改脚本 —— 脚本那条粗切法同时在挡真的漏查。

### 权衡

**[内容规模基准](../../../canon/gameplay/玩法定位.md)逐样重判，结论是都不补行，而三条理由各不相同：**

| 候选行 | 判成什么 |
| --- | --- |
| 图鉴条目 | **不补。** 它是那张表各行的投影 —— 补一行等于把那些行加起来抄一遍，而加一类内容时那一行会静默漏掉 |
| 城区图 | **不补。** 它的家在[玩法定位 · 场景规模](../../../canon/gameplay/玩法定位.md)那张表；补一行就是同一个数两个家，而这张表最怕的正是那个 |
| 地点 | **不补。** 「每张图含一处特殊设施」已经写在场景规模那一行里，而具体有哪些地点跟着[世界观 · 主要设施](../../../canon/world/世界观.md)走 —— 补一行会变成第三处说同一件事 |

**判据前提的复核是人看的**：那张表的数一个没动，所以那几条平衡判据的前提原样成立；跑推演只证明参数那一侧没被顺手动坏。**这一句必须写出来** —— 报「通过」而不说它是人看的，就等于假装它被机器守住了。
