# GP-58：`design/图鉴系统.md`（含它自己那个存档分片）

> **只读历史归档，不得作为现行依据。** 现行事实在[`图鉴系统`](../../../design/图鉴系统.md)：收的是内容定义不是实例、「见过」按类各声明一个落在已有动作上的时刻、收录只有一级、对外只有一个幂等且不可撤销的写入口、不给「还没见过的有几个」。**这个编号还没做完** —— 文档已交付而代码一行都没写，落地顺序与状态在[待办台账](../../../spec/issues/README.md)，不在本文。

## 目标

让「按什么粒度收、谁置位、那份『已见过』记在哪」只写在一处，而且那一处**对别人的世界状态一个写入动作都没有**。

## 来源

- PRD：[`prd-codex-and-city-map.md`](./prd.md) 的 `US-001` 与 `US-002`
- 起因：正典把图鉴的要求写全了（[玩法定位 · 查询与图鉴](../../../canon/gameplay/玩法定位.md)），但**那份「已见过」被三份文档各推开一次** —— [`统计事件总线系统` · 它给存档加零个字段](../../../design/统计事件总线系统.md)写「不是本页的」、[`事件系统` · 持续引导：同一条管道，两条出口](../../../design/事件系统.md)写与引导清单「条目一条都不互通」、[`装备系统`](../../../design/装备系统.md)写「必须给图鉴一个挂载点」。于是「那份记账要不要进存档」没人答，而[`存档系统` · 一个分片要声明什么](../../../design/存档系统.md)要求分片由持有者自己声明。
- **`US-001` 与 `US-002` 合成本条**：它们是同一份文档，拆成两条会让同一份文件有两处进度。

## 依赖

无阻塞依赖。**与 `GP-59`、`DOC-59`、`DOC-60` 互相引用**，四条一起写完一起验。

## 验收标准

**先答一个结构问题，答案与过程都写进本条的实现笔记：** 图鉴与城区地图该写成几份文档。按[`生产系统` · 什么时候拆出去单独成篇](../../../design/生产系统.md)那条判据（**它有没有自己的状态机**）逐样判一遍，并用上第 6 批那条补充（**多读者无主时问它有没有宿主页**）、第 8 批那条（**两样能不能互为宿主**）与第 9 批那条（**它有宿主页时先问「分出去会不会让同一条判据有两个家」**）—— 不默认拆，也不默认不拆。

### 文档骨架

- [x] 按 [SYSTEM 模板](../../../templates/SYSTEM.md)八节写全、顺序不变，多一节当场判失败。
- [x] `type: system`、文件名以「系统」结尾、放 `design/` 根下、`upstream` 指[玩法定位](../../../canon/gameplay/玩法定位.md)。
- [x] **同批被正典链接到**（`DOC-59` 那一条做），否则文档一落地就判失败。
- [x] 接进[系统文档与提案索引](../../../design/README.md)的系统文档表（`DOC-62` 那一条做）。

### 收录的形状

- [x] 写明**图鉴收的是内容定义、不是物品实例**，并写明[`物品系统` · 没选让图鉴按品质分条](../../../design/物品系统.md)那一条由此变成这条判据的一次应用 —— **写链接，不抄那一条**。
- [x] 收录粒度按类各一行写成一张表，每行填「收录对象是什么」与「置位时刻是哪个已有动作的完成点」；**宝物、宝石与作物都是物品，走物品那一条，本页不为它们另定粒度**。
- [x] **「见过」不是一条通用定义，而是每一类各声明一个时刻**：物品那一类取**进过任何一个属于玩家侧的容器**，敌人那一类取**显形那一刻**。同一处写明这两条为什么不统一 —— 物品那一侧不读可见集（[`感知与视野系统` · 目标离开可见集之后：记忆项与残影](../../../design/感知与视野系统.md)那份数据每帧重算、且不在俯视场景生效，把长期记录挂在缓存上不报错；而且走一趟商业区会一次收录一大批），敌人那一侧必须读（条目的用处是查对策，等打死才收录就白瞎了）。
- [x] **收录只有一级**：没有「见过／摸透」两档，一个标识就是一位记录（结构约束）。同一处写理由（正典只给了「已见过的才收录」这一条判据，两档要在它旁边长出第二条而正典没给）与**重判条件**（等敌人内容与对策声明真的存在、证明一级不够用时按同一条判据加一位 —— 那时是加法）。
- [x] 宝物条目里的副词条**只列已经在实际物品上见过的那几条**，不列候选池（结构约束）—— 同一条收录形状的第二次应用，不给条目开例外。
- [x] **敌人放出来的招不进技能那一类**：技能那一类只收角色学得到的技能（学会那一刻收录），敌人的招在敌人条目里，对策声明本来就挂在[`战斗AI系统`](../../../design/战斗AI系统.md)那上面。同一处写理由：混进去之后技能图鉴里会有一批永远学不会的条目，而它的用处正是「我能学什么」。

### 谁置位、谁读

- [x] **对外只有一个写入口**（「记下见过这个标识」），本页对别人的世界状态一个写入动作都没有（结构约束）。
- [x] 同一个标识重复置位是**幂等**的，集合大小不变。
- [x] **收录不回退**：关卡失败或撤退之后那一关里置位的条目仍在；全库没有「撤销一次收录」的入口（结构约束）。理由写明：「见过」是一个关于玩家的事实，不是一件战利品；要回退就得记「哪几位是这一关里置的」，那是第二份存储。
- [x] **不订阅[`统计事件总线系统`](../../../design/统计事件总线系统.md)来记账**：全库找不到「图鉴读总线」这条依赖（结构约束）。理由自己写 —— 总线只发瞬间，而且它明写订阅者不存在时丢弃、不排队，把一份必须正确的状态挂在一条可丢的通道上不报错。**不抄那一份「不是本页的」那句的理由。**
- [x] 写明**关卡内照常收录**，并写清它与[玩法定位 · 手环的管理功能在关卡内不可用](../../../canon/gameplay/玩法定位.md)为什么不冲突：那条限制的对象是玩家的**操作**，而收录是世界里发生的事；正典点名图鉴在关卡内可查看。
- [x] 写明与[`事件系统` · 持续引导：同一条管道，两条出口](../../../design/事件系统.md)那份引导清单**条目一条都不互通**，只共用那条收录形状；**写链接、不复述那一份的理由**。
- [x] 按类别数得出**已收录**多少条（读口），而它由集合算出来、不是一个存起来的数。
- [x] 接口那一节写成「谁调它、谁读它」一张表，并写明**挂载点到此为止**。

### 不做的那两条，各写自己的理由

- [x] **不提供「还没见过的有几个」这类读口**（结构约束）。理由**自己写**，落在收集动机与剧透的边界上：那个分母是「全部内容定义有多少条」，显示它等于把还没见过的东西的存在告诉玩家，而那正是「已见过才收录」要挡的；另一半是内容外置之后分母会随内容包变大，玩家会把它读成「我倒退了」。**同一处写明与前几批那几处不同源、不许互抄。**
- [x] 同一处写明**允许什么**：按类别数得出已收录多少条 —— 那是玩家自己的记录，不泄露任何没见过的东西。不写这一句，「不给计数器」会被读成「连自己见过几个都不给看」。
- [x] **每日结算不为图鉴加一步**（结构约束：那张顺序表的步数在本页落地前后完全一致）。**理由写在那份文档里、本条不抄** —— 要求只有一条：**它与别处任何一条「不加步」都不同源**，按词核对那一轮逐处读一遍来证明。
- [x] 同一处写明**不列那份名单** —— 要查有哪些就按词搜「不占一步」。

### 存档

- [x] 在「下游同步」里**自己声明那个分片**：分片标识、持有它的系统、进哪一侧、缺字段补什么，按[`存档系统` · 一个分片要声明什么](../../../design/存档系统.md)那张表填齐；缺一格在注册那一刻报错。
- [x] 进哪一侧按[`存档系统` · 进哪一侧：判据一句话](../../../design/存档系统.md)判出**正式存档**，理由写明（见过就是永久见过，跨过一次睡眠仍成立）。
- [x] 存的是**标识集合**而不是条目内容；解析不到的标识走[`存档系统` · 载入：先读分片，再统一解析标识](../../../design/存档系统.md)那份不可用清单，**隔离而不是删除**，装回内容后一条不少。
- [x] **不存派生量**：「已收录多少条」不在分片里（[`存档系统` · 派生量不单独存](../../../design/存档系统.md)那条判据的一次应用）。
- [x] 写明**不按周目继承**（它在存档位里，而一位就是一条世界线），并写明**重判条件**：等二周目与元进度那一批真给玩家级记录开了一个家时按那时的结构重判。
- [x] [`存档系统`](../../../design/存档系统.md)**一个字不用改**。若发现必须改它，说明本条把某个字段清单放错了地方 —— 回头改本页。

### 收口

- [x] 写一节同名不同物：至少写清「清单」这个词在本作的几处所指各指哪一份（[`存档系统`](../../../design/存档系统.md)那一份已经列过，本页写链接、只补自己那一格）。
- [x] 「验收」里分「可自动验证项」与「必须实机确认项」，后者为空时写明「无」并说清为什么。
- [x] 「下游同步」里写台账编号、落地顺序、数值归属（**逐样判、结论在 `DOC-61`**）与界面归属（`UI-22`）。
- [x] `python tools/check_docs.py` 0 项必须修复 —— **与 `GP-59`、`DOC-59`、`DOC-60` 合并之后才成立**。

## 实现笔记

### 设计决策

- **模糊点**：收录粒度要不要逐类各定一套规则 —— 正典点名了几类，而每类的实例形态都不一样（宝物有掷定的副词条、敌人有档位、技能有实战值档位）。
- **选择**：**收的是内容定义、不是实例**，一条判据管全部；逐类只定「哪一刻算见过」。
- **理由**：逐类各定一套规则会长成一张会跑偏的表 —— 每加一类就要重新判一次「这一类的什么算一条」。而[`物品系统`](../../../design/物品系统.md)那条「同一种物品的不同品质只收录一条」本来就是这条判据的一个实例，把它升成判据之后那一条从例外变成推论，别处不用再各答一遍。

- **模糊点**：物品那一类的「见过」取哪一刻。
- **选择**：**取得过**（进过任何一个属于玩家侧的容器）；**敌人那一类单独取显形那一刻**。
- **理由**：读可见集有两处代价 —— 它每帧重算（[`感知与视野系统`](../../../design/感知与视野系统.md)明写存它等于存缓存），而且它不在俯视场景生效；另一半是走一趟商业区会一次收录一大批，「已见过才收录」那半个收集动机当场没了。敌人必须例外，因为条目的用处是查对策（[`战斗AI系统`](../../../design/战斗AI系统.md)那份声明），等打死才收录就白瞎。**由此「见过」不是一条通用定义，而是每类各一行。**

- **模糊点**：「不给未收录计数」要不要连「已收录几条」一起不给。
- **选择**：给已收录的条数，不给任何以未收录量为分母的东西。
- **理由**：不写这一句，那条边界会被读成「连自己见过几个都不给看」—— 而已收录是玩家自己的记录，不泄露任何没见过的东西。

### 偏离

- **方案怎么说**：`DOC-60` 原写[`感知与视野系统`](../../../design/感知与视野系统.md)一个字不用改。
- **实际怎么做**：它加了一行「出」（敌人首次进入可见集时往图鉴报一次）。
- **为什么**：挂载点要两侧都列全，否则本页单方面声明一条对方不承认的接口。那一行同时写明**图鉴不是它那几类读者之一** —— 拿到的是一次转变而不是一份数据，所以「一次计算、没有第二份」与那条清空可见集的反证都不受影响。同一条理由让[`背包系统`](../../../design/背包系统.md)与[`成长系统`](../../../design/成长系统.md)各加了一行挂载点。

- **方案怎么说**：本条与 `DOC-60` 原把「不加步」的理由抄在条目与 PRD 里。
- **实际怎么做**：两处都改成**只要求「它与别处任何一条都不同源」，理由只写在系统文档里**。
- **为什么**：按词核对第二轮抓到那条理由与[`主线推进系统`](../../../design/主线推进系统.md)那一条同源（都写成「置位时刻由因果可见性定」）。改掉本页那条之后，抄在别处的副本立刻过期 —— 那正是「理由只该有一个家」的证据，所以根治办法是删副本而不是同步副本。

### 权衡

**拆成几份文档的判断过程。** 判据取[`生产系统` · 什么时候拆出去单独成篇](../../../design/生产系统.md)那一条（**它有没有自己的状态机**），加第 6 批那条补充（**多读者无主时问它有没有宿主页**）、第 8 批那条（**两样能不能互为宿主**）与第 9 批那条（**它有宿主页时先问「分出去会不会让同一条判据有两个家」**）：

| 候选 | 有自己的状态机吗 | 有宿主页吗 | 结论 |
| --- | --- | --- | --- |
| 图鉴的「已见过」与收录粒度 | **没有** —— 收录是往一个只增的集合里置位，没有流转 | **没有**，而且被三份文档各推开一次；读者是物品、装备、技能、敌人与作物那几侧 | **单独成篇** |
| 城区地图与导航 | 边界切换带一个蓄势计时，但那是一条计时不是流转表 —— 与侧视那条「按键加读条」同量级，而那一条只是[`关卡系统`](../../../design/关卡系统.md)里的一节 | **没有**：那一份明写不做它，`design/` 根下也没有管城区的文档 | **单独成篇** |
| 两样合成一份 | —— | —— | **不合** |

**不合的硬理由**：唯一的共同点是「都挂手环」，而手环是**载体**不是系统 —— 按那条合篇会开出一份手环杂物间。而每一条要紧的性质都相反：本页按「已见过」收录，那一份**刻意不按「已去过」收录**；本页关卡内只读，那一份关卡内根本不存在；本页那份记账跨睡眠成立，那一份的「在哪张图」只进续玩点。**第 9 批那条补充在本批不适用** —— 它是「有宿主页时」才问的，而两样都无主。

**「靠[`统计事件总线系统`](../../../design/统计事件总线系统.md)代记」考虑过**，它看起来正是干这个的。没选：那一份明写订阅者不存在时丢弃、不排队，一条可丢的通道承载不了一份必须正确的状态，而分叉的表现是「我明明见过却查不到」且不报错。**理由与那一份自己写的「它只发瞬间」不同源，两条都留。**

**「做两级收录（见过／摸透）」考虑过**，敌人那一侧尤其可惜（第一眼就把对策全给了）。没选：正典只给了「已见过的才收录」一条判据，两档要在它旁边长出第二条（什么算摸透），而那条判据只能由本页发明、没人能核；真实代价也不是多存一位，是每一类都要再定第二个时刻。**重判条件写进了文档。**

**「结论被重判的条件」另有一条**：不按周目继承是因为图鉴在存档位里；等二周目与元进度那一批真给玩家级记录开了一个家（成就已经在那一侧），按那时的结构重判。

### 待确认

无。**本批不为本页新建 ADR**：门槛是「影响多系统且难撤销」，而记账归属的撤销成本是改一条调用方向，规则的家已经在[`统计事件总线系统`](../../../design/统计事件总线系统.md)与[`存档系统`](../../../design/存档系统.md) —— 再写一份等于给同一条判据加第三个家。
