# UI-41：格子与迷你两档尺寸进排版单位

> **历史背景·非依据。只读归档件，不得作为现行依据。** 现行事实见同目录 [`prd.md`](./prd.md) 的「归档三问」；状态与剩余动作在[待办台账](../../../spec/issues/README.md)，不在本页。

## 目标

格子与迷你成为代码里两档正式尺寸，各自由既有排版单位推出来，改一个单位另一个跟着变或当场红。

## 来源

- PRD：[`spec/prd-ui-art-baseline.md`](./prd.md) 的 `US-001`。
- 两档的画法与用途在[界面绘制约定 · 尺寸阶梯](../../../production/界面绘制约定.md)，本条不复述。

## 依赖

- 无前置：界面件已交付（`ART-27`），本条只动排版单位。
- 与 `ENG-24` 有交界：图标档那段注释由本条改，侧视缩放那个常量仍归它。

## 验收标准

- [x] 可核对：`rules/UI/UIMetrics.cs` 有格子与迷你两档，注释写明它们由哪几个既有单位推出来。
- [x] 可测试：两条关系各一条测试 —— 格子 ＝ 小图标 ＋ 两倍格内边距（格内边距是一像素描边加两像素留白）；迷你 ＝ 栅格。改一个数另一个不跟就红。测试在代码仓 `tests/UI/UISkeletonTests.cs`。
- [x] 可核对：图标档那段注释里过期的理由按现行正典改写，`ENG-24` 条目里那一格同步勾掉。
- [x] 可核对：那几档的注释写明「改它要回去重算[界面绘制约定](../../../production/界面绘制约定.md)里的尺寸」—— 约定里的数是引用，代码这边一改它就静默过期，而能提醒改的人的只有这一处注释。
- [x] 可核对：[界面控件 · 八、排版量从哪来：界面里不写数字字面量](../../../reference/godot/界面控件.md)那段 `UIMetrics` 内容清单改成不列。
- [x] 可核对：侧视缩放那个常量不动 —— 它还在管相机，归 `ENG-24`。
- [x] 代码仓 `python tools/verify.py` 全绿，看它自己打的摘要。

## 实现笔记

### 设计决策

- **格内边距拆成描边与留白两个常量**（代码仓 `rules/UI/UIMetrics.cs` 的 `CellOutline`、`CellPadding`、`CellInset`）。约定里写的就是「一像素描边加两像素留白」，拆开之后改其中一个，格子的边长跟着算出来，不用回头找写死的 22。
- **四档都写成常量**，与 `SafeMargin = Grid` 同一种写法：值由别的常量算出来，编译期就定了。
- **`UIMetrics` 那份内容清单改成不列**：抄一份清单，加一个量这里就静默过期，而这一篇要讲的是「数从哪来」，不是有哪几个。

### 偏离

- **验收原写「格子 ＝ 小图标 ＋ 两倍面板内边距」**，面板内边距是 4，算出来是 24，对不上约定与需求文档里的 22。需求文档的验收写的是「两倍格内边距」，本条照它做，验收那一格已改。
