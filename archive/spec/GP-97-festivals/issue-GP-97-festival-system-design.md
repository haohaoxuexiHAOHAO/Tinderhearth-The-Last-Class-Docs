# GP-97：节日与比赛的结构

> **只读历史归档，不得作为现行依据。** 现行事实在[`节日系统`](../../../design/节日系统.md)；`GP-97` 这个编号仍然开着（剩下的是落地），状态在[待办台账](../../../spec/issues/README.md)。

## 目标

交付 `design/节日系统.md`，让「一个节日怎么声明、谁读它、那天玩家做什么」各有唯一一处答案，而且加一个节日只要填数据。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-001` 到 `US-005`、`US-007`、`US-008`

## 依赖

**无。** 它要的三样输入都在：季节那一维在正典，天气那一维已交付，事件那张后果表已交付。

落地那一半的卡点另记：日期本身还没有持有者（跟每日结算那一批走），节日场景要作者搭（走 `ENG-21` 那条路），比赛另记在 `GP-98`。

## 验收标准

按这个顺序写，前一条不成立时后一条无处落脚。

- [x] **一份按 [SYSTEM 模板](../../../templates/SYSTEM.md)骨架的文档**，含术语一节与一张图；图上标明重画条件
- [x] **声明表**：标识、显示名文本键、第几季、季内第几天、那天办哪几场比赛；每格写明缺了怎么办，缺格一律载入报错
- [x] **每季多少天不复述**（家在正典）；声明的日期落在一季之外时载入被拒
- [x] 同一季同一天声明了两个节日时载入被拒，并报得出是哪两个
- [x] 写明一个节日只占一天、每年同一天重来，而且**这件事不靠任何记账**
- [x] **两个读口**：「今天是哪个节日」与「下一个是哪一个、还差几天」；写明为什么是两个而不是一个两档
- [x] 写明**刻意没有默认取值**，并说清它与天气那个必须有的默认态为什么不同
- [x] **与天气逐项对照的小表**：至少覆盖挂什么、频率、默认态、未来可见性、存档、战斗量
- [x] 写明节日这一半**给正式存档加零个字段**（它由日期与声明表算得出来）
- [x] **预告**走手环通知，不新开界面页也不新开渠道；提前几天是一个全局的值，值进尚未给值表
- [x] **后果**：写明比赛之外一律是事件那张表上的格子，本页没有自己的后果表；方向是事件指节日
- [x] 一个节日对应**一条**事件（一组后果），理由写明；事件前置引用不存在的节日标识时载入被拒
- [x] **不新开钩子、不新增结算步骤**各有一条结构约束写在验收里
- [x] 关系涨幅走那条只收正值的增量管道、带来源标签，并**撞得到那一对的每日上限**（反证）
- [x] **节日场景**：进去时钟停（走关卡那条既有形状）、出来推到散场时刻；那个时刻是全局值、家在正典，本页只写「必须早于熬夜起点」
- [x] 场景里的动作**照扣精力**；精力见底时报名被拒
- [x] 写明场景**不算城区图**、作者摆站位点、常驻 NPC 一律在场而**学生只有今天没被派工的才在场**（读那张按天指派表）
- [x] 写明时钟跳过的那一段里唯一按时刻发生的事已经被正典答过，本轮不为「跳过」新加规则
- [x] 在节日场景里退出游戏时，续玩点恢复到场景入口
- [x] **比赛**：声明比哪一样已有动作、限时多久、读哪个量计分、对手各是什么成绩、名次给什么奖；缺格载入报错
- [x] 写明比赛**不新造动作**；声明一样不存在的动作时载入被拒
- [x] 对手成绩是声明的目标值，写明为什么不模拟 NPC 走一遍渠道
- [x] 比赛期间世界不暂停；产出走生产那条既有入库管道；奖品走背包那个入口且满时只拒不丢
- [x] 只在节日当天的节日场景里报得上名
- [x] 写明**不做比武那一类**，理由是视角
- [x] **边界与非目标**节里，节日与比赛都不碰活跃失衡总量、不碰学生个体失衡、不改任何战斗量
- [x] 那一份的「下游同步」写明落地顺序、数值归哪里、界面归哪个编号
