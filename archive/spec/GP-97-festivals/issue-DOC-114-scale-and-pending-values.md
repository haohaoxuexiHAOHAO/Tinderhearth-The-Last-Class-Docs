# DOC-114：量那一侧

> **只读历史归档，不得作为现行依据。** 现行事实在[玩法定位 · 内容规模基准](../../../canon/gameplay/玩法定位.md)、[玩法定位 · 场景规模](../../../canon/gameplay/玩法定位.md)与[数值模型](../../../design/数值模型.md)的尚未给值表；状态在[待办台账](../../../spec/issues/README.md)。

## 目标

让节日与比赛各有一个起步量、节日场景在规模表上有一行，而那几个还定不出来的数各写明为什么不给、谁来给。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-006`，起步量的判据在它的「技术考虑」

## 依赖

`GP-97` —— 要先知道一个节日与一场比赛各要声明什么，才说得出「多少条才试得出来」。

## 验收标准

改的是[玩法定位](../../../canon/gameplay/玩法定位.md)与[数值模型](../../../design/数值模型.md)：

- [x] **内容规模基准多两行**：节日一行（谁在等它填 `GP-97`）、比赛一行（填 `GP-98`）
- [x] 那两行的「理由」各写清要试出什么 —— 节日那行是日期触发、预告、每年重来与跨季分布；比赛那行是「同一套壳套在不同动作上」，所以要比两样不同的动作
- [x] **场景规模多一行**节日场景，写明**它不算城区图**，所以那份 11 处的枚举与那个张数**一个字不动**
- [x] **尚未给值表**收下这几个量：预告提前几天、比赛限时、比赛的关系涨幅、经济那一面的幅度、奖品量级；每个写量纲、为什么不给、归属
- [x] **散场时刻不进这张表也不进参数表**：它已经有值，家在正典那一节（`DOC-113`）
- [x] 那几行里立得住的约束形式先立下来 —— 预告必须提前到玩家安排得动那一天、比赛限时要短于一天
- [x] 改完按维护入口跑一次 `python tools/simulate_week.py`，证明参数那一侧没被顺手动坏；**那几条平衡判据的前提还成不成立是人看的**，报「通过」时要写明这一点
- [x] `python tools/check_docs.py` 0 FAIL，「谁在等它」那一列的守卫认得出新加的两行
