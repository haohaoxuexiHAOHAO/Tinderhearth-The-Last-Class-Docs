## 验收标准

**链路**：

- [x] 「填一行声明 → 提前几天收到通知 → 那天天气是好天 → 走进节日场景、时钟停住 → 报名一场比赛、扣精力、出成绩与名次 → 奖品进背包 → 退出时时刻推到散场」每一环都指得到一份文档里的一节，**没有一环写着「待定」**
- [x] 失败路径逐条查得到落点：缺格、日期越界、同一天两个节日、事件引用不存在的节日标识、比赛声明一样不存在的动作、散场时刻晚于熬夜起点、精力见底时报名、背包满时发奖

**没有孤儿**：

- [x] 按词搜**两个仓加 `.kiro`**：节日、比赛、`Festival`、`GP-97`、`GP-98`，每处命中都说得出它为什么在那里
- [x] **状态只在台账一处**：新交付的那几份散文里没有第二处写「做到哪了」
- [x] 那张与天气的对照表**只有一处**，别的文档写链接不复述
- [x] 那几个数各自只有一个家：每季多少天、熬夜起点、散场时刻、起步量

**零改动那几处要查得出来**：

- [x] 天气那一份的声明表、权重与预报三处一个字未动
- [x] 事件那一份除后果表那一行之外一个字未动
- [x] 正典「季节影响的那几处」与恶劣天气那几种的名字一个字未动
- [x] 城区那 11 处的枚举与张数一个字未动
- [x] **代码仓这一轮零改动**（`git status` 作证）

**工具**：

- [x] `python tools/check_docs.py` 0 FAIL，**并且看它自己打印的覆盖量摘要**（退出码 0 不等于成功）
- [x] 动过正典之后 `--repin` 跑过，指纹进 git
