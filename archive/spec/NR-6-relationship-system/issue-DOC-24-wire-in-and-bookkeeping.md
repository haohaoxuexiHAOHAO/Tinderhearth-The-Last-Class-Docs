# DOC-24：新文档接进索引，本批记账收口

> **只读历史归档，不得作为现行依据。** 现行事实是[系统文档与提案索引](../../../design/README.md)里 `人际系统` 那一行与[待办台账](../../../spec/issues/README.md)的各行。

## 目标

让 `人际系统` 从 README 点得到、从台账查得到，而不是孤岛；本批的状态只落在台账一处。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-006`
- 判据来自检查器：系统文档没有正典引用会报孤岛，没接进 [`design/README.md`](../../../design/README.md) 会报「从 README 无法到达」。

## 依赖

`GP-38`（文档要先存在）。

## 验收标准

- [x] [系统文档与提案索引](../../../design/README.md)的系统文档表补一行，一句话说清它持有什么、不持有什么。
- [x] [待办台账](../../../spec/issues/README.md)的 `NR-6`、`GP-37`、`GP-38` 三行按完成情况改写，备注**不复述**文档里的规则。
- [x] [待办台账](../../../spec/issues/README.md)「系统深化顺序」档 1 里「信任度与人际」那一项的进度跟着改；档 1 其余项的状态不动。
- [x] `GP-36` 那行确认指得到本批定下的框（五档、档名、基础 AI 不分档），且它自己持有的仍然只是那两样未决 —— **不把本批已定的东西复述进去**。
- [x] 台账每格不超过 360 字符。**往已经超限的格子里继续加就是把 `DOC-17` 记的问题做得更糟** —— 真放不下就拆条目文件，台账只留链接与落地顺序。
- [x] `DOC-17` 那条超长格清单核一遍，本批有没有新增或消掉超限的格子。
- [x] `python tools/check_docs.py` 0 项必须修复。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：`GP-38` 的台账行该不该保留指向本目录条目文件的链接。上一批（`GP-30`／`GP-31`／`GP-32`）改成了不带链接的「X 系统落地」。
- **选择**：**保留链接。**
- **理由**：上一批那三条之所以不带链接，是因为它们的条目文件**已经移进 `archive/`** 了；`GP-38` 的还在 `spec/issues/`。**去掉链接会让那份条目从 README 走不到** —— 实测就是这么被检查器抓到的（一条「从 README.md 无法经链接到达」的提示）。判据因此是：**条目文件还在本目录就必须被台账链着**，归档之后才改成纯文本。

### 偏离

- **方案怎么说**：本条把 `NR-6`／`GP-37`／`GP-38` 三行「按完成情况改写」。
- **实际怎么做**：另外把「系统深化顺序」档 1 那一项的名字从「信任度与人际」改成「人际」。
- **为什么**：那个名字本身带着旧量名。留着它，档 1 会成为全库唯一一处还把「信任度」当量名的地方 —— 而那正是 `DOC-22` 要收的东西，只是它的清单没覆盖到台账自己。

### 权衡

`design/README.md` 那一行写得比其他系统文档长。特意的：这份文档最容易被误用的地方是**「关系不会掉」与「没有闩锁」之间的因果** —— 有人只看到「没有闩锁」会以为漏做了。所以那一行把「所以」写出来了（单调性让当前档位就够，代价是那条不变式成了承重件），而不是只列持有什么。

### 待确认

**一处留给收尾**：本批做完后「下一件」该指哪里。台账现在没有 `最高` 优先级的行 —— 本批七条都完成了，而下一批（任务与关卡）还没开 PRD。这条由 `DOC-25` 或下一轮立项时定，本条不替它决定。
