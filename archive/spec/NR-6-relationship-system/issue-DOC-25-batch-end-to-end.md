# DOC-25：这一批的端到端与交叉核对

> **只读历史归档，不得作为现行依据。** 核对结论已经落在被核对的那几份文档里（[`数值模型`](../../../design/数值模型.md)、[`成长系统`](../../../design/成长系统.md)、[`人际系统`](../../../design/人际系统.md)），没有单独的落点。

## 目标

用一条命令加一次人工对照，看出这一批有没有互相矛盾、有没有把某处说法改漏。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-007`
- 检查器判不了两份散文对同一件事的描述是否分叉（理由见 [WORKFLOW § 3. 反漂移：事实只许有一个家](../../../WORKFLOW.md)的两条边界），所以交叉核对只能人工做。

## 依赖

本批其余全部条目。

## 验收标准

- [x] `python tools/check_docs.py` 0 项必须修复（含体裁归位、八节骨架、正典上游、节名引用、断链、编号、入口可达、行尾）。**看脚本自报的覆盖量摘要，不只看退出码。**
- [x] `python tools/simulate_week.py` 与 `--check-doc` 都绿，判据条数按脚本自报。
- [x] 覆盖关键失败路径：**任何降低关系的调用必须被拒**（单调性那条不变式的反证）；「同一天把全部涨法各点一遍」必须被每日上限挡住；**双方之一声明不参与恋爱时恋爱不成立**；缺少那项声明的角色定义**载入时被拒**。
- [x] 交叉核对表逐处列出处比对 —— 量叫什么、分几档、爱心是刻度还是接口、关系会不会掉、AI 五档读哪两个量、结局条件三读什么；这些事在正典、`人际系统`、参数表与台账里各出现一次且互相不矛盾。
- [x] 全库搜不到「默契」；搜「信任度」「好感度」时它们只作为旧说法出现，不再当量名用。
- [x] 两套五档的档名放在一起看过一遍 —— 技艺那套（生手／熟练／老练／精通／大师）与关系那套（陌生／了解／熟悉／认可／信赖）没有一个词能被读成另一套里的档。
- [x] 机制一律读档位、没有任何分叉读填充量 —— 人工核，因为它是「爱心是刻度不是接口」能不能立住的地方。
- [x] `temp/` 为空（临时文件用完即删）。
- [x] **本条不含实机项。** 表现层是作者在 Godot 里配场景、素材与检查器参数的事（[ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md) 的分工），与「文档之间有没有分叉」没有依赖关系；把实机项挂进文档批次的验收只会让条目永远勾不满。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：验收里那条「覆盖关键失败路径」在一个**纯文档批次**里没有可跑的东西 —— 关系这个量在代码仓一处都没有。
- **选择**：把它读成「**这四条反证已经被写成 `人际系统` 验收里的必做项**」，而不是「本轮跑过了」。
- **理由**：跑不了的东西不许记成跑过了（[WORKFLOW § 7. 结论必须有依据](../../../WORKFLOW.md)：只汇报实际执行过的验证）。四条落在[`人际系统`](../../../design/人际系统.md)的验收那一节，并进了 `GP-38` 的落地顺序 —— 其中**单调性那条被标成承重项**，因为结局判定省掉闩锁全靠它。

### 偏离

- **方案怎么说**：本条只核对，不改文档。
- **实际怎么做**：交叉核对查出并修掉了下面这些，都改了 ——
  - [`数值模型`](../../../design/数值模型.md)有一句写「队友与敌人 AI 那**四档**里『熟练档会闪避有预警的攻击』」—— **档数过期，而且把一个已经被推翻的行为分配当成了事实**（那条分配现在归 `GP-36`）。改成不指定档位，并写明分配未定。
  - [`成长系统`](../../../design/成长系统.md)一处「与队友 AI **四档**同一条」的档数过期。
  - [`人际系统`](../../../design/人际系统.md)的「三套刻度」漏了第四套 —— **生活技能熟练度档位**。见下面「权衡」。
- **为什么**：前两处是同一个形状 —— **改了档数但没搜「四档」这个词**。旧量名与「默契」都搜过了，档数没搜，于是漏了两处。这正是[WORKFLOW § 3. 反漂移：事实只许有一个家](../../../WORKFLOW.md)那条「量级事实的散文副本判不了」的实例：机器分不出两个「四」说的是不是同一件事。

### 权衡

**查出一个还没发生的撞名，选择现在就写下来。** 生活技能熟练度也走档位制，而它**最顺口的档名正好就是技艺那一套**（生手到大师）—— 那批词刚被队友 AI 占掉。它现在还没命名（档数归 `GP-7`、落地跟着 `GP-30`），所以不是缺陷。

选择在两处各写一句预警（[`人际系统`](../../../design/人际系统.md)的边界、[`成长系统`](../../../design/成长系统.md)的档位制那一条），而不是新立一个编号。理由：**它不是一件待办，是一条给将来那件待办的约束** —— 立成编号会在台账里多一行永远做不完的「注意别撞名」，而写在两份文档里的话，给熟练度命名的人一定会读到其中一份。代价是它没有守卫（机器判不出两套档名会不会撞），只能靠那两句话被读到。

### 待确认

**一处留给收尾**：台账现在没有 `最高` 优先级的行 —— 本批七条都完成了，下一批（任务与关卡）还没开 PRD。「下一件」指哪里由下一轮立项时定，本条不替它决定。
