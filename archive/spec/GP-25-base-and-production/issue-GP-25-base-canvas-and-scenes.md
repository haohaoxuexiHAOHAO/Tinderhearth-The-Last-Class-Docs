# GP-25：基地画布扩到 80×60，场景与建筑清单跟着改

> **只读历史归档，不得作为现行依据。** 现行事实在[玩法定位 · 场景规模](../../../canon/gameplay/玩法定位.md)与[时间与经营 · 建造](../../../canon/gameplay/时间与经营.md)。

## 目标

让基地大到摆得开建筑、耕地、畜牧区与装饰，并把「建筑有室内」「种植区是土地不是建筑」这两件事写进正典。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-001`
- 起因是一笔算得出来的账：可建造区 40×30 格 = 1200 格，俯视 1 倍缩放下**整个基地只有一屏宽**（`rules/Ui/CameraRig.cs` 的注释写明拿可建造区当钳制边界时横向不存在滚动）。

## 依赖

无。本条是这一批的第一件，`GP-26`／`ENG-22`／`DOC-15` 都等它先定建筑清单与尺寸。

## 验收标准

- [x] [玩法定位 · 场景规模](../../../canon/gameplay/玩法定位.md)写明可建造区 80×60 格（1280×960px）
- [x] 同一张表新增「建筑室内（俯视）」一类场景，并写明**第一版只做一类当样板**、其余按生产相关四类加住宿补齐
- [x] 水面写明落在**可建造区之外的周边地形**，不占可建造格
- [x] [时间与经营 · 建造](../../../canon/gameplay/时间与经营.md)的尺寸跟着改，建筑清单为八类且**按名列出**
- [x] **种植区从建筑清单移出**，改写成可耕地（要开荒清理）
- [x] 正文与全库都不再出现「第 N 类建筑」这种按序号引用清单的写法（`教育系统` 三处已改按名引用；PRD 与本批 issue 里提到它是在描述这件事本身）
- [x] 建筑外观尺寸写明常规 7×4 格、封顶 8×6 格（长宽仍取 16 的倍数）
- [x] `python tools/check_docs.py` 0 FAIL

## 实现笔记

### 设计决策

- **模糊点**：建筑清单原来有**两份** —— [时间与经营 · 建造](../../../canon/gameplay/时间与经营.md)与[内容规模基准](../../../canon/gameplay/玩法定位.md)各写了一遍名字。改清单时两处都得动，而没有任何东西能发现它们分叉。
- **选择**：清单只留在建造那一处；内容规模基准那格改成「功能建筑各 1 级，另加各自的室内」并指过去，不复述名字。
- **理由**：量级基准要的是数量级，不是名单。留两份名单等于给同一个事实两个家。

### 偏离

- **方案怎么说**：`GP-25` 的验收只要求建筑清单改成八类且按名列出。
- **实际怎么做**：顺带删掉了内容规模基准里那份重复清单，并把 `教育系统` 三处「第 7 类建筑」改成按名引用。
- **为什么**：建筑清单一变，那三处立刻就是错的 —— 留着它们过夜比顺手改掉的风险大。`教育系统` 那三处本来记在 `DOC-15`，已在那条勾掉。

### 权衡

建筑外观封在 8×6 格而不是更大：作者原话是「200 多 px」，但那样七栋就吃掉旧画布的 84%–99%。改成小建筑加大画布（星露谷的谷仓外观也只有 7×4），容量靠室内承担。

### 待确认

无。水面的具体位置与形状归作者在编辑器里定（`ADR-0009` 的分工）。
