# DOC-33：两份 ADR 与一份系统文档接进索引，本批记账收口

> **只读历史归档，不得作为现行依据。** 现行事实在[系统文档与提案索引](../../../design/README.md)里装备系统那一行、[ADR 索引](../../../decisions/README.md)那两行，以及[待办台账](../../../spec/issues/README.md)各行。状态只在台账一处，不在本文。

## 目标

让本批产出的三份文件从 README 点得到、从台账查得到，而不是孤岛；本批的状态只落在台账一处。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-006`
+- 判据来自检查器：系统文档没有正典引用会报孤岛，没接进 [`design/README.md`](../../../design/README.md) 会报「从 README 无法到达」；ADR 同样要接进 [ADR 索引](../../../decisions/README.md)。

## 依赖

`GP-24`、`GP-46` 与 `GP-47`（三份文件要先存在）。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：`GP-46`／`GP-47`／`GP-48` 三条做完了，按 `/to-issues` 的硬规矩「完成的条目直接删除」该删；但归档要靠那几行才落得住。
- **选择**：照本仓既有做法 —— **留行、标「已完成」并写现行事实落点，下一批归档时再移进「已归档编号」**。
- **理由**：归档那一步要按编号把条目文件移进 `archive/spec/`，并在「已归档编号」写现行事实落点；行先删掉的话，下一批就查不到这几条做过什么。上一批的 `GP-39`、`DOC-29`–`DOC-31` 都是这个形状。

第二处：**「系统深化顺序」档 2 的「下一件」交给了 `GP-36`**（敌人 AI、感知视野与队友 AI 五档一起看）。那一档里只有一件事能是「下一件」，装备做完就得有人接。

### 偏离

- **方案怎么说**：验收里写「`GP-24` 那一行改成落地顺序 ＋ 链接，优先级从最高降下来」。
- **实际怎么做**：先把链接改成了纯文本，**被检查器当场抓到**「从 README.md 无法到达」，才改回链接。
- **为什么**：上一批留下的那条判据是 **「条目文件还在 `spec/issues/` 就必须被台账链着」**，归档之后才改纯文本。我按「已交付的行改纯文本」这个印象动手，顺序反了。**这正是那条判据存在的理由** —— 它不靠记性，靠一条会报错的检查。

### 权衡

「把两份 ADR 并成台账一行」考虑过（少一行）。没选：它们各裁一件事、各有自己的候选与后果，`ADR 索引`那张表也是一份一行；合并会让「查某个取舍的来历」多一跳。

「`UI-16` 也建条目文件」考虑过。没选：控件与排版由作者实机定，写成文件也只有一句话 —— 与 `UI-13`、`UI-15` 同形，台账一行就够。

### 待确认

无。
