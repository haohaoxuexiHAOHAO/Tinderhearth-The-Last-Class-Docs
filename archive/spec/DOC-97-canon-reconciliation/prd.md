# PRD：正典对账

> **只读归档件，不是现行依据。** 本轮的现行事实在正典、[`design/`](../../../design/README.md) 那批系统文档、[待办台账](../../../spec/issues/README.md)与 `tools/check_docs.py` 那条守卫里；要引结论请引它们，不要引本文。

## 1. 概述

`design/` 那批系统文档把各系统的结构与接口写定了，而 `canon/` 那批正典写在它们之前。两侧对同一件事因此各留了一套说法；正典里还有一批「以后再定」指着已经关闭的编号 —— 顺着那些指针走会得出与现行事实相反的结论。

这一轮把两侧对一遍账：**同一件事只留一种说法，每个「以后再定」都指得到一个活着的归处。** 取舍已由作者逐条定过，清单在 [`DOC-97`](./issue-DOC-97-canon-reconciliation.md) 的验收标准里 —— **本文不复述那份清单**，它是那一条的家。

为什么现在做：正典是[权威层级](../../../spec/README.md)的顶层，指错的正典会让后面每一次落地各自猜一遍；而每交付一份系统文档，两侧就多一处可能分叉的接缝，成本只会涨。为什么它单独成一个需求而不是并进上一轮：发现它的那一轮（系统文档读得懂）明确不动 `canon/`，而那一轮的收尾条目要判的正是「有没有改到结论」—— 本轮改的全是结论，混进同一批 diff 就判不出来了。

## 2. 目标

- 正典与已闭环的系统设计对同一件事只有一种说法。
- 正典里不再有指向已关闭编号的「以后再定」。
- 属数值的待定项有唯一入口、属手感的待定项有唯一入口，两者都不再是 `GP-2`。
- **改完之后每一条规则的行为与改前一致** —— 本轮只改说法，不改机制。

## 3. 上游约束

- [`DOC-97` 条目文件](./issue-DOC-97-canon-reconciliation.md)：**全部取舍的家。** 每一批改什么、改成什么，一律以它的验收标准为准；本 PRD 只定批次、顺序与验收形式。
- [待办台账](../../../spec/issues/README.md)：编号的状态只在这里。本轮之所以要改，正是因为正典里那些指针指向的编号在这里已经是已完成或已归档；`NR-28` 与 `GP-75` 在这里已有登记行，本轮只引它们、不做它们。
- [WORKFLOW § 3. 反漂移：事实只许有一个家](../../../WORKFLOW.md)：本轮全部改法的依据 —— 散文只写理由不写状态、状态只在台账一处、别处写链接不复述、按编号搜要把两个仓加 `.kiro` 一起搜。
- [WORKFLOW § 4. 归档](../../../WORKFLOW.md)：**已接受的 ADR 与归档件不得用今天的理由改写当时的背景** —— 本轮因此不动 `archive/` 与 ADR 正文，`DOC-96` 登记的那两处已知过期说法留在原处。
- [ADR-0010](../../../decisions/ADR-0010-文档体裁与系统文档归位.md)：体裁与位置的对应关系。本轮不新建文档、不搬文件，只在既有位置改句子。
- [`数值模型` · 尚未给值的量，各自写明校准办法](../../../design/数值模型.md)：正典那批属数值的「以后再定」改指的落点。它同时是 `DOC-84` 要合并进去的那一处。

## 4. 用户故事

**批次与条目文件的对应**：`US-003` 到 `US-006` 各对上[条目文件](./issue-DOC-97-canon-reconciliation.md)验收标准里的一节；`US-002` 从「过期的编号与引用」那一节里单独拆出量最大的那一条；同批带走的三个已有编号各成一批（`DOC-84` 在 `US-001`、`DOC-95` 在 `US-007`、`DOC-86` 在 `US-008`）。**这样拆是为了让逐条复核是机械的** —— 一批对一节，不用在两份清单之间做映射。

**`US-009` 到 `US-011` 是条目文件之外的三批**：它们是「指着一个已关闭编号」这个毛病的根治 —— 状态变成字段、设计侧一起清、守卫钉住。为什么它们值得进本轮而不是另记一条账，理由各写在那三条里；**代价写在「非目标」之后那一段**。

**顺序上硬的几处**，其余可调：

- `US-001` 在 `US-002` 之前（理由在该条里）。
- `US-009` 在 `US-011` 之前 —— 状态读不出来，守卫只覆盖得到一半。
- `US-002` 与 `US-010` 都在 `US-011` 之前 —— 两侧没清干净，守卫开起来就是一片红。
- `US-012` 最后。

**跨批撞同一节时的处理**：同一个自然段或同一张表被两批各改一句时，允许并到先到的那一批一次改完（两次过同一段落只会制造合并摩擦），但**复核仍按条目文件的清单逐条走**，不按批次走。

### US-001：待收敛项合成一处，让手感那一侧也有唯一入口

**描述**：作为三周后要给手感数值定值的人，我想要待收敛项只有一份清单，以便不必先判断两份里哪一份是全的。

**为什么排在最前**：`US-002` 要把正典那批属手感的「以后再定」改指 `GP-2` 之外的落点，而那个落点现在有两份对不上的清单。先合并再重指，正典指过去的那一刻它就是全的；反过来做会留下一个「正典已经指过来、清单还缺一半」的窗口。合并方向由 [`DOC-84`](../../../spec/issues/README.md) 定过：清单的家是[`数值模型` · 尚未给值的量，各自写明校准办法](../../../design/数值模型.md)，台账那一格改成写链接与落地顺序。

**验收标准**：

- [ ] 可核对：两份清单的项名做双向差集，两个差集都为空 —— 逐项列出对照结果，不写「已核对」
- [ ] 可观察：台账 `GP-6` 那一格不再列项名，改成指那张表的链接
- [ ] 可核对：[`数值模型`](../../../design/数值模型.md)「边界与非目标」里「不给手感帧数……它们不属数值模型」那句要跟着说清「表里登记归属不等于本页持有它们的值」，否则这份文档自己和自己那张表打架
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

### US-002：正典那批「归 `GP-2`」全部改指活着的归处

**描述**：作为读正典时看到「这个数归某某」的人，我想要那个指针指向一个还在被跟的地方，以便不会得出「这个值已经定了」的反结论。

**为什么单独成一批**：它是本轮改动点最多的一条，横跨全部正典分册；与别的条目混在一批会让 diff 大到没法逐处看。**每一处都要判一次「属数值还是属手感」**，这个判断不是机械替换，所以要一批专门的注意力。

**验收标准**：

- [ ] 可测试：`canon/` 下 `GP-2` 的出现次数为 0（改完搜一遍，写出搜之前与之后两个数）
- [ ] 可核对：逐处写出改指了哪一侧（那张尚未给值表，或 `GP-6`）与判断依据，**逐处，不按文件汇总**
- [ ] 可核对：属手感的那几处指 `GP-6`，而它在 `US-001` 之后已是唯一入口
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

### US-003：口径分叉一律按正典跟设计走的方向改正典

**描述**：作为同时读正典与系统设计的人，我想要两侧对同一件事只有一种说法，以便不必判断哪一份更新。

**范围**：[条目文件 · 口径分叉：正典跟设计走](./issue-DOC-97-canon-reconciliation.md)那一节的全部条目。其中一条是**净删**、一条是**只补半句**、一条是**档名跨几份文档的搬家**，三种形状各有自己的失手方式，所以验收要分开写。

**验收标准**：

- [ ] 可核对：该节每一条各写一行复核结果，写明改了哪一句、改成什么、与哪一份设计对齐

- [ ] 可核对：只补半句那一条没有顺手把值也写进正典（值仍归它原来的归处）
- [ ] 可核对：那条「机制一侧一个字不动」的约束成立 —— 改动只落在说法上，判定与结算的描述不变
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

### US-004：其余过期的编号与引用各改指真落点

**描述**：作为顺着正典里的指针去找细节的人，我想要指针落在已经交付的东西上，以便不去找一份不存在的将来文档。

**范围**：[条目文件 · 过期的编号与引用](./issue-DOC-97-canon-reconciliation.md)那一节里除 `GP-2` 那一条之外的全部条目，含 `.kiro` 那一侧的两处。

**外加一处，条目文件里没有**：[玩法定位 · 系统清单](../../../canon/gameplay/玩法定位.md)那行「排出玩法定位范围**并已立项**」里列着中文像素字体（`ART-2`），而那个编号已归档、现行事实在 [ADR-0008](../../../decisions/ADR-0008-中文像素字体选型.md)。它与本批同毛病同改法，所以并进来而不是另记一条账；**复核时要写明它是清单外多出来的一条**。

**为什么 `.kiro` 那两处在本轮而不是另记一条**：它们与正典里那批是同一个失败模式的两半 —— `DOC-9` 修过一次，当时只搜了自己在改的那个仓，于是 `.kiro` 那一侧留了下来。分两轮改就是让同一个漏法再生效一次。

**验收标准**：

- [ ] 可测试：`.kiro` 下「代码仓是空仓」这类说法的出现次数为 0

- [ ] 可核对：记录实际结论的那一处写的是真结论（而不是当初那句「先评估现成方案」）
- [ ] 可核对：指代码仓的那一处路径在代码仓里真的存在（`check_docs.py` 的路径检查会判这一条）
- [ ] 可测试：按 `NR-28` 与 `GP-75` 各搜两个仓加 `.kiro`，确认引到它们的地方都只写链接、不复述状态

### US-009：台账的状态改成机器读得出的字段

**描述**：作为想让工具判断「这个编号还开着吗」的人，我想要状态是一个有固定取值的字段，以便不必让机器去读一句散文。

**为什么它是根治的第一步**：今天「已归档」读得出来（它自己一张表），而「已完成」只是备注里加粗的一句话 —— 所以 `NR-1`、`ART-8`、`ENG-6` 这种「做完了但没归档」的编号，机器分辨不出它已经关了。**本轮指错的那几处正好都是这一类。** 不先把状态变成字段，`US-011` 那条守卫就只覆盖得到一半。

**改法**：备注单元格必须以一个来自固定词表的状态词开头。**这不是加一列** —— 域表里大多数行本来就是这个形状，把剩下那些收进来即可。词表要分清一件事：**文档交付不等于条目关闭**（设计已交付但落地未做的仍然开着），所以「已完成」与「设计已交付」是两个不同的取值，不能合并。

**验收标准**：

- [ ] 可测试：域表每一行的备注都以词表里的某个词开头，不合的行数为 0（写出改之前与之后两个数）
- [ ] 可核对：词表写在台账自己那一页，取值互斥且穷尽；**「设计已交付」明确算未关闭**
- [ ] 可核对：收编那几行时只改开头的措辞，**理由与链接一个字不动**（用 `git diff` 逐行看）
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

### US-010：设计侧那批指向已关闭编号的引用一起改掉

**描述**：作为读系统文档的人，我想要「这个数以后再定」指向一个还开着的地方，以便不会得出与正典那一侧相反的结论。

**为什么它必须在本轮**：它与 `US-002` 是同一个毛病，只是在另一侧、而且处数更多。**只清正典那一侧的话，同一个毛病会留在设计侧，而 `US-011` 那条守卫也就开不起来** —— 一条开不起来的守卫等于没有守卫。

**改法与 `US-002` 相同**：属数值的指[`数值模型` · 尚未给值的量，各自写明校准办法](../../../design/数值模型.md)，属手感的指 `GP-6`；指向别的已关闭编号的，各自改指它的现行落点。

**顺带一处要小心**：[玩法定位](../../../canon/gameplay/玩法定位.md)有个**节标题**本身就带着那个已归档编号，而[`数值模型`](../../../design/数值模型.md)按节名引用它。改标题要连着改引用，否则节名守卫会报 —— **这一处同时落在正典与设计两侧，所以它与 `US-002` 同批改还是本批改都行，但只能改一次。**

**验收标准**：

- [ ] 可测试：`design/` 下指向已关闭编号的引用处数为 0（写出改之前与之后两个数）
- [ ] 可核对：逐份文档写出改了几处、各指向哪里；**指向仍然开着的编号那些一处不动**
- [ ] 可核对：那个节标题改完之后，按节名引它的地方也改了，`check_docs.py` 的节名检查通过
- [ ] 可核对：设计侧的结论一个字没改 —— 改动只落在「归处」那半句上
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

### US-011：守卫落地，让这个毛病不能再悄悄发生

**描述**：作为下一个写文档的人，我想要「指了一个已关闭的编号」当场被拦下，以便不靠谁记得去查。

**依赖**：`US-009`（状态要先读得出来）、`US-002` 与 `US-010`（两侧都清干净，守卫才开得起来）。

**判法**：`canon/` 与 `design/` 里引用状态为已关闭的编号时报错。**唯一的放过形式是写成指台账的链接** —— 那样读者一跳就落到台账那一行，看得到它关了、现行事实在哪。零误判，**不需要机器判断散文**。

**为什么不判「所有裸编号一律要写成链接」**：那条形式上更整齐，但它要动的地方多得多，而收益只在已关闭那一小撮上 —— 判法却要动全部。按关闭状态判是把守卫对准真正的失败模式。

**验收标准**：

- [ ] 可测试：故意把一处改回指某个已关闭编号，守卫报错并说清是哪一处、该改成什么（撞一次失败路径，写出它报了什么）
- [ ] 可测试：写成指台账链接的那种形式不报错（撞一次放过路径）
- [ ] 可测试：全库跑一遍 0 FAIL，且守卫**自报它检查了多少处** —— 覆盖量为 0 说明它在空转
- [ ] 可核对：判法与豁免写在守卫的文档字符串里，含「为什么不判所有裸编号」那条理由
- [ ] 可核对：[WORKFLOW § 6. 执行体](../../../WORKFLOW.md)那张表加上这一条

### US-012：整轮对账的端到端复核

**描述**：作为要把这一轮收口的人，我想要一次走完整份清单的复核，以便确认没有一条被做漏、也没有一条被顺手做多。

**为什么它不能只靠门禁**：`check_docs.py` 判的是断链、节名、体裁、编号存在性与行尾 —— **它判不出两份文档对同一件事说了两套话**。「指着已关闭的编号」这一类在 `US-011` 之后有守卫了，但本轮其余几类仍然只能靠人看。所以这一条的主要证据是人工逐条对照，门禁只是附加条件。这条边界不是本轮的发现，[WORKFLOW § 3](../../../WORKFLOW.md) 已经写明它判不了哪一类。

**依赖**：其余全部故事。

**验收标准**：

- [ ] 可核对：**按条目文件的验收清单逐条对照复核**，每一条写出「改在哪一句、现在说什么、对齐的是哪一份」，结果写进 `DOC-97` 的「验证结果」—— 不接受只写「门禁 0 FAIL」
- [ ] 可核对：清单里每个勾选框都有对应的一行结果；一条也没漏，多出来的改动也要写出来并说明是哪一批带的
- [ ] 可测试：`canon/` 与 `design/` 下指向已关闭编号的引用处数都为 0，且这一条现在由 `US-011` 的守卫判得到（不再只靠搜一遍）
- [ ] 可核对：`git diff` 逐处看过，改动只落在清单列出的那些句子、加上 `US-009` 到 `US-011` 三批各自声明的范围上
- [ ] 可测试：`python tools/check_docs.py` 0 FAIL —— **同时看它自报的覆盖量**，退出码 0 不等于它真的检查过（节名引用覆盖量那一行为 0 就说明它在空转）

- [ ] 可观察：`temp/` 为空

## 5. 功能需求

- FR-1：两侧对同一件事分叉时，必须按正典跟设计走的方向改正典。
- FR-2：正典里的每个「以后再定」必须指向一个仍在被跟的归处。
- FR-3：`GP-2` 不得再作为正典里任何「以后再定」的归处。
- FR-4：属数值的待定项必须指[`数值模型` · 尚未给值的量，各自写明校准办法](../../../design/数值模型.md)。
- FR-5：属手感的待定项必须指 `GP-6`。
- FR-6：待收敛项的清单必须只有一处，其余位置写链接。
- FR-7：按编号做的改动必须同时搜设计仓、代码仓与 `.kiro` 三处。
- FR-8：每一批的验收结果必须包含按条目文件清单的逐条对照，不得只写门禁结果。
- FR-9：正典里的场所名必须与正典自己的枚举对得上。
- FR-10：同一条量级事实的值必须只写在一处，别处写链接。
- FR-11：本轮引用 `NR-28` 与 `GP-75` 时只写链接，不复述它们的状态、也不实现它们。
- FR-12：台账里每个编号的状态必须是一个取自固定词表的值，机器读得出。
- FR-13：那张词表必须把「文档已交付」与「条目已关闭」分成两个取值。
- FR-14：`canon/` 与 `design/` 都不得拿已关闭的编号当待定项的归处。
- FR-15：守卫必须在有人写出这种引用时报错，并说清那一处该改成什么。
- FR-16：守卫必须自报它检查了多少处，覆盖量为零时不得报成通过。

## 6. 非目标

- **不改机制。** 只改说错了的说法。任何一处改动若让某条规则的行为与改前不同，那处就改错了。
- **设计侧的结论一个字不动。** 分叉一律往正典那一侧改；`design/` 那批只动过期的注记（`US-006`）、那张合并进来的清单（`US-001`）与那些指向已关闭编号的半句（`US-010`）。
- **不动 `archive/`，不动已接受的 ADR 正文。** `DOC-96` 登记的那两处已知过期说法留在原处，理由在 [WORKFLOW § 4](../../../WORKFLOW.md)。
- **不给任何系统补新设计。** 缺设计的地方本轮只把指针改对，设计本身跟着它自己的编号走。
- **不动数值与参数表。** `design/numeric-model-params.json` 一个键不改；`US-001` 只搬清单，不给任何量赋值。
- **不做 `NR-28` 与 `GP-75`。** 它们本轮只被正典引用。
- **不动那几条没写「跟 `DOC-97` 同批」的同类账**（按方向引、代码注释指向不存在的系统、同名不同物那几条）。它们各自卡在别的编号上。
- **守卫只加一条，只判一件事**（`US-011`）。口径分叉、复述与直译腔那几类机器判不出来，不为它们造守卫 —— 那等于要机器判断两份散文说的是不是同一件事。
- **不判「所有裸编号都要写成链接」。** 理由在 `US-011` 里：要动的面大得多，而收益只在已关闭那一小撮上。
- **不给台账加一列。** `US-009` 是把既有的备注开头收成固定词表，不改表的形状。
- **「市场」作经济学概念的那几处不动**（定价三层、市场存量记忆、「底线之上的市场」）。只改指那张城区图的场所名。

**本轮比条目文件的清单大了多少，写在这里免得以后被当成范围蔓延**：清单本身管的是正典那一侧；`US-009` 到 `US-011` 把同一个毛病的设计侧、台账那个结构前提与守卫一起带上，改动处数因此大约翻三倍。**换来的是这一类不会再悄悄复发** —— 判据是那条守卫，不是谁的记性。

## 8. 技术考虑

- **全部改动落在设计仓与 `.kiro`，代码仓一行不改。** `US-004` 会往正典里写一处代码仓路径，`check_docs.py` 的路径检查会判它存在。
- **`US-011` 是本轮唯一的工具改动**，所以它排在全部文档批之后 —— 混在中间会让「改动只落在那些句子上」这条验收判不出来。它自己没有自证入口（同 `check_docs.py` 其余部分），所以要靠撞失败路径与放过路径各一次来证明它真的在工作。
- **搜索是主要工具，替换不是。** 每一条都要人判「这一处该指哪一侧」，所以用编辑工具逐处改，不做批量替换。这也是[命令纪律](../../../WORKFLOW.md)的要求。
- **门禁的判定面**：`check_docs.py` 判文件头、断链、节名引用、体裁与骨架、术语、按序号引用、自计数、代码路径、唯一台账、编号存在性、入口可达与行尾。**本轮改的东西几乎都在这个面之外** —— 唯一会被它接住的是改错链接与改出断名。
- **`check_docs.py` 没有自证入口**（随 `ADR-0009` 删除），所以它报的覆盖量要自己看一眼，别只看退出码。
- **动了[`数值模型`](../../../design/数值模型.md)就要跑 `python tools/simulate_week.py --check-doc`**。`US-001` 只搬清单、不碰参数路径旁的数字，所以预期它通过而不是需要改参数 —— 这是**待验证**，跑一次就知道。
