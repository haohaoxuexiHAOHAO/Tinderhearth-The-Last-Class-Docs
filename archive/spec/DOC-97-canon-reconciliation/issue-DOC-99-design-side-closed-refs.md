# DOC-99：设计侧那批指向已关闭编号的引用改指真落点

> **只读归档件，不是现行依据。** 本轮的现行事实在正典、[`design/`](../../../design/README.md) 那批系统文档、[待办台账](../../../spec/issues/README.md)与 `tools/check_docs.py` 那条守卫里；要引结论请引它们，不要引本文。

## 目标

`design/` 下没有一处「这个数以后再定」指着一个已经关闭的编号 —— 每处都指到仍在被跟的落点。

## 来源

PRD：[`spec/prd-canon-reconciliation.md`](./prd.md) 的 `US-010`。

它与 [`DOC-97`](./issue-DOC-97-canon-reconciliation.md) 的正典那一侧是**同一个毛病的另一半**，只是处数更多。**实测**：正典那一侧 47 处（正好等于 `DOC-97` 清单里点名的那些），设计侧 105 处，其中绝大多数指着同一个已归档编号。**这两个数是量出来的，不是估的**；但「哪些算已关闭」这一步用的是在台账备注里找措辞的办法，所以它的可靠性要靠 [`DOC-98`](./issue-DOC-98-ledger-status-field.md) 兑现。

只清正典那一侧会留下两个后果：设计侧照旧误导读者，而 [`DOC-100`](../../../spec/issues/README.md) 那条守卫开起来就是一片红 —— 只能靠加豁免关掉它，而带豁免的守卫等于没有守卫。

## 依赖

无硬依赖。**建议排在 [`DOC-98`](./issue-DOC-98-ledger-status-field.md) 之后** —— 那份处数清单是用措辞嗅探量出来的，状态成了字段之后重新量一遍才靠得住。

## 验收标准

- [x] `design/` 下指向已关闭编号的**裸引用**处数为 0（写出改之前与之后两个数；改之前那个数要用 `DOC-98` 之后的判法重量一遍）。**写成指台账链接的那几处不算** —— 那是 [`DOC-100`](./issue-DOC-100-closed-id-guard.md) 唯一的放过形状，本条立账时还没定下这一点，所以这一条按那个形状收窄过一次
- [x] 改法与正典那一侧一致：属数值的指[`数值模型` · 尚未给值的量，各自写明校准办法](../../../design/数值模型.md)，属手感的指 `GP-6`，别的各指自己的现行落点
- [x] 逐份文档写出改了几处、各指向哪里 —— **逐份，不按全目录汇总**

- [x] 那个**节标题**里带着已关闭编号的一处改掉，并且按节名引它的地方跟着改；`check_docs.py` 的节名检查通过
- [x] 设计侧的结论一个字没改 —— 改动只落在「归处」那半句上（`git diff` 逐处看过）
- [x] `python tools/check_docs.py` 0 FAIL
- [x] `python tools/simulate_week.py --check-doc` 通过（其中一份被改的是[`数值模型`](../../../design/数值模型.md)）

## 逐条复核结果

**重量过了，数跟立账时不一样。** 按 [`DOC-98`](./issue-DOC-98-ledger-status-field.md) 的状态词重判：活文档里指向已关闭编号的引用**改之前 109 处、改之后 5 处**。立账时用措辞嗅探量出来的是 105 —— 差别来自嗅探会把「文档侧已完成」这类行也算成关闭，而它们按新词表是**设计已交付**（还开着）。**正典那一侧已经是 0**（`DOC-97` 那一批清的）。

**剩下的 5 处刻意不动，它们是允许的形状**：全部写成了指台账的链接，语义也都是历史引用（某条判断当初记在哪、某个结论由哪一批做掉）。读者点进去落在台账那一行，看得到它已经关闭、现行事实在哪 —— 这正是 [`DOC-100`](./issue-DOC-100-closed-id-guard.md) 唯一的放过路径。

**大头是同一个编号的 83 处**，改法统一：那些句子说的是「本页不定数值，数值归那份文档」，所以指[数值模型](../../../design/数值模型.md)整份，而不是它的尚未给值表 —— 与正典那一批的判法一致（正典那边是「这个数以后再定」才指表）。**去重也在这一批**：原先有几处写成「[数值模型] 与 `<编号>`」，两个指针指同一处，删掉后者。

**其余各处要单独判，因为它们的落点各不相同**：

| 原来指 | 现在 |
| --- | --- |
| 城区分图与命名（4 处） | `NR-28`，与正典那一侧同一个去处 |
| 派生公式两侧的同步（2 处） | 写明**已经做过**，指[数值模型](../../../design/数值模型.md) |
| 生活技能那张清单 | [角色与成长 · 技能分两类：放出来的动作，与做事的熟练度](../../../canon/gameplay/角色与成长.md)，并写明项数只在那里写一次 |
| 地块与开荒、派工指派那张表 | 写明**现行事实就在本页** —— 那两个编号已归档，而它们交付的正是这一份 |
| 玩家级偏好那一节的立项 | 写明设计已交付、现行事实就是本页那一节 |
| 界面骨架那一批、宝石筛法、键位映射、转场那条上升 | 改成陈述结论并指真落点，不再借编号说事 |
| 判据 C1 那个区间的来源 | 指台账（它来自一轮已归档的需求，不是正典） |

**一处刻意删掉了三个编号**：[`角色动作状态系统`](../../../design/角色动作状态系统.md)那句拿三个已完成编号当证据（「全是已实现并验过的 X／Y／Z」）。**句子要说的是「这几样已经实现并验过」，编号本身不承载信息**，所以改成一个指台账的链接、不再列号。

**没做的**：`design/` 那批文档的结论一个字未改 —— 改动只落在「归处」那半句与几处历史引用的写法上。仍然开着的编号（`GP-6`、`GP-7`、`GP-45` 这些）一处没动。
