# DOC-100：守卫 —— 活文档不许拿已关闭的编号当待定项的归处

> **只读归档件，不是现行依据。** 本轮的现行事实在正典、[`design/`](../../../design/README.md) 那批系统文档、[待办台账](../../../spec/issues/README.md)与 `tools/check_docs.py` 那条守卫里；要引结论请引它们，不要引本文。

## 目标

有人在活文档里写下「这件事归某个已经关闭的编号」时当场被拦下，不靠谁记得去查。

## 来源

PRD：[`spec/prd-canon-reconciliation.md`](./prd.md) 的 `US-011`。

它是 [`DOC-97`](./issue-DOC-97-canon-reconciliation.md) 那一轮的**修根那一半**：那一轮修的是实例，本条修的是让实例能存在的机制。**这个毛病已经复发过一次** —— `DOC-9` 修的是同一类，当时只搜了自己在改的那个仓。第二次复发之后还只修实例不修机制，就是第三次的预约。

为什么原来的门禁接不住它：链接仍然有效、编号在台账里也仍然解析得到，所以断链检查与编号存在性检查都为真。**指针指错的唯一症状是「读者顺着它走会得出反结论」，而那件事原来没有任何执行体在判。**

## 依赖

- [`DOC-98`](./issue-DOC-98-ledger-status-field.md)：状态要先是机器读得出的字段，否则本条只覆盖得到「已归档」那一半，漏掉「已完成但没归档」那一类 —— 而 `DOC-97` 那一轮指错的几处正是后者。
- [`DOC-97`](./issue-DOC-97-canon-reconciliation.md) 与 [`DOC-99`](./issue-DOC-99-design-side-closed-refs.md)：两侧都清干净了守卫才开得起来。带豁免的守卫等于没有守卫，所以**不许为了让它变绿而加豁免**。

## 验收标准

- [x] 判法：`canon/` 与 `design/` 引用状态为已关闭的编号时判失败，报出是哪一处、以及该改成什么
- [x] **唯一的放过形式是写成指台账的链接** —— 那样读者一跳就落到台账那一行，看得到它关了、现行事实在哪
- [x] 撞一次失败路径：故意把一处改回指某个已关闭编号，守卫报错（写出它报了什么）
- [x] 撞一次放过路径：同一处改成指台账的链接，守卫不报
- [x] 全库跑一遍 0 FAIL，且守卫**自报它检查了多少处**；覆盖量为 0 判失败而不是跳过
- [x] 判法与豁免面写在守卫的文档字符串里，含**为什么不判「所有裸编号一律要写成链接」**那条理由（那条要动的面大得多，收益只在已关闭那一小撮上）
- [x] 台账、`archive/`、`decisions/` 与 `templates/` 不在判定面内，且这条豁免写明理由
- [x] [WORKFLOW § 6. 执行体](../../../WORKFLOW.md)那张表加上本条
- [x] `python tools/check_docs.py` 0 FAIL

## 逐条复核结果

**执行体**是 `tools/check_docs.py` 里的 `check_closed_issue_refs`，判定面是 `canon/` 与 `design/`。

**撞过三条路径，各一次**（在一份正典里临时插一句、跑门禁、读结果、还原，还原后比对一致）：

| 撞什么 | 结果 |
| --- | --- |
| 裸编号指一个已关闭的编号 | 退出码 1，报出**文件、行号、哪个编号、该改成什么** |
| 同一处写成指台账的链接 | 退出码 0，不报 |
| 指一个仍然开着的编号 | 退出码 0，不报（**这条是防误判的对照**，没有它「守卫是不是把所有编号都报了」判不出来） |

**自报覆盖量**：台账里解析出多少个编号已关闭、在判定面下检查了多少处引用，两个数每次跑都打出来；**解析不出任何已关闭编号时判失败而不是通过** —— 状态词或已归档那张表的形状一变，守卫会当场说「这一轮没有执行」，而不是假装绿。

**第一次跑就抓到一处误判，而它教出了判定形状。** 那一处是 `archive/spec/` 下的**目录名**里带着编号（归档目录按编号命名），按裸编号判会把一条路径判成过期指针。改法：**只认反引号里的编号** —— 全库引编号一律加反引号，而不加反引号的那些恰恰不是引用。这条理由写进了守卫的注释，免得以后有人「顺手放宽」。

**顺带一个发现要记下来**：我在 `DOC-99` 那一批用来数处数的脚本也是只找反引号，所以那两个数（改前 109、改后 5）**量的是反引号里的引用**。守卫现在按同一个面判，两者对得上；但如果以后有人写出不带反引号的编号引用，**守卫按定义看不见它**。这是已知的覆盖边界，不是漏洞 —— 收紧它要先统一「编号一律加反引号」这条书写纪律，而那是另一笔账。

**判定面之外的三处豁免各有理由，写进了守卫注释**：台账自己是状态的家；`archive/` 与已接受的 ADR 按规则不许用今天的说法改写；`spec/` 下是过程文件、会随需求归档走掉。**没有为了让它变绿加任何豁免** —— 两侧是先清干净的（`DOC-97` 与 `DOC-99`），守卫才开的。

**排掉的那个更宽的判法**：「所有裸编号一律要写成链接」形式上更整齐，但全库裸编号是这一批的好几倍，而收益只落在已关闭那一小撮上 —— 判法却要动全部。理由写在守卫注释里。
