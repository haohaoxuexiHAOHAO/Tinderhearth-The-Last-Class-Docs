# GP-51：`design/感知与视野系统.md`

> **只读历史归档，不得作为现行依据。** 现行事实在[`感知与视野系统`](../../../design/感知与视野系统.md)，它的读者在[`战斗AI系统`](../../../design/战斗AI系统.md)与[`关卡系统`](../../../design/关卡系统.md)。**这个编号还没做完** —— 文档已交付而代码一行都没写，落地顺序与状态在[待办台账](../../../spec/issues/README.md)，不在本文。

## 目标

让「谁能看见谁」只算一次、只有一份数据，而 AI 的目标选择、玩家看到的画面与资源点的显形都从它读。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-003`
- 起因：[战斗与关卡 · 感知与视野](../../../canon/gameplay/战斗与关卡.md)写明 **AI 感知与玩家视野表现必须由同一份可见性数据驱动**，而现在没有一处持有那份数据；[`关卡系统` · 资源点受视野约束](../../../design/关卡系统.md)已经在引它（资源点与敌人的显形都读同一份可见性数据），而被引的那一侧不存在。
- **它单独成篇不是因为状态机，而是因为它多读者无主**：敌人 AI、队友的「优先处理远程」、关卡的资源点显形、玩家的视野表现四处都读它。塞进任何一份都等于让另外三个读者去读一份讲别的事情的文档 —— 那正是防重构点要挡的。判断过程记在下面的「权衡」。

## 依赖

`GP-49`（房间模型决定这套感知兑现的是什么）。**与 `GP-50`、`GP-36` 互相引用**，三条一起写完一起验。

## 验收标准

- [x] 按 [SYSTEM 模板](../../../templates/SYSTEM.md)八节写全，`type: system`、文件名以「系统」结尾、`upstream` 指[战斗与关卡](../../../canon/gameplay/战斗与关卡.md)，**并在 `GP-50` 那一轮就被正典链接到**。
- [x] 写明**一份数据、一次计算**：每帧算出「每个阵营看得见哪些实体」，AI 与表现两侧都只读它。**这是本批的防重构点**，理由指回正典那句，本页不重写理由。
- [x] **视野组件要声明哪些字段写成一张表**，至少覆盖朝向扇形的角度与距离、一个不看朝向的近身半径、它属于哪个阵营；**缺任一字段载入报错**（[ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md)：不留能用的默认值）。
- [x] **近身半径写明它为什么必须存在** —— 没有它，贴在背后打他他还不知道，那看起来像坏了（与「基础 AI 不分档」那条判据同源）。
- [x] 写明**两边共用同一套视野组件**，友方取并集、敌方独立取并集；队友倒下时并集会缩，这是刻意的。
- [x] 写明**遮挡按片段声明的遮挡区域判** —— 作者在片段里摆遮挡区域，视线只问「两点之间有没有跨过一个遮挡区域」；并写明这条判定在纵深上怎么成立。
- [x] 同一处写明**没选引擎射线的理由**：`ENG-19` 实测过同一个坑（影子射线取 `Mask=1`，而层 1 既是地形也是角色，于是影子跳到对方头顶且不报错），带纵深之后还要在三个轴上判；而声明式的遮挡区域让作者在编辑器里直接看得出哪里能躲。
- [x] 写明**记忆项与残影是同一件事的两半**：目标离开可见集后在最后已知位置留一条记忆项并带一个时长，残影是它的表现；**记忆项不跟着目标移动**。
- [x] 写明 **AI 只许读可见集与记忆集**，不许直接读世界里的实体表。**这条要有反证钉住** —— 把可见集清空，AI 必须找不到目标。
- [x] 写明**地形始终可见**、未被感知的区域只以统一灰调压暗，且**压暗长什么样归表现、作者实机看**，本页不判。
- [x] 写明**本系统只在侧视关卡生效**，俯视场景不做迷雾；理由指回正典，不重写。
- [x] 写明**资源点显形读同一份数据**（[`关卡系统` · 资源点受视野约束](../../../design/关卡系统.md)），且本页不给「还剩几个」的计数器。
- [x] 写明**这套感知在一屏一清的房间模型下兑现的是什么** —— 不是绕开整个房间，而是这一屏里逐个偷袭还是站中间被一群一起围。理由指回正典那句「不先处理掉哨兵，接下来要面对被叫来的一群」，那句说的本来就是传播而不是绕路。
- [x] 写明**同一份可见性数据的开销**由正典那条同屏上限兜着，**本页不定优化手段**（超出量级要空间划分是正典的话，怎么划归实现）。
- [x] 挂载点列全并写明「到此为止」，至少覆盖 AI 的目标选择、玩家视野的表现层、资源点显形、残影的表现、统计事件总线（发现与失去目标各一条）、临时续玩点（记忆项进它、不进正式存档）。
- [x] 边界那一节写明**不持有**：AI 的决策与行为、迷雾贴图与压暗的画法（作者）、视野角度与距离的值（`GP-7`）、俯视场景（不适用）、片段里遮挡体摆在哪（作者搭片段，[`关卡系统`](../../../design/关卡系统.md)）、可见性计算的优化手段。
- [x] 文档里一个玩法数值都没有。
- [x] `python tools/check_docs.py` 0 项必须修复（与 `GP-50`、`GP-36` 合并之后才成立）。

### 权衡

**拆成几份文档的判断过程记在 `GP-36` 的「权衡」里**（三样一起判才说得清），本条只记与感知直接相关的那一半：

按[`生产系统` · 什么时候拆出去单独成篇](../../../design/生产系统.md)那条判据（**有没有自己的状态机**），**感知没有** —— 可见集每帧重算；记忆项带一个时长，但那是一条 TTL，与状态效果的时长同形，不是流转。**所以按判据直读它不该单独成篇。**

**它最后还是单独成篇了，理由是判据没覆盖到的一种情形：多读者无主。** 四处读它（[`战斗AI系统`](../../../design/战斗AI系统.md)的目标选择、队友的「优先处理远程」、[`关卡系统`](../../../design/关卡系统.md)的资源点显形、玩家的视野表现），而没有一处是它天然的家。塞进任何一份都等于让另外三个读者去读一份讲别的事情的文档 —— 而正典那条防重构点正是「只有一份可见性数据」，结构上让它无主会直接削弱它。

**这是对那条判据的补充，不是例外**：判据问的是「它会不会撑大宿主页」，这里问的是「它有没有宿主页」。将来被重判的条件是读者收敛到只剩一处 —— 那时它该并回去。
