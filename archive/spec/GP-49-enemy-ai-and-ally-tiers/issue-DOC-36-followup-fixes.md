# DOC-36：这一批的连带修正，落在已交付的文档上

> **只读历史归档，不得作为现行依据。** 现行事实落在被改的那几份文档自己身上：[`角色动作状态系统`](../../../design/角色动作状态系统.md)（动作集按角色声明、死亡终态按载体类别收窄）、[`成长系统`](../../../design/成长系统.md)（派生表里精准防御回报那一行）、[`关卡系统`](../../../design/关卡系统.md)（转场往前那一道门）与[战斗与关卡 · 完成标准](../../../canon/gameplay/战斗与关卡.md)那条的**理由**。状态在[待办台账](../../../spec/issues/README.md)，不在本文。

## 目标

让本批答完的那几件事在别人那份文档里也对得上，而不是只在新文档里成立。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-005`
- 起因：本批的答案落在别人已经写死的句子上 —— 精准防御能被天赋与状态提升（要进派生表）、死亡终态按载体类别分（[`角色动作状态系统`](../../../design/角色动作状态系统.md)现在写的是「转为可采集的尸体」）、一屏一清（[`关卡系统`](../../../design/关卡系统.md)现在写的是「三个方向同一条规则」）、不是每个角色都有全套动作（那张流转表现在读起来像每个角色都有全部姿态）。
- 单独列成一条是因为这几处各在一份**已交付**的文档里，漏一处就是一次静默分叉。

## 依赖

`GP-49`（关卡那一处按那份 ADR 改）、`GP-50` 与 `GP-36`（另几处要按定下来的结论改）。

## 验收标准

- [x] [`角色动作状态系统`](../../../design/角色动作状态系统.md)补上**动作集按角色声明**：那张流转表是**全集**，一个角色的实际动作机是**它声明的那些动作在表上导出的子图**；**不为缺席的动作在表上开例外** —— 缺席只是那几条流转不存在。
- [x] 同一处写明**哪些动作必有的判据是「别人要不要读它」**，并按判据给出必有的那几样：站立与行走（AI 走位、纵深排序与实体阻挡都要它有个位置）、受击（[`伤害系统`](../../../design/伤害系统.md)的结果要有落点）、生命周期终态（不然打不死）。其余一律可选。
- [x] 同一处写明**攻击是可选的**，并给出已经存在的例子 —— 训练木桩只挨打不还手，它只声明必有那几样。**这条同时说明可选不是为怪物开的例外。**
- [x] 同一处写明**免疫失衡靠「不声明失衡与击倒」表达，不靠一个开关**（两种说法会让同一件事有两个家），并写明代价（对这种敌人「打出失衡再补重击」这条循环不成立，所以内容上不能让全部精英都这样）。
- [x] 同一处写明**主角必须有全套动作**，理由写清（玩家操作他，缺一个动作就是一个按键没反应）。
- [x] 同一处写**两条载入校验**，各说清报什么：声明的每个动作都要**进得去**（有一条从站立可达的路）、都要**出得来**（有一条回站立的路）。同一处写明它抓的是哪种配错 —— **声明了击倒却没声明失衡**，击倒只从失衡进，于是永远进不去，而那不报错。
- [x] 同一处写明**动作集是角色定义上的一个声明项**，与 `DOC-35` 那张待拼的字段表是同一侧；**缺声明时报错、不给默认全集**（[ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md)）。
- [x] [`角色动作状态系统` · 生命周期：倒下可救、死亡是终态](../../../design/角色动作状态系统.md)那句「转为可采集的尸体」**收窄成由载体类别决定**（尸体／残骸／什么都不留），并写明纯灵之物不留尸体因此搜刮对它不成立。
- [x] [`成长系统` · 派生表：基底与来源分两栏](../../../design/成长系统.md)那张表**补一行精准防御的回报量**，按那一节自己的规则填四格：基底是常量而不是属性（照「无基底」那条先例，并写明常量在[数值模型](../../../design/数值模型.md)）、其余来源是天赋与状态、谁读它是动作侧、值归 `GP-7`。
- [x] 同一处写明**为什么它必须进这张表** —— 天赋与状态要能提升它，而那张表是下游唯一入口；不进表就得另开一条修饰路径，那正是[玩法定位 · 跨系统约定](../../../canon/gameplay/玩法定位.md)要挡的。
- [x] [`关卡系统` · 片段之间是转场，不是无缝滚动](../../../design/关卡系统.md)按 `GP-49` 改写 —— **往前那个方向多一道门**，往回与撤离不变；并写明**往回退仍然可能带着活着的敌人走**（当前这一屏还没清完），所以那条读条的理由原样成立。
- [x] 同一处写明**战斗片段就是一屏、战斗中相机不平移**，非战斗片段可以比一屏长、相机照常跟随；细节指回 `GP-49` 那份 ADR，本页不复述理由。
- [x] [战斗与关卡 · 完成标准](../../../canon/gameplay/战斗与关卡.md)那条「不用清空全部敌人」的**理由重新说清**：它现在的理由是「漏掉一两只杂兵会让玩家满地图找」，而一屏一清之后那种情形不存在了 —— 它剩下的意思是**不要求走遍全部分支**。**不改结论，改理由**，否则半年后有人会以为这条已经作废。
- [x] [`关卡系统` · 节奏约束写成形式，值归 `GP-2`](../../../design/关卡系统.md)那条「相邻两个战斗片段之间至少隔一个非战斗片段」**写明它与一屏一清是同一套节奏**（打一屏、喘一屏），不是两条独立约束。
- [x] **这几份文档之外没有第五处被改。** 判据是 `git status` —— 本批动过的文件列出来，逐个说得出它为什么在里面。
- [x] `python tools/check_docs.py` 0 项必须修复。
