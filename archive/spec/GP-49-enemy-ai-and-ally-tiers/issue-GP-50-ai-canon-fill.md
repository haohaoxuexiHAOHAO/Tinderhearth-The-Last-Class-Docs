# GP-50：正典补齐 —— 两条轴不合成、精准防御的回报、敌人侧四样的收口

> **只读历史归档，不得作为现行依据。** 现行事实在[战斗与关卡](../../../canon/gameplay/战斗与关卡.md)那几节（两条轴各成一个档号、地板收进三条、精准防御的回报按角色一律相同、敌人侧四样的收口）与[玩法定位 · 系统清单](../../../canon/gameplay/玩法定位.md)那三行。顺带修掉的那处正典自相矛盾也在那几节里。状态在[待办台账](../../../spec/issues/README.md)，不在本文。

## 目标

让正典一次说清「队友变强是怎么被看见的」与「敌人凭什么会发现我」，并修掉那一节里两句自己打架的话。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-002`
- 起因：[战斗与关卡 · 分档的是时机、衔接与配合](../../../canon/gameplay/战斗与关卡.md)写着「两条轴怎么合成一个档号，还没有规则」与「每一档各解锁哪几条行为还没有定」，本批答它们。
- **同一节有一处自相矛盾**：那批「待分配的分档行为」里有一条是「响应标记集火与撤退指令的延迟明显更短」，而[战斗与关卡 · 队友 AI 分档：学生「变强」必须看得见](../../../canon/gameplay/战斗与关卡.md)开头写着升档必须解锁一个玩家看得出来的具体行为、**「而不是提高反应速度与命中率」**。

## 依赖

`GP-49`（正典完成标准那条的理由要按那份 ADR 改）。**与 `GP-51`、`GP-36` 互相引用** —— 正典要链两份系统文档（长期规格没有正典引用当场 FAIL），系统文档要链正典那几节，所以三条一起写完一起验。

## 验收标准

- [x] [战斗与关卡 · 分档的是时机、衔接与配合](../../../canon/gameplay/战斗与关卡.md)那句「两条轴怎么合成一个档号，还没有规则」改写成**不合成**：两条轴各自成一个档号、共用同一套五档档名，每条分档行为在定义时声明它读哪一条轴。
- [x] 同一处写明**不合成的三条理由**，都指回已有的正典句 —— 合成会让「关系好就打得准」与「练得多就配合得好」同时成立（否掉正典给两条轴各写的驱动理由）；合成之后玩家看到的是一个总档，分不出该去练还是该去处关系（否掉「升档必须解锁一个玩家能看出来的具体行为」）；正典点名的那批行为本身已经沿这条线分成两组。
- [x] 同一处写明**被放弃的两个合成办法各自的代价**：取较低者会让「我练了他却没变强」成立（关系成了约束边）；加权与分段门让玩家看不出原因。
- [x] 同一处写明**每一档解锁哪几条行为的那张表不在正典** —— 正典持有判据与档名，清单归系统文档。理由指回正典自己那句「加一条新行为时按这句话问，而不是去背清单」。
- [x] 那批候选里**「响应标记集火与撤退指令的延迟明显更短」被划掉并移进地板**，同一处写明理由（它正是同一节开头排掉的「提高反应速度」，玩家分辨不出来）。**这是正典自己两句话打架，本条修掉它。**
- [x] 同一处**「会去扶倒地的同伴」也移进地板**，理由按判据写（它是「做不做」而不是「什么时候做」），并写明放进档位会让一支新队伍完全不能互救、而[战斗与关卡 · 失败判定](../../../canon/gameplay/战斗与关卡.md)写着每人每关可被救起一次。
- [x] [战斗与关卡 · 基础 AI 不分档，人人从第一天就有](../../../canon/gameplay/战斗与关卡.md)收进上面两条，**并补一条**：不挤在同一处的站位也是地板（四个人全叠在主角身后一格会被当成坏了，那 48px 的纵深排位就白做了）。
- [x] [战斗与关卡 · 防御与失衡](../../../canon/gameplay/战斗与关卡.md)写明**精准防御的回报按角色一律相同** —— 三份全给（免体力条、回少量 HP、回少量 MP），主角与队友同一份，**档位管的是掐不掐得准、不管吃多少**。
- [x] 同一处写明**那份回报可以被天赋与状态提升**，而修饰走[`成长系统` · 派生表：基底与来源分两栏](../../../design/成长系统.md)那条唯一的路；正典只写「可以被提升」，结构不在正典。
- [x] 同一处写明**它凭什么不绕掉「精准防御的回蓝效率不得高于进攻回蓝」** —— 那条约束按每次成功的效率判、不按谁来按，所以[数值模型](../../../design/数值模型.md)里已经在跑的那条判据原样管得住它。
- [x] [战斗与关卡 · 队友与敌人](../../../canon/gameplay/战斗与关卡.md)写明**敌人不走那五档** —— 它的强弱由全局难度与委托档位两层管，理由写清（那五档量的是学生练没练过，而敌人不练）。
- [x] 同一节写明**分级面板是同一套面板的两个子集**，不是两份数据形状；缺的那几栏读作空或零。理由指回[角色与成长 · 角色面板](../../../canon/gameplay/角色与成长.md)那条一致性要求与[`成长系统`](../../../design/成长系统.md)那条「不许给任何角色开专用成长通道」。
- [x] 同一节写明**动作机也是同一套，但一个角色有哪些动作由它自己声明** —— 只保证基础动作，有些怪物没有跳跃；写明它与分级面板是**同一个形状**（面板是同一套、栏可以空；动作机是同一套、动作可以缺），**细节指给[`角色动作状态系统`](../../../design/角色动作状态系统.md)，正典不展开**。
- [x] 同一节写明**敌人的载体类别是定义上的一个声明项**，取值见[世界观 · 外魔与魔化](../../../canon/world/世界观.md)（**本节不复述类数**），并写明它在战斗里**只决定死亡终态留下什么**，不改数值也不改行为。
- [x] [战斗与关卡 · 跳跃保留，不换成「按技能自动空中打击」](../../../canon/gameplay/战斗与关卡.md)那条挂着的账**当场兑现**：写明敌人的攻击定义要声明它的对策，「有据可查」那句改成指得到落点。
- [x] [玩法定位 · 系统清单](../../../canon/gameplay/玩法定位.md)里队友 AI、敌人 AI 与感知视野**三行按补齐后的范围改写**，各挂上指向本批两份新文档的链接；照既有形状**只写一句备注、不复述规则**。
- [x] **「撤退」这个同名不同物写清**：队友的「撤退」指令是脱离交战往主角身后退，与[战斗与关卡 · 失败判定](../../../canon/gameplay/战斗与关卡.md)那条玩家「返回入口点撤出关卡」是两件事。
- [x] 正典里一个玩法数值都没有新增；**五档的档数与两条轴的条数是接口常量**，写明归属就在这一节。
- [x] `python tools/check_docs.py` 0 项必须修复（与 `GP-51`、`GP-36` 合并之后才成立）。
