# ENG-3：建立验收总入口

> **本文件已归档，只读，不得作为现行依据。** 入口的现行用法见代码仓 `README.md`「怎么验收」，
> 执行体登记见 [WORKFLOW §6](../../../WORKFLOW.md)，现行待办见[台账](../../../spec/issues/README.md)。

## 目标

代码仓有一条命令能完成整轮验收，且**每一步都不只看退出码**。

## 来源

不来自 PRD —— 本条是工程基础设施，在台账直接立项。两个必须覆盖的具体形状来自本项目自己踩的坑：[踩坑记录 29](../../../reference/踩坑记录.md)（摘要说通过、有测试没跑）与同 33（导出泄漏不报错）。

## 依赖

`ENG-2`（已归档）—— 要先有工程、规则层与测试底座才有东西可验。

`ENG-11`（行尾守卫覆盖到代码仓）**不是**本条依赖，反过来它可以接进本入口。

## 验收标准

- [x] 一个总入口串联构建、测试、导出、跑产物，门禁只调它
- [x] 每步日志落盘；标准输出每步只有一行
- [x] 写一份带起止时间戳的运行摘要
- [x] 测试：断言运行器报的条数等于预期条数，光看「Passed」不算
- [x] 导出：校验产物确实生成、实际运行产物、并看包内清单有没有泄漏
- [x] 上一轮那个一次性的五步导出校验脚本被收编成 `tools/` 下的入口
- [x] 守卫自报覆盖量，并用真实缺陷形状自证（[WORKFLOW §6](../../../WORKFLOW.md)）

## 归档小结

**范围**：动了代码仓 `tools/`（新建）与两处文档说明，设计仓改了 `WORKFLOW.md`、`reference/踩坑记录.md`、台账。**没动**任何游戏代码、场景与数据 —— 本条只是把已有的三条命令串起来并加产物校验。`ENG-11`（行尾守卫覆盖代码仓）明确不在本轮。

两处**有意超出**「只做串联，不做新检查」这条边界，都已报备：多做了 `tools/selfcheck_verify.py`（[WORKFLOW §6](../../../WORKFLOW.md) 对守卫的自证要求是硬的），以及给 `tools/` 与 `logs/` 各配 `.gdignore`（这两个目录是本条自己往 `res://` 下加的，不配就等于一边加泄漏检查一边制造泄漏源）。

**结论**：入口是代码仓 `tools/verify.py`，四步串联、失败即停、逐步日志落盘、标准输出每步一行、另写带起止时间戳的 `summary.md`。三处退出码不可信的地方各有一个**独立量具**：构建自己数错误行且认不出输出形状就拒绝判过；测试比对运行器报的条数与从测试源码静态数出的条数；导出先清空 `export/` 让「文件存在」等于「本轮生成」，再自己解 `.pck` 逐条查泄漏；产物用引擎 `--log-file` 落盘的日志确认真的跑到内容载入完成。自证是 `tools/selfcheck_verify.py`。

被放弃的两个选项及理由：**放设计仓 `tools/`** —— 要跨目录找兄弟仓，守卫会依赖工作区布局；**放工作区根做成两仓共用** —— 那里不属于任何仓库，脚本不入库、不被 review，丢的是可复核性（工作区本身是稳定的，所以理由不是怕丢）。**包内清单读导出日志**也被放弃：日志的详细程度随引擎版本与开关变，而清单是产物本身。代价是要自己实现格式解析，而**第一版的格式假设就是错的** —— 靠「解析失败一律报错、绝不返回空清单」这条硬性检查当场暴露，否则它会安静地报出「泄漏 0 条」。

跑产物会让产物建自己的 `user://`（`mods` 与 `saves`）。入口**刻意不删** —— 那将来是玩家真正的存档位置，验收工具去删它很难收场；它不是临时资源，是正常启动的一部分，路径由产物自己打进冒烟日志。作者 2026-08-30 确认按此办。

**未尽**：`ENG-11` 行尾守卫覆盖到代码仓（本轮用一次性命令核过 40 个文本文件 0 不合规，一次性命令不是守卫）。**不顺手一起做的理由**：本条自己已有两处必须用真实缺陷形状自证的判定，再塞一个守卫的自证会让验收报告长到没人逐条核；而 `ENG-11` 还有个未定取舍（抽成两仓共用 vs 代码仓建等价入口），那够得上单独一轮。接口成本为零 —— 本入口的步骤表加一步即可。

冒烟标记钉在 `src/Main.cs` 那个脚手架上，入口会在标记脱节时当场判失败并提示同步改，不另立编号。

**教训**（均已进踩坑记录）：第 35 条「自证工具的还原必须覆盖被测系统的副产物」—— 挪走 `.gdignore` 那条用例让 Godot 生成了 8 个 `.cs.uid`，而「还原后复验」的判据看不见它们，是 `git status` 才发现的。第 36 条「导出产物的输出读不到，因为 release 包没有控制台包装器」。第 20 条补了一条：交互终端会截断长输出并给出无意义的退出码，长跑工具必须自己写日志。
