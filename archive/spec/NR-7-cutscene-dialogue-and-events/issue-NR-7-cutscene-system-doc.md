# NR-7：`design/剧情演出系统.md` 与它的那份 ADR

> **只读历史归档，不得作为现行依据。** 现行事实在[`剧情演出系统`](../../../design/剧情演出系统.md)与[ADR-0014](../../../decisions/ADR-0014-对话是演出脚本的一类指令.md)。**这个编号还没做完** —— 文档已交付而代码一行都没写，落地顺序与状态在[待办台账](../../../spec/issues/README.md)，不在本文。

## 目标

让「一段演出是什么、怎么推进、正式对话怎么在里面」只写在一处，而不是在教学关、开局与每个主线节点各长一套；同一轮把「正式对话是演出脚本上的一类指令」这条难撤销的取舍立成 ADR。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-001` 与 `US-003`
- 起因：[玩法定位 · 剧情演出：一律引擎内，不做视频](../../../canon/gameplay/玩法定位.md)写明它**很早就得有**（教学关与开局都依赖它），而现在没有一处持有「一段演出长什么样」；[玩法定位 · 对话：气泡与正式对话是两套东西](../../../canon/gameplay/玩法定位.md)只切开了气泡与正式对话，**没说正式对话与剧情演出是什么关系** —— 那个口子就是本条要答的。
- 它卡着 `NR-5`：那一行写明对话与剧情文本的落点「卡在两样东西上」，数据格式是其中一样。

## 依赖

`GP-53`（正典补齐，两份新文档的正典反向链接落点）。**与 `GP-52` 互相引用**（事件的一条后果是播一段演出，而演出里状态变更那一格要指回事件那边的记账），**一起验**。

ADR 不单独占编号：它只改正典一句、外加决定两份新文档的形状，所以并进本条。上一批那份 ADR 给了自己的编号，因为它同时改了三处已交付文档。

## 验收标准

**先答一个结构问题，答案与过程都写进本条的实现笔记：** 演出、事件、持续引导、气泡这几样**该写成几份文档**。按[`生产系统` · 什么时候拆出去单独成篇](../../../design/生产系统.md)那条判据（**它有没有自己的状态机**）逐样判一遍，并用上第 6 批留下的补充（**判据问的是「它会不会撑大宿主页」，而当一样东西多读者无主时，问的是「它有没有宿主页」**）—— 不默认拆，也不默认不拆，并写明结论将来被重判的条件。

### ADR 那一半

- [x] 按 [ADR 模板](../../../templates/ADR.md)写成 `ADR-0014`，落 `decisions/`，接进 [ADR 索引](../../../decisions/README.md)（索引那一行归 `DOC-42`）。
- [x] 背景写清正典留的口子在哪，以及不作决定的后果 —— 实现时会长出两台状态机与两套选项处理，而「演出里插一段带选项的对话」在[主线故事 · 二十个主线节点](../../../canon/narrative/主线故事.md)的节点 15 是必然需求。
- [x] 候选摆出**一份格式**、**两份且可嵌**、**两份不互嵌**，各写收益、代价与被否决的原因。两份可嵌那条要写出它的真代价（选项分支、跳过、存档字段、统计事件与本地化各做两遍，而「对话中途要不要推镜」落在两份格式的缝里）；两份不互嵌那条要写出节点 15 那种「一边说话一边推镜」直接做不出来。
- [x] 决策写成两句：**一段演出是一串指令，正式对话是其中一类**；**只有对话指令的脚本就是一次纯对话**。
- [x] 同一处写明**气泡不共用这份格式**，判据落在「接不接管输入」上（气泡不接管输入、没有流转、按上下文键选句，它是一条选取策略不是脚本），并写明这条正好兑现正典那句「不要合成一个系统」—— 气泡与正式对话从此在两份不同的文档里。
- [x] 写明它**没有**改的东西：气泡那几条约束（正典已写全）、演出的复杂度上限、「不做视频」那条、正式对话接管输入所以暂停世界那条。
- [x] 后果那一节写明**它让什么变便宜了**：跳过、快进、存档字段、统计事件与本地化都只做一遍。
- [x] 后果那一节写明落地要求各归哪一条编号。

### 系统文档那一半

- [x] 按 [SYSTEM 模板](../../../templates/SYSTEM.md)八节写全，`type: system`、文件名以「系统」结尾、`upstream` 指[玩法定位](../../../canon/gameplay/玩法定位.md)，**并在 `GP-53` 这一轮就被正典链接到**。
- [x] 一级标题写成一句结论，不是名词短语。
- [x] **一段演出写成一台状态机**，至少覆盖待命、推进、等玩家输入、收尾，每条流转写出进出条件；并写明**它与[`角色动作状态系统`](../../../design/角色动作状态系统.md)那两层是正交的**（一个管「这段脚本走到哪」，一个管「这个角色现在摆什么姿态」）。
- [x] **一条指令要声明哪些字段写成一张表**，至少覆盖指令类型、目标、参数与「它要不要等玩家」；同一处写明**指令类型是一张开口的表**（镜头、站位与移动、角色动作、正式对话、淡入淡出、状态变更、等待），**加一类指令时填的是这张表，而不是在状态机上加一个分支**。
- [x] **正式对话那一类指令写成一格**：说话者、文本键、可选的选项表，选项各带一个后续跳转。理由指回那份 ADR，本页不重写。
- [x] 写明**气泡不在本页**，并写清判据与它现在的家（约束在正典，语料条目的字段还没有落点 —— 记账编号由 `DOC-42` 那一轮加）。
- [x] **「文本一律按键取」只在本页展开一次**：脚本里不存台词、只存文本键；**日记与事件回看用的是同一条管线，所以三处不各写一套**。写明它已经落地（代码仓 `data/text/zh-CN.json` 与 `ENG-5` 那条文本外置预留），本页只定演出与对话怎么从它取文。
- [x] 写明**演出接管输入所以世界暂停**，暂停复用顿帧那个闸门（[玩法定位 · 弹界面接管输入就暂停世界，世界里的动作不暂停](../../../canon/gameplay/玩法定位.md)）；**由此推出演出期间不由玩家操作的角色也停着，本页不为 AI 加任何东西**。
- [x] 写明**演出摆布角色时把动作递给动作机、不经决策循环**（[`战斗AI系统` · 决策循环：一条顺序固定的链](../../../design/战斗AI系统.md)），且**引用了这个角色没声明的动作要载入报错**（[`角色动作状态系统` · 一个角色有哪些动作，是它自己声明的](../../../design/角色动作状态系统.md)）。
- [x] 写明**演出结束后的交还**：角色回到什么姿态与位置由脚本自己声明，**不做自动还原**（那会让「演出把人挪到门口」这种刻意的结果被悄悄撤销）；敌人的警戒状态在演出期间一个字都不改。
- [x] **跳过与快进各写成什么**：快进是加速推进、不跳过等玩家输入的那一类；跳过是直接跑到收尾并把脚本声明的状态变更**一次性全部应用**。同一处写明**跳过不许漏掉状态变更** —— 漏了会出现「跳过演出之后那个学生没加入」，而它不报错；这条要有反证。
- [x] 写明**防误触的形状是按住而不是点一下**，时长归 `GP-6`；能不能跳过按那份触发记账判（与 `GP-52` 共用）。
- [x] 写明**关卡中途触发演出时的边界**：世界暂停所以玩家不会在看剧情时被打；退出后由临时续玩点恢复到关卡入口，**演出不单独续玩**（要么没播完所以重播，要么已应用状态变更所以不再播）。
- [x] 写明**镜头指令分成两半**：本页定「有哪些镜头指令、各要什么参数」，**具体机位与时长由作者在检查器里填**（[ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md)）；相机手感那几个数不在本页（`UI-12`）。
- [x] 挂载点列全并写明「到此为止」，至少覆盖文本管线、动作机、相机、状态载体、统计事件总线（演出播完一条）、存档（已播过的脚本）、事件系统（它来点播一段）、任务与剧情节点（谁触发它）。
- [x] 边界那一节写明**不持有**：台词与脚本内容（内容外置，`ENG-5`）、气泡、日记、镜头手感值（`UI-12` 与 `GP-6`）、主线节点之间怎么解锁（进度见[待办台账](../../../spec/issues/README.md)）、骨骼动画级演出与预渲染视频（正典排掉）、界面排版（界面侧）。
- [x] 同名不同物写进边界那一节，至少覆盖：**「演出」与「过场」**（同一样东西，后者不用）、**「对话」的两个意思**（气泡与正式对话）、**「状态变更」**（演出脚本上那一类指令与[`状态效果系统`](../../../design/状态效果系统.md)的载体项不是一回事）。
- [x] 文档里一个玩法数值都没有。**指令类型的条数写成「一张开口的表」，不复述数字。**
- [x] `python tools/check_docs.py` 0 项必须修复（**与 `GP-53`、`GP-52` 合并之后才成立**，这一点写进「偏离」）。

## 实现笔记

### 拆成几份文档的判断

按[`生产系统` · 什么时候拆出去单独成篇](../../../design/生产系统.md)那条判据（**它有没有自己的状态机**）加第 6 批那条补充（**多读者无主时问它有没有宿主页**）逐样判：

| 东西 | 有自己的状态机吗 | 有宿主页吗 | 结论 |
| --- | --- | --- | --- |
| 剧情演出 | **有** —— 一段演出有开始、逐条推进、等输入与收尾，还带跳过与快进两条边界 | —— | **拆**（`design/剧情演出系统.md`） |
| 事件 | 没有 —— 它是「条件成立 → 调几个已有入口」 | **没有** —— 后果入口分散在经济、任务、失衡、状态载体、背包与人际各一处，塞进任何一份都让其余读者去读一份讲别的事的文档 | **拆**（`design/事件系统.md`），理由是无宿主而不是状态机 |
| 持续引导 | 没有 | **有** —— 它与事件共用同一份「已触发过」记账 | **不拆**，收进事件那一份当一节 |
| 气泡 | 没有 | **没有合法的** —— 正典禁止它与正式对话合成一个系统，所以进不了演出那一份；而它的记账语义与引导相反（冷却池会循环回来 vs 首次之后不再主动出现），同一份存储装不下 | **本批不写**，只定边界，结构立项记账（`NR-8`） |

**篇幅复核**：演出那一份的「结构」一节没有超过其余各节之和，事件那一份收下三个来源之后也没有 —— 两份都不需要再拆。

**结论将来被重判的条件**：① 引导长出**分步教学**（一步一步等玩家做对才继续）—— 那时它有了自己的状态机，按判据拆出去；② 气泡真有语料内容之后，按同一条判据重判它的落点；③ 演出那一份的指令类型表长到把「结构」一节撑过其余各节之和 —— 那时先拆的应该是镜头那一侧，因为它是唯一有自己参数面的一类。

### 设计决策

- **模糊点**：正典没说「要不要等玩家」这件事是从指令类型推出来，还是每条指令各自声明。
- **选择**：**每条指令显式声明，不从类型推。**
- **理由**：演出里有「自语一句、镜头继续推」这种用法，从类型推会把它删掉 —— 而它不报错，表现只是演出忽然变得很赶。代价是每条对话指令多填一格。

- **模糊点**：演出结束时角色与相机要不要自动还原。
- **选择**：**不自动还原，回哪由脚本自己声明。**
- **理由**：演出挪动角色常常正是它要的结果（把人送到门口），自动还原会把它悄悄撤销。

### 偏离

- **方案怎么说**：PRD 每条故事都写「`python tools/check_docs.py` 0 项必须修复」。
- **实际怎么做**：本条与 `GP-52`、`GP-53` **合并之后才 0 FAIL**。
- **为什么**：`type: system` 有「必须被正典链接到」的硬判定，而反向链接在 `GP-53` 那一轮才落地；两份新文档又互相引用。单独跑任何一条都会当场 FAIL，这不是缺陷。

- **方案怎么说**：条目里写「同名不同物」那一节要写清「演出」与「过场」。
- **实际怎么做**：原来写成「『过场』是旧说法，不再使用」，**交叉核对第一轮当场抓到它与文档自己打架** —— 那份文档正文用了「剧情过场」六处，而正典那句「全部剧情与过场」本来就在用它。改成「同一样东西、正式名是剧情演出」。
- **为什么**：一条自己都不遵守的命名禁令比没有禁令更坏。

### 权衡

- **ADR 没单独占编号**，并进本条。上一批那份 ADR 给了自己的号，因为它同时改了三处已交付文档；这一份只改正典一句，外加决定两份新文档的形状。
- **考虑过把气泡也写进本批**（三份格式那条候选），被正典那句「不要合成一个系统」挡掉；理由与代价都记进了 `ADR-0014`。

### 待确认

- **「跳过之后状态变更一条不少」这条反证的具体形式要等实现**：它挡的是「把状态变更写在每条指令的执行路径里」那种写法，而写法是实现时才定的。
- **本地化那一侧没有守卫**：脚本里存了台词原文这件事，等文本量上来才判得出来，现在只有纪律。
