# DOC-45：这一批的新量登记与规模基准复看

> **只读历史归档，不得作为现行依据。** 现行事实在[数值模型](../../../design/数值模型.md)的尚未给值表与[玩法定位 · 内容规模基准](../../../canon/gameplay/玩法定位.md)。**这个编号已完成**，去处见[待办台账](../../../spec/issues/README.md)的已归档编号表。

## 目标

让这一批新出现的量都有登记、校准办法与归属，而接口常量不被当成数值搬进参数表。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-005`
- 起因：[`数值模型` · 尚未给值的量，各自写明校准办法](../../../design/数值模型.md)是「值还没定的量」的唯一登记处；不登记的量会在实现时被凭手感填一个数，而那个数没有任何东西判得到。

## 依赖

依赖 `NR-8`、`NR-9`（要登记的量在那两份里定义）。

## 验收标准

- [x] 气泡那组量登记进尚未给值表：冷却池容量、单位时间新增上限、同时显示上限、同一角色不连说的最短间隔、同一条目跨角色的最短间隔、气泡停留时长。**归 `GP-7`** —— 要等语料与场景真的存在才定得出来。
- [x] 日记那组量同表登记：别人那本的解锁档位、**要不要给条目设保留上限**。**归 `GP-7`**。
- [x] 同一处写明**给值那一轮必须同时把判据接上**，并写出现在就判得到的那几条约束形式：**上限必须存在且大于零**；**解锁档位必须是五档中的一档且不是最低档**（最低档等于没有门）。
- [x] 保留上限那一行写明**判据是实测存档体积，不是估算** —— 现在写出来的量级是推断（条目数 ＝ 有日记的角色数 × 平均每天条数 × 天数，而正典写明无全局日期上限），实测办法是实现之后写满一段时间的条目、量存档文件。
- [x] 停留时长那一行写明它与引导提示的停留时长**同侧**（都归 `GP-7`），**不归 `GP-6`** —— `GP-6` 装的是只能实机逐帧调的战斗手感量。
- [x] **接口常量不进那张表**，各写明归属：上下文键有哪五个、优先级分几档、关系五档，家在正典；两级排序、条目类别表、纪事与心声的分工，家在本批两份文档。
- [x] [玩法定位 · 内容规模基准](../../../canon/gameplay/玩法定位.md)按**逐行重判**的结果补行，判断过程记在下面的「权衡」里。**不许直接抄上一批对引导条目那个「不补」的结论。**
- [x] 动了基准就跑 `python tools/simulate_week.py` 与 `python tools/simulate_week.py --check-doc`，并写明**结果不动是正常的**（脚本只读参数表与[数值模型](../../../design/数值模型.md)、不读基准那张表）以及**判据前提还成不成立是人工复核的**。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。四类都要过一遍，某类没有就写「无」并简要说明。

### 设计决策

- **模糊点**：气泡语料的条数是不是派生量。它看着像「上下文键组合数 × 每组几句」，而派生量按规矩不补基准行。
- **选择**：不是派生量，补一行。
- **理由**：派生量的判据是「它由别处某个数决定」。在本批定下的匹配规则下没有那个数 —— 一条语料只声明它在意的那几个键、没声明的视为任意，所以一条通用句能覆盖大量情境，条数与组合数不成比例。

### 偏离

- **方案怎么说**：基准表里那一行按类别的正式名命名。
- **实际怎么做**：改成「日记里那类『他怎么看』的条目」，类别的正式名指回[`日记系统` · 条目的类别是一张开口的表](../../../design/日记系统.md)。
- **为什么**：按词核对那一轮发现正典里出现了类别名，而类别表的家在系统文档 —— 正典写名字等于给那张表开第二个家。改成描述加链接之后，改类别名会被节名引用守卫抓到。

### 权衡

**规模基准逐行重判，三行各自的结论与理由。**

判据是：**这个数是派生量还是真的要定的内容量。** 派生量不补行 —— 补了就是同一个数两个家，而且它会随另一处变化静默过期。

- **气泡语料条目数：补一行。** 它容易被当成派生量（「上下文键组合数 × 每组几句」），但在本批定下的匹配规则下**不是** —— 一条条目可以只声明一个键、覆盖大量情境，所以条目数与键的组合数不成比例。它是真的要定的内容量，而且这一行要写明它得覆盖到什么：冷却池耗尽前不重复试得出来、两级排序里「专用句盖过通用句」看得出来、三个优先级档都有内容。
- **心声类条目数：补一行。** 它由「给几个角色写、每人写几条」决定，是内容量。这一行要写明它得覆盖到什么：至少要有揭示需求的条目（否则「读日记 → 发现需求 → 解锁小事件」整条链试不出来）、关系档触发与事件触发两种来源各若干、同一件事至少有一组不同角色的不同变体（否则「每个人的看法不同」这条试不出来）。
- **纪事类条目数：不补行。** 它是派生量 —— 条数跟着事件与日常动作走，而那两样各有自己的基准行。这个结论与上一批对引导条目的「不补」**形状相同但不是抄的**：那一条的理由是「条数由系统数决定」，这一条的理由是「条数由事件与动作数决定」。两条都落在同一条判据上，但各自指向不同的上游。

### 待确认

起步量那两个数是按「要覆盖到什么」算出来的，不是实测的。第一批语料与条目写出来之后要复看一遍它们够不够 —— 尤其气泡那一行，「冷却池耗尽前不重复」只有真跑一个场景才看得出来。
