# DOC-124：本轮端到端核对

> **只读历史归档，不得作为现行依据。** 现行事实在[`状态效果系统` · 谁在等这份载体，各要哪一档](../../../design/状态效果系统.md)、[`角色动作状态系统` · 谁把动作递进来，动作机答什么](../../../design/角色动作状态系统.md)、[SYSTEM 模板](../../../templates/SYSTEM.md)那段文件头示例与 `tools/check_docs.py` 里那条按体裁分的判定；状态在[待办台账](../../../spec/issues/README.md)。

## 实现笔记

### 设计决策

- **模糊点**：「逐个调用方点开确认」怎么留下痕迹 —— 人读一遍之后，下一个人怎么知道它被读过。
- **选择**：写一个临时核对脚本，把每一行与「对侧文档里必须搜得到的那句原文片段」配成一对，跑一遍打表；**脚本跑完即删**，结果抄进下面的验证结果表。
- **理由**：这一条判的不是措辞对不对（那归人读），而是**这一行不是凭印象写的**。配对本身是人做的判断，脚本只负责把「那句话还在不在」变成可复跑的事实。留成 `tools/` 入口反而不对 —— 它判的东西一次性（这两张新表），而[工作流那条判据](../../../WORKFLOW.md)是「看它判的东西在 Godot 里看不看得出来，别看它长得像不像守卫」：这两张表的正确性靠的是节名引用守卫加人读，不需要第二个常驻入口。

### 偏离

**无。**

### 权衡

考虑过把那个核对脚本落成 `tools/` 下的常驻入口。**没选**，理由在上面「设计决策」里 —— 它会变成一份要跟着两张表一起维护的配对清单，而那正是「同一个事实两个家」。

### 待确认

**无。** 本轮全部超边界发现都已记账：`DOC-125`（天气那处措辞）。`DOC-120` 那一处四份文档里的第四个自计数副本按同一缺陷实例就地改掉，理由写在那一条的「偏离」里。
