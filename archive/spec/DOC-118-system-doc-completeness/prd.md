# PRD：系统文档的接口节与元数据收口

> **只读历史归档，不得作为现行依据。** 现行事实在[`状态效果系统` · 谁在等这份载体，各要哪一档](../../../design/状态效果系统.md)、[`角色动作状态系统` · 谁把动作递进来，动作机答什么](../../../design/角色动作状态系统.md)、[SYSTEM 模板](../../../templates/SYSTEM.md)那段文件头示例与 `tools/check_docs.py` 里那条按体裁分的判定；状态在[待办台账](../../../spec/issues/README.md)。

## 1. 概述

`design/` 根下那批系统文档九节骨架齐、`python tools/check_docs.py` 0 FAIL，但**深度分两代**：先写的那批没有回头按后来成型的接口节写法补。

这次审计量了每一份的九节篇幅、接口节形状、图数与文件头新鲜度，查出四类问题：

1. **两份战斗核心文档的接口节没写全** —— 只写了它们俩之间那条接缝，没写别人怎么用它们。
2. **[`活跃失衡系统`](../../../design/活跃失衡系统.md) 没有台账编号** —— 它的落地进度按编号查不到。
3. **文件头两个字段已经在说假话** —— `last_verified` 与实际改动日期对不上，`status` 与台账的说法对不上。
4. **一批形状缺口**（该画的图、缺的小节与缺的那一行）没有编号，所以它们现在不存在于任何查得到的地方。

现在做的理由：第 1 类挡着落地 —— 台账里有一批待办等着状态载体扩容，而实现的人要跨五六份文档自己拼接口。第 2 与第 3 类是反漂移的漏洞，越晚补越贵。

## 2. 目标

- 打开那两份文档的接口节就能回答「谁调它、它调谁」，不用再翻别的文档。
- [`活跃失衡系统`](../../../design/活跃失衡系统.md) 在台账域表里查得到，与其余三十多份系统文档同形。
- 文件头 `last_verified` 与 `status` 两个字段从系统文档移除 —— 它们答的两个问题各自已经有家，留着是第二个家而且已经漂了。
- 本轮不做的那批形状缺口各有一个编号，不再是静默的。

## 3. 上游约束

只链接，不复制。

- [WORKFLOW §3](../../../WORKFLOW.md)：事实只许有一个家；散文只写理由、状态只在台账一处。**约束第 2 与第 3 类问题的判据 —— 两个字段与台账说不同的话时，没有任何东西判得出来哪个过期。**
- [ADR-0010](../../../decisions/ADR-0010-文档体裁与系统文档归位.md)：系统文档是活文档、骨架固定、随实现更新。**约束本轮只在既有骨架内补内容，不重排任何一节。** 骨架节数那一条已被 [ADR-0019](../../../decisions/ADR-0019-系统文档骨架加术语一节.md) 取代，本轮照现行那一份。
- [SYSTEM 模板 · 接口](../../../templates/SYSTEM.md)：接口节要列出「产出与效果分别落在哪个已有系统」，挂载点要**列全**并写明到此为止。**这是第 1 类问题的判据来源，本 PRD 不复述它的原句。**
- [ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md)：交界面是 `[Export]` 与 `Resource`，参数唯一来源是场景与资源。**约束接口表里「作者填」那一行是什么，也约束本轮不为任何字段留能用的默认值。**
- [待办台账 · 系统深化顺序](../../../spec/issues/README.md)：那一节写明它点名的每一项都要有编号，否则它在按编号查得到的地方不存在。**这是第 2 类问题为什么算问题的依据。**
- [ADR-0023](../../../decisions/ADR-0023-帧动画决定手感上限与技能归属.md)：技能一律瞬发、打断挂敌人预备帧。**它是第 3 类问题的实例** —— 它改写过 [`角色动作状态系统`](../../../design/角色动作状态系统.md) 的施放那一格，而那份文档的文件头没跟着重录。

## 4. 用户故事

**四个批次，按下面的顺序做。** 批次之间的依赖只有一处：`US-007` 依赖其余全部。

| 批次 | 装什么 | 故事 |
| --- | --- | --- |
| 批次一 | 补那个缺的台账编号 | `US-001` |
| 批次二 | 两份文档的接口节补齐，连同清掉过期措辞 | `US-002`–`US-004` |
| 批次三 | 文件头两个字段收口 | `US-005` |
| 批次四 | 其余形状缺口登记进台账 | `US-006` |
| 收口 | 端到端核对 | `US-007` |

### US-001：[`活跃失衡系统`](../../../design/活跃失衡系统.md) 有自己的台账编号

**描述**：作为要实现它的人，我想要按编号在台账域表里查到它的落地进度，以便不必去「系统深化顺序」那一节里翻散文。

**验收标准**：

- [ ] 可核对：台账「玩法与数值」表里有一行它的编号，备注以状态词表里的一个词开头。
- [ ] 可核对：那份文档的文件头「台账：」与「下游同步」两处都指向那个编号，不再指向 [待办台账 · 系统深化顺序](../../../spec/issues/README.md)。
- [ ] 可核对：新编号不复用任何已删除或已关闭的号。
- [ ] 可核对：落地顺序写在那一行的备注里，与文档正文不重复。
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL。

### US-002：[`状态效果系统`](../../../design/状态效果系统.md) 的接口节列全谁在等它

**描述**：作为要做载体扩容的人，我想要在一处看到「哪几个系统各要哪一档时长单位」，以便一次扩对，不必翻五六份文档对照。

**验收标准**：

- [ ] 可核对：接口节有一张表，按「谁要什么」列出全部等它扩容的系统，每行写明要的是哪一档时长单位。
- [ ] 可核对：表里每一行都指回那个系统自己那份文档，本页不复述它的规则。
- [ ] 可核对：接口节以「挂载点到此为止」收口，与其余系统文档同形。
- [ ] 可核对：接口节有「它不碰的那几条接缝」一节。
- [ ] 可核对：表里有「作者填」那一行，按 [ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md) 写明作者在编辑器里要填什么、没有就写「无」并说明。
- [ ] 可核对：本轮**没有改动**那份文档的任何设计结论 —— 三类分类、三种时长单位、显示与实际分离、薪尽火传那一节都一个字不动。

### US-003：[`角色动作状态系统`](../../../design/角色动作状态系统.md) 的接口节列全调用方

**描述**：作为要给动作机接一个新调用方的人，我想要在接口节看到已有的调用方都是谁，以便判断我这一个该挂在哪，而不是顺手插一个新钩子。

**验收标准**：

- [ ] 可核对：接口节有一张表，列出全部调用方，每行写明它递进来的是什么、动作机答什么。
- [ ] 可核对：既有的[那条唯一接缝](../../../design/角色动作状态系统.md)一个字不改，它仍然是与载体之间唯一的那一条。
- [ ] 可核对：接口节以「挂载点到此为止」收口。
- [ ] 可核对：接口节有「它不碰的那几条接缝」一节。
- [ ] 可核对：表里有「作者填」那一行。
- [ ] 可核对：本轮**没有改动**流转表、两条连通性载入校验与经营侧那一节的任何结论。

### US-004：三份文档里的代码字面量、批次名与自计数清掉

**描述**：作为读这三份文档的人，我想要它们说的话与自己开头那句承诺一致，以便不用判断哪一句才算数。

**要清的是这几样：**

- **代码字面量与它们的取值**，在 [`角色动作状态系统`](../../../design/角色动作状态系统.md) 的动作叠加层那一节 —— 而那份文档开头写着全部帧数与数值归 [数值模型](../../../design/数值模型.md)、本页一个都不定。
- **过程叙述**，同一处那句括号里的接线待办 —— 它是待办不是事实，家在台账。
- **批次名** `A1` 与 `A2`，出现在 [`伤害系统`](../../../design/伤害系统.md)、[`状态效果系统`](../../../design/状态效果系统.md) 与 [`角色动作状态系统`](../../../design/角色动作状态系统.md) 三份的正文里 —— 批次是状态。
- **自计数**，[`状态效果系统` · 载体的字段](../../../design/状态效果系统.md) 那份清单的条数在验收与完成边界两处被复述，而清单最后一条自己说它是两个字段 —— 实现时数出来与复述的数不一致。

**验收标准**：

- [ ] 可核对：那两个代码字面量与它们的取值从正文消失，行为照旧写得出来（写行为、不写代码）。
- [ ] 可核对：括号里那句接线待办从正文消失；真有剩余动作就在台账记一条。
- [ ] 可核对：三份文档里搜不到 `A1` 与 `A2` 这两个批次名；要指那批已实现的行为时按行为名指，不按批次名指。
- [ ] 可核对：那处自计数**删掉而不是改对数字** —— 按 `DOC-68` 立下的那条判据，改对数字撑不到下次加项。
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL。

### US-005：文件头那两个字段收口

**描述**：作为三周后回来读文档的人，我想要文件头说的话可信，以便不必去 git 里对一遍才知道它新不新。

**它现在的样子**：`last_verified` 在多数系统文档里比 git 最后一次改动它的日期早，最旧的一份差了半个多月；`status` 几乎全是 `draft`，而台账逐条写着「设计已交付」。检查器只验 `last_verified` 的格式，不验新鲜度。

**做法已定：删字段，不加守卫。** 理由是它们各自要答的问题都已经有家，留着就是第二个家：

- `last_verified` 要答「这一份还准不准」，而那个答案在**上游指纹**那套机制里 —— 改动正典某一节之后检查器会报「引那一节的上游约束要复核」，复核完 `--repin` 重录，指纹进 git，所以「我看过了」已经留得下痕迹。
- `status` 要答「做到哪一步了」，而那是状态，家在[待办台账](../../../spec/issues/README.md)一处（[WORKFLOW §3](../../../WORKFLOW.md)）。
- **没选加守卫那条路**：它要求每次改文档都顺手改一行日期，而那类「每次记得做」的纪律靠不住；更实际的是批量改链接会一次报一批，于是还要再造一个显式重录的入口 —— 为一个没有读者的字段建一套机制。

**验收标准**：

- [ ] 可核对：两个字段从全部 `type: system` 与 `type: model` 文档的文件头移除。
- [ ] 可核对：`tools/check_docs.py` 的必填字段与允许值跟着改，**那两条校验连同它们的 FAIL 文案一起删** —— 留着判一个不存在的字段会让每一份都报错。
- [ ] 可核对：[SYSTEM 模板](../../../templates/SYSTEM.md)里那段文件头示例跟着改。
- [ ] 可核对：其余体裁（正典、ADR、制作规格、模板、台账、需求文档）**这一轮不动** —— 范围只到系统文档与跨系统模型，理由写在非目标里。
- [ ] 可核对：按字段名搜两个仓加 `.kiro`，没有指着系统文档那两个字段的残留说法。
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL，并读它自报的覆盖量 —— **退出码 0 不等于成功**。

### US-006：其余形状缺口登记进台账

**描述**：作为排后续批次的人，我想要这些缺口各有一个编号，以便它们排得进顺序，而不是只存在于一次会话里。

**要登记的是这几样：**

- **该画图而没画的两份**：[`活跃失衡系统` · 三个新读口带来一个正反馈，刹车必须先在](../../../design/活跃失衡系统.md)（它写出了一个自加强的环，而环用散文写，读者要自己在脑子里连线）与 [`地图与导航系统` · 切换是世界里的动作](../../../design/地图与导航系统.md)（边界切换是一条固定顺序链，且它刻意与关卡那条转场不同）。
- **缺「它不碰的那几条接缝」的那批**：伤害、地块、成长、技能、教育、活跃失衡、物品、生产、背包。
- **接口表缺「作者填／作者做」那一行的那批**，清单在实现时按那条形状量出来，**不在本 PRD 抄一份**。

**验收标准**：

- [ ] 可核对：上面每一样在台账域表里各有一行，备注以状态词表里的一个词开头。
- [ ] 可核对：每一行写明它卡在什么上，或者写明不卡任何人。
- [ ] 可核对：本 PRD 与那几行不互相复述清单 —— 清单只有一个家。
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL。

### US-007：端到端核对

**描述**：作为收口的人，我想要一次把这一轮的每一条都核过，以便交付时说得出哪一条凭什么算过了。

**验收标准**：

- [ ] 可核对：`python tools/check_docs.py` 0 FAIL，并读它自报的覆盖量，不只看退出码。
- [ ] 可核对：设计仓与代码仓两个仓加 `.kiro` 都按本轮动过的编号与字段名搜过一遍，零残留。
- [ ] 可核对：那两份文档的接口节各能独立回答「谁调它」—— 逐个调用方点开对应文档确认那条接缝真存在，不是凭印象写的。
- [ ] 可核对：本轮声称「一个字未改」的那几处拿 `git diff` 的删除行数作证，不只说「我没动」。
- [ ] 可核对：本轮超出边界的发现各有一个台账编号。
- [ ] 必须实机确认：**不适用** —— 本需求全是文档与检查器，没有表现与手感。

## 5. 功能需求

- FR-1：[`活跃失衡系统`](../../../design/活跃失衡系统.md) 必须在台账域表里有一行属于它自己的编号。
- FR-2：那份文档的文件头与下游同步两处必须指向那个编号。
- FR-3：[`状态效果系统`](../../../design/状态效果系统.md) 的接口节必须有一张表，列出等它扩容的系统各要哪一档时长单位。
- FR-4：[`角色动作状态系统`](../../../design/角色动作状态系统.md) 的接口节必须有一张表，列出全部调用方。
- FR-5：那两份文档的接口节必须各以「挂载点到此为止」收口。
- FR-6：那两份文档的接口节必须各有「它不碰的那几条接缝」一节。
- FR-7：那两份文档的接口表必须各有「作者填」那一行。
- FR-8：代码字面量与它们的取值必须从 [`角色动作状态系统`](../../../design/角色动作状态系统.md) 的正文移除。
- FR-9：批次名必须从三份长期文档的正文移除。
- FR-10：[`状态效果系统`](../../../design/状态效果系统.md) 那处自计数必须删除，不许改成对的数字。
- FR-11：`type: system` 与 `type: model` 的文档必须不带 `last_verified` 与 `status` 两个字段。
- FR-12：检查器必须按体裁分别要求文件头字段 —— 对这两个体裁要求它们**不在**，对其余体裁照旧要求它们在。
- FR-13：本轮明确不做的每一样缺口必须在台账里各有一行。
- FR-14：本需求的全部改动完成后 `python tools/check_docs.py` 必须 0 FAIL。

## 6. 非目标

- **不改任何系统文档的设计结论。** 本轮只补接口清单、删过期措辞、改元数据。任何一处要改结论，立项另记。
- **不重排九节骨架，不新增第十节。** 骨架归 [ADR-0010](../../../decisions/ADR-0010-文档体裁与系统文档归位.md) 与 [ADR-0019](../../../decisions/ADR-0019-系统文档骨架加术语一节.md)。
- **不动代码仓。** 本轮唯一要改的工具是设计仓的 `tools/check_docs.py`。
- **不本轮补那批缺的小节与那一行**（US-006 只登记）。理由：它们涉及二十来份文档，与本轮那两份的深度补齐是两种工作量；混在一批会让回归责任说不清。
- **不本轮画那两张图**（同上，只登记）。画图要连着复核那一节的正文，属另一批。
- **不碰那些零张图但不该画图的文档** —— 物品、图鉴、界面与数值模型四份都是表能说清的分类与字段，没有状态机也没有顺序链。
- **不新建任何系统文档，也不拆分现有的任何一份。**
- **不改 ADR。** 本轮没有跨域取舍。
- **不删其余体裁的文件头字段。** 正典、ADR、制作规格、模板、台账与需求文档照旧带 `status` 与 `last_verified` —— `status` 在 ADR 与归档件那边挂着真机制（归档边界判定、`superseded` 配对），删它是另一件事。**范围只到 `type: system` 与 `type: model`。**

## 7. 界面与表现考虑

不适用 —— 本需求只动设计仓的文档与检查器，不产生任何玩家看得到的东西。

## 8. 技术考虑

- **唯一要动的工具是 `tools/check_docs.py`**：它现在无条件要求那四个文件头字段，要改成按体裁分。
- **两处机制不许被顺手动掉**：归档件那条 `status` 判定（归档边界靠它）与 ADR 那条「`superseded` 必须同时写 `superseded_by`」。**这正是本轮只删系统文档与跨系统模型那两个体裁的理由** —— `status` 在 ADR 与归档件那边是真机制，在系统文档这边才是第二个家。
- **删掉之后要有东西挡住它长回来**，否则下一份系统文档照着别处抄一遍文件头就又有了。所以检查器那一条要判「这两个体裁不许带它们」，而不是只把必填改成可选。
- **不依赖任何尚未裁定的玩法或数值。** 本需求不碰玩法结构，也不碰参数表。

## 留下的判据

- **纯锚点链接不在任何守卫的判定面内。** 断链判定的目标组要求至少一个非 `#` 字符，节名引用守卫要求标签里有分隔符 —— 所以 `](#某一节)` 两条都不匹配，改名就静默断掉。要在同一份文档里指自己某一节时，写成「文件加锚点」的形式。
- **「零删除行」这条证据要用 `--numstat`，不要用按行前缀过滤。** Markdown 列表行在 diff 里以 `--` 开头，`^-[^-]` 那种模式会把它漏掉 —— 本轮就是这么差点漏掉两行。
- **一份文件同时被几条 issue 改到时，整文件暂存就分不开。** 本轮的做法是按「只动文件头」与「有正文改动」分组提交，让每次提交仍然说得清一件事。
