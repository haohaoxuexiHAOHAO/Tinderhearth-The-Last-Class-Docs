# DOC-119：`角色动作状态系统` 的接口节列全调用方

> **只读历史归档，不得作为现行依据。** 现行事实在[`状态效果系统` · 谁在等这份载体，各要哪一档](../../../design/状态效果系统.md)、[`角色动作状态系统` · 谁把动作递进来，动作机答什么](../../../design/角色动作状态系统.md)、[SYSTEM 模板](../../../templates/SYSTEM.md)那段文件头示例与 `tools/check_docs.py` 里那条按体裁分的判定；状态在[待办台账](../../../spec/issues/README.md)。

## 目标

打开[`角色动作状态系统`](../../../design/角色动作状态系统.md)的接口节就能回答「谁递东西进来、动作机答什么」，于是要接一个新调用方的人先问「它挂在这几个里的哪一个」，而不是顺手插一个新钩子。

## 来源

PRD：[`prd.md`](./prd.md) 的 `US-003`。

**立项依据**：那一节是全库最薄的接口节，只写了与[`状态效果系统`](../../../design/状态效果系统.md)那一条接缝。而[`剧情演出系统`](../../../design/剧情演出系统.md)写着摆布角色走动作机那条既有的路、[`战斗AI系统`](../../../design/战斗AI系统.md)递「想做什么」、[`伤害系统`](../../../design/伤害系统.md)算出的结果要有落点、[`生产系统`](../../../design/生产系统.md)的劳作是经营侧那一层的读条动作 —— 这些调用方在那一节里一个都没出现。

## 依赖

无。本条只改文档。

## 验收标准

- [x] 接口节有一张表，列出全部调用方，每行写明它递进来的是什么、动作机答什么。
- [x] 表里每个调用方都指回它自己那份文档，**本页不复述它的规则**。
- [x] 表里有「作者填」那一行，按 [ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md) 写明作者在编辑器里要填什么；确实没有就写「无」并说明为什么。
- [x] 接口节以「挂载点到此为止」收口。
- [x] 接口节有「它不碰的那几条接缝」一节。
- [x] 与载体那条唯一接缝**一个字不改**，方向仍然只有一个（拿 `git diff` 作证）。
- [x] 流转表、两条连通性载入校验与经营侧那一节的结论**都一个字不改**（同上作证）。
- [x] 逐个调用方点开对应文档，确认那条接缝在对侧真的写着 —— 不是凭印象写的。
- [x] `python tools/check_docs.py` 0 FAIL。

## 实现笔记

### 设计决策

- **模糊点**：这张表该按「谁调它」排，还是按「递进来什么」排。
- **选择**：按调用方排，而表头那一句写明**递进来的东西只有一种形状（「想做什么」），动作机答的也只有一句（能不能发出）**。
- **理由**：按形状排会得到一张只有两行的表，而读者的问题是「我这个系统怎么接上去」。把「只有一种形状」提到表头，既保住了那条结论，又让每个调用方查得到自己那一行。

### 偏离

**无。** 实际改动与条目一致：只加了两小节，既有内容零删除（`git diff --numstat` 报 33 增 0 删）。

### 权衡

- 考虑过把[`感知与视野系统`](../../../design/感知与视野系统.md)也列进调用方表。**没选**：它自己那一页写明「本页不往动作机递任何东西」，所以它属于「不碰的接缝」那一节 —— 列进调用方表会让一条明确的否定看起来像一条肯定。
- 考虑过把那条「引用了没声明的动作要报错」的载入校验只留在结构那一节。**没选**：它盖住的两类引用者正是接口表里的两行，写在表下面才问得出「我这一行要不要过它」。

### 待确认

**无。** 表里每一行都在对侧文档里找到了原句，代码路径 `rules/Combat/CombatInput.cs` 实测存在。
