# DOC-118：`状态效果系统` 的接口节列全谁在等它

> **只读历史归档，不得作为现行依据。** 现行事实在[`状态效果系统` · 谁在等这份载体，各要哪一档](../../../design/状态效果系统.md)、[`角色动作状态系统` · 谁把动作递进来，动作机答什么](../../../design/角色动作状态系统.md)、[SYSTEM 模板](../../../templates/SYSTEM.md)那段文件头示例与 `tools/check_docs.py` 里那条按体裁分的判定；状态在[待办台账](../../../spec/issues/README.md)。

## 目标

打开[`状态效果系统`](../../../design/状态效果系统.md)的接口节就能回答「哪几个系统在等载体扩容、各要哪一档时长单位」，不必翻那几份文档自己拼。

## 来源

PRD：[`prd.md`](./prd.md) 的 `US-002`。

**立项依据**：它是全库被引用最多的几份之一，却是篇幅最小的一份，而接口节只写了与动作机那一条接缝 —— 那一节既没有表、没有「挂载点到此为止」收口、也没有「它不碰的那几条接缝」，而其余系统文档都有。

## 依赖

无。本条只改文档。

## 验收标准

- [x] 接口节有一张表，按「谁要什么」列出全部在等载体扩容的系统，每行写明要的是哪一档时长单位。
- [x] 表里每一行都指回那个系统自己那份文档，**本页不复述它的规则**。
- [x] 表里有「作者填」那一行，按 [ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md) 写明作者在编辑器里要填什么；确实没有就写「无」并说明为什么。
- [x] 接口节以「挂载点到此为止」收口，与其余系统文档同形。
- [x] 接口节有「它不碰的那几条接缝」一节。
- [x] 与动作机那条唯一接缝**一个字不改**，它仍然是唯一的那一条（拿 `git diff` 作证）。
- [x] 三类分类、三种时长单位、显示与实际分离、薪尽火传那一节**都一个字不改**（同上作证）。
- [x] `python tools/check_docs.py` 0 FAIL。

## 实现笔记

### 设计决策

- **模糊点**：表里每一行「要哪一档」的依据，是去各自那份文档里读出来的，还是凭本页已有的三种单位反推。
- **选择**：逐份读对侧文档，按它自己写的那句填；本页不替任何一侧决定它该要哪一档。
- **理由**：反推会让本页成为那件事的第二个家 —— 对侧改了要求而本页不会报错。逐份读之后，这张表是索引而不是第二份声明，所以每一格都指回去。

### 偏离

**无。** 实际改动与条目一致：只加了两小节，既有内容零删除（`git diff --numstat` 报 38 增 0 删）。

### 权衡

- 考虑过把这张表按「时长单位」分成三张小表（帧一张、天一张、永久一张）。**没选**：读它的人问的是「我这个系统要什么」，不是「哪些人要帧」—— 按读者的问题排序，一张表一次答完。
- 考虑过在表里写每一档的推进点。**没选**：那是结构那一节已有的事实，抄到接口节就多一个家。

### 待确认

- [`天气系统`](../../../design/天气系统.md) 的「下游同步」把它要的那一档说成「在场期间」，而它自己的「上游约束」写着不新造一种时长单位，它的机制也确实是永久项加来源标签。**本轮按后者填表、没有改那一份**（超出本条边界），那处措辞另记 `DOC-125`。

## 验证结果

| 命令 | 结果 | 判定 |
| --- | --- | --- |
| `python tools/check_docs.py` | 扫 308 份文档／0 项必须修复／0 条提示 | 通过 |
| `git diff --numstat -- design/状态效果系统.md` | `38  0` | 通过 —— 零删除行，证明既有结论未动 |
| `git diff -U0` 过滤删除行 | 无输出 | **不作为独立证据** —— 当时用的过滤模式是 `^-[^-]`，它会漏掉 Markdown 列表行（`- ` 在 diff 里变成 `-- `）。这个缺陷在评审那一轮查出来并改了模式。**「零删除」那条结论靠 `--numstat` 的 `0`，那一侧不受模式影响** |
