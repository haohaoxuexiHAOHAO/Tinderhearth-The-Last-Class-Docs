# GP-122：装备那几个上限定值，各有唯一的家

> **只读历史归档，不得作为现行依据。** 本条的结论已经写进它指的那几份活文档，落点清单在同目录 [`prd.md`](./prd.md) 的「归档三问」；状态与剩余动作在[待办台账](../../../spec/issues/README.md)，不在本页。

## 目标

界面要画几格有依据，实现时不必现场拍一个以后查不到出处的数。

## 来源

- PRD：[`prd-extensible-lists`](./prd.md) 的 `US-004`
- 判据：[ADR-0025](../../../decisions/ADR-0025-取值集的家由加一个的代价决定.md) —— 它们都是别处要按它排版的数，所以归接口常量、只写一处

## 依赖

无。落地跟 `GP-24` 走。

## 立项理由

[`装备系统`](../../../design/装备系统.md)的边界那一节把这几个数的家写成「正典那一节与本页」两处，而核过之后**两处都没有值** —— [角色与成长 · 装备：宝物与宝石](../../../canon/gameplay/角色与成长.md)只给了宝物栏格数与每个技能的孔数。而[数值模型](../../../design/数值模型.md)明写接口常量不进它那张表，所以这几个数现在谁都不持有。

## 验收标准

- [x] 主词条恰好 1 条。**这一条不是新定的** —— [`装备系统` · 词条：主词条写死，副词条掷定即不变](../../../design/装备系统.md)通篇写的就是单数，而它给的理由（让玩家一眼看出「这件是攻击向的」）在两条主词条下不成立
- [x] 副词条最多 3 条，条数**按稀有度逐档递增、最低那一档 1 条** —— 稀有度自己就答了「有几条」，**不另开一张对照表**。写成规则而不是一串数，理由见下面「偏离」
- [x] 宝物孔最多 3 个，理由指得回宝石的起步量：进得了宝物孔的只有声明了属性侧的那些，孔开得比宝石多只会让缺口更大；而一件宝物旁边要画的格子越多面板越挤
- [x] 强化最多 5 级，理由是「强化到顶」要是一个记得住、看得见头的目标 —— 每一级都走同一条花钱花材料的路，级数多了它就从目标变成一条磨的曲线
- [x] 这几个数各**只写在一处**（[角色与成长 · 装备：宝物与宝石](../../../canon/gameplay/角色与成长.md)），[`装备系统`](../../../design/装备系统.md)与[数值模型](../../../design/数值模型.md)两处「家在正典与本页」的说法都改成了一处
- [x] 各档稀有度给几个基础孔、强化每级开几个附加孔**仍留在**[数值模型](../../../design/数值模型.md)的尚未给值表，本条不给
- [x] 反证写进[`装备系统`](../../../design/装备系统.md)的验收（跟 `GP-24` 走）：孔数超上限被拒、强化到上限后再强化被拒、**带两条固定主词条被拒且一条都不带也被拒**（两条一起才钉住它是「恰好一条」而不是「至多一条」）、声明条数超上限的稀有度配置被拒
- [x] 按词搜两个仓加 `.kiro`，活文档里没有第二处写着这几个数

## 实现笔记

### 设计决策

- **模糊点**：这几个数的家定在正典还是[`装备系统`](../../../design/装备系统.md)。
- **选择**：**正典那一节**，全族一处。
- **理由**：那一节已经持有宝物栏格数与每个技能的孔数，而它给的判据是「改它要连带改内容与界面排版，所以它的家就是这一行」—— 我这几个数都有同一个性质。拆成两处会让同一族数字里一半在正典、一半在设计侧，而读者不知道该查哪边。

### 偏离

- **方案怎么说**：副词条「按稀有度三档给 1／2／3 条」。
- **实际怎么做**：写成「按稀有度逐档递增、最低那一档 1 条」。
- **为什么**：写成一串数就把稀有度的档数硬编进了这一行 —— 而**稀有度到底可不可扩现在没有答案**（那正是 `GP-127` 记的那笔账）。写成规则的话，档数变了它仍然给得出答案。**同一处另写明了那条耦合**：加一档稀有度会顶破副词条那个上限，所以两件事要一起看。

### 权衡

- **考虑过把这几个数放进[数值模型](../../../design/数值模型.md)。** 否决理由是那一份自己写着接口常量不进它的表 —— 它持有的是进得了不等式判据的平衡量，而这几个数决定的是界面画几格。
- **考虑过宝物孔上限取更大的数**（例如与宝物栏格数同数）。否决理由：起步能进宝物孔的宝石就那几颗，孔开得比宝石多只是把缺口变大，而取舍的性质（哪颗两用宝石往哪边镶）一点没变。

### 待确认

- 无。

## 顺带修掉的一处

[`装备系统`](../../../design/装备系统.md)与[数值模型](../../../design/数值模型.md)两处都把**专属栏格数**列在接口常量那一批里，而它在角色定义上按角色声明（可以是 0）—— 它是一个内容字段，不是全局常量。两处都改了。它与本条同一句话，所以不另立编号。
