# GP-124：作物阶段数由每种作物自己声明

> **只读历史归档，不得作为现行依据。** 本条的结论已经写进它指的那几份活文档，落点清单在同目录 [`prd.md`](./prd.md) 的「归档三问」；状态与剩余动作在[待办台账](../../../spec/issues/README.md)，不在本页。

## 目标

做得出三天成熟的速生菜；而「最快几天成熟」这个会被抄错的数字从此不存在。

## 来源

- PRD：[`prd-extensible-lists`](./prd.md) 的 `US-006`
- 判据：[ADR-0025](../../../decisions/ADR-0025-取值集的家由加一个的代价决定.md) —— 阶段序列是一条作物自己的声明，加一种作物不用写代码

## 依赖

无。落地跟 `GP-87` 走；素材那一半归作者（[ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md)）。

## 立项理由

现在[`地块系统`](../../../design/地块系统.md)固定五个阶段、其中四个计时，于是算出一个「最短生长周期」。那个数被[数值模型](../../../design/数值模型.md)抄了一份并且抄错了值，同一行还要求「五个阶段各几天」而实际只有四项。**放开阶段数是根治**：那个数由每种作物自己的声明算出来，没有一个全局的数可以抄错。

## 验收标准

### 形状

- [x] 一种作物声明一个阶段序列，**第一个必须是种子、最后一个必须是成熟可收**，中间几个由它自己定
- [x] 最少就这两个（种子 → 成熟），所以计时阶段至少一项
- [x] 成熟是终态、**不带天数**（到了就一直等玩家收）。这条不变，理由照旧是多一个没人读的字段填错了不报错
- [x] 计时的阶段各至少 1 天
- [x] 可测试：一项、两项、多项都载入成功且各自算得出自己的成熟序号；**一项都没有的被拒**。两条一起才钉住判的是「至少一项」
- [x] 可测试：**只有种子与成熟的速生作物一天就待收** —— 钉住按天推进读的是这条作物自己的成熟序号
- [x] **循环收获那一格照旧**：填阶段号＝退回那一阶段，填成熟那一阶段或更后被拒，另配「退回成熟之前照旧成立」的反向反证

## 实现笔记

### 设计决策

- **模糊点**：「退回的阶段不许到成熟」这条上界要读成熟序号，而成熟序号现在由阶段天数那一项算出来 —— 两个字段之间的校验，`init` 里做不到（属性赋值顺序不保证）。
- **选择**：把这条校验挪进 `Parse`，`init` 只留「不为负」。
- **理由**：内容一律从数据文件来（`ENG-5`），所以 `Parse` 是唯一的真实入口；直接 `new` 只出现在测试里。**边界写进了注释**，那条测试也跟着改成走 JSON。**没选改成位置参数 record** —— 那会推翻类注释里那条实测结论（位置参数 record 配 `System.Text.Json` 时缺字段不报错、拿 `default` 填）。

### 偏离

- **方案怎么说**：[`prd-extensible-lists`](./prd.md) 的非目标写着「**不改代码**」。
- **实际怎么做**：连代码一起改了（定义、按天推进、两份测试、`ARCHITECTURE.md`）。
- **为什么**：地块的规则层**已经落地了**，代码把阶段数写成了常量并强制天数恰好几项。只改文档的话，文档说可变、代码写死，当场造一个分叉 —— 而这一轮的全部目的正是消除这类分叉，留一个新的等于自己打自己的脸。**这一条与本轮别的条目不同源**：那些系统的代码还不存在，所以文档超前是正常的，反证跟落地编号走就行。**作者已按这条走。**

### 权衡

- **考虑过只改文档、代码那一侧另立编号。** 否决理由见上面「偏离」。
- **考虑过保留一个「默认阶段数」常量**，让没声明的作物退回五个阶段。否决理由是 `ADR-0009`：代码不留能用的默认值 —— 有默认值的话「作者忘了声明」会被静默兜底成五个阶段。
