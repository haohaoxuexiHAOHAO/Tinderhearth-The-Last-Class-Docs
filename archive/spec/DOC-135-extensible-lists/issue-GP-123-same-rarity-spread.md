# GP-123：同稀有度的两件宝物差距小，而拿到好东西仍然爽

> **只读历史归档，不得作为现行依据。** 本条的结论已经写进它指的那几份活文档，落点清单在同目录 [`prd.md`](./prd.md) 的「归档三问」；状态与剩余动作在[待办台账](../../../spec/issues/README.md)，不在本页。

## 目标

同一稀有度同品质的两件宝物几乎一样，所以开不出废品；惊喜改由「你拿到的是什么」承担，而不是「它掷了多少」。

## 来源

- PRD：[`prd-extensible-lists`](./prd.md) 的 `US-005`
- 上游：[`物品系统`](../../../design/物品系统.md)那条分工 —— 稀有度答「有几条副词条」、品质答「每条有多强」。本条全部搭在它上面，不新开第三条轴

## 依赖

无。本条那张正负条数表要的副词条条数上限由 `GP-122` 给，状态查[待办台账](../../../README.md)。落地跟 `GP-24` 走。

## 验收标准

### 差距的上界

- [x] 副词条里正负各几条**按稀有度固定、不随机**：负面恰好一条，正面条数随稀有度长，所以同稀有度的两件实例形状完全一样
- [x] **负面永远恰好 1 条** —— 这是「被坑得多惨」那一侧的上界
- [x] **掷正负条数的做法明确不做**：那会让同一件开出「零正三负」，而玩家会直接当废品
- [x] 反证写进[`装备系统`](../../../design/装备系统.md)的验收（跟 `GP-24` 走）：正负条数与稀有度不符的实例被拒，**另加一条反向反证**（不同稀有度掷出来的正面条数不同，缺了它就分不出判的是「固定」还是「全都一样」）
- [x] 立了一条约束形式：单条副词条的掷定波动不得大到让同稀有度同品质的两件差出一个品质级差
- [x] 立了第二条：品质的级差必须大于同级内的掷定波动 —— 否则「这件是传奇」在面板上看不出来
- [x] 这两条登记进[数值模型](../../../design/数值模型.md)装备那一行，值归 `GP-7`，并写明给值那一轮要把它们接成判据

### 爽感的落点

- [x] **光环那一格原先不存在** —— 正典写着宝物提供特殊光环，而字段表里没有它。本条把它建起来了
- [x] 它**按声明必填**：声明了才有、没声明不报错，声明了却填不出换掉哪一条则被拒 —— **所以「有没有光环」自己就是一处跳变**
- [x] 一件宝物的光环**必须换掉一条判定或加一条本来没有的行为**，不得只是又一个属性修饰；判据与[`技能系统` · 宝石：改机制，不只是改数字](../../../design/技能系统.md)那条**同一条，不新造**
- [x] 写明它**落载体的参数类、不是第四类**（「改判定」本来就属参数类），所以不新建载体、不新建分类
- [x] 惊喜的来源在[`装备系统`](../../../design/装备系统.md)那一节写明，各指回一样已经存在的东西
- [x] [内容规模基准](../../../canon/gameplay/玩法定位.md)宝物那一行加一条硬要求：**带光环的与不带光环的各至少有一件** —— 全带或全不带都会让那处跳变试不出来
- [x] 反证写进那一份的验收（跟 `GP-24` 走）：没声明光环的定义载入成功、声明了却填不出的被拒（**同一批用例**）、只声明数值修饰的被拒、光环不新增分类与时长单位

### 两条边界

- [x] **最低那一档是过渡品，这是刻意的。** 它只有一条正面主词条与一条负面副词条，净收益可能接近零 —— 玩家一眼看得出该早点换掉。**不给它开纯增益的口子**（那会撞破 [ADR-0011](../../../decisions/ADR-0011-纯增益装备的窄例外.md)，那条窄例外的对象是几件唯一装备而不是一整档），**也不靠「把负面幅度压得很小」缓解**（那是个值，压多小要等 `GP-7`，于是问题一直没有答案）
- [x] **「刷到极品」那条路刻意没有。** 不做重掷、波动又窄，换来的是不开废品；两者只能选一个，文档里写明这是取舍而不是遗漏

## 实现笔记

### 设计决策

- **模糊点**：正典写着「宝物增强属性、提供特殊光环」，而[`装备系统`](../../../design/装备系统.md)的宝物字段表里**根本没有光环那一格** —— 所以「每件都有吗」从来没被答过，而本条的爽感方案正好压在它身上。
- **选择**：**按声明必填** —— 声明了才有，没声明就是没有光环、不报错。
- **理由**：两条。**内容量**：每件都要就是起步那十几件各配一个独特机制。**低档定位**：本条同一份文档里刚把最低那一档定成「一条正面主词条 ＋ 一条负面副词条」的过渡品，再送它一个独特光环，两条会当场矛盾。**顺带的收益比这两条都实**：「有没有光环」于是自己成了一处看得出来的跳变，等于多一层爽感。**作者已按这个走**，[内容规模基准](../../../canon/gameplay/玩法定位.md)因此加了「带的与不带的各至少一件」那条硬要求 —— 全带或全不带都会让这处跳变试不出来。

### 偏离

- **方案怎么说**：[`prd-extensible-lists`](./prd.md) 的 `US-005` 写「12 件宝物，**每件**各带一个特殊光环」。
- **实际怎么做**：改成按声明必填，并给基准表加了「各至少一件」。
- **为什么**：见上面那条设计决策 —— 方案那句与本条自己定的「最低那一档是过渡品」互相矛盾，两条不能都成立。

### 权衡

- **考虑过让光环也吃「必带负面」那条校验、即光环自己就要正负各一。** 否决理由：那会让每个光环都要设计一条配套负面，而负面的额度一件宝物只需要一份 —— 它已经落在副词条上了。现在的写法是**光环可以是纯正面，但那件宝物整体不许没有负面项**。
- **考虑过为光环新开一档载体分类。** 否决理由：「改判定」在[`状态效果系统`](../../../design/状态效果系统.md)那三类里本来就属参数类（它不动动作机），所以不需要第四类 —— 这一条在文档里写明了，否则读者会以为要扩容载体。

### 待确认

- 无。
