# NR-32：救回那条支线分成三档，完美结局认中间那档

> **只读归档 · 历史背景，不是现行依据。** 现行事实在[主线故事 · 三条重要支线](../../../canon/narrative/主线故事.md)与[`主线推进系统`](../../../design/主线推进系统.md)自己身上，对不上时以它们为准。

## 目标

一个把其他条件都做到的玩家，无论推主线推得多快，都拿得到完美结局；而「真把人救活」另有一份回报。

## 来源

PRD：`spec/prd-narrative-repair-and-cast.md` 的 `US-004`。

立项理由：[主线故事 · 三条重要支线](../../../canon/narrative/主线故事.md)自己写着「拿一个他控制得了的时点去结算一条他控制不了的进度，等于把全部风险摊给玩家，而本作不施加这种隐形惩罚」。那段论证只兑现了一半 —— 它保住了「照护中不被判成失败」，但结局判定读「三条支线全部完成」时，进行中的照样不算完成。于是一个先还清债务、做完穹盾三项改造、压低失衡、刷满关系的玩家，在节点 8 遇到那个人之后一口气推到节点 17（节点解锁不看天数），照护的若干季来不及走完，完美结局落空。

## 依赖

无。它改的判据是 `NR-24` 的输入，所以要在 `NR-24` 写内容之前定。

## 验收标准

- [x] 支线三那一节改成三档：**完成**＝那个人被带回基地且没有死；**完满**＝他真的活过来了；**失败**＝他死了；并写明三档是递进的而不是三个互斥状态
- [x] 完美结局条件二读「完成」那一档，不读「完满」
- [x] 「完成」与「完满」两个词在全库各只有一个意思，没有第三处用法（搜过两个仓加 `.kiro`；支线二那条链用的是「完美完成」，说的是一条链的完成度、不是一个人的状态，两者不同层）
- [x] 「失败必须是可能的结局之一」原封不动成立，且仍只由那个对象死亡触发，仍没有换对象重来的路径
- [x] 完满多一段属于他的戏，方向定为**他第一次能说话**（依据：[世界观 · 外魔与魔化](../../../canon/world/世界观.md)写明失去自主的生命已经无法被沟通）
- [x] 那段戏挂在「他活过来」这件事上，触发条件里没有天数、日期或节点编号（[ADR-0016](../../../decisions/ADR-0016-推进挂在曾经发生过的事上.md)）
- [x] 完满赶在节点 17 之前的话他仍出现在黎明那一幕；晚于那一幕仍有他自己那段戏
- [x] 完满不给任何机制增益 —— 他成为可建立关系的常驻 NPC 就是回报
- [x] [`主线推进系统`](../../../design/主线推进系统.md)跟着改：上游约束那句、支线三那一节、铸造判据那个例子、以及三条验收项。**那一份自己判出要三位标记**（第三档是带否定的条件，而标记只置位不回落），并留了一条载入不变式
- [x] 台账 `NR-24` 的备注跟着改（判据变了）
- [x] 按编号搜**两个仓加 `.kiro`**，没有残留指向旧判据的地方。唯一保留旧说法的是 PRD 里那条上游约束 —— 它记的是立项时的状态，按体裁该保留
