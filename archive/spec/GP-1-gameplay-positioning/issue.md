## 实现笔记

### 设计决策

**全部已写进正典，连同各自的理由。** 见[canon/gameplay/](../../../canon/gameplay/玩法定位.md)；当时的推导过程见 Git 历史。

### 偏离

本轮偏离多，因为 PRD 转 `approved` 之后又讨论了十几轮。**作者主动推翻六处，我自己改了两处结构。**

作者推翻的（均已落正典，PRD 保持快照）：

| 方案怎么说 | 实际怎么做 | 为什么 |
| --- | --- | --- |
| FR-18「一人一天一件事」 | 每角色独立体力，出征与派工共用 | 四项基本属性里本来就有「体力」，学员却没有体力条 —— 那项属性在经营侧是死的 |
| 「一个钱包」 | 每角色独立钱包，含城区 NPC | 物品有归属、钱也该有归属；学员有钱才会去买自己喜欢的东西 |
| 「固定名单，初期剧情全部加入」 | 开局 2–3 人，其余陆续到齐 | 9 人一次到齐，教学关承受不住；陆续到齐还让每次加入本身成为事件 |
| 正典 64px 铁律 | 32px，且阈值收紧 | 角色精灵格定为 32×32；顺带写明「相机放大不增加信息量」 |
| 「主角是学院教官」 | 自购基地的办训者，考教官被拒 | 作者改设定；这让伪装第一次让他付出代价 |
| 「不与学员争战力、数值恒定不变」 | 删除，玩家直接操作主角 | 硬约束放宽，定位改由招式面板承载 |

我做的两处结构性偏离：

- **方案怎么说**：PRD 定稿后走 `/prd-to-spec` 出一份 SPEC 承接 83 条功能需求（我自己提的推荐，作者已批准）。
  **实际怎么做**：**不写 SPEC**，改为写四份 `canon/gameplay/` 正典，PRD §5 收缩成区间索引。
  **为什么**：读完技能规则才发现两条硬理由 —— SPEC 只为「需要架构决策」的需求写，而 `GP-1` 一个架构决策都没有（架构归 `ENG-2`）；且代码仓是空仓，任何代码落点都是编的，硬写就落进技能自列的「复述 PRD」这条常见错误。而 83 条行为的永久住址本来就是正典（归档三问第一条要求的正是这个）。**这个偏离改的是交付物形态，作者当场同意。**

- **方案怎么说**：PRD 的 `## 5. 功能需求` 承载 83 条 `FR-N` 全文。
  **实际怎么做**：删成 13 行区间索引指向正典。
  **为什么**：正典已把每条规则连同理由写了，PRD 那 83 行成了同一批规则的单行复述 —— 我在同一轮里刚警告过「不要造第二份会漂移的副本」，然后自己留了 83 行。**触发点是配额 FAIL，但配额只是症状。**

### 权衡

备选方案与否决理由已随过程叙述删除，见 Git 历史。**最值得留的一条**：掉落物归属我推荐「全归主角」以省操作，被作者否掉 —— 那样学员个人背包就失去意义、所属权系统在战斗侧被完全架空。判据错了，不是结论错了。

### 待确认

- [ ] **`GP-2` 的六个数字**，尤其「19 游戏小时能装多少事」（浇水、走路、一次出征、读书各占多久）与「至少一种作物生长周期 ≤ 4 天」。前者是所有时间决策的基准，后者不满足则前期现金流断。清单见[推演 §6](./推演.md)。
- [ ] **中文像素字体的授权未核实**：方舟像素字体、缝合像素字体、Zpix 三款的授权本轮**没有确认**，只确认了 Cubic 11 是 SIL OFL。点点像素是 GPL 2.0，商业发行须慎用。核实归 `ART-2`。
- [ ] **10px 中文像素字的实机可读性未实测。** 分辨率下限的推算按 12px 做的，若 10px 可用则 320×180 可能重回候选。
- [ ] **Fray 与 animated-shape-2d 能否用于 Godot 4.7.2 未实测**，且 Fray 是 GDScript 插件、从 C# 调用要走互操作。评估归 `ENG-6`。
- [ ] **导出后 `res://` 只读、mod 需走可写路径这条未实测**，它决定 mod 目录放哪，放错改起来贵。验证归 `ENG-2`。
- [ ] **「好不好玩」只能实机确认。** 这是本轮做完全部功夫仍无法在文档阶段判定的唯一一件事 —— 检查器与纸面推演都判不了。
