# GP-40：委托生命周期的两步进每日结算，并封三处边界

> **只读历史归档，不得作为现行依据。** 现行事实在[时间与经营 · 结算顺序（固定，不得改动）](../../../canon/gameplay/时间与经营.md)（委托超期作废与委托板补满各一步，先作废后补满）与[战斗与关卡 · 委托只是任务的一类](../../../canon/gameplay/战斗与关卡.md)（主线不占额度也无截止、一次出征只结一条、个人请求无失败、「采集」是总称不是技能名）。状态在[待办台账](../../../spec/issues/README.md)，不在本文。

## 目标

让一条委托从上板到作废的每个时点都真的会发生，而不是靠某个系统顺手做掉；同时把「主线算不算额度」「一次出征结几条」「个人请求算不算任务」这三处正典没接上的地方封掉。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-001`
- 起因：[时间与经营 · 结算顺序（固定，不得改动）](../../../canon/gameplay/时间与经营.md)那张表里**没有委托超期与委托板补满这两步**，而[战斗与关卡 · 委托与关卡](../../../canon/gameplay/战斗与关卡.md)写着「每日补满至固定条数」与「每条 3 天内截止」—— 两件按天发生的事都没有执行体。

## 依赖

无。**它是本批其余各条的用词与时点前提** —— 任务系统的接口表要按步名引这两步，先按「还没有这一步」写完再回头改是两次工。

## 验收标准

- [x] [时间与经营 · 结算顺序（固定，不得改动）](../../../canon/gameplay/时间与经营.md)加入**委托超期作废**与**委托板补满**两步，写明相对顺序是**先作废、后补满**，理由是过期的还占着板上位置时补满会少补。
- [x] 同一节写明硬约束：两步都排在**季节更替判定**之后、**生成结算摘要**之前；并写明落点选在**债务计息**之后的理由（那之后没有一步读委托，且不动已有那几条约束里的括号编号）。
- [x] 超期作废那一步写明它**同时清两处**：板上没被接取的，以及玩家手上已接取但没去的。
- [x] 补满那一步写明它必须满足[时间与经营 · 货币、钱包与债务](../../../canon/gameplay/时间与经营.md)那条无门槛委托的保底，所以不是纯随机抽取；并写明它**只读季节与主线节点，不读[活跃失衡](../../../canon/world/世界观.md)档位**（理由：正典那条「出征清理不改变失衡总量」正是要把出征与失衡解耦）。
- [x] [战斗与关卡 · 委托与关卡](../../../canon/gameplay/战斗与关卡.md)写明**截止日期从上板那天算起**，接不接都一样；理由是从接取算会让玩家把好委托囤在板上，而「同时最多接 3 条」那条压力就消失了。
- [x] 同一节写明**主线任务不占那 3 条额度、也没有截止**，理由指回正典已有的「不推主线也能一直经营」与「不施加隐形期限」。
- [x] 同一节写明**一次出征只结算一条任务**，出发前选定；理由是档位挂在单条委托上，带两条档位不同的委托进同一张图就没有一致的敌人配置。
- [x] 同一节写明**学生的个人请求也是任务**，但不占额度、没有截止、没有失败结算 —— 拒绝或放着不管都不产生后果，红线指回[人物 · 教师权力、同意与关系红线](../../../canon/characters/人物.md)。
- [x] 同一节写明**「采集」在本作一律是总称**（指出征时在关卡里取资源这件事整体），具体作业各有名字；**它不是一项生活技能的名字**，那张表归 `GP-39`。
- [x] `python tools/check_docs.py` 0 项必须修复。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：那张表标着「固定，不得改动」，而两步必须加进去 —— 加在哪一格，表自己不回答。
- **选择**：排在**债务计息**之后。
- **理由**：硬约束只框住一个区间（都要在**季节更替判定**之后、**生成结算摘要**之前），区间内没有任何依赖能再收窄，所以判据换成「改动面最小」：债务计息之后没有任何一步读委托，而且那一节已有的几条约束里带着括号编号，插在更前面会让它们全部平移。**这个理由要写出来** —— 不写的话，下一个人会以为那个位置有依赖，然后不敢动它。

另一处：**表前那句「四条约束」改成了不带数字的说法。** 加一条约束之后它就是五条，而自计数守卫按「数字词 ＋ 紧随清单」判 —— 改法是删掉数字词，不是把数字改对（`GP-33` 那一批踩过三次）。

### 偏离

- **方案怎么说**：本条只改[时间与经营](../../../canon/gameplay/时间与经营.md)与[战斗与关卡](../../../canon/gameplay/战斗与关卡.md)。
- **实际怎么做**：新写的那一节里刻意**没有**指向 `任务系统` 的链接，正文只写事实；那条链接由 `GP-41` 在自己那一轮补上。
- **为什么**：文档还不存在，链上去就是断链、检查器当场报。而 `GP-41` 本来就要在自己那一轮加正典反向链接（长期规格没有正典引用会被判孤岛），所以这不是把工作往后推，是让本条自己就能跑绿。

第二处：[时间与经营](../../../canon/gameplay/时间与经营.md)那句「委托的 3 天截止按日期计算」后面加了一句指向战斗与关卡的链接。**它说的是「从哪天开始算」，而那个事实的家在战斗与关卡** —— 两处各写一遍就是制造分叉。

### 权衡

「任务与事件的判据」考虑过放进 `任务系统` 而不是正典。取正典，因为它要回答的是「新东西该进哪一边」，而提问的人可能正在写事件那一侧 —— 判据只写在其中一边的系统文档里，另一边的人查不到。

「个人请求算不算任务」考虑过把它划成事件。取任务，因为它有目标与进度（「带三个 X 给我」），按判据就是任务；而它没有失败结算这件事是**红线的结果**，不是它不是任务的证据。
