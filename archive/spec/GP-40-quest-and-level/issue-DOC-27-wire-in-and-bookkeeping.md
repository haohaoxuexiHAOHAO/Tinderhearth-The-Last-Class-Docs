# DOC-27：两份新文档接进索引，本批记账收口

> **只读历史归档，不得作为现行依据。** 现行事实在[系统文档与提案索引](../../../design/README.md)（任务系统与关卡系统两行）与[待办台账](../../../spec/issues/README.md)（各行与「系统深化顺序」）。本条留下一条仍然成立的判据：**条目文件还在 `spec/issues/` 就必须被台账链着**，归档之后才改成纯文本。

## 目标

让 `任务系统` 与 `关卡系统` 从 README 点得到、从台账查得到，而不是孤岛；本批的状态只落在台账一处。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-005`
- 判据来自检查器：系统文档没有正典引用会报孤岛，没接进 [`design/README.md`](../../../design/README.md) 会报「从 README 无法到达」。

## 依赖

`GP-41` 与 `GP-42`（文档要先存在）。

## 验收标准

- [x] [系统文档与提案索引](../../../design/README.md)的系统文档表补两行，各一句话说清它持有什么、不持有什么。
- [x] [待办台账](../../../spec/issues/README.md)本批各行按完成情况改写，备注**不复述**文档里的规则，只留落地顺序与链接。
- [x] [待办台账](../../../spec/issues/README.md)「系统深化顺序」档 1 里「任务与关卡片段拼装」那一项的进度跟着改；档 1 其余项的状态不动。
- [x] `GP-36`、`ENG-16`、`ENG-5` 与 `GP-39` 四行确认引得到本批定下的东西，且各自持有的仍然只是自己那几样未决 —— **不把本批已定的东西复述进去**。
- [x] `ENG-21` 那行确认写明了「片段要作者搭，所以拼装落地排在那条改造之后或与它同批」这层依赖，而不是让它凭空出现。
- [x] 台账每格不超过 360 字符。**往已经超限的格子里继续加就是把 `DOC-17` 记的问题做得更糟** —— 真放不下就拆条目文件。
- [x] `DOC-17` 那条超长格清单核一遍，本批有没有新增或消掉超限的格子。
- [x] `python tools/check_docs.py` 0 项必须修复。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：`GP-41` 与 `GP-42` 的台账行该不该保留指向条目文件的链接 —— 它们的设计已交付，形状看起来该照 `GP-30`／`GP-31`／`GP-32` 那样写成纯文本。
- **选择**：**保留链接**，等本批归档、条目文件移进 `archive/` 之后才改成纯文本。
- **理由**：`GP-30` 那三条之所以不带链接，是因为它们的条目文件**已经在 `archive/` 里**了。条目文件还在 `spec/issues/` 时去掉链接，那份条目就从 README 走不到 —— 这是 `DOC-24` 那一轮被检查器当场抓到过的（一条「从 README.md 无法经链接到达」的提示）。判据因此是：**条目文件还在本目录就必须被台账链着。**

### 偏离

- **方案怎么说**：本条只补 `design/README.md` 两行，加改台账。
- **实际怎么做**：另外改了三行不在清单里的：`ENG-16` 补上「[`关卡系统`](../../../design/关卡系统.md)把宽度一致当接得上的条件，改 48 等于同时改全部片段」，`ENG-5` 的内容类型清单补上关卡片段与资源点，`ENG-21` 补上「`GP-42` 的片段拼装依赖本条」。
- **为什么**：这三条本来就在验收里（「确认引得到本批定下的东西」「`ENG-21` 那行确认写明了依赖」）。写出来是因为它们各自补的都是**依赖方向**，而依赖漏写的后果是实现时排错顺序 —— `ENG-16` 那条尤其：改 48 现在的连带面比原来大了一圈。

### 权衡

`design/README.md` 那两行写得比其他系统文档长。特意的：这两份最容易被误读的地方各有一处 —— 任务那份是「委托跟任务是什么关系」，关卡那份是「为什么不要求接缝对齐」。两处都把「所以」写出来了，而不是只列持有什么。

### 待确认

**一处留给收尾**：台账现在没有 `最高` 优先级的行 —— 本批六条都完成了，而下一批（经济 ＋ 建造）还没开 PRD。「下一件」指哪里由下一轮立项时定，本条不替它决定。
