# NR-11：`design/主线推进系统.md`（含结局判定）

> **只读历史归档，不得作为现行依据。** 现行事实在[`主线推进系统`](../../../design/主线推进系统.md)（结局判定也在那一份），它的故事侧要求在[主线故事](../../../canon/narrative/主线故事.md)。**这个编号还没做完** —— 文档已交付而代码一行都没写，落地顺序与状态在[待办台账](../../../spec/issues/README.md)，不在本文。

## 目标

让「一个节点凭什么解锁、推进状态是哪几样东西、结局判定读什么」只写在一处，而且那一处里**一个天数都没有** —— 推进挂在「曾经发生过的事」上，不挂在日期上。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-001` 与 `US-002`
- 起因：[主线故事 · 二十个主线节点](../../../canon/narrative/主线故事.md)自己明写**解锁条件长什么样还没定**，[玩法定位 · 系统清单](../../../canon/gameplay/玩法定位.md)主线任务那一行同样写着「形状还没定」。而前几批各留了一个口子等它：[`事件系统`](../../../design/事件系统.md)前置条件表里那一格「读推进侧标记」、[`活跃失衡系统`](../../../design/活跃失衡系统.md)那个「归推进侧持有」的只置位标记、[`每日结算系统`](../../../design/每日结算系统.md)那条记账、[`存档系统`](../../../design/存档系统.md)等它声明分片、[`任务系统`](../../../design/任务系统.md)与[`剧情演出系统`](../../../design/剧情演出系统.md)两处「节点解锁不在本页」。
- **`US-001` 与 `US-002` 合成本条**：它们是同一份文档，而「不拆文档」的理由正是「分开会让同一条判据有两个家」—— 拆成两个条目会让同一份文件有两处进度。

## 验收标准

**先答一个结构问题，答案与过程都写进本条的实现笔记：** 推进骨架与「主线任务与结局判定」该写成几份文档。按[`生产系统` · 什么时候拆出去单独成篇](../../../design/生产系统.md)那条判据（**它有没有自己的状态机**）逐样判一遍，并用上第 6 批那条补充（**多读者无主时问它有没有宿主页**）、第 8 批那条（**两样能不能互为宿主**）与上一批那条（**它有宿主页时先问「分出去会不会让同一条判据有两个家」**）—— 不默认拆，也不默认不拆。

### 文档骨架

- [x] 按 [SYSTEM 模板](../../../templates/SYSTEM.md)八节写全，`type: system`、文件名以「系统」结尾、`upstream` 指[主线故事](../../../canon/narrative/主线故事.md)，**并在 `DOC-53` 那一轮就被正典链接到**。
- [x] 标题写成一句结论，不是名词短语。
- [x] 摘要写明它**持有什么**与**不持有什么**，并把最要紧那条承诺放进去。

### 推进状态与节点

- [x] 写明推进状态是哪几样东西，并写明**不用「当前节点索引」**的理由。
- [x] 一条解锁条件只有两类（前置节点已完成、某位标记已置位），**求值器遇到第三类当场报错**、不当成成立。
- [x] **天数一律不进解锁条件**：带天数、日期或季节序号的节点声明**载入被拒**（承重项的反证）。
- [x] 写明「玩家要经历过某件事」怎么表达成一位标记；并给出**要不要新开一位标记的判据** —— 能用「某个节点已完成」表达的就不新开（举得出至少一个按这条判据**不**新开的例子）。
- [x] 节点之间是**有向图**：前置是集合而不是单个前驱。
- [x] **不存「可选」或「必经」字段**（结构约束）：「占编号但不阻塞主链」由图上的可达性算出来。同一处写明这是[`存档系统` · 派生量不单独存](../../../design/存档系统.md)那条通用判据的一次应用，**不是本页新立的规则**。
- [x] 节点可以声明一条**关闭条件**，而它**只许引用「另一个节点已完成」** —— 引用天数的关闭条件载入被拒；同一处写明理由（玩家决定什么时候推那个节点，所以它不是一道会自己走到的期限）。
- [x] 关闭条件与解锁条件**走同一个求值器**，不是第三类条件。
- [x] **「已解锁」是一次求值，不是一份存储**（承重项的反证）：改一位标记再问一次，解锁集合跟着变；没有第二份解锁缓存。
- [x] 一个节点完成**由它派出的那一条主线任务或那一段演出报回来**，本页不实现任何完成判定。
- [x] 节点声明缺任一必填项**当场报错**（[ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md)），每个必填项各一条用例。
- [x] 标记**只能置位**：任何清除标记的输入被拒。

### 长期时间轴与每日结算

- [x] 写明长期时间轴是什么：天、季、年三级只驱动按天到期的东西，推进挂在标记上；**不引入新的时间单位**。
- [x] 写明**推进状态不随游玩时长增长**（各项的上限是接口常量或内容量），并写明它正好答上[`存档系统` · 存档位摘要与体积实测](../../../design/存档系统.md)那笔「无全局日期上限」的体积账。
- [x] **每日结算不为推进加一步**，理由**自己写**、与别处任何一条不同源；同一处写明**不列那份名单**、要查按词搜。
- [x] 那串步序**一个字不复述、一步不增减**；引用某一步时按**步名**引，不写「第 N 步」。

### 结局判定

- [x] 判定时点**写链接不复述**（家在[主线故事 · 结局结构](../../../canon/narrative/主线故事.md)）。
- [x] 判定**只读「曾经达成」**（承重项的反证）：判定之前把失衡拉回阈值之上，结果不变。
- [x] 那几条各写明持有者：失衡那一位**由本页持有**、三条重要支线各自那一位或那几个节点、关系那一条**读当前档位不加标记**且理由指[`人际系统` · 结局判定读当前档位，不需要闩锁](../../../design/人际系统.md)、**不复述**。
- [x] **关系那一侧一位标记都没加**（结构约束）。
- [x] 失衡那一位**只置位、不回落**；本页是[`活跃失衡系统` · 对外只有档位，没有精确值](../../../design/活跃失衡系统.md)那张接口表里登记的总量读者之一，**阈值不在本页、也不新开一行登记**。

- [x] 判定结果**只影响呈现**：两种结局之后世界状态的可操作性完全一致。
- [x] 支线三的失败是可能的结局之一：存在一条「那一位永不置位」的路径，且它不让任何节点卡住。
- [x] 写明**支线三失败之后有一次收束、但没有第二次机会**：后果走已有入口（点播一段演出、往参与者各自的日记里各写一条），**不提供换一个对象重来的路径**。

## 实现笔记

### 设计决策

- **模糊点**：「玩家该经历过某件事」这类叙事前提怎么表达 —— 那份已删的提案当时选的是**天数下限**（它举的例子正是「玩家得先见过一次季节更替」）。
- **选择**：写成一位只置位标记，由那件事的持有者在它真的发生时置位；**天数一律不进解锁条件**。
- **理由**：天数只是那件事的一个**近似值**，而那个近似值会随每季天数改一次就全部漂掉；更硬的一条是它读不出玩家的状态。取舍升成了 [ADR-0016](../../../decisions/ADR-0016-推进挂在曾经发生过的事上.md)。

- **模糊点**：「占编号但不阻塞主链」要不要做成节点上的一格。
- **选择**：不做 —— 它是图上的可达性。
- **理由**：存了就会出现「标着必经但没人依赖它」这种自相矛盾的数据，而**它不报错**。同一处写明这是[`存档系统` · 派生量不单独存](../../../design/存档系统.md)那条通用判据的一次应用，**不是本页新立的规则**。

- **模糊点**：关闭条件（正典对一个节点明写了它）算不算一道截止。
- **选择**：算，除非**只许引用「另一个节点已完成」**。
- **理由**：那个节点什么时候推由玩家自己决定，所以这道门不会自己走到；引用天数的话它就是一道玩家什么都不做也会关上的门。这一条与「不许有截止」是同一件事的两半。

- **模糊点**：结局判定那几位「曾经达成」由谁持有 —— [`活跃失衡系统`](../../../design/活跃失衡系统.md)只说「归推进侧」。
- **选择**：失衡那一位由本页持有并由本页比阈值；关系那一条**读当前档位、一位标记都不加**。
- **理由**：那一份刻意没有任何按时间变的东西，也刻意不持有「曾经」这种语义，而那一位只有结局判定一个读者。关系那一侧的理由在[`人际系统`](../../../design/人际系统.md)自己那里，**本页写链接不复述** —— 抄一遍就是给同一条判据加第二个家。

- **模糊点**：每日结算要不要为推进加一步。
- **选择**：不加。
- **理由**：**置位时刻由因果可见性定，而那个时刻不在一天的末尾。** 推进的每一位都在玩家做完某件事的那一刻成立，挪到当晚会让「我做了什么 → 于是解锁了什么」隔一次睡眠。这条理由是新写的，与别处那几条各不相同；同一处**没有列那份名单**，要查按词搜「不占一步」。

- **模糊点**：文件叫什么。
- **选择**：`主线推进系统`。
- **理由**：「推进」单独用会与结算里的「日期推进」、各步的「进度推进」、任务的「进度」撞名（那几处都写进了「同名不同物」）；加「主线」二字之后它与[主线故事](../../../canon/narrative/主线故事.md)、主线任务对得上。编号用 `NR` 而不是 `GP`：`upstream` 是第 3 级叙事正典，邻居是 `NR-1`，与[`剧情演出系统`](../../../design/剧情演出系统.md)、[`日记系统`](../../../design/日记系统.md)同一路子（机制在玩法侧、内容在叙事侧）。

### 偏离

- **方案怎么说**：PRD 的 `US-001` 把「界面侧那几处硬约束」列在「界面与表现考虑」一节。
- **实际怎么做**：那几条**分散写在本页的「结构」与「接口」里**，各挨着它约束的那个机制，而不是集中一节。
- **为什么**：八节骨架里没有「界面」这一节，而集中写会让它们离被约束的机制很远 —— 例如「关闭前要预警」只有紧挨着关闭条件才读得懂为什么。

- **方案怎么说**：`GP-7` 会多几项（节点解锁的阈值之类）。
- **实际怎么做**：**零个新量**，理由逐样写在「下游同步」。
- **为什么**：解锁条件里没有天数、标记是布尔位，而真有阈值的那两条（失衡、关系）各自的阈值与档位都已经登记在它们自己那一行。**位没有量纲**，所以没有可登记的东西。

### 权衡

**拆成几份文档的判断过程。** 判据取[`生产系统` · 什么时候拆出去单独成篇](../../../design/生产系统.md)那一条（**它有没有自己的状态机**），加第 6 批那条补充（**多读者无主时问它有没有宿主页**）、第 8 批那条（**两样能不能互为宿主**）与上一批那条（**它有宿主页时先问「分出去会不会让同一条判据有两个家」**）：

| 候选 | 有自己的状态机吗 | 有宿主页吗 | 结论 |
| --- | --- | --- | --- |
| 推进骨架与长期时间轴 | **没有** —— 已完成节点是一个只增的集合、标记只置位，而「解锁」是一次求值而不是一个态 | 没有：多读者无主（任务、事件、失衡、结算、存档、演出都在等它） | **单独成篇** |
| 主线任务与结局判定 | 没有 —— 一条主线任务的机器已经在[`任务系统`](../../../design/任务系统.md)，判定只是在一个时点读几位 | **有，就是上一行那一份** | **并进去** |

**并进去的硬理由**：分出去会让「结局判定只读『曾经达成』」这条判据有两个家 —— 一处持有那几位标记，一处读它们。**结论被重判的条件**：如果「结局之后那份说明」将来长成一整套周目结算（星火积分、成就、二周目继承），那一侧会有自己的状态与流转，届时按同一条判据重判。

**「给推进状态加一个『当前节点索引』」考虑过**，它最省存储。没选：索引隐含「节点是一条线」，而有两个节点占编号却不阻塞、最后两个是自主终态 —— 表达这些要在索引旁边挂一堆例外标记，**而那些标记才是真状态**。

**「让解锁读当前值」考虑过**（名册人数、已完成委托数这类，那份已删提案里有）。没选：当前值可能回落，于是「解锁过又没了」要另写规则挡；而且它逼着本页持有一堆阈值，与「只许有下限」直接相冲。

### 待确认

无。本条没有留下待验证的假设 —— 唯一一处推断（代码仓那一域现在没有推进逻辑）已写成「实现前按名再搜一遍确认」，落在「下游同步」里。
