# GP-32：`design/伤害系统.md`

> **只读历史归档，不得作为现行依据。** 现行事实在[`伤害系统`](../../../design/伤害系统.md)。落地顺序按编号活在[待办台账](../../../spec/issues/README.md)。

## 目标

把「一次命中怎么算出一个数字与一条状态」写在一处，加新技能时不用重新发明结算顺序。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-003`
- 现状：代码仓 `rules/Combat/HitResolution.cs` 只产命中反应（击退距离、硬直帧数、顿帧帧数），一点伤害计算都没有 —— 所以结算顺序落地时是新增，不是改写既有行为。

## 依赖

`GP-33`（防御与抗性从哪来、韧性上限这个名字）与 `GP-34`（防御的形状）。本页读它们定下的量，不自己定。

## 验收标准

- [x] 新文档按 [SYSTEM 模板](../../../templates/SYSTEM.md)八节写全，`type: system`、文件名以「系统」结尾、`upstream` 指[战斗与关卡](../../../canon/gameplay/战斗与关卡.md)，并被正典链接到。
- [x] 结算顺序写死 **倍率 → 防御 → 暴击 → 保底 1**，并写明为什么暴击排在减伤之后（排在前面时暴击会被减伤吃掉一部分，「暴击翻多少倍」就随对面防御变，玩家看不懂）。
- [x] 伤害类型只有物理与魔法，**各对一份防御**；防御的边际收益递减。
- [x] 穿透落在防御那一步：物理穿透只减物理防御、法术穿透只减魔法防御，且**穿透后的有效防御不得小于 0**（不做负防御放大）。
- [x] **元素不是伤害类型** —— 它是技能字段，唯一的机制作用是决定这一击尝试施加哪种状态；「弱火」是内容描述用语，机制上读的是灼烧那条状态的抗性，**没有单独的火抗**。
- [x] 状态抗性**按状态各一份、减施加概率**，实际概率钳在 0–100；构造「技能概率 100 对抗性 0」与「技能概率 0 对抗性 100」两个极端，两者都不得产生越界值。
- [x] 两条硬约束写明：**技能的施加概率不得等于或超过 100**、**抗性不得堆到 100**，理由是两头都要留一线（否则要么必中要么免疫，状态这一维就没有博弈）。
- [x] **不做友军伤害** —— 同阵营命中不进结算，一条反证测试。
- [x] 暴击只作用于伤害，**不作用于治疗与屏障量**（否则回血量随机跳动，玩家没法规划）。
- [x] 本页不新建载体也不新建姿态 —— 施加状态调[`状态效果系统`](../../../design/状态效果系统.md)、硬直与失衡的姿态归[`角色动作状态系统`](../../../design/角色动作状态系统.md)；接口表列全挂载点并写明「到此为止」。
- [x] 边界那一节写明本页**不持有**命中判定（横向与纵深两个条件在正典与 `rules/Combat/DepthOverlap.cs`）、不持有打击反馈、不持有伤害数字的显示。
- [x] 文档里一个玩法数值都没有。
- [x] `python tools/check_docs.py` 0 项必须修复。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：伤害与状态是一条线还是两条。裁定只说了结算顺序与抗性各自的形式，没说它们要不要互相影响。
- **选择**：**两条独立的线** —— 伤害被防到最低不代表状态就挂不上，状态被抗掉也不减伤害。
- **理由**：合成一条会长出「打得越疼越容易中毒」这类没人要求的联动，而那等于凭空造一层规则引擎 —— [`状态效果系统`](../../../design/状态效果系统.md)已经为同一个理由否掉过「效果之间互相触发」。

### 偏离

- **方案怎么说**：正典反向链接归 `DOC-19`（「三份文档接进索引与正典」）。
- **实际怎么做**：**本条就把[战斗与关卡 · 异常状态](../../../canon/gameplay/战斗与关卡.md)那条链接加上了**，`DOC-19` 那边只剩 `design/README` 的表、内容规模基准与台账。
- **为什么**：检查器对长期规格有一条「必须被正典链接到」的硬判定 —— 新文档一落地、链接不在，当场 FAIL。攒到 `DOC-19` 会让中间这几条条目都跑不绿，而「每条条目自己就能跑绿」比「链接集中加」重要。`GP-31`／`GP-30` 同办。

### 权衡

穿透取「减目标防御的值」而不是「按比例忽略防御」：防御已经有软化分母管边际递减，再叠一层百分比就有两处递减，说不清「加 10 点穿透值多少」。减值式还天然带一个可读的上界 —— 扣到 0 就到顶。

暴击排在减伤之后：单次伤害算出来与排前面等价，但排前面会让玩家看到的暴击倍数随对面防御浮动，而暴击是最需要一眼看懂的机制。

另外多写了几条本页不做的东西，因为它们都属于「看着小、成本很大」并且容易被以后顺手加进来：**混合伤害类型**（要同时读两份防御，于是「这件装备有没有用」说不清）、**伤害随机浮动**（「这次少了」会有两种解释而玩家只能猜，随机性已由暴击承载）、**背击与部位伤害**（站位已由纵深承载；部位要每个敌人各画一套判定框）。

### 待确认

无。全部裁定来自 PRD 与作者答复，没有新的待定项。
