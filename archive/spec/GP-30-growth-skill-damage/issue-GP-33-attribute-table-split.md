# GP-33：正典属性表改成攻防分离

> **只读历史归档，不得作为现行依据。** 现行事实在[角色与成长 · 四项属性的作用方向](../../../canon/gameplay/角色与成长.md)，约束形式在[数值模型](../../../design/数值模型.md)。

## 目标

让四项属性各自只负责一个方向，堆一项不会同时让角色变强又变耐打；并把防御与抗性的大头明确挂到装备、宝石、天赋与状态上。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-001`，[角色与成长](../../../canon/gameplay/角色与成长.md)那一半
- 现状是[`数值模型`](../../../design/数值模型.md)的派生公式还是「一份攻击力、一份防御」的形状，与伤害分物理魔法两类对不上。

## 依赖

`DOC-18`（用词）。属性名与两条资源名要先定下来，否则这张表要写两遍。

## 验收标准

- [x] [角色与成长 · 四项属性的作用方向](../../../canon/gameplay/角色与成长.md)逐项重写：力量给物理攻击；智力给魔法攻击，并保留 MP 上限与书籍阅读速度；体质给 HP 上限、体力条上限、韧性上限与精力上限；敏捷给移动与攻击速度、暴击与闪避冷却。
- [x] 同一节写明**防御与抗性的大头来自饰品、技能宝石、天赋与状态**，属性只给基底，并写明理由 —— 一项属性既给攻又给防时，堆它的收益是相乘的。
- [x] 写明**两份防御的基底由体质给**，力量与智力一点防御都不给；并写明这不违反攻防分离（那条要挡的是同一项属性既给攻又给防，而体质不给攻）。
- [x] **「受击硬直抗性」改名「韧性上限」**，且写明它就是[`角色动作状态系统` · 受击链：受击 → 失衡 → 击倒 → 起身](../../../design/角色动作状态系统.md)里失衡值要累积到的那个阈值，不是一个独立机制。全库搜不到旧名。
- [x] 魔法攻击写明**同时驱动伤害、屏障与治疗的量** —— 主角靠辅助技立身，他得有理由堆智力；这也是原来「技能强度加成」那一项的去处。
- [x] 写明一条约束形式：**不得出现某一项属性在任何构筑下都严格优于另一项**。体质派生的东西比力量多，而判据 C1 只管战力差总量、看不出「哪一项属性最值」。登记进[`数值模型` · 尚未给值的量，各自写明校准办法](../../../design/数值模型.md)，并写明给值那一轮必须把每点属性的收益各自算出来并接上判据。
- [x] `python tools/check_docs.py` 0 项必须修复。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：正典这一节要不要直接链到 `伤害系统` 与 `成长系统`（伤害类型与派生表的家）。
- **选择**：本条**不加那两条链接**，正文只写事实，链接由 `DOC-19` 统一接。
- **理由**：那两份文档还不存在，链上去就是断链，检查器当场报 —— 而 `DOC-19` 的职责正是「接进索引与正典」。这不是把工作往后推，是让每条条目自己就能跑绿。

### 偏离

- **方案怎么说**：验收只要求四项属性逐项重写。
- **实际怎么做**：顺带把「韧性上限」与失衡值阈值的关系写进了同一节，并往[`数值模型`](../../../design/数值模型.md)的尚未给值表加了「每点属性的收益」那条约束形式。
- **为什么**：改名如果只改名字、不写明它是哪个阈值，读者会以为身上多了一项减伤 —— 那正是旧名「受击硬直抗性」造成的误读，换个名字不写清楚等于没修。约束形式那条同理：体质派生的东西一下子变多，不当场立约束，下一轮给值时没人会想起来。

### 权衡

「防御与抗性的基底挂在哪」考虑过两条路：挂体质，或按等级给而属性完全不碰防御。取前者，因为后者会让同级角色的减伤率相同，判据 C1 的战力差只剩 HP 与攻击撑着，重算后可能掉出 4–6 倍 —— 那是把一个已经成立的判据推到要重新校准的位置，换来的只是「更纯」。

「魔法攻击」与「魔法伤害」考虑过分成两个量（一个管伤害、一个管屏障与治疗的效果量）。取一个，因为没有任何机制去区分它们，而两个标量会让面板多一行玩家分不清的数字。

### 待确认

[`数值模型`](../../../design/数值模型.md)的四项属性表与派生公式还是旧形状（一份攻击力、一份防御），本条只改正典。那一侧归 `GP-35`，它排在三份系统文档之后。
