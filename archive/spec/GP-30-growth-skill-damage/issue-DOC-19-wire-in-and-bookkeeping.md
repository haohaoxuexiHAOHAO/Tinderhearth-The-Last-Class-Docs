# DOC-19：三份系统文档接进索引与正典，连带记账

> **只读历史归档，不得作为现行依据。** 现行事实：三份文档的条目在[系统文档与提案索引](../../../design/README.md)，正典反向链接在[角色与成长](../../../canon/gameplay/角色与成长.md)与[战斗与关卡](../../../canon/gameplay/战斗与关卡.md)，战斗中用道具那一套在[`背包系统`](../../../design/背包系统.md)。

## 目标

让三份新文档从 README 与正典都点得到，并把这一批带出来的、不属于本批的事都记上账。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-007`
- 判据来自检查器：系统文档没有正典引用会报孤岛，没接进 [`design/README.md`](../../../design/README.md) 会报「从 README 无法到达」。

## 依赖

`GP-30`／`GP-31`／`GP-32`（得先有文档才接得进去）。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：「关卡内背包默认落消耗品页、点物品在右侧展开使用／丢弃」这条规则该写在台账的 `UI-13` 备注里，还是写进系统文档。
- **选择**：**写进[`背包系统`](../../../design/背包系统.md)的关卡那一节**，台账那格只留一句「关卡里那一套也归本条，规则在那份」。
- **理由**：台账只该持有**状态**，规则的家是系统文档 —— 这正是本仓「散文只写理由、状态只在台账一处」那条的另一面。写进台账还会立刻撞 360 字符上限，而那个上限本来就是为了逼这种搬迁。

### 偏离

- **方案怎么说**：正典反向链接（角色与成长 → 成长系统／技能系统，战斗与关卡 → 伤害系统）在本条加。
- **实际怎么做**：那三条链接在 `GP-32`／`GP-31`／`GP-30` 各自那一轮就加上了，本条只核了一遍。
- **为什么**：检查器对长期规格有「必须被正典链接到」的硬判定，新文档一落地链接不在就当场 FAIL。攒到本条会让中间三条条目都跑不绿，而「每条条目自己就能跑绿」比「链接集中加」重要。

- **方案怎么说**：`GP-18` 的防御那一段补进它的台账备注。
- **实际怎么做**：**新建了 [`issue-GP-18`](../../../spec/issues/issue-GP-18-actor-state-slices.md)**，把它原有的六步落地顺序与姿态切片一起搬进去，台账那格从 539 字符收到限内。
- **为什么**：我那一句把一个本来就超上限的格子从 435 推到 539 —— 继续往里塞就是把 `DOC-17` 记的问题做得更糟。搬进条目文件是那条记账本来定的改法，顺带把超长格从六格降到四格，`DOC-17` 的清单跟着改了。

### 权衡

`UI-13` 与 `GP-18` 都选**补进既有编号**而不是各开新号：它们是那两条本来就要做的事的细化，开新号会让同一件事有两个入口。区别只在解释放哪 —— `UI-13` 的规则有系统文档可去，`GP-18` 的没有，所以给它建了条目文件。

无。
