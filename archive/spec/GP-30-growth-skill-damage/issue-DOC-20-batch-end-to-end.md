# DOC-20：这一批的端到端与交叉核对

> **只读历史归档，不得作为现行依据。** 核对结论已经落在被核对的那几份文档里，本文只是当时的核对记录。现行事实见[系统文档与提案索引](../../../design/README.md)与两份正典。

## 目标

一条命令看出这一批有没有把某处说法改漏，再人工核一遍机器判不了的那几处。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-008`
- 检查器判不了两份散文对同一件事的描述是否分叉（理由见 [WORKFLOW § 3. 反漂移：事实只许有一个家](../../../WORKFLOW.md)的两条边界），所以交叉核对只能人工做。

## 依赖

- [x] `python tools/check_docs.py` 0 项必须修复（含体裁归位、八节骨架、正典上游、节名引用、断链、编号、入口可达、行尾）。

- [x] 工作区根的 `temp/` 只剩作者原有的三项（`art-inbox`、`gp16-prompt.md`、`README.md`），本批建的临时文件都已删。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：「四处交叉核对」怎么做才不是走个形式。
- **选择**：对每件事**按关键词把全库的出现处列出来，再逐处读一遍是不是同一个说法**，而不是凭印象确认。
- **理由**：检查器判得了断链与节名，判不了两份散文是否分叉 —— 那正是这条只能人工做的原因。不列出处就等于只核了自己记得的那几处。

### 四处交叉核对的结果

| 要核的事 | 出现在哪 | 结论 |
| --- | --- | --- |
| 属性派生出什么 | [角色与成长 · 四项属性的作用方向](../../../canon/gameplay/角色与成长.md)（方向）、[`成长系统`](../../../design/成长系统.md)（派生表，含基底与来源两栏）、[`数值模型`](../../../design/数值模型.md)（公式与参数键） | 三处分工清楚：正典给方向、成长系统给表、数值模型给键与公式。**没有两处定义同一件事** |
| 一次命中怎么算 | [`伤害系统`](../../../design/伤害系统.md)（顺序与理由）、[`数值模型`](../../../design/数值模型.md)（算式） | 「倍率 → 防御 → 暴击 → 保底 1」在两处**逐字一致**；数值模型那份写明「顺序由伤害系统定死，本节只给算式」 |
| 防御与抗性从哪来 | 正典那一节、成长系统派生表、伤害系统、数值模型 | 四处都说「属性只给基底、大头来自饰品／宝石／天赋／状态」，且都点明两份防御的基底读体质。成长系统另写「状态抗性无基底是合法取值」，与正典那条是同一句话的极端情形 |
| 技能占不占槽位 | [战斗与关卡 · 按键与连击](../../../canon/gameplay/战斗与关卡.md)、[角色与成长 · 技能分两类：放出来的动作，与做事的熟练度](../../../canon/gameplay/角色与成长.md)那张表、[`技能系统`](../../../design/技能系统.md) | 三处一致：只有主动技占位（6 个），被动、天赋与光环不占位也不设上限。**这一处原先是自相矛盾的**（正典一边写「主动与被动都占位」、一边写「被动不设上限」），本批已收 |

### 偏离

- **方案怎么说**：本条验收写「`temp/` 为空」。
- **实际怎么做**：改成核「只剩作者原有的三项」。
- **为什么**：`temp/README.md` 是这个目录的约定说明、`art-inbox` 是作者的素材收件箱 —— 它们不是临时文件。判据该是「本批建的临时文件都删了」，写成「为空」会永远勾不上。

### 权衡

无。

### 待确认

无。**表现层不在本条范围** —— 本条核的是文档之间有没有分叉，而画面上好不好看是作者在 Godot 里配参数与素材时的事（[ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md) 的分工），两件事没有依赖关系。把实机项挂进文档批次的验收只会让条目永远勾不满。
