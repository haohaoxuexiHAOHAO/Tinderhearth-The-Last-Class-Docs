# DOC-91：三份样板定风格

> **只读历史归档，不得作为现行依据。** 现行事实就在那三份文档自己身上（[`角色动作状态系统`](../../../design/角色动作状态系统.md)、[`伤害系统`](../../../design/伤害系统.md)、[`成长系统`](../../../design/成长系统.md)）；只列不判的那个入口是 `tools/audit_readability.py`；状态在[待办台账](../../../spec/issues/README.md)。

## 目标

**各代表一种图型**，好让作者一次看到风格全貌：

| 文档 | 它最难读的那一块 | 画什么 |

## 实现笔记

### 设计决策

- **模糊点**：怎么判一个词该进本页术语节还是共用表。凭感觉分，两边都会长歪。
- **选择**：落成 `python tools/audit_readability.py`（只列不判，退出码恒 0），它按份数报「这个词够跨页了，该进共用表」与「这个词两处都有」。
- **理由**：这件事在后面五批里要做二十七遍，而手工量一个词出现在几份里既慢又会漏。**它当场就抓到三处** —— `后摇` 与 `加点` 够跨页却留在本页、`起身与逃生窗` 这个词名在正文里根本不存在。这三处靠人读是发现不了的。

- **模糊点**：`角色动作状态系统` 那张十八行流转表要不要画成一张图。
- **选择**：画两张，一张受击链、一张玩家主动操作的主干。
- **理由**：一张混着画会有十八个节点，而那正是现在这张表读不动的原因。拆成两张之后各答一个问题：一张答「被打之后会依次落到哪几个姿态」，一张答「从站着能进到哪几个动作」。

- **模糊点**：Mermaid 里的标签能不能随便写。
- **选择**：**每个标签都写成本页正文里真实存在的子串。**
- **理由**：`DOC-93` 要加的那条守卫是按子串核对标签。与其到时候给守卫开例外，不如现在就让标签满足它 —— 这反过来也是个好约束：写不出对应正文的标签，通常说明那个节点是图自己发明的。

### 偏离

- **方案怎么说**：PRD 的 `FR-21` 把那个只列不判的入口排在 `DOC-93`。
- **实际怎么做**：本条就把它建了（`tools/audit_readability.py`），并且它同时报术语与句长两项。
- **为什么**：本条与后面五批都要反复用它，而「会做第二次的操作写成 `tools/` 下的 Python 入口」是命令纪律里的硬要求。`DOC-93` 那一条改成在它上面接守卫，不重建。

### 权衡

- **按词类扫了一遍全库 `design/`，代价是动到七份不属于样板的文档。** 起因是作者指出「钳到 0–100」不是中文说法（那是 clamp 直译）。同一类还有两个：「惰性算」（lazy 直译）与「闩锁」（latch 直译）。三类合计在 `design/` 下清空，涉及[`技能系统`](../../../design/技能系统.md)、[`教育系统`](../../../design/教育系统.md)、[`数值模型`](../../../design/数值模型.md)、[`经济系统`](../../../design/经济系统.md)、[`人际系统`](../../../design/人际系统.md)、[`主线推进系统`](../../../design/主线推进系统.md)与[系统文档索引](../../../design/README.md)。**选一次扫完而不是分到五批**，理由是同一个词在库里读两种说法，比读法不好更难查；那七份的其余改造仍归各自批次。
- **「闩锁」那一处顺带还消掉一个同义词。** 它说的就是[`主线推进系统`](../../../design/主线推进系统.md)里那种「只置位的标记」，两个名字指同一件事。改成「另记一笔『曾经到过』」之后，[`人际系统`](../../../design/人际系统.md)那个节名也跟着变了，而引用它的两处由节名守卫盯着 —— 改漏一处会当场报错。
- **`求值` 与 `幂等` 没改，改的是解释。** 它们不是直译腔，是有确切含义的词：`求值` 进了[术语表](../../../reference/术语表.md)（它出现在三份以上）；`幂等` 只在两份里，留给它自己那一页的术语节。**判据是「换个说法会不会丢掉意思」** —— 「钳到」换成「限制在」一点没丢，而「求值」换成「计算」会丢掉「不存结果」那一层。
- **正典里那四处同类没动**（[战斗与关卡](../../../canon/gameplay/战斗与关卡.md)三处、[玩法定位](../../../canon/gameplay/玩法定位.md)一处）。PRD 的非目标写明不动 `canon/`，所以按「超出边界不许顺手修」记成了 `DOC-95`。

- **句长只拆了最长的那几条，没有逐句改写。** 判据是投入产出：最长那几条都是「把一串测试用例塞进一行」，改成子项清单立刻短一半且一个结论不动；而中位数 39 字那一档本来就读得顺。**上限那个数本条不定** —— 它要等二十七份都改完、分布稳定之后再定（`DOC-93`），现在定就是拿一个会变的分布拍数。
- **`伤害系统` 那段 ASCII 图删掉了、没有与 Mermaid 并存。** 两个都留就是同一件事有两个家，而 ASCII 那版还不能被任何守卫检查。
- **三份的旧式直引号顺手改成了全角引号。** 那是格式不是结论，但它出现在被拆的那几句里 —— 拆句时不改，diff 里会留下一半新一半旧。

### 待确认

- **作者实读确认还没做。** 三份是 [`角色动作状态系统`](../../../design/角色动作状态系统.md)、[`伤害系统`](../../../design/伤害系统.md)、[`成长系统`](../../../design/成长系统.md)。要看的是：摘要首段读完知不知道这页答什么、术语表够不够用、四张图有没有帮上忙。风格认可之后 `DOC-92` 才铺开。
