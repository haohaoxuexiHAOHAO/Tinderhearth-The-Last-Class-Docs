# DOC-90：SYSTEM 模板补齐术语节与图的规矩

> **只读历史归档，不得作为现行依据。** 现行事实在 [SYSTEM 模板](../../../templates/SYSTEM.md)（九节骨架、白话导语、图那四条与重画条件的固定形状）与 [ADR-0019](../../../decisions/ADR-0019-系统文档骨架加术语一节.md)；状态在[待办台账](../../../spec/issues/README.md)。

## 实现笔记

### 设计决策

- **模糊点**：PRD 没算到「八节」是写在一份**已接受的 ADR** 里的（[ADR-0010](../../../decisions/ADR-0010-文档体裁与系统文档归位.md) 有一整节就叫「系统文档骨架：八节，顺序固定」），而 [WORKFLOW §4](../../../WORKFLOW.md) 禁止用今天的理由改写已接受的 ADR。
- **选择**：新写 [ADR-0019](../../../decisions/ADR-0019-系统文档骨架加术语一节.md)，只取代那一条；ADR-0010 正文不动，只在文件头加 `superseded_by`。
- **理由**：ADR 链本来就是为「后来推翻前面一条」准备的。绕开它的办法都更贵：改 ADR 正文违反 §4；把节数这条规矩整体搬出 ADR 会削弱全部已接受 ADR 的权威，那是远超本需求的取舍。

- **模糊点**：图的规矩该写在模板哪一节。
- **选择**：写在文首（骨架那几条纪律旁边），不写进「结构」节。
- **理由**：图会出现在「结构」也会出现在「接口」，规矩挂在其中一节就会被另一节的读者漏掉。同时写明「图放在它解释的那一节里、不集中到附录」—— 图离它解释的那段越远越没人看。

- **模糊点**：重画条件那一行长什么样。
- **选择**：`**重画条件**：<什么改动之后要重画>`，紧跟在图后面。
- **理由**：守卫要认得出它，所以形状必须写死；用行首加粗而不是新起一个标题，是因为这一行会在一份文档里出现好几次，而标题重名会让节名引用变歧义。

### 偏离

- **方案怎么说**：PRD 的非目标原写「不动 `canon/`、`decisions/`、`archive/`」。
- **实际怎么做**：`decisions/` 加了一份新 ADR，并给 ADR-0010 的文件头加了一行 `superseded_by`。
- **为什么**：见上面第一条设计决策。PRD 那条非目标已按实际收窄成「只加一份、只改一行文件头，ADR 正文一个字不动」，并经作者确认。

### 权衡

- **模板里的图型对照表没有抄过来。** 它的家是画图技能，而技能在 `.kiro` 里、不在仓库中 —— 所以模板既不复述它也不链接它（链一个不在仓库里的路径会断）。代价：从模板走到图型对照表要靠人知道那个技能存在。换来的是那张表不会有第二份。
- **`装备系统` 与 `界面系统` 里那两句「按八节骨架写」本轮没改。** 它们在两份系统文档的上游约束里，而那两份各自属于 `DOC-92` 的批一与批五 —— 顺手改会让那两批的 `git diff` 里多出与本条无关的改动。改法已经定了：不复述节数、只写「按固定骨架」。
- **模板自己不受骨架守卫管**（检查器对 `is_template` 直接返回），所以模板改成九节不会立刻让三十份报错。这一条正是过渡顺序得以成立的前提，写出来免得以后有人以为守卫漏判了。
