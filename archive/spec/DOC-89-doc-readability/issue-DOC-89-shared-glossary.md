# DOC-89：共用术语表落地

> **只读历史归档，不得作为现行依据。** 现行事实在[术语表](../../../reference/术语表.md)（含收词判据与词条形状）；状态在[待办台账](../../../spec/issues/README.md)。

## 目标

跨页共用的那批自造词有一处能查的地方，并且**每个词只有一个家**。

## 来源

PRD：[`spec/prd-doc-readability.md`](./prd.md) 的 `US-001`。

## 依赖

无。它是本批其余条目的前置 —— 模板要链过来，样板要按它判「这个词归本页还是归共用表」。

## 实现笔记

### 设计决策

- **模糊点**：PRD 只说「跨页共用的词进共用表」，没说**怎么判「跨页」**。判不了就会变成凭感觉收词，而那张表会无限膨胀。
- **选择**：写死成两道判据 —— 出现在 3 份以上系统文档（可机检），且一个没读过本库的人看字面读不出意思（人判）。阈值那个数的家是那一份的「收词判据」一节。
- **理由**：只在一两份里出现的词，通常是「本页与它的直接下游」在共用，不是全库词汇；给它开一个全局条目等于把本该属于那一份的东西搬走。取 3 是因为它是「两份成对」之外的第一个数。

- **模糊点**：领域词条该指到**节**还是指到**文档**。
- **选择**：指到文档。只有定义写得特别分散的才点到节。
- **理由**：节名会改（引用纪律那条守卫存在的原因就是它），而「一个词在哪份文档里定义」是稳定的。指到节能多省读者一次翻页，代价是这张表会跟着别人改标题而失效 —— 换不来。

- **模糊点**：文件叫什么。
- **选择**：`reference/术语表.md`。
- **理由**：原先在 PRD 里写的是「设计术语表」，而「设计」是体裁词 —— [design/README.md](../../../design/README.md) 的命名规则明说名字不带体裁词。守卫只对 `system`／`model` 判后缀，所以这一条不会报错，但**一条自己不遵守的命名规则比没有规则更坏**。

### 偏离

- **方案怎么说**：PRD 的 `US-001` 写「领域词条各有一条指向权威定义那一节的链接」。
- **实际怎么做**：指向那份**文档**，不指向节。
- **为什么**：见上面第二条设计决策。条目的验收标准已按实际做法改写，PRD 那一句留着不动 —— 它是需求侧的意图，偏离记在这里才是这一节的用处。

### 权衡

- **「同名不同物」那张表没有做成词条**，它是交叉索引：同一个词（`失衡`、`档位`）在定义表里已有条目，在那里再出现一次是应该的。所以那一份写明了「词条」只指两张定义表里的行 —— 否则 `DOC-93` 那条「每个词条至少被一份系统文档用到」会不知道自己该扫哪几张表。
- **`只列不判` 被删掉了。** 它是个好词，但逐条量下来它在系统文档里出现 **0** 次（它活在 WORKFLOW 与台账里）。留着就会在 `DOC-93` 那条守卫打开的当天报错 —— 而那时看起来会像守卫写错了。
- **方法论表加了一列「为什么不用大白话代替」。** 多写一列的成本换掉一个反复出现的问题：读者看到解释之后会问「那为什么不直接说『只读查询接口』」，这一列当场答掉。

无。
