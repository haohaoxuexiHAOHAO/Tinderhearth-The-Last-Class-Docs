# GP-54：`design/存档系统.md`（含 `ENG-7` 的容错形状）

> **只读历史归档，不得作为现行依据。** 现行事实在[`存档系统`](../../../design/存档系统.md)（`ENG-7` 的容错形状也在那一份），它的玩法要求在[玩法定位 · 存档](../../../canon/gameplay/玩法定位.md)。**这个编号还没做完** —— 文档已交付而代码一行都没写，落地顺序与状态在[待办台账](../../../spec/issues/README.md)，不在本文。

## 目标

让「一份存档由什么组成、谁决定某个量存在哪一侧、缺内容怎么办」只写在一处，而且那一处**不持有任何字段清单** —— 否则每加一个系统都要回来改它。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-001` 与 `US-002`
- 起因：[玩法定位 · 存档](../../../canon/gameplay/玩法定位.md)把存档的要求写全了，但那些都是**要求**，没有一处说它们各自落在哪。而从第一批到上一批，每一份系统文档的「下游同步」里都写了它给存档加什么 —— 那些声明到本批才齐，所以存档现在写得出来。
- 另一处起因是 `ENG-7`：它一直是一条要求（「不许静默丢数据，也不许崩档」），没有形状。本条把它变成一条可实现的形状，**而它不新开编号**。

## 依赖

`ENG-5`（内容外置那条边界 —— 「悬空引用」的前提是内容按标识引用）。与 [ADR-0015](../../../decisions/ADR-0015-存档的版本与缺字段口径.md)（`GP-57`）、[`每日结算系统`](../../../design/每日结算系统.md)（`GP-56`）、[`统计事件总线系统`](../../../design/统计事件总线系统.md)（`GP-55`）**互相引用，一起验**。

## 验收标准

**先答一个结构问题，答案与过程都写进本条的实现笔记：** 本批三样东西该写成几份文档。按[`生产系统` · 什么时候拆出去单独成篇](../../../design/生产系统.md)那条判据（**它有没有自己的状态机**）逐样判一遍，并用上第 6 批那条补充（**多读者无主时问它有没有宿主页**）与上一批那条（**两样能不能互为宿主**）—— 不默认拆，也不默认不拆。

### 文档骨架

- [x] 按 [SYSTEM 模板](../../../templates/SYSTEM.md)八节写全，`type: system`、文件名以「系统」结尾、`upstream` 指[玩法定位](../../../canon/gameplay/玩法定位.md)，**并在 `DOC-48` 这一轮就被正典链接到**。
- [x] 一级标题写成一句结论，不是名词短语。

### 分片与判据

- [x] **一个分片要声明什么写成一张表**，覆盖分片标识、持有它的系统、进哪一侧、缺字段时补什么；**缺任一必填项在注册时报错**（[ADR-0009](../../../decisions/ADR-0009-编辑器主导的开发模式.md)）。
- [x] 「进哪一侧」**没有「两边都进」这个取值**，并写明为什么（想两边都进的东西其实是两样）。
- [x] **注册是显式的，没有自动发现**，并写明理由（自动发现把「我忘了注册」变成「扫不到」，而那不报错）。
- [x] **本页不持有「一共存了什么」那张清单**，理由写明（两个家、每加一个系统要回改两处）。
- [x] **「一共存了什么」由一个运行时读口回答**，并写明它**不是第二份存储**，形状指[`事件系统` · 持续引导：同一条管道，两条出口](../../../design/事件系统.md)。
- [x] **「进哪一侧」写成一条判据**（跨过一次睡眠还成立的进正式存档），并用既有那几处的结论说明它判得出来，**但不复述那几份里的清单**。
- [x] **正式存档不存玩家位置**，作为那条判据最短的一个例子。
- [x] **续玩点是全量快照、按存档位各一份**，两条各写理由与代价。

### 机制

- [x] **分片之间不许有载入顺序依赖**，配一条反证（任意顺序读出同一结果）。
- [x] **派生量不单独存**（承重项），配一条判得到的反证（改基底之后派生量跟着变），并写明它挡的是哪种实现、那种实现为什么不报错。
- [x] **写入是一次事务**（写临时文件 → 原子替换 → 提交），并写明**不另留玩家读得到的备份**及其理由。
- [x] **格式、版本号层级、缺字段与多字段全指 [ADR-0015](../../../decisions/ADR-0015-存档的版本与缺字段口径.md)**，本页不重写它的理由。
- [x] **存档位摘要在文件最外层**，**不另存索引文件**。
- [x] **体积实测的入口**：写入之后报得出按分片分摊的字节数，并指到[`日记系统`](../../../design/日记系统.md)那个等实测的量。

### `ENG-7` 那一半

- [x] **悬空引用 ＝ 标识解析不到**，并写明这是既有形状而不是本批新加的约定。
- [x] **一条不可用记录说得出四样**，含**缺哪个 mod**；由此**存档里要记「写档时启用了哪些 mod」**，理由指回正典那句「因缺少 mod」。
- [x] **那份清单不是存储**，且**理由与引导清单不同源**（一个是已有集合的读口，一个是一次解析的结果）。
- [x] **玩家选「继续」之后隔离保留、不删除**，配一条反证（装回 mod 之后一件不少）。
- [x] **不可用的东西不参与任何结算与任何计数**，并写明这是隔离能成立的全部依赖。
- [x] **写回时原样写回读不懂的标识**，并写明它是 [ADR-0015](../../../decisions/ADR-0015-存档的版本与缺字段口径.md)那条「多出来的字段丢弃」的唯一例外、两处都写明了。
- [x] **载入不许抛**，配一条反证（含悬空标识的存档载入成功并列出清单）。
- [x] **清单只在出现新的不可用标识时才弹**，那一格存进正式存档，并写明它是本页唯一一个为界面服务的存档字段。
- [x] **缺 mod 与版本降级不是一件事**，两者的处置与理由各写一处。

### 收口

- [x] 边界那一节写明**不持有**：任何系统自己的字段、序列化格式的理由、云同步、成就进度、界面、任何数值；**并写明读档界面不挂手环**及其理由。

## 实现笔记

### 设计决策

- **模糊点**：正式存档与续玩点的字段划分要不要写成一张集中的表。
- **选择**：各系统自己声明，本页只持有机制；「一共存了什么」做成一个运行时读口。
- **理由**：集中表每加一个系统都要回改，于是同一件事有两个家（本页那张表与那个系统自己的声明），而两处不一致时没有任何东西判得出来哪一处过期；而它增长的速度正好等于系统数。「查不到一处」这个缺口用**读口**补而不是用表格补 —— 那是[`事件系统`](../../../design/事件系统.md)那份引导清单已经验过的形状。剩下那个风险（忘了注册）有两个方向的挡法：**存档里出现未注册的分片名时不静默丢**，加一条往返反证。

- **模糊点**：缺 mod 之后玩家选「继续」，那些东西留还是删。
- **选择**：隔离保留 —— 标成不可用，不参与任何结算与计数，写回时原样写回。
- **理由**：正典写的是「不能静默丢数据」，而删掉与静默丢的差别只在有没有弹一次提示 —— **提示过的数据丢失仍然是数据丢失**，而这件事十有八九是误删或临时移走了 mod。隔离的代价（每一处计数入口都要排除它们）**写得成反证**；删掉那个代价写不成反证。

- **模糊点**：续玩点是全局一份还是按存档位各一份，以及它是全量还是增量。
- **选择**：按位各一份，全量快照。
- **理由**：全局一份的失败形态正好是正典写下续玩点这条机制的那个理由本身（退出就白玩）；而「去看一眼另一个档」是玩家会做的事，他做的时候不会预期要付一关的代价。全量让「读续玩点」与「读存档」走同一条路径 —— 一条路径就只有一处会错；增量要回答「基于哪一份」，而那一份可能已经被下一次睡眠覆盖过。

### 偏离

- **方案怎么说**：PRD 的 `US-002` 是一条独立的用户故事。
- **实际怎么做**：它的验收并进本条 —— `ENG-7` 那一半与本页是同一份文档的同一批小节，而台账 `ENG-7` 那一行改写成指落点、**不新开编号也不建第二份条目文件**。
- **为什么**：两份条目文件的勾选框会指向同一批小节，于是进度有两处。**同一件事不新开登记行。**

- **方案怎么说**：`check_docs` 0 FAIL。
- **实际怎么做**：本条单独跑不绿 —— 它指向 [ADR-0015](../../../decisions/ADR-0015-存档的版本与缺字段口径.md)、[`每日结算系统`](../../../design/每日结算系统.md)与[`统计事件总线系统`](../../../design/统计事件总线系统.md)，那三份不在时全是断链；正典反向链接也要等 `DOC-48`。**那条 0 FAIL 是合并之后才成立的。**
- **为什么**：两份以上互相引用的东西不可能各自独立跑绿。

### 权衡

**拆成几份文档的判断过程。** 判据取[`生产系统` · 什么时候拆出去单独成篇](../../../design/生产系统.md)那一条（**它有没有自己的状态机**），加第 6 批那条补充（**多读者无主时问它有没有宿主页**）与上一批那条（**两样能不能互为宿主**）。四样各判一遍：

| 候选 | 有自己的状态机吗 | 有宿主页吗 | 结论 |
| --- | --- | --- | --- |
| 存档 | **有** —— 一次写入是一段有提交点的事务；一次载入还带一个「等玩家决定」的停等态 | **没有**，而且写它的系统最多（每一份都往它注册一块） | 单独成篇 |
| 统计事件总线 | 没有 —— 发一条、转发、结束 | **没有**。成就与统计明确后置；它与存档只在一个问题上相交（而答案是「不算存档字段」），与[`事件系统`](../../../design/事件系统.md)只共用一个词 | 单独成篇 |
| 每日结算 | **有** —— 一段有提交点的事务，而且要回答出错与中断 | **没有**。挂进去的系统很多，没有一份是它天然的家；步序本身在正典，而结构不写进正典 | 单独成篇 |
| 经营侧动作机 | **有**（它就是一台状态机） | **有** —— [`角色动作状态系统`](../../../design/角色动作状态系统.md) | **并进那一份** |

**最后一行看起来违反判据，所以理由要写死**：判据问的是「它会不会撑大宿主页」，而它**有**宿主页时先问的是「分出去会不会让同一条判据有两个家」。经营侧那台机器读的是同一条判据（一次只能一个的归动作机）、共用同一份状态载体、共用同一条接缝与同一对连通性校验，连「劳作读条」这个形状都与战斗侧的采集与用道具是同一个。分出去之后那条判据要在两份文档里各写一遍，而它们迟早不一致。**代价是那一份变长**，而那比让一条判据有两个家便宜。

**「统计事件总线并进存档」考虑过**（它们在「成就进度算不算存档字段」这一个问题上相交）。没选：那个问题的答案恰好是「不算」，所以并进去之后它在那一份里会是一节与存档无关的东西，而十来个发出者要去读一份讲存档的文档。

**「每日结算并进存档」考虑过**（它们在同一时刻发生）。没选：方向是单向的 —— 结算调存档，存档只是它的一步；并进去之后那一份要同时回答「一天怎么推进」与「一份存档长什么样」，而写它的人与读它的人本来是两拨。

**结论被重判的条件**：如果将来存档那一份里的「机制」缩到只剩注册与往返（分片判据上升进正典、版本口径全在 ADR），它就可能小到该并回别处；反过来，如果续玩点长出自己的一套流转（例如「续玩点也分几种」），那时要重看它是不是两样东西。

### 待确认

- **世界状态复制得出来**是[`每日结算系统`](../../../design/每日结算系统.md)对代码提的结构要求，而本页的分片收集也用得上同一件事。两者是不是同一个入口，实现时才看得出来。
- **存档与内容数据要不要共用同一份 JSON 选项**（代码仓 `rules/Foundation/Content/ContentJson.cs` 放行注释与尾逗号，那是给手写文件的）。本页只定「格式与内容数据同一种」，共用不共用是实现时的具体判断。
