# DOC-51：三份系统文档接进索引，本批记账收口

> **只读历史归档，不得作为现行依据。** 现行事实在[系统文档与提案索引](../../../design/README.md)、[ADR 索引](../../../decisions/README.md)与[待办台账](../../../spec/issues/README.md)。**这个编号已完成**，去处见台账的已归档编号表。

## 目标

让本批产出的三份文档从 README 点得到、从台账查得到，而不是孤岛；本批发现的界面欠账有账可查，而状态只落在台账一处。

## 来源

- PRD：[`prd.md`](./prd.md) 的 `US-010`
- 起因：检查器有一条「从 README 出发能否走到每份非归档文档」的判定 —— 不接索引就报提示；而台账里 `ENG-7`、`GP-18` 与「系统深化顺序」那几格写的是本批之前的状态，答完就过期。

## 依赖

## 实现笔记

### 设计决策

- **模糊点**：`ENG-7` 与经营侧动作机要不要各新开一个编号。
- **选择**：都不开 —— 前者改写已有那一行、形状落进[`存档系统`](../../../design/存档系统.md)；后者并进 `GP-18`。
- **理由**：**同一件事不新开登记行。** `ENG-7` 一直是「存档要容忍缺失的 mod 内容」这一件事，本批给了它形状而不是换了一件事；经营侧那台机器与战斗侧共用判据、接缝与两条连通性校验，两个编号会让同一条判据有两处进度。

- **模糊点**：`UI-20` 那一行该装多少 —— 存档位列表、不可用清单、结算摘要、手环里的完整明细看起来是四处不同的界面。
- **选择**：一条，理由写在那一行里。
- **理由**：分工判据沿用 `UI-18`／`UI-19` 那两条的形状 —— **按「它属于哪一批的产出」分，不按「它是几个界面」分**。四处都是本批两份新文档带出来的，而它们共用同一组硬约束（每一处都要说得出「为什么」与「会怎么样」）。

### 偏离

- **方案怎么说**：PRD 的 `US-010` 写「界面侧那一项立项记账」，编号由本轮分配。
- **实际怎么做**：分成 `UI-20`，并且在 PRD 里刻意**没有**写死那个号 —— 写死会让检查器在 `/to-issues` 之前就报「引用了台账里没有的编号」。
- **为什么**：编号分配是 `/to-issues` 这一步的事；PRD 写「取界面域现有最大值往后一个」既准确也不会让中间那个状态跑不绿。**这一条上一批也撞过一次**（形状不同：那次是链接与文件移走的顺序）。

- **方案怎么说**：台账每格 ≤360 字符。
- **实际怎么做**：`DOC-48` 那一行第一稿写到 408，量出来才发现，已把改了哪几处移进条目文件、台账只留链接与那条「结算顺序一字未改」。
- **为什么**：**改完要量一遍，不凭眼估** —— 这一条上一批也是量出来才发现的（`GP-53` 那一格 399）。

### 权衡

**「把三份新文档的索引行写短一点」考虑过**（现在每行都很长）。没选：那张表是从 README 进来的人**唯一的选路依据**，而「它不持有什么」正是选路时最有用的一半。代价是那几行长，但它们在表格里、不影响正文阅读。

**「给本批三份新文档在『系统深化顺序』里各写一格」考虑过。** 没选：那一节回答的是「接下来该深化哪个系统的设计」，而本批三样都已交付 —— 状态回到各编号自己的备注里。**那一节只留分批的理由**，这是上一批就立下的纪律，本批照做（档 2 那一格因此从「除……全部已交付」缩成「全部已交付」）。
