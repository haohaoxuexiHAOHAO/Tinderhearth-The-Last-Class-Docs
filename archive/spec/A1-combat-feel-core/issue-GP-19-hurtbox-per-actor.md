# GP-19：受击框按角色取实测本体，不再一个数套所有人

> **只读历史归档，不得作为现行依据。** 随 A1 归档；文中的验收手段（图形探针与守卫）已全部删除。
> 现行事实见[待办台账](../../../spec/issues/README.md)与代码仓。

## 目标

让每个角色的受击框等于它自己的本体，而不是共用一个写死的高度。

## 来源

作者 2026-09-12 用 `ENG-6` 刚做好的调试叠层实机看，发现主角的受击框明显比画面上的人高，木桩的却贴得准。**这是那把尺子的第一份产出。**

## 依赖

`GP-11`（受击框与命中结算）、`ENG-6`（看得见框才发现得了）。

## 根因

受击框原先是 `Hurtbox` 里写死的 18×**32**，两个角色共用。而 32 是**木桩柱子**的高度：木桩本体确实 32，所以它贴得准；主角实测本体只有 **28**（登记表「角色本体」，各动作 26–30）。

更要紧的是**同一个仓里对「主角多高」有两份真相**：`PlayerActor` 的碰撞框早就绑了实测 28 并写明理由，而受击框那份写死 32。两处不一致**不报错**，只表现为「从头顶 1–4px 掠过的攻击照样命中」——玩家侧读到「我明明躲过了却被打到」，而这种反馈会被归因成「判定不准」。

## 作者裁定（2026-09-12）

- 主角受击框取**站立姿实测 28**，不取各动作最大值 30。「稍微有一点头顶超出是没有什么问题的」——闪避那几帧本来就是主动规避的姿态。
- 木桩的受击框从**它自己的柱子高度**导出，不再各写一个 32。

## 验收标准

- [x] 受击框高度**按角色给**：`Hurtbox.HeightWorldPx` 改成必填 `init` 属性，新角色接进来时编译器逼着调用方回答「它多高」
- [x] 主角的碰撞框与受击框共用一处常量（`PlayerActor.BodyHeightWorldPx = 28`，取登记表实测站立姿），消掉那两份真相
- [x] 木桩的碰撞框、绘制与受击框共用一处常量（`PostHeightWorldPx = 32`），三处相等不再靠人记得
- [x] 判据**逐角色核各自高度**，并钉「两个角色的高度必须不相等」——谁再把它们并成一个数会当场变红
- [ ] 逐帧自适应高度：**明确不做**，理由见下（记录用，不是待办）
- [ ] 按状态分（站立／滞空／闪避／将来的蹲伏）：归 `GP-18`＋`GP-6`，本条不做

## 实现笔记（2026-09-12）

### 设计决策

- **静态、按角色、绑实测值**，而不是逐帧自适应。`ENG-15` 的影子踩过同一形状：整帧不透明边界含四肢，`walk` 的逐帧宽度实测在 11–20px 之间摆（手臂摆动），当时被迫加下限。高度同理会在 26–30 之间脉动，而**受击框脉动会让命中学不会**——同一招有时中有时不中且读不出原因。另一层：按 alpha 量会把伸出去的拳脚也算成可被打的部位，通常不是想要的。
- **必填而不是给默认值。** 给默认值等于把「忘了量」变成静默通过，而这条 issue 的起因正是一个被继承下来的默认值。

### 偏离

- 顺带把 `Hurtbox` 的碰撞形状也改成从 `BoxLocal` 建（原先形状与叠层各写一份几何），几何等价。

### 权衡

- 闪避/重击那几帧本体到 30px，头顶会露出受击框外 2px，那两帧头顶不可被击中。作者已裁定接受；正确的长期形状是按状态给不同高度（`GP-18`）。

### 待确认

- 按状态分的具体形态与数值，等 `GP-18` 的状态机切片推进时定，归 `GP-6` 校准。
