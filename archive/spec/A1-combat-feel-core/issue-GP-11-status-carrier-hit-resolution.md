# GP-11：规则层统一状态载体与命中结算

> **只读历史归档，不得作为现行依据。** 随 A1 归档；文中的验收手段（图形探针与守卫）已全部删除。
> 现行事实见[待办台账](../../../spec/issues/README.md)与代码仓。

## 目标

在规则层建成最小统一状态载体（硬直、无敌）与由攻击轻重决定反应的命中结算，脱离引擎即可单元测试。

## 来源

- PRD：[`A1/prd.md`](./prd.md) 的 `US-003`、`US-004`（**历史背景·非依据**，2026-09-18 归档）
- SPEC：[`A1/spec.md`](./spec.md) 的 §3.1、§4.3、§5、`StatusEffects`、`HitResolution`（**历史背景·非依据**）

## 依赖

`GP-10`——复用 `CombatFeel` 常量与 `MotorState`（无敌窗作为一个状态注册）。落实[玩法定位 · 跨系统约定](../../../canon/gameplay/玩法定位.md)的「统一状态系统现在就成立」。

## 验收标准

- [x] `rules/Combat/StatusEffects.cs`：状态条目带 `StatusKind` 与「可否解除」标志；硬直与无敌两种，A1 均不可解除；帧数每帧递减到 0 自动解除
- [x] `rules/Combat/HitResolution.cs`：`Resolve(轻/重)` → 击退量、硬直帧、顿帧帧数、是否重击（触发震屏），取值来自 `CombatFeel`
- [x] 单元测试：击退量与硬直帧随轻重变化、硬直刷新取新值不叠加、顿帧帧数有限且自解除、无敌与硬直的「可否解除」标志
- [x] `rules/Combat` 不引用 Godot

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。四类都要过一遍，某类没有就写「无」并简要说明。

### 设计决策

- **模糊点**：SPEC 未指定载体逐帧推进归属、顿帧最后一帧返回语义与重复 Begin 的处理。
- **选择**：`MotorState.Statuses` 是角色唯一载体，由 Motor.Tick 开头推进一次；独立载体由角色逻辑拥有者推进。Apply 立即生效，第 N 次 Tick 到期。闪避仅在第 2 帧施加 11 帧，IsInvulnerable 直接查载体，保持 `[2,13)`。调用顺序已补 SPEC §3.3。
- **理由**：集中倒计时消除独立布尔与状态不一致的通道；在施加前递减旧状态，避免新无敌少一帧。只读快照不能修改内部剩余帧；零／负时长拒绝，不能绕过不可解除限制。上述规则有 26 条新增用例覆盖，Combat 从 24 增至 50 条。
- `HitstopTimer.Tick` 消费冻结帧并返回本帧应否冻结，最后一次仍 true；外层时钟必须继续推进。重复 Begin 替换时长，不叠加，非法输入保持原值。Resolve 复用 ComboKind，只接受 Light／Heavy。

### 偏离

- **方案怎么说**：角色各持 MotorState 与状态载体，顿帧计时实现位置只列引擎 Hitstop。
- **实际怎么做**：载体由 MotorState 内建并公开供施加与查询；额外增加纯规则 HitstopTimer，未增加引擎节点。状态载体在零帧时清空有效时长，Get 返回 RemainingFrames=0 的未生效快照。
- **为什么**：由运动机统一推进可维持现有 Tick 签名和已验窗口；纯规则计时用于脱引擎验证有限结束，不替代 GP-13 的冻结执行体。两种固定状态用两个槽位，无逐帧分配。

### 权衡

- 未采用调用方同时 Tick motor 与 status 的方案：能独立编排，但每个调用者都要维护两次调用的顺序；当前选择 Motor 内推进，独立木桩载体仍可单独使用。
- 未采用无敌窗内每帧刷新：会覆盖其他命中施加的时长且掩盖载体是否真的到期；仅窗口起点注册，后续由统一倒计时完成。相同种类不区分来源，按本切片刷新规则覆盖，不提前做多来源叠加系统。
- 不新增通用效果框架或引擎冻结实现；后者属于 GP-13。没有新增可复用排错教训，本轮是明确 GP-11 接口边界。

### 待确认

- 六个反应参数均为 `CombatFeel` 标注的未实测初值：轻／重击退 8／16 世界像素、硬直 10／18 帧、顿帧 3／5 帧；不是 GP-2 平衡量。由 GP-6 在训练房与帧工具可用后实机校准。
- GP-13 需验证外层在冻结期间持续调用 HitstopTimer.Tick 且不推进角色／相机；GP-14 负责完整场景与作者手感确认。本轮未验这些，不推进 GP-12。

### 评审记录

- 目标：两仓未提交改动及新增文件。八维核对：隐藏副作用（状态只属实例）、兼容性（原 Tick 签名不变）、边界（无效枚举、非正／最大时长、首末帧）、性能（Tick 无分配）、安全（无 I/O／外部数据）、命名（击退距离不是速度）、测试（刷新／到期／不可解除／Motor 回归）、维护（复用 ComboKind，无平行无敌字段）。
- 接受并修复：删除布尔赋值遗留的缩进；SPEC 未写推进归属易使引擎重复递减，补 §3.3；ARCHITECTURE 的“状态系统不存在”更新为最小载体已落地。
- 否决扩大到 GP-10 连段／运动其他行为或现在实现引擎冻结：与本条边界无关，原有行为保持。最终无剩余可行动问题。文档对照 PRD／SPEC 原文核对，未把手感或引擎接入写为已验证。
