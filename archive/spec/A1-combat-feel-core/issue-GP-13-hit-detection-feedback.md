# GP-13：引擎层命中检测与打击反馈四件套

> **只读历史归档，不得作为现行依据。** 随 A1 归档；文中的验收手段（图形探针与守卫）已全部删除。
> 现行事实见[待办台账](../../../spec/issues/README.md)与代码仓。

## 目标

引擎层做命中检测与打击反馈四件套，木桩受击有反应但不还手、不死。

## 来源

- PRD：[`A1/prd.md`](./prd.md) 的 `US-004`（**历史背景·非依据**，2026-09-18 归档）
- SPEC：[`A1/spec.md`](./spec.md) 的 §2.2、§5（**历史背景·非依据**）

## 依赖

`GP-12`；屏幕震动复用 `GameCamera.Rig.Shake()` 与 `ShakeEnabled`。

## 验收标准

- [x] 攻击判定框仅在 Active 帧启用；同一次挥击对同一受击框只结算一次
- [x] 命中触发：顿帧（双方与相机一同静止）、受击闪白、击退位移随轻重不同、重击触发屏幕震动
- [x] 屏幕震动经 `ShakeEnabled` 可关，关闭后重击零震动位移（Offset=0，不禁止跟随）
- [x] 木桩受击进入硬直（走 `GP-11` 统一状态载体），不还手、不移动（除击退）、不死、无血条、无伤害数字
- [x] 顿帧期间不接受新输入推进，结束后继续
- [x] 作者实机确认：四件套合起来「打得实」，且顿帧不长到打断连击的输入节奏 —— **作者 2026-09-13 实机确认，「暂时保持这一版」**。确认的是 `GP-20` 强化后的组合（火花＋白闪＋音效＋震屏轻重两档同帧），不是本条当时那个「裸顿帧」版本

## 实现笔记

### 设计决策

- 命中帧先推进旧角色状态、运动与相机，再统一命中并 Begin；随后外层 Tick 返回 true 的 N 帧全部跳过。输入门面继续收事件，不缓存冻结中的短按。引擎探针验证轻3/重5冻结帧、倒计时及状态/动画/位置/相机保持不变。
- `Hitbox` 在 Active 硬门后实时 `IntersectShape`，不依赖刚启用 Area 的重叠缓存；每段 Active 入口清 HashSet，自身受击框排除。实体层与受击层分开。
- 击退为距离：按命中硬直 N 帧匀速消费距离/N，碰撞用 MoveAndCollide；旧状态递减时保留本次应消费位移，第 N 次到期不尾滑。新命中替换时长与剩余位移。
- `CombatFeel` 增闪白6帧与攻击框，均为未校准初值；不消费数值模型。
- **判定框 2026-09-08 按轻重分开**（`ART-6`）：原来共用 28×28，而画面上轻拳在 Active 帧伸到脚底锚点右侧 18px、重拳 22px —— 重击打得更远却同框，读起来就是「重击不实」，且不报错。现取值由 Active 帧的实测伸展导出：轻 18×4、重 22×16，中心距脚底 18（轻重实测都是 17.5，差半像素内）。`Hitbox` 每个 Active 帧按连段类型换尺寸；原来写在 `Hitbox.cs` 里的字面量 −18 搬进 `CombatFeel`，那里才是全部可调手感量的唯一落点（`FR-18`）。**仍是未校准初值，归 `GP-6`**：量出来的是「跟画面对齐」不是「手感对」，轻击框只有 4px 高（作者画的直拳本身就这么高），若实机易打空，要调的是宽容量而不是这条对齐口径。
- **闪白口径定为「由代码持有，动画只提供受击姿态」**（`ART-6`）。代码侧能按轻重分调时长、跟顿帧一同冻结、做成可关的无障碍项，每个新敌人也不必各画一套；一份实证研究（[arXiv 2208.06155](https://arxiv.org/abs/2208.06155)）也把顿帧、音效一致性与相机控制列为**可能**影响最强的三项，闪白不在这一档 —— 所以调优精力放在顿帧与相机。取值依据与原文限定见 [`ART-6`](../../../spec/issues/issue-ART-6-role-action-frames.md)。执行体：进仓精灵表不许出现整帧单色的帧。

### 偏离

- SPEC 草图给双方 Motor；木桩没有自主运动，只持独立 `StatusEffects`，由自身唯一推进，避免虚构完整运动机。
- 不使用 TimeScale：`Hitstop` 包装规则计时器，场景显式推进玩家与相机。`GameCamera.ManualAdvance` 默认 false，旧场景兼容，不新增 Camera2D 派生类。
- 木桩用双色几何，闪白时直接画白色，不把彩色纹理 Modulate 白误当变白。截图像素证明白色与恢复。
- 本条只建 `HitFeedbackDev.tscn` 和 `tools/hit_feedback_dev.py` 体验入口；不是 GP-14 完整训练房，也不完成 ENG-6 选型与帧调优工具。保留 PlayerDev 及 Main 探针链。

### 权衡

- AreaEntered 会漏出招前已重叠，故选实际形状查询。当前单玩家单木桩每 Active 帧查询一次；同屏多敌性能未验证，不提前建立空间索引。
- 关震屏只控制震动偏移，不能冻结正常跟随；相机专项复跑确认默认行为兼容。
- 边界探针直接推进实际规则对象后查询真实物理世界；主路径及新增输入阶段按真实物理帧读取 InputRouter。二者覆盖口径不同，不把全部56项都说成完整输入端到端。
- 补齐两项弱验证：真实轻重命中结束后，在落地、非攻击、零速度的独立阶段主动 Begin(5)，隔离动作锁。跳跃/轻击/重击分别在冻结F1末 deferred按下、F2核按住后末尾松开、F3至F5核松开；五帧均零位移，最后冻结帧剩余0仍不推进。恢复R1及R1至R8逐帧确认落地待机无重放，R8末新按，R9确认起跳或对应攻击，再松开并等待自然回到待机。
- 冲刺阶段F1末 deferred同时按右与冲刺，冻结5帧零位移；恢复每帧核规则横速、引擎横速、实际位移和Dash相位/无无敌。R1速度1040/60、位移1040/3600；R11达到176，R12维持后松冲刺。R13至R15按150→124→104减速且Grounded，R17仍普通移动后松方向，至R22停稳。均经InputRouter与真实MoveAndSlide，不手造CombatInput；这些是现行未校准参数的可重算期望。
- 原34标签保留，新增22标签；日志守卫逐个注入新增标签缺失与FAIL，加原11用例共55/55。未发现运行时缺陷，修复的是验证盲点，未修改冻结所有权或最后冻结帧语义。
- **2026-09-08 再加 6 标签、共 62**：判定框分开之后光看常量不够 —— 常量分开了而 `Hitbox` 忘了按轻重换尺寸，两个数照样各自正确、测试照样全绿，而画面上重击仍打不到远处。所以加**行为级**判据：木桩摆在受击框左沿 21px 处，`light-reach-miss`（轻 18 够不到）与 `heavy-reach-hit`（重 22 刚够到）一正一反，另加 `reach-split-shape` 核两种尺寸真的不同、`reach-split-drained` 保证这一段留下的闪白被清掉（第一版漏了它，表现是 `restored-pixel` 失败而原因与它自己要测的东西无关）。另两条是**前提**判据（`tick-frame-1to1`、`focus-kept`），理由同 `GP-12`。

## 评审结果

目标为代码仓本轮未提交 GP-13 改动及本条/SPEC，保留既有 ENG-14、GP-12 改动。

- 隐藏副作用/兼容性：显式推进默认关闭；GP-12与相机专项复跑通过。无输入绑定或Main链修改。
- 边界/测试：接受「只有首命中不足」发现，补末Active、首Recovery、重新进入、下一挥击、落地取消、墙挡、刷新、无尾滑、闪白恢复像素和持续输入；复跑开关震屏各34/34。
- 性能：Active时小规模查询会分配引擎结果集合，当前单目标范围接受；没有每帧查节点或资源加载。
- 安全：不读存档或mod内容；日志路径来自本地工具环境变量。
- 命名/维护：拒绝照搬不存在的 CurrentWeight/CurrentSwingHitSet；状态推进归属明确，不引第二份载体。
- 文档：对照PRD与SPEC保留未校准、未人工验收和范围限定。没有剩余已接受的可行动问题；不把此结论当实机手感通过。
