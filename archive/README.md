# 历史归档

本目录**只读**。里面的内容记录「当时是怎么做的」，**不得作为现行依据**。

恢复上下文时**不要预读本目录** —— 它会稀释现行事实，而且归档件描述的很多东西（前作的类名、已废弃的流程）在本项目里并不存在。

## 内容

| 路径 | 内容 |
| --- | --- |
| [变更日志归档](./history/变更日志归档.md) | 每个已归档需求一行 |
| `spec/` | 已归档需求的 PRD、SPEC 与 issue 文件，由 `/ship-archive` 移入 |

## 引用规则

正典、专项设计、制作规格与 ADR 引用本目录时，**必须在同一行标注「历史背景·非依据」**。检查器会拦。

索引与工作流文档指向本目录属于导航，不算拿它当依据，不需要标注。

归档件自己也要自证：文件头 `status: archived`，且**文首 20 行内**出现「只读」「历史归档」「已废弃」「不得作为」「非依据」之一。

## 为什么留着而不是直接删

Git 保存了全部历史，所以「删掉归档、需要时翻提交记录」在技术上成立。留着的理由是**检索成本**：翻 Git 历史需要先知道找哪个提交，而变更日志一行就能定位。

代价是归档件可能被误当成现行依据 —— 上面那套标注和检查器就是为此设的。
