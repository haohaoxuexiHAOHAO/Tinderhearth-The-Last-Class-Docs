# ADR-0005：技术基线（Godot 4.7.2 · C# · net10.0）

## 背景

项目从零开始，需要在建工程前定下引擎、语言与目标框架，否则每份文档都得对版本留白。

关键约束来自 .NET 的支持周期：**.NET 8 与 .NET 9 都在 2026-11-10 结束支持**（[微软公告](https://devblogs.microsoft.com/dotnet/dotnet-8-9-end-of-support/)），距本决定不到三个月。.NET 10 是长期支持（Long Term Support，简称 LTS）版本，支持到 2028-11（[生命周期表](https://learn.microsoft.com/en-us/dotnet/core/releases-and-support/)）。

本决定作出时的本机实测情况（2026-08-25，复跑 `python tools/setup_godot.py --check` 可得当前工具链状态）：`dotnet --list-sdks` 只有 `10.0.301`；`dotnet --list-runtimes` 有 3.1.8、7.0.20、9.0.5、10.0.9，**没有 8.0**。`D:\godot\4-7\` 下装的是 Godot 4.7-stable 的标准版与 .NET 版，以及两套导出模板；本机已在同日按本决定升到 4.7.2。

前作使用 Godot 4.7 + `net8.0`（游戏工程）与 `net9.0`（测试工程），根命名空间 `Emberfall`。

## 候选

### 引擎版本

1. **沿用 4.7-stable**：本机已装，零成本。但缺 4.7.1 与 4.7.2 的缺陷修复。
2. **升到 4.7.2（采用）**：2026-08-18 发布的第二个 4.7 维护版，39 位贡献者修了 57 个缺陷，官方称与 4.7.1 无已知不兼容（[发布公告](https://godotengine.org/article/maintenance-release-godot-4-7-2/)）。NuGet 上 `Godot.NET.Sdk` 最新稳定版同为 4.7.2。
3. **等 4.8**：目前只有 dev 快照，不适合作为基线。

### 目标框架

1. **`net8.0`**：与前作一致，但两个月后 EOL，且本机没有 8.0 运行时。
2. **`net9.0`**：本机有运行时，但同样 2026-11-10 EOL，属于确定要再迁一次的选择。
3. **`net10.0`（采用）**：唯一还在 LTS 支持期内的选项，本机 SDK 与运行时都具备，可用 C# 14。

## 决策

```
引擎              Godot 4.7.2（.NET 版）
构建 SDK          Godot.NET.Sdk/4.7.2
目标框架          net10.0
语言版本          latest（.NET 10 对应 C# 14）
可空引用          Nullable=enable
根命名空间        Tinderhearth
分支              两个仓库都用 main
```

美术风格为 2D 像素。**逻辑视口分辨率、字号音阶与间距家族本轮明确不定**，等玩法与界面结构确定后立项。

## 后果

- **正面**：基线落在 LTS 上，未来两年不必因支持周期被迫迁移。本机已有的 SDK 与运行时直接可用，不需要额外安装。
- **代价与风险**：**存在一项未验证事实** —— Godot 4.7 自带的编辑器工具链（`GodotTools.deps.json`）面向 `.NETCoreApp v8.0`。`net10.0` 的游戏程序集能否被 4.7 的运行时与**导出模板**正常加载，本决定作出时**没有实测证据**，官方文档与社区检索也未给出权威结论。这条按 [WORKFLOW §7](../WORKFLOW.md)「结论必须有依据」明确标为推断。
- **落地要求**：`ENG-1` 是建 Godot 工程后的**第一件事** —— 跑一次 `--export-release` 加冒烟验证。导出退出码不可信，必须另行校验产物文件确实生成。
- **回退方案**：若 4.7 导出模板不支持 `net10.0`，回退 `net9.0`，更新本 ADR，并在[待办台账](../spec/issues/README.md)记一条“11 月前迁到 net10”。
- **验证方法**：见 `ENG-1`。在它通过之前，`STATUS §3` 必须保留“尚未实测”的标注。
