# 架构决策记录（ADR）

ADR 是“架构决策记录”（Architecture Decision Record）的缩写，用来保存影响多个系统、难以逆转或容易反复争论的决定。**产品与工程决定都放在本目录，代码仓库不另设决策目录。**

已接受的 ADR 要保留“当时为什么这样决定”。后续复核可以补充现行效力和落地状态，但不能用今天的理由改写当时的背景；新的取舍与旧决定冲突时，应新建 ADR 并明确写出取代关系。

| [ADR-0011](./ADR-0011-纯增益装备的窄例外.md) | 已接受 | 正典那句「装备必带正负面」开一个窄例外：**纯增益只对宝物开、只从变异品质与剧情给予出、且不可叠装**（定义必须带唯一性标记，缺了载入被拒）。三条边界缺一条例外就不安全 —— 它与同批的「同一件宝物可以装多件」叠起来正好兑现被推翻那句的理由。宝石没有这个例外 |
| [ADR-0012](./ADR-0012-宝石的两个镶嵌目标.md) | 已接受 | 宝石定义声明**属性侧**与**机制侧**，填了哪侧才能进对应的孔（宝物孔给属性、技能孔改机制），缺那侧就被拒、两侧都不填载入被拒 —— 分类由声明推出来，不是另一条字段。「宝石孔」因此分成**宝物孔**与**技能孔**两个名字。`技能系统` 那条「改机制」判据一个字不改，改的是分工的措辞：从「词条 vs 宝石」改成按孔的种类分 |
| [ADR-0013](./ADR-0013-战斗片段就是一屏.md) | 已接受 | **一个战斗片段就是恰好一屏**；这一屏还有活着的敌人时**往前的转场被拒，往回与撤离照常可用**（打不过的房间要退得出来）；**战斗片段内相机不平移**，非战斗片段照常跟随。依据是正典那笔纵深几何账本来就按一屏的宽度算 —— 本决定把那个假定写成规则。敌人预算由此有了单位，代价是「绕开整个房间」不成立、正典「不用清空全部敌人」那条的**理由**要重说（结论不变，剩下的意思是不要求走遍全部分支）。被放弃的是 arena lock 与软门 |
| [ADR-0014](./ADR-0014-对话是演出脚本的一类指令.md) | 已接受 | **一段剧情演出是一串按顺序推进的指令，正式对话是其中一类**（说话者、文本键、可选的选项表，每个选项各带一个跳转）；**只含对话指令的脚本就是一次纯对话**，所以「与 NPC 交谈」不需要自己的机制。**气泡不共用这份格式** —— 判据落在「接不接管输入」上，这条把正典那句「不要合成一个系统」落成了位置上的分隔。收益是跳过、快进、存档字段、统计事件与本地化都只做一遍，代价是一条最简单的对话会带着几个用不到的可选字段。被放弃的是两份格式（可嵌与不互嵌）与「气泡也并进来」；后者直接与正典冲突 |
| [ADR-0015](./ADR-0015-存档的版本与缺字段口径.md) | 已接受 | 存档**格式是明文**、**版本号全存档只有一个**且放在最外层、**只增不减**。缺字段**按版本分两条**：版本旧的按分片声明的默认值补，**同版本缺字段报错**，比当前新的**显式拒绝**；多出来的**字段**丢弃，而整个不认识的**分片**不许丢。它与 [ADR-0009](./ADR-0009-编辑器主导的开发模式.md) 那条「代码不留能用的默认值」为什么可以不同源，理由落在**谁修得了**上 —— 场景缺配置是作者当场能改的失误，旧存档在玩家硬盘上没有人修得了。承重项是那半句「同版本缺字段报错」。被放弃的是缺字段一律报错、一律补默认值、每分片各带一个版本号、多出来的字段原样保留 |
| [ADR-0016](./ADR-0016-推进挂在曾经发生过的事上.md) | 已接受 | **主线推进挂在「曾经发生过的事」上，不挂日期。** 解锁条件只有两类（前置节点已完成、某位标记已置位），**天数、日期与季节序号一律不进**，求值器遇到第三类当场报错；**关闭条件只许引用「另一个节点已完成」**，所以那道门不会自己走到。「玩家该经历过某件事」一律写成一位只置位的布尔标记，由那件事的持有者在它真的发生的那一刻置位。适用范围只是推进 —— 委托的截止、考试的季末年末与按天状态照旧按日期走。承重项是那半句「天数一律不进解锁条件」，反证是带天数的节点声明载入被拒。被放弃的是按年份或天数排期、在两类之外再留一条天数下限（那份已删的旧提案当时选的路）、以及让解锁读会回落的当前值 |
| [ADR-0017](./ADR-0017-版本更新对旧存档的两种后果.md) | 已接受 | **一次版本更新对旧存档只有两种后果：兼容，或者要求重开档**，判据是这一版改的是内容还是结构。**追加内容一律兼容**（存的是标识，旧存档读不到新标识就等于没有它），所以正典那句「追加内容不得破坏旧存档」是这条判据的后果而不是一句愿望；只有规则结构的改动才**可能**要求重开档，而且**能迁就必须迁**（承重项）。闸门是游戏这一侧一个**只增的「最低兼容存档版本」常量**，它是**规则常量不是配置项**（mod 改不了它）；**[ADR-0015](./ADR-0015-存档的版本与缺字段口径.md) 一个字不改** —— 本决定只在它前面加了一道更粗的闸。拒绝时指向游戏内一处**随包带、不联网**的更新公告。被放弃的是「存档永远打得开」、每分片各带一个可读起点、运行时试着迁、把那个常量做成配置项、公告联网拉 |
| [ADR-0018](./ADR-0018-内容定义按声明扩展.md) | 已接受 | **一个内容定义只有一张表，每个条目自己声明它有哪几项能力**，每一项按三种必填级别落位（全体必填／按声明必填／随用途必填）；**「它没声明这项能力」与「它漏填了」必须分得出来**，前者合法后者报错。它把已经应用过四次的同一条判据收成一个家（动作集按角色声明、敌人分级面板是子集、宝石按声明进孔、专长轴按技能声明），那四处**一个字不改**。**只约束数据的形状，不约束代码怎么建模。** 被放弃的是按类型分叉，三条代价：类型会打架而打架不报错（夙渊、望渚各是一例）、类型数是乘法、以及 **mod 加不了子类**（承重，直接违反正典给 mod 的承诺）|

| [ADR-0019](./ADR-0019-系统文档骨架加术语一节.md) | 已接受 | 系统文档与跨系统模型的骨架**加一节「术语」**，排在「摘要」之后、「上游约束」之前；那一节**只列只有本页在用的词**，跨页共用的归[术语表](../reference/术语表.md)，两处不许都有。起因是实测「全库没有一处说过 `判据`、`载体`、`读口` 这些词是什么」。**本 ADR 只取代 [ADR-0010](./ADR-0010-文档体裁与系统文档归位.md) 的骨架那一条**，那份的其余三条结论与正文一个字不动。被放弃的是做成「摘要」节内的三级标题（省事但藏起来，与「查得快」这个目标相反）、每个词就地解释（同一个词多份说法而机器查不出分叉）、专属词也塞进共用表（那张表会变成垃圾桶）、以及把节数这条规矩整体搬出 ADR（那会削弱全部十八份 ADR 的权威，远超本需求）|

前四份的决定内容继承自前作《火种》的同类 ADR（原编号 0001／0002／0007／0009），因为那些取舍是纯工程性的、与具体游戏无关，本项目不必从零重踩。背景段落已按本项目的实际情况重写，不照抄前作叙述。
