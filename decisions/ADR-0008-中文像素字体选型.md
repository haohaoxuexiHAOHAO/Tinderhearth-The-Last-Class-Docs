# ADR-0008：中文像素字体选型（缝合像素字体 12px，不做子集化）

## 背景

`ART-2` 要选中文像素字体。它跨四处：**界面**（字号决定逻辑分辨率的下限）、**美术**（字宽与行高必须落在像素网格上）、**本地化**（字形覆盖决定哪些字能显示）、**发行合规**（授权决定能不能卖）。一旦铺开就难换 —— 换字号等于重排全部界面，所以按 [WORKFLOW §1](../WORKFLOW.md) 走 ADR 而不是直接实现。

`UI-1` 卡在本条：[玩法定位 · 分辨率的下限由中文可读性决定](../canon/gameplay/玩法定位.md)那张推算表是按 12px 估的，10px 的实机可读性从未实测，而「10px 能不能用」会决定 320×180 是否重回候选。

不作决定的后果不是停工，是**先做起来再说**：随便挑一款开始画界面，等到发行前才发现授权不许商用或缺常用字，那时界面已经按它的字宽排好了。

本轮实测推翻了两条凭印象的判断，这也是「结论必须有依据」在本条的具体形态：

- 台账原先把 **Zpix 最像素**列为候选。实读它的授权声明：个人与教育免费，**单个商业产品 USD $1000／RMB ￥7000**，且**所有授权档位**都禁止修改、转换、拆分。
- 台账原先把 **方舟像素字体**写成「作者写明面向游戏开发」。实读它的 README：作者自己挂了 WARNING 说仍缺大量汉字、8／10／12px 建议改用缝合像素字体。实测印证 —— 方舟 12px 对设计仓语料缺 60 个字，其中有**势、即、奖、恋、姿、嵌**这类常用字；10px 连代码仓现有那点脚手架文本都只覆盖 66.67%；16px 只有 99 个汉字码位。

另有一条只在深挖时才看得见：缝合像素字体 README 指向的上游许可证 `assets/fonts/misaki/LICENSE.txt` 在当前 master 里**已不存在**（实际文件叫 `misaki.txt`）。只读顶层 LICENSE 会漏掉整条字形来源链。

## 候选

先按授权筛，再按覆盖筛。覆盖数字全部由 `python tools/audit_fonts.py` 于 2026-08-30 实测（自解 `cmap`，不依赖 fontTools），语料五份：GB2312 汉字 6763 个、GBK 汉字 20923 个、设计仓语料 1688 个（本仓 39 份 `.md` 里出现过的全部汉字）、中文标点 54 个、**代码仓游戏文本 57 个**（`data/text` 下外置文本里的汉字 —— 真正会渲染给玩家看的那批）。

| 候选 | 许可证 | 汉字码位 | GB2312 | 设计仓语料 | 游戏文本 | 否决理由 |
| --- | --- | --- | --- | --- | --- | --- |
| Zpix 最像素 | **非开源**，商业逐产品付费 | 21998（作者自述） | 未量 | 未量 | 未量 | 授权即出局，且禁止拆分＝子集化做不了 |
| 点点像素 | **GPL 2.0** | 22000+（作者自述） | 未量 | 未量 | 未量 | 闭源商业发行不可接受 |
| 方舟像素字体 12px | SIL OFL 1.1 | 19779 | 92.84% | 96.45% | 100% | **缺常用字**（势、即、奖、恋） |
| 方舟像素字体 10px | SIL OFL 1.1 | 1085 | 10.65% | 24.70% | **66.67%** | 连现有脚手架文本都渲染不全 |
| 方舟像素字体 16px | SIL OFL 1.1 | 99 | 1.12% | 3.14% | **12.28%** | 同上，更差 |
| Cubic 11 | SIL OFL 1.1 | 9201 | 77.35% | 99.29% | 100% | 繁体导向；**汉字宽 13px** 不合 16 网格 |
| **缝合像素字体 12px** | SIL OFL 1.1 | **20694** | 97.86% | 99.64% | 100% | 采用 |
| 缝合像素字体 10px | SIL OFL 1.1 | 10570 | 86.90% | 99.59% | 100% | 备选，本轮不启用 |
| 缝合像素字体 8px | SIL OFL 1.1 | 14717 | **100%** | 100% | 100% | 备选，本轮不启用 |

「设计仓语料」这一列会随文案增长而变，上表是语料 1688 字时的实测。选定款在这一列缺的 6 个字正是**本文引用的** 劐唣嗍垡墚墼 —— 说明字体缺哪些字就得把那些字写出来，所以这一列只作报告，不当判据（见「验证方法」）。

两条反直觉的实测结果，记下来免得将来重推一遍：**8px 的 GB2312 覆盖比 10px 和 12px 都全**（它的字形来自美咲＋美績＋精品點陣體，那几款本就按 JIS／GB 全集做）；**Cubic 11 的汉字宽是 13px**，压不进 16px 基础单位的网格，界面对齐会一直别扭。

点点像素的字形派生自文泉驿点阵宋体（GPL 2.0）。**未核实**它的上游是否带字体嵌入例外 —— 但派生方自己只声明 GPL 2.0、没提例外，据以判断就够了，所以不再往上查。要推翻这条得先读 wenq.org 的授权页并确认例外条款能传递到派生作品。

### 字号

10px 与 12px 的差别不是覆盖（都够）而是可读性，而可读性只能人判。作者 2026-08-30 在临时对比工程里实机看过 320×180／480×270／640×360 三档 × 四款字体，结论：**12px 最好，10px 不启用。**

### 字库子集化

1. **做静态子集化。** 用 `pyftsubset` 只留用到的字，6.83 MB 可压到约 0.6 MB。
2. **不做（采用）。** 理由不是省事：代码仓 `ARCHITECTURE.md` 定了 mod 放 `user://mods/<名字>/` 并对文本**逐键合并**，也就是**运行时会出现我们没见过的汉字**；`ENG-5` 还写明将来联机时玩家用自定义角色（名字由玩家输入）。静态子集化把这两条变成静默豆腐块，而省下的 6 MB 对 Steam 的 PC 端买断制发行没有意义。

## 决策

```
主字体          缝合像素字体 12px 比例模式 简体版
文件            fusion-pixel-12px-proportional-zh_hans.ttf
版本            2026.08.11（钉死；上游发新版要重跑审计再换）
体积            6,995,400 字节
sha256          5f43f090748d2ee00792d942a1257f44723b807b5cfefa133a856a3a0c5ff702
许可证          SIL OFL 1.1（上游七环全部核过，见下）
字号            12（＝设计尺寸，不得非整数缩放）
实测度量        汉字宽 12｜西文宽 8｜行高 16｜ascent 13｜descent 3
字库子集化      不做
系统字体回退    关闭
```

**宽度模式取「比例」而不是「等宽」**，依上游 README 的建议：等宽模式行高有限、基线偏高，中西文混排时西文重心偏高。汉字在两种模式下都是全宽 12px，所以取比例不影响网格对齐，只让西文更紧。

Godot 4.7.2 的像素完美渲染配置，十项**全部实测存在并已设上**（2026-08-30，`FontFile` 属性表逐项探过）：

| 属性 | 值 | 为什么 |
| --- | --- | --- |
| `antialiasing` | `FONT_ANTIALIASING_NONE` | 抗锯齿会造出半透明像素，违反[像素绘制原则 §9](../production/像素绘制原则.md) |
| `hinting` | `HINTING_NONE` | 字形本来就在整数网格上，hinting 只会挪动它 |
| `subpixel_positioning` | `SUBPIXEL_POSITIONING_DISABLED` | 半像素定位＝糊边 |
| `multichannel_signed_distance_field` | `false` | MSDF 是为任意缩放做的，与像素风相反 |
| `generate_mipmaps` | `false` | 同上 |
| `force_autohinter` | `false` | 同 hinting |
| `disable_embedded_bitmaps` | `true` | 只用轮廓，行为可预测 |
| `keep_rounding_remainders` | `false` | 字宽本来是整数，不需要余量累计 |
| `oversampling` | `1.0` | 任何过采样都会引入非整数缩放 |
| `allow_system_fallback` | **`false`** | **有意让缺字显成豆腐块**：开着会悄悄换成系统中文字体，像素风当场破掉，而且不同机器表现不同 |

工程侧只有一条是本条要求的：`rendering/textures/canvas_textures/default_texture_filter = 0`（最近邻）。

**明确不包含：**

- **逻辑分辨率与界面结构** —— `UI-1`。本条只给它三条输入（见「落地要求」）。
- **界面色彩、尺寸与放置清单** —— `DOC-2`。临时对比工程里那套暖炭配色是占位值，不是色板结论。
- **繁体与日文版本的字形版本选择** —— 本作只发简体。缝合像素字体同一套 `cmap` 提供五个字形版本（`zh_hans`／`zh_hant`／`ja`／`ko`／`latin`），覆盖率完全相同，届时换文件即可，不必重选字体。
- **字体资源进代码仓、主题接线与实际排版** —— 跟着 `UI-1` 落地。本条刻意不把 7 MB 的字体先塞进仓：字号虽已定，但要不要同时上第二档、放哪个目录，都取决于 `UI-1` 的界面结构。

## 后果

**正面影响**

- 授权这一层不再是印象。五款的官方许可证原文全部落成可重跑的判定：内容 SHA256 钉死、据以下结论的关键句逐条比对，上游改条款会当场报出来。
- 入选款的字形来源逐环有据：七环里六环 SIL OFL 1.1（方舟像素、美績点陣體、精品點陣體 7×7 与 9×9、Cubic 11、Galmuri），一环是美咲フォント的全权限自由授权（原文明示可商用、可改）。**链上没有 GPL，也没有「基于某款商用字体改造」。**
- 字号定了，`UI-1` 与 `DOC-2` 的阻塞解除。
- 像素完美不再靠目测：字宽与行高都是实测整数（12／16），不整数就说明配置错了。

**代价与风险**

- **体积 6.83 MB**，单文件。不做子集化是有意的取舍，代价明摆着。
- **缺 145 个 GB2312 生僻字、1771 个 GBK 字**。设计仓语料全覆盖，但 mod 文本与玩家自定义名字可能撞上缺字，表现是豆腐块。这是**关掉系统回退换来的**：宁可显豆腐块也不要在玩家机器上悄悄换成微软雅黑。缺字发生时的补法是给字体加 `fallbacks` 链而不是打开系统回退。
- **缝合像素字体是补丁式方案**，上游 README 自己写明「不应对语言特定字形抱有特别期待」。也就是说不同来源的字形风格不完全统一，这在 12px 下多数人看不出，但审图时可能撞到个别别扭的字。
- **上游仍在活跃开发**（方舟像素是它的基础字形来源，而方舟自己承认缺字）。好处是覆盖会变好，代价是升级版本要重跑审计，且字形可能微调。版本已钉死，不自动跟随。
- **未验证（一）**：本轮的渲染配置与度量是在 `temp/` 的**临时 GDScript 工程**里、用 `stretch/mode="viewport"` 实测的，**没有在代码仓的 C# 工程与导出产物里验过**。字体光栅化不经过 C#，所以证据可迁移；但「导出后 `.pck` 里的字体能正常加载」属于另一件事。回退方案：若导出后加载异常，改用 Godot 的字体导入管线（`.import` 生成 `.fontdata`）而不是运行时 `load_dynamic_font`，配置项名称一致。

  **2026-08-30 复核（`UI-4`）：拉伸模式那一半已验，结论成立且承重项与当时的推测不同。** 工程用的是 `canvas_items` 而非 `viewport`，实测 12px 中文在 ×2／×3／×4 下最小同色跑长恰为 2／3／4 —— 字形整块摊开，是块状。**真正承重的是最近邻纹理过滤，不是 `oversampling`。** 两次反证：不钉 `oversampling=1.0` 时结果逐字节不变；把纹理过滤改成线性则三档的最小跑长全部塌到 1，非背景段数从 7982／15972 涨到 31458／125652（插值出来的渐变像素）。复现：`python tools/font_preview.py --measure --canvas-items`，加 `--linear-filter` 看反证。「导出产物里加载字体」这一半仍未验，跟着字体进代码仓时验。
- **未验证（二）**：只实测了字号 12 本身。放大文字用整数倍字号（24、36）是否同样落在整数网格，**未实测** —— 需要时用同一套办法量一次即可。

**落地要求**

给 `UI-1` 的三条输入：

1. **字号下限 12px。** 320×180 维持排除 —— 12px 下一行 26 个汉字，与玩法定位的估算一致。10px 已实测可用但作者判定不启用，所以它不能用来给 320×180 解锁。
2. **必须整数缩放 + 最近邻。** 非整数缩放会让上面整张配置表作废。
3. **整数倍除得尽哪些屏**：16:9 的三档主流里，480×270 在 2560×1440 上是 ×5.33 **除不尽**，640×360 对 1920×1080／2560×1440／3840×2160 分别是 ×3／×4／×6 全整数，320×180 是 ×6／×8／×12。玩法定位那张表只算了一行装几个字，没算这一层。**分辨率仍由 `UI-1` 定。**

OFL 1.1 的两条义务，字体进代码仓时必须同时满足：

- **随发行附许可证与版权声明**（OFL 第 2 条）。字体进仓时把 `LICENSE-OFL` 一起放进去，并确保它进入发行包。
- **不得对修改版沿用保留字体名**（OFL 第 3 条）。将来若真做了子集化或改字形，输出的字体名不能再叫原名。

这两条会被忘掉，所以按「决策必须有执行体」另立 `ART-3` 做守卫，依赖字体进仓。

**验证方法**

```
python tools/audit_fonts.py            # 授权 + 上游七环 + 覆盖 + 度量
python tools/audit_fonts.py --licenses # 只核授权（不下载字体，快）
python tools/audit_fonts.py --clean    # 删掉 temp 下的下载物
```

它是本条的守卫。2026-08-30 全量跑一次 `EXIT=0`，同一次运行自报的覆盖量是「6 份许可证原文（登记 6 份）；上游 7 环（登记 7 环）；37 个字体文件（登记 7 个下载源）；语料 5 份；选定款的全覆盖硬要求登记 1 条、实际执行 1 条」。三类判定会失败：许可证内容变了（SHA256 对不上）、据以下结论的关键句不见了、**选定款对代码仓 `data/text` 下的游戏文本缺字**。后一条是缺字的执行体 —— 文案越写越多，新写的生僻字会在这里当场报出来，而不是等上线被玩家发现。

**硬要求只落在会被渲染给玩家看的字上**，另外三份语料（GB2312、GBK、设计仓全部 `.md`）只报数字不判失败。GB2312 那 145 个缺字全是「劐唣嗍垡墚墼」这类生僻字，设成硬要求会让判定永远 FAIL、我们学会忽略它（同一条理由见[像素绘制原则 §11](../production/像素绘制原则.md)）。设计仓语料降为报告项的理由更具体，是写这份 ADR 时当场撞出来的：**要说明字体缺哪些字就得把那些字写进正文**，于是语料里必然出现字体不覆盖的字。设计文档本来就该能引用字体没有的字。

**只能人工验收的部分**：可读性。作者 2026-08-30 实机看过三档分辨率 × 四款字体后判定 12px，10px 不启用。自动检查判不了「看不看得清」。

复现办法已落成入口，因为要判的场合不止一次（`UI-1` 判逻辑分辨率、`DOC-2` 判界面配色时都得看真字）：

```
python tools/audit_fonts.py             # 先把字体下到 temp/font-audit/
python tools/font_preview.py            # 交互看：←→ 换字体，1/2/3 换分辨率，F 全屏
python tools/font_preview.py --shots    # 只要图：每个分辨率 × 字体一张，外加一张总表
python tools/font_preview.py --clean    # 收尾
```

Godot 工程源码在 `tools/font-preview/`（三个文件），入口把它铺到 `temp/font-preview/` 再启动 —— 直接在仓库里跑会留下 `.godot/` 缓存。三个细节决定判定可信，改它时别丢：**字号等于设计尺寸、基线取整、样本里混进生僻字与全角标点**（缺字会当场显成豆腐块而不是悄悄换字体）。2026-08-30 实测 `--shots` 出图 13 张、`EXIT=0`。
