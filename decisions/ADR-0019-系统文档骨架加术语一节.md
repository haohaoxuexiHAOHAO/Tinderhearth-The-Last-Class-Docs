# ADR-0019：系统文档骨架加第九节「术语」，只取代 ADR-0010 的骨架那一条

## 背景

[ADR-0010](./ADR-0010-文档体裁与系统文档归位.md) 定下了系统文档的八节骨架，并把它做成了守卫。但那一轮没有回答一个问题：**那批文档里的自造词在哪解释。**

实测：`design/` 下那三十份系统文档里，`判据` 出现在二十九份、`挂载点` 二十七份、`量纲` 与 `反证` 各二十六份、`载体` 二十四份、`读口` 与 `分片` 各二十一份，而**全库没有一处说过它们是什么**。读这批文档的人只能从上下文猜，猜错不会被任何东西纠正 —— 而这批文档的用途正是实现时反复回来查「这件事归谁」。

跨页共用的那批词现在有家了（[术语表](../reference/术语表.md)，`DOC-89`）。剩下的是**只有一份文档在用**的词（`动作机`、`姿态`、`受击链`、`点差` 这类）：它们不该进共用表，否则那张表会被本该属于某一页的东西填满。它们要有一个固定位置，而**位置不固定就等于没有** —— 读者得每份重新找一遍。

不作决定的后果：术语要么散在正文里各自解释（同一个词在多处各有一份说法，而检查器查不出两处已经分叉），要么干脆不解释（现状）。

## 候选

1. **加第九节「术语」，插在「摘要」与「上游约束」之间**（采用）。收益：它是一节，所以在大纲视图里单独成行，二十到七十 KB 的文档里靠大纲跳转找得到；骨架守卫照原样判它的存在与顺序，不新增机制。代价：要取代 ADR-0010 已经写死的「八节」，所以得有这份 ADR；三十份文档要各加一节。

2. **做成「摘要」节内的三级标题**。收益：ADR-0010 一个字不动、不用写这份 ADR，而且三十份的「三级标题升二级」那一步整个省掉。代价：术语不在大纲里单独成行 —— 而「查得快」正是这一轮要治的根，把它藏进另一节的内部与那个目标相反。被否决的理由是目标冲突，不是成本。

3. **不加节，每个词首次出现时就地解释**。代价：同一个词在几份文档里各有一份说法，而**检查器查不出两处已经分叉**（它查断链，判不了两段话是不是在说同一件事）。这正是 [WORKFLOW §3](../WORKFLOW.md) 的漂移条款要挡的形状。

4. **只留共用术语表，专属词也塞进去**。代价：那张表会被只有一份文档在用的词填满，于是「跨页共用」这个收词判据失效，表变成一个什么都收的垃圾桶；而专属词的精确定义本来就在它自己那一页，搬走等于让它离权威定义更远。

5. **把节数这条规矩从 ADR 搬到模板，ADR-0010 保持原文不动**。代价：它顺手削弱了 ADR 的权威 —— 「已接受的 ADR 记的只是当时的形状」这句话一旦成立，就对全部十八份 ADR 成立，而那是一次远超本需求的取舍。要做也该单独立项，不该夹在一次文档可读性改造里。

## 决策

**系统文档与跨系统模型的骨架从八节变九节**，新增的「术语」排在「摘要」之后、「上游约束」之前：

`摘要` → **`术语`** → `上游约束` → `结构` → `接口` → `边界与非目标` → `理由与取舍` → `验收` → `下游同步`。末尾仍然只许追加「附录」。

**这一节只列「只有本页在用」的词。** 跨页共用的词归[术语表](../reference/术语表.md)，两处不许都有 —— 那会给一个词开两个家。哪些算跨页，判据在那一份的「收词判据」一节，别处只链接、不复述那个阈值。本页确实没有专属词就写一行「无」并说明为什么，**与骨架其余各节同一条规矩** —— 骨架一旦可选就等于没有骨架。

**本 ADR 只取代 [ADR-0010](./ADR-0010-文档体裁与系统文档归位.md) 的「系统文档骨架：八节，顺序固定」那一条。** 那份 ADR 的其余三条结论（体裁按寿命归位、命名后缀写死、系统文档必须有正典上游）**继续有效，正文一个字不动** —— 按 [WORKFLOW §4](../WORKFLOW.md)，已接受的 ADR 不得用今天的理由改写当时的背景，取代关系只写进双方文件头。

**明确不包含**：不重排其余八节、不合并任何节、不动提案那份十一节骨架、不改文档体裁的归位与命名规则。

## 后果

**正面影响**

- 自造词有了一个固定位置，而**位置固定是「查得快」的前提** —— 读者不必每份重新找一遍。
- 「忘了写术语」从一件没人会发现的事，变成骨架守卫当场报错的事。
- 专属词与共用词的分家有了可执行的边界：一个词要么在本页这一节，要么在术语表，不许都有（守卫在 `DOC-93`）。

**代价与风险**

- 三十份文档各要加一节，这是一次性清欠。**风险在过渡期**：守卫改成九节的那一刻，没加的文档全部报失败 —— 所以落地顺序写死（见下）。
- 对很小的系统，这一节可能只有两三行甚至一行「无」。判据沿用 ADR-0010 的那一条：**宁可留一节写明「无」，也不要每份自己改骨架**。
- 活文档里还有两处复述了「按八节骨架写」（在两份系统文档的上游约束里）。**改法是不复述节数、只写「按固定骨架」** —— 数字只在它的家写一次。跟着 `DOC-92` 里它们各自那一批走。
- 归档件与已接受 ADR 里的「八节」**一律不动**，它们记的是当时的事实。

**落地要求**

**顺序写死，因为门禁任何时刻都要绿。** 骨架判定是逐字比对并判顺序的，所以守卫改成九节的那一刻，没加节的文档全部报失败 —— 三条路只有一条不会让门禁红着过夜：

- 先改守卫、同批给三十份各插一个占位节 —— **排掉**：占位只能写成「待补」，而散文不写状态（[WORKFLOW §3](../WORKFLOW.md)）。
- 让守卫过渡期同时接受八节与九节 —— **排掉**：那就是可选骨架，而骨架一旦可选就等于没有骨架。
- **过渡期把术语写成「摘要」节内的三级标题**（位置与终态一致：摘要之后、上游约束之前），全部填实之后统一升成二级标题并同批改守卫 —— **采用**。每一批都是完整交付，门禁一直绿。

顺序因此是：**模板先改 → 三十份分批填实（过渡形态）→ 统一升二级标题并同批改守卫。** 进度按编号查[待办台账](../spec/issues/README.md)（`DOC-90` 到 `DOC-93`），本页不复述状态。

**验证方法**

| 判什么 | 怎么判 |
| --- | --- |
| 骨架含那九节、顺序对、末尾只许追加「附录」 | `python tools/check_docs.py` 的骨架判定（`DOC-93` 改成九节） |
| 术语节里的每个词在本页正文出现过 | 同上，新判定 |
| 同一个词不同时出现在术语表与某页术语节 | 同上，新判定 |
| 术语表里每个词条至少被一份系统文档用到 | 同上，新判定 |
| 一节里的词解释得对不对、够不够白 | **只能人工验收**：作者实读（[ADR-0009](./ADR-0009-编辑器主导的开发模式.md) 的分工） |
