# ADR-0032：心情不单独成量，由他身上挂着的状态表示

## 背景

[角色与成长 · 心情](../canon/gameplay/角色与成长.md)原先把心情立成角色身上一个单独的跨日量：按角色记的归一化值
映射成五档（沮丧 → 失落 → 平静 → 高兴 → 兴奋），每天往平静回归；上行过「各条来源自己的节流阀 ＋ 每日涨幅上限」
两道闸门，下行过一道；档位长出两项经营侧修饰（体力劳作少耗精力、产出品质更好），落在状态载体的永久项上。
结构写成了一份系统文档，需求写成了一份已获确认的 PRD，**代码一行都还没写**。

**逐条对它接的那些事，几乎每一件都已经各有落点：**

| 心情原先接的事 | 它已经有的落点 |
| --- | --- |
| 吃上饭 | 食物给按天的增益（[时间与经营 · 生产](../canon/gameplay/时间与经营.md)） |
| 被教 | 授课增益，按天（[`教育系统`](../design/教育系统.md)） |
| 考好、考差 | 考好给增益，考差得一条纯描述评语（[时间与经营 · 教学与考试](../canon/gameplay/时间与经营.md)） |
| 节日那天在场 | 节日与比赛给的增益（[`节日系统`](../design/节日系统.md)） |
| 营养不良 | 一条按天的参数类状态（[时间与经营 · 精力](../canon/gameplay/时间与经营.md)） |
| 倒下养伤 | 伤病本身就是一条按天状态（[时间与经营 · 每日结算](../canon/gameplay/时间与经营.md)） |
| 没吃上饭、熬夜 | 精力上限的加项（[时间与经营 · 精力](../canon/gameplay/时间与经营.md)） |
| 收到礼物、派到擅长的工位 | 涨关系（[`人际系统`](../design/人际系统.md)） |
| 同队的人这一趟倒下 | 无 |

所以那套结构是**同一件事的第二个家**：一顿好饭既挂一条增益、又让心情涨一格，两处的幅度、时长与原因各维护
一份，分叉时不报错。[`日记系统`](../design/日记系统.md)那条判据也已经写着「这个角色现在心情如何 —— 那是状态」。

**不作决定的后果**：落地时照心情那一套实现，多出一个量、一条回归、两道闸门与它们的反证、一项能力声明、
一条「单次上行大于每日回归」的载入校验、一份存档字段，以及一条要和载体对账的修饰路径。

## 候选

### 甲：照原样做心情系统

**收益**：一个读数直接答「他今天高不高兴」；修饰按档给，玩家只看一个档名。

**代价**：上表那几件事各记两份；上面「不作决定的后果」那一串一样不少。品质那一侧还缺一个出口
（`GP-132`），那项修饰本来就接不上。

**否决理由**：它答的问题已经有人答了，多出来的那一份只会和原来那一份分叉。

### 乙：面板上显示一个心情档，由身上的状态算出来、不单独存

**收益**：没有第二份存储，玩家仍然看得到一个总评。

**代价**：要定哪些状态算、各算多少、分几档 —— 档位边界与权重又请回来了；而且每加一条状态都要回答
「它算不算心情、算多少」，漏答不报错。

**否决理由**：把甲的大半复杂度换了个地方放；总评还会盖住「是吃得差还是伤着了」这个玩家真要据以行动的原因。

### 丙：心情不单独成量，看身上挂着的状态（采用）

**收益**：零个新结构 —— 载体已经有按天这一档、显示名、来源、叠加规则与存档；「为什么」的答案就是那条状态本身。

**代价**：见「后果」。

## 决策

**取丙。**

- **「他这几天过得怎么样」由他身上挂着的状态回答**：没有心情值、没有心情档，也没有「参与心情」这项能力声明。
- **要表达「高兴」「难过」这一类，就加一条状态**，它是内容。事件后果表里「给增益」那一格**正负都收**，挂得上。
  **干活顺不顺由那条状态自己声明**，没有一条「心情好就干活顺」的通则。
- **气泡与小事件改读「他身上挂着哪几种状态」，读的是显示字段。** 主角的状态栏是伪造的
  （[`状态效果系统` · 显示与实际是两个字段](../design/状态效果系统.md)），读实际那一份会让一句闲话或一件小事
  替他把伪装说漏。气泡那一格读到的是一组种类，所以匹配按「挂着」判，不按「相等」判。
- **角色面板的状态子页列出他身上挂着的状态**：名字、来由，按天的另写还剩几天。抬头显示那条状态栏答的是
  「我」，学生身上挂着什么原先没有一处看得到（[`界面系统`](../design/界面系统.md)）。
- **拒绝不让他身上多出任何负面状态，按天的也算**：不来上课、拒绝单独指导、拒绝高风险派工都一样。心情那一节
  原先写着「拒绝不掉心情」，拿掉心情之后这条保证要换一个家；而[人物 · 教师权力、同意与关系红线](../canon/characters/人物.md)
  原文只点名永久的惩罚。家在[时间与经营 · 学生与派工](../canon/gameplay/时间与经营.md)。
- **「同队的人这一趟倒下」不补状态。** 它原先只用来推心情；真要做「队友倒下大家难过」，另立一条。

### 明确不包含

- **不新增任何一条状态。** 现有那几条照旧；情绪一类的状态有哪几种、各改什么、挂几天，是内容，跟内容一起来。
- **不改状态载体的结构。** 分类、时长单位与字段一样不加。
- **不碰活跃失衡。** 它仍是由境况驱动、跨季才动的那一个量，本记录不改它的任何一条。
- **不碰状态在画面上的表达。** [人物](../canon/characters/人物.md)那条「状态变化要表达机制，不表达情绪」照旧管着，
  低头、拖步那类待机变体不做。
- **不定数值。** 各条状态的幅度与时长照旧归[数值模型](../design/数值模型.md)。

## 后果

- **正面影响**：少一个系统 —— 少一份存储、一条回归、两道闸门、一项能力声明和一条修饰路径；「他为什么不好」
  的答案就是那条状态与它的来由，只有一个家。学生身上挂着什么第一次有地方看。

- **代价与风险**：
  - **没有一个一眼看得出的总评。** 玩家读的是一列状态，而不是一个档名；挂多了读不读得清只能实机看。
  - **「心情好就干活顺」不再自动成立**，要靠内容给具体那几条状态声明效果 —— 漏了不报错，只是少一样东西。
  - **送礼、派到擅长的工位不再有「当天的回应」**，只涨关系；要回应得另加状态。
  - **气泡与事件多了一个读口**，读的是显示字段；读成实际字段时伪装会漏，所以那一处要一条反证钉住。

- **落地要求**：
  - 正典：[角色与成长 · 心情](../canon/gameplay/角色与成长.md)改成这一条；[时间与经营](../canon/gameplay/时间与经营.md)
    学生与派工那条拒绝加一句、教学与考试那条改成指过去、生产那条变异的排除项删掉心情；
    [玩法定位](../canon/gameplay/玩法定位.md)气泡上下文键那一句换成身上挂着的状态。
  - 系统文档：[`状态效果系统`](../design/状态效果系统.md)、[`气泡对话系统`](../design/气泡对话系统.md)、
    [`事件系统`](../design/事件系统.md)、[`界面系统`](../design/界面系统.md)、[`成长系统`](../design/成长系统.md)、
    [数值模型](../design/数值模型.md)、[`地块系统`](../design/地块系统.md)、[`天气系统`](../design/天气系统.md)
    与[系统文档索引](../design/README.md)。
  - 过程件：心情那份需求与系统文档归档到 [`GP-131-mood/`](../archive/spec/GP-131-mood/prd.md)（**历史背景·非依据**）；
    台账 `GP-131` 作废，进「已归档编号」那张表。
  - 代码：不用删任何东西 —— 代码仓里没有心情。气泡那个键跟 `NR-8` 落地，事件读状态那一格跟 `GP-52`，
    状态子页那一列跟 `UI-29`。

- **验证方法**：
  - **判得出来的**（落地时各配一条用例）：说话者身上同时挂着几种状态时，声明其中任意一种的气泡条目都进候选集；
    气泡与事件前置条件读的都是显示字段（反证：伪装状态下，只在实际字段里的那一种匹配不上）；状态子页那一列
    读显示字段、负面的一条不藏、一条都没挂时显示「没有」；不来上课、拒绝单独指导、拒绝高风险派工三条路径
    走完，身上的状态一条不多。
  - **按词搜得出来的**：两个仓的活文档与代码里不再有心情值、心情档或「参与心情」这项声明。
  - **判不出来的，只能人工**：内容里一条「被拒之后挂两天闷闷不乐」的状态写进事件不报错，只能内容审查；
    一列状态读不读得清、来由读不读得完，要实机看。
