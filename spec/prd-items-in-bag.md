# PRD：东西能拿在手上 —— 收上来的菜进背包

## 1. 概述

农场里现在收上来的东西没有去处：收获那一下只在输出面板打一行「收上来 N 件」，然后就没了（代码仓 `src/World/Farm/FarmField.cs`）。随身栏装的种子是一份按标识排的清单，种下去不少一颗。代码仓里没有物品定义、没有品质、没有背包，按名搜过，`Inventory`、`Bag`、`ItemDefinition` 一处都没有。

这一份做的是[从哪里开始 · 东西能拿在手上](../reference/godot/从哪里开始.md)那个里程碑：收上来的菜进背包，背包满了再收看得出被拒、而地上那一株还在；变异那一株收上来是变异品质，与没变的分两堆；随身栏是背包的前六格，种一颗少一颗；退出再进来，背包里还是那些。

**为什么现在做**：经营循环已经闭合（种、睡、醒），但收成还落不到任何地方，后面「有人买东西」要卖的那一筐菜、「能盖一栋房子」要的材料都得先有地方放。

**排序**：这一份与[作物素材表那份](./prd-crop-sheet.md)、[睡一觉那份](./prd-sleep-advances-day.md)并存，照[需求工作区 · 一次只做一个需求](./README.md)那条的例外办：那两份的代码都已做完、只剩作者实机，所以改文件的只有这一份。那两份的实机反馈要改代码时，单独一次提交，不混进这一份。

**分工**（[ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)）：作者在 Godot 里给每个物品配图标（作物那几样从素材表第 7–9 列框）、把手环与一条即时提示摆进农场、在检查器里填提示停留多久；我写物品定义与两条轴的档位表、背包、收获进背包、随身栏读背包、存档、手环里的背包页、开手环的键、测试与一份跟着做的指南。

**做到哪为止**：只有主角的背包，没有仓库、队友与派工，所以[背包系统 · 满了怎么办：不自动丢弃，每个入口各有一条明确的拒绝路径](../design/背包系统.md)那张入口表里只有「主角拾取」这一条在游戏里走得到，主角亲手收获就是它；其余几条留给各自的落地编号（见「非目标」）。品质只有两个来路：变异那一株给变异，没变的给寻常（见「技术考虑」里那条占位）。

**台账**：`GP-23`（背包）、`GP-22`（物品与两条轴）、`UI-13`（背包页）、`UI-35`（随身栏读背包）、`UI-24`（开手环的键）、`GP-118`（任务奖励的去处）。这一份各交付它们的一部分，剩下的仍挂在原编号上，见「非目标」。

## 2. 目标

- 在地里收一株：东西进了主角的背包，在手环的背包页里看得到种类、品质与件数；变异那一株与没变的分成两堆。
- 背包满了再收：被拒，那一株照旧待收，屏上当场一行字说清是背包满了；丢掉一堆腾出位置再收，收到的与第一次本该收到的一样。
- 随身栏就是背包前六格：选中种子那一格播下去，那一格少一颗；选中收获物那一格去播，被拒并说清不是种子。
- 停掉游戏再进来，背包里每一格的种类、品质与件数都还是那样。
- 加一种物品、加一档品质，只是加数据文件，不改代码。

## 3. 上游约束

- [时间与经营 · 背包与仓库](../canon/gameplay/时间与经营.md)：格子制、一格一种、同种堆到上限、满时提示且不自动丢弃。**约束背包的全部行为，这一份只落地其中主角背包那一半。**
- [时间与经营 · 翻包暂停，用道具不暂停](../canon/gameplay/时间与经营.md)：打开背包是界面接管输入，世界停。**约束手环在农场里打开时世界照样停，复用已有的导航栈，不自造暂停。**
- [玩法定位 · 开局](../canon/gameplay/玩法定位.md)：起始资金只够买第一批种子。**约束新开档时背包是空的；这一份没有商店，种子由开发期调试键给（见 US-005）。**
- [`背包系统`](../design/背包系统.md)：堆的标识是「种类 ＋ 品质」、满载的定义、只拒不丢、排序筛选与一键整理的形状与三条硬约束、格数与堆上限归数值模型。**这是背包那一半的全部规则来源，这一份只决定落成哪些用例。**
- [`物品系统`](../design/物品系统.md)：物品定义那张字段表、两条轴的档位是在册的声明表、有些物品没有品质、品质从哪来。**约束物品定义的形状与缺字段报错；种子声明无品质、收获物声明有品质照那一节的判据定。**
- [`生产系统` · 一条管道，四个环节，顺序固定](../design/生产系统.md)：产出 → 归属 → 付酬 → 入库。**约束收获不许绕过管道直接塞进背包** —— 代码里那句「不要在这里顺手加一个容器装它」就是这一条。
- [`地块系统` · 作物定义：一张表，缺字段报错](../design/地块系统.md)：作物定义指一个产出物品。**约束种子那一格照同一形状加、指到物品定义，指不到被拒。**
- [`界面系统` · 手环上：背包](../design/界面系统.md)：这一页答「我要的那样东西在哪，我还背得下吗」、品质必须看得见、被拒的原因不许藏。**约束背包页必须显示的那几项。**
- [ADR-0015](../decisions/ADR-0015-存档的版本与缺字段口径.md)与[ADR-0017](../decisions/ADR-0017-版本更新对旧存档的两种后果.md)：全存档一个版本号，同版本缺字段被拒，旧版本按存档默认值补。**约束背包进存档时版本升一级、旧档补一个空背包。**
- [ADR-0018](../decisions/ADR-0018-内容定义按声明扩展.md)、[ADR-0022](../decisions/ADR-0022-内容清单的家是数据文件.md)与[ADR-0025](../decisions/ADR-0025-取值集的家由加一个的代价决定.md)：内容定义一张表、按声明扩展，清单的家是代码仓 `data/`，内容型的取值集要真的装得下一个没人预见过的值。**约束物品、类别与两条轴的档位都是数据文件，加一档不改代码。**
- [ADR-0030](../decisions/ADR-0030-作物成熟时按几率变异.md)：变了的那一株收上来全是变异品质。**约束收获时的品质来路。**
- [键鼠技能位挪到右手](../design/proposals/键鼠技能位挪到右手.md)那份提案里打开手环与直达页的键位表。**约束 `UI-24` 这一半用哪几个键。**
- **依赖**：仓库等仓储建筑（`GP-44`）；队友自动采集等队友进场；派工产出入库等 `GP-28`；买种子等 `GP-43`；种植技能给的品质等 `GP-45`。这一份不等它们，各自落地时接已有的入口。

## 4. 用户故事

### US-001：物品有定义，类别、稀有度与品质各是一张在册的表

**描述**：作为作者，我想把物品、类别与两条轴的档位都写成数据，以便加一种物品或一档品质只是加一份文件。

**验收标准**：

- [ ] 可测试：物品定义照[物品系统 · 物品定义的字段：只写「它是什么」，不写「它能干什么」](../design/物品系统.md)那张表逐格读；缺任一格载入被拒并说清缺哪一格，「有无品质」与「用掉前要不要一道确认」两格也不给默认值。
- [ ] 可测试：名称与描述写成中文串而不是文本键的，载入被拒。
- [ ] 可测试：稀有度与品质的档位照[物品系统 · 两条轴的档位各是一张在册的声明表](../design/物品系统.md)逐项读；缺任一声明项被拒；显示色不是色板里的一档被拒；品质最高那一级的几个值同一条色带被拒；排序位允许重复。
- [ ] 可测试：类别是一张带层级的表；物品填的类别不在表里，或稀有度不在册，载入被拒并点名。
- [ ] 可测试：多放一份品质档位文件、不改代码，载入成功且排序按它的排序位走（[ADR-0025](../decisions/ADR-0025-取值集的家由加一个的代价决定.md)那条内容型反证）。
- [ ] 可核对：读法与作物定义同一套（基础内容加 mod 覆盖，一份读不出来点名是哪一份、来自哪里）；主场景启动时也读一遍，导出冒烟判得到坏文件。

### US-002：素材表上每种作物都有一份种子、一份收获物

**描述**：作为作者，我想素材表上每一行作物都有对应的种子与收获物定义，以便种下去、收上来的都是真的物品。

**验收标准**：

- [ ] 可核对：代码仓 `data/crops/` 下每一种作物，各有一份种子与一份收获物的物品定义；种子声明无品质，收获物声明有品质。
- [ ] 可测试：作物定义多一格「用什么种子」，与「产出什么物品」同一形状；两格都必须指到在册的物品定义，指不到载入被拒并点名作物与那一格。
- [ ] 可核对：每个新物品的名称与描述在文本表里；缺了照作物那样启动时报出来。
- [ ] 可核对：[地块系统 · 作物定义：一张表，缺字段报错](../design/地块系统.md)那张表加上种子那一行。

### US-003：背包：一格一堆，满了只拒不丢

**描述**：作为玩家，我想东西按种类与品质摞成堆、满了明说放不下，以便我知道背了什么、还背不背得下。

**验收标准**：

- [ ] 可测试：同种同品质合进一堆、堆到那种物品的堆上限再占下一格；同种不同品质各占一格；无品质的只按种类分堆。反过来构造一次「不同品质被合进一堆」的断言，必须失败。
- [ ] 可测试：满载 = 没有可合的同标识堆且没有空格；格子用尽但有半满的同标识堆时照样放得进去。两个方向各一条用例。
- [ ] 可测试：一次放进去的那一份放不下时整份被拒，背包一件不变。
- [ ] 可测试：排序三个键（品质、类别、最近获得）各排一次，同键排两次结果相同；筛选按类别与按品质，筛选态下挪格与丢弃的结果与未筛选时相同，被筛掉的不动。
- [ ] 可测试：一键整理把同标识的散堆并成一堆、再按当前排序键重排；总数一件不变；没有散堆时它是空操作。
- [ ] 可测试：把一堆挪到另一格，目标格空着就搬过去，有东西就两格互换。
- [ ] 可测试：丢弃把一整堆移出背包，丢之前一律要一道确认，取消时背包一件不变；物品声明了不可丢弃的，丢弃被拒并说清是这一种。
- [ ] 可测试：格数按背包等级从配置读，缺了当场报错；堆上限按种类从物品定义读。

### US-004：收上来的菜进背包，放不下那一株还在

**描述**：作为玩家，我想收获之后东西进我的背包，背包满了收不进时那一株还留在地里，以便满载从不吞掉我的收成。

**验收标准**：

- [ ] 可测试：主角在地里收获走生产那条管道的四个环节（[生产系统 · 一条管道，四个环节，顺序固定](../design/生产系统.md)）：产出是这一株的件数与品质，归属是主角，不付酬，入库进主角的背包。
- [ ] 可测试：变异那一株收上来是变异品质；没变的是寻常（这一条是占位，见「技术考虑」）。
- [ ] 可测试：放不下时那一格照旧待收，件数、品质与变异那一位都不变；腾出位置再收，收到的与第一次本该收到的一样。
- [ ] 可观察：放不下时屏上当场出现一行字，说清是背包满了；它不进手环的事件流（[背包系统 · 接口](../design/背包系统.md)那一行「满载提示」）。
- [ ] **作者实机确认**：背包满了再收，看得出被拒、那一株还在；丢掉一堆再收，收进来了。

### US-005：随身栏是背包的前六格，种一颗少一颗

**描述**：作为玩家，我想随身栏显示的就是我背包里的东西，播种用掉手上那一颗种子，以便种子是一样要花的东西。

**验收标准**：

- [ ] 可测试：随身栏显示背包的前六格，随身栏自己不存任何物品（`UI-35`）；随身栏那几条已有用例与「播种取选中那一格」那几条用例（`UI-34`、`GP-128`）一条不改照样通过 —— 换内容来源不重做载体，这一条是承重项。
- [ ] 可测试：播种成功从选中那一格扣一颗种子；扣到零那一格变空。
- [ ] 可测试：选中那一格放的是收获物时播种被拒，原因是「不是种子」；那一格与地都不变。
- [ ] 可测试：开发期调试键往背包放一批种子：按标识排，一批的种数与随身栏格数相同，每种一满堆；放不下时整批被拒并说清；按到最后一批之后回到第一批。它不进输入映射，与 `N` 同一条理由。
- [ ] 可核对：调试键与输入绑定表登在一处，「同一个物理位不被两个动作抢」那条测试把调试键一起判。原先调试键是直接读的按键，那条测试看不见它们。
- [ ] **作者实机确认**：数字键选到种子那一格播得下去、那一格少一颗；选到收获物那一格播不下去，屏上说清原因。

### US-006：背包进存档

**描述**：作为玩家，我想背包里的东西跟着存档走，以便退出再进来还在。

**验收标准**：

- [ ] 可测试：主角背包的内容是正式存档里的一个分片；写出去再读回来，每一格的种类、品质与件数都一致，空格还在原来的位置。
- [ ] 可测试：存档版本升一级；上一版的存档读进来补一个空背包，日期与每一格地照旧。
- [ ] 可测试：同一版的存档缺背包分片，载入被拒（[ADR-0015](../decisions/ADR-0015-存档的版本与缺字段口径.md)）。
- [ ] 可测试：存档里的物品标识在物品定义里找不到时，载入被拒并点名哪一格、哪个标识；存档里的格数比现在配置的格数多时，载入被拒并说清两边各是几格。
- [ ] **作者实机确认**：收几样东西、睡一觉，停掉游戏再进来，背包里还是那些。

### US-007：农场里打得开手环，Tab 开手环、B 直达背包

**描述**：作为玩家，我想在农场里随时打开手环看背包，以便知道自己背了什么。

**验收标准**：

- [ ] 可核对：手环由作者摆进农场，摆在界面根下面、接上素材资源；缺哪一格当场报错说清缺谁。主场景里的手环照旧。
- [ ] 可测试：打开手环、直达背包、直达地图、直达角色面板四个动作进动作清单，键鼠依次是 `Tab`、`B`、`M`、`C`，照[键鼠技能位挪到右手](../design/proposals/键鼠技能位挪到右手.md)那份提案的键位表；手柄 `Start` 开手环。
- [ ] 可核对：手柄 `Start` 那一条的引擎自报名起一次引擎实读后写进绑定表，不照文档抄。
- [ ] 可测试：直达键打开的是手环的那一页，不是第二个面板；手环开着时按另一个直达键换到那一页，再按同一个键关上。
- [ ] 可测试：睡下到醒来那一段输入关着，按这几个键打不开手环。
- [ ] **作者实机确认**：农场里按 `Tab` 打开、`Esc` 关上，开着时世界停着；按 `B` 直接落在背包页。

### US-008：手环里的背包页

**描述**：作为玩家，我想打开背包看到每一堆是什么、什么品质、有几件，还能排、筛、整理、挪与丢，以便找得到东西、腾得出位置。

**验收标准**：

- [ ] 可观察：每一格画格子、图标、件数（多于一件才写）、品质点（按品质那一档的显示色染；无品质的不画）与稀有度框（按稀有度那一档的显示色染）；空格只画格子。
- [ ] 可观察：页上写着当前排序键、当前筛选条件与还剩几个空格；选中一格时下面一行写它的名称、品质与件数。
- [ ] 可测试：排序、筛选、一键整理、挪格与丢弃在这一页都点得到，结果与 US-003 那几条用例一致。
- [ ] 可观察：被拒的操作当场说清原因，比如这一样不可丢弃。
- [ ] 可观察：点丢弃先弹一道确认，写明丢的是哪一样、几件、什么品质；点确认才丢，点取消或按返回什么都不变。
- [ ] 可核对：整页用素材资源里已有的件拼出来（厚框、格子各态、选中框、品质点与稀有度框），样子照作者给的那张参考图：深色厚框里一行四格，格数多了往下加行。一行几格写在规则层的排版单位里，有测试管着。
- [ ] **作者实机确认**：同名不同品质分得出来；16 像素图标上的件数与品质点分得清；一屏同名多行读得下去；排版与操作顺不顺手。

### US-009：物品图标由作者配，缺图一次全报

**描述**：作为作者，我想在 Godot 里给每个物品配图标，配漏了启动就告诉我，以便不会有一格空着却不报错。

**验收标准**：

- [ ] 可核对：每个物品一份图标资源；有品质的另配变异那一张，或明写同原图。作物那几样每种两份：种子那份框素材表（代码仓 `assets/self-drawn/crops/crop1.png`）第 7 列，收获物那份框第 8 列、变异那一张框第 9 列，与作物素材同一个做法（配好第一种、复制一份改 `y`）。
- [ ] 可测试：在册物品缺图标、有品质却没写变异那一张、两份图标配给同一个物品，载入时一次全报，一行一处；判在规则层，引擎层只交出每一格配没配。
- [ ] 可观察：品质是变异的那一堆，格子里画变异那一张。

### US-010：即时提示：放不下、播不了，当场一行字

**描述**：作为玩家，我想一个动作被拒时屏上马上说清为什么，以便不会把「没反应」当成坏了。

**验收标准**：

- [ ] 可观察：收获放不下、播种被拒、调试键那一批放不下时，屏上出现一行字说清是哪一种；后一条顶掉前一条，不排队。
- [ ] 可核对：这一行由作者摆进农场（摆在界面根下面），停留多久由作者在检查器里填、没有默认值；缺了或填了零当场报错。
- [ ] 可核对：停留时长登进[数值模型](../design/数值模型.md)那张尚未给值的表，与升档提示那一行分开（两者的丢弃语义不同）。
- [ ] **作者实机确认**：那一行看得见、停得够读完、不挡人。

### US-011：任务奖励的东西去哪

**描述**：作为设计，我想先定下任务奖励的东西去哪，以便任务系统落地时既不静默丢掉它，也不替玩家塞进背包。

**验收标准**：

- [ ] 可核对：[背包系统 · 满了怎么办：不自动丢弃，每个入口各有一条明确的拒绝路径](../design/背包系统.md)那张入口表加一行任务奖励：委托、主线任务与个人请求的奖励物品一律当作货物送到家旁边的货物箱，也就是订货送达的那个送达点，不直接进背包；玩家回基地自己去取，取不进背包就一直在箱里。箱子只出不进。[`任务系统`](../design/任务系统.md)那句「满了走背包那条只拒不丢的路」跟着改，[`经济系统`](../design/经济系统.md)送达点那几处写明任务奖励也落在这里。
- [ ] 可核对：那一节的标题与正文不再写入口的个数，加一行之后不用改标题；引它的几处节名跟着改。
- [ ] 可核对：这一条只改文档；任务系统还不存在，代码不动（`GP-118`）。货物箱本身另立一个编号，跟最先往里送东西的那个系统落地。

### US-012：跟着做的指南：东西能拿在手上

**描述**：作为作者，我想照一份指南在农场里摆好手环与即时提示、配好物品图标，以便不读代码也知道每一格接什么。

**验收标准**：

- [ ] 可核对：新写一篇跟着做的指南，形状照[一块地能种出东西](../reference/godot/一块地能种出东西.md)：每一步一张照着点的表，选中谁、做什么、填什么值都写出来；「跑一遍验收」是一张每行带加粗行名的表；末尾按症状查。
- [ ] 可核对：[从哪里开始 · 东西能拿在手上](../reference/godot/从哪里开始.md)那一格指到这篇，「你搭」那一行照实际分工改；Godot 参考那一组的索引登上它。
- [ ] **作者实机确认**：照着搭完，收一株看得到它进了背包。

### US-013：东西能拿在手上的端到端

**验收标准**：

- [ ] 自动化测试走完主路径：开新档（背包是空的）→ 调试键放一批种子 → 播种（选中那一格少一颗）→ 推进到成熟（一株变异必中、一株必不中）→ 收获进背包（变异与寻常各一堆）→ 写档、用写出的那一份读回，背包、日期与每一格地都一致。

- [ ] 测试独立可重复：随机源注入；写档走注入的写入口，不碰真文件；物品、作物与文本表读工程里那一份，只读不写。
- [ ] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。
- [ ] 作者实机确认清单：照 US-012 那篇的「跑一遍验收」那张表走，清单在这一条拆出来的端到端条目里按行名对号。

## 5. 功能需求

**物品与两条轴**

- FR-1：系统必须从代码仓 `data/` 下的物品定义文件读出全部物品，缺任一字段时载入被拒并说清缺哪一格。
- FR-2：系统必须拒绝名称或描述不是文本键的物品定义。
- FR-3：系统必须从数据文件读出稀有度与品质两张档位表，缺任一声明项时载入被拒。
- FR-4：系统必须拒绝显示色不在色板里的档位。
- FR-5：系统必须拒绝品质最高那一级里两个值落在同一条色带上的档位表。
- FR-6：系统必须从数据文件读出带层级的类别表，并拒绝类别或稀有度不在册的物品定义。
- FR-7：读档位的代码必须遍历在册的那几档，不按序号取某一档。
- FR-8：系统必须拒绝种子或产出指不到在册物品的作物定义。

**背包**

- FR-9：背包里一堆的标识必须是「种类 ＋ 品质」；无品质的物品只以种类为标识。
- FR-10：放进一份东西时，系统必须先合进同标识的未满堆，再占空格。
- FR-11：系统必须只在既没有可合的同标识堆、也没有空格时判满载。
- FR-12：一份东西放不下时，系统必须整份拒收，背包一件不变。
- FR-13：系统必须能按品质、类别、最近获得三个键之一排序，同一个键排两次结果相同。
- FR-14：系统必须能按类别或按品质筛选，筛选态下的操作结果与未筛选时相同。
- FR-15：一键整理必须把同标识的散堆并成一堆并按当前排序键重排，不改任何数量。
- FR-16：系统必须能把一堆挪到另一格，目标格有东西时两格互换。
- FR-17：系统必须能丢弃一整堆，并拒绝丢弃声明了不可丢弃的物品。
- FR-18：背包的格数必须按背包等级从配置读，缺配置时当场报错。
- FR-19：每种物品的堆上限必须从它的物品定义读。

**收获**

- FR-20：主角收获时，系统必须让收成依次走产出、归属、付酬、入库四个环节。
- FR-21：入库那一环必须把主角亲手的收成放进主角的背包。
- FR-22：变异那一株的收成必须是变异品质，没变的必须是寻常。
- FR-23：背包放不下收成时，系统必须让那一格保持待收，件数、品质与变异那一位都不变。

**随身栏与播种**

- FR-24：随身栏必须显示背包的前六格，自己不持有物品。
- FR-25：播种成功时，系统必须从选中那一格扣掉一颗种子。
- FR-26：选中那一格不是种子时，系统必须拒绝播种。
- FR-27：开发期调试键必须按标识顺序一批批往背包放种子，每种一满堆，放不下时整批拒收。
- FR-28：系统必须把开发期调试键与输入绑定登在同一处，让物理位冲突的测试一起判它们。

**存档**

- FR-29：主角背包的内容必须作为正式存档的一个分片写入与读回。
- FR-30：加了背包分片之后，存档版本必须升一级，上一版的存档读进来补一个空背包。
- FR-31：存档里的物品标识找不到定义时，系统必须拒绝载入并点名哪一格、哪个标识。
- FR-32：存档里的格数多于配置的格数时，系统必须拒绝载入并说清两边各是几格。

**手环与按键**

- FR-33：手环必须能由作者摆进农场的界面根下面，缺配置时当场报错。
- FR-34：系统必须提供打开手环、直达背包、直达地图、直达角色面板四个输入动作，键鼠绑 `Tab`、`B`、`M`、`C`。
- FR-35：手柄 `Start` 必须绑到打开手环，绑定里写引擎实读的自报名。
- FR-36：直达键必须打开手环的那一页，手环开着时按同一个键必须关上。
- FR-37：睡下到醒来那一段，这几个键必须不起作用。

**背包页与图标**

- FR-38：背包页的每一格必须画出图标、件数、品质点与稀有度框。
- FR-39：背包页必须显示当前排序键、当前筛选条件与剩余空格数。
- FR-40：背包页必须为选中的那一格写出名称、品质与件数。
- FR-41：背包页里被拒的操作必须当场说清原因。
- FR-42：系统必须在载入时一次报出全部缺图标、缺变异那一张与重复配置的物品。
- FR-43：品质是变异的那一堆必须画物品的变异图标。

**即时提示**

- FR-44：收获、播种或调试键放种子被拒时，系统必须在屏上显示一行即时提示说清原因。
- FR-45：即时提示必须一次只显示一条，后一条顶掉前一条。
- FR-46：即时提示的停留时长必须从检查器读，缺了或为零时当场报错。

**丢弃确认**

- FR-47：丢弃一堆之前，系统必须弹一道确认，写明丢的是哪一样、几件、什么品质。
- FR-48：确认被取消时，系统必须让背包一件不变。

## 6. 非目标

- **仓库**：仓库那一个容器、入库与背包页签下仓库那一页，等仓储建筑（`GP-44`）。那一页照旧是空的。
- **队友背包与自动采集、派工产出入库**：没有队友进场，也没有派工（`GP-28`）。那两条拒绝路径与「玩家入库」那一条，各跟自己的落地编号走。
- **背包升级**：等级固定为第一级；等级从哪来是内容与经济侧的事（[背包系统 · 接口](../design/背包系统.md)那一行）。
- **买种子、卖菜**：商店与钱包归「有人买东西」那个里程碑（`GP-43`）。
- **品质进基础价、商店按档位上架**：`GP-22` 剩下的那两步。档位表里的基础价系数这一份只读进来、核一遍，没有人用它。
- **物品详情面板的星级**：`UI-40`。这一份只画格子里的品质点与选中那一行的品质名。
- **关卡里翻包暂停、用道具、掉在地上的那一件**：战斗侧，跟关卡落地走。
- **种植技能给的品质**：`GP-45`。
- **判据 C7 按堆数重算**：`GP-7`。
- **图鉴记「见过没有」**：`GP-58`。
- **随身栏选中位进存档**：选中位不存，进来时落在第一格。
- **拖拽**：挪格是点一格、再点目标格，键盘与手柄用同一套焦点走得通；不做拖拽。
- **手柄的换页与按键提示图标**：`UI-54` 明确后置，这一份手柄只绑 `Start`。

## 7. 界面与表现考虑

- **背包页**答「我要的那样东西在哪，我还背得下吗」。信息的先后：格子那一片最重，其次是选中那一格的名称、品质与件数，再次是排序键、筛选条件与空格数。
- **格子复用随身栏那一套素材**（素材资源里格子各态与选中框），品质点与稀有度框按那一档声明的颜色染，规矩在[界面绘制约定](../production/界面绘制约定.md)那张「代码管什么」的表里，不新画。
- **背包页的样子照作者给的参考图**：深色厚框里格子一格挨一格，一行四格，格数多了往下加行。全部用已经画好的件拼，代码按排版单位摆，不另画、也不靠目测调位置。
- **丢弃那一道确认在弹窗那一层**：它接管输入，所以开着时世界停着，与背包页本来就停着的世界是同一个暂停。
- **被拒不许没反应**：收获放不下、播不了、丢不掉，都当场一行字说清是哪一种。**即时提示不接管输入**，所以它出现时世界不停，与弹窗是两回事。
- **编辑器里看不到格子与像素字体**，跑起来才有，与睡一觉那两个窗同一个情况；指南里写明，免得当成没接上。

## 8. 技术考虑

- **落点**：物品定义、类别、两条轴的档位、背包与生产那条管道都在规则层（不引用 Godot），落在哪个命名空间照代码仓 ARCHITECTURE 那张表；手环、背包页、即时提示与图标资源在 `src/`。
- **读法**：物品、类别与档位照作物定义那一套读（基础内容加 mod 覆盖、按标识去重、一份读不出来点名）；农场不经过主场景，所以两边各读一遍，与作物现在一样。
- **收获的那一道闸**：代码仓 `rules/Economy/Plot.cs` 的 `TryHarvest` 一次调用里既算收成又改地块，放不下时要那一格不动，所以要拆成先算、放得下再改。算的那一半没有副作用：变异那一位在长成那一下已经掷定，件数由浇水记录算出来。
- **生产那条管道**：这一份只走主角亲手那一支。归属照正典「基地产出归主角」，付酬只对派工的学生；管道是规则层的一个入口，将来清理物与派工产出也从这里进，所以收获不许绕过它直接放进背包。
- **没变的那一株给寻常，是占位**：[`地块系统`](../design/地块系统.md)写的是读种植那项生活技能，而技能还不存在（`GP-45`）。寻常是[物品系统 · 品质五级，顶上那一级有两个名字](../design/物品系统.md)那张表里「日常制作与采集的常态」；技能落地时换成读技能，代码那一处的注释指过去。
- **种子无品质**：照[物品系统 · 有些物品没有品质这条轴](../design/物品系统.md)那条判据 —— 一颗种子长成什么、收上来什么品质，由作物、浇水、技能与变异定，种子自己没有做得好坏之分。
- **格数与堆上限的值**：格数照[数值模型](../design/数值模型.md)参数表里 `capacity.backpack_slots_by_level` 那一行写进代码仓 `data/config/game.json`，堆上限照 `stack_limit_default` 写进每一份物品定义。它们是按种类数校的起步值，按堆数重算归 `GP-7`；代码里那一份与参数表对不对得上现在没有守卫，归 `DOC-6`。
- **存档**：背包分片的存档默认值就是新开档时的空背包，与「这个分片从来没存过」时的初始值同一处（[`存档系统`](../design/存档系统.md)那张分片声明表）。版本从 1 升到 2，最低兼容版本不动（代码仓 `rules/Foundation/Save/SaveFile.cs`）。
- **手环进农场**：手环现在只在主场景里由代码建出来（代码仓 `src/UI/WristbandPanel.cs`），不是界面根认得的那一种，素材资源、文本表与像素主题都由主场景塞给它。要让作者摆进农场，它得改成界面根认得、素材资源走检查器、文本表与主题在运行时拿到；主场景那条建法照旧。
- **背包页由代码拼**：与手环外壳、随身栏同一个做法，格子大小、间距与一行几格是规则层的排版单位、有测试管着，格数变了不用重摆。作者只摆手环那一个节点；[从哪里开始 · 东西能拿在手上](../reference/godot/从哪里开始.md)那一格「你搭：背包界面的格位网格」跟着改。
- **丢弃确认**：一道带确认与取消两个按钮的弹窗，经导航栈开关，按返回等于取消。睡一觉那两个窗只有一个按钮，所以不复用它们，另做一个；按钮的样子同样来自像素主题。
- **键**：`B` 现在是农场里的换批调试键，直接读按键，绑定表看不见它。它让给背包，放种子的调试键换成 `G`：与绑定表、主场景和训练房里的调试键都不撞（按代码仓 `rules/UI/InputBindings.cs` 与几处直接读按键的地方查过）。`Start` 的自报名照 `UI-14` 那次的办法读：起一个一次性无头工程打出 `as_text()`，用完即删。
- **待验证**：手环打开、世界暂停时，农场节点的每帧处理会不会跟着停，按推断会（它没有改处理模式）。落地时实测一次：手环开着按交互键，不该锄地。

## 9. 待确认问题（阻塞项）

无。答复都已写进正文：

- **收获放不下**：整份拒收，那一株照旧待收（US-003、US-004）。
- **物品图标**：每个物品一份图标资源，作物那几样框素材表第 7–9 列（US-009）。
- **任务奖励的东西**：委托、主线任务与个人请求一律当作货物送到家旁边的货物箱，也就是订货送达的那个送达点，不直接进背包；箱子只出不进；箱子本身跟最先往里送东西的那个系统落地（US-011）。
- **丢弃**：一律要一道确认。整堆丢掉之后背包不做撤销，所以每一次都问一下（US-003、US-008、FR-47）。
- **背包页的格子**：代码用已经画好的件拼，样子照作者给的参考图（US-008、「技术考虑」）。

## 10. 成功判据

- 在农场里收一株：它进了背包，背包页里看得到种类、品质与件数；变异与没变的分两堆。
- 背包满了再收：被拒，那一株还在，屏上一行字说清；丢一堆再收，收进来了。
