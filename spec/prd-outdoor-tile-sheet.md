# PRD：地形与崖改用图块表画

## 1. 概述

作者的室外图块表画完了。地形按裸土、草、浅水、深水一种叠一种：裸土以外每种一套 16 格，只画自己那种，下面那一种的地方留透明；每种地形一块开阔地整块；下面一片是一块拼好的高处，崖按块拼。怎么拼、为什么这样排，在[俯视地图用图块表拼](../design/proposals/俯视地图用图块表拼.md)，本文不复述。

游戏里还是老一套：几张配对图，每张两种地形都画；一层显示层按配对查表；纹理图加着色器那一套代码也还在，[ADR-0033](../decisions/ADR-0033-地面纹理直接画进图块.md) 之后用不上了。这一份把图块表接进游戏，地形（台账 `ENG-42`）与崖（`ENG-43`）一起接，作者在 Godot 里只搭一次。

**为什么现在做**：图块表定稿了。[水边砌一道石壁](./prd-shore-stone-wall.md)剩下的验收要看新图；[俯视地形挡得住人](./prd-terrain-blocks-walking.md)里给水的标记瓦片画碰撞那一步，标记瓦片要随这一份换到图块表上，先画就得画两遍。

**排序**：排在[背包改成网格](./prd-grid-bag.md)后面，那一份收尾之前不改代码，作者在 Godot 里那几步也从那时开始。理由同[需求工作区 · 一次只做一个需求](./README.md)：两份同时改代码，回归失败说不清是哪一份引起的；能锄的那一片就框在代码仓 `src/World/Farm/FarmField.cs` 里，背包那一份正在改这个脚本。石壁那一份剩下的验收并进这一份的端到端，两份一起收尾。给水画碰撞那一步排在这一份落地之后，只做一次。

**代码落地之后，农场要先照指南「铺天然地形」那一步把新的显示层搭好，才按得了 `F6`**：新的几层缺了当场报错、说清缺哪一层。别的几份等农场实机的需求，那一趟从这一步开始。

**分工**（[ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)）：作者把图块表放进代码仓，在 Godot 里给数据层换标记瓦片、搭显示层与崖那两层、给崖那几块画碰撞、从农场复制一份测试场景拼高处，然后实机看。我写排法那张表、显示层的画法、交图检查与样板生成器、载入时那几条核对、测试、指南与规矩，删掉旧的那几样。

**做到哪为止**：农场的地面换成图块表画；崖只在测试场景里拼、看，农场的地图不加崖。测试场景看完留不留由作者定，它不进 `verify.py`。

**台账**：`ENG-42` 是这一份的端到端，另拆出 `ENG-45`、`ENG-46`、`ENG-47`、`ENG-48`、`ENG-49`、`ENG-43`、`ENG-50`、`DOC-161`。`ENG-41`（石壁的端到端）、`ART-33`、`ART-34`、`ART-35` 剩下的核对与实机，以及 `ENG-25` 剩下的「在编辑器里刷一片看」，都并进 `ENG-42`。

## 2. 目标

- 农场的地面由图块表画：一种地形一层按顺序叠，开阔地取整块。一大片草与水看不出格线，水边是石壁，交界的拐角是圆的。
- 作者刷好的那片地不用重刷：迁过去之后，每一格还是原来那种地形。
- 刷数据层时，显示层在编辑器里当场跟着变，跟现在一样。
- 高处照块拼：崖面挡人，楼梯走得上去，走到高处边上停得住。配错了按 `F6` 当场报错、一次全报、说清是哪一格：崖那两层的碰撞开关关着，该挡人的块没画碰撞，楼梯的路或顶面画了碰撞，能锄的那一片压在水或崖上。
- 交图检查判新的图块表：同一类格边、崖边两头对不上时，说清是哪一张、哪一格、哪条边；`verify.py` 照旧跑它。
- 图块表的排法只写在代码仓一处，样板、交图检查与游戏读的是同一份。
- 配对图、纹理图那一套、按方向声明的规范边与外圈模板都删掉，两个仓里不再有讲它们的句子。
- 作者照[一块地能种出东西](../reference/godot/一块地能种出东西.md)「铺天然地形」那一步就搭得出来、改得了图块表。

## 3. 上游约束

- [俯视地图用图块表拼](../design/proposals/俯视地图用图块表拼.md)：叠放顺序、一套 16 格里下面那一种留透明、开阔地按世界位置取整块、崖分两层按块拼、碰撞挂在崖那几块上、拼崖的规矩。**这是本需求全部结构的来源。**
- [ADR-0033](../decisions/ADR-0033-地面纹理直接画进图块.md)：地面纹理画在作者的图块里。**约束纹理图、着色器与配置那一套全部删掉，不留第二条画法。**
- [ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)：场景、节点树、碰撞区域与检查器里的值归作者，缺配置当场报错。**约束显示层几层、崖那两层与测试场景由作者搭，崖的碰撞由作者在 TileSet 里画；代码只往显示层上画，并在载入时核配置。**
- [场景绘制约定 · 俯视里什么挡人：一律是碰撞，地形的挂在数据层](../production/场景绘制约定.md)：挡人的一律是物理碰撞，地形的挂在数据层的标记瓦片上。**约束水照旧挂在数据层；崖不在数据层，碰撞挂在崖那几块上，那一节里悬崖那一行跟着改。**
- [场景绘制约定 · 基地要画哪几套](../production/场景绘制约定.md)：每种地形只挨着顺序里它左右那一种。**约束每一套只叠在一种地形上，按顺序叠才成立；这条纪律不变。**
- [时间与经营 · 建造](../canon/gameplay/时间与经营.md)：水面等周边地形在可建造区之外。**约束崖也在可建造区之外，摆位与锄地不认崖，只核能锄的那一片没压上去。**
- [玩法定位 · 像素基准](../canon/gameplay/玩法定位.md)：一格就是基础单位。**约束图块表、整块与崖的每一块都按整格取。**

**描述**：作为玩家，我想看到一大片草与水不按格重复，交界那几格与旁边整片接得上，以便农场不像方格纸。

## 5. 功能需求

- FR-1：显示层必须一种地形一层，按裸土、草、浅水、深水从下往上叠。
- FR-2：画某一种地形那一层时，系统必须把压着这种地形、或者压着顺序在它后面那几种地形的格角，算作这种地形。
- FR-3：一个显示格四个角都算这种地形时，系统必须取这种地形整块里第 (x mod 宽, y mod 高) 那一格；x、y 是显示格坐标，负数取向下的模。
- FR-4：只有一部分角算这种地形时，系统必须按四角编码从这种地形那一套里取那一格，编码与 `CodeToAtlasOffset` 那张表照旧。
- FR-5：一个角都不算这种地形时，系统必须让那一层的这一格空着。
- FR-6：裸土没有那一套；画裸土那一层时，系统必须只在四个角都算裸土时取整块，否则空着。
- FR-7：数据层范围外的角，系统必须按最近的边缘格算。
- FR-8：数据层范围内没刷的格、或者刷的那一块没标地形，系统必须当作不是任何一种地形。
- FR-9：数据层一有改动，系统必须在编辑器里当场重画显示层那几层。
- FR-10：图块表的排法必须只写在代码仓一处，显示层的画法、崖的载入核对、交图检查与样板生成器都从那里读。
- FR-11：检查器里显示层少接了、一种地形没指给任何一层、或者同一层、同一种地形指了两次时，系统必须一次全报；编辑器里警告，运行时报错。
- FR-12：显示层那份 TileSet 里少建了画法要用到的格时，系统必须报出少的是哪几格。
- FR-13：交图检查必须核每一张图块表的宽高：宽等于排法定的宽，高至少到排法的最后一行，都是整格。
- FR-14：交图检查必须核每一套里同一侧、两端地形一样的格边逐像素一样，透明的像素也算。
- FR-15：交图检查必须核崖边北沿、西边、东边每一种格的两头那条边都一样，四个角挨着它们的那条边也与它们一样；草顶另画的那几格同样。
- FR-16：交图检查报错必须说出是哪一张图块表、哪一套或哪一块、哪一格、哪条边。
- FR-17：载入时，崖那两层任何一层的 `Enabled` 或 `Collision Enabled` 关着，系统必须报错。
- FR-18：载入时，崖那两层的位置与数据层不一样，系统必须报错。
- FR-19：载入时，崖那两层的 TileSet 里，崖面（崖顶、中间、崖脚那几行，含草顶另画的崖顶）、楼梯左右各一列、崖边那一层的每一块，有没画碰撞的，系统必须报错。
- FR-20：载入时，崖那两层的 TileSet 里，楼梯中间那几列、顶面那几格与裸土、草的整块，有画了碰撞的，系统必须报错。
- FR-21：载入时，能锄的那一片压着数据层带碰撞的格、或者崖那两层刷了的任何一格，系统必须报错，列出压着的格。
- FR-22：崖与能锄的那一片的核对必须一次全报，每处写明是哪一层、哪一格、为什么不对。
- FR-23：水的碰撞必须照旧只挂在数据层的标记瓦片上。

## 6. 非目标

- **农场的地图不加崖**：崖只在测试场景里拼、看。基地哪里要高处，跟着地图怎么画走。
- **不改数据层与碰撞的做法**：水照旧挂在数据层的标记瓦片上，判定照旧在代码仓 `rules/Foundation/Terrain/TerrainCollisionCheck.cs`；地图纪律不变。
- **不配规矩以外的崖**：北边往里凹的拐角、一高一矮挨着、北西东三面的坡道、挨着水的崖脚，理由在[俯视地图用图块表拼 · 崖的形状我们只配方的、只在南边开楼梯](../design/proposals/俯视地图用图块表拼.md)。
- **不做换季**（`ART-22`）：这一张是夏天那一张，四季先都用它。
- **不做水里亮点的闪**（`ART-31`）、**装饰层**（`ART-21`）、**单独一格手改的补丁层**（`ENG-44`）。
- **不判画面**：交界与整片接不接得上、看不看得出重复、崖面的接缝、谁压着谁，都是实机看；交图检查只判格边与崖边两头。
- **色板与硬边不归交图检查**：照旧由代码仓 `tools/check_art.py` 核，跟别的素材一样。
- **不改耕地那一层。**
- **不留旧做法当后备**：配对图与纹理图那一套删干净，不留开关。

## 7. 界面与表现考虑

不涉及界面。表现上要留意的几样：

- **交界那几格与旁边整片接不接得上**：一套里这种地形自己的那一半是画死的，旁边的整块按位置变。草的整块是平的，不受影响；水的整块带纹理时最容易看出来。只能实机看。
- **崖排在地形那几层上面、角色下面，不做前后排序**：高处是方的、崖面只在南边，角色挨着崖面时总站在崖面前面，所以总压在崖上。这是推断，「跑一遍验收」里谁压着谁那一行实机核。
- **配错的报错**：编辑器里是警告，按 `F6` 是报错，跟现在一样；一处一行，写明是哪一层、哪一格、该怎样。

## 8. 技术考虑

- **排法写在代码里，作者不在检查器里填坐标**：要知道各块在表上哪里的，有显示层的画法、崖的载入核对、交图检查与样板生成器，分在 C# 与 Python 两边。排法是图块表的格式、不是调出来的参数，跟 `CodeToAtlasOffset` 一样写在代码里：放在代码仓 `rules/Foundation/Terrain/` 下一张表，交图检查与样板生成器照 `check_dualgrid.py` 现在读 `CodeToAtlasOffset` 的办法读它。检查器里作者只填接线与地形编号：哪一层画哪一种地形、那种地形是数据层里的第几种、图块表是那份 TileSet 里的第几个源。
- **几份 TileSet**：数据层一份，地形集与水的碰撞都在它上面；显示层那几层共用一份，只有图块表一个源，不配地形集、不画碰撞 —— 显示层整层错开半格，挂在它上面的碰撞也会跟着错开；崖那两层共用一份，图块表一个源，带一个物理层。这几份用的是同一张图。
- **数据层怎么迁**：在数据层那份 TileSet 里把图块表加成新的图集源，每种地形标一张标记瓦片，编号照旧，所以接线里填的地形编号不用改。然后用油漆桶、取消勾选 Contiguous，点一下就把整层里同一张旧标记瓦片全换成新的（[Using TileMaps](https://docs.godotengine.org/en/stable/tutorials/2d/using_tilemaps.html) 讲 Bucket Fill 的那一段，内容为合规做过改写）；全换完删掉旧的源。旧的显示层只读每一格的地形编号，所以迁完它照旧画得出来。
- **换过去的顺序**，每一步之后场景都打得开：
  1. 作者：图块表放进代码仓，照上一条迁好数据层。
  2. 我：代码落地，包括排法、显示层的画法、交图检查与样板生成器、载入时那几条核对，以及删掉纹理图那一套。场景还引用着的配对图与 `DualGridPair.cs` 这一步先留着。
  3. 作者：删掉旧的显示层，照「铺天然地形」那一步搭新的几层、接线，存一次场景。
  4. 我：确认 `scenes/farm/farm.tscn` 不再引用配对图与 `DualGridPair`，再删掉它们与旧模板。
  5. 作者：给水的标记瓦片画碰撞（`ENG-27` 那一步），从农场复制一份测试场景、照样板「拼好的样子」拼高处、给崖那几块画碰撞，然后实机。
- **待验证**：作者存一次场景之后，场景文件里 `Pairs` 那一行和它引的那几份 `DualGridPair` 资源会不会自己掉 —— 那个属性在新的画法里已经没有了。删配对图之前搜一遍场景文件；还在的话，跟作者说过再删那几行。
- **地图纪律断了不再报错**：现在的画法在四个角涉及没配对素材的两种地形时报错。按顺序叠，任何组合都画得出来，纪律断了的那一处只是样子不对，比如深水直接挨着草，浅水那一套画在水那半格里的墙面会被深水盖住；刷的时候在编辑器里看得见，所以不另报。纪律本身照旧写在[场景绘制约定 · 基地要画哪几套](../production/场景绘制约定.md)。
- **能锄的那一片认「水」认的是带碰撞的格，不认地形**：压在任何挡人的格上都是同一个毛病，站在旁边锄得到、人却走不进去；以后加了别的挡人地形也照样核得到。所以给水画碰撞之前，这一条只核得到崖。
- **崖那几条核对挂在哪个节点上**、检查器里多哪几格，实现时定，写进指南。已经定下的是：没有崖的场景不放崖那两层，也照样按得了 `F6`，所以农场不用为崖多搭什么；放了就得接齐，缺了当场报错、说清缺谁，几处不对一次全报。
- **整层重画**：照现在的做法，数据层一变就把那几层整层重画。基地那个格数量级不值得做增量，现在的代码注释里是同一个判断。
- **交图检查留在 `verify.py` 的构建之前**：纯 Python、不启引擎。它判的格边在 Godot 里只看得出「接缝不好看」，看不出是哪一格哪条边；而哪两格挨着由玩家刷地决定，所以要它。理由同现在双网格那一步的注释。
- **样板生成器的输出**照旧写到工作区 `art-source/self-material/tiles-template/`，不进代码仓；格边长读代码仓 `rules/UI/UIMetrics.cs` 的基础单位。
- **引擎里跑的测试没有入口**（`tests/` 只测 `rules/`），所以崖的走一遍做成一次性无头场景，照 `ENG-27` 那一次的办法，跑完删。
