# GP-148：日历按天、季、年走，世界状态整份复制得出来

## 目标

日期按天、季、年往前走，开新档从开局那一天开始；日期与那片地合成一份世界状态，整份复制之后改副本不碰原件。

## 来源

- PRD：[`spec/prd-sleep-advances-day.md`](../prd-sleep-advances-day.md) 的 `US-001`（日历那一半）与 `FR-1`。
- 结构要求：[`每日结算系统` · 下游同步](../../design/每日结算系统.md)那条「世界状态要复制得出来」。
- 日历的量在[时间与经营 · 时间](../../canon/gameplay/时间与经营.md)，开局那一天在[玩法定位 · 开局](../../canon/gameplay/玩法定位.md)，本条都不复述。

## 依赖

无。

## 验收标准

- [x] 可测试：日期往前推一天；一季最后一天之后是下一季第一天；最后一季最后一天之后是下一年第一季第一天；年份一直往上加，很大的年份照样进一年。另有一条从开局那一天推满一年、正好落在下一年同一天。
- [x] 可测试：日历里季节的先后是一张写出来的表，季节枚举里每一个都恰好出现一次；往枚举里加一个季节而不排进这张表，测试失败。表在代码仓 `rules/Economy/Calendar.cs` 的 `SeasonOrder`。
- [x] 可测试：年小于 1、日不在一季的天数之内时，日期被拒；不在那张表里的季节也被拒。
- [x] 可核对：日历只有年、季、日三个量，没有「月」；一季几天与季节先后各只写一处，注释指向设计仓正典「时间与经营」的「时间」一节。日期在代码仓 `rules/Economy/GameDate.cs`。
- [x] 可测试：开新档时日期是开局那一天；它是一个规则常量（`Calendar.StartDate`），注释指向设计仓正典「玩法定位」的「开局」一节。

- [x] 可核对：那片地改由规则层的世界状态持有，农场节点（代码仓 `src/World/Farm/FarmField.cs`）读写它、自己不再持有地块。世界状态在代码仓 `rules/Economy/WorldState.cs`，那片地在 `rules/Economy/PlotGrid.cs`。

## 实现笔记

### 设计决策

- **模糊点**：一年里季节的先后从哪来。
- **选择**：日历里一张写出来的先后表，不读季节枚举的声明顺序；枚举里每个季节都要在表里恰好出现一次，有测试盯着。
- **理由**：季节枚举的注释写明它的顺序不参与任何判定。读声明顺序的话，调一下枚举就悄悄换了日历，而那不报错。

- **模糊点**：一格地怎么复制。
- **选择**：浅拷贝，外加一条测试钉住地块的字段全是值类型与字符串。
- **理由**：逐项复制在加一个字段时会漏，漏了不报错；浅拷贝对现在这些字段就是整份拷贝，而它不成立的那一天（加了一个会变的引用类型字段）那条测试会失败。

- **模糊点**：那片地的格坐标在规则层用什么类型。
- **选择**：规则层自己的一格（代码仓 `rules/Economy/GridCell.cs`），农场节点与瓦片层的格坐标互换。
- **理由**：规则层不引用 Godot（编译器强制）。它写成文字与引擎的格坐标同一个样子，日志里两边对得上。

- **模糊点**：日期怎么改。
- **选择**：世界状态只给一个「往前推一天」的方法，日期本身没有公开的写法。
- **理由**：日期只该被每日结算的「日期推进」那一步改；只留这一个口，`GP-149` 那一格「推进日期的地方只在这几步里」按名搜得到。

### 偏离

无。

### 权衡

- **`N` 仍只推那片地、不推日期**：日期推进那一步与 `N` 改走结算入口都在 `GP-149`。现在让 `N` 推日期，就是在那串步序之外多开一个推进日期的地方。
- **开局那一天是规则常量，不是检查器里的一格**：它是正典定的，不是要调的数。
