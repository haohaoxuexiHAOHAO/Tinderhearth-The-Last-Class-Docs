# GP-123：同稀有度的两件宝物差距小，而拿到好东西仍然爽

## 目标

同一稀有度同品质的两件宝物几乎一样，所以开不出废品；惊喜改由「你拿到的是什么」承担，而不是「它掷了多少」。

## 来源

- PRD：[`prd-extensible-lists`](../prd-extensible-lists.md) 的 `US-005`
- 上游：[`物品系统`](../../design/物品系统.md)那条分工 —— 稀有度答「有几条副词条」、品质答「每条有多强」。本条全部搭在它上面，不新开第三条轴

## 依赖

无。本条那张正负条数表要的副词条条数上限由 `GP-122` 给，状态查[待办台账](./README.md)。落地跟 `GP-24` 走。

## 验收标准

### 差距的上界

- [ ] 副词条里正负各几条**按稀有度固定、不随机**：低档 1 条负面，中档 1 正 1 负，高档 2 正 1 负
- [ ] **负面永远只有 1 条** —— 这是「被坑得多惨」那一侧的上界
- [ ] 可测试：构造一件正负条数与它的稀有度不符的实例时被拒
- [ ] 立一条约束形式：单条副词条的掷定波动不得大到让同稀有度同品质的两件差出一个品质级差
- [ ] 立第二条：品质的级差必须大于同级内的掷定波动 —— 否则「这件是传奇」在面板上看不出来
- [ ] 这两条登记进[数值模型](../../design/数值模型.md)的尚未给值表，值归 `GP-7`，并写明给值那一轮要把它们接成判据

### 爽感的落点

- [ ] 一件宝物的光环**必须改变一条机制**，只给数值修饰的定义载入被拒；判据与[`技能系统` · 宝石：改机制，不只是改数字](../../design/技能系统.md)那条同一条，**不新造判据**
- [ ] 可测试：一件宝物的光环只声明「某个量乘一个系数」时载入被拒
- [ ] 那五处惊喜的来源在[`装备系统`](../../design/装备系统.md)写明，各指回它现成的依据（宝物件数与各自的光环、品质级差、副词条组合、稀有度换形状、那件纯增益唯一装备）

### 两条边界

- [ ] **最低那一档是过渡品，这是刻意的。** 它只有一条正面主词条与一条负面副词条，净收益可能接近零 —— 玩家一眼看得出该早点换掉。**不给它开纯增益的口子**（那会撞破 [ADR-0011](../../decisions/ADR-0011-纯增益装备的窄例外.md)，那条窄例外的对象是几件唯一装备而不是一整档），**也不靠「把负面幅度压得很小」缓解**（那是个值，压多小要等 `GP-7`，于是问题一直没有答案）
- [ ] **「刷到极品」那条路刻意没有。** 不做重掷、波动又窄，换来的是不开废品；两者只能选一个，这一条要写明是取舍而不是遗漏
