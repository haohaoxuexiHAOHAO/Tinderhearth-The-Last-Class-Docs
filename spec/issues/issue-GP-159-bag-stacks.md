# GP-159：背包装东西：按种类与品质分堆，满了整份拒收

## 目标

主角的背包按「种类 ＋ 品质」摞成堆、堆到上限再占下一格，满了整份拒收、一件不变；格数与堆上限都从数据读。

## 来源

- PRD：[`spec/prd-items-in-bag.md`](../prd-items-in-bag.md) 的 `US-003` 前半。

## 依赖

- `GP-157`：堆上限与有无品质读物品定义。

## 验收标准

- [x] 可测试：同种同品质合进一堆、堆到那种物品的堆上限再占下一格；同种不同品质各占一格；无品质的只按种类分堆。反过来构造一次「不同品质被合进一堆」的断言，必须失败。
- [x] 可测试：满载 = 没有可合的同标识堆且没有空格；格子用尽但有半满的同标识堆时照样放得进去。两个方向各一条用例。
- [x] 可测试：一次放进去的那一份放不下时整份被拒，背包一件不变。
- [x] 可测试：格数按背包等级从配置读（代码仓 `data/config/game.json`），缺了当场报错；等级在这一份里固定为第一级。堆上限按种类从物品定义读。
- [x] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。

## 实现笔记

### 设计决策

- **先算、全放得下才动手。** 代码仓 `rules/Economy/Bag.cs` 放进一份之前先算出每一格各放几件（先按格号合进没满的同标识堆，再按格号占空格），算不出就一件不放。同一个「算」也单独露出来（放不放得下、这一种是不是满载），收获那一道闸要在动地块之前问它（`GP-161`）。
- **调用方给错的当场抛，不当成放不下。** 物品不在册、有品质的没带品质、无品质的带了品质、品质不在册、件数不为正，都是调用方的错；「放不下」只留给真放不下那一种，否则一处接错会显成背包满了。
- **每一堆记着最近一次进东西是第几次。** 排序那三个键里有「最近获得」（`GP-160`），而背包的内容要进存档（`GP-162`）；这一位现在就在堆上，存档那一片从第一版起就带着它，不必为排序再升一次存档版本。
- **格数按背包等级从配置读。** 代码仓 `data/config/game.json` 多一项每一级几格，值照设计仓 `design/numeric-model-params.json` 的 `capacity.backpack_slots_by_level` 抄过去；开新档时是第一级，没配的那一级当场抛。背包升级跟内容与经济那一侧走（`GP-23`）。
