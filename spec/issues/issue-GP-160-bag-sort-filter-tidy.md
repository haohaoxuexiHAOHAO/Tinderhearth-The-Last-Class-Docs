# GP-160：背包里的排序、筛选、一键整理、挪格与丢弃

## 目标

规则层上，背包能排序、筛选、一键整理、挪格与丢弃，每一样都守[背包系统 · 分堆的代价由排序、筛选与一键整理来付](../../design/背包系统.md)那几条硬约束。

## 来源

- PRD：[`spec/prd-items-in-bag.md`](../prd-items-in-bag.md) 的 `US-003` 后半。

## 依赖

- `GP-159`：背包本体。

## 验收标准

- [ ] 可测试：排序三个键（品质、类别、最近获得）各排一次，同键排两次结果相同。
- [ ] 可测试：筛选按类别与按品质，筛选态下挪格与丢弃的结果与未筛选时相同，被筛掉的不动。
- [ ] 可测试：一键整理把同标识的散堆并成一堆、再按当前排序键重排；总数一件不变、不跨容器；没有散堆时它是空操作。
- [ ] 可测试：把一堆挪到另一格，目标格空着就搬过去，有东西就两格互换。
- [ ] 可测试：丢弃把一整堆移出背包；物品声明了不可丢弃的，丢弃被拒并说清是这一种。丢之前那一道确认在界面侧（`UI-66`），规则层只管确认之后那一下。
- [ ] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。

### 待确认

- **排序与一键整理碰不碰随身栏那几格（`UI-39`）**：随身栏按位置读背包开头那几格（`UI-60`），所以排序与一键整理会换掉玩家手上那一格装的东西，而[`背包系统` · 分堆的代价由排序、筛选与一键整理来付](../../design/背包系统.md)那条「不做撤销」自己写着：出现按格号读背包的东西，撤销就得跟着补上。**推荐：排序与一键整理只动随身栏之后的那些格**，随身栏那几格只有玩家自己挪格时才变。这样手上那一格不会被整理换掉，「不做撤销」照旧成立，理由换成「承载语义的只有随身栏那几格，而整理与排序不碰它们」。被放弃的两条：给整理加撤销（每整理一次手上那几格照样被洗一遍，撤销只救得了误点）；判成「不算按格号读」（玩家没动手上那一格、那一格却换了东西，正是那条判据要挡的）。作者定了之后改那一节与理由那一节的两处，再改本条验收。
