# GP-160：背包里的排序、筛选、一键整理、挪格与丢弃

## 目标

规则层上，背包能排序、筛选、一键整理、挪格与丢弃，每一样都守[背包系统 · 分堆的代价由排序、筛选与一键整理来付](../../design/背包系统.md)那几条硬约束。

## 来源

- PRD：[`spec/prd-items-in-bag.md`](../prd-items-in-bag.md) 的 `US-003` 后半。

## 依赖

- `GP-159`：背包本体。

## 验收标准

- [x] 可测试：排序三个键（品质、类别、最近获得）各排一次，同键排两次结果相同。另有一条打乱了再排还是同一个样子：排出来的顺序只看每一堆自己，不读原来的格号。用例在代码仓 `tests/Economy/BagArrangementTests.cs`，下同。
- [x] 可测试：筛选按类别与按品质，筛选态下挪格与丢弃的结果与未筛选时相同，被筛掉的不动。按大类筛连它下面的小类一起看得见；挪格与丢弃碰到被筛掉的那一格当场抛。
- [x] 可测试：一键整理把同标识的散堆并成一堆、再按当前排序键重排；总数一件不变、不跨容器；没有散堆时它是空操作。「空操作」按「没有散堆、又已经按当前键排好」测，另有一条整理两次与一次一样，理由见「偏离」。
- [x] 可测试：把一堆挪到另一格，目标格空着就搬过去，有东西就两格互换。
- [x] 可测试：丢弃把一整堆移出背包；物品声明了不可丢弃的，丢弃被拒并说清是这一种。丢之前那一道确认在界面侧（`UI-66`），规则层只管确认之后那一下。
- [x] 可测试：排序与一键整理不碰随身栏那几格。用随身栏自己的格数测，排序与整理前后随身栏读到的那几格一格不变；反过来不留那几格时，同一批东西会挪进去。
- [x] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。

## 实现笔记

### 设计决策

- **排序与一键整理只动随身栏之后的那些格**，随身栏那几格只在玩家自己挪格时才变。这一条写进了[`背包系统` · 分堆的代价由排序、筛选与一键整理来付](../../design/背包系统.md)，「不做撤销」照旧成立、理由换了，被放弃的两条在同一页的理由那一节。背包那一侧不认识随身栏：开头几格不动由调用方给格数，规则层的经营那一侧照旧不依赖界面那一侧。
- **筛选态下排序与整理只在看得见的那几格里重排**，空格算看得见：被筛掉的那几堆待在原地。不筛时同一条就是把东西挪到前面、空格留在最后，两种情况走的是同一条规则。
- **排序的先后只由每一堆自己的内容定**：每个键先比自己那一项，比不出来再依次比类别、种类、品质、件数与先后序号。品质与类别按在册的先后比，类别按从大类往下走的那一串逐段比，于是一个大类下面的小类挨在一起。按品质时好的在前、没有品质的排在最后；按最近获得时新的在前。
- **一键整理只并没装满的那几堆**：同一种同一品质的散堆并成满堆加至多一个零头，记参与合并的那几堆里最近的那个序号；原本装满的那几堆不动件数也不动序号。挪格是两格互换，同标识的两堆挪到一起也不合堆。
- **当前排序键与筛选条件是背包页那几个控件的状态**（代码仓 `rules/Economy/BagControls.cs`），不进存档，进来时是按类别、全部都看。与随身栏选中位不存同一个理由（需求的「非目标」那一节）。按类别当起点，是因为没挑过键就点整理时，玩家多半要的是同一类的东西摆在一起。

### 偏离

- **方案怎么说**：没有散堆时一键整理是空操作。
- **实际怎么做**：没有散堆、但还没按当前键排好时，整理照样重排；「空操作」按「没有散堆、又已经排好」测，另测整理两次与一次一样。
- **为什么**：整理的后半就是按当前键重排。照字面做，没有散堆时点整理什么都不发生，而东西明明是乱的，玩家会读成按了没反应。

### 权衡

- **排序与整理不碰随身栏那几格，代价是那几格只能手动整**：玩家挪格时把东西放进去、拿出来。换来的是手上那一格永远是他自己放的那一样，「不做撤销」也不必翻过来。

### 待确认

无。
