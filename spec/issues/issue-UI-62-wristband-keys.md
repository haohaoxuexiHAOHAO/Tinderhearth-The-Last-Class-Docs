# UI-62：打开手环与直达三页的键

## 目标

`Tab` 打开手环，`B`、`M`、`C` 直达背包、地图与角色面板，手柄 `Start` 打开手环；直达键开的是手环的那一页，不是第二个面板。

## 实现笔记

### 设计决策

- **直达键打开的是手环里的那个页签。** 背包、地图与角色面板各是手环的一个顶层页签，直达键落在那个页签的第一个可用子页上，所以按 `B` 落在背包那一页。哪个键开哪个页签只登在规则层一处，与开关的判定在同一个文件里。
- **每个键都是按一下开、再按一下关。** 开着时按开手环的键，或者按停着的那个页签的直达键，就关上；按别的页签的直达键就换过去、焦点跟着过去。开手环的键也管关，是因为开着时再按没反应的话，玩家分不清是键没绑上还是它本来不管关；需求只写了直达键这一半。开手环的键打开时停在上一次停的那个页签。
- **别的界面在最上面时几个键都不理**，手环关着、只开着一个弹窗时也一样。那时接管输入的是那一个（醒来那个摘要窗这一类），越过它开关手环，不是把它压在手环底下，就是让手环垫在它底下。
- **键由手环自己听**，经输入门面问、每帧一次，作者在检查器里多接一格输入门面，不另摆一个节点。门面那道闸关着时什么都读不到，睡下到醒来那一段因此按不开。手环挂在面板那一层，那一层在世界暂停时照跑，所以开着时同一个键关得上。开关一律经界面根的导航栈。
- **界面根打开一个没登记的界面当场抛**（代码仓 `src/UI/UIRoot.cs`）。原样放过的话，它进了导航栈、世界停了，屏上却什么都没出来，而那不报错：手环没直接摆在界面根下面，按 `Tab` 就是这个样子。醒来那两个窗走的也是这一处。
- **手柄上只给开手环绑了 `Start`**，三个直达键在手柄上是登记过的豁免。进了手环换页签现在靠焦点走过去；用肩键换页与 `Select`、右摇杆按下那两个符号归 `UI-54`。

### 偏离

- **方案怎么说**：睡下到醒来那一段按这几个键打不开手环，可测试。
- **实际怎么做**：规则层不另判那道闸；起一个一次性场景实测一次（见验证结果），加上可核对的一条：这几个键只经输入门面问，门面在闸关着时什么都读不到，关闸的是睡觉那一段。
- **为什么**：闸判在引擎那一侧的门面里，规则层的用例碰不到它。为了能测，在规则层再传一份闸的开关进来，测到的只是那一份副本，真正会坏的那一处（有人绕过门面直接读按键）照样测不到。

### 权衡

- **作者在手环上多接一格。** 换来的是农场里不多一个只为听键而摆的节点，与「作者只摆手环那一个节点」那一条对得上。
- **`Tab` 也是引擎内置的切焦点键。** 手环开着时按 `Tab`，焦点先挪到下一个页签、手环再关上，看不出来；关着时没有焦点，切焦点那一下什么都不做。这一条是按引擎行为推的，实机那一趟顺带看一眼。
