## 实现笔记

### 设计决策

- **模糊点**：六条渠道差异很大（钓鱼有互动、种植有地块、设备不占人力），一份文档装得下吗。
- **选择**：本页只持有**共用管道**（产出 → 归属 → 付酬 → 入库，顺序固定），渠道之间的差异收敛成**四格**：产什么、耗多少、品质读哪项生活技能、有没有自己的状态机。
- **理由**：加第七条渠道时要填的是那四格，不是再发明一套管道。四个环节里「归属排在付酬之前」是硬顺序 —— 反过来会出现「花钱买本来就归自己的东西」。

### 偏离

- **方案怎么说**：`GP-28` 依赖 `GP-26`，排在它之后单独做。
- **实际怎么做**：和 `GP-26` 同一轮做完了。
- **为什么**：`GP-26` 往正典写了三处指向本页的链接，本页不存在就是断链、检查器当场报。与其把链接降级成纯文字再回来补，不如按 PRD 自己写的那条「正典与它服务的系统文档同批交付」直接做完。

### 权衡

**拆分判据写在文档里而不是现在决定**：「有没有自己的状态机」就是判据，按它现在只有「开荒与种植共用的地块」一条候选。所以种植那节若长过其余五条之和就拆出 `design/种植系统.md`，这个判断按篇幅实际做（记在 `GP-29`），不预先拍。

### 待确认

无。钓鱼手感、设备「在转／缺料」的呈现归作者实机看。
