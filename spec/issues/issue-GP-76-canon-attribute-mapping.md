# GP-76：正典改掉四项属性的作用方向

## 目标

正典里力量与敏捷各自给什么改成新的分法，且全库对这件事只有一份说法。

## 来源

- PRD：[`spec/prd-attribute-payoff-rebalance.md`](../prd-attribute-payoff-rebalance.md) 的 `US-001`

## 依赖

无。它是本轮其余条目的前提 —— 正典是权威层级的上游，设计侧那几份跟着它改。

**它同时是这一轮需求的归档编号**，所以本条关闭之后仍留在台账，不新开第二条登记行。

## 验收标准

- [x] [角色与成长 · 四项属性的作用方向](../../canon/gameplay/角色与成长.md) 里力量那一条写明它给物理攻击、给命中时对目标累积的失衡值增量，并给体力劳作的精力折扣
- [x] 同一节敏捷那一条不再出现「移动速度」与「攻击速度」，写明它给暴击、闪避冷却与体力条的关卡内回复速度，且**没有施法读条速度**（那条判据与三个量的处置在 `GP-80`）
- [x] 同一节写出力量与体质在失衡这条轴上是一对（力量推高对方的失衡值、体质撑高自己的韧性上限），且韧性上限仍挂在体质
- [x] 同一节写出那条判据（这活靠力气，还是靠手艺、时机与口舌），并写明具体哪几项由各生活技能自己声明；**正典里没有那张清单**
- [x] 同一节那句「不得出现某一项属性在任何构筑下都严格优于另一项」的括号说明与改完的分法一致（原文点名「体质派生的东西比力量多」，已改成「四项各自派生的东西不一样多」）
- [x] [战斗与关卡 · 三条资源](../../canon/gameplay/战斗与关卡.md) 那张表里体力条的回复一栏写出敏捷是它的来源
- [x] [玩法定位](../../canon/gameplay/玩法定位.md) 系统清单里角色面板那一行改成指回正典那一节、不复述哪几项带经营侧作用
- [x] [战斗与关卡 · 按键与连击](../../canon/gameplay/战斗与关卡.md) 那条「闪避有冷却、敏捷缩短它」一个字未改
- [x] `python tools/check_docs.py` 0 FAIL

## 实现笔记

### 设计决策

- **模糊点**：力量拿了经营侧作用之后，敏捷成为唯一没有经营侧作用的一项 —— 要不要给它也补一条。
- **选择**：不补，并把「敏捷是唯一没有经营侧作用的一项」显式写进正典。
- **理由**：补一条就得先回答「灵巧让哪件活变好」，而那个问题没有不牵强的答案；硬补会长出一个没人用得上的量。显式写出来比留白好 —— 留白会让下一个读者以为漏了一项，于是有人来补。

- **模糊点**：「失衡值」与「活跃失衡」在同一页出现，正典自己要求两者同时出现时写全名。
- **选择**：在属性那一节加一句点明这里说的是战斗内那条会衰减的累积量，并链到本页的活跃失衡那一节。
- **理由**：属性那一节原先不涉及活跃失衡，现在涉及了，那条既有纪律就落到了这一处。

### 偏离

- **方案怎么说**：`US-001` 的验收里写「[玩法定位] 系统清单里角色面板那一行的『经营侧作用』说法与改完的映射一致」。
- **实际怎么做**：改成那一行不再说哪几项带经营侧作用，只指回正典那一节。
- **为什么**：把数目写在两处就是给同一个事实开两个家，而这一轮改的正是它 —— 同步一次不如取消一处。

### 权衡

考虑过把韧性上限从体质挪到力量，让力量的量更多。放弃了：那会让失衡这条轴的两头挤在同一项属性上，「力量推、体质撑」这对就没了，而那对正是力量新身份的来源。
