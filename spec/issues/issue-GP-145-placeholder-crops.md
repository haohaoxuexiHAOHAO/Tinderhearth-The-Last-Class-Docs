# GP-145：素材表上每一种作物都有一份占位数据，启动时就解析

## 目标

素材表上每一行都是一种种得下去的作物：各有一份作物定义、一个名字与一段描述，游戏一启动就逐份解析，坏一份当场报错。

## 来源

- PRD：[`spec/prd-crop-sheet.md`](../prd-crop-sheet.md) 的 `US-006`（`FR-12`）。
- 素材表每一列是什么在那份需求的「概述」里，本条不复述。

## 依赖

无。数据是占位：正式的作物清单归 `GP-88`，阶段天数这类数值归 `GP-7`。

## 验收标准

- [x] 可核对：代码仓 `data/crops/` 下素材表每一行一份作物定义，标识按行号补零取，排序与行序一致；试验用的那一份删掉。标识是 `crop_01` 起，数字就是行号。
- [x] 可核对：每份都是三个计时阶段各 1 天、只收一次、四季都能种，文件里写明这是占位值、归 `GP-88` 与 `GP-7`。
- [x] 可核对：文本表每种作物一个名字、一个描述，占位写成「作物N」「作物描述N」；正式文案只改这一处。键是 `crop.标识.name` 与 `crop.标识.description`，在代码仓 `data/text/zh-CN.json`。
- [x] 可核对：游戏启动时逐份解析作物定义并打出在册数；有一份解析失败，代码仓 `python tools/verify.py` 的跑产物那一步判失败。读在代码仓 `src/Main.cs` 的 `LoadCrops`，打出「[启动] 作物定义 N 份」，那一行也是跑产物那一步认的标记。

## 实现笔记

### 设计决策

- **模糊点**：作物的名字与描述放哪 —— 像角色那样在定义上加一格键名，还是由标识拼键。
- **选择**：由标识拼键，定义上不加字段；一种作物要文本表里有哪几条由定义自己列出来（代码仓 `rules/Economy/CropDefinition.cs` 的 `TextKeys`），启动时按它核。
- **理由**：作物的正式名字归物品定义的名称那一格（[数值模型](../../design/数值模型.md)那条「不占命名权」），而物品定义还没有（`GP-22`）。现在加一格键名，等物品定义来了名字就有两个家。

- **模糊点**：文本表里缺一种作物的名字或描述，启动时该停下来还是只报。
- **选择**：打一条错误、游戏照跑，错误里点名缺的那几个键。
- **理由**：与文本表缺键显成占位、不抛是同一个理由（代码仓 `rules/Foundation/Text/TextCatalog.cs`）：一个 mod 漏写一句描述，不该让整个游戏起不来。错误那一行照样让跑产物那一步判失败。

- **模糊点**：坏一份时报错要不要说是哪一份。
- **选择**：按标识建表那一处（代码仓 `rules/Foundation/Content/ContentCatalog.cs` 的 `ResolveById`）把解析抛的报错包一层，写上文件与来源，原来那条留作内层；角色也走这一处，一起受益。
- **理由**：实测一份作物定义缺一个键，序列化器的报错只说缺了哪个属性、不说哪个文件，而作物一种一份，不点名就只能一份份去试。

### 偏离

无。

### 权衡

- **怎么读、什么算坏只有一处**：主场景与农场都调代码仓 `rules/Economy/CropDefinition.cs` 的 `LoadAll`，一份都没有也是在那里报。农场不是主场景，只在农场里读的话，坏一份要进了农场才报错，导出冒烟判不到。
- **跑产物那一步多认一行「[启动] 作物定义」**：启动时那次读作物被删掉，verify 当场就红，不会悄悄回到只有进农场才报错。代价是脚手架换成正式启动流程时这一行要跟着改；标记与源码脱节时那一步会说清。
- **每份数据文件只写一段占位说明、指向字段表**，不逐字段写说明：同一段说明抄进每一份，改一份其余的不报错。字段各是什么在[`地块系统` · 作物定义：一张表，缺字段报错](../../design/地块系统.md)，填错时载入的报错说得清是哪一项。
