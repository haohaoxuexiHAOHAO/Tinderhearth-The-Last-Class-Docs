# ENG-42：图块表接进游戏的端到端

## 目标

一趟走完就知道新地面、水边石壁与崖都对，配错会报；这一份与[水边砌一道石壁](../prd-shore-stone-wall.md)那一份一起收尾。

## 来源

- PRD：[`spec/prd-outdoor-tile-sheet.md`](../prd-outdoor-tile-sheet.md) 的 `US-007`。
- 并进来的：`ENG-41`（石壁那一份的端到端）、`ART-33`、`ART-34`、`ART-35` 剩下的核对与实机，`ENG-25` 剩下的「在编辑器里刷一片看」。

## 依赖

- `ENG-46`、`ENG-49`、`ENG-50`、`DOC-161`；它们上游是 `ENG-45`、`ENG-47`、`ENG-48` 与 `ENG-43`。
- 作者：从农场复制一份测试场景，照样板「拼好的样子」拼高处、给崖那几块画碰撞。

## 验收标准

- [ ] 自动化：`ENG-47`、`ENG-48`、`ENG-43`、`ENG-50` 的规则层单测进代码仓 `python tools/verify.py`，可重复。
- [ ] 自动化：交图检查对图块表通过，故意改错的副本报得清（`ENG-46`）。
- [ ] 自动化（一次性无头场景，跑完删）：在作者的测试场景里，一个与农场角色一样大的碰撞体从崖脚朝北走，停在崖脚；从楼梯往北走，走得到顶上；在顶上朝北、西、东、南各走一次，都停在边上、走不下去。失败路径：崖底下那一层关掉 `Collision Enabled`，载入当场报错，说清是哪一层。再拿一块压着崖的矩形与一块哪都没压着的矩形各核一次能锄的那一片：前者列出压着的格，后者不报。结果与删了什么写在「验证结果」里。
- [ ] 可核对：代码仓 verify 全过；设计仓 check_docs 0 FAIL。
- [ ] **作者实机确认清单**：照下面「作者实机清单」走。

## 作者实机清单

先照[一块地能种出东西](../../reference/godot/一块地能种出东西.md)「让水挡住人」那一小节，给水的标记瓦片画上碰撞；那一趟照 [`ENG-27`](./issue-ENG-27-terrain-blocks-walking-e2e.md) 的清单走。再照「跑一遍验收」那张表按行名对号，怎么做只写在那张表里：

| 那张表的行名 | 对应哪一条 |
| --- | --- |
| **看不出格线** | 本需求 `US-002`：一大片草与水看不出格与格之间的接缝，也看不出同一块图案一格一格地重复 |
| **两边的草一样** | 本需求 `US-002`：一块草一边挨着裸土、一边挨着水，两边的草长得一样 |
| **裸土与耕地分得开** | `ART-34`：裸土的整块与耕地并排，一眼分得开 |
| **北岸露墙面** | `ART-33`：北岸看得到墙面，墙脚一道亮的水线，墙面下方的水里有倒影 |
| **南岸看不见墙** | `ART-33`：南岸看不见墙，只有草边 |
| **两侧是石壁的侧面** | `ART-33`：左右两岸是石壁的侧面，只露一窄条暗石头 |
| **拐角接得上** | `ART-33`：内外拐角都接得上 |
| **纹理铺到石壁** | `ART-33`：草地与水面的纹理一直画到石壁，和旁边整片的接得上 |
| **停在墙顶** | `ART-33`：朝水走过去，人停在墙顶的岸上，不像浮在水面上，也不像陷进墙里 |
| **土边一簇簇的草** | `ART-34`：草挨着裸土的边是一簇簇探出去的小草，草的影只落在草南边的土上 |
| **深水北边的坑壁** | `ART-34`：深水北边看得见水下的坑壁；别的方向只有坑沿一道细线 |
| **三套一个画法** | `ART-34`：三套放在一起，草边、石壁与深水边像一个人画的 |

`DOC-161` 往那张表里加的几行（刷一笔就跟着变、拐角是圆的、崖那几行在测试场景里看、配错会报那几行），加上之后在这里补上行名与对应哪一条：刷一笔那一行对 `ENG-48` 与 `ENG-25`，崖那几行对本需求 `US-004` 与 `ART-35`。全部看完，这一格与 `ENG-41`、`ART-33`、`ART-34` 里作者实机那几格一起勾，`ART-35` 也一起收。
