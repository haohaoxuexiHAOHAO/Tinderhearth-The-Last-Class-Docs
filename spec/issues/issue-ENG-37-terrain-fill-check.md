# ENG-37：纹理声明的检查，载入时与交图时各核一遍

## 目标

作者给天然地形配纹理时，配错的那几种情形在载入时一次全报、说清错在哪；交纹理图时，交图核对判得出它是不是全不透明、宽高是不是整格。

## 来源

- PRD：[`spec/prd-terrain-texture.md`](../prd-terrain-texture.md) 的 `US-002`（判定那一半）与 `US-003`。两条核的都是「纹理图与它的声明守不守规矩」，有一条规矩相同（宽高是整格），所以合成一条。

## 依赖

无。

## 验收标准

- [x] 可测试：规则层的判定（代码仓 `rules/Foundation/Terrain/TerrainFillCheck.cs`），交进去「数据层地形集里有哪几种地形、每一项声明了什么、各地形读出来的主色、格边长」，报出：没声明的地形；声明了数据层里没有的地形；同一种地形声明了两次；一项既没给纹理图也没写不铺，或两样都给了；纹理图宽或高不是格边长的整数倍（说出实际多大）；两种地形读出来的主色相同；配了纹理图的那种地形读不出主色（没有哪一套双网格认得它）。
- [x] 可测试：几处同时错时一次报全、顺序固定；声明齐全、尺寸都对时不报；一项都没声明时不报 —— 那是「不铺纹理」，由 `ENG-38` 照旧画地面。
- [x] 可核对：用例进代码仓 `tests/Foundation/TerrainFillCheckTests.cs`，`python tools/verify.py` 全过。
- [x] 可核对：代码仓 `python tools/check_art.py` 核纹理图那个目录（`res://assets/self-drawn/tiles/fill/`）：全不透明、宽高都是格边长的整数倍，不合的逐张报出；格边长从规则层的基础单位读，不另写一个数。只用色板色那一条它本来就核。
- [x] 可核对：拿一张故意做坏的图（带透明、宽不是整格）跑一次 check_art，两条都报出来；跑完删掉那张图，在「验证结果」里写明。

## 实现笔记

### 设计决策

- **一项都没声明是「不铺纹理」，判定返回空表**：PRD 的 FR-8 要求那时地面照旧画。声明了任意一项，才要求每种地形都有一项。
- **一项里纹理图与 No Fill 二选一，两样都给、都没给都报**：「这种地形没有声明」由「没有这一项」表达，一项本身就只剩两种合法写法。两样都给的时候读不出作者要哪一样。
- **另报两种 PRD 没点名的配错**：数组里空着的一格（没建资源），与没填 Terrain 的一项。它们在检查器里最常见，不报的话会落成「某种地形没有声明」，指错了地方。
- **主色撞了只在其中一种要铺纹理时报**：两种都不铺时没有像素会被换掉。**读不出主色也只在那种地形配了纹理图时报**。
- **格边长由调用方交进来**：载入时用数据层 TileSet 的 Tile Size，那是游戏里真正对齐的网格；交图核对在引擎外，读规则层的 `UIMetrics.BaseUnit`。
- **颜色用 8 位整数**（`Rgb8`），报错里写成 `#RRGGBB`，与色板里的值逐位比。
