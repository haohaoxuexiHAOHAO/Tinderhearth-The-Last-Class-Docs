# GP-103：敌人的出手只有一份定义，而且查得出它有哪几招

## 目标

敌人的每一招都查得出它能不能被打断，而那条「全部敌人合起来覆盖每一种对策」的载入校验有可遍历的对象。

## 来源

PRD：`spec/prd-richness-and-feel.md` 的 `US-003`。

立项理由：[`技能系统`](../../design/技能系统.md)写明不碰敌人的招，而[`战斗AI系统`](../../design/战斗AI系统.md)说敌人的恢复手段走技能、分级面板也给敌人一栏技能。结果是「能不能打断」那一格在攻击定义上，而要被打断的那一招在技能定义上。同一处还缺一格：**敌人定义与它的攻击定义之间没有任何引用**，所以那条覆盖校验现在不知道该遍历什么。

## 依赖

无。文档侧可以现在就改；落地跟 `GP-36` 与 `GP-31` 走。

## 验收标准

- [x] 两份文档对「敌人的招是什么」只有一种说法，恢复类也在其内 —— 那张表**改名为出手定义**，装攻击与恢复两类，见下面「偏离」
- [x] 敌人定义的字段表里有指向出手定义的那一格，缺了载入报错 —— **那一格原来就在正典里**，是分级面板上「技能」那一栏，见「设计决策」
- [x] 那条覆盖校验写得出遍历路径（敌人定义 → 它声明的那几条出手 → 每条声明的对策）
- [x] 那句「敌人被打断不退还 MP」有落点 —— 出手定义加了**耗蓝**一格，并写明它在预警开始那一刻扣、被打断不退还
- [x] `python tools/check_docs.py` 0 FAIL（术语表多一条词条，`出手定义`）

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：「敌人定义指向它有哪几招」这一格该新加，还是已经存在。
- **选择**：**已经存在** —— 正典给敌人的分级面板里有「技能」那一栏，本轮只写明它对敌人指向出手定义。
- **理由**：新加一格会与正典那一栏并存，于是「它有哪几招」有两个家。写成「那一栏是一份指针，两侧指向不同的表」之后，正典一个字不用改，而[`技能系统`](../../design/技能系统.md)那句「敌人的招不走技能那张表」也照旧成立。

### 偏离

- **方案怎么说**：敌人的一切出手统一走**攻击定义**（沿用原名），技能那一格只给主角与队友。
- **实际怎么做**：那张表**改名为出手定义**，并加了「类别」（攻击／恢复）一格。全库共 8 份文档跟着改；[ADR-0023](../../decisions/ADR-0023-帧动画决定手感上限与技能归属.md) 是历史件，**正文不改、只在文首加一行改名注**；[术语表](../../reference/术语表.md)新增词条并写明旧名。
- **为什么**：一张装着治疗手段的表叫「攻击定义」是让名字说谎，而这条判据全库都在用（`数值模型` 不叫「数值模型系统」就是同一条）。改名代价是 8 份文档的词，**代码里零处引用**，所以这笔很便宜；不改的代价是每个读者第一次看到「治疗走攻击定义」都要被绊一下。

### 权衡

考虑过让敌人的招**就是技能**、把预警／窗口／对策三格加到技能定义上。否决理由：技能带的那一串（归属角色、占技能位、靠书学会、实战值在命中时累积）对敌人全是空的，而敌人要的那三格对主角全是空的 —— 合成一张表等于让两侧各带一半永远填不上的格子，而[ADR-0018](../../decisions/ADR-0018-内容定义按声明扩展.md) 要求「它没声明这项能力」与「它漏填了」必须分得出来，两侧各一半空格会让那条校验判不动。

### 待确认

**一处顺带发现，没有顺手修**：敌人的实战值那一栏写着「唯一的读者是技能孔解锁」，而敌人的招现在走出手定义 —— 出手定义上有没有技能孔本轮没定。它不影响本条的四个验收项（预警、对策、引用格、耗蓝都齐了），但落地前要答。**留在本条的待确认里，跟 `GP-36` 一起判** —— 单独立一条编号会让它与本条抢同一件事。
