# GP-121：技能的作用目标与形态写明是代码的事

## 目标

读文档的人知道这两格加一个取值必须写代码，不去数据文件里白试；而这处对 mod 的收窄在文档里查得到。

## 来源

- PRD：[`prd-extensible-lists`](../prd-extensible-lists.md) 的 `US-003`
- 判据：[ADR-0025](../../decisions/ADR-0025-取值集的家由加一个的代价决定.md) —— 加「一条直线」要一份新的目标选择器，加一种形态要一整套新的槽位规则，两样都是新逻辑

## 依赖

无。

## 验收标准

- [x] [`技能系统` · 一个战斗技能要声明的字段](../../design/技能系统.md)对这两格写明它们归代码，加一个取值算一次改设计、要先立项
- [x] **那处对 mod 的收窄显式写出来**，并指回 [玩法定位 · mod 的扩展边界](../../canon/gameplay/玩法定位.md) —— 不写的话，读者按那条承诺去试会白试，而白试不报错
- [x] **形态那一格不改成按能力声明**，理由写进了文档：三格拆开之后「哪几种组合是合法的」从此没有家，而一个非法组合只表现为槽位行为古怪、不报错
- [x] 同一处写明它与元素那一格的分别 —— **这条判据不是一刀切**：元素只指一条状态，形态指的是三条规则
- [x] 反证写进那一份的验收（跟 `GP-31` 走）：各填一个没有实现的取值时载入被拒并说清它不在册、填在册的通过；另加一条结构约束**代码里读不到「占不占位」这类可以独立设置的位**
- [x] 同一处写明这两条与元素那一条**读的不是同一份册** —— 元素查外置数据，这两格查代码里实现了哪几个
- [x] 顺带兑现 [ADR-0025](../../decisions/ADR-0025-取值集的家由加一个的代价决定.md) 的落地要求：正典那条 mod 边界加了一句指向两份 ADR，并写明收窄的清单**不在正典列**（列了就是一份漏补不报错的副本）
- [x] `python tools/check_docs.py` 0 FAIL；`python tools/simulate_week.py --check-doc` 通过

## 实现笔记

### 设计决策

- **模糊点**：`ADR-0025` 的落地要求里有一条「正典那条 mod 边界加一句指向本决定」，而它不在本轮任何一条的验收里。
- **选择**：在本条做掉，并写明**收窄的清单不在正典列**，各处各自写。
- **理由**：本条是第一次真的收窄那条承诺，所以那句指针在这里加最省事。不列清单的理由与全库其余几处同源 —— 一份要随归类结果长的清单，漏补时不报错。

### 偏离

- **无。** 本条的四项验收都按方案做完，另外多做了上面那条正典指针。

### 权衡

- **考虑过把形态拆成三项能力声明**（占不占位／有没有上限／能不能镶宝石），那样加一种形态就只是换一组取值、真的归内容。**否决理由写进了文档**：三格拆开之后「哪几种组合合法」没有家，而非法组合不报错。这是本条唯一一次判据指向「可以归内容」而我仍然选了结构 —— 所以理由必须落在文档里，否则下次有人照判据重推会得出相反结论。
- **考虑过给作用目标留一个「自定义选择器」的挂点**，让 mod 填一个标识、代码侧注册实现。否决理由：那等于把「规则不外置」换成「规则半外置」，而它要一整套注册与校验机制，换来的只是这一格的扩展性 —— 与 `GP-120` 那处优势维表达式的否决理由同源。

### 待确认

- 核上游引用时撞到一处本条范围外的：[`物品系统`](../../design/物品系统.md)的上游约束写着「两条轴的取值集合可扩」，而稀有度三档与品质五级在别处是当接口常量用的。已记账 `GP-127`，本条不动。
