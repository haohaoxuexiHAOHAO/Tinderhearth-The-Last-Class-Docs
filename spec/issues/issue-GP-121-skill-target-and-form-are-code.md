# GP-121：技能的作用目标与形态写明是代码的事

## 目标

读文档的人知道这两格加一个取值必须写代码，不去数据文件里白试；而这处对 mod 的收窄在文档里查得到。

## 来源

- PRD：[`prd-extensible-lists`](../prd-extensible-lists.md) 的 `US-003`
- 判据：[ADR-0025](../../decisions/ADR-0025-取值集的家由加一个的代价决定.md) —— 加「一条直线」要一份新的目标选择器，加一种形态要一整套新的槽位规则，两样都是新逻辑

## 依赖

无。

## 验收标准

- [ ] [`技能系统` · 一个战斗技能要声明的字段](../../design/技能系统.md)对这两格写明它们归代码，加一个取值算一次改设计、要先立项
- [ ] **那处对 mod 的收窄显式写出来**，并指回 [玩法定位 · mod 的扩展边界](../../canon/gameplay/玩法定位.md) —— 不写的话，读者按那条承诺去试会白试，而白试不报错
- [ ] 可测试：外置数据里给一个技能填一个代码里没有实现的作用目标时**载入被拒**，并说清它不在册
- [ ] 可测试：填一个没有实现的形态时同样被拒
- [ ] **形态那一格不改成按能力声明。** 这一条要写明是刻意的：三种形态的槽位规则（占不占位、有没有上限、能不能镶宝石）各不相同，拆成三项能力声明只是把一张表摊成三格，而「合法的组合有哪几种」从此没有家
- [ ] `python tools/check_docs.py` 0 FAIL
