# GP-30：`design/成长系统.md`

## 目标

把角色身上那些会涨的量各给一条明确的涨法，并把派生表做成伤害与技能两侧共用的输入口。

## 来源

- PRD：[`spec/prd-growth-skill-damage.md`](../prd-growth-skill-damage.md) 的 `US-005`
- 已有的上游事实散在[角色与成长 · 特质与天赋](../../canon/gameplay/角色与成长.md)、[角色与成长 · 书 → 学会 → 练熟](../../canon/gameplay/角色与成长.md)与[角色与成长 · 加点与洗点](../../canon/gameplay/角色与成长.md)。生活技能那一侧由[`生产系统`](../../design/生产系统.md)只读、不持有。

## 依赖

`GP-31` 与 `GP-32`（派生表要写出「派生给谁用」，而那两份定义了消费方）。

## 验收标准

- [ ] 新文档按 [SYSTEM 模板](../../templates/SYSTEM.md)八节写全，`upstream` 指[角色与成长](../../canon/gameplay/角色与成长.md)，并被正典链接到。
- [ ] 持有的量列全，每一项写明**它由什么推动**：等级与经验（出征为主、训练为辅）、属性点与派生、特质、天赋树与点数、技能实战值与档位（只在命中时累积）、生活技能熟练度（只在做成那件事时涨）。
- [ ] **派生表是另两份文档的输入口**：物理攻击、魔法攻击、两份防御的基底、暴击率、韧性上限、闪避冷却、三条资源上限各由哪一项属性派生，形式一律是量纲而非值。
- [ ] 派生表把**基底与来源分成两栏** —— 基底由属性给（两份防御都读体质），其余来自饰品、宝石、天赋与状态；这样「我这点加的是什么」与「我这件装备加的是什么」不会混成一个数。
- [ ] 生活技能熟练度是**档位制**，每升一档必须解锁一件玩家看得见的事（新配方、更高的品质上限之类），理由与[战斗与关卡 · 队友 AI 分档：学生「变强」必须看得见](../../canon/gameplay/战斗与关卡.md)同一条 —— 只涨数字玩家分辨不出来。
- [ ] 属性点不可重置、天赋可洗点这条不对称原样保留，理由归属写清（正典已有，本页只引）。
- [ ] 边界那一节写明**不持有**：装备词条（`GP-24`）、书籍掌握度（[`教育系统`](../../design/教育系统.md)）、失衡增益（[`活跃失衡系统`](../../design/活跃失衡系统.md)）、生活技能怎么进产出（[`生产系统`](../../design/生产系统.md)）。
- [ ] 文档里一个玩法数值都没有。
- [ ] `python tools/check_docs.py` 0 项必须修复。
