# GP-122：装备那几个上限定值，各有唯一的家

## 目标

界面要画几格有依据，实现时不必现场拍一个以后查不到出处的数。

## 来源

- PRD：[`prd-extensible-lists`](../prd-extensible-lists.md) 的 `US-004`
- 判据：[ADR-0025](../../decisions/ADR-0025-取值集的家由加一个的代价决定.md) —— 它们都是别处要按它排版的数，所以归接口常量、只写一处

## 依赖

无。落地跟 `GP-24` 走。

## 立项理由

[`装备系统`](../../design/装备系统.md)的边界那一节把这几个数的家写成「正典那一节与本页」两处，而核过之后**两处都没有值** —— [角色与成长 · 装备：宝物与宝石](../../canon/gameplay/角色与成长.md)只给了宝物栏格数与每个技能的孔数。而[数值模型](../../design/数值模型.md)明写接口常量不进它那张表，所以这几个数现在谁都不持有。

## 验收标准

- [ ] 主词条恰好 1 条。**这一条不是新定的** —— [`装备系统` · 词条：主词条写死，副词条掷定即不变](../../design/装备系统.md)通篇写的就是单数，而它给的理由（让玩家一眼看出「这件是攻击向的」）在两条主词条下不成立
- [ ] 副词条最多 3 条，按稀有度三档给 1／2／3 条 —— 稀有度自己就答了「有几条」，**不另开一张对照表**
- [ ] 宝物孔最多 3 个。理由要指得回宝石的起步量：进得了宝物孔的只有纯属性与两用那两类，孔上限再大只是让缺口更大、不改变取舍性质
- [ ] 强化最多 5 级。理由是[`装备系统` · 强化：一条支出，两个对象，各有自己的等级](../../design/装备系统.md)要求「强化到顶」是个记得住的目标
- [ ] 这四个数各**只写在一处**，边界那一节不再说两处都有家
- [ ] 各档稀有度给几个基础孔、强化每级开几个附加孔**仍留在**[数值模型](../../design/数值模型.md)的尚未给值表，本条不给
- [ ] 可测试：宝物孔数超过上限的定义载入被拒
- [ ] 可测试：达到强化级数上限后再强化被拒
- [ ] 可测试：一件宝物定义带两条固定主词条时载入被拒
- [ ] 按词搜两个仓加 `.kiro`，没有第二处写着这四个数
- [ ] `python tools/check_docs.py` 0 FAIL
