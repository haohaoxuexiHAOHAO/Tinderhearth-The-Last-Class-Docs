# ENG-27：俯视地形挡得住人的端到端

## 目标

两种水都挡住人、配错会当场报错，这两条各有测试或一次性场景走过一遍；作者照指南的验收表在农场里看完。

## 来源

- PRD：[`spec/prd-terrain-blocks-walking.md`](../prd-terrain-blocks-walking.md) 的 `US-001` 与 `US-005`。两条的验收大半是同一趟一次性场景加同一趟实机，所以合成一条。
- 它补的是一条「正典写了没实现」的断链：[场景绘制约定 · 俯视布景](../../production/场景绘制约定.md)写明水本身不可走，而俯视侧一条地形碰撞都没有。

## 依赖

- `ENG-35`：那几条检查与它的单测。
- `DOC-151`：规则那一节。
- `DOC-152`：作者照着配的那一小节，与验收表新加的那几行。

## 验收标准

- [ ] 自动化：`ENG-35` 那条判定的单测进代码仓 `python tools/verify.py`，可重复。
- [ ] 自动化（一次性无头场景，跑完删）：主路径 —— 照指南配好（两种水的标记瓦片带整格碰撞、数据层用 `Visible` 隐藏），一个用 `MoveAndSlide` 的角色朝水格走，停在水格边上；贴岸斜走时沿岸方向的位移不为零。失败路径 —— 数据层关 `Enabled`，当场报错、信息说清。在下面记下删了什么。引擎内测试入口要等 `ENG-6`，所以这一段做不成可重复的测试。
- [ ] 可核对：TileSet 新加的物理层默认在第几层、与角色默认的掩码对不对得上，用同一趟无头场景读回。
- [ ] 可核对：代码仓 verify 全过；设计仓 check_docs 0 FAIL。
- [ ] **作者实机确认清单**：照指南「跑一遍验收」新加的那几行走，按行名对号，见下面「作者实机清单」。

## 作者实机清单

照[一块地能种出东西 · 跑一遍验收](../../reference/godot/一块地能种出东西.md)那张表走，怎么做只写在那张表里。先照第二步「让水挡住人」那一小节配好。

| 那张表的行名 | 对应哪一条 |
| --- | --- |
| **走不进水里** | `US-001`：朝浅水、朝深水各走一次都走不进去，停下的位置看着在岸边 |
| **贴着岸滑开** | `US-001`：斜着贴一段直岸走，顺着岸滑开、不卡 |
| **地面照旧** | `US-001`：草地与裸土走得过去，数据层藏起来之后看不到标记瓦片 |
| **关错了会报** | `US-002`：数据层取消勾选 `Enabled` 之后按 `F6`，输出面板说清改用眼睛隐藏 |

全部看完，「作者实机确认清单」那一格一起勾。
