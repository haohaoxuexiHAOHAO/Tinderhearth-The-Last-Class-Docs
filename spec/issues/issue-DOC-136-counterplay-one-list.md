# DOC-136：「对策」那份取值全库只有一份说法

## 目标

「玩家能用哪几种办法应对一招」只有一份清单，所以那条覆盖校验保证的范围不含糊。

## 来源

- PRD：[`prd-extensible-lists`](../prd-extensible-lists.md) 的 `US-007`
- 在设计文档普查时查出来的分叉

## 依赖

无。

## 立项理由

[`战斗AI系统` · 预警与对策：都是出手定义上的显式声明](../../design/战斗AI系统.md)列的对策带**打断**，而[战斗与关卡](../../canon/gameplay/战斗与关卡.md)与[玩法定位](../../canon/gameplay/玩法定位.md)两处的列举都没有它。

**后果是具体的**：那一份靠「全部敌人合起来要覆盖到每一种对策」这条载入校验，**顺带**保证了至少有一招打得断；而[人物](../../canon/characters/人物.md)写着主角的价值有一半靠打断。按少一项的那份实现，这条保证静默消失 —— 校验照旧通过，只是它保证的范围窄了一项。

**正典自己并不否认打断在那一格里** —— [战斗与关卡](../../canon/gameplay/战斗与关卡.md)另一处写明「每一招可不可打断由它自己声明，那一格与对策是同一格」。所以要改的是那两处列举，不是那条规则。

## 验收标准

- [x] **正典那两处的列举删掉了，不是补齐** —— 见下面「偏离」
- [x] 这份取值集按 [ADR-0025](../../decisions/ADR-0025-取值集的家由加一个的代价决定.md) 归类并写明归属 —— 加一种对策要写一段新的应对判定，所以它归代码；而**一招带哪几种是内容**
- [x] **家只有一处**（[`战斗AI系统` · 预警与对策：都是出手定义上的显式声明](../../design/战斗AI系统.md)），正典两处写链接不复述那串名字，并各写明为什么不复述
- [x] 反证写进那一份的验收（跟 `GP-36` 走）：合起来缺任一种时被拒且说清缺哪一种、每种都齐时不报错
- [x] **另加一条钉住那条顺带保证**：构造一批每一招都不带「打断」的敌人定义，载入被拒 —— 缺了它就分不出那条覆盖校验认不认「打断」这一项，而主角的价值有一半押在它身上
- [x] 另加一条：一招填了没有实现的对策时被拒并说清它不在册（这一格归代码）
- [x] 按词搜两个仓加 `.kiro`，活文档里没有第二处列那串名字
- [x] `python tools/check_docs.py` 0 FAIL；`python tools/simulate_week.py --check-doc` 通过

## 实现笔记

### 设计决策

- **模糊点**：两处正典的列举短一项，是补齐还是删掉。
- **选择**：**删掉**，两处都改成只写「覆盖到每一种对策」并指向家。
- **理由**：补齐只是让两份副本**暂时**一致 —— 下一次加一种对策时它们还会各说一套，而机器分不出两串东西说的是不是一件事（[WORKFLOW §3](../../WORKFLOW.md)）。核过之后发现**两句正典的论点都不需要那一整串**：一句在论证「跳跃有价值」，它只需要「跳」这一个；另一句在要求起步那几个敌人覆盖每一种，它根本不需要列名字。所以删掉不损失任何论证。

### 偏离

- **方案怎么说**：本条与 [`prd-extensible-lists`](../prd-extensible-lists.md) 的 `US-007` 都写「正典那两处列举**补上**「打断」」。
- **实际怎么做**：删掉那两处列举，改成指向家。
- **为什么**：见上面那条设计决策 —— 补齐治的是这一次的症状，删掉治的是「它为什么会不一致」。**这一轮的主题正是后者**，所以按主题走。

### 权衡

- **考虑过把那串名字上升进正典当权威**（反过来让设计侧指回正典）。否决理由：加一种对策要写新代码，所以它是代码结构；而正典按定义不装结构（`ADR-0010`）—— 把它放进正典会让一次纯代码改动变成一次改正典。
