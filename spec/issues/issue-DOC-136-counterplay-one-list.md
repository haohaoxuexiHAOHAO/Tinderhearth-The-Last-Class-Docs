# DOC-136：「对策」那份取值全库只有一份说法

## 目标

「玩家能用哪几种办法应对一招」只有一份清单，所以那条覆盖校验保证的范围不含糊。

## 来源

- PRD：[`prd-extensible-lists`](../prd-extensible-lists.md) 的 `US-007`
- 在设计文档普查时查出来的分叉

## 依赖

无。

## 立项理由

[`战斗AI系统` · 预警与对策：都是出手定义上的显式声明](../../design/战斗AI系统.md)列的对策带**打断**，而[战斗与关卡](../../canon/gameplay/战斗与关卡.md)与[玩法定位](../../canon/gameplay/玩法定位.md)两处的列举都没有它。

**后果是具体的**：那一份靠「全部敌人合起来要覆盖到每一种对策」这条载入校验，**顺带**保证了至少有一招打得断；而[人物](../../canon/characters/人物.md)写着主角的价值有一半靠打断。按少一项的那份实现，这条保证静默消失 —— 校验照旧通过，只是它保证的范围窄了一项。

**正典自己并不否认打断在那一格里** —— [战斗与关卡](../../canon/gameplay/战斗与关卡.md)另一处写明「每一招可不可打断由它自己声明，那一格与对策是同一格」。所以要改的是那两处列举，不是那条规则。

## 验收标准

- [ ] 正典那两处列举补上「打断」，与[`战斗AI系统`](../../design/战斗AI系统.md)那一份一致
- [ ] 这份取值集按 [ADR-0025](../../decisions/ADR-0025-取值集的家由加一个的代价决定.md) 归类并写明归属 —— 加一种对策要写一段新的应对判定，所以它归代码
- [ ] **家只有一处**，另外两处写链接不复述那串名字 —— 复述一遍就又有一个会漂的副本
- [ ] 可测试：全部敌人定义合起来缺任一种对策时载入被拒，并说清缺哪一种
- [ ] 可测试：构造一批都不带「打断」的敌人定义时被拒（这一条钉住那条顺带保证真的在）
- [ ] 可测试：每种都齐时不报错（反向反证，缺了就分不出它判的是什么）
- [ ] 按词搜两个仓加 `.kiro`，没有短一项的副本
- [ ] `python tools/check_docs.py` 0 FAIL
