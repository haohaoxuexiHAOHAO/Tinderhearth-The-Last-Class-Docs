# DOC-145：代码里的步名表与正典那串对得上，检查器判得出来

## 目标

代码里每日结算的步名表与正典那串步序项数、顺序与每一项的开头都一致；任何一边改了而另一边没跟上，设计仓 `tools/check_docs.py` 判失败。

## 来源

- PRD：[`spec/prd-sleep-advances-day.md`](../prd-sleep-advances-day.md) 的 `US-002` 第三格与 `FR-7`；「技术考虑」里「步名表与正典的对账放在设计仓」与「步名取正典那一条的开头」两条。

## 依赖

- `GP-149`：步名表是它建的。

## 验收标准

- [ ] 可核对：`check_docs.py` 读正典[时间与经营 · 结算顺序（固定，不得改动）](../../canon/gameplay/时间与经营.md)那张编号表，再读代码仓那张步名表，逐项比：项数相同、顺序相同、代码里每一项是正典那一条去掉加粗之后的开头。
- [ ] 可核对：对不上时报出是哪一项、两边各写的什么。
- [ ] 可核对：读不到那张编号表（节名改了、表没了）或读不到代码仓那一份时判失败，不静默跳过。
- [ ] 可核对：故意改错代码里一个字、对调代码里两项、给正典那张表临时加一项，各跑一次都判失败；改回之后 0 FAIL。
- [ ] 可核对：覆盖量那一行报出核了几步。
- [ ] 可核对：设计仓里按名引那串步序的地方用的是正典的步名：[`每日结算系统`](../../design/每日结算系统.md)里两处「书籍阅读推进」改成「书籍阅读进度推进」。
