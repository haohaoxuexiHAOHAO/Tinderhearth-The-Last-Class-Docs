# DOC-145：代码里的步名表与正典那串对得上，检查器判得出来

## 目标

代码里每日结算的步名表与正典那串步序项数、顺序与每一项的开头都一致；任何一边改了而另一边没跟上，设计仓 `tools/check_docs.py` 判失败。

## 来源

- PRD：[`spec/prd-sleep-advances-day.md`](../prd-sleep-advances-day.md) 的 `US-002` 第三格与 `FR-7`；「技术考虑」里「步名表与正典的对账放在设计仓」与「步名取正典那一条的开头」两条。

## 依赖

- `GP-149`：步名表是它建的。

## 验收标准

- [x] 可核对：`check_docs.py` 读正典[时间与经营 · 结算顺序（固定，不得改动）](../../canon/gameplay/时间与经营.md)那张编号表，再读代码仓那张步名表，逐项比：项数相同、顺序相同、代码里每一项是正典那一条去掉加粗之后的开头。比的是相等：从正典那一条取出步名（以加粗开头的取那一段加粗，否则取到第一个中文标点为止），代码那一项要与它一字不差。守卫是 `tools/check_docs.py` 的 `check_settlement_steps`，读的是代码仓 `rules/Economy/SettlementSteps.cs` 的 `Order`。
- [x] 可核对：对不上时报出是哪一项、两边各写的什么；项数不同时报出两边各几步、哪一边多了哪几个名字。
- [x] 可核对：读不到那张编号表（节名改了、表没了）或读不到代码仓那一份时判失败，不静默跳过。另外两种也判失败：代码里没有 `Order` 那张表、那张表里有一个认不出的名字。
- [x] 可核对：故意改错代码里一个字、对调代码里两项、给正典那张表临时加一项，各跑一次都判失败；改回之后 0 FAIL。另加两种：截短代码里一项、把正典那一条的开头改长，都判失败。
- [x] 可核对：覆盖量那一行报出核了几步。
- [x] 可核对：设计仓里按名引那串步序的地方用的是正典的步名：[`每日结算系统`](../../design/每日结算系统.md)里两处、[`教育系统`](../../design/教育系统.md)下游同步那张表里一处、[待办台账](./README.md)已归档那张表里一处，改用正典的步名「书籍阅读进度推进」。

## 实现笔记

### 设计决策

- **模糊点**：「代码那一项是正典那一条的开头」按前缀判，还是按相等判。
- **选择**：先从正典那一条取出步名，再判相等。以加粗开头的取那一段加粗，否则取到第一个中文标点为止。
- **理由**：只判前缀的话，截短的名字（「日期推」）能过，正典那一条的开头改长了（「日期推进与天气」）也能过，两种都让代码里那个名字悄悄不再是那一步的名字。按标点切单靠它不够：「委托板补满至固定条数」那一条的步名在标点之前，要靠开头那段加粗才取得对。正典一个字不用为它改。

- **模糊点**：哪些标点算步名的终点。
- **选择**：只收中文标点（逗号、顿号、冒号、分号、左括号、句号、破折号）。
- **理由**：「次日 6:30 醒来」那一步的名字里就有半角冒号与空格，收了它们，这一步就取成了「次日」。

- **模糊点**：代码仓那张表怎么读。
- **选择**：读那个文件里的字符串常量，再按 `Order` 里写的先后把常量换成名字；`Order` 里出现一个不是本文件常量的名字就判失败。
- **理由**：驱动、测试与那几步都按常量引步名，表里写的也是常量；直接在表里写字面量会让同一个名字有两处写法。

### 偏离

- **方案怎么说**：验收那一格写的是「两处改名」，只点了每日结算系统。
- **实际怎么做**：按名搜全库，另外两处一起改了：教育系统那张表里写成了「典籍阅读进度推进」，台账已归档那张表里写成了「书籍阅读推进」。
- **为什么**：验收那一格的要求是「按名引那串步序的地方用的是正典的步名」，那两处同样是在点那一步。

### 权衡

- **正文里按名引那一步的地方，这条守卫判不到**：判的只是代码那张表。正文的写法五花八门（「某某那一步」「**某某**」「某某之后」），挑不出一个只匹配步名、不误伤别处的形状。这一次是按名搜出来的。
- **没把错写法登进退役术语那张表**：那张表收的是撤掉的概念与改掉的人名，这两个错写法不是撤掉的概念，登进去会让那张表的口径变宽。

### 待确认

无。
