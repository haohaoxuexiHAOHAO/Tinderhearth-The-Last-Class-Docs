# DOC-46：两份系统文档接进索引，本批记账收口

## 目标

让本批产出的两份文档从 README 点得到、从台账查得到，而不是孤岛；本批发现的界面欠账有账可查，而状态只落在台账一处。

## 来源

- PRD：[`prd-bubble-dialogue-and-diary.md`](../prd-bubble-dialogue-and-diary.md) 的 `US-006`
- 起因：检查器有一条「从 README 出发能否走到每份非归档文档」的判定 —— 不接索引就当场 FAIL；而台账那两行写的是本批之前的状态，答完就过期。

## 依赖

依赖 `NR-8`、`NR-9`（要接进索引的两份文档得先存在）。

- [x] [待办台账](./README.md)里 `NR-8` 与 `NR-9` 两行**整段改写**（原来写的是「还没有家」与「本批只定了那一个接口」，本批答完两句都过期），并各写出落地顺序。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。四类都要过一遍，某类没有就写「无」并简要说明。

### 设计决策

- **模糊点**：`UI-19` 与 `UI-18` 的界线 —— 引导提示的界面在 `UI-18`，而本批那条硬约束（气泡与引导要在形状上不一样）同时约束两者。
- **选择**：约束写进本批两份系统文档，界面侧两条记账行各自引它，**不新开第三条记账行**。
- **理由**：那是一条约束、两处兑现；给它单开一行会让「它做没做」有两个答案。

### 偏离

- **方案怎么说**：「系统深化顺序」档 3 那一格只改状态那半。
- **实际怎么做**：整格换成分批的**理由**，状态一个字不留。
- **为什么**：上一批实测过「往已经在限内的格里加连带说明会把它顶出上限」。换成理由之后它既回到限内，又少了一处会随批次增长的散文。**改完量过**：全表 177 行 617 格，超限的仍是 `DOC-17` 点名的那三格，本批一格都没加进去 —— 顺带把归档那一轮写超的 `GP-53` 一格也收回了限内。

### 权衡

**为什么本批不建 ADR。** 门槛是「影响多个系统且难以撤销」。三个最像候选的都不够：

- **两份各自成篇**：这是文档归位，规则的家已经在 [ADR-0010](../../decisions/ADR-0010-文档体裁与系统文档归位.md)，判据的家在[`生产系统` · 什么时候拆出去单独成篇](../../design/生产系统.md)。再写一份 ADR 等于给同一条判据加第三个家。
- **冷却池只进临时续玩点**：它影响存档那一批，但**撤销成本很低** —— 改成进正式存档就是多一个字段，不用改任何别人的结构。
- **需求标记落在日记条目上**：它跨日记与事件两份，但那一处是**措辞精确化**（把已有那一格读的东西说准），不是新取舍。

**判据不满足就不写**，否则 ADR 会从「难撤销的取舍」退化成「这一批的摘要」。
