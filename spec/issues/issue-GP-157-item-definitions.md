# GP-157：物品定义、类别表与两条轴的档位表进数据

## 目标

物品、类别与稀有度、品质两条轴的档位都是代码仓 `data/` 下的数据文件，缺字段载入被拒，加一档不改代码。

## 来源

- PRD：[`spec/prd-items-in-bag.md`](../prd-items-in-bag.md) 的 `US-001`。

## 依赖

无。

## 验收标准

- [x] 可测试：物品定义照[物品系统 · 物品定义的字段：只写「它是什么」，不写「它能干什么」](../../design/物品系统.md)那张表逐格读；缺任一格载入被拒并说清缺哪一格，「有无品质」与「用掉前要不要一道确认」两格也不给默认值。
- [x] 可测试：名称与描述写成中文串而不是文本键的，载入被拒。
- [x] 可测试：稀有度与品质的档位照[物品系统 · 两条轴的档位各是一张在册的声明表](../../design/物品系统.md)逐项读；缺任一声明项被拒；显示色不是色板里的一档被拒；品质最高那一级的几个值同一条色带被拒；排序位允许重复。
- [x] 可测试：类别是一张带层级的表；物品填的类别不在表里，或稀有度不在册，载入被拒并点名。
- [x] 可测试：多放一份品质档位文件、不改代码，载入成功且排序按它的排序位走（[ADR-0025](../../decisions/ADR-0025-取值集的家由加一个的代价决定.md)那条内容型反证）；读档位的代码遍历在册那几档，不按序号取某一档。
- [x] 可核对：读法与作物定义同一套（基础内容加 mod 覆盖，一份读不出来点名是哪一份、来自哪里）；主场景启动时也读一遍，导出冒烟判得到坏文件。
- [x] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。

## 实现笔记

### 设计决策

- **图标不在物品定义上。** 每个物品一份图标资源，资源上写它是哪个物品，由作者在 Godot 里配 —— 与作物素材同一个做法，规则层看不见图片。这样「两份图标配给同一个物品」才是一个判得到的错（定义上存一个引用的话那种错根本写不出来，而 `UI-63` 要判它）。[`物品系统`](../../design/物品系统.md)那张字段表、接口表的图标两行与验收那一条跟着改了。
- **值归数值模型、还没给值的那几格写显式的空值。** 物品的基础价量级、两条轴各档的基础价系数现在都没有值（系数归 `GP-7`），数据里写 `null`；不写这个键是漏填、载入被拒。规则写进了[`物品系统`](../../design/物品系统.md)字段表下面那一段，读它的定价读到空值要当场报错。
- **色板随发行包走，载入时按名字查。** 档位的显示色是色板里一档的名字，要在载入时判在不在色板里、属于哪条色带，界面以后还要按它染色，所以代码仓 `export_presets.cfg` 的 include_filter 带上了 `assets/self-drawn/palette.gpl`，运行时由代码仓 `src/Platform/ContentBootstrap.cs` 读。解析从测试里挪进规则层（代码仓 `rules/UI/Palette.cs`），测试与游戏读同一份色板走同一个解析。
- **物品这一侧不认识色板。** 物品与档位在代码仓 `rules/Progression/`（物品属于角色与成长那一组），它只收一个「这一项在色板里吗、属于哪条色带」的查询，不引用界面那一侧的类型 —— 玩法那几块不依赖界面那一块。
- **正面副词条几条照正典推出来**：[角色与成长 · 装备：宝物与宝石](../../canon/gameplay/角色与成长.md)写着条数逐档递增、最低一档 1 条且那一条是负面，[`装备系统`](../../design/装备系统.md)的验收写着负面恰好一条，所以三档的正面条数是总条数减一。上限那条（面板画得下几条）的载入校验跟 `GP-24` 走。
- **使用效果那一格现在只许空着。** 效果那一侧还没有数据表（`GP-18`），填了的引用一条都解析不到；放过它，「能用」的物品用下去什么都不发生。
- **类别先只有占位作物用得上的那几个**：材料、它下面的药材、最顶层的种子。占位作物季节全开，而跨季的作物不能是粮食，所以它们的收获物归药材；正式的作物清单与各自的类别跟 `GP-88`。
- **跨文件的错一次全报**：物品指的类别与稀有度、类别的层级、档位的显示色、顶上那一级的色带、同一级的系数，核完一起报，一行一处。单份文件读不出来时照作物那样当场报、点名是哪一份。
- **一条轴一档都没读到也报。** 目录名拼错或没进发行包，读出来是空的，而没有哪一份文件会替它报错；物品还没有时，「指不到在册的稀有度」那一条也兜不住它。

### 偏离

- **方案怎么说**：物品定义照字段表逐格读。
- **实际怎么做**：图标那两格不进定义，进每个物品一份的图标资源；其余各格逐格读。
- **为什么**：见设计决策第一条。字段表已改成同一个说法，两处没有分歧。

### 权衡

- **界面那几档代码设的颜色仍抄在代码里**（代码仓 `rules/UI/HudPalette.cs`）：色板现在进了发行包，改成运行时查做得到，代价是把色板传进每一处用色的地方。那几档由测试逐项对着色板核，抄错会红，所以这一份不动。
- **品质同一级共用一个系数也核了**：两档都还是空值时这条判不出差别，但它是[数值模型](../../design/数值模型.md)定价那一节写明的约束，有了值之后填错一档不报错。
