# GP-157：物品定义、类别表与两条轴的档位表进数据

## 目标

物品、类别与稀有度、品质两条轴的档位都是代码仓 `data/` 下的数据文件，缺字段载入被拒，加一档不改代码。

## 来源

- PRD：[`spec/prd-items-in-bag.md`](../prd-items-in-bag.md) 的 `US-001`。

## 依赖

无。

## 验收标准

- [ ] 可测试：物品定义照[物品系统 · 物品定义的字段：只写「它是什么」，不写「它能干什么」](../../design/物品系统.md)那张表逐格读；缺任一格载入被拒并说清缺哪一格，「有无品质」与「用掉前要不要一道确认」两格也不给默认值。
- [ ] 可测试：名称与描述写成中文串而不是文本键的，载入被拒。
- [ ] 可测试：稀有度与品质的档位照[物品系统 · 两条轴的档位各是一张在册的声明表](../../design/物品系统.md)逐项读；缺任一声明项被拒；显示色不是色板里的一档被拒；品质最高那一级的几个值同一条色带被拒；排序位允许重复。
- [ ] 可测试：类别是一张带层级的表；物品填的类别不在表里，或稀有度不在册，载入被拒并点名。
- [ ] 可测试：多放一份品质档位文件、不改代码，载入成功且排序按它的排序位走（[ADR-0025](../../decisions/ADR-0025-取值集的家由加一个的代价决定.md)那条内容型反证）；读档位的代码遍历在册那几档，不按序号取某一档。
- [ ] 可核对：读法与作物定义同一套（基础内容加 mod 覆盖，一份读不出来点名是哪一份、来自哪里）；主场景启动时也读一遍，导出冒烟判得到坏文件。
- [ ] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。
