# GP-143：变异几率的基础值与上限在检查器里填，修饰有入口

## 目标

变异几率由作者在检查器里调：一个基础值、一个上限，事件与设备那两路修饰有地方加进来，填了不合法的值当场报错。

## 来源

- PRD：[`spec/prd-crop-sheet.md`](../prd-crop-sheet.md) 的 `US-003`（`FR-6`、`FR-7`、`FR-8`）。
- 合成规则在[`地块系统` · 变异几率：一个基础值，加事件与设备两路修饰](../../design/地块系统.md)，取值登记在[数值模型](../../design/数值模型.md)的尚未给值表，本条不复述。

## 依赖

无。修饰的来源（事件、设备）跟 `GP-52`、`GP-28` 走，本条只留入口。

## 验收标准

- [x] 可测试：几率 ＝ 基础值加修饰之和、再钳在上限以内；没有修饰时就是基础值。
- [x] 可测试：基础值不大于零、基础值大于上限、上限不小于 1，各自当场被拒并说清是哪一条。
- [x] 可测试：负的修饰被拒 —— 事件与设备那两路只往上调。
- [x] 可核对：`Field` 节点多出基础值与上限两格，都没有默认值；不填时启动当场报错。两格叫 `Mutation Base Chance` 与 `Mutation Chance Cap`（代码仓 `src/World/Farm/FarmField.cs`），没填就是两个零，在构造那一下被基础值那一条拦下。

## 实现笔记

### 设计决策

- **模糊点**：修饰交进来的是什么 —— 带着来源与剩余天数的一条条记录，还是只有幅度。
- **选择**：只收幅度，一组不为负的数（代码仓 `rules/Economy/MutationChanceRule.cs` 的 `ChanceWith`）。
- **理由**：来源怎么记、事件那一路怎么过期，是事件与设备那两侧的事（`GP-52`、`GP-28`），合成规则只要「作用在这一格上的那几个数」。现在就定记录的形状，等于替那两侧先拍板。

- **模糊点**：两格没填时报哪一条。
- **选择**：没填就是两个零，先判基础值，报「基础值必须大于零」，报错里写明没填也是零。
- **理由**：检查器里「没填」与「填了零」长得一样，一条拒绝把两种都拦下；它与产量系数下限那一格是同一个做法（代码仓 `rules/Economy/HarvestYieldRule.cs`）。

### 偏离

无。

### 权衡

- **基础值与上限只在启动那一下校验一次**：两格在检查器里改了要重跑才生效。它们本来就是实机种几季才调的量，跑着改不到也不碍事。

### 待确认

无。
