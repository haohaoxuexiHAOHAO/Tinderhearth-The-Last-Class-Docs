# GP-153：写档不会写坏，进农场时读回

## 目标

睡下时存档要么写成完整的一份、要么一字不动；进农场时有存档就读回，没有就开新档；读不出来、被拒或对不上那片地时当场报错说清，不开新档。

## 来源

- PRD：[`spec/prd-sleep-advances-day.md`](../prd-sleep-advances-day.md) 的 `US-005` 前六格与实机那一格，`FR-29` 到 `FR-36`。
- 「技术考虑」里「写档不用 Godot 那一套」与「只读那一条怎么做」：理由、源码链接与只读实测都在那里，本条不复述。

## 依赖

- `GP-152`：自动存档那一步调的就是这一下写。
- `GP-57`：读回时走那几条版本口径。

## 验收标准

- [x] 可核对：写档是「在同一目录写临时文件 → 落盘 → 一次带覆盖的改名」，用 .NET 的文件接口，不用 Godot 的 `DirAccess.RenameAbsolute`；代码注释写明理由。在代码仓 `src/Platform/SaveStore.cs`；改名之前哪一步失败，临时文件删掉，原来那一份不动。
- [x] 可核对：写成功之后输出面板一行：存档的绝对路径、总字节数、各分片的字节数。各分片的字节数由代码仓 `rules/Foundation/Save/SaveFile.cs` 量，有一条测试；量在写进文件之前，理由见下面「设计决策」。
- [x] 可核对：在本机写一份、把存档文件设成只读、再写一次：这一次失败、原因说得出来，目标文件一字不动。实测：一个只编进 `src/Platform/SaveStore.cs` 的一次性工程，放在工作区根的 temp 目录，跑完连同编译产物一起删了。只读那一次抛出的报错是「存档写不进〈存档的绝对路径〉：Access to the path is denied.」，内层是 `UnauthorizedAccessException`；目标还是第一次写的那一份，临时文件也删掉了；去掉只读再写一次就成了。PRD「技术考虑」里那条待验证随之改成实测。
- [x] 可核对：进农场时有存档就读回，输出面板一行写读回的日期；没有存档就按开局那一天与场景里那片地开新档，也打一行。读文件在代码仓 `src/World/Farm/FarmField.cs`，判在规则层 `rules/Economy/FarmSave.cs`，开新档与读回各有一条测试。
- [x] 可核对：存档在、但读不出来或被拒时，当场报错说清是哪个文件、哪一条，不开新档。报错写着存档的绝对路径与被拒的那一条；农场节点的每帧回调与调试键停着不开，所以没有哪一下能把那份存档盖掉。读不出来、整份被拒有一条测试。
- [x] 可测试：存档里那片地与场景里那片地对不上时被拒，说清多了哪几格、少了哪几格。测试在代码仓 `tests/Economy/FarmSaveTests.cs`，挪过位置与改过大小各一条。
- [x] 可测试：存档里的作物标识在作物定义里找不到时被拒，点名哪一格、哪个标识（隔离那条路归 `ENG-7`）。这一条随 `GP-151` 落地：代码仓 `tests/Economy/WorldShardsTests.cs` 的「地里那种作物找不到定义时被拒并点名哪一格与哪个标识」。
- [x] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。
- [ ] **作者实机确认**：按 `N` 推进一天，停掉游戏，再跑农场，日期与每一格地都是推进之后那一刻的样子。串在 `GP-155` 的清单里。

## 实现笔记

### 设计决策

- **模糊点**：存档里那片地与场景里那片地对不上时怎么办。
- **选择**：载入被拒，说清两边的左上角与大小、各多出哪几格；多出的格数多时只点名前面几格，再报个数。
- **理由**：对不上多半是改过场景里那片地。按场景重铺或只取重叠那一块，都会悄悄丢掉玩家种过的地，而下一次睡觉就把那份存档盖掉了。作者看两边各多出哪几格，就分得清是挪了还是改了大小。

- **模糊点**：读不出来或被拒之后，农场节点还开不开。
- **选择**：不开：每帧回调与调试键 `N`、`B` 都等存档读回来之后才开。
- **理由**：读不出来时世界是空的，再按 `N` 只会在那条报错下面多刷一条空引用；更要紧的是，开着就有一条路能写档。

- **模糊点**：各分片的字节数什么时候量。
- **选择**：写进文件之前。
- **理由**：写进文件那一下必须是自动存档那一步里最后一件会失败的事。它之后再抛，盘上已经是新的一天，结算却当这一天没有推进。

- **模糊点**：各分片的字节数怎么量。
- **选择**：每个分片按写存档那套选项单独写一次再数字节，几块加起来比整份略少：差的是最外层那几个键，和嵌在里面每一行多出来的缩进。
- **理由**：要说得出是哪一块在长（[`存档系统` · 存档位摘要与体积实测](../../design/存档系统.md)），按块单独量就够了，不必为对上总数去算缩进。

### 权衡

- **只读时的那句原因带着系统的英文说法**（本机实测如此）：弹窗里那一行会是中文开头加一句英文。没在这里按报错种类改写成中文：那是弹窗怎么说的事，跟着 `UI-59` 定。
