# GP-153：写档不会写坏，进农场时读回

## 目标

睡下时存档要么写成完整的一份、要么一字不动；进农场时有存档就读回，没有就开新档；读不出来、被拒或对不上那片地时当场报错说清，不开新档。

## 来源

- PRD：[`spec/prd-sleep-advances-day.md`](../prd-sleep-advances-day.md) 的 `US-005` 前六格与实机那一格，`FR-29` 到 `FR-36`。
- 「技术考虑」里「写档不用 Godot 那一套」与「只读那一条怎么做」两条，理由与源码链接都在那里，本条不复述。

## 依赖

- `GP-152`：自动存档那一步调的就是这一下写。
- `GP-57`：读回时走那几条版本口径。

## 验收标准

- [ ] 可核对：写档是「在同一目录写临时文件 → 落盘 → 一次带覆盖的改名」，用 .NET 的文件接口，不用 Godot 的 `DirAccess.RenameAbsolute`；代码注释写明理由。
- [ ] 可核对：写成功之后输出面板一行：存档的绝对路径、总字节数、各分片的字节数。
- [ ] 可核对：在本机写一份、把存档文件设成只读、再写一次：这一次失败、原因说得出来，目标文件一字不动。这是 PRD「技术考虑」里那条待验证。
- [ ] 可核对：进农场时有存档就读回，输出面板一行写读回的日期；没有存档就按开局那一天与场景里那片地开新档，也打一行。
- [ ] 可核对：存档在、但读不出来或被拒时，当场报错说清是哪个文件、哪一条，不开新档。
- [ ] 可测试：存档里那片地与场景里那片地对不上时被拒，说清多了哪几格、少了哪几格。
- [ ] 可测试：存档里的作物标识在作物定义里找不到时被拒，点名哪一格、哪个标识（隔离那条路归 `ENG-7`）。
- [ ] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。
- [ ] **作者实机确认**：按 `N` 推进一天，停掉游戏，再跑农场，日期与每一格地都是推进之后那一刻的样子。串在 `GP-155` 的清单里。
