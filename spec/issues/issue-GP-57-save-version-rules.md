# GP-57：存档版本与兼容口径的落地反证

## 目标

载入时先判这份存档还打不打得开，再处理缺的与多的字段；ADR-0015 与 ADR-0017 的每一条各有一条用例钉住。

## 来源

- PRD：[`spec/prd-sleep-advances-day.md`](../prd-sleep-advances-day.md) 的 `US-004` 第五、六格，`FR-23` 到 `FR-28`。
- 口径在 [ADR-0015](../../decisions/ADR-0015-存档的版本与缺字段口径.md) 与 [ADR-0017](../../decisions/ADR-0017-版本更新对旧存档的两种后果.md)，顺序在[`存档系统` · 载入：先读分片，再统一解析标识](../../design/存档系统.md)，本条都不复述。
- 本编号原先只登了一行；这份需求把它并进来，才有了条目文件。

## 依赖

- `GP-150`：判的是那份文件的外形与那几个已注册分片。

## 验收标准

- [ ] 可测试：比当前旧、而不低于最低兼容版本的存档缺一个字段，按那个分片的存档默认值补上，载入成功；整个分片缺了也一样。
- [ ] 可测试：与当前同版本的存档缺一个字段，载入被拒，并说清是哪个分片缺哪一项。
- [ ] 可测试：版本比当前新的存档被拒。
- [ ] 可测试：版本低于最低兼容版本的存档被拒，被拒的说法分得出是这一种；这时没有任何一个分片被交给持有者。指向更新公告那一句归 `UI-23`，那一页还不存在。
- [ ] 可测试：把最低兼容版本调到等于当前，原先落在区间里、能补齐的那一份转为被拒（钉住那个常量真的在被读）。
- [ ] 可测试：分片里多出来的字段被丢弃，再写回时不带它。
- [ ] 可测试：存档里出现一个没注册的分片，载入被拒并点名它；它不被丢掉（隔离那条路归 `ENG-7`）。
- [ ] 可测试：只往作物定义里加一种作物，旧存档照样打得开。
- [ ] 可核对：把「同版本缺字段」临时改成补默认值跑一次，那条用例失败；改回。
- [ ] 可核对：当前版本号与最低兼容版本是两个规则常量、放在同一处，注释指向那两份 ADR。
- [ ] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。
