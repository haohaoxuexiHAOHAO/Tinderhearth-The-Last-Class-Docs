# DOC-59：正典那几处挂上链接，意图一个字不改

## 目标

让正典里提到图鉴、地图与导航、边界切换的地方都点得进本批那两份新文档，**而正典自己的意图与那几个量级一个字不改**。

## 来源

- PRD：[`prd-codex-and-city-map.md`](../prd-codex-and-city-map.md) 的 `US-005`
- 起因：`type: system` 有「必须被正典链接到」的硬判定 —— 新文档一落地、正典里的链接不在，检查器当场判失败。

## 依赖

`GP-58` 与 `GP-59`（链接的目标得先存在）。**四条一起验**，本条单独跑不绿。

## 验收标准

### 挂链接

- [x] [玩法定位 · 查询与图鉴](../../canon/gameplay/玩法定位.md)挂上图鉴那一份的链接；**收哪几类那一句一个字不改**（它是接口常量的家）。
- [x] [玩法定位 · 跨系统基础设施](../../canon/gameplay/玩法定位.md)里「图鉴与查询」「地图与导航」两行各挂上链接；**快速旅行仍写「推后」**，不改成「已做」。
- [x] [玩法定位 · 场景规模](../../canon/gameplay/玩法定位.md)边界切换那几段挂上地图那一份的链接。
- [x] [玩法定位 · 系统清单](../../canon/gameplay/玩法定位.md)里若还有指不到落点的地方，一并挂上。

- [x] **图张数、那三层辨识度与那半秒一个字不改**，也不在它们上面新增任何状态陈述。
- [x] [结算顺序（固定，不得改动）](../../canon/gameplay/时间与经营.md)那串**一个字未改，也没有在它上面加任何链接** —— 动它的形状会让人以为它可以被讨论。
- [x] 正典里**不出现两份新文档里那几张表的字段名与类别名**：写描述加节名链接，否则那些名字会有两个家而机器判不出来。
- [x] 正典里**不新增任何状态陈述** —— 进度仍只在[待办台账](./README.md)一处。
- [x] [世界观](../../canon/world/世界观.md)**一个字不改**：主要设施与穹盾那几节是新文档的上游，不是被它改写的对象。

## 实现笔记

### 设计决策

- **模糊点**：链接挂在哪几处才够，又不至于让正典长出第二份说明。
- **选择**：四处 —— [玩法定位 · 查询与图鉴](../../canon/gameplay/玩法定位.md)末尾一句、[玩法定位 · 跨系统基础设施](../../canon/gameplay/玩法定位.md)那两行、[玩法定位 · 场景规模](../../canon/gameplay/玩法定位.md)边界切换那一段。
- **理由**：这四处是读者从正典进来的入口；其余提到图鉴的地方（关卡内只许查看、弹界面暂停世界那份清单）说的是**别的规则恰好点到了图鉴**，在那里挂链接会让那两条规则看起来是图鉴的一部分。

- **模糊点**：[世界观](../../canon/world/世界观.md)要不要改。
- **选择**：**一个字不改。**
- **理由**：主要设施与穹盾那几节是新文档的**上游**，不是被它改写的对象；地点清单与分区隔离那条设定都留在原处，新文档写链接引它们。

### 偏离

- **方案怎么说**：正典只挂链接。
- **实际怎么做**：[玩法定位 · 跨系统基础设施](../../canon/gameplay/玩法定位.md)地图那一行**另去掉了一处张数副本**（改成指「场景规模」那一节）。
- **为什么**：那一行原来自带张数，而张数的家在[玩法定位 · 场景规模](../../canon/gameplay/玩法定位.md)那张表 —— 同一个数两个家时没有任何东西判得出来哪处过期。正在编辑那一行，顺手收掉比另记一条账诚实。**这不改意图，只删了一份副本。** 同一轮按量级数字还查出两处更远的副本，改在 `DOC-60`。

### 权衡

**「在关卡内只许查看那一条上也挂链接」考虑过。** 没选：那条规则的对象是手环的管理功能，图鉴只是被点名的例子之一；挂上去会让人以为那条限制归图鉴管。新文档自己写明了它与那条规则的关系（收录不是玩家的操作）。

无。
