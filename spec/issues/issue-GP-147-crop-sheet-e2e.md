# GP-147：作物素材表那份需求的端到端

## 目标

这一份需求的主路径与失败路径都有测试走一遍，作者照一份清单在农场里把全部改动看完。

## 来源

## 依赖

- `DOC-148`：清单对号用的那张验收表是它改出来的，它剩下的那一格实机也串在这里。

## 验收标准

- [x] 自动化测试走完主路径：播种 → 推进到长成（必中）→ 待收且变异 → 收获结果带变异 → 回到已锄。测试在代码仓 `tests/Economy/CropSheetE2ETests.cs`，从工程里那批作物数据读起、经随身栏播种。
- [x] 覆盖失败路径：上限不小于 1 被拒；没到成熟不掷；循环作物下一茬重掷、不继承上一茬。
- [x] 测试独立可重复：随机源注入，不读真随机。每一次掷用的随机数由测试按顺序给，多掷一次就取空、当场失败；作物数据只读不写。
- [x] 代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。两个都看脚本自己打的摘要，不只看退出码。
- [ ] **作者实机确认清单**：要看的几样在 PRD `US-009` 那一格里（含农场里的随身栏与当前操作格）。落地时在本条展开成按在 Godot 里走到哪排的逐步清单，每一步写它勾哪一格；`GP-128` 与 `GP-87` 剩下的实机格一起串进来，它们等的也是农场跑起来。清单在下面「作者实机清单」。

## 作者实机清单

照[一块地能种出东西](../../reference/godot/一块地能种出东西.md)搭完、配完全部作物，再照[一块地能种出东西 · 跑一遍验收](../../reference/godot/一块地能种出东西.md)那张表从上往下走。怎么做、该看到什么只写在那张表里，这里只写每一行勾哪一格：

- 「缺图一次全报」→ `GP-144`「故意空一种作物的那一格」、`GP-87`「缺任一张作物素材时报错说清缺哪张」；补回去之后载入不报缺 → `DOC-144`「照着配完全部作物，载入不报缺」。
- 「换格」→ PRD `US-009` 清单里随身栏那一样。
- 「框跟着指针」→ PRD `US-009` 清单里当前操作格那一样、`GP-87`「框跟着指针跳格」。
- 「种一整轮」→ `GP-87`「四个动作各做一次」。
- 「扫一眼田」→ `GP-87`「一格锄过没锄过」「一屏之内分得出哪几格浇过水」「耕地挨着草与天然裸土」那几格。
- 「换一种种子」→ `GP-128`「换一种种子再播」。
- 「手上是空格」→ `GP-128`「三条被拒路径各撞一次」里空手那一条。另外两条在农场里撞不到：「这一格不许播」的理由在 `GP-128` 条目的偏离；「不是种子」撞不到，是因为随身栏现在只装种子（代码仓 `src/World/Farm/FarmField.cs` 的 `FillCarryBarWithSeeds`）。
- 「成熟分得开」→ `GP-87`「成熟那一阶段与它前一阶段在实际尺寸下分得开」。
- 「两种成熟」→ `GP-144`「一片地里看得到变与没变两种成熟」、PRD `US-009` 清单。
- 「收到变异」→ PRD `US-009` 清单。
- 「前后遮挡」→ `GP-144`「人站进一株作物那一格的上半截」、`GP-87`「走到作物后面被它挡住」。
- 「每一种都看一遍」→ `GP-146`「每一种都种下去、长到成熟看过一遍」、PRD `US-009` 清单的换批键那一样。
- 「数值第一版」→ `GP-87`「上面那四个量各调出第一版」；走动速度与可及范围那两个量不在这一份需求里，调出来一并说。
- 「四向走一遍」「帧率」「接着上一次」不对应这一份需求的勾选框，照走就是。
- 照着指南搭完、走完这张表，没有卡在指南的说法上 → `DOC-148`「照着两篇走得通」的一块地那一半。

## 实现笔记

### 设计决策

- **模糊点**：端到端读测试里手写的作物，还是工程里那批作物数据。
- **选择**：读工程里那批，走启动与农场共用的那个读法；循环收获那一条把其中一份的收获后退回那一格改成 1 再解析。
- **理由**：这份需求的一半是「素材表上每一种都种得下去」，用手写的作物就测不到那批数据真的读得进来、按标识排的第一批真的种得下去。占位作物都只收一次，所以循环那一条要在读进来的文本上改一处。

- **模糊点**：随机源怎么注入。
- **选择**：测试按顺序给一串随机数，每一次掷取下一个、再按几率判中没中。
- **理由**：这样几率规则也在路径上（小于几率算中），与农场里那一行是同一个判法；多掷一次就取空、当场失败，「没到成熟不掷」不用另数次数。

- **模糊点**：清单里怎么做写不写。
- **选择**：不写。指南「跑一遍验收」那张表每一行有一个加粗的行名，清单按行名对号到勾选框（`DOC-148`）。
- **理由**：怎么做只写一处，改做法时不会有一份清单留着旧的；行名写在指南里，勾选框编号只写在这里，编号归档之后指南里不留过期指针。

### 权衡

- **清单比 PRD 那一格长**：`GP-128` 与 `GP-87` 剩下的实机格并进来之后，一趟农场就能把三条的实机都看完，不用分三次搭。
