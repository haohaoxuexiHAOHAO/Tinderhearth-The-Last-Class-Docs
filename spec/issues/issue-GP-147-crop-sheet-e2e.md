# GP-147：作物素材表那份需求的端到端

## 目标

这一份需求的主路径与失败路径都有测试走一遍，作者照一份清单在农场里把全部改动看完。

## 来源

- PRD：[`spec/prd-crop-sheet.md`](../prd-crop-sheet.md) 的 `US-009`。

## 依赖

- `GP-143`、`GP-134`、`GP-144`、`GP-145`、`GP-146`、`DOC-144`：它们各自的测试与改动是这一条要串起来的东西。

## 验收标准

- [x] 自动化测试走完主路径：播种 → 推进到长成（必中）→ 待收且变异 → 收获结果带变异 → 回到已锄。测试在代码仓 `tests/Economy/CropSheetE2ETests.cs`，从工程里那批作物数据读起、经随身栏播种。
- [x] 覆盖失败路径：上限不小于 1 被拒；没到成熟不掷；循环作物下一茬重掷、不继承上一茬。
- [x] 测试独立可重复：随机源注入，不读真随机。每一次掷用的随机数由测试按顺序给，多掷一次就取空、当场失败；作物数据只读不写。
- [x] 代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。两个都看脚本自己打的摘要，不只看退出码。
- [ ] **作者实机确认清单**：要看的几样在 PRD `US-009` 那一格里（含农场里的随身栏与当前操作格）。落地时在本条展开成按在 Godot 里走到哪排的逐步清单，每一步写它勾哪一格；`GP-128` 与 `GP-87` 剩下的实机格一起串进来，它们等的也是农场跑起来。清单在下面「作者实机清单」。

## 作者实机清单

先照[一块地能种出东西](../../reference/godot/一块地能种出东西.md)搭到第六步，数值那几格照那一节的表先填。下面按在 Godot 里走到哪排，每一步后面写它勾哪一格。

**配素材**

1. 照第七步配好第一种之后，先把它的 `Mutated Ripe Texture` 清空，配完其余作物再按 `F6`：报错写明是哪一种作物、缺的是变异成熟那一张。→ `GP-144`「故意空一种作物的那一格」、`GP-87`「缺任一张作物素材时报错说清缺哪张」。
2. 把那一格补回去，`F6` 载入不报缺。→ `DOC-144`「照着配完全部作物，载入不报缺」。

**随身栏与当前操作格**

3. 数字键与手柄十字键各换几格，右下角那条随身栏的选中框跟着走。→ PRD `US-009` 清单里随身栏那一样。
4. 鼠标指着够得到与够不到的格，两张框照[一块地能种出东西 · 第五步：框出当前操作格](../../reference/godot/一块地能种出东西.md)看。→ PRD `US-009` 清单里当前操作格那一样、`GP-87`「框跟着指针跳格」。

**种一整轮**

5. 清理、锄、播、浇、收各做一次，每一下都看得见结果。→ `GP-87`「四个动作各做一次」。
6. 站在田边扫一眼：锄过没锄过分得出来，一屏之内分得出哪几格浇过水；耕地挨着草与裸土的硬边看一眼违不违和。→ `GP-87` 那三格。
7. 用数字键换一种种子再播。→ `GP-128`「换一种种子再播」。
8. 按 `B` 换到最后一批，选一个空格去播：输出面板说手上那一格是空的。另外两条被拒路径一条在游戏里撞不到（理由在 `GP-128` 条目的偏离），能撞的照撞。→ `GP-128`「三条被拒路径各撞一次」。

**成熟与变异**

9. 种一排按 `N` 到成熟：成熟那一阶段与前一阶段在实际尺寸下分得开，关掉颜色也成立。→ `GP-87`「成熟与它前一阶段分得开」。
10. 把 `Mutation Base Chance` 调到 `0.5`（上限照旧 `0.5`）重跑，再种一排按 `N` 到成熟：地里同时看得到变与没变两种成熟，输出面板为变了的每一格打一行。→ `GP-144`「一片地里看得到变与没变两种成熟」、PRD `US-009` 清单。
11. 收一株变异的：输出面板那一行带着「（变异）」。→ PRD `US-009` 清单。
12. 人站进一株作物那一格的上半截时被它挡住，走到前面时压在它上面。→ `GP-144`「人站进一株作物那一格的上半截」、`GP-87`「走到作物后面被它挡住」。

**每一种都看一遍**

13. 按 `B` 一批批换，把素材表上每一种都种下去、长到成熟看一遍。→ `GP-146`「每一种都种下去、长到成熟看过一遍」、PRD `US-009` 清单的换批键那一样。

**数值第一版**

14. 荒置天数、收几件、两个浇水系数各调出第一版，调完把数说一声，登进[数值模型](../../design/数值模型.md)。→ `GP-87`「那四个量各调出第一版」。

## 实现笔记

### 设计决策

- **模糊点**：端到端读测试里手写的作物，还是工程里那批作物数据。
- **选择**：读工程里那批，走启动与农场共用的那个读法；循环收获那一条把其中一份的收获后退回那一格改成 1 再解析。
- **理由**：这份需求的一半是「素材表上每一种都种得下去」，用手写的作物就测不到那批数据真的读得进来、按标识排的第一批真的种得下去。占位作物都只收一次，所以循环那一条要在读进来的文本上改一处。

- **模糊点**：随机源怎么注入。
- **选择**：测试按顺序给一串随机数，每一次掷取下一个、再按几率判中没中。
- **理由**：这样几率规则也在路径上（小于几率算中），与农场里那一行是同一个判法；多掷一次就取空、当场失败，「没到成熟不掷」不用另数次数。

### 偏离

无。

### 权衡

- **清单比 PRD 那一格长**：`GP-128` 与 `GP-87` 剩下的实机格并进来之后，一趟农场就能把三条的实机都看完，不用分三次搭。

无。
