# UI-61：手环能摆进农场

## 目标

作者把手环当一个节点摆进农场的界面根下面、接上素材资源，它就能开能关；缺哪一格当场报错。主场景里的手环照旧。

## 来源

- PRD：[`spec/prd-items-in-bag.md`](../prd-items-in-bag.md) 的 `US-007` 前半。
- 现状：手环只在主场景里由代码建出来（代码仓 `src/UI/WristbandPanel.cs`），素材资源、文本表与像素主题都由主场景塞给它，界面根不认得它。

## 实现笔记

### 设计决策

- **手环成了界面根认得的那一种。** 它声明自己挂面板那一层、是手环那个界面，界面根就绪时把它挪过去、登记、先藏起来，之后由导航栈开关。主场景由代码建的那一条照旧，两条来路由同一个就绪方法搭。
- **文本表与主题没人给就自己拿**，来源与主场景同一处：文本表走内容引导那一处读，主题用同一份素材资源装。不拿的话子页签上一片缺文本的占位，字也退回引擎默认字体，后者不报错。
- **界面根先藏再挪**（代码仓 `src/UI/UIRoot.cs`），与代码建的那一条先藏再挂同一个顺序。反过来的话，手环进面板那一层时自己先进树、页签后进树，可见的话就在这个夹缝里发显示变化的信号；手环在信号里给页签拿焦点，引擎报错（实测，见验证结果）。顺序放在界面根而不在手环里挡，是因为夹缝是挪法造成的：以后摆进来的面板在显示时拿焦点，也不会再碰到它。
- **主场景的主题在手环挂上之前给**（代码仓 `src/Main.cs`），与 HUD 同一份。晚给的话，手环就绪时没人给，会先自己装一份再被换掉。
- **暂停时农场停不停，按推断会停。** 依据：农场那几个脚本与场景都没改处理模式，跟着根节点是可暂停的（按处理模式的代码名与场景字段名搜过代码仓 `src/World/Farm/` 与 `scenes/`）；交互键只在 `FarmField` 的每帧回调里听；引擎文档写明可暂停的节点在暂停时不跑每帧回调与输入回调，信号照常送达（[Pausing games](https://docs.godotengine.org/en/4.7/tutorials/scripting/pausing_games.html)，内容为合规做过改写）。主场景记过一次同一条规则在输入那一半的实测（代码仓 `ARCHITECTURE.md`）。

- **文本表与主题各留两个来源**（给的，或自己拿的），不只留自己拿那一条：主场景已经读好了那一份文本表，再读一遍要把内容来源与 mod 再走一趟；农场没有主场景可依。
