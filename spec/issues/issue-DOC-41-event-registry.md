# DOC-41：这一批的新量登记与规模基准复看

## 目标

让这一批新出现的量都有登记与校准办法，而接口常量不被当成数值搬进参数表。

## 来源

- PRD：[`prd.md`](../prd-cutscene-dialogue-and-events.md) 的 `US-006`
- 起因：本批新出现了一组事件与引导侧的量（权重、冷却、触发条数上限、提示停留时长），而[`数值模型` · 尚未给值的量，各自写明校准办法](../../design/数值模型.md)那张表里现在一条都没有。
- 另一处：[玩法定位 · 内容规模基准](../../canon/gameplay/玩法定位.md)里小事件那一行现在只按「关系的兑现」写，而本批定下小事件是事件 —— 那一行与随机事件之间是什么关系要说清。

## 依赖

`NR-7`、`GP-52`（量是它们定出来的）。

## 验收标准

### 新量登记

- [x] 登记进[`数值模型` · 尚未给值的量，各自写明校准办法](../../design/数值模型.md)那张表，覆盖本批全部新量，至少包括：事件权重的基线与按失衡档位的偏移幅度、事件冷却的时长、每个钩子一次最多触发几条、引导提示的停留时长与同时显示上限。
- [x] **手感量归 `GP-6` 而不是 `GP-7`** 的那几项写明归属：跳过要按住多久、快进的倍率、对话推进的最短间隔（防连点跳过一整段），并写明它们为什么不进平衡判据。
- [x] 每条登记都写明**给值那一轮必须同时把判据接上**，形式与那张表已有各行一致。
- [x] 那一组写明**一条约束形式** —— **事件权重按档位的偏移不得大到让失衡自己滑到底**；同一处写明这**不是新约束**，[`活跃失衡系统` · 三个新读口带来一个正反馈，刹车必须先在](../../design/活跃失衡系统.md)已经写着它，本批只是把它的一头（事件权重）登记成一个有名字的量。
- [x] 那一组另写明**一条上界约束**：一次钩子触发多条事件时，它们各自的后果加起来也不许越过被调用那一侧自己的上限（例如需求系数那一层的幅度上限），并写明给值那一轮要把它接成判据。
- [x] **接口常量不进那张表**并写明归属，至少覆盖：三类事件、钩子有哪几处、演出指令的类型表、一次性与可重复两类。**免得以后被当数值搬走。**
- [x] **同一件事不新开登记行** —— 能并进已有那一行的就并进去，新开之前先找。

### 规模基准复看

- [x] [玩法定位 · 内容规模基准](../../canon/gameplay/玩法定位.md)里**小事件那一行复看**：本批定下小事件是事件之后，那一行数的还是「关系的兑现要多少条」；**同一处写明它与随机事件是两件事**（触发源与后果面不同），别处不复述。
- [x] 同一张表**补随机事件一行**，起步量要能覆盖到每一个后果入口与一次性、可重复两类，理由句说出「这个量级够试出什么」。
- [x] 同一张表**补剧情演出脚本一行**，起步量要能覆盖纯对话、带镜头与站位、带选项分支、关卡中途触发这几种用法，理由句说出为什么少了就试不出「一份格式」这条结论。
- [x] **持续引导提示补不补行，写明判断** —— 它是不是「一套内容要多少条才试得出这个设计成立」那一类；判断过程记进本条实现笔记。
- [x] **表里不复述别处的数** —— 量级事实只在它的家写一次，别处写链接。

- [x] `python tools/simulate_week.py --check-doc` 无分叉。**参数路径必须写全键名，不许用通配符指代。**

## 实现笔记

### 设计决策

- **模糊点**：事件权重按境况档位的**偏移幅度**要不要进本批那一行。
- **选择**：**不进** —— 它已经登记在[数值模型](../../design/数值模型.md)活跃失衡那一行里（连同那条刹车约束），本批那一行只写链接。
- **理由**：「同一件事不新开登记行」。而那条刹车约束（推力必须小于递减系数造成的阻力）本来就是失衡那一侧的不变式，把它搬到事件这一行会让它与被它约束的那个环分家。本批只把**权重的基线**登记进来 —— 那是新量。

- **模糊点**：持续引导提示要不要在[内容规模基准](../../canon/gameplay/玩法定位.md)里补一行。
- **选择**：**不补。**
- **理由**：那张表回答的是「一套内容要多少条才试得出这个设计成立」，而引导条目的条数是**派生量** —— 每个系统各一条，加教学关教过的各一条。写一个起步数会立刻和系统数分叉，而分叉的表现是「表里写 8 条，实际有 14 条」，没有任何东西判得出来。**它要多少条由系统数决定，不由这张表决定。**

### 偏离

- **方案怎么说**：条目里写「登记事件与引导侧那几个量」。
- **实际怎么做**：登记的是**基线、冷却、条数上限、提示停留与同时上限**四样；偏移幅度并进已有那一行。
- **为什么**：见上面第一条。

### 权衡

- **考虑过把「跳过要按住多久」也登记进[数值模型](../../design/数值模型.md)的主表**，否决：那是纯手感量、进不了平衡判据，归 `GP-6`；数值模型那张表已经在表头写明手感帧数不属于它。本批只在那一行的「归属」格里写明它们去哪。

### 待确认

- **那条「一次触发多条时后果加起来不越过被调用侧的上限」的约束**现在只有形式。它要等每个入口各自的上限都有值之后才接得成判据 —— 那一轮要同时改这一行。
