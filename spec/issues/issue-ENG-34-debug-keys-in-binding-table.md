# ENG-34：开发期调试键与输入绑定登在一处，冲突测试一起判

## 目标

开发期那几个直接读的调试键与输入绑定表登在同一处，「同一个物理位不被两个动作抢」那条测试把它们一起判。

## 来源

- PRD：[`spec/prd-items-in-bag.md`](../prd-items-in-bag.md) 的 `US-005`（调试键那一条）。
- 起因：背包要用 `B`，而 `B` 现在是农场里的换批调试键，直接读按键，代码仓 `tests/UI/InputMappingTests.cs` 那条冲突测试只扫绑定表，看不见它。

## 依赖

无。

## 验收标准

- [x] 可测试：农场与训练房里那几个调试键各登一条（哪个场景、哪个键、做什么），登在代码仓 `rules/UI/InputBindings.cs` 那一处或紧挨着它；直接读按键的地方从这张表取键，不再各写一个字面量。登记在紧挨着它的 `rules/UI/DebugKeys.cs`，农场与训练房（`src/World/Farm/FarmField.cs`、`src/World/TrainingRoom.cs`）按登记比键；每个调试键字段都在全部那一份里，有一条用例盯着。
- [x] 可测试：冲突测试把调试键与绑定表合起来判；故意让一个调试键与一条绑定撞同一个物理位，测试变红。合起来判的是代码仓 `tests/UI/InputMappingTests.cs` 的「同一个物理位不被两个动作抢」；另有一条用例常驻反过来构造一次撞位，判得出来。
- [x] 可核对：调试键照旧不进输入映射，不出现在玩家能改键的那份清单里。输入映射只照绑定表灌，调试键不在表里；上面那条冲突测试同时保证表里没有哪一条占着调试键的位。
- [x] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。

## 实现笔记

### 设计决策

- **调试键用绑定表同一套物理位符号。** 冲突测试比的是物理位，调试键只有落在同一套符号上才比得了；它们占的那几个位各加一个符号，注释写明只给调试键用。
- **调试键比物理键位，不比字符。** 绑定表一律按物理键位，两边比的若不是同一种「键」，冲突测试判的就不是实际按下去撞不撞。翻译走代码仓 `src/UI/InputMapInstaller.cs` 那同一处，不另写一张符号对引擎键的表。
- **调试键只许在键盘上**，有一条用例：比的是按键事件，落到鼠标或手柄位上按了没反应，而那不报错。
- **代码注释里不写调试键是哪个字母**，写「推进一天那个调试键」并指到登记那一处：字母只在登记那一处有一个家。给作者看的指南照旧写字母 —— 作者要知道按哪个。

### 偏离

无。

### 权衡

- **比物理键位之后按下去响不响，没有机器判据**：规则层够不着引擎事件。在作者用的键盘布局上，这几个字母的物理位与字符位是同一个键；绑定表里每个键也是按物理键位绑的、实机按得响，所以引擎送来的按键事件带着物理键位 —— 这是推断。农场那两个键在 `GP-147`、`GP-155` 那几趟实机里本来就要按，响不响顺带看到；训练房那三个跟训练房的实机走（`GP-14`）。
- **别的场景直接读按键、却不登在这里**，冲突测试看不见它；规则层够不着引擎层的代码，这一条只靠登记那一处的注释管着。
