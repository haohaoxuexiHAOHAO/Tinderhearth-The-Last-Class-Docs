# UI-48：代码里还在设的界面色按名字取色板里的一档

## 目标

界面上的每一个颜色都出自同一份色板，改色板里一个色全游戏一起变，不会长出第二套近似色。

## 来源

- PRD：[`spec/prd-ui-art-baseline.md`](../prd-ui-art-baseline.md) 的 `US-004`。
- 实测 `rules/UI/HudPalette.cs` 里的颜色没有一个在代码仓 `assets/self-drawn/palette.gpl` 里。探针实测，那批占位色多数在色板里已有近邻或凑得出。
- 色板口径在[像素绘制原则 · 本项目的色带口径](../../production/像素绘制原则.md)，本条不复述。

## 依赖

- `UI-45`：资源条的填充换成画的图之后，只为染色存在的那几个色才删得掉。按名字取那一半不等它。

- [x] 可核对：测试读色板时只读不写，定位仓库根靠向上找工程文件。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：画的界面件接进来之后，代码里还要设哪几个色、各取哪一档。
- **选择**：只剩正文、次要与强调那几档字色，冷却遮罩，伤害数字（与强调同一档）；各取离现在那个占位色最近的一档，记在色板被借那几条的「借给界面」里，本条不复述。面板底与边、条底、倒地头像色、格子高亮随画的图删掉；读条是画的两层，代码不染色。
- **理由**：原先那组占位色是判 12 像素中文可读性时用的配色，取最近的那档，那次判断大体还成立 —— 验收里实机重看那一格照旧不能省。

- **模糊点**：色值放哪 —— 运行时去读色板，还是抄在代码里。
- **选择**：抄在代码里，每一档带着色板里的项名（代码仓 `rules/UI/HudPalette.cs` 的 `PaletteEntry`）；测试读色板逐项对，项名拼错、值对不上都点名报出是谁取的哪一档。
- **理由**：`.gpl` 不是引擎资源，导出包里没有它（实测：`verify.py` 写出的导出清单里查不到），运行时去读，发行版里就读不到。

- **模糊点**：测试怎么知道代码里有哪几档。
- **选择**：反射扫规则层里所有静态的 `PaletteEntry` 属性；另有一条用例钉住反射确实找到了正文那一档与冷却遮罩那一档。
- **理由**：手列一份清单就是第二个家，新加一档忘了登记就没人核。反射一项都没找到时第一条会空跑通过，所以那条兜底不能省。
