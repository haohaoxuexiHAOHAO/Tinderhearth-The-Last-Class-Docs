# GP-29：开荒与地块状态机

## 目标

让一片荒地要玩家自己清出来，清出来的东西还能当材料；地块从未清理到待收的流转写清。

## 来源

- PRD：[`spec/prd-base-and-production.md`](../prd-base-and-production.md) 的 `US-006`

## 依赖

依赖 `GP-28` —— 它是六条渠道里唯一有自己状态机的那条，先有共用管道才判得出它要不要独立成篇。

## 验收标准

- [x] 地块状态与流转写清（未清理 → 可耕 → 已播种 → 待收，收获与换季枯死都回到可耕），换季枯死与跨季作物接既有正典
- [x] 清理物**只产初级材料**且供应受重生速率限制；进阶材料仍靠加工或购买
- [x] 清理物**只在未开垦区域重生**，已开垦地块不长，理由写明（不罚离家出征的玩家）
- [x] 开局那一小块已开垦的种植区按[玩法定位 · 开局](../../canon/gameplay/玩法定位.md)保留 —— 不要求玩家第一天先开荒
- [x] **拆分判据写进文档**：判据是「有没有自己的状态机」；**按篇幅实测的结论是不拆**，`design/种植系统.md` 不建
- [x] 全文一个玩法数值都没有（重生速率、清理产量归 `GP-2`）
- [x] `python tools/check_docs.py` 0 FAIL

## 实现笔记

### 设计决策

- **模糊点**：耕地用哪套网格 —— 建造那套 80×60 的格，还是自己一套。
- **选择**：**用建造那套格**，一格一株，不另设耕地网格。
- **理由**：两套网格会让「这块地能不能盖房」变成要两处对账的问题，而 `可耕` 这个状态本来就等于「普通的可建造格」。顺带它让「开荒出来的地既能种也能盖」自然成立，不需要额外规则。

### 偏离

- **方案怎么说**：篇幅超过其余五条渠道之和就拆出 `design/种植系统.md`。
- **实际怎么做**：**没拆** —— 写完实测没超过，所以地块那一节留在[`生产系统`](../../design/生产系统.md)里。
- **为什么**：拆分判据是「有没有自己的状态机 ＋ 篇幅是否压过其余」，前者成立、后者不成立。拆了反而要在两份文档之间维护一套接口，而那套接口现在只有一条（地块的缺水标记给将来的灌溉设备）。

### 权衡

灌溉只留了一个接点（地块的「缺水」标记），没有铺开自动化灌溉 —— 正典把它排在后面，现在写等于替将来的设备设计做决定。

### 待确认

无。清理物的重生速率与产量归 `GP-2`，已记在 `DOC-14`。
