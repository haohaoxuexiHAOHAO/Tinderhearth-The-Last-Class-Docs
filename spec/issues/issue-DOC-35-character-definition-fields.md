# DOC-35：一个角色定义上有哪些不会变的声明项

## 目标

角色定义上那些声明项收成一张表，于是把角色外置那一轮不必翻遍全部系统文档才拼得出它。

## 来源

- PRD：[`spec/prd-design-closure.md`](../prd-design-closure.md) 的 `US-002`
- 落点判据：[`成长系统`](../../design/成长系统.md)已经持有「角色身上会涨的量」，再多一节「角色定义上不会变的声明项」是同一侧
- 两处已经点名要收进本条那张表：[`日记系统` · 谁有日记，由角色定义上的一个声明项决定](../../design/日记系统.md)与[`角色动作状态系统` · 一个角色有哪些动作，是它自己声明的](../../design/角色动作状态系统.md)

## 依赖

无。与 `DOC-64` 同类、同一轮做，两者都排在 `ENG-5` 之前。

## 验收标准

- [x] 可核对：[`成长系统`](../../design/成长系统.md)多一节，把角色定义上的声明项列成一张表，每行只写「有哪些、缺了报不报错、规则在哪」，**不复述规则**。
- [x] 可核对：那张表覆盖到已经散在别处的那几项（恋爱资格、偏好轴、专属栏格数），并且每一项都指回它自己那份文档。
- [x] 可核对：写明**这张表是开口的**，以及加一项的判据（它说的是「这个角色是什么」而不是「他能干什么」—— 与[`建造系统` · 加新字段前先问一句](../../design/建造系统.md)同一形状）。
- [x] 可核对：名册容量**不进这张表**并写明理由（它是配置项、不是某个角色的属性）。
- [x] 可核对：`python tools/check_docs.py` 0 项必须修复。

## 实现笔记

> 由实现与评审之后填写。四类都要过一遍，某类没有就写「无」并简要说明。

### 设计决策

- **模糊点**：PRD 点名了三项（恋爱资格、偏好轴、专属栏格数），而「完整」要覆盖到哪里没说。
- **选择**：按名搜全库，收进已经明写「在角色定义上」的每一项 —— 标识、显示名文本键、出生特质（这三项代码里已有）、动作集、恋爱资格、装备偏好轴、专属栏格数、有没有日记。
- **理由**：两处已经点名要收进本条那张表（[`日记系统`](../../design/日记系统.md)与[`角色动作状态系统`](../../design/角色动作状态系统.md)），漏掉它们等于让那两处的引用指向一张不含它们的表。判据取「文档里明写它在角色定义上」，不取「看着像角色属性」—— 后者会把派生量与参数表里的量一起吸进来。
- **模糊点**：这张表本身算不算第二个家 —— [`存档系统`](../../design/存档系统.md)刚刚才排掉一张集中字段表。
- **选择**：建这张表，但**把它的代价写在同一节里**，并写明代码里那条记录是最终权威。
- **理由**：两个情形不同。存档那边每个分片声明本来就各有一个家，集中表是纯粹的第二份；而「一份角色定义有哪些键」现在**一个家都没有** —— 那正是这一条的缺口。仍然有一栏是副本（「缺了怎么办」），所以降低代价的办法都写明了：「规则在哪」那一栏指得到原文、表不抄规则只抄那一句报不报错、代码里 `rules/Progression/CharacterDefinition.cs` 那条记录是单一真相。这落在 [WORKFLOW § 3](../../WORKFLOW.md)写明的那两条不能根治的边界之内，不假装已解决。
- **落点选在[`成长系统`](../../design/成长系统.md)而不是新开一篇**：拆篇判据是有没有自己的状态机，这张索引没有；而「这个角色是什么」与「他身上什么在涨」是同一个问题的两半，分居两处会让填一份角色定义要翻两份文档。
- **不进这张表的各写了理由**：名册容量（配置项，一个角色身上没有「名册能装几个人」这回事）、会涨的量与派生量（在本页另一侧）、值归参数表的量（[`教育系统`](../../design/教育系统.md)那个按角色取的满值 —— 「按角色取」说的是读取形状）、作者在 Godot 里摆的东西（碰撞区域与受击框本体，[ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md) 的分工）。

### 偏离

- **方案怎么说**：PRD 要求「列成一张表」。
- **实际怎么做**：一节里两张表 —— **全体必填的那几项**一张，**按声明才有的那几项**一张，「缺了怎么办」按级别在表外定一次。
- **为什么**：作者随后裁定内容定义**按声明扩展、不按类型分叉**（[ADR-0018](../../decisions/ADR-0018-内容定义按声明扩展.md)），而那条判据的形状正是两级必填。顺带把我原来写明的那个代价变小了：「缺了怎么办」原先是每项一句的副本，现在按级别定一次，副本从八句缩成两句。

- **方案怎么说**：PRD 只要求加一节与一张表。
- **实际怎么做**：另把两处指向本条的引用改成按名指那一节（[`日记系统`](../../design/日记系统.md)与[`角色动作状态系统`](../../design/角色动作状态系统.md)），并给[`成长系统`](../../design/成长系统.md)补了验收项与边界条款。
- **为什么**：那两处原来写的是**状态**（「那张字段表还没拼出来，进度见台账」「这一格要收进那张表」），本条做完它们就过期了 —— [WORKFLOW § 3](../../WORKFLOW.md) 第 3 条要求按编号搜两个仓加 `.kiro` 一起改。搜下来活文档里只有这两处，其余命中都在 `archive/`（不动）。

### 权衡

- **「敌人定义」原先记账后置，作者答复后当轮答掉。** 先按超边界立了 `DOC-82`（[`角色动作状态系统` · 真正死亡](../../design/角色动作状态系统.md)把魔化载体类别写在敌人定义上，而 `ENG-5` 那份清单把「角色定义」与「敌人」分成两项列）；作者随后定了方向，于是答案落进 [ADR-0018](../../decisions/ADR-0018-内容定义按声明扩展.md)：**一张表**，「会真正死亡」成了按声明才有的一项，`DOC-82` 随之关闭。**当时记账没有白记** —— 它让这个问题在被答之前一直查得到。
- **没选给每一项也写「值归谁」一栏。** 这张表上的项大多不是数值（标识、文本键、动作集都不是），写了会有一半是空格 —— 与本页排掉「全局专长轴表」同一条理由。

### 待确认

- **表是开口的，所以它会随系统长。** 加一个声明项而忘了回来加一行时没有守卫判得出来，只能靠改的人顺「规则在哪」那条链核一遍。这一条已经写在那一节里，不是遗漏。
