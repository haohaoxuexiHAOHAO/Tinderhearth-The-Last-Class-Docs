## 实现笔记

### 设计决策

- **端到端那一条判的是段与段之间的交接**：各段的关系各有单测；这里每一步用的数取自上一步，或取自作者画好的那张图的尺寸 —— 格子推出那条栏、栏高对画好的那条栏，HUD 资源条的槽高就是精英血条的高、也就是画好的那张槽的高。一段改了、下一段没跟，各自的单测照样过，这里红。
- **主路径写成一条测试，照需求那条链的顺序走**：拆成几条就又是一组单测，看不出这一段接着那一段。哪一步红，断言上面的注释写着是哪一步。
- **失败路径用的是真判据，而且要点得出是谁**：
  - 纵深带那条拿主路径用的那个越界判定，看挪进去一像素的正是被报的那一块、别的块不受连累，贴着下沿不算越界。判越界的那个入口只收它自己算的那一套，所以测试照它的做法过一遍挪过一块的那一套。
  - 色板那条对被界面引用的每一档各改一次值、各删一次，报出来的要正是取那一档的那几处。
  - 素材资源那条照实机删格那一步清空两格，报的条数与清空的格数一样，每一条带路径、尺寸与状态。
- **目标没报高度那条另判绕不绕得过**：世界那一层的偏移只收核过的那一份，而它只有一个入口；测试钉住它没有公开构造函数、两项都改不了。有人加一个，没报的目标就绕过去了，而那不报错。
- **「只读不写」落成测试**：读色板前后，文件的哈希与修改时间都不变，内存里改过的那一档不留到下一次读；几条测试共用的素材清单改不动。只靠读代码看出来的只读，哪天有人在读的那一处顺手写回去，没人知道。
- **读色板、找不带项名的颜色、照清单填一份，用既有测试里那一份**：`PaletteTests` 与 `UIArtTests` 里的帮手改成测试程序集内可见，不另写第二份。
- **实机清单按在 Godot 里走到哪排，不按条目排**：打开一次关卡预览就能把手环、指针、资源条、格子角上的字一起看完，再换基地、再改素材资源、最后去农场。每一步写它勾哪一格，判据留在那一格里不复述。

### 偏离

- **方案怎么说**：清单只走两种场合的 HUD、手环与素材资源那几样。
- **实际怎么做**：清单把这份需求剩下的实机格都串成一趟：资源条怎么动、格子角上的字、指针、字读不读得清、农场里的随身栏与当前操作格、作者自查。两种场合的 HUD 与手环已经在 `UI-42`、`UI-44` 的实机里勾过，不再重看。
- **为什么**：这份需求收尾之前作物那份不动代码，而剩下的实机格散在几个条目里；串成一趟，作者看一次就能收尾。

### 权衡

- 与各段单测有重叠：纵深带、色板、缺格那几条判据两边都撞。不删：单测钉的是一段自己的关系，改那一段时先红的是它；这里钉的是交接。删掉任何一边，另一边判不到对方那一种坏法。
