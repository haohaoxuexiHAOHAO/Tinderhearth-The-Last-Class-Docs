# UI-32：手环队伍页显示两个档名

## 目标

玩家在出征前看得到每个学生的操作档与配合档走到了哪一档。

## 来源

PRD：`spec/prd-richness-and-feel.md` 的 `US-019`。

立项理由：「学生变强必须看得见」是[战斗与关卡](../../canon/gameplay/战斗与关卡.md)那条分档设计的全部目的，而[`战斗AI系统`](../../design/战斗AI系统.md)自认这也是它的核心风险、且**永远没有机器判据**。而支撑玩家感知它的渠道现在都不成立：档号不上战斗抬头显示（省屏幕空间，那个取舍保留）、行为差异靠还没有的内容、唯一的提示渠道是**一次性**的引导提示 —— 它答不了「他现在到哪一档」。

改法：放手环队伍页，战斗界面一个字不加。

## 验收标准

- [x] [`界面系统`](../../design/界面系统.md)的手环队伍那一处必须显示两个档名，并写明为什么不上战斗抬头显示（指回既有理由，不复述）
- [x] 两个档号**分两格显示、不给总评** —— 那条既有的硬约束照旧管着它
- [x] 读的是两条轴各自的档位读口，**不读精确值**
- [x] 两套档名不会被误读成同一套（技艺词一套、关系词一套，档名交集为空那条照旧）
- [ ] **作者实机确认**：满编时那一页装得下
- [x] `python tools/check_docs.py` 0 FAIL

## 依赖

无强依赖；读的是 `GP-36` 那两条轴各自的档位读口。

## 实现笔记

### 设计决策

- **模糊点**：「手环队伍那一处」在[`界面系统`](../../design/界面系统.md)里**不存在**。那一份的载体表把**队伍状态**列在查看类里（正典也点名了它：关卡内只许查看图鉴、任务目标与队伍状态），而全份文档没有一节写它 —— 又一次「读口在、名字在、页不在」，且没有任何东西会报错。
- **选择**：给它补一节，按那份文档既有的三样写；**本轮这一页只装那两个档名**。
- **理由**：走的是那一份自己写下的路（「加一页时按同一条办：那时按本页那三样补一节」）。**它比 `UI-30` 那一屏更轻**：载体归类不用判（那一格早就在查看类里）、读口不用找（那两条轴的档位读口早就在），**所以 `UI-29` 那条「手环标签页的条数一个未增」照旧成立** —— 本条没有新开一格，只是把那一格的内容写出来。这一句要写明，否则看起来像是刚把它加进去。
- **战斗界面一个字没加。** 两个档号仍然不上抬头显示，那条理由（满编一屏下常驻要占掉最贵的那块地，而档号平时不变）在那一份的「理由与取舍」里，**本条只指回去**。[战斗与关卡](../../canon/gameplay/战斗与关卡.md)与[`角色动作状态系统`](../../design/角色动作状态系统.md)**都零改动**。
- **它与角色面板那一行战斗评级是两页，不是两个家**：两处都读那两条轴的档位读口、界面侧一份都不存。判据写成了两个问题 —— **角色面板答「这个人是什么水平」，队伍页答「这几个人里谁是什么水平」**。跨人比较本来就要一张把人列在一起的页，而那正是角色面板那一节当时写下「跨学生的比较不在本轮」时缺的那张。
- **由此顺带修了那一节的口径**：那张列表页现在有了，但它只装这两个档名 —— 吸收效率与关系那两处跨人比较**仍然不在本轮**，要上去得按那三样另写一条，而不是因为「那一页反正已经在了」就顺手挂上去。
- **「不给总评」那条反证要在两处各判一次。** 一处守住不等于另一处守住，而合成（取较低者或加权）在数据上不违反任何东西 —— 读口仍然是两个，所以它不报错。

### 偏离

- **方案怎么说**：「两套档名不会被误读成同一套（技艺词一套、关系词一套，档名交集为空那条照旧）」。
- **实际怎么做**：写的是**两格各自带轴名**，理由是**两条轴共用同一套五档档名**；而「档名交集为空」那条照旧、但它防的是另一对。
- **为什么**：验收那一句把两件事合成了一句。正典只给 AI 分档一套档名（生手到大师，那是**技艺词**），[`战斗AI系统`](../../design/战斗AI系统.md)也明写两条轴**共用同一套**；而「交集为空、靠词义分层防撞」那条说的是**AI 档名与关系档名**之间（技艺词对关系词）。所以这一页上真正的误读风险不是「两套档名撞了」，而是**两格用的是同一套词** —— 不标明哪格是哪条轴，玩家猜错了看起来仍然合理。关系那一套词**不出现在这一页上**（本轮它只装两个档名），所以那条防撞规则在这一页没有对象；它照旧管着角色面板那一屏（那里关系档与战斗评级紧挨着）。

- **方案怎么说**：只说「手环队伍那一处」。
- **实际怎么做**：另写明**挑谁去不在这一页**（那是编队：安排别人，所以归操作类、关卡内禁用），并在「同名不同物」里给「队伍页」与「编队」立了一条。
- **为什么**：这一页在关卡里打得开，而编队在关卡里必须关着。不写这一条，落地时最自然的做法就是把「看队伍」与「排队伍」做成一页 —— 那时关卡内要么把查看一起锁掉（正典点名它可以查看），要么开出一条调度的后门。

- **顺带改了持有方一处**：[`战斗AI系统`](../../design/战斗AI系统.md)的边界里原先写着「那一份把两个档号落在**角色详情页**一行战斗评级的两格上」。**那是一份会过期的副本**，而它已经在过期路上 —— 页名与界面那一份的「角色面板」对不上，而本轮它又多了一页。改成只说「摆成两格、不许合成总评」，**摆在哪几页由界面那一份说**。形状与 `UI-29` 那轮修持有方三处读口行一样。

### 权衡

- **本轮这一页刻意很薄**（每人一行、每行两格）。它本来可以顺手装上养伤、精力、关系与境况 —— 代价是那几样各有自己的页或还没有落地编号，而「这一页反正已经在了」正是页面膨胀的入口；那一份的判据是「每一页只答一个问题」，装上那几样之后它就答不出「它答哪一个问题」了。
- **满编时那一页装不装得下没有机器判据。** 每一行两格，行数等于名册人数 —— 这一条比角色面板那一行更容易出事（那一屏上只有一个人）。它归作者实机，本条不判。
- **缺值那一格显示成最低档而不是空白**：配合档读的正是关系档位，而没创建过的对读作最低档（[`人际系统`](../../design/人际系统.md)那条既有规则）—— 一个空格子读起来像坏了。

### 待确认

- **那一页要不要能排序（按操作档、按配合档）现在不定。** 名册人数是一个量级已定的数（家在正典那张表），这一页一屏装得下的话排序就是多余的；装不下时排序与滚动哪个更顺只有实机看得出来。**若将来要加，它是这一页的第二个问题（「谁最强」），按那三样另写一条。**
