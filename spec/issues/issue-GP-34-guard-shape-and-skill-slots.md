# GP-34：正典补齐防御的形状与技能位的边界

## 目标

把防御「按下之后到底怎么回事」写清（朝向、能不能动、精准怎么判、怎么防狂点），并把技能位收窄成只装主动技能、光环改成不设数量上限。

## 来源

- PRD：[`spec/prd-growth-skill-damage.md`](../prd-growth-skill-damage.md) 的 `US-001`，[战斗与关卡](../../canon/gameplay/战斗与关卡.md)那一半
- 现状留了两处没答：[战斗与关卡 · 防御与失衡](../../canon/gameplay/战斗与关卡.md)只写「防御分两档」，没写精准那一档怎么触发；[`角色动作状态系统` · 动作叠加层：互斥的主动动作，给运动层一个"定身/忙"标志](../../design/角色动作状态系统.md)写的是「锁住**或**限制移动」，两种读法都留着。
- 另一处是自相矛盾：[角色与成长 · 技能分两类：放出来的动作，与做事的熟练度](../../canon/gameplay/角色与成长.md)写「战斗技能（主动与被动）占技能位（6 个位）」，而[战斗与关卡 · 主角的招式构成](../../canon/gameplay/战斗与关卡.md)写「普通被动技能不设上限」。

## 验收标准

- [x] [战斗与关卡 · 防御与失衡](../../canon/gameplay/战斗与关卡.md)写明**防御朝向就是角色朝向**，不存在「盾朝前、人后退」；并写明这同时解释了防御为什么不需要一个独立的方向输入。
- [x] 同一节写明**防御即定身**：按下那一刻朝向定住，期间不移动，要换位置先松开。理由一起写 —— 移动的职责归闪避与冲刺（正典把闪避定为唯一带无敌帧的脱身手段），而精准防御要求帧级准确，同时按住移动会给「按下那一瞬」多一个变量。
- [x] 同一节写明**普通与精准不是两个动作，是同一次按下的两段**：按下防御的起始窗口内挡住来袭是精准防御，此后持续举着期间挡住的一律是普通防御。并写明推论 —— 预判提前举盾拿不到精准回报还要付体力条，这正落在「奖励敢在正确的时刻按下去」那条意图上。
- [x] 同一节写明**连点防御键不刷精准窗口**：两次按下间隔过短时，第二次只进普通防御。理由一起写 —— 不堵的话狂点防御就是最优解，判据形式与「打空不能续段」「实战值只在命中时累积」同一条纪律。
- [x] 窗口帧数与连点间隔下限**不在本条给值**，正典写明归 `GP-6`（只能实机逐帧调）。**进[`数值模型`](../../design/数值模型.md)尚未给值表那一步放在 `GP-35`** —— 它本来就要重写那张表，两条条目改同一张表会撞。
- [x] 闪避冷却写进[战斗与关卡 · 按键与连击](../../canon/gameplay/战斗与关卡.md)，**冷却必须有下限**；「闪避没有被动率」原样保留，并写明两条不冲突（一条管躲不躲得开，一条管多久能再躲一次）。
- [x] 「6 个技能位」收窄成**只装主动技能** —— 出征前选 6 个带进关卡；[角色与成长](../../canon/gameplay/角色与成长.md)那张表里「主动与被动都占位」的说法跟着改。
- [x] 写明**被动技能、天赋与常驻光环都不占位，也不另设「能装几个」的上限**；同一处写明这与天赋点总量上限（判据 C2）不冲突 —— 那条管「你能点几个节点」，本条管「点到的要不要挑着装」。
- [x] [战斗与关卡 · 主角的招式构成](../../canon/gameplay/战斗与关卡.md)里「常驻光环有槽位上限」改写成不设上限，**并换掉旧理由** —— 不能留着「不设上限就回到数值堆叠」却把上限删了。改写处写明槽位上限被什么替代，并指向将来的 `技能系统`。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：「常驻光环有槽位上限」删掉之后，那句话的理由（「不设上限就回到数值堆叠」）要不要留着当警示。
- **选择**：**整句换掉**，写成「不设上限，防堆叠靠同类只取最大 ＋ 必带可感负面」，并写明选约束而不选数量钳的理由是「玩家看得见原因」。
- **理由**：留着旧理由就是留一句与现行规则矛盾的话。而且删了上限不给替代，等于把正典那条担忧变成没人负责的漏洞。

### 偏离

- **方案怎么说**：窗口帧数与连点间隔下限要登记进[`数值模型`](../../design/数值模型.md)的尚未给值表。
- **实际怎么做**：正典写明它们归 `GP-6`，但**没有动那张表** —— 登记那一步挪进 `GP-35`。
- **为什么**：`GP-35` 本来就要重写同一张表（派生公式那一批新量）。两条条目各改一次，第二条会在冲突里重排第一条刚加的行，而那种 diff 最难复核。

### 权衡

「防御期间能不能移动」考虑过「能朝自己朝向那边慢速前进」。取定身，因为那条会要求玩家同时按住移动键与防御键，而在 `WASD` 手位下防御键无论放哪根手指都在跟移动抢 —— 它会直接压缩 `UI-14` 的解空间。

「精准防御怎么触发」没选「另给一个键」或「靠松手时机」。取「按下的起始窗口」，因为它同时满足两件事：正典要的「奖励敢在正确的时刻按下去」，以及不新增按键 —— 而键位本来就已经不够（见 `UI-14`）。代价是必须补「连点不刷窗口」，否则狂点就是最优解。

### 待确认

无。窗口帧数与连点间隔下限只能实机逐帧调，归 `GP-6`。
