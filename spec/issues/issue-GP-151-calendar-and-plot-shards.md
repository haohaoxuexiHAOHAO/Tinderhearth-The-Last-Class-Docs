# GP-151：日历与地块两个分片，存进去读出来一样

## 目标

日历与那片地各是正式存档里的一个分片：存进去再读出来完全一致，分片按什么顺序读结果都一样；地块那一份存的项与设计里那张清单一致，而那张清单补上它漏掉的一项。

## 来源

- PRD：[`spec/prd-sleep-advances-day.md`](../prd-sleep-advances-day.md) 的 `US-004` 第三、四、七、八格，`FR-21`、`FR-41`。
- 地块存什么在[`地块系统` · 一格要存什么](../../design/地块系统.md)，进哪一侧的判据在[`存档系统` · 进哪一侧：判据一句话](../../design/存档系统.md)。

## 依赖

- `GP-148`：存的是那份世界状态。
- `GP-150`：分片按那里的声明注册。

## 验收标准

- [x] 可测试：日历与地块两个分片存进去再读出来完全一致；地块逐格逐项比，含变异那一位。走的是整份正式存档的文本，那片地里有在长、待收且变异、收过一茬又在长、枯死、荒置、未清理、可耕各一格。测试在代码仓 `tests/Economy/WorldShardsTests.cs`。
- [x] 可测试：分片按逆序、乱序读，结果与顺序读一致。分片里各格的先后倒过来也一样。
- [x] 可测试：地块分片存的项与[`地块系统` · 一格要存什么](../../design/地块系统.md)那张清单逐项一致。测试比的是地块的全部公开属性：分片里每一项状态各一格，一项不多、一项不少；那张清单照这些属性补齐。
- [x] 可核对：那张清单补上「这一茬实际经过了几天」：它是产量系数的分母，由别的项算不出来（代码仓 `rules/Economy/Plot.cs`）。为什么推不出来写在那一节里。
- [x] 可测试：一格地存的项彼此矛盾时载入被拒并点名哪一格（例：没有作物的状态带着作物标识、计数为负、阶段超出那种作物的阶段数）。另有在长的作物记着变异、认不出的状态、一串的项数不对；几格同时坏了一次全报。
- [x] 可测试：两个分片的存档默认值就是开新档时那一份：日历是开局那一天，地块是场景里那片地的起始状态。注册之后那片地再怎么变，默认值不跟着变。
- [x] 可核对：分片里没有派生量；摘要不进存档。一份世界只写日历与地块两个分片（有测试）；格坐标由左上角与宽高算出来，不存。
- [x] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。

## 实现笔记

### 设计决策

- **模糊点**：地块那一块按格排（每格一个对象），还是按项排（每项一串）。
- **选择**：按项排：摆法（左上角、宽、高）之外，每一项状态一串，串里从上到下、每行从左到右。代码在代码仓 `rules/Economy/WorldShards.cs`。
- **理由**：缺字段按存档默认值补，补的是分片里的一格。按项排时地块的一项状态正好是一格，以后给地块加一项，旧存档缺的就是那一格，补得上；按格排时新加的那一项落在每一格的对象里，分片那一层补不到它。代价是读起来要按下标数格子。

- **模糊点**：存档默认值什么时候取。
- **选择**：注册那一刻把开新档那一份写下来，之后每次给它的一份拷贝。
- **理由**：农场里那片地注册之后就开始变；默认值若每次现写，读到的会是玩到一半的那片地。

- **模糊点**：读回来时拦哪些矛盾。
- **选择**：只拦地块那台状态机自己走不出来的组合：没有作物的状态带着作物标识、计数或浇水标记；空着的已锄地之外记着荒置天数；有作物的状态没有标识或找不到定义；变异不在待收；在长的阶段到了或过了成熟；待收不在成熟那一阶段；枯死的计数不是零；计数为负。判法在代码仓 `rules/Economy/Plot.cs` 的 `Problems`。
- **理由**：拦得比状态机还严，一份正常走出来的存档就会被拒，而那等于丢档。浇水天数与经过天数的大小关系就没拦：它错了只让产量系数落到上下限，不会让任何东西坏掉。

- **模糊点**：读一格时取不到、类型不对怎么报。
- **选择**：一组共用的取法（代码仓 `rules/Foundation/Save/ShardFields.cs`），报错一律写明哪个分片的哪一格、实际写的是什么；一片地里几处坏了一次全报。
- **理由**：每个分片的持有者都要读自己那一块，报错的口径该一样；一格一格修、修一处跑一次，是最慢的那种排错。

### 偏离

- **方案怎么说**：「存档里的作物标识在作物定义里找不到时被拒，点名哪一格、哪个标识」是 `GP-153` 的一格。
- **实际怎么做**：判在这里的读法里，测试也在这里（`地里那种作物找不到定义时被拒并点名哪一格与哪个标识`）。
- **为什么**：读地块那一块本来就要拿作物定义核阶段有没有超出，找不到定义是同一处的同一类问题。`GP-153` 那一格到时候勾上并指到这条测试。

### 权衡

- **对齐清单的那条测试比的是代码，不是设计文档**：代码仓的测试不读设计仓。那张清单照地块的公开属性补齐，以后两边对不对得上靠改的人守。
