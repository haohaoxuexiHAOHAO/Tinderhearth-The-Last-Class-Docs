# GP-32：`design/伤害系统.md`

## 目标

把「一次命中怎么算出一个数字与一条状态」写在一处，加新技能时不用重新发明结算顺序。

## 来源

- PRD：[`spec/prd-growth-skill-damage.md`](../prd-growth-skill-damage.md) 的 `US-003`
- 现状：代码仓 `rules/Combat/HitResolution.cs` 只产命中反应（击退距离、硬直帧数、顿帧帧数），一点伤害计算都没有 —— 所以结算顺序落地时是新增，不是改写既有行为。

## 依赖

`GP-33`（防御与抗性从哪来、韧性上限这个名字）与 `GP-34`（防御的形状）。本页读它们定下的量，不自己定。

## 验收标准

- [ ] 新文档按 [SYSTEM 模板](../../templates/SYSTEM.md)八节写全，`type: system`、文件名以「系统」结尾、`upstream` 指[战斗与关卡](../../canon/gameplay/战斗与关卡.md)，并被正典链接到。
- [ ] 结算顺序写死 **倍率 → 防御 → 暴击 → 保底 1**，并写明为什么暴击排在减伤之后（排在前面时暴击会被减伤吃掉一部分，「暴击翻多少倍」就随对面防御变，玩家看不懂）。
- [ ] 伤害类型只有物理与魔法，**各对一份防御**；防御的边际收益递减。
- [ ] 穿透落在防御那一步：物理穿透只减物理防御、法术穿透只减魔法防御，且**穿透后的有效防御不得小于 0**（不做负防御放大）。
- [ ] **元素不是伤害类型** —— 它是技能字段，唯一的机制作用是决定这一击尝试施加哪种状态；「弱火」是内容描述用语，机制上读的是灼烧那条状态的抗性，**没有单独的火抗**。
- [ ] 状态抗性**按状态各一份、减施加概率**，实际概率钳在 0–100；构造「技能概率 100 对抗性 0」与「技能概率 0 对抗性 100」两个极端，两者都不得产生越界值。
- [ ] 两条硬约束写明：**技能的施加概率不得等于或超过 100**、**抗性不得堆到 100**，理由是两头都要留一线（否则要么必中要么免疫，状态这一维就没有博弈）。
- [ ] **不做友军伤害** —— 同阵营命中不进结算，一条反证测试。
- [ ] 暴击只作用于伤害，**不作用于治疗与屏障量**（否则回血量随机跳动，玩家没法规划）。
- [ ] 本页不新建载体也不新建姿态 —— 施加状态调[`状态效果系统`](../../design/状态效果系统.md)、硬直与失衡的姿态归[`角色动作状态系统`](../../design/角色动作状态系统.md)；接口表列全挂载点并写明「到此为止」。
- [ ] 边界那一节写明本页**不持有**命中判定（横向与纵深两个条件在正典与 `rules/Combat/DepthOverlap.cs`）、不持有打击反馈、不持有伤害数字的显示。
- [ ] 文档里一个玩法数值都没有。
- [ ] `python tools/check_docs.py` 0 项必须修复。
