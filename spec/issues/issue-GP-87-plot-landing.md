# GP-87：地块落地（开荒与种植共用的那台状态机）

## 目标

一格地从长着杂草到收上来一筐菜，全程可玩。规则、状态与字段表的权威是
[`地块系统`](../../design/地块系统.md)，本文件只记落地这一侧：谁做了哪一半、换过哪条口径、还剩什么。

## 分工

| 谁 | 做什么 |
| --- | --- |
| 作者 | 俯视场景的节点树、两层瓦片图层（天然地形 ＋ 耕地叠加）、耕地那 16 张与干湿两套、作物各阶段素材加枯死那张、检查器里那几个量 |
| 代理 | 状态机与作物定义（规则层）、把它接到瓦片层与作物精灵、当前操作格那个框、俯视走动、缺素材报错 |

跟着做的逐步指南在 [`reference/godot/一块地能种出东西.md`](../../reference/godot/一块地能种出东西.md)。

## 已落地的

**规则层**（代码仓 `rules/Economy/`，不引用 Godot，有单元测试）：那台状态机、作物定义那张表、
收获量规则、浇水那两个量、荒置退化。**承重的那一条**：收成取整且至少 1 件 —— 它挡的是
「出征回来颗粒无收」，与「家畜不死只停产」同一条纪律。

**引擎侧接线**（代码仓 `src/World/Farm/`）：把状态机接到两层瓦片图层（耕地那一层走引擎原生的
四边拼接，干湿各是一种地形、各自拼接）、作物按阶段换图、当前操作格那个框、俯视走动、
以及**缺哪张素材报错说清缺哪张**（那条校验只能在引擎层，规则层看不见任何素材路径）。

**顺带立下的那条分线**（行为字段归规则层、素材归引擎层）记在代码仓 `ARCHITECTURE.md`。

**它是从 `GP-28` 拆出来的，不是新需求** —— 拆篇那条判据与量法在[`生产系统`](../../design/生产系统.md)那一节。

## 为什么它没等 `ENG-21`

`ENG-21` 管的是「把**已经存在**的场景改成编辑器里可编辑的节点树」—— 它的对象是那几个在 `_Ready()`
里 `AddChild` 出来的场景。**这一片地是新搭的**，一开始就是「作者搭树、脚本读 `[Export]`」那个形状，
所以它不在 `ENG-21` 的范围里。

**由此顺带改了一件事的顺序**：训练房换血（`GP-14`）原先排在全部里程碑之前，理由是「这套分工的第一次
实跑放在最小的场景上」。那个理由已经用掉了 —— 经营这一片地就是第一次实跑，而且它同时产出了能玩的
东西。所以 `GP-14` 回到战斗侧的第一件，路线在
[`reference/godot/从哪里开始.md`](../../reference/godot/从哪里开始.md)。

## 换掉的那条验收口径

**原验收里有「对着可耕地按播种被拒，且看得出为什么」，它实机试不到了。**

落地时用的是**一个键按当前格状态派发**：六个状态各自恰好对应一个玩家动作（未清理→清理、可耕→锄、
已锄→播种、已播种→浇水、待收→收获、待清→清枯株），所以「按下去做什么」由那一格自己的状态答得出来。
这不是一个简化，它是那台状态机形状的直接读法。

**代价**：玩家没有办法主动选一个不该用的动作，所以那条拒绝路径在实机上触发不到。它仍由规则层
单元测试守着（代码仓 `tests/Economy/PlotTests.cs`），**实机那一条等「怎么选一个逐格动作」有了载体
再试**。

**那个载体在全库还没有编号持有 —— 这是一处已知的设计空白，不是这里漏做的一件事。** 最近的两个是
`GP-23`（背包与仓库，堆与随身物那一层）与 `UI-27`（当前操作格，它只答「作用在哪一格」、不答
「作用是什么」）。**播哪一种作物现在是检查器里填一个标识**，同属这处空白的下游。

## 四个还没有值的量

它们都是 `[Export]` 且**刻意没有默认值**，填 0 当场报错（[ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md)）。
量纲与约束形式登记在[数值模型](../../design/数值模型.md)的尚未给值表，值归 `GP-7`。

| 量 | 约束 | 怎么定 |
| --- | --- | --- |
| 荒置退化天数 | 至少 1 | 太短会罚出征的玩家，太长则荒置这条规则形同虚设 |
| 浇满时一次收几件 | 至少 1 | 与产量系数一起看 |
| 一次没浇时的产量系数 | **必须大于零** | 它就是「一次没浇也不颗粒无收」那条下限 |
| 俯视走动速度 | 大于零 | 实机拖着调 |

**可及范围的大小也是同一类**，但它归 `UI-27`（形状已定：十字、不含斜角）。

## 验收标准

**机器判得出的：**

- [x] 状态机每条流转各一条用例；「可耕格不能播种」与「未清理格既不能种也不能盖」各一条拒绝路径
- [x] 作物定义缺任一字段、任一阶段小于 1 天、季节列表为空，都在载入时被拒且说清缺哪一项
- [x] 阶段数由作物自己声明：一项都没有的被拒；一项、两项、多项都载入成功
- [x] 收获后退回成熟那一阶段的作物定义被拒
- [x] 收成件数是整数且至少 1 件（把浇水天数设成 0 也要收得到东西）
- [x] 循环收获退回声明的那一阶段，且浇水累计清零
- [x] 荒置计时只对空格走
- [x] 代码仓 `python tools/verify.py` 五步全绿
- [ ] 缺任一张作物素材时报错说清缺哪张 —— **代码已写，等作者实机撞一次确认文案说得清**

**必须实机确认的**（按 ADR-0009 由作者看，门禁判不了）：

- [ ] 四个动作（锄、播、浇、收）各做一次，每一次都看得见结果
- [ ] 一格锄过没锄过，站在田边扫一眼分得出来
- [ ] **一屏之内分得出哪几格浇过水**
- [ ] 成熟那一阶段与它前一阶段在实际尺寸下分得开，**关掉颜色也成立**
- [ ] 走到作物后面被它挡住、走到前面压在它上面（Y 排序那一条）
- [ ] 框跟着指针跳格，够不到的格框成不可用的样子
- [ ] 上面那四个量各调出第一版，调完登进[数值模型](../../design/数值模型.md)

## 口径提醒

两处容易记错的：**「清理」有两处**（未清理格那次产初级材料、算开荒渠道的产出；待清格那次清掉枯株
不产材料也不耗精力）；**收成的件数到「几件」为止**，归属、付酬与入库一律走[`生产系统`](../../design/生产系统.md)
那条唯一的管道 —— 不许在地块这一侧另开一个入库入口。
