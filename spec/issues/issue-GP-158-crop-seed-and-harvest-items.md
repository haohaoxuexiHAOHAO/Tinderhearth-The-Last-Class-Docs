# GP-158：每种作物一份种子、一份收获物

## 目标

素材表上每一行作物都有对应的种子与收获物定义，作物定义写明用哪一样种子，指不到在册物品就载入被拒。

## 来源

- PRD：[`spec/prd-items-in-bag.md`](../prd-items-in-bag.md) 的 `US-002`。

## 依赖

- `GP-157`：物品定义的读法与载入校验要先有。

## 验收标准

- [x] 可核对：代码仓 `data/crops/` 下每一种作物，各有一份种子与一份收获物的物品定义；种子声明无品质，收获物声明有品质。
- [x] 可测试：作物定义多一格「用什么种子」，与「产出什么物品」同一形状；两格都必须指到在册的物品定义，指不到载入被拒并点名作物与那一格。
- [x] 可核对：每个新物品的名称与描述在文本表里；缺了照作物那样启动时报出来。
- [x] 可核对：[地块系统 · 作物定义：一张表，缺字段报错](../../design/地块系统.md)那张表加上种子那一行。
- [x] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。

## 实现笔记

### 设计决策

- **读作物时一定先有物品。** 代码仓 `rules/Economy/CropDefinition.cs` 的 `LoadAll` 多收一份物品表，所以读作物不可能跳过「种子与产出指不指得到」这一次核对；主场景与农场都先读物品、再读作物。指不到的一次全报，一行一处，点名是哪种作物的哪一格。
- **品质那一位也在载入时核。** 种子那一格指到声明了有品质的、产出那一格指到声明了无品质的，同样被拒：种子没有做得好坏之分，而产出那一样要装得下变了的那一株收上来的变异品质。这两条写进了[地块系统 · 作物定义：一张表，缺字段报错](../../design/地块系统.md)那张表。
- **作物没有自己的名字与描述，读它的收获物。** 物品有了名称那一格之后，作物再留一条「作物N」就是同一个名字的两个家（[数值模型](../../design/数值模型.md)「不占命名权」那一条说正式名字归物品定义）。所以文本表里那批作物条目换成了种子与收获物的条目，醒来那份完整明细里的作物名改读收获物；规则写进了地块系统那一节。
- **占位内容照参数表与正典填**：种子归种子那一类、收获物归药材（理由在代码仓 `data/item_categories/herb.json`），都是低级稀有度；堆上限照设计仓 `design/numeric-model-params.json` 的 `capacity.stack_limit_default`；价还没给值写空值；可丢可卖、用掉前不确认。正式的作物清单跟 `GP-88`。

### 偏离

- **方案怎么说**：作物定义多一格种子，两格都要指到在册物品。
- **实际怎么做**：另外核了品质那一位，并把作物的名字改成读收获物。
- **为什么**：前一条不核的话，填反的那一份在收获与播种时才出错；后一条不改的话，同一个名字从这一份起就有两个家。两条都写在设计决策里。

### 权衡

- **作物名改读收获物，醒来那份完整明细要多拿一份物品表。** 代价是那一处的调用多一个参数；换来的是名字只写一处。地里那一株与收上来的东西叫不一样的名字（稻与米那一类）时，要的是给作物加回一格名字，那时再加，现在没有这样的内容。
