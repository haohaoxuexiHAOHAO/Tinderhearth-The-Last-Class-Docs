# UI-67：背包页画成网格

## 目标

背包页是一张格子挨着格子的网格，大东西画在它占的那一块上；随身栏那一排画在网格上面，拿起一堆之后看得出放不放得下。

## 来源

- PRD：[`spec/prd-grid-bag.md`](../prd-grid-bag.md) 的 `US-006`，方向键那一条之外。方向键那一条在 `UI-68`。

## 依赖

- `GP-170`、`GP-171`：这一页的点击与按钮都调到它们管着的那几条规则。

## 验收标准

- [x] 可观察：每格 16 像素的图外面套 22 像素的格子框，格子框挨着、不留缝；大东西占的那几格并成一个大框，图不缩放、放在正中；件数、品质点与稀有度框画在那一块上。位置与大小由验证结果里那次一次性场景量过，看得清不清归下面那一格实机。
- [x] 可观察：随身栏那一排画在网格上面，每格标着它在随身栏里是第几格。随身栏几格不够一行也占一整行，网格从下一行开始；格号画在每一块上面，那一格有东西时也看得见。格号画出来的样子归实机。
- [x] 可观察：拿起一堆之后，指着的地方画出它要占的那一块，放得下与放不下画得不一样（形状不同，不只换颜色）：放得下是当前操作格够得到的那一张（四个角），放不下是够不到的那一张（四个叉角），按那一块的大小拉开；出了网格的那一截不画。
- [x] 可观察：焦点框画在那一块的里面一圈，拿起来的那一块底色亮一档，都不压到旁边那一格（偏离见下）。
- [x] 可测试：配置里每一级的背包，整页都放得进游戏菜单的内容区，高算上随身栏那一行与右边那一列按钮。用例在代码仓 `tests/UI/BagPageLayoutTests.cs`；宽在用例里只判厚框，连右边那一列的整页宽由验证结果里那次一次性场景量，筛选按钮换成很长的类别名时没量。
- [ ] **作者实机确认**：格子框与大东西的大框看得清；大东西的图看得清细节；一格里的件数与品质点不把图盖掉太多；拿起、放下顺手；两种被拒的说法看得懂。串在 `GP-173` 的清单里。
- [x] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。

## 实现笔记

### 设计决策

- **一格一个按钮管点与焦点，每一堆一块叠在上面**：块、随身栏的格号与预览各是一层，都不接鼠标，点到哪一格都落在下面那个按钮上；被块盖着的格，自己的格子框收起来、由那一块画。代码在代码仓 `src/UI/BagPageView.cs`。
- **点到一块里的哪一格都拿得起那一堆**，拿起时点的那一格对准指着的那一格放下（`rules/Economy/BagPage.cs` 的 `AnchorIndexOf`）。原先只有左上角那一格拿得起。
- **大框是格子框按九宫格拉开的**：`kit/slot_normal`、焦点那一圈 `kit/slot_focus`、稀有度那一圈 `kit/rarity_edge`、当前操作格那两张都声明了九宫格边距（四边各 4，代码仓 `tools/ui_art.py` 的 `SLOT_NINE`），边距进素材资源，作者能在检查器里改；一格大的用处照旧原尺寸贴。
- **页上的行列由规则层算**：随身栏几格不够一行也占一整行，网格从下一行开始（`rules/UI/BagPageLayout.cs` 的 `CarryRows`、`BagPage.PositionOf`）；一块多大、图放在哪、预览离块边多远都在那一份里，有测试管着。
- **放不放得下问 `Bag.PreviewMove`**：在一份副本上挪一次，与按下去时是同一套判法，算预览不改背包（`tests/Economy/BagPageBlocksTests.cs`）。

### 偏离

- **拿起来的那一堆不套选中框，换一张底色亮一档的格子框**（`kit/slot_held`，由格子框换色派生）。理由：格子框挨着格子框，选中框画在外面会压到旁边那一格；格子框里面那一圈已经由焦点框与稀有度框占满，再套一圈就盖住其中一样。`界面系统`与需求里那两句跟着改了。这是先定的样子，作者实机看了不合适再改。
- 方向键在大小不一的块之间怎么走归 `UI-68`。

### 待确认

无。
