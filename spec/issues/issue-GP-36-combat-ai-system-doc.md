# GP-36：`design/战斗AI系统.md`

## 目标

让「一个不由玩家操作的角色这一帧决定做什么」只写在一处：一套决策循环两个阵营共用，敌人挂警戒状态机与传播，队友挂两个档号与指令。

## 来源

- PRD：[`spec/prd-enemy-ai-and-ally-tiers.md`](../prd-enemy-ai-and-ally-tiers.md) 的 `US-004`
- 起因：[战斗与关卡 · 队友与敌人](../../canon/gameplay/战斗与关卡.md)点了敌人侧四样（分级面板、施法与打断、警戒传播、脱战）却没写它们的形状；[`关卡系统` · 关卡系统只持有配额，不持有敌人](../../design/关卡系统.md)已经把敌人预算交出去了，接口缺口就在这里。
- **本条复用已有编号**（本行那一格原来装的正是「两条轴怎么合成、每档解锁哪几条行为」这两个缺口），按「同一件事不新开登记行」不另起号。

## 依赖

`GP-49`（敌人预算以一屏为单位）、`GP-51`（决策循环的第一步是取可见集与记忆集）。**与 `GP-50`、`GP-51` 互相引用**，三条一起写完一起验。

## 验收标准

- [x] 按 [SYSTEM 模板](../../templates/SYSTEM.md)八节写全，`type: system`、文件名以「系统」结尾、`upstream` 指[战斗与关卡](../../canon/gameplay/战斗与关卡.md)，**并在 `GP-50` 那一轮就被正典链接到**。
- [x] **拆不拆的判断写进本条的「权衡」**，逐样按「有没有自己的状态机」判并附一条篇幅复核，写明结论与它将来被重判的条件。
- [x] 写明**一套决策循环两个阵营共用**，敌我的差别只在挂上去的门与可用动作；理由写清（两边共用同一份角色面板、同一套技能与道具管道、同一份可见性输入，拆开会让「这个动作现在可不可用」有两个家）。
- [x] **决策循环写成一条顺序固定的链**（至少覆盖「取可见集与记忆集 → 选目标 → 选动作 → 交给动作机」），并写明**本页不出姿态** —— 姿态与流转在[`角色动作状态系统`](../../design/角色动作状态系统.md)，本页只产出「想做什么」。
- [x] 写明**动作能不能真的发出由动作机说了算**，AI 被拒时不许绕过去（受击、失衡、冷却未到都走同一条拒绝路径）。
- [x] 写明 **AI 只从这个角色声明的动作集里选** —— 那是正常筛选、不是错误；没有跳跃的怪物不会尝试跳，也不需要为它写特例。
- [x] 写明**一条行为引用了角色没声明的动作时载入报错**，并说清是哪条行为要哪个动作。**这条与上一条分开写** —— 混在一起会让配错静默变成「它就是不做那件事」。
- [x] 写明**「对策」说的是玩家有办法应对，与敌人自己的动作集是两件事** —— 主角有全套动作，所以那条对策覆盖校验不受动作集影响。**这一句要显式写**，否则两处都带「跳」字会被读成同一件事。
- [x] **敌人的警戒状态机写成一张流转表**，至少覆盖未察觉、警戒、追击、脱战返回、归位恢复，每条流转写出进出条件；并写明**它与[`角色动作状态系统`](../../design/角色动作状态系统.md)那两层是正交的**（一个管「打谁」，一个管「现在能不能动」）。
- [x] **脱战的两个条件各写出量纲**（追击距离与追击时长），写明脱战后**回原位并恢复状态**指恢复哪些量，且**不为片段边界写特例**。
- [x] 写明**那两个条件在一屏一房间的模型下还剩多少用处**：片段边界替它兑现了大半，所以距离条件收窄成「不离开自己的守卫点太远」（让远程守在原地而不是全屋追人），时长条件挡的是「打掉一半退回去、等它站着不动再进来」。**这一句要写出来**，免得给值那一轮照大地图的尺度给。
- [x] **警戒传播写明传给谁、传几跳**：按范围传、**只有一跳**；理由写清（链式在一个片段内等于全图警戒，「先处理掉哨兵」这个决策就消失了，同屏上限也会被撞破），并写明不做传播会让「从背后摸过去」只剩省几秒路程。
- [x] 写明**传播的对象是警戒状态本身**（附最后已知位置），不是「直接知道玩家在哪」—— 被叫来的同伴要自己走到那个位置再重新感知。
- [x] **预警动作写成攻击定义上的显式声明**（有没有预警、预警窗口多长），**不从动画前摇推**；理由指回 [ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md)（美术改一帧不该改掉玩法），并写明分工：字段与判定我写、动画与窗口值作者填。
- [x] **攻击定义要声明它的对策**（跳、纵深挪步、闪避、防御），缺声明**载入报错**；并写一条载入校验 —— **全部敌人定义合起来必须覆盖到每一种对策**，少一种就报错并说清少哪种。这条兑现正典挂着的那笔账。
- [x] **「打断敌方施法」写明它读的是既有那条读条规则**（[战斗与关卡 · 读条与打断](../../canon/gameplay/战斗与关卡.md)），打断要有可见反馈（**反馈长什么样归表现、作者实机看**）；同一处写明敌人被打断**不退还 MP**（[`角色动作状态系统`](../../design/角色动作状态系统.md)已定，本页不改）。
- [x] **分级面板写成同一套面板的两个子集**：杂兵取等级、四属性与技能，精英与 BOSS 另取特质、天赋与实战值；**缺的栏读作空或零，不是另一份数据形状**。
- [x] 写明**敌人的实战值在定义上给定、不在关卡内累积**，唯一读者是技能孔解锁（[`技能系统`](../../design/技能系统.md)）；理由写清（敌人不跨关存在，累积那一份没有读者），并写明这**不是**专用通道 —— 字段与读口都是同一套。
- [x] **精英与 BOSS 装宝物、走同一条自动配装与同一条偏好轴；杂兵不装**（简化面板里没有宝物栏这一栏）；**穿着的那件不保证掉落**（掉落表是定义上另一件事）。同一处写明理由 —— [角色与成长 · 四项属性的作用方向](../../canon/gameplay/角色与成长.md)写明防御与抗性的大头不在属性上，所以不装宝物的精英只剩基底防御，除非给敌人加一个「直接写死防御」的字段，而那就是专用通道。
- [x] 写明**偏好轴对精英与 BOSS 必填、缺了载入报错**，判据用[`装备系统` · 谁来配：玩家配主角，学生自动配而玩家可覆盖](../../design/装备系统.md)那条既有的（只对不由玩家操作的角色成立），**不把它改成三态**。
- [x] 写明**敌人不用消耗道具**，恢复手段一律走技能；理由写清（这样「打断」照样有对象 —— 治疗技能要读条，而不用给敌人开背包与一条「打死它掉不掉那瓶药」的路）。
- [x] **三种敌人的差别写成决策配置的取值，不是三套代码分支**；理由指回[玩法定位 · mod 的扩展边界](../../canon/gameplay/玩法定位.md)（内容外置、规则不外置）。
- [x] **队友那一侧的分档表写全五档、两条轴各一列**，最低档按「都还不会」写、最高档写出来；表里**不许出现任何一条地板行为**（清单在正典那一节，本页写链接不复述）。
- [x] **两条轴各有一条「这一档在读谁」的判据**，写在表的前面 —— 操作档读的对象逐档往外推（自己的处境 → 对手的预警 → 对手正在读的那一条 → 一整套招与冷却），配合档读的方数逐档变多（自己 → 一个同伴 → 主角的当前动作 → 别人的出招时点 → 整场的分配）。
- [x] **操作档五档**：生手＝都还不会；熟练＝挑时机（先退出攻击范围再读条）加**简单衔接**；老练＝会闪避有预警的攻击；精通＝会打断敌方施法加优先处理远程敌人；大师＝掐得准防御时机加**复杂衔接**。
- [x] **简单衔接与复杂衔接各写出可判定的形式**。简单衔接＝相邻两招不互相废掉（不在自己读条期间插另一招、不在把目标打退之后接近身技、不空按冷却未到的招），判据只看上一招的收招与射程。复杂衔接＝三招以上串成一套、顺序由目标当前状态与自己全部技能的冷却决定，判据是「同一组技能在两种目标状态下排出两种顺序」。
- [x] 写明**技能衔接为什么跨两档出现** —— 它是这条阶梯上唯一能连续加深的东西（别的行为都是「会不会」），而正典要求每一档都多一件看得出来的事。
- [x] 写明**技能衔接不是普攻连段**（[战斗与关卡 · 按键与连击](../../canon/gameplay/战斗与关卡.md)那条固定连段是另一件事），同名不同物两处都写全名。
- [x] **配合档五档**：生手＝都还不会（各打各的）；熟练＝自发集火（不用玩家下令也跟队友打同一个目标）；老练＝主角放屏障或控场时主动进入范围；精通＝会接主角与同伴起手的连击；大师＝会分战场（补到主角覆盖不到的那一排或那一侧、主角被围时主动解围、有人在扶倒地同伴时主动上前顶住）。
- [x] 写明**「接连击」从正典的「接主角起手」扩到「接主角与同伴起手」**，理由指回正典自己那句「跟主角与同伴怎么配合」。
- [x] 写明**站位被判据切成两半**：不挤在同一处是地板，主动补到主角覆盖不到的那一侧是分档。
- [x] 写明**不设「不离主角太远」的跟随半径** —— 一个战斗片段就是一屏，队友走不远，加一条半径等于给一个不存在的问题写规则。
- [x] 写明**地板行为与分档行为走同一条动作管道**，差别只在触发条件里多不多一个时机判断；理由写清（两条管道会让低档队友在实现上真的变成另一种角色）。
- [x] **三条指令写成一个互斥的指令档**，写明**默认档是「自由作战」而它不是一条指令** —— 没有指令时的样子，所以正典那三条不变。
- [x] 写明**指令与分档正交**：指令改「打哪个、要不要打」，分档改「掐得准不准、接不接得上」；**收不收得到指令与响应多快都是地板**，不随档位变（理由在正典那一侧，本页不复述）。
- [x] 写明**「撤退」指令与玩家撤离关卡是两件事**（同名不同物，两处都写全名）。
- [x] **队友自动与场景物件互动**那条写明它读可见集（看不见的资源点不会被自动采），且玩家标记的优先目标**优先于 AI 自己挑的**；形状指回[`关卡系统`](../../design/关卡系统.md)与[`装备系统` · 谁来配：玩家配主角，学生自动配而玩家可覆盖](../../design/装备系统.md)那条「玩家手动的优先」，**不新造规则**。
- [x] 写明**精准防御的回报不按档位分配** —— 档位只决定掐不掐得准，吃到多少是同一份；本页不复述那份回报是什么（家在正典那一节）。
- [x] **难度那一层落成两个量**：反应速度（从进入可见集到出手的延迟）与攻击欲望（「进攻还是后退」这个选择的权重），两个都写出量纲；写明**它们作用在决策循环上、不作用在分档上**，也**不碰资源产出**。
- [x] 写明**敌人预算从[`关卡系统`](../../design/关卡系统.md)接住**：那一侧给数量、能不能有精英与 BOSS、放置位；本页给种类与行为，**不反过来改配额**。并写明**预算以一屏为单位**（`GP-49`）。
- [x] 写明**死亡终态留下什么由载体类别决定**（尸体／残骸／什么都不留），并写明纯灵之物不留尸体因此搜刮对它不成立；[`角色动作状态系统`](../../design/角色动作状态系统.md)那一侧的收窄归 `DOC-36`。

### 权衡

**拆成几份文档的判断过程。** 判据取[`生产系统` · 什么时候拆出去单独成篇](../../design/生产系统.md)那一条：**它有没有自己的状态机** —— 有的拆出去（它会带来一整套流转、时点与边界条件），没有的留着当一节。三样各判一遍：

| 候选 | 有没有自己的状态机 | 判据给的结论 |
| --- | --- | --- |
| 敌人的警戒 → 追击 → 脱战 → 归位 | **有。** 五个互斥状态，每条流转各有进出条件，其中两条还带时长 | 拆出去 |
| 队友的行为分档 | **没有。** 它是两个按阈值查出来的档号，门在决策循环里，没有流转 | 留着当一节 |
| 感知与视野 | **没有。** 可见集每帧重算；记忆项有一个时长，但那是一条 TTL，与状态效果的时长同形，不是流转 | 留着当一节 |

**按判据直读只有敌人那条状态机是拆分候选，而队友分档与感知都不是。** 但「留着当一节」要有一个宿主页，而队友分档的宿主不可能是一份叫「敌人 AI」的文档 —— 所以先得有一份两个阵营共用的页，敌人那条状态机才谈得上从它里面拆出去。

**于是真正要判的是「敌人那条状态机值不值得从共用页里拆走」。** 按 `GP-29` 那次的办法加一条**篇幅复核**：警戒状态机加脱战加传播三节，对比决策循环、动作集、分级面板、两个档号与两张五档表、指令、难度、预算这一串 —— **敌人那一侧没有超过其余部分之和**，所以不拆。与 `GP-29` 的地块那次是同一个结论形状。

**感知那一份最后还是单独成篇了，理由不是状态机。** 它是**多读者无主**：本页、队友的「优先处理远程」、[`关卡系统`](../../design/关卡系统.md)的资源点显形、玩家的视野表现四处都读它。塞进任何一份都等于让另外三个读者去读一份讲别的事情的文档，而正典那条防重构点正是「只有一份可见性数据」。**这是对那条判据的一次补充，不是例外** —— 判据问的是「它会不会撑大宿主页」，而这里问的是「它有没有宿主页」。

**将来被重判的条件**：① 敌人的警戒长出巢穴、增援波次或 BOSS 阶段这类带自己时点的东西，那时警戒那几节会超过其余部分之和，按同一条判据拆出去、本页只留接口；② 队友分档长出「档位之间可以掉回去」这类流转（现在它只升不降地读两个派生量），那时它自己就成了状态机。
