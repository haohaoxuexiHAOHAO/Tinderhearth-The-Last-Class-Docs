## 实现笔记

### 设计决策

- **正典最后删**：它链着几乎所有系统文档，先删它，指向它的链接一次断完、一次改完；先删系统文档的话，要先改一遍马上也要删的正典。
- **链接一次改完**：删之前用 `tools/rewire_links.py` 照一份计划把还活着的文档里指向它们的链接改指 desc 或留下的文档，找不到去处的变成纯文字；节名在新目标里找不到就只留文档名，所以改完的链接都过得了节名引用那条守卫。
- **结算步名那条守卫改读 desc**：步序的家搬到 `desc/经营规则.md` 的「结算顺序」那张表，检查器只把它当数据读，判的是代码仓那张步名表跟没跟上。

### 偏离

- 提案留下两份：「季节换色重着色贴图」是 `ART-22` 的做法（那条还没开始），「键鼠技能位挪到右手」还被 `UI-14`、`UI-62` 与代码仓引着；结论迁出之后再删。
- 被删文件的路径在台账里还以纯文字出现。
- 第四批删了已关闭编号的条目文件，台账里指向它们的那几行去掉了「理由在条目文件」；进行中的需求一份都没做完，所以 `spec/` 下的 PRD 一份没删。
- `archive/` 也删了：留着的话检查器照样要扫、搜索照样会搜到，与 ADR-0036 不把删掉的东西挪进去是同一个理由。指着它的链接先照计划改掉；以前的「已归档编号」（已退役）与已完成的行并成「已关闭编号」一张表，一个编号一句话。
- 设计文档被删、还没开工的那些行，状态词从「设计已交付」改成「未开始」：交付的那份文档已经不在了，开工时先从 desc 写一份短的系统文档。
- 「归档」（已退役）登进了退役术语：现在只有「关闭」（台账编号）与「删掉」（文档）两种说法。
