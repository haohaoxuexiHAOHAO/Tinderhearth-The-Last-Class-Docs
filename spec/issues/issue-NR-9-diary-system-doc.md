# NR-9：`design/日记系统.md`

## 目标

让「一本日记里有哪些条目、各怎么生成、各存多少、谁翻得开」只写在一处，从而让「读日记发现需求 → 解锁小事件」这条链有一个可实现的形状。

## 来源

- PRD：[`prd-bubble-dialogue-and-diary.md`](../prd-bubble-dialogue-and-diary.md) 的 `US-002`
- 起因：[角色与成长 · 日记](../../canon/gameplay/角色与成长.md)写明日记有机制作用且非解锁不可翻，而[`人际系统`](../../design/人际系统.md)与[`事件系统`](../../design/事件系统.md)两处都明写不做它 —— **它是多读者无主**：事件要往它写回看、小事件要读它解锁出来的需求、界面要翻它、存档要存它。
- **本条的编号是上一批留下的记账行**，那一行当时只定了它作为事件回看渠道的那一个接口。

## 依赖

无阻塞依赖。**与 `NR-8`、`NR-10`、`DOC-44` 互相引用**，四条一起写完一起验。

## 验收标准

- [x] 按 [SYSTEM 模板](../../templates/SYSTEM.md)八节写全，`type: system`、文件名以「系统」结尾、`upstream` 指[角色与成长](../../canon/gameplay/角色与成长.md)，**并在 `NR-10` 那一轮就被正典链接到**。
- [x] **按角色各一本、主角也有一本**；写明它**不是一本全局流水**，理由是同一件事在不同人笔下不一样，而那份不同只有并排放在各自名下才读得出来。
- [x] **谁有日记由角色定义上的一个声明项决定**，起步铺主角与学生、常驻 NPC 的格子留着；写明理由（写成「全体都有」会让缺内容时无声地显示一本空册，写成声明项则「他还没有日记」是数据里看得见的事实），并写明这一格要收进 `DOC-35` 那张角色定义字段表。
- [x] **条目的类别写成一张开口的表**，起步两类：**纪事**（发生了什么，模板打底＋参数快照，自动写入）与**心声**（他怎么看，预写文本，由关键事件与关系档位触发）。写明**加一类是填这张表**，以及类别只决定「怎么生成、谁翻得开」，不决定它存在哪。
- [x] **条目不按天生成，按「发生了值得一记的事」生成**；写明为什么不做每天一条的摘要（一半条目会是「今天没什么事」，而日记的作用恰恰是让角色显得活着），并写明由此条数是派生量。
- [x] **纪事类条目 ＝ 模板文本键 ＋ 一组参数快照 ＋ 日期 ＋ 类别**，**不存渲染好的句子**；理由写准 —— 省的不是体积（一句渲染好的中文与一个键加几个参数差不多大），而是**正确性**：存渲染结果会让改模板或改语言之后旧条目还是旧样子，而它不报错。
- [x] 同一处写明参数是**当时的快照**而不是读取时现查；**这是「重建出来的和当时看到的一样」这条承诺的全部依据**（现查会让「那天他还只是熟悉」在今天变成信赖），**要有反证钉住**。
- [x] **一件事可以往多本日记各写一条**，各取那个角色自己的文本变体；**变体缺失时按条目声明的通用变体取，通用变体也缺失时报错** —— 写明这是**声明式回落**，与「缺键退化成显示键名」那种静默降级不是一回事。
- [x] **心声类条目自带声明**（哪个角色、由什么触发），**不做「角色 × 事件」或「角色 × 关系档」那种二维索引表**；理由写明：交叉表要求每个格都有内容，而内容是分批铺的。
- [x] **需求那条链写成「日记条目上的一个标记」**：一条条目可以声明它揭示哪个需求标识，读到那一条时那个需求进「已发现」集合；**小事件的前置条件读的是需求标识**。同一处写明为什么不用「读过某人的日记」当条件（翻开一次就解锁全部，于是「发现需求」退化成「点开过那一页」）。
- [x] **「非解锁不可翻」按本判，不按类别判**：**主角自己那本一律可翻**，**别人那本读关系档位**；理由指回制度来源（[世界观 · 多功能手环与治理](../../canon/world/世界观.md)的最小必要原则与[人物 · 教师权力、同意与关系红线](../../canon/characters/人物.md)），**最小必要原则保护的是第三方的私人信息**。
- [x] 同一处写明**记与读是两件事**：主角不在场的、别人之间的事照样记进当事人那本，写入不看解锁。**这条让「都记下来」与最小必要原则同时成立**，要有反证钉住。
- [x] 同一处写明**事件回看因此永远查得到**：凡是走过手环通知的事，主角那本里都有一条纪事 —— 这是[`事件系统` · 呈现与回看走已有渠道](../../design/事件系统.md)那个接口在新形状下的落点。
- [x] 写明**不读「某条小事件演过没有」当解锁条件**：小事件本来就读关系档位，用它当门是把同一个条件绕一层，还会让解锁链成环。
- [x] **存法按「参数化的存参数、静态的只存标识」写死**：纪事类条目进正式存档，心声类只存「哪些条目已被写出来」的标识集合（正文从内容数据重建，重建结果与当时一致，因为正文是静态的），**已发现的需求集合进正式存档**，**解锁状态不单独存**（它读关系档位，是派生量 —— 贯彻上一批留下的那条原则）。
- [x] 写明**不设条目保留上限**，代价写准：正典写明**无全局日期上限**，所以条目总量没有上界，存档体积随游玩时长线性长。同一处写明**为什么仍然不设**（设了就查不到老事件，而回看正是为了让玩家不把事件当 bug），以及**要不要设、设多少是一个等实测的量**（`GP-7`，判据是实测存档体积而不是估算）。
- [x] **日记打开时暂停世界**（它接管输入），判据指回[玩法定位 · 弹界面接管输入就暂停世界，世界里的动作不暂停](../../canon/gameplay/玩法定位.md)；同一处写明**它与气泡是同一条判据的两侧**。**关卡内只许查看**。
- [x] **文本一律按键取，写链接不复述管线**（[`剧情演出系统` · 文本一律按键取，日记与事件回看共用同一条](../../design/剧情演出系统.md)）。
- [x] 挂载点列全并写明「到此为止」，至少覆盖事件回看的写入口、日常动作（派工、出征、上课这一类）的写入口、关系档位读口、需求集合的读口、文本管线、手环、统计事件总线、存档。
- [x] 边界那一节写明**不持有**：日记文本内容、小事件的触发与后果、需求满足之后怎么样、翻页排版与搜索筛选、任何数值。
- [x] 「同名不同物」那一格写明：**「日志」是「日记」的口语说法**，本项目里「日志」另有所指（工具自己写的那种），活文档一律写日记；**「行为日志」原是日记两半之一的旧名字，现在是条目的一个类别（纪事）**；**「需求」有两个意思**（本页这个被日记揭示的需求标识，与[玩法定位 · 系统清单](../../canon/gameplay/玩法定位.md)里「饥饿与自主进食」那条需求驱动 AI）。
- [x] 文档里一个玩法数值都没有。
- [x] `python tools/check_docs.py` 0 项必须修复（合并之后才成立）。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。四类都要过一遍，某类没有就写「无」并简要说明。

### 设计决策

- **模糊点**：正典原来写「玩家视角的行为日志 ＋ 角色视角的私人日记**两者都做**」，读起来像两本册子，但没说它们是两份存储还是一本里的两类。
- **选择**：一本，条目按类别分；正典那一句同批改写（`NR-10`）。
- **理由**：那两个「视角」的差别是**条目怎么生成**的差别，不是**存在哪**的差别。做成两本的代价很具体：同一次远征要在两处各写一条，而「每个人的看法不同」这份价值只有把它们放在同一个人名下才读得出来。

### 偏离

- **方案怎么说**：PRD 的 `US-002` 说类别决定「怎么生成、谁翻得开」两件事。
- **实际怎么做**：类别只决定**怎么生成**；解锁改成**按本判**（主角那本无门、别人那本读关系档位），与类别无关。文档里同一处写明了这一点。
- **为什么**：按类别判解锁会让同一本里有的能读有的不能，读起来像坏了；而「他愿不愿意让你看」本来就是对整本的判断，与「这条是记事还是心声」无关。写明是为了挡下一次有人照 PRD 那句去加一条按类别的门。

### 权衡

**气泡与日记能不能互为宿主 —— 判断过程记在这里。**

拆篇判据是[`生产系统` · 什么时候拆出去单独成篇](../../design/生产系统.md)那条（**有没有自己的状态机**）。两样都没有：气泡是每次询问重新选一条，日记是只追加的条目集合，都没有流转表。**所以按判据直读，两样都不该单独成篇。**

第 6 批给那条判据补过一句：**多读者无主时，问的不是「它会不会撑大宿主页」，而是「它有没有宿主页」。** 上一批已经排掉了演出与事件两个候选，所以剩下要判的就是这两样能不能互为宿主。

**答案是不能。** 它们看着同类（都是按键取文的叙事文本载体，都读关系档位，都要求语料外置，都受台词红线管），但每一条要紧的性质都相反：

| | 气泡 | 日记 |
| --- | --- | --- |
| 谁发起 | 系统自发推送 | 玩家请求翻阅 |
| 有没有门 | 没有，在场就可能听到 | 有，非解锁不可翻 |
| 记账语义 | 说过了进冷却池、**还会回来** | 写过就**一直读得到** |
| 出入口 | 只有读出口 | 有运行时写入口 |
| 机制作用 | **刻意没有**（不承载必要信息） | 有（解锁小事件），而那是它存在的理由 |

**合成一份的后果是这些相反性质全变成表上的分支**，而分支一多，「气泡不承载必要信息」与「日记非解锁不可翻」这两条就会各被读成另一条的例外 —— 那正是两条最不能松的约束。

**被重判的条件**：其中一样的读者收敛到只剩另一样。现在不成立 —— 日记的读者里有事件、小事件、界面与存档，一个都不是气泡。

### 待确认

**存档体积那笔账是推断，不是实测。** 条目数 ＝ 有日记的角色数 × 平均每天条数 × 天数，而正典写明无全局日期上限；实测办法已写进文档与尚未给值表（实现之后写满一段时间的条目、量存档文件）。**这一条在实测之前不许被当成结论** —— 尤其不许据它现在就去设一个保留上限。
