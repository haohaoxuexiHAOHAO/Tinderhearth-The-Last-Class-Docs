# UI-44：素材资源：界面件一律从作者改得动的那份资源取

## 目标

作者在 Godot 里换一张界面图、重跑就看到它；代码里不再写死任何界面件的路径，缺了哪一项启动时一次说全。

## 来源

- PRD：[`spec/prd-ui-art-baseline.md`](../prd-ui-art-baseline.md) 的 `US-005` 代码那一半，与 `US-007` 里接线、底板与手环那几格（`FR-14`、`FR-15`、`FR-24`）。
- 字段清单就是[界面绘制约定](../../production/界面绘制约定.md)那几张表，本条不复述。

## 依赖

- `ART-27`：界面件已交付，主场景那一批要的图都在；它剩下的主菜单标题、底图与建筑图标不在那一批里，不挡本条。
- 载入时核尺寸用的格子与迷你两档是 `rules/UI/UIMetrics.cs` 的 `Cell` 与 `Mini`（`UI-41` 加的）。
- 图标页签挂在两级页签的顶层那一级上，顶层页签的标识就是那张图标的文件名，家在代码仓 `rules/UI/Wristband.cs`（`UI-53` 落地的）。

## 验收标准

- [x] 可核对：素材资源这个类型能在 Godot 的「新建资源」里找到。它是带 `[GlobalClass]` 的资源类型（代码仓 `src/UI/UIArt.cs`），Godot 文档写明这样的类型列在新建资源里；在编辑器里看那一眼归下面那条实机确认。
- [x] 可核对：资源的字段就是约定那几张表里的件（内容图标除外，它们由内容数据引用），每一格写明它是什么、多大、有哪几种状态。**先接进游戏的只是主场景那一批**（清单在[界面素材那份需求 · US-006（作者）：交模板，生成器切件补件，一次交付](../prd-ui-art-baseline.md)），其余格子载入时照样核尺寸，接线跟各自那一页走 —— 这样整批交付的尺寸一次就核完。「写明」写在每一格的文档注释里：用在哪、多大、九宫格边距、同一件有哪几态、来源。
- [x] 可测试：尺寸能由排版单位推出的那几类（格子、图标几档、迷你、头像框、条高）按排版单位核，九宫格件按「画布大于两倍边距」核；代码里没有散落的数字字面量。测试在代码仓 `tests/UI/UIArtTests.cs`，做法见设计决策。
- [x] 可核对：九宫格边距是资源里的格子，代码那一侧先照约定的数填；字离框多远是内容边距，从排版单位取 —— 两者分开。资源里没有内容边距那一格。
- [x] 可核对：一份空的素材资源载入时，报错列出全部缺项，每一项带名字、尺寸与状态。判在规则层（代码仓 `rules/UI/UIArtCheck.cs`），有测试；引擎那一侧（代码仓 `src/UI/UIArtGuard.cs`）把整份问题拼成一条报错抛出。
- [ ] 可核对：代码那一侧按约定的文件名把交付的图填进一份素材资源，载入不再报缺；作者在检查器里核过一遍。**代码那一半已做**：那一份在代码仓 `assets/self-drawn/ui/ui_art.tres`，主场景启动时核一次，导出的游戏里打出「全部在、尺寸都对」那一行；剩作者在检查器里核。
- [x] 可核对：按钮、面板这类控件的主题由素材资源组装，不在主题编辑器里手敲项名。代码仓 `src/UI/PixelTheme.cs`：带字按钮、两种页签、外框、内容区与浅底上的字各是一种（后几种是类型变体），贴图边距读素材资源那一格，内容边距取排版单位。
- [x] 可核对：HUD、随身栏、手环、读条圆环用到的界面件一律从素材资源取；代码仓里不再有写死的界面件路径（按 `assets/placeholder/ui/` 搜，引擎层与规则层为零）。**技能与物品图标是内容**，由调用方给；演示数据里那几张占位内容图留在演示那一处。**资源条的槽与填充除外，那一组归 `UI-45`**（理由见偏离）；当前操作格那两张由 `UI-46` 接上，同样从素材资源取。搜 `assets/placeholder/ui/` 只剩演示数据里的占位内容图（代码仓 `src/World/HudDemoModel.cs`）；没人用的那几张占位图已删。
- [x] 可核对：HUD 各块的底换成作者画的细框，不再是代码画的纯色框；代码仓 `rules/UI/HudPalette.cs` 里只为那种纯色框存在的面板底与面板边两个占位色随之删掉。那条横排格子坐在画好的那条栏上，其余几块坐在 HUD 的细框上（代码仓 `src/UI/HudPlace.cs`）。
- [x] 可核对：手环换成图标页签，不另放当前页标题；鼠标指着一个页签、或键盘与手柄的焦点停在它上面满一段时间，在它下面弹出写着名字的小窗。外壳用作者画的那张面板，尺寸照[界面绘制约定 · 个人界面那一套](../../production/界面绘制约定.md)那个推荐值、居中。代码仓 `src/UI/WristbandPanel.cs`、`rules/UI/WristbandLayout.cs`，照作者那张模板：页签最下面一行压在外框顶边上，子页签用字、下面一块浅底内容区；名字小窗的底是深色细框。两种页签的焦点那一态用的是作者在模板里画的那一张（子页签照它派生）。
- [x] **作者实机确认**：主场景里两种场合的 HUD 与手环各看一遍，名字小窗的位置与停留时长一起看。
- [ ] **作者实机确认**：换一张图重跑能看到变化；删掉一格重跑，报错说得清缺哪一格。

## 实现笔记

### 设计决策

- **一件一格，格名就是文件名，检查器里按 `assets/self-drawn/ui/` 下的目录分组。** 属性名是目录加文件名转成 PascalCase（`kit/frame_thick_dark` → `KitFrameThickDark`），分组带目录那一截当前缀，检查器里显示时去掉它。被放弃的是一张按文件名查的表：格子少，但检查器里没有逐格的名字，键写错也不报错。
- **九宫格件那一格是一个 `NinePiece`**（代码仓 `src/UI/NinePiece.cs`）：图与四边的边距放在一起，不在资源里另开四格。一件九宫格的边距只对那一张图有意义，分开放就会出现「换了图、忘了改边距」，而那不报错。
- **三份产物由一个入口照生成器清单写出**（代码仓 `tools/ui_art_resource.py`）：规则层那份清单 `rules/UI/UIArtManifest.cs`、资源类型 `src/UI/UIArt.cs`、按文件名填好的那一份资源。手写一百多格，漏一格、拼错一个名字都不报错。资源只在不存在时写；存在时只报它比清单少了、多了哪几格，作者在检查器里换过的格子不覆盖。
- **「按排版单位核」分两段接起来**：载入时每一格按清单核原尺寸（作者换图要保持原尺寸）；清单里能由排版单位推出的那几档，由测试钉在单位上。清单里的尺寸是生成器写出的那张图的尺寸，不是散在判断里的字面量。
- **每一件属于哪一档按名字写在测试里，不按尺寸反推**：按尺寸反推会自证循环 —— 改了单位、清单一重写，那一件就悄悄不属于任何一档了。名字对不上任何一件时那条测试也红，改名不会让它静默空转。
- **九宫格边距不跟清单比，只判它还成不成立**（两头加起来比画布窄）：作者重画边框之后在检查器里改边距，正是这一格存在的理由。
- **主场景在搭界面之前核一次**，所以代码仓 `python tools/verify.py` 的跑产物那一步判得到资源坏了。
- **页签名字的小窗自己做，不用 Godot 自带的提示框。** 自带那个只在鼠标停住时出现（[Godot 文档 · Control](https://docs.godotengine.org/en/stable/classes/class_control.html) 的 `tooltip_text`），键盘与手柄停上去永远不弹，而焦点与悬停要是同一个样子（[界面绘制约定 · 九宫格怎么画](../../production/界面绘制约定.md)）。停多久借引擎提示框那一项（项目设置的 GUI · Timers），不另开一格：它答的就是「停多久弹提示」。面板打开时自己把焦点放到当前页签上，那一下不算停留、不弹。小窗贴着页签下面、左边对齐，隔一个组内间距。
- **页签的焦点那一态不走 Godot 的焦点那一格。** 那一格是叠在当前那一态上面画的（[Godot 文档 · Button](https://docs.godotengine.org/en/stable/classes/class_button.html) 的 `focus`），而作者画的是一整张换了底色的页签，叠上去会盖掉选中那一张。所以它进悬停那一格（悬停是换掉、不叠），键盘与手柄的焦点在进出时照样把「没选中」那一格换成它，焦点那一格留空。
- **焦点停在选中的那个页签上时，照旧显示选中的样子，不另画一态。** 那时整排看不出焦点在哪，但往旁边挪一下，高亮跳到邻居上就知道了；为这一下多画一张不值。手柄适配时也不补。
- **先排尺寸、再接线。** 画好的件比原先的排法大，所以 HUD 各块先由 `UI-42` 排成画好的尺寸（格子 22×22、那条栏高 32、资源条的槽高 10、头像框 20），接线时只剩换来源。
- **HUD 的框读素材资源，不走主题。** 随身栏会被作者摆进别的场景，那里没人装主题；走主题的话那一块会悄悄退回引擎默认的灰框。所以随身栏自己多了一格素材资源（缺了当场报错），HUD 几块的框由同一处按素材资源造。
- **技能图标由调用方给**：HUD 只按技能位问「这一位装的那个技能的图标」，哪一位装着哪个技能、技能图标是什么都是内容，界面层不持有那张表。随身栏的物品图标同一个做法。
- **没解锁的技能位画「还没开」那张格子**（带锁的那张），不画图标、照旧占位。随身栏选中的那一格是选中框叠在格子外面一圈，不再给格子换色；选中框往外让出的那一圈是排版单位里的一个量，有测试拿画好的那张对它，另有一条判它不出那条栏、不压邻格。
- **读条圆环按角度露出交给引擎的进度条**（顺时针填充那一种）：底环与那一圈是作者画的两张，不拉伸、不染色；圆环的尺寸照画好的那张，原先那段代码画的弧与它的几个量删了。
- **按住扳机时那一组格子亮起来，还是给画好的格子换色**，那一张跟手柄适配一起后置（`UI-54`）。倒地队友是盖在头像上的一张记号、头像框不换色（`UI-46`）。

### 偏离

- **资源条的槽与填充不在本条换，跟 `UI-45` 一起换。** 验收那一条原本连它们也要清零。画好的填充要放在槽里 (2,2)、按槽里那一片裁掉出界的像素、中段平铺、右端的头跟着末端走，而追与留一截动的正是这同一根条；拆成两次做，这套画法就要写两遍、中间还有一版只为过渡的接法。占位那两张因此留到 `UI-45`，它的条目里接着判「按 `assets/placeholder/ui/` 搜只剩演示数据」。
- **手环外壳的那几个数进了规则层**（代码仓 `rules/UI/WristbandLayout.cs`）：外壳尺寸由一屏减去约定那两档留白算出来，页签底的边长由小图标加两圈图标内边距算出来，第一个页签离外框左边多远与页签间距照模板量。测试钉住两件事：顶层页签一排放得进外壳，页签底与画好的那张一样大。
- **主菜单的标题与底图不进资源。** 约定的表里有它们，而作者还没画、主菜单那一页也还没有；进了资源就是启动时永远报缺。清单里单列（`UIArtManifest.AuthorOwned`），用到它们的那一页落地时再接。
- **「每一格写明它是什么」写在资源类型每一格的文档注释里。** Godot 检查器里显不显示这几行没实测；不显示的话照旧查代码仓 `python tools/ui_art.py --list`，那里每一件一行。

### 权衡

- **素材资源，还是在主题编辑器里手敲项名**：PRD 选了前者 —— 名字填错的可能为零，载入时还能逐张核尺寸。代码再拿它组装引擎的主题。
- 资源类型是工具写出的代码，手改会在下次重跑时被冲掉而不报错；这条记进了代码仓 `CONVENTIONS.md` 的工具脚本那一节。
