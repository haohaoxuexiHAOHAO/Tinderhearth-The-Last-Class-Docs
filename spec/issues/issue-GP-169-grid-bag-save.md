# GP-169：背包存每一堆的位置，存档升一版，旧档迁过来

## 目标

背包那一片存档记下每一堆在网格里的位置与随身栏那一排，写出去读回来一格不差；上一版的存档读进来东西一件不少，手上那几格还在手上。

## 实现笔记

### 设计决策

- **位置明写，不靠项数推**：网格里一堆一项，带着它左上角那一格在第几列、第几行，网格几格宽、几格高也写进去。配置里的网格以后变宽，按格号推位置的话同一个格号会落到另一列另一行；有一条用例读进一张更大的网格，盯着每一堆还在原来那一列那一行。网格里的空格不记。
- **随身栏那一排一格一项，空格照写**：那一排格数固定、第几格就是位置，所以照格排，空格的种类与品质写空、件数与序号写零。
- **旧档由那个分片声明的升级迁过来**：分片声明多一项可选的升级（代码仓 `rules/Foundation/Save/SaveShardDeclaration.cs`），读档时比当前旧的存档先经它变成现在的形状，再补缺字段。补与丢只认现在的形状，不先升，旧形状那几串会被当成多出来的字段丢掉，背包悄悄变空而不报错。只有形状改过的分片才声明它，规则写进[`存档系统` · 载入：先读分片，再统一解析标识](../../design/存档系统.md)。背包的升级遇到改成网格之后的存档原样交回：以后别的分片改形状、版本再往上走，这一片不跟着动。
- **读档时网格与随身栏照现在的配置核**：存的比配置大就被拒，说清两边各多大，多出来的那一片没有地方放，而任何入口都不自动丢弃；小的照现在的大小读。
- **报错分两步、每一步一次列全**：先报读不出来的（类型不对、随身栏的空格记着东西、网格里一堆没有物品标识、左上角不在网格里、两堆左上角同一格），都读得出来再报与物品定义和网格对不上的（物品不在册、品质、件数、序号、随身栏里的大东西、出了网格、压在一起）。后一步由代码仓 `rules/Economy/Bag.cs` 的 `Restore` 报，网格里的一堆写成它左上角那一格的 (列, 行)，从 0 数，与存档里记的一样。

### 偏离

无。

### 权衡

- **没选照旧按格号存、只多记一个网格宽**：位置由格号与宽算得出来，可那样空格也要一格一项地写，而设计写的是每一堆存它的位置；改形状反正要升版本，就一次改成每一堆带位置。
- **没选沿用原来那几串的名字、按版本号换读法**：同一个名字在两版里意思不同（原来一格一项、开头几格是随身栏，现在是网格里一堆一项），读的那一步就得知道版本号，而分片的持有者读的时候拿不到它。换成新名字，旧形状只有升级那一步认得。

### 待确认

无。
