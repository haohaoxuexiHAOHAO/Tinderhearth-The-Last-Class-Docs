# DOC-121：系统文档与跨系统模型删掉文件头那两个字段

## 目标

`type: system` 与 `type: model` 的文档不再带 `last_verified` 与 `status` —— 它们要答的问题各自已经有家，而检查器要挡得住它们长回来。

## 来源

PRD：[`spec/prd-system-doc-completeness.md`](../prd-system-doc-completeness.md) 的 `US-005`，作者已确认走删字段这条路。

**立项依据**（实测）：`last_verified` 在多数系统文档里比 git 最后一次改动它的日期早，最旧的一份差了半个多月；`status` 几乎全是 `draft`，而[待办台账](./README.md)逐条写着「设计已交付」。检查器只验 `last_verified` 的格式，不验新鲜度 —— 所以这两个字段现在给的是假信心。

**为什么删而不是加守卫**：`last_verified` 要答「这一份还准不准」，而那个答案在上游指纹那套机制里（改正典某一节之后检查器会报要复核，`--repin` 重录，指纹进 git）；`status` 要答「做到哪一步了」，而那是状态、家在台账一处（[WORKFLOW §3](../../WORKFLOW.md)）。加守卫要求每次改文档都顺手改一行日期，而那类纪律靠不住。

## 依赖

无。但**排在 `DOC-118`、`DOC-119`、`DOC-120` 之后做** —— 那三条动的是同几份文档，先改正文再动文件头，回归责任分得开。

## 验收标准

- [x] 两个字段从全部 `type: system` 与 `type: model` 文档的文件头移除。
- [x] `tools/check_docs.py` 按体裁分别要求文件头字段：这两个体裁要求它们**不在**，其余体裁照旧要求它们在。
- [x] 那两条旧校验（`status` 允许值、`last_verified` 日期格式）对这两个体裁不再适用，**FAIL 文案一起改** —— 留着判一个不存在的字段会让每一份都报错。
- [x] 构造一份带着这两个字段的系统文档，检查器**报 FAIL**（挡它长回来的那条反证）。
- [x] [SYSTEM 模板](../../templates/SYSTEM.md)里那段文件头示例跟着改。
- [x] **归档件那条 `status` 判定与 ADR 那条「`superseded` 必须同时写 `superseded_by`」一个字不改**（两处都是真机制，拿 `git diff` 作证）。
- [x] 其余体裁（正典、ADR、制作规格、模板、台账、需求文档）**一份没动**。
- [x] 按字段名搜两个仓加 `.kiro`，没有指着系统文档那两个字段的残留说法。
- [x] `python tools/check_docs.py` 0 FAIL，并读它自报的覆盖量 —— **退出码 0 不等于成功**。

## 实现笔记

### 设计决策

- **模糊点**：旧的那两条校验（`status` 允许值、`last_verified` 日期格式）要不要整条删掉。
- **选择**：**留着，但只对带这两个字段的体裁生效**。判定写成「字段在就查它的取值」，而不是「这个体裁才查」。
- **理由**：其余体裁照旧带着它们，而 ADR 的 `superseded` 与归档件的 `archived` 都是真取值 —— 整条删掉会把那两处的取值校验一起带走。现在的形状是：长期规格判「不许带」，其余体裁判「必须带」，取值校验对两边都是「带了就查」。
- **另一处**：`REQUIRED_KEYS` 从四个收成 `type` 与 `owner`，另开一个 `CONDITIONAL_KEYS` 与一个 `FORBIDDEN_KEYS`。这样「哪个体裁要哪几个字段」在一处读得完，而不是散在判定里。
- **为什么判「不许带」而不是「可以不带」**：只把必填改成可选的话，下一份系统文档照着别处抄一遍文件头就又有了，而那不报错。

### 偏离

**有一处，写明理由**：`.kiro/skills/insight-diagram/SKILL.md` 里有一句列了那四个字段，而它前一句正说「图放 `design/` 对应的系统文档」—— 也就是字段已经不该有的那一种情形。条目原先只写「搜残留说法」，实际改了那一句：**不再复述字段清单，改成指模板与检查器**。理由与本条同源（清单只有一个家），而且不改它就留下一句会把人引回旧形状的话。

### 权衡

- 考虑过**加守卫**那条路（判 `last_verified` 不早于 git 最后改动日期）。**没选**，理由在上面「来源」那一节，作者已确认。
- 考虑过把两个字段从**全部**体裁删掉。**没选**：`status` 在 ADR（`superseded` 配对）与归档件（归档边界判定）那边挂着真机制，删它是另一件事、另一轮的范围。

### 待确认

**无。**
