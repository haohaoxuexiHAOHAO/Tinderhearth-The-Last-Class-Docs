# GP-154：床，以及调试键 N 走同一个入口

## 目标

站在床的范围里按交互键就睡；不在范围里照旧作用在当前操作格上；调试键 `N` 走同一个入口，每按一次也写一次档。

## 实现笔记

### 设计决策

- **模糊点**：交互键由床自己听，还是只在农场那一处听。
- **选择**：只在农场节点那一处听；床只回答「角色在不在我的范围里」。
- **理由**：两处各听各的，同一下按键先被谁接住就看引擎的调用先后，那正是「不看引擎返回的顺序」要挡的。

- **模糊点**：床怎么接到那片地上。
- **选择**：床的检查器里接那片地，床在 `_Ready` 里把自己登记过去；那片地不要求一定有床。
- **理由**：摆了床却没接上，床自己当场报错。没摆床的农场照样能种地、只能按 `N` 推进一天，而床迟早要搬进室内（`GP-130`）。反过来让那片地必须接一张床的话，[作物素材表那份的端到端](./issue-GP-147-crop-sheet-e2e.md)那份实机清单在摆床之前就跑不起来。

- **模糊点**：站进范围里的「角色」怎么认。
- **选择**：床的检查器里接那个角色，只认他。
- **理由**：按类型认的话，以后农场里有了别的走动的人，他站在床边、玩家在别处按交互键，也会睡过去。

- **模糊点**：推进一天那个入口公开还是私有。
- **选择**：私有，床那一下也由农场节点调。
- **理由**：推进一天只有一个入口；公开的话，别处能绕过「挑是睡还是作用在格上」那一步直接睡。

### 偏离

- **方案怎么说**：只加床。
- **实际怎么做**：农场节点的类注释里「本类只做三件事」那一句改成不带数的说法，列出它现在做的几样。
- **为什么**：结算与存档接上之后它早就不止那几样，那个数已经不对了。

### 权衡

- **键鼠上站在床的范围里点哪一格都是睡**：交互键在键鼠上的第一条绑定是鼠标左键，而床的范围优先。所以床要摆得离开那片地；搬进室内之后这件事就没了。
- **床在运行中挪出场景树再挪回来不会重新登记**：`_Ready` 只跑一次。床不会这么用，所以没做。

无。
