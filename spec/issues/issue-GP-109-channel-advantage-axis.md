# GP-109：六条生产渠道各声明一个优势维

## 目标

每条生产渠道都有一件它做得最好的事，玩家按今天缺什么去选，而不是照抄一条收益最高的。

## 来源

PRD：`spec/prd-richness-and-feel.md` 的 `US-010` 前半（声明与正典那一侧）。

立项理由：现行那条判据是「畜牧、钓鱼、烹饪与设备的每点精力收益都不得高于种植」。它防住了「新渠道更省事还更赚」，代价是把六条渠道排成一条线 —— **排成一条线之后第二名往后的渠道玩家没有理由用**。作者定的改法是不比总收益、比「它强在哪一维」。

三维各有对应的量：每点精力的钱、到手有多快、要不要你在场。各渠道的长处按现行规则填：种植是每点精力的钱最高（它仍是尺子）、畜牧出货最稳、钓鱼到手最快且不占任何格、加工价格天花板最高、烹饪是唯一出增益的且品质上限最高、设备是唯一不用你在场的。

## 依赖

无。它是 `GP-110`（判据换到推演里）与 `GP-111`（两级链）的输入。

## 验收标准

- [x] [`生产系统`](../../design/生产系统.md)的渠道表多一格「优势维」，缺了载入报错；**设备那张声明表上也加了同一格**，按 [ADR-0018](../../decisions/ADR-0018-内容定义按声明扩展.md)的**按声明必填**落位 —— 「产什么」填空的那类不填，而那与「漏填了」分得出来。两张表都没有按类型分叉
- [x] [时间与经营 · 生产](../../canon/gameplay/时间与经营.md)那句旧约束换成新的两条（**在它声明的那一维上最强**、**不许严格支配**），并写明旧那条防的是「新渠道比已有的更省事还更赚」；**新的怎么接住它有一个精确答案** —— 种植声明的就是「每点精力的钱」，而一维只归一个声明者，于是「别的渠道都不得在这一维上超过种植」是新两条的**推论**，旧那条防的东西一个字没丢
- [x] 六条渠道各自的优势维都填了，且没有两条填同一维 —— **「没有两条填同一维」落成载入校验，不只是「现在填的正好不一样」**；同一处另加两条校验（填了不在册的维、在册的维没有任何声明者）。**这里的「六条渠道」指[`生产系统`](../../design/生产系统.md)那张表的六行，含开荒、不含设备**（见下面「偏离」第二处）
- [x] 各维量什么都写明，且都指得到现有的量（格数、基础价、精力、天数、派工位、状态载体那条引用），**一个复合分数都没造**。**但维不是三条**：三条撑不起「每条至少在一维上最强」（见下面「偏离」第一处）
- [x] `python tools/check_docs.py` 0 FAIL 且摘要里各项覆盖量都不是零；动了正典所以按守卫的要求逐处复核了引它的「上游约束」再 `--repin`（见下面「核过没改」）。另跑了 `python tools/simulate_week.py` 与 `--check-doc` 两个入口做回归，都过 —— **本条一个参数都没动**，跑它们只是证明没顺手改坏

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：三条维撑不起「每条渠道至少在一维上最强」。一条轴只有一个最大值，而要声明的是六条渠道加设备。
- **选择**：**一维一个声明者** —— 维的数目由声明者的数目定，不预先拍一个数。在册的维与各自量的那个量写成一张表，家在[`生产系统`](../../design/生产系统.md)。
- **理由**：`US-010` 自己填出来的长处已经不止三种（畜牧出货最稳、加工价格天花板最高、烹饪出增益，三样都不在「钱／快／在场」那三条轴上），所以「三维」这个数是它自己破的。反过来说，**一维一个声明者把立项理由变成了载入校验**：加一条渠道就得同时加一维，而写不出「它最强在哪一件别人做不到的事上」的渠道就加不进来 —— 这正是「写不出它最强在哪的渠道不该存在」那句话的执行体。
- **第二处**：设备在「每点精力的钱」上**没有分母** —— 添料不占时间与精力，所以那一维对它是零除。这说明旧那条判据把设备列进去的那一半**从来就判不到东西**。改法：**设备不与渠道同台比**，它比的是同一条渠道的两个执行者，而那条约束早就在（产量必须低于同渠道人工）。它在册占「不用你在场」那一维，因为六条渠道在那一维上一律是同一个值 —— 那一维分得开设备与人工，分不开渠道与渠道。
- **第三处**：**维这张册必须外置得下。** 它看着像结构（与六条渠道加设备一一对应，而那份清单在正典），但 mod 加一条渠道时得能加一维 —— 把维写成规则层的一个枚举，[ADR-0018](../../decisions/ADR-0018-内容定义按声明扩展.md)给 mod 的那条承诺（加一样没人预见过的东西不用改代码）在这一格上就不成立。
- **第四处**：「在册却没人声明」也报错。一条没有主人的比较轴谁都不会去看，留着只让这张表越长越松；判它才让「一一对应」是真的。

### 偏离

- **方案怎么说**：`US-010` 与本条验收都写「三维」，并列出三条（每点精力的钱、到手有多快、要不要你在场）。
- **实际怎么做**：三条都留着、都在册，另外四条按同一形状补齐（腾出可用的地、出货最稳、价格天花板最高、唯一出增益）。**正文不写维的条数**，只写「声明者有几个就要几维」。
- **为什么**：见上面「设计决策」第一条。补充一句：**三维那一版不是错的方向，是不够的数** —— 三条轴上取得到最大值的就那么几个声明者，剩下的必然落进「哪一维都不是最强」，而那正是立项要修的缺陷换了个位置重新出现。

- **第二处（「六条渠道」两个所指不同）**：`US-010` 与本条的来源段填的是**种植、畜牧、钓鱼、加工、烹饪、设备**，而[`生产系统`](../../design/生产系统.md)那张表的六行是**开荒、种植、畜牧、钓鱼、加工、烹饪**，设备是不占人力的执行体、不占表里的行。**按文档那六行填**，设备的那一维落在它自己那张声明表上。理由：渠道表是一张表（ADR-0018），留一行空着就要另编一个「它没有这项能力」的故事；而开荒确实有一件别人做不到的事 —— **它是一块地变得可用的唯一入口**，别的渠道一格都不腾。
- **第三处（烹饪那一维取哪个）**：来源段写「烹饪是唯一出增益的**且品质上限最高**」，实际填的是**唯一出增益**。品质已经并进基础价（[`物品系统`](../../design/物品系统.md)），所以「品质天花板」与加工那条「价格天花板」不是两个独立的量 —— 两条都在册就等于同一件事占两维。而「产出条目里有没有引用状态载体那条增益项」是查得到的、且只有烹饪有。
- **第四处（「最强」允不允许并列）**：验收只写「没有两条填同一维」，没说最强算不算并列。**写明允许并列**，并举出真的并列的那一处：开荒与钓鱼都是当场到手，所以钓鱼在「到手最快」上是并列最快。不允许并列的话这一条今天就判不过，而它判不过的原因是度量粒度、不是设计错。挡住「没有理由用」的护栏因此明确落在**不许严格支配**那一条上。
- **第五处（多改了一处，连带四份活文档）**：渠道表那一节的标题里带着自计数（「只在四格上不同」），而本条给它加了一格。**标题改成不带数的「六条渠道，差别只在那几格」** —— 标题是别人按名引用的东西，它带一个会变的数就等于每加一格都要改一圈引用。跟着改的引用处：台账 `GP-62` 那一行、[`状态效果系统`](../../design/状态效果系统.md)接口表、[`地块系统`](../../design/地块系统.md)、[`关卡系统`](../../design/关卡系统.md)上游约束。**归档件与已接受的 ADR 按规矩不动。**
- **第六处（刻意没动的一处）**：[数值模型](../../design/数值模型.md)里还有几处按旧那条措辞写（`C10` 那一句、尚未给值表里渠道产量那一行、体力劳作折扣那一行、关卡拼装那一行末尾那条边界）。**没动它们**：判据侧归 `GP-110`，而旧那条现在是新两条的**推论**，所以那几处引述**不是错的**，只是还没换成新形式。

### 权衡

**也可以保留三维，把「每条至少在一维上最强」弱化成「每条至少不被支配」。** 判起来更省，而且三维那张小表好读。否决理由是它答不出立项要的那个问题：「不被支配」只说明这条渠道不是处处更差，玩家仍然问不出「什么时候该用它」—— 而一条没人用的渠道**不报错**，它只表现为内容白做。一维一个声明者的代价写明：判定更贵（要六条渠道的产量与耗时全有值才判得到数），而且**加渠道从「填几格」变成「填几格加想出一维」**；后者是有意的门槛，不是副作用。

**另一条被放弃的是把开荒排除在外**（当它是种地与盖房的前置，不是玩家为产出而选的渠道）。那样维少一条、也与来源段那六项对得上。否决理由：渠道表是一张表，排除它就要在那一行留个空，而 ADR-0018 那条分界要求「没声明这项能力」与「漏填了」分得出来 —— 于是又要为它单独编一项声明，而它本来就答得出自己最强在哪。
