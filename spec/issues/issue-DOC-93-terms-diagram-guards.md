# DOC-93：守卫收口，骨架升九节加六条新判定

## 目标

这次收拾完之后，「忘了写术语」「把定义又写了一遍」「改了流转却没重画图」都会当场报错，不靠人记。

## 来源

PRD：[`spec/prd-doc-readability.md`](../prd-doc-readability.md) 的 `US-005`。

## 依赖

`DOC-92` 全部填实（**已满足**）。术语节升二级标题与骨架改九节必须一次改完 —— 中间任何一份没升级，门禁当场全红。

## 开工前查出来的一件事：升级不是改个标题就完了

**过渡期那三十个术语块，位置都在「摘要」正文的前面。** 当时按「摘要之后、上游约束之前」放，落成的形状是：

```
## 摘要
  白话导语
### 术语
  （术语表）
  摘要正文 ← 它在这儿
## 上游约束
```

所以**直接把 `###` 改成 `##`，摘要正文会被吞进术语那一节**。三十份都是这样（术语块到「上游约束」之间还夹着 481–1396 字正文，逐份量过）。

**正确的改法是每份都要搬一次块**：把术语块移到摘要正文之后、`## 上游约束` 之前，再升成二级标题。三十份各两处编辑，**而且必须在同一批里做完** —— 骨架守卫是逐字比顺序的，改到一半门禁就是红的。

## 落地顺序

粗粒度的顺序、以及它排掉的那几条路，都在 [ADR-0019](../../decisions/ADR-0019-系统文档骨架加术语一节.md) 的「落地要求」。本节只补这一批的细步：

1. **三十份各搬一次术语块**：移到摘要正文之后、`## 上游约束` 之前，同时升成 `## 术语`。**这一步走完门禁必然是红的**（骨架还是八节），所以紧接着做下一步，中间不要停。
2. **骨架那份可执行副本改成九节**，顺序 `摘要 → 术语 → 上游约束 → 结构 → 接口 → 边界与非目标 → 理由与取舍 → 验收 → 下游同步`，与 [SYSTEM 模板](../../templates/SYSTEM.md)逐字一致。跑一次 `check_docs.py`，**这时应该回到 0 FAIL** —— 回不到就说明第 1 步有漏的，按报错逐份修。
3. **加术语那三条判定**，各撞一次失败路径。
4. **加图那两条判定**（重画条件那一行、标签子串核对），各撞一次失败路径。模板给的固定形状是 `**重画条件**：<…>`，守卫判的就是它。
5. **句长那条先跑成只列不判**，看全库分布再定上限，最后才升成失败。定之前不许开 —— 误报多的门禁会被绕过。
6. 撤回撞失败路径用的临时改动，确认 `git status` 干净。

**第 1 步与第 2 步之间是本批唯一的红灯窗口**，把它压到最短。

## 六条新判定各挡什么

| 判定 | 它挡的是 |
| --- | --- |
| 术语节里的每个词必须在本页正文出现过 | 抄一张与本页无关的表 |
| 同一个词不许同时出现在共用术语表与某份文档的术语节 | 一个词有两个家 |
| 共用术语表里的每个词条至少被一份系统文档用到 | 那份表只增不减地膨胀 |
| 每个 Mermaid 块旁必须有那一行重画条件 | **图静默腐烂** —— 它最主要的失效方式 |
| Mermaid 里的标签必须能在本页正文或表里找到（子串匹配） | 图偷偷引入了正文没有的事实 |
| 正文段落里的单句不超过字数上限 | 长句重新长回来 |

**句长那条有先后**：先跑成只列不判、看这三十份的分布，再定上限、再升成报错。误报多的门禁会被绕过，而被绕过的门禁比没有门禁更坏。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：「Mermaid 里的标签」包不包括连线上的文字。模板原来那个例子（「超时」对得上「超时自然站起」）举的恰好是一条连线文字，所以按字面读是包括。
- **选择**：**只判节点上读者看得见的字**，连线文字不判；模板那个例子同步换成节点，并写明连线的措辞归人读。
- **理由**：连线文字大半是「是／没有／到了」这类分支词，它们在正文里找得到也证明不了任何事；而一条连线编码的那个事实 —— 这条流转存在 —— 已经由它连起来的两个节点承载了。实测：连线算进来全库命中 47 处，只判节点是 30 处，多出来那 17 处全是分支词。**误报多的门禁会被绕过，被绕过的门禁比没有门禁更坏。**

- **模糊点**：带显示文字的节点，标识算不算标签。
- **选择**：不算。先收一遍「标识 → 显示文字」，后文裸引用那个标识时解析成显示文字。
- **理由**：`本子["当事人那本"]` 里的 `本子` 是程序内名字，**永远不渲染给读者**，拿它去正文里找是凭构造就会失败的误报。不先收这一遍，光这一类就多报六处。

### 偏离

- **方案怎么说**：本条只说「加六条判定，各撞一次失败路径」。
- **实际怎么做**：另外改了十三份系统文档的图节点措辞（三十处）与十二处长句。
- **为什么**：六条判定开成失败之后，全库有三十处标签与十五处长句越线 —— 要么改文档，要么把判定调松到判不出东西。判定的形状是 `FR-11`／`FR-19`／`FR-20` 写死的，所以改文档。**改的全是措辞**：标签换成本页已经在用的说法（`{"还有空格吗"}` → `{"有没有空格"}` 这类），长句在原有的分号处断开；有三处本页确实没说过图上那件事，就把它补进图旁那句说明（那正是这条判定要查的东西）。一条结论都没动。

### 权衡

- **句长上限取现在这个数，而不是更严。** 更严一档就要一次报出几十条，而那几十条大半是「下游同步」里的枚举 —— 那类行是给人扫的，不是那种「一句话套三个从句」的难读句。机器分不出枚举与嵌套从句，所以线放在长尾走平处，**它挡的是「长句重新长回来」，不是把全库拉到中位**。
- **句长只判长期规格。** 两条理由：定上限时量的就是这一群，把一个没量过的群体套上这个数，这个数就没有依据了；而冻结的体裁（归档件、已接受的 ADR）按规则不许用今天的说法改写，正典这一轮也明确不动 —— 对改不动的东西设门禁只会逼人绕过它。别处的句长由人读时把握。
- **骨架报错文案顺手修了一处既有错**：`type: model` 原来会被说成「DESIGN 模板」（[`数值模型`](../../design/数值模型.md)就是 `model`）。它在本条要改的那个函数里，且报错指错模板会让人去改错文件。
