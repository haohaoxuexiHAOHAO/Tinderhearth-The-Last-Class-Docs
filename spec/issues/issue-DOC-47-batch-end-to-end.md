# DOC-47：这一批的端到端与交叉核对

## 目标

用两条命令加三轮人工对照，看出这一批有没有和正典打架、有没有改漏某处说法、有没有踩别人写死的不变式。

## 来源

- PRD：[`prd-bubble-dialogue-and-diary.md`](../prd-bubble-dialogue-and-diary.md) 的 `US-007`
- 起因：纯文档批次没有可运行的对象，所以「做完了」这件事只有检查器的覆盖量与人工对照两种证据。

## 依赖

依赖本批其余全部条目。**它是最后一条。**

- [x] `python tools/simulate_week.py` 与 `python tools/simulate_week.py --check-doc` 都跑，并记下各自自报的覆盖量。
- [x] 代码仓 `python tools/verify.py` 记「不适用」并写明理由（纯文档批次，没有改动对象），**不留空**。
- [x] **按词核一轮，跑两遍。** 第一遍扫本批新词（气泡语料条目、上下文键、优先级档、冷却池、纪事、心声、需求标识、声明式回落），各只有一个家。第二遍扫容易互抄的那几组**理由** —— 尤其「为什么不共用一份存储」：气泡对事件（记账语义相反）、气泡对引导（引导是必要信息不许被丢弃）、日记对事件（日记是被写入方而不是记账方），三处理由各不相同，**抄一份就会让改动其中一侧时另一侧静默失去依据**。
- [x] **按量级数字核一轮**：本批没有在系统文档里抄第二遍量级事实（五档、十颗爱心、五个上下文键、九人名册、每季天数这类），写的是不带数字的说法或链接。

- [x] `temp/` 用完即空（只剩 `README.md`），设计仓 `logs/` 清掉，并在验证结果里写明删了什么。
- [x] **收尾时最后再跑一次 `check_docs.py`**，验证结果里抄的覆盖量用**那一轮**的数字 —— 填实现笔记本身会把节名引用处数顶过期。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。四类都要过一遍，某类没有就写「无」并简要说明。

### 设计决策

- **模糊点**：按词搜「过期说法」时，过程件里必然命中（它们在描述「从什么改成什么」），而机器分不出那是陈述还是对比。
- **选择**：把扫描分区 —— **活文档（`canon/` 与 `design/` 根下）里出现才算失败**，`spec/` 下的过程件只列不判；活文档里带对比词的行另列出来人判。
- **理由**：不分区的话这条检查会报几十处命中、每一处都要人看一遍，那等于没有检查。分区之后它报出的第一栏（活文档里当成现行陈述的）本轮是 0 处 —— 那才是一条说得出结论的判据。

### 偏离

- **方案怎么说**：三轮核对各跑一遍，记下结果。
- **实际怎么做**：第二轮（按量级数字）抓出四处真的副本并修掉了 —— 气泡那一份写了「五个键」，日记那一份三处写了「五档」。
- **为什么**：这正是那一轮存在的理由。量级事实的散文副本机器判不了（它分不出两个数字说的是不是同一件事），所以只能按词搜出来人判；修法是**删掉数字词**（改成「每个键」「关系那条阶梯上的一档」），不是把数字改对。

### 权衡

**又一次拒绝把「按词交叉核对」落成 `tools/` 入口。** 机器搜得出一个词出现在几处，**判不出那几处说的是不是同一件事** —— 而本轮要判的恰恰是「三处『不共用一份存储』的理由是不是同一个」。判断一个入口该不该留，看它判的东西在 Godot 里看不看得出来、机器判不判得到，不看它长得像不像守卫。**留一个没有判定能力的守卫比没有守卫更坏。**

### 待确认

代码仓那一侧本轮没跑（纯文档批次，没有改动对象），所以**「两份新文档描述的代码落点真的是空的」仍是推断** —— 两份文档的「下游同步」里都写明了这一点，实现前要先搜一遍代码仓。
