# DOC-65：逻辑分辨率在正典里写成已定值

## 目标

正典里的逻辑分辨率是一个结论而不是一张候选表，且这个数全库只有一个家。

## 来源

- PRD：[`spec/prd-canon-hardening.md`](../prd-canon-hardening.md) 的 `US-004`
- 起因：`UI-1` 已归档、值早在代码仓 `project.godot` 里跑着（`viewport_width=640`、`viewport_height=360`、`scale_mode="integer"`），而[玩法定位 · 像素基准](../../canon/gameplay/玩法定位.md)还摆着两个「可用」候选、说选哪个归 `UI-1`

## 依赖

无。它不依赖本批任何一条，本批也没有一条依赖它 —— 所以它排「下一件」。

## 验收标准

- [x] 可核对：[玩法定位 · 像素基准](../../canon/gameplay/玩法定位.md)那张表改成结论「**已定 640×360**」，并写出两条理由（12px 中文一行装得下；720p／1080p／1440p／4K 四档都整数倍放大）。
- [x] 可核对：被排除的候选各留一句为什么，**表里不再出现「可用」这个词** —— 它是这条问题的根源。
- [x] 可核对：480×270 那一行的理由写准 —— 它**连 720p 都除不尽**（1280 ÷ 480 = 2.67），不止正典现在写的 1440p。算式写出来，不引外部来源。
- [x] 可核对：[战斗与关卡 · 48px 是怎么算出来的](../../canon/gameplay/战斗与关卡.md)那笔账前面写明前提「按 640×360，已定」，**表里数字一个不改**。
- [x] 可核对：那一节不再把这件事指给 `UI-1`（它已归档）。
- [x] 可核对：按 [WORKFLOW § 3](../../WORKFLOW.md) 第 3 条搜两个仓加 `.kiro`，分辨率这个数**只有一个家**，别处写链接不复述。三处刻意保留的例外与理由见下面「偏离」。
- [x] 可核对：`python tools/check_docs.py` 0 项必须修复。

## 实现笔记

### 设计决策

- **模糊点**：那一节的标题「分辨率的下限由中文可读性决定」现在只说了两条约束里的一条，读着像该改名。
- **选择**：标题一个字不动，约束二写进正文。
- **理由**：[ADR-0008](../../decisions/ADR-0008-中文像素字体选型.md)按节名引用着这个标题，而节名引用有守卫（[WORKFLOW § 3](../../WORKFLOW.md) 第 5 条 ①）；改名会当场断链，而按 [WORKFLOW § 4](../../WORKFLOW.md) 已接受的 ADR 不许改。标题本身仍然成立 —— 下限确实是可读性定的，整数放大只排掉了下限之上的一个候选。

### 偏离

- **方案怎么说**：分辨率这个数**只有一个家**，别处写链接不复述。
- **实际怎么做**：正典、[待办台账](./README.md)、[`成长系统`](../../design/成长系统.md)、[`生产系统`](../../design/生产系统.md)与[踩坑记录 42](../../reference/踩坑记录.md)里的复述都改成了链接；另有三处刻意留着数字。
- **为什么**：① [ADR-0008](../../decisions/ADR-0008-中文像素字体选型.md)两处 —— 已接受的 ADR 不得用今天的理由改写当时的背景（[WORKFLOW § 4](../../WORKFLOW.md)）；② 代码仓 `rules/Ui/UiMetrics.cs` 与 `src/World/GameCamera.cs` 的注释 —— 本需求[明确不写一行代码](../prd-canon-hardening.md)，且那两处紧贴着它们解释的常量，属 [WORKFLOW § 3](../../WORKFLOW.md) 写明的「描述代码行为的散文根治不了」那条边界；③ [踩坑记录 41](../../reference/踩坑记录.md)的症状里那一行是诊断输出的实测记录，换成链接会让那条记录失去复现价值 —— 它不会因为改分辨率而变错。

### 权衡

正典里那笔 48px 的账要不要连带写出「640×360」这个数，两说。写了就是一处复述，不写则「这笔账只在那个分辨率下成立」这句话无从核对。选写，因为它是**前提声明**而不是独立主张：数字后面紧跟着指向家的链接，家变了这一处就是查得出来的断链，而不是静默过期的副本。

### 待确认

无。
