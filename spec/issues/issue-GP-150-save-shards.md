# GP-150：存档按分片声明与注册，一份存档文件的外形

## 目标

每个分片由持有它的系统显式声明并注册，声明缺一项或重复注册当场被拒；有一个读口列得出全部已注册的分片；一份存档文件最外层只有一个版本号与各分片，是明文 JSON。

## 来源

- PRD：[`spec/prd-sleep-advances-day.md`](../prd-sleep-advances-day.md) 的 `US-004` 第一、二、九格，`FR-18` 到 `FR-20`、`FR-22`。
- 结构在[`存档系统` · 一个分片要声明什么](../../design/存档系统.md)，格式在 [ADR-0015](../../decisions/ADR-0015-存档的版本与缺字段口径.md)，本条都不复述。

- [x] 可测试：已注册分片的读口列出的正是注册过的那几个，不多不少；没注册的不在里面，也没有自动发现。新建的那一份是空的。
- [x] 可测试：写出来的存档文件最外层只有一个版本号与各分片，每个已注册分片一格。缺一个进正式存档的分片、多给一个没注册的、给了一个进续玩点的，都被拒。代码在代码仓 `rules/Foundation/Save/`，写法是 `SaveFile.WriteFormalSave`。

## 实现笔记

### 设计决策

- **模糊点**：存档默认值是一份固定的数据，还是每次现做。
- **选择**：一个工厂，每次调用给一份新的；注册时先调一次，给不出来与没填一样被拒。
- **理由**：它要与「这个分片从来没存过」时的初始值同一处，所以最直接的做法就是拿那个初始值调一次本分片的写法。地块那一片的初始值是场景里那片地，事先写不成一份固定数据。每次给新的一份，也免得哪一处改了它、把别处一起改掉。

- **模糊点**：「进哪一侧」漏填怎么判得出来。
- **选择**：枚举从 1 起，0 留给没填，注册时与枚举里没有的数一起被拒。
- **理由**：从 0 起的话，漏填就等于填了正式存档，而那不报错。

- **模糊点**：存档的 JSON 选项要不要与内容数据共用一份。
- **选择**：分开。存档那一份不放行注释与尾逗号，换行写死成 LF，中文不转义。
- **理由**：内容是手写的，那两样是给人的宽容；存档是程序写的，出现那两样只能是被改坏了。LF 让同一份存档在不同系统上写出来逐字节一样；存档里会有玩家起的名字，转义之后在文本编辑器里认不出。

- **模糊点**：注册表是一个全局的，还是每次建一份。
- **选择**：每次建一份，由用它的那一侧建、显式注册。
- **理由**：全局一份要回答「谁来清空」，测试之间也会互相串；而没有自动发现这一条，在每次新建的那一份上看得最清楚。
