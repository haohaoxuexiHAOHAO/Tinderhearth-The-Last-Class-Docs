# GP-43：`design/经济系统.md`

## 目标

把「钱记在哪、一件货这一刻值多少、报酬引用怎么变成一笔钱」写进一处，加一条支出或一个价格因子时不用重新发明一遍。

## 来源

- PRD：[`spec/prd-economy-and-building.md`](../prd-economy-and-building.md) 的 `US-003`
- 起因：正典的[定价三层](../../canon/gameplay/时间与经营.md)已定，但那三层落成什么字段、每一层读谁、玩家在哪查得到原因，一条都没写。
- 两处已经欠着的债：[`任务系统` · 任务实例的字段](../../design/任务系统.md)写明「报酬只存引用，不存数额 —— 定价归后续的经济那一批」，[`物品系统` · 品质并进基础价，不当第四个乘数](../../design/物品系统.md)把品质系数指给了参数表。两边都在引一个还没有家的东西。

## 依赖

`GP-39`（点差那一侧要引重排后的生活技能表）。**与 `GP-44` 互相引用** —— 建造的花费走本条的支出管道，本条的挂载点表要列建造下单，所以两条一起写完一起验。

- [x] **三层各自的输入写成一张表**：基础价读什么、需求系数读什么、供给系数读什么，以及各自什么时候变。写明**三层之外不许再加乘数**，并写明它防的是什么。
- [x] 写明**基础价对一个具体实例固定不变**，品质已并进它而不是第四个乘数（指回[`物品系统`](../../design/物品系统.md)，本页不复述系数）。
- [x] 写明**需求系数买卖双向、供给系数只在卖出侧**，理由写清（供给系数量的是玩家自己的出货量，买入不构成出货；需求高时只涨卖价不涨买价那不是一个市场）。
- [x] 写明**需求偏好按货物分组公布，不按具体物品**，分组是[`物品系统`](../../design/物品系统.md)那条类别轴更粗的一层，**不新建字段**。
- [x] 写明**供给系数的「同一批次」指一次结算里的同种货物**，跨季的市场存量记忆属于后续扩展那一层；同一处写明那两层扩展各挂在哪个已有输入上，**不新建层**。
- [x] **每个因子都有一个可查的读口**：当前值加一条原因引用，原因是**引用**而不是写死的中文串。
- [x] 写明**事件调价走需求系数那个输入**，不另开通道（[玩法定位 · 随机事件：事件可以晚做，扩展点现在就留](../../canon/gameplay/玩法定位.md)）。
- [x] **点差写成一个作用形式**：买卖**双向对称**、偏离量同一个数、**不进三层**；写明它与三层的分工，写明双向的理由，并写明点差有上限。
- [x] **钱包的结构**：按角色各一个、内部只有一个量纲而分级只在显示层，理由指回[世界观 · 货币、信贷与私产](../../canon/world/世界观.md)的总量固定。
- [x] **支出只有一条管道**：报酬、建造下单、治疗、还款、采购都走它；现金不足一律**只拒不赊**并给出缺口，**不产生欠款记录**。
- [x] **债务的结构**：本金、累计利息、利率、计息时点；**还款只从主角钱包出**的理由指回所属权，**无硬期限、逾期只加息、不没收基地、不进败局**，并写明「破产」不是一个状态。
- [x] 写明**利息单独累计、不并进本金所以不计复利**，应付总额是本金加累计利息，**还款先冲利息再冲本金**；理由写清，并写明[`数值模型`](../../design/数值模型.md)那两处本来就是按单利算的、不必重算。
- [x] 写明**债务计息在每日结算里占的是已有那一步，本页不新增结算步**（按步名引用，不按步号）。
- [x] **报酬引用的解析**：报酬表按「类型 × 档位」给，结果是一笔钱加可能的物品引用；写明它与[`任务系统` · 时间与精力的消耗按「类型 × 档位」查表](../../design/任务系统.md)那张消耗表**同一形状、两张表**，并写明为什么不合成一张。
- [x] **生产队收购这条路径**：时点、错过不罚、玩家不在基地时按指定区域自动结算、不讨价还价、收购能力不受对方钱包限制；写明**不限品类**并给出理由。
- [x] **商店这条路径**：上架读所在区的[失衡档位](../../design/活跃失衡系统.md)（就近读，不读全城总量）、高级一律不卖；写明**上架清单与刷新幅度不在本页**。
- [x] 写明**商店库存的刷新不占每日结算的任何一步**：进店时按「距上次刷新过了几天」惰性算，每家店存一个「上次刷新在哪天」；理由写清。
- [x] 写明**刷新间隔按商店种类各声明一个天数**，而上架的内容与数量仍读所在区的档位 —— 两件事分开。
- [x] 写明**手环订货与到店读同一份上架结果、同一个价格，差别只有送达延迟一天**；理由写清（延迟不碰价格模型）。
- [x] 挂载点列全并写明「到此为止」，至少覆盖派工报酬、任务报酬、建造下单、治疗费、还款、生产队收购、商店买卖与手环订货、事件调价、统计事件总线、存档。

- [x] 文档里一个玩法数值都没有；三层、货币级数、档位这些量级写链接不复述。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：点差「不进三层」落成什么形状 —— 验收只要求写明它不进，没说它在哪。
- **选择**：写成 `玩家到手 = 成交价 ± 点差`，与那条乘法链**分两行**。
- **理由**：分两行之后手环里就能把「市场价」和「你谈成的价」各写一行，而这正是可解释性要的东西。更要紧的是它给出了一条能写的反证：**改点差时基础价与两个系数一个字都不变** —— 「不进三层」原本是一句判不了的话，这么写之后判得到了。

第二处：**支出做成一条管道，收入不做。** 收入没有「不够」这一支（卖货、报酬、上交都是直接入账），唯一要判的是归属，而归属已经在正典里。给收入也套一条管道就是为对称付一份没有收益的成本。

第三处：**货币内部只存一个量纲。** 三级硬通货存三个字段看着直观，但那套换算固定不变（总量固定、不能增发），所以它是显示格式而不是规则 —— 存三个数就要处理进位与借位，而那类错不报错。

### 偏离

- **方案怎么说**：本条只写 `design/经济系统.md`，`GP-44` 另写建造那份。
- **实际怎么做**：两条是同一轮做完并一起验的，本条的文档直接链了 `建造系统`。
- **为什么**：**两份互相引用的系统文档不可能各自独立跑绿** —— 建造的花费走本页的支出管道，本页的挂载点表要列建造下单。可选项只有两个：其中一份先写成不带链接的散文、下一轮再补（两次工，而且中间那版的挂载点表读起来像缺一半），或者一起写完一起验。取后者，**所以本条的「`check_docs` 0 FAIL」是与 `GP-44` 合并之后才成立的** —— 写在这里免得被当成单独跑绿了。

第二处：**顺带删掉了三处「定价归后续的经济那一批」占位**（[`任务系统`](../../design/任务系统.md)两处、[`关卡系统`](../../design/关卡系统.md)一处）。它们不在本条的验收清单里，但它们指的就是本条 —— 落地后不删，就是指向一个已被回答的问题的指针。

第三处：**[数值模型](../../design/数值模型.md)里补了一句「债务用单利」**。那份的判据 C8 与 C9 抄了两个算出来的量（利息折到每天、还债天数），它们本来就是按单利算的 —— 不写明的话，下一个人改成复利时不会想到要重算那两处。

### 权衡

「商店库存刷新加一步每日结算」考虑过，最直观。没选：那张表标着「固定，不得改动」，上一批刚为加两步付过一次代价；而且城区若真有多家店，每天要全算一遍、算完绝大多数玩家当天根本不去。**惰性算的代价写明了**：要存一个时间戳，而且刷新那一刻不进结算摘要。

「刷新间隔按区给」考虑过，与上架读同一个来源更省。没选：那会让「区」同时管两件事（货有多好、多久换一批），而正典只把档位与「货有多好」绑在一起。

「报酬表与时间精力消耗表合成一张」考虑过。没选：两张表**改动的理由不同** —— 消耗表调的是「一天装得下几次出征」，报酬表调的是「出征值不值得」；合成之后想让委托更赚就会顺手把耗时也改了。

「给收购加品类限制」考虑过（高级的东西不收）。没选：正典点名要避免「卖不掉只是卡住」。买卖两侧本来就不对称 —— 不卖高级是为了让钱买不到战力，收高级只是让玩家把打回来的东西变成钱。

### 待确认

**一处是推断，未实测**：「经济的逻辑在代码仓一处都没有」这句写进了下游同步那一节，**但没有搜过代码仓确认**。验法很简单，实现前搜一遍；写明它是推断是因为上一批同样的句子是搜过的，这一批没搜。
