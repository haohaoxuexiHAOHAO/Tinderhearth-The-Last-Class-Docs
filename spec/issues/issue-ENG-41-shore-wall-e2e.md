# ENG-41：水边石壁的端到端

## 目标

三套重画的双网格从声明到画面走一遍：按方向声明的检查过得了新的三套，故意改错一个格边像素时说得清错在哪，作者照指南在农场里看完。

## 来源

- PRD：[`spec/prd-shore-stone-wall.md`](../prd-shore-stone-wall.md) 的 `US-005`，作者实机那几格来自 `US-002` 与 `US-006`。

## 依赖

- `ENG-36`：按方向声明与报错。
- `ART-33`、`ART-34`：新图要先交来，检查才有东西可判。
- `ENG-42`：作者的瓦片集要先按它的形式接进游戏，农场里才看得到新图。
- `DOC-155`、`DOC-156`、`DOC-157`：规矩那一节，与作者照着走的指南那几行。

## 验收标准

- [ ] 自动化：作者交图之后，代码仓 `python tools/verify.py` 里双网格那一步按新的方向声明通过新的三套。
- [ ] 自动化（一次性，跑完删）：拿一份故意改错一个格边像素的副本跑检查，报出那一张、那条边、那个方向。结果与删了什么写在「验证结果」里。
- [ ] 可核对：代码仓 verify 全过；设计仓 check_docs 0 FAIL。
- [ ] **作者实机确认清单**：照指南「跑一遍验收」新加的那几行走，按行名对号，见下面「作者实机清单」。

## 作者实机清单

等作者的瓦片集（`ART-33`、`ART-34`）由 `ENG-42` 接进游戏，再照[一块地能种出东西 · 跑一遍验收](../../reference/godot/一块地能种出东西.md)那张表走，怎么做只写在那张表里：

| 那张表的行名 | 对应哪一条 |
| --- | --- |
| **北岸露墙面** | `US-002`：北岸看得到墙面，墙脚一道亮的水线，墙面下方的水里有倒影 |
| **南岸看不见墙** | `US-002`：南岸看不见墙，只有草边 |
| **两侧是暗的侧面** | `US-002`：左右两岸是暗的墙的侧面 |
| **拐角接得上** | `US-002`：内外拐角都接得上 |
| **纹理铺到石壁** | `US-002`：草地与水面的纹理一直铺到石壁，石壁、水线与倒影没有被纹理换掉 |
| **停在墙顶** | `US-002`：朝水走过去，人停在墙顶的岸上，看着不像浮在水面上，也不像陷进墙里 |
| **土边一簇簇的草** | `US-006`：草挨着裸土的边是一簇簇探出去的小草，草的影只落在草南边的土上 |
| **深水落下去的那一面** | `US-006`：深水北边看得出是落下去的那一面，别的方向只有一道窄边 |
| **三套一个画法** | `US-006`：三套放在一起，草边、石壁与深水边看着是一个画法 |

**停在墙顶**要先照「让水挡住人」配好数据层、照第三步把角色放进来 —— 仓里那份农场的数据层还关着 `Enabled`，一按 `F6` 先报数据层的碰撞。全部看完，「作者实机确认清单」那一格与 [`ART-33`](./issue-ART-33-shore-stone-wall-set.md)、[`ART-34`](./issue-ART-34-grass-dirt-shallow-deep-redraw.md) 里作者实机那几格一起勾。
