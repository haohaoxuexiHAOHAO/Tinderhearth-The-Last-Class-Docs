# DOC-139：还有一批取值集没按 `ADR-0025` 归过类

## 目标

`design/` 下每一处「某一格能填哪些值」都有一个归类，所以写载入校验的人不用自己挑一边。

## 来源

- 本轮开头那次全库普查（[ADR-0025](../../decisions/ADR-0025-取值集的家由加一个的代价决定.md) 的判据就是从它归纳出来的）
- 收口时（`DOC-138`）确认这批没被那一轮覆盖 —— [`prd-extensible-lists`](../../archive/spec/DOC-135-extensible-lists/prd.md)（**历史背景·非依据**）只点名了其中几格

**来源要写明**：这批**不是收口时另跑的一次核对**，所以逐处按判据定归属仍然是本条的活，不能拿普查结论直接当结论。

## 依赖

无。判据已经有了（`ADR-0025`），本条是把它逐处套一遍。

## 共同形状

**文档写着「这张表是开口的」却没说开口通向数据文件还是通向代码。** 于是写载入校验的人自己挑一边，而挑错了不报错 —— 挑成数据则填得进一个没有实现的取值，挑成代码则 mod 加不了本该能加的东西。

## 实现笔记

**归类结果按类分**：

- **结构型**（加一个要写代码，只有我能加、先立项）：剧情演出的指令类型、教育的知识书产出表、生产的「它另外做什么」、节日的计分量、统计总线的标识与量名、关卡的职责轴、失衡的掌握程度、气泡的上下文键表。
- **内容型**（加一个只填数据）：关卡的结构轴、委托配额、生产的「在哪做得了」。
- **接口常量**：天气的侵袭档。

**三格原先不是归类问题，是别的问题，所以处置不同**：

- 多周目的「上限」与剧情演出的「目标与参数」都是**校验形状**问题 —— 前者改成按产出落点判（兑换项刻意没有类字段），后者写明为什么这里允许按类型必填而不违反 `ADR-0018`（指令类型是结构型，每一类各有一段实现，所以「没声明这项能力」这种情形不存在）。
- 统计总线那一格除了归类，还缺一张**在册的登记表** —— 不补它，量名改了不报错。

**顺带修掉三处自相矛盾**（都不是本条立项时点名的）：

- 关卡那两轴**同时写着「家在正典」与「家在本页」**，两句成立不了 —— 现在结构的起步清单在正典、在册的在数据，职责整格在本页；正典那四种形状跟着写明是**起步内容、不是封闭清单**。
- 多周目「属性点那一类必须声明上限」**没有可判的对象**。
- 物品系统那句「两条轴的取值集合可扩」是**一句做不到的承诺** —— 那件事归 `GP-127`，本轮一起办了。

**三格顺手归的**：气泡的上下文键表（与清单同形）、生产的「在哪做得了」改成引用建筑类别那个已有取值集（原先散在三处）、节日那一格顺带写明「比哪一样动作」不是取值集（它的合法性由那个动作存不存在判）。

**偏离一处**：改了一个节标题（剧情演出「指令类型是一张开口的表」→「指令类型：开口通向代码，不通向数据」），所以引它的两处跟着改了。归档件里那两处没动 —— 它们只读。
