# UI-8：关卡 HUD 的屏幕空间部分

## 目标

侧视关卡里玩家能一眼看清自己的资源、技能位、目标进度与队友状态，且这些东西不压掉屏幕中间那块该看角色的区域。

## 来源

- PRD：[`spec/prd-ui-framework.md`](../prd-ui-framework.md) 的 `US-007`（屏幕空间那一半；世界空间部分在 `UI-9`）
- 取 HUD 当样板界面由作者 2026-08-30 定。理由：它落在全游戏最挤的一块地方 —— 640×360 在侧视 2 倍缩放下有效视野只有 320×180。

## 依赖

`UI-6`（层级与排版单位）、`UI-7`（修饰键组合的当前组数据）、`ART-4`（占位素材）。

## 验收标准

- [ ] 主角 HP／SP／MP 与体力常驻可见
- [ ] 6 个技能位可见并有冷却表现；手柄修饰键按下时显示当前那一组对应哪三个技能
- [ ] 目标进度常驻可见（还差几个素材、还剩几个来源点）；为 0 或已达成时仍显示而不隐藏（[战斗与关卡](../../canon/gameplay/战斗与关卡.md)要求始终可见）
- [ ] 队友状态可见，容纳编队上限 4 名学员；队友为 0（单人采集）时该区收起而不是留空槽
- [ ] 同屏 10–15 个敌人时 HUD 不遮挡角色所在的可读区
- [ ] 显示的数值全部由视图模型传入，代码里没有任何写死的数字（`GP-2` 的参数表不在本条落地）
- [ ] 没有绝对像素坐标，全部锚点与容器
- [ ] 作者实机确认：打开样板场景，看 12px 文字在动态下读不读得清、HUD 有没有压掉该看的东西
