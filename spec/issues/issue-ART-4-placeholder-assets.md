# ART-4：占位素材生成器与素材槽位登记表

## 目标

有一条可重跑的入口按最终规格产出占位素材，并有一份登记表记住每个槽位的规格与来源，使作者用自己的像素资源替换时不需要改任何代码。

## 来源

- 作者 2026-08-30 定的工作方式：占位素材先跑通逻辑，最终由他用自己的像素资源替换。他画图需要时间，不可能一次性提供全部素材。
- PRD：[`spec/prd-ui-framework.md`](../prd-ui-framework.md) 第 8 节「占位素材」三条约束

## 依赖

无。但它阻塞 `UI-8`（HUD 要素材才摆得出来）与 `ENG-10`（守卫要登记表才能比对尺寸与槽位）。

## 验收标准

- [x] 生成器是可重跑的入口：代码仓 `python tools/gen_placeholders.py`，重跑实测逐字节一致（第二次跑"内容有变化的 0 个"）
- [x] 24 个槽位：9-slice 面板、资源条底与填充、6 个技能位框、6 个技能图标、目标进度、头像框、读条圆环、3 个角色剪影、3 种地形图块
- [x] 一眼可辨是占位：洋红描边加左上角标 —— 洋红在废土低饱和暗色盘里不会出现
- [x] 符合[像素绘制原则 §9](../../production/像素绘制原则.md)：实测 24 个文件的 alpha 只有 0 或 255
- [x] 带 1px 细节，实测没有任何一个文件"每个 2×2 块同色"，不会被 `ENG-10` 误判
- [x] 登记表 `tools/asset-registry.json`：路径、用途、宽、高、帧数、来源、授权、待替换、可进发行包
- [x] 登记表放 `tools/`（有 `.gdignore`），因此进不了发行包 —— 它是开发期元数据
- [x] 双向比对并自证：注入"多一个未登记文件"与"槽位尺寸不符"各一次，两次都被拦（`EXIT=1`），还原后复验通过
- [x] 顺带堵掉一个静默炸弹：`detect_3d/compress_to` 默认为 1，纹理一旦被判定用在 3D 就重新导入成 VRAM 压缩、毁掉像素图。改成项目级 `[importer_defaults]`，并把三项导入参数纳入 `--check`（守卫当场抓出 24 个旧 `.import`，删掉重导后通过）
- [x] 不做纯 PNG 依赖：用 zlib 手写 PNG，本机没有 Pillow，也不为占位件加依赖
- [ ] 下载类素材（角色精灵与动画）标明来源链接与许可证 —— **本轮无下载件**。规格与流程写在 `temp/art-inbox/README.md`，作者放进去后再登记
- [ ] 作者实机确认：占位件在 640×360 下看得出布局意图（跟 `UI-8` 的 HUD 一起看）
