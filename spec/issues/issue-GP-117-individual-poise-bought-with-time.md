# GP-117：活跃失衡的个体层可以被时间线性买光

## 目标

「越低越难再降」这条承重设计覆盖到个体层，而不只是社区组那一层。

## 来源

**超边界记账**：在 `spec/prd-richness-and-feel.md` 那一轮的评审中发现，**明确排出了那个 PRD 的范围** —— 它要重新校准教学与失衡两侧，塞进那一轮会让验收范围说不清。

## 依赖

`GP-100`（活跃失衡落地）与 `GP-21`（教育落地）。**它要两侧一起改**，所以不能只挂一个。

## 证据

三份文档各自自洽，串起来是一条可以用时间买通的路径：

- [`活跃失衡系统`](../../design/活跃失衡系统.md)的「越低越难再降」写成缩放，**而那个公式只作用在组那一层**（递减系数读该组当前值）；个体层没有递减。
- 个体层唯一的降法是教学（学生那一侧），而[`教育系统`](../../design/教育系统.md)的防刷是知识吸收效率 —— 它**按学生记**，所以每天换一个人指导就永远是满效率。
- 个体值计入总量，而总量决定完美结局的条件之一（[主线故事](../../canon/narrative/主线故事.md)）。

于是：轮教 → 效率永远满 → 个体失衡线性降到底 → 那条完美结局条件被时间买通。**而[`活跃失衡系统`](../../design/活跃失衡系统.md)建立的全部前提是「代价急剧上升」。**

**这是推断，不是实测** —— 两侧都还没落地，所以现在量不到「多少天买得光」。验证办法：两侧落地后按参数跑一遍个体失衡的逐日曲线，看它到零用多少天，与还债、练满两条曲线比（形式与判据 `C9` 同源）。

## 验收标准

- [ ] 个体层有没有递减这件事有明确结论，并写进[`活跃失衡系统`](../../design/活跃失衡系统.md)
- [ ] 若选了给个体层加递减，它与组那一层共用同一条缩放形式还是另一条，写明理由
- [ ] 若选了不加递减，写明那条「代价急剧上升」为什么对个体层不适用 —— 不许留成默认
- [ ] 教育侧那条「吸收效率按学生记」是否要改（例如按主角的授课额度记）有明确结论
- [ ] 那条曲线接进推演，能算出个体失衡到零的天数，并与还债、练满同量级那条判据一起判
- [ ] `python tools/check_docs.py` 0 FAIL
