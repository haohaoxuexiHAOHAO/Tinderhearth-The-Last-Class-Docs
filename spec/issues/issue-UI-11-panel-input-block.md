# UI-11：不暂停的面板打开时玩法动作该不该屏蔽

## 目标

定清楚「关卡内打开背包（不暂停世界）时，手柄的跳跃与闪避该不该被遮」，并让这条裁定有执行体。

## 来源

`UI-7` 实现时撞出来，跨 `UI-6` 的导航栈与 `UI-7` 的输入门面，故不在 `UI-7` 顺手定。

## 依赖

`UI-6`（导航栈）、`UI-7`（InputRouter 门面）。

## 验收标准

- [x] 裁定有文字依据且写进了代码注释
- [x] `InputRouter.IsPressed` 与 `IsJustPressed` 在面板打开且手柄时遮挡跳跃与闪避
- [x] 键鼠不受影响
- [x] 规则层有单元测试覆盖两层遮挡（修饰键遮挡 + 面板遮挡）
- [x] 测试把被遮清单与内置补丁的面键钉在一起，面键分配改了会在测试里先失败

## 实现笔记

### 裁定（作者 2026-09-02）

**面板打开时屏蔽跳跃与闪避（仅手柄）。**

理由：面板打开时玩家的意图是操作界面，不是战斗。背包不暂停世界这件事让玩家保留了移动与攻防
能力，能一边整理背包一边走位、防御；但跳跃与闪避在手柄上与 UI 确认、返回共用同一个键，
「按下去到底是哪个」本身就是歧义，歧义里选玩家在做的那件事（界面操作）更合理。

代价：面板打开期间手柄玩家不能跳跃与闪避。可接受，原因是正典已为失衡结束设了逃生窗口，
这段时间玩家在整理背包，本身就不应该处于需要立即闪避的战斗压力下。

键鼠不受影响：键鼠的确认与返回用 Enter／Escape，这两个键没有绑玩法动作。

### 设计决策

**一、规则落在 `rules/Ui/PanelInputBlock.cs`，而不是散在调用方。**
`BlockedByOpenPanel` 是一份清单，改动有一个地方。与修饰键遮挡（`SkillModifierState.ShouldSuppress`）
对称：两层遮挡都在规则层定义，`InputRouter` 只是执行者。

**二、`InputRouter` 通过 `Nav` setter 注入 `UiRoot` 拥有的导航栈。**
`InputRouter` 不知道面板是谁打开的，只需要知道「现在有没有面板」—— `NavigationStack.Depth > 0`
就够了。不注入时用自己的空栈（`Depth` 永远为 0），与没有 `UI-11` 之前的行为兼容，测试不受影响。

**三、连线在 `Main.ProbeInputMapping()`，顺序有保证。**
`ProbeUiSkeleton()` 先于 `ProbeInputMapping()` 跑，`_ui` 有值时才赋 `_router.Nav = _ui.Navigation`，
不存在空引用的时序风险。

### 权衡

`IsJustReleased` 不加面板遮挡。松开事件不会触发跳跃或闪避的动作效果，只影响「停止跳跃」这类
持续型动作的收尾，而跳跃与闪避都是单次触发，松开遮不遮没有行为差异。多遮一层只增加迷惑性。
