# UI-63：物品图标资源，缺图一次全报

## 目标

每个物品在 Godot 里配一份图标资源，配漏了、配重了启动当场一次全报；变异品质的那一堆画变异那一张。

## 来源

- PRD：[`spec/prd-items-in-bag.md`](../prd-items-in-bag.md) 的 `US-009`。

## 依赖

- `GP-157`：物品定义与有无品质那一格。
- `GP-158`：作物那几样物品要先在册。

## 验收标准

- [ ] 可核对：每个物品一份图标资源；有品质的另配变异那一张，或明写同原图。作物那几样每种两份：种子那份框素材表（代码仓 `assets/self-drawn/crops/crop1.png`）第 7 列，收获物那份框第 8 列、变异那一张框第 9 列。**资源的样子与配法已就位，那几份由作者配**：资源是代码仓 `src/UI/ItemIcon.cs`，农场的 `Item Icons` 一组接上；配法在[东西能拿在手上 · 第三步：配物品图标](../../reference/godot/东西能拿在手上.md)。
- [x] 可测试：在册物品缺图标、有品质却没写变异那一张、两份图标配给同一个物品，载入时一次全报，一行一处；判在规则层，引擎层只交出每一格配没配。判在代码仓 `rules/Economy/ItemIconCheck.cs`，用例在 `tests/Economy/ItemIconCheckTests.cs`。
- [ ] 可观察：随身栏与背包页的格子里画物品的图标；品质是变异的那一堆画变异那一张。**随身栏已接上**，背包页随 `UI-65`；看得见要作者配完图之后实机。
- [x] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。

## 实现笔记

### 设计决策

- **一个物品一份 `ItemIcon`**：物品标识、图标、变异那一张与「同原图」那个勾。资源上写它是哪个物品，物品定义上没有这一格，所以缺不缺、重不重只能从那一组资源里读出来。农场的 `Item Icons` 一组接上，与 `Crop Arts` 同一个做法，农场启动时核。
- **核对一次全报，一行一处。** 除了需求点名的三种，空着的一项、配给不在册物品的一份、图标那一张空着、变异那一张配了又勾了同原图、无品质的东西配了变异那一格，也各报一行。在册却没有图标的物品一种一行：一份都还没配时，这几行就是要配的那张清单。
- **「同原图」是一个勾，不是把图标那一张再拖一遍。** 拖一遍与复制出来忘了改看起来一模一样，勾了才说得出是作者定的。
- **画哪一张只看品质是不是变异那一档**，那一档的标识与收获给的是同一个（代码仓 `rules/Economy/Harvesting.cs`），其余各档一律画图标那一张。
- **随身栏那一格带上那一堆的品质**（代码仓 `rules/UI/CarrySlots.cs`），取图标时交物品标识与品质。在册的每一样都核过有图标，所以取图标的办法不再返回空，缺了就是接线错了。
- **核对放在规则层的经营那一侧**，与作物素材的核对同一处：规则层的界面那一侧不依赖物品与背包。

### 偏离

无。

### 权衡

- **农场在全部物品图标配完之前起不来**，与作物素材一样。缺图在格子里的样子是空着，而玩家分不清「这一格没东西」和「这一格有东西但没图」；画成空框不报错，代价是错只在画到那一格时才看得出来。所以配一处起一处不行，作者要一次配完那一组。
- **随身栏那一格的品质是可以不填的一格**（不填是无品质）。往随身栏里装背包那几格的只有农场那一处，它填了；漏填的后果是变异那一堆画成原图。

### 待确认

无。
