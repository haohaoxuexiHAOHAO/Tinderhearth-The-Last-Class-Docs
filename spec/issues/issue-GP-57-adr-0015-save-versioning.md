# GP-57：`ADR-0015` 的落地反证

## 目标

让「以后每加一个字段，玩家手上的旧存档怎么办」只有一个答案，而且那个答案与 [ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md) 那条「代码不留能用的默认值」为什么可以不同源，有一段写下来的理由。

## 来源

- PRD：[`prd-save-settlement-and-stats-bus.md`](../prd-save-settlement-and-stats-bus.md) 的 `US-006`
- 起因：[玩法定位 · DLC 就是官方 mod](../../canon/gameplay/玩法定位.md)写明**追加内容不得破坏旧存档**，而 [ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md) 照字面读会禁掉「缺字段补默认值」。不裁定的后果是每个分片的持有者各自决定自己那一格缺了怎么办 —— 于是「旧存档能不能打开」取决于这一版动了哪个分片，**而那件事没有任何东西判得出来**。

## 依赖

`GP-54`（[`存档系统`](../../design/存档系统.md)：分片声明里那份「存档默认值」是本决定的落点）。

## 验收标准

### 为什么它够得上一份 ADR

- [x] 门槛是「影响多个系统且难以撤销」，**两条都要写明成立**：它约束**每一个分片**；而存档格式一旦随版本发行出去，玩家硬盘上那些文件就是既成事实，**改口径改不动它们**。

### 决定与理由

- [x] 按 [ADR 模板](../../templates/ADR.md)写全（背景／候选／决策／后果），编号 `ADR-0015`，接进 [ADR 索引](../../decisions/README.md)。
- [x] **决定写清四件事**：格式、版本号放在哪一层、缺字段怎么办、多出来的字段怎么办。
- [x] **与 [ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md) 的张力写成一段理由、不是一条例外**，而那段理由**落在「谁修得了」上** —— 场景缺配置是作者当场能改的失误，旧存档在玩家硬盘上没有人修得了。那张对照表要把这两件事的每一栏都摊开。
- [x] **同一处写死那条口径的边界**：默认值只对版本比当前旧的存档生效，**同版本缺字段一律报错**。写明这一半是承重项 —— 只留另一半的话，本决定就退化成被否决的那个候选。
- [x] **比当前新的版本显式拒绝**，不做尽力而为的读取。
- [x] **多出来的字段丢弃，而丢弃只在字段粒度成立**：整个不认识的分片不许丢，走[`存档系统` · 缺 mod 的内容：隔离，不删除](../../design/存档系统.md)那份清单。
- [x] **被放弃的方案与各自的代价都写出来**：缺字段一律报错、一律补默认值、每分片各带一个版本号、多出来的字段原样保留。

### 后果与验证

- [x] 「后果」四栏都填（正面影响、代价与风险、落地要求、验证方法），**代价那一栏要写明降级彻底不支持**。
- [x] **落地要求里写明那份存档默认值必须与「这个分片从来没存过」时的初始值同一处**，并写明两处会分叉、而分叉的表现是「新开档与旧档载入结果不一样」。
- [x] **验证方法写成四条用例加一条把承重项钉住的反证**（把「同版本缺字段」那条改成补默认值之后，那个用例必须失败）。
- [x] **落地时的用例数与跑法不写在 ADR 里**，写在本条 —— 历史数字会静默过期。
- [x] 索引那一行一句话说得出这份决定了什么。
- [x] `python tools/check_docs.py` 0 项必须修复（合并之后才成立）。

## 实现笔记

### 设计决策

- **模糊点**：存档缺字段报错还是补默认值。
- **选择**：按版本分两条 —— 旧版本补分片声明的默认值，同版本报错，更新的版本显式拒绝。
- **理由**：一律报错直接违反「追加内容不得破坏旧存档」；一律补默认值正是 `ADR-0009` 要挡的兜底。分两条之所以成立，是因为**看版本就分得出「版本演进」与「写坏了」这两件事** —— 而这一条判得到，不靠语感。

- **模糊点**：格式与版本号的数量。
- **选择**：明文，全存档一个版本号。
- **理由**：存档缺陷几乎全是「某个值不对」或「某块没读回来」，那两种在明文下是看一眼的事；而[`日记系统`](../../design/日记系统.md)那条判据要的是**按分片量出来的体积**，二进制下分摊不到分片。版本号选一个是因为「规则不外置」保证 mod 加不了分片，所以每分片一个版本的那份灵活性没有对应的需求，而它的代价（版本组合是乘法）落在测试上。

### 偏离

- **方案怎么说**：PRD 的 `US-006` 把「要不要立 ADR」也当成一个问题。
- **实际怎么做**：立了，而且在 ADR 自己的「背景」里把「为什么够得上一份 ADR」写成一段。
- **为什么**：门槛判断本身是这份决定的一部分 —— 不写下来的话，下一次有人会拿一个单系统内的取舍照它的形状再开一份 ADR。

- **方案怎么说**：`check_docs` 0 FAIL。
- **实际怎么做**：本条单独跑不绿（它指[`存档系统`](../../design/存档系统.md)，而那一份也指它）。**那条 0 FAIL 是合并之后才成立的。**
- **为什么**：两份以上互相引用的东西不可能各自独立跑绿。

### 权衡

**「不立 ADR，把口径写进[`存档系统`](../../design/存档系统.md)的理由与取舍」考虑过。** 没选：它与 `ADR-0009` **正面相撞**，而 ADR 之间的关系只有 ADR 说得清 —— 写在系统文档里会让「`ADR-0009` 是不是被一份系统文档开了例外」这个问题无处回答。这也是本批与上一批的分别：上一批那三个候选都是单系统内的取舍或一处措辞精确化，本条不是。

**「给 `ADR-0009` 加一条例外条款」考虑过**（在那一份里写「存档除外」）。没选：已接受的 ADR 不得用今天的理由改写当时的背景（[WORKFLOW §4](../../WORKFLOW.md)）；而且「例外」的写法会让那条纪律看起来可以被逐个场景谈判，而本决定要的恰好相反 —— 它是**另一条判得到的规则**，不是一个豁免。

**「校验和或签名」考虑过**（防手改存档）。没选：单机买断制，改自己的存档是玩家的事；而「写一半断电」这个真实风险由原子替换挡住了，加校验和只会在玩家手改之后把存档变成读不出来的。

### 待确认

- **旧版本的迁移代码放哪**：本决定只定口径（谁补、谁报错、谁拒绝），没定「第 N 版到第 N+1 版那段转换写在哪」。等真的有第二版存档时再答，**而那时要答的是形状不是口径**。
- **「同版本缺字段报错」在发行之后会不会变成一条崩档路径**（例如玩家手改坏了）。它现在是刻意的；如果实测发现玩家手改很常见，那时要重看是不是该把它降成「拒绝载入这一位存档」而不是报错 —— **拒绝与报错是两件事，本决定现在只说了后者。**
