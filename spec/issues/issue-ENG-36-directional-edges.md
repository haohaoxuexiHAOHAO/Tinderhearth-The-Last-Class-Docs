# ENG-36：双网格的规范边按方向分别声明

## 目标

一套双网格素材的四个方向（A 在上、A 在下、A 在左、A 在右）可以各画各的交界，检查照样逐像素判得了，外圈模板照方向各出一圈；没声明方向的套照旧四个方向共用一串。

## 来源

- PRD：[`spec/prd-shore-stone-wall.md`](../prd-shore-stone-wall.md) 的 `US-001`。
- 起因是实测：交界的影子绕着草一圈、四个方向一样粗，与[场景绘制约定 · 交接处那些光影归谁](../../production/场景绘制约定.md)要求的「暗带只画在岸在上方的那几张上」对不上。

## 依赖

无。

## 验收标准

- [x] 可核对：代码仓 `tools/check_dualgrid.py` 里一套素材可以给四个方向各声明一串交界像素；没声明方向的套，四个方向照旧共用一串。
- [x] 可核对：`python tools/check_dualgrid.py --emit-ring <目录>` 照新的声明出外圈模板，四个方向各是自己那一串。
- [x] 可核对：现有三套不改声明，代码仓 `python tools/verify.py` 里双网格那一步照旧通过。
- [x] 可测试：一张图块的某条边与它那个方向的规范边差一个像素时，检查报出是哪一张、哪条边、哪个方向。

## 实现笔记

### 设计决策

- **两种写法二选一**：`shade_a` 与 `shade_b` 照旧是四个方向共用的那一对；新加的 `dirs` 给 `A在上`、`A在下`、`A在左`、`A在右` 各写一对。**写了 `dirs` 就要四个方向都写**，不留「没写的方向用共用那一对」的半截写法 —— 那样漏写一个方向不报错，而那个方向会悄悄照对称的画法判。
- **方向按「一条格边上 A 在 B 的哪一边」说**：竖着的格边从上往下读，上面是 A 就是 `A在上`，也就是 A 那一片在界线北边。报错里不写 A、B，直接写两种地形谁在哪一边（「草在上、浅水在下」），作者不用回头查哪种是 A。
- **过渡像素一律从界线往外数**：第一项紧挨着界线，A 侧与 B 侧同一种排法，作者照着模板数像素时不用分两种读法。现有三套每侧至多一项，排法影响不到它们的规范边，逐项对照的结果在下面。
- **一侧最多 7 项**：格边两端那一个像素是格角、必须是纯地形色，所以半条边里最多 7 个过渡像素。超了在声明那一步就报，不等画出来再报一堆外圈不对。
- **声明本身写错时先报、不往下判**：规范边算不出来，拿错的规范边去比素材只会报一堆假的错。
- **报错多写差在第几个像素**：「从上往下第 11 个」比「差 1 个像素」好找。

### 偏离

- **方案怎么说**：「可测试」那一格。
- **实际怎么做**：用一次性脚本拿合成出来的一套图跑了一遍，跑完删了，没有进 `verify.py`。
- **为什么**：这个脚本照规矩没有自证入口（文件头那句「本脚本没有自证入口」）；`verify.py` 里那一步判的是仓里真的素材，等 `ART-33` 交图之后它就天天判按方向声明的那一套。

### 权衡

- **每个方向声明一对过渡，不直接写整条 16 像素的规范边**：写整条更自由，但「两端是纯色、界线落在正中」就要靠人数对；照现在的形状，规范边永远是「纯色 + 过渡 + 过渡 + 纯色」，8:8 由构造保证。

### 待确认

- 按方向声明的那一套要等 `ART-33` 交图才真正用上：新图与 `grass-shallow.png` 那一项改成 `dirs`，放进代码仓同一次提交。
- 北岸那一张里，墙面、水线与倒影要一起装进水那半格的 7 个像素以内。
