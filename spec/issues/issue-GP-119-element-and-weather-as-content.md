# GP-119：元素与天气改成加一种只要多一条数据

## 目标

加一个元素或一种恶劣天气不用改代码，也不用回正典改一份名字清单。

## 来源

- PRD：[`prd-extensible-lists`](../prd-extensible-lists.md) 的 `US-002`
- 判据：[ADR-0025](../../decisions/ADR-0025-取值集的家由加一个的代价决定.md) —— 这两格都不用写代码，所以归内容型

## 依赖

无。[ADR-0025](../../decisions/ADR-0025-取值集的家由加一个的代价决定.md) 是它的判据来源，状态查[待办台账](./README.md)。

## 验收标准

### 元素

- [ ] [`技能系统` · 一个战斗技能要声明的字段](../../design/技能系统.md)的元素那一格不再列定长取值，改成指一份外置声明
- [ ] 那份声明的形状写明：一个元素声明它施加哪一条状态，缺声明载入报错
- [ ] [`伤害系统`](../../design/伤害系统.md)那处「元素到状态的映射是固定的」改成指同一份声明，不再是一段说不出家在哪的散文
- [ ] 正典那两行（元素、异常状态）改成只写起步量与选取判据，不当封闭清单
- [ ] **那条推论不动**：异常状态的条数仍然由元素的条数推出来，正典那一行照旧不自己写一个数
- [ ] 可测试：外置数据里加一个正典没点名的元素，载入成功且代码零改动
- [ ] 可测试：一个元素缺「它施加哪条状态」时载入被拒，并说清是哪一个

### 天气

- [ ] [`天气系统`](../../design/天气系统.md)那句「本页不添新的一种」改掉 —— 它现在的意思是「清单不在本页」，而写法读起来像「不许加」
- [ ] 正典那一行改成只写起步量与选取判据
- [ ] **修饰组那条边界一个字不动**：一种天气只许引用[`成长系统`](../../design/成长系统.md)派生表里已有的量。加一种天气是填格，不是往战斗里加一条新轴
- [ ] 可测试：外置数据里加一种正典没点名的天气，载入成功且代码零改动
- [ ] 可测试：一种天气的修饰组引用了派生表里没有的量时载入被拒

### 收口

- [ ] 两处的归类按 [ADR-0025](../../decisions/ADR-0025-取值集的家由加一个的代价决定.md) 显式写在各自那份系统文档里
- [ ] 按词搜两个仓加 `.kiro`，旧的定长说法零残留
- [ ] `python tools/check_docs.py` 0 FAIL
