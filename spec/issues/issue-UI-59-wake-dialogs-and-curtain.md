# UI-59：醒来的两个弹窗与转场遮罩

## 目标

睡下时淡出、结算完淡入，淡入播完弹简版摘要；存档没写上时弹「这一天没有推进」；这一段里第二次推进被拒、玩家输入不起作用、世界不暂停；完整明细在手环那一页落地之前打在输出面板上。

## 来源

- PRD：[`spec/prd-sleep-advances-day.md`](../prd-sleep-advances-day.md) 的 `US-007`、`US-003` 第四、五格，`FR-16`、`FR-17`、`FR-39`、`FR-40`、`FR-42` 到 `FR-44`。
- 两个弹窗各答什么问题：[`界面系统` · 弹窗那一层：结算摘要与二次确认](../../design/界面系统.md)，以及[`界面系统` · 主菜单那一侧：读档位列表、更新公告、设置](../../design/界面系统.md)里「存档写入失败」那一段。

## 依赖

- `GP-154`：床与 `N` 是触发这一段的两处。

## 实现笔记

### 设计决策

- **模糊点**：作者摆的弹窗怎么进导航栈。
- **选择**：界面根认一种新的界面节点（代码仓 `src/UI/IPlacedUI.cs` 里的 `IPlacedSurface`）：挪它过去时一并登记、先藏起来，之后由界面根开关。
- **理由**：代码建的界面走的那条登记路自己挂节点，作者摆的那一块已经有父节点了。另开一条显隐路的话，窗自己与界面根都设显隐，谁后设谁说了算，而那不报错。

- **模糊点**：睡下到醒来那一段由谁走。
- **选择**：作者摆一个节点挂 `src/World/Farm/SleepPresentation.cs`，接上遮罩、两个窗、界面根与输入门面，它在启动时把自己登记到那片地上；推进一天的入口仍在那片地上。没摆它的农场按 `N` 照样推进一天，结果只打在输出面板上；摆了床却没有它，启动之后当场报错。
- **理由**：[作物素材表那份的端到端](./issue-GP-147-crop-sheet-e2e.md)那份实机清单搭出来的农场没有床、也没有弹窗；让那片地必须接这一套的话，那份清单在摆床之前就跑不起来。床是睡的入口，所以判据是「有床就必须有这一套」。

- **模糊点**：转场那一段的输入怎么关。
- **选择**：输入门面上加一道闸，按关闸的一方记；关着时按着、刚按下、刚松开与移动方向全读不到。`N` 与 `B` 不经门面，由农场节点问那一段走完没有。
- **理由**：转场时世界不暂停，玩法节点照跑，而这一段不许碰暂停，所以只能在门面上挡。按一方记是为了将来演出也关闸时，先办完的一方一打开，另一方那一段不会漏进输入。

- **模糊点**：那一段什么时候交回。
- **选择**：淡入播完、弹窗弹出那一刻；之后由暂停接手。
- **理由**：窗一开世界就停，玩法节点不跑，按什么都推不动一天。等窗关掉再交回的话，界面根得多一个「关掉了」的通知，而那条通知只为这一处。

- **模糊点**：关窗那一下会不会落进世界。
- **选择**：窗上那个按钮必须松开才算按下（引擎默认就是这样），启动时验；返回键关窗由界面根收。
- **理由**：交互键在键鼠上是鼠标左键。按下就关窗的话，窗一关世界恢复，同一下按键在这一帧还算刚按下，站在床边会紧接着又睡一次。

- **模糊点**：原因那一句要不要先给一句中文。
- **选择**：要。原因由写档那一处给（代码仓 `src/Platform/SaveStore.cs`）：没有写入权限那一类先写一句中文、再跟系统原话，别的先写「写不进去」、再跟原话；路径不写进原因，窗与输出面板各自另起一行写它。
- **理由**：原话是英文，只给它玩家读不懂；只给中文的话，少见的那几种又说不清。这一句是诊断文字，与代码里的报错写在同一处、不进文本表；窗上固定的那几句进文本表。没有写入权限那一类是实测过的：存档文件设成只读时抛的正是它。

- **模糊点**：停在别的步时那个窗怎么说。
- **选择**：第一句写「结算停在「步名」，这一天没有推进」，不写存档路径。
- **理由**：那时存档根本还没写，说「存档没写上」是错话；第一句照样先说没有推进。

- **模糊点**：两个窗的字体从哪来。
- **选择**：醒来那一套接素材资源，装好像素主题挂到两个窗上（代码仓 `src/World/Farm/SleepPresentation.cs` 的 `Art` 那一格）。
- **理由**：像素主题由代码按素材资源组装，主场景里由启动那一处装；农场不经过主场景，不在这里装的话，窗上的字退回引擎默认字体，而那不报错。挂到窗上与主场景给手环挂主题是同一个做法。

- **模糊点**：字放不下怎么办。
- **选择**：分页。一页几行是正文那一块在检查器里的 Max Lines Visible，作者定；按钮上的字跟着换成「下一页」或「知道了」。
- **理由**：[文字与文本框 · 六、字放不下：对话框分页，别处按整行滚](../../reference/godot/文字与文本框.md)给对话框定的是分页。按钮换字就让玩家看得出后面还有没有，不必再画一张小图。

### 偏离

- **方案怎么说**：只做两个窗、遮罩与输入那道闸。
- **实际怎么做**：读文本表的那一段从主场景挪进代码仓 `src/Platform/ContentBootstrap.cs`，农场与主场景共用；作物名字的键加了一个按标识拼的读口；读档与推进那两行输出改成照文本表写日期。设计仓[`每日结算系统` · 下游同步](../../design/每日结算系统.md)里「代码一处都没有」那一句改成指向现在的文件，[界面控件](../../reference/godot/界面控件.md)补了作者摆的弹窗怎么进导航栈。
- **为什么**：在编辑器里单独跑农场时没有主场景，文本表只有主场景读的话，农场里的窗全是缺文本的占位。那两处文档说的与代码已经对不上。

### 权衡

- **返回键直接关窗**：后面还有页时按返回键，剩下几页就不看了。返回键的意思本来就是「不看了」。
- **遮罩那两段播不完时输入会一直关着**：不存在、循环与长度为零的，以及播放器关着、速度不大于零或只能手动推的，启动时就报；那一段里哪一下抛了，先撤掉遮罩、交回输入，再照常抛出去，不然报错那一条被盖在下面，看起来像卡死。
- **引擎那一半没有自动化测试**：节点接线、遮罩播放与窗的显隐只能实机看，串在 `GP-155` 的清单里。规则那一半（第二次推进被拒、门面那道闸、窗里写什么）都有用例。
