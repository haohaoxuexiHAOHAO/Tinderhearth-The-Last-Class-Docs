# DOC-120：三份文档清掉代码字面量、批次名与自计数

## 目标

让这三份文档说的话与它们自己开头那句承诺一致 —— 读的人不必判断哪一句才算数。

## 来源

PRD：[`spec/prd-system-doc-completeness.md`](../prd-system-doc-completeness.md) 的 `US-004`。

**要清的是这几样：**

- **代码字面量与它们的取值**，在[`角色动作状态系统`](../../design/角色动作状态系统.md)的动作叠加层那一节 —— 而那份文档开头写着全部帧数与数值归[数值模型](../../design/数值模型.md)、本页一个都不定。[SYSTEM 模板 · 结构](../../templates/SYSTEM.md)也写着写行为、不写代码。
- **过程叙述**，同一处那句括号里的接线待办 —— 它是待办不是事实。
- **批次名**，出现在[`伤害系统`](../../design/伤害系统.md)、[`状态效果系统`](../../design/状态效果系统.md)与[`角色动作状态系统`](../../design/角色动作状态系统.md)三份的正文里。批次是状态，家在[待办台账](./README.md)。
- **自计数**，[`状态效果系统` · 载体的字段](../../design/状态效果系统.md)那份清单的条数在验收与完成边界两处被复述，而清单最后一条自己说它是两个字段 —— 实现的人数出来与复述的数不一致。**检查器那条自计数守卫只认「行尾冒号 ＋ 紧跟清单」那一种形状，所以这一处它判不到。**

## 依赖

无。与 `DOC-118`、`DOC-119` 动的是同几份文档，但改的是不同段落，先后都行。

## 验收标准

- [x] 那两个代码字面量与它们的取值从正文消失，而对应的行为照旧写得出来。
- [x] 括号里那句接线待办从正文消失；真有剩余动作就在[待办台账](./README.md)记一条。
- [x] 三份文档里搜不到那两个批次名；要指那批已实现的行为时**按行为名指，不按批次名指**。
- [x] 那处自计数**删掉而不是改对数字** —— 按 `DOC-68` 立下的判据，改对数字撑不到下次加项。
- [x] 三份文档的任何设计结论都没变（拿 `git diff` 的删除行数作证）。
- [x] `python tools/check_docs.py` 0 FAIL。

## 实现笔记

### 设计决策

- **模糊点**：删掉那个字面量之后，「重击现在是单招」这条行为还要不要写。
- **选择**：写，但只写行为（「重击是单招，所以命中确认对它现在没有可见效果」），不写那个常量的名字与取值；同一句末尾补一条「帧数与击退距离归[数值模型](../../design/数值模型.md)与 `GP-6`」。
- **理由**：那句话的价值是「将来给重击加连段时同一条规则即生效」，而这与常量叫什么无关。带着常量名的版本会让读者以为文档在规定代码，而它开头刚写过自己一个数都不定。
- **另一处**：两个批次名指的都是「已经实现并验过的那批行为」，所以按行为名改写（「已实现的那批命中反馈」「受击只有地面那一种」「有真敌人会横扫时」），而不是换成一个编号 —— 换编号只是把状态搬了个家。

### 偏离

**有一处，写明理由：** 条目原先写「三份文档」，实际动了**四份** —— [`战斗AI系统`](../../design/战斗AI系统.md)的「上游约束」里有同一个自计数的第四处副本（它复述的正是[`状态效果系统` · 载体的字段](../../design/状态效果系统.md)那份清单的条数）。

- **为什么一起改而不是另立一条**：它是同一个缺陷的同一个实例，而不是一件新事 —— 本条的功能需求写的就是「那处自计数必须删除」。更要紧的是，把计数从它的家去掉却留一份副本在别处，正是这一轮要修的那种漂移。
- **改的是一个词**（「六个字段」→「的字段」），那份文档别的地方一个字没动。

### 权衡

考虑过把删掉的那些代码细节搬进代码注释。**没选**：判定框按段分开、轻击不击退这些规则在文档里已经写全了行为，而取值本来就在代码里 —— 再抄一遍注释是第三个家。

### 待确认

**无。** 那句接线待办不留残余动作：它说的是「把空中照搬地面连段改成单招」，而正文已经写明空中攻击是单一招式，所以那是一句已经被结论覆盖的过程话，不需要新编号。
