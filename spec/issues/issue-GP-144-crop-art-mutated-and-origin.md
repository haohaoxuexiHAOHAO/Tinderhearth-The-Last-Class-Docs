# GP-144：作物素材多一格变异成熟，地里按那一位换图、按接地那一行排前后

## 目标

每种作物配一张变异成熟图，漏配一张载入就说清是哪一种；地里一眼看得出哪一株变了，人走到作物后面时被它挡住。

## 来源

- PRD：[`spec/prd-crop-sheet.md`](../prd-crop-sheet.md) 的 `US-001`、`US-005`（`FR-1`、`FR-10`、`FR-11`）。
- 一种作物交几张图在[场景绘制约定 · 作物按它声明的阶段数交付](../../production/场景绘制约定.md)，本条不复述。

## 依赖

- `GP-134`：换图读的是那一格的变异标记。素材那一格与精灵原点不等它，先做，作者配素材时就照新的那一格配。

## 验收标准

- [x] 可核对：作物素材在检查器里多出「变异成熟」一格，排在枯死那一格前面。那一格叫 `Mutated Ripe Texture`，代码仓 `src/World/Farm/CropArt.cs`。
- [x] 可核对：那一格空着时，载入报错写明作物标识与缺的是变异成熟那一张。
- [x] 可核对：作物精灵的原点落在格子底边中点、图往上画，与角色的脚底原点同一个口径。代码仓 `src/World/Farm/FarmField.cs` 的 `CropOriginIn` 与 `DrawnUpFromOrigin`。
- [x] 可核对：待收且变异的那一格显示变异成熟那张，其余照旧。代码仓 `src/World/Farm/FarmField.cs` 的 `TextureFor`，读的是 `GP-134` 给地块加的那一位。
- [ ] **作者实机确认**：故意空一种作物的那一格跑一次，报错说得清缺谁。
- [ ] **作者实机确认**：把基础值临时调高，一片地里看得到变与没变两种成熟；人站进一株作物那一格的上半截时被它挡住。

## 实现笔记

### 设计决策

- **模糊点**：变异成熟那张放进阶段那一组的末尾，还是单独一格。
- **选择**：单独一格，在检查器里排在枯死那一格前面。
- **理由**：它不是生长阶段，是待收那一株变了的样子。混进阶段那一组就要按下标挑，挑错了不报错，表现只是显示成了别的那一张 —— 与枯死那一张不进那一组是同一个理由。

- **模糊点**：原点怎么挪到底边中点。
- **选择**：节点位置放在格子底边中点，关掉居中、用 `Offset` 把图往上画、横向居中，两样都取整。
- **理由**：Y 排序比的是节点位置、不看图画在哪，所以挪的必须是节点位置。不用「居中再往上挪半张」：图高是奇数时差半像素。农场里主角那张图也是这个写法（关掉居中、`offset` 往上），所以两边比的是同一行。

- **模糊点**：素材配错时，载入报第一处就停，还是一次全报。
- **选择**：一次全报，一行一处。判在规则层（代码仓 `rules/Economy/CropArtCheck.cs`），与界面素材那一份（`rules/UI/UIArtCheck.cs`）同一个做法：引擎层只交出每一份素材每一格配没配，再把全部问题拼成一条报错。两份素材配给同一种作物单独报一条，点名是哪两项。
- **理由**：全部作物一起配的时候，报第一处就停要一处一处改、一次一次重跑。配给同一种那一条挡的是照指南「复制一份、改行号」时最容易漏的那一步：原先后一份会悄悄顶掉前一份，报出来的是另一种作物「有定义但没有素材」，要绕一圈才找得到原因。
