# UI-36：D-pad 四个方向装不下三条队友指令加两个挪位键

## 目标

让 D-pad 那四个方向各有一个明确的主人，且没有两个动作抢同一个方向。

## 来源

**超边界记账**，在 `UI-34`（随身栏）落地时撞到。D-pad 现在有三份互相重叠的主张：

- **队友三指令**（集火／撤退／待命）：代码仓 `rules/Ui/InputBindings.cs` 移动那一段的注释写着
  「D-pad 要留给正典的队友三指令」，[那份键位提案](../../design/proposals/键鼠技能位挪到右手.md)
  也这么写。**它现在一个动作名都没有、一条绑定都没有** —— 结构在
  [`战斗AI系统`](../../design/战斗AI系统.md)，落地归 `GP-36`。
- **随身栏挪选中位**：`UI-34` 已经占了**左右两向**（`rules/Ui/InputBindings.cs` 里的
  `carry_prev`／`carry_next`）。
- **一件消耗品的快速使用键**：[`背包系统` · 关卡里：翻包暂停，用道具不暂停](../../design/背包系统.md)
  把「D-pad 第四向空着」记成一条后手。**这一条大概已经被 `UI-34` 顶掉了** ——
  随身栏就是那个快速使用入口，而且它给六格不是一件；要不要正式作废它由本条判。

**三加二大于四**，所以队友指令落地时必须有人让一步。

## 依赖

不依赖谁，但**它要在 `GP-36` 之前答完** —— 那一批一动手就会撞上。

## 验收标准

- [ ] D-pad 四个方向各写明归谁，且**加起来不超过四个**
- [ ] 让步的那一方写明它换到哪里去了、代价是什么
- [ ] 若结论是「同一个方向在关卡与经营场景里各干一件事」，那就要先答**按场景分动作集**这件事
      本身 —— 现在没有这一层，两个动作绑同一个物理位会**同时触发**
- [ ] `rules/Ui/InputBindings.cs` 那条「D-pad 留给队友三指令」的注释跟着改（它现在与实际不符）
- [ ] [`背包系统`](../../design/背包系统.md)那条「第四向空着」的后手明确留或废
- [ ] 代码仓 `python tools/verify.py` 五步全绿
