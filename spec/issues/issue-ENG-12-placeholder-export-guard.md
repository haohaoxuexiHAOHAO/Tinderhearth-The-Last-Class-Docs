# ENG-12：发行包不得含占位素材的导出守卫

## 目标

发行包里出现登记为占位的素材时导出验收判失败，使"开发期随便用、发行时只用自己的素材与 CC0"这条约束有执行体。

## 来源

- 作者 2026-08-30 定的工作方式与前提：代码仓是私有单人仓库，私有持有不构成再分发；**真正的分发行为是发行包**。
- 因此守卫落在导出而不是入仓。落点已存在：`verify.py` 的导出那一步本来就解 `.pck` 逐条看清单（`ENG-3`，见[踩坑记录 33](../../reference/踩坑记录.md)）。
- PRD：[`spec/prd-ui-framework.md`](../prd-ui-framework.md) 第 8 节

## 依赖

`ART-4`（要有登记表才知道哪些是占位件）。

## 验收标准

**分两档，否则这条守卫会从第一天起一直红。** 2026-08-30 撞出来的：`ART-4` 落地后包内条目从 15 涨到 63，占位件本来就该在开发期的包里。如果"包里有占位件就判失败"，门禁会红到所有素材替换完为止 —— 那种守卫的实际后果是大家学会绕过它，连真失败一起绕。

日常导出（默认）：

- [ ] **未登记的素材判失败**，报出是哪几个文件 —— 漏登记等于绕过守卫
- [ ] 登记表里标了"不得进发行包"的素材判失败（包是可分发物，开发期也一样）
- [ ] 判据是**"许可证明确允许作为游戏的一部分分发"，不是"必须 CC0"**。2026-08-30 撞出来的：作者下载的侍武士素材允许商业使用与随游戏分发，只禁止把素材本身转售、再分发或做成 NFT —— 按 CC0 一刀切会误杀它。所以登记表记的是**许可证依据原文**加一个判定，不是一个布尔值
- [ ] 占位件**不判失败**，但报出剩余数量（"还有 N 个占位件待替换"），让进度可见
- [ ] 自报覆盖量：包内素材总数、登记命中数、未登记数、占位件数

发行导出（`--release` 或等价开关）：

- [ ] 包内出现任何占位件即判失败
- [ ] 包内出现任何非"自有或 CC0"的素材即判失败

共同：

- [ ] 检查接在 `verify.py` 已有的解包清单那一步里，不新增一条并行门禁
- [ ] 自证：往包里塞一个未登记素材确认拦得住；`--release` 下塞一个占位件确认拦得住；还原后复验通过
- [ ] 改了 `verify.py` 就跑 `python tools/selfcheck_verify.py`
