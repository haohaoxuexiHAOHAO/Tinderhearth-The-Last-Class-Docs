# UI-14：键鼠战斗键位重排

## 目标

让六个技能位落在按得到的键上 —— 现在它们在数字键 1–6，而左手按住 `WASD` 时那一排要抬手才够得到。

## 来源

- 在 [`spec/prd-growth-skill-damage.md`](../prd-growth-skill-damage.md) 那一批的讨论中定的边界，`US-007` 记账、`GP-34` 删掉正典里那句具体映射。
- 现状是代码仓 `rules/Ui/InputBindings.cs` 的绑定表：键鼠侧 `Digit1`–`Digit6` 对应六个技能位，轻重攻击 `J`／`K`，防御 `Q`、闪避 `E`、交互 `F`、冲刺 `Shift`、跳跃 `Space`。

## 依赖

`GP-34`（正典里那句「6 个技能位在键鼠上是数字键」要先删掉，否则正典与本条给的是两套映射）。

## 验收标准

- [ ] 先出一份提案（`/to-design`，落 `design/proposals/`），摆出被放弃的布局与各自的代价 —— 这是一个受硬约束的布局问题，不是一条一句话能定的裁定。
- [ ] 提案必须处理这几条已知约束：
  - **技能位挪到 `J`／`K` 周边**（作者已定方向，例如 `U`／`I`／`L` 这一带）。
  - **手柄侧不动**：`LT`／`RT` 加面键的组合已经铺满六个位，四个面键、两个肩键、左摇杆按压与 D-pad 也各有归属。
  - **左手已经满了**：`WASD` 占无名指、中指与食指，`Shift` 占小指，`Space` 占拇指，所以 `Q`／`E`／`F` 本来就是抬手去按。提案要说清哪几个键留在左手、哪几个挪到右手。
  - **鼠标接攻击已被排掉**：右手一上鼠标就按不到任何技能键，所以 `rules/Ui/InputBindings.cs` 里那条「侧视战斗没有瞄准、不用鼠标」的裁定继续成立。
  - **防御即定身**（`GP-34`），所以防御键与移动键从不同时按住 —— 这条放宽了解空间，提案要利用它。
- [ ] 结论落代码仓 `rules/Ui/InputActions.cs` 与 `rules/Ui/InputBindings.cs`，绑定表仍是唯一权威源（不往 `project.godot` 的 `[input]` 段写第二份）。
- [ ] `rules/Ui/InputBindings.cs` 的豁免登记跟着改 —— 故意不绑某个设备族的都要留理由，否则「忘了绑」与「故意不绑」长得一样。
- [ ] 代码仓 `python tools/verify.py` 五步全绿。
- [ ] **作者实机按一遍**：连段时轻重攻击与技能位够不够得着、防御与闪避会不会跟移动抢手指。按键绑错现在没有守卫（原 `check_input_map.py` 随 [ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md) 删除），只能靠按。
