# ENG-38：显示层按世界坐标铺纹理

## 目标

显示层里每种天然地形的主色，按世界坐标换成那种地形的纹理图上同一位置的像素；一项都没声明时地面照现在的样子画。

## 来源

- PRD：[`spec/prd-terrain-texture.md`](../prd-terrain-texture.md) 的 `US-001` 与 `US-002`（接线那一半）。

## 依赖

- `ENG-37`：配置对不对由那一条的判定说；这一条只把引擎里读到的东西交过去、把结论报出来。

## 实现笔记

### 设计决策

- **材质由代码挂在显示层上，带一条元数据认出是自己挂的**：声明了纹理而显示层上已经挂着别的材质时报错，不覆盖作者的东西；一项都没声明时只摘自己挂的那一个。
- **编辑器存场景前摘下材质、存完挂回去**：材质是照声明现算的，存进场景文件只会多一段跟着声明变的着色器代码。进树时会重挂，所以按 `F6` 跑起来照样有。
- **着色器按要铺几种现写**，每种一个取样器、一个主色，不用取样器数组：GLSL ES 3.00 只许拿常量下标取样器数组。
- **主色读四角全同那一张左上角那个像素**：`tools/check_dualgrid.py` 保证那一张整张纯色、同一种地形各套同色，所以哪一套先读到都一样。
- **判之前先确认 `Data Terrain Set` 在数据层 TileSet 里存在**，不然读不出有哪几种地形。
- **配错时先摘掉材质再报**：编辑器里只警告，摘掉之后地面回到纯色，配错一眼看得出来。

### 偏离

- **方案怎么说**：PRD「技术考虑」原先写主色每次重画都从双网格图里读。
- **实际怎么做**：进树与点「重画显示层」时读，刷地形的每一笔不重读。
- **为什么**：刷地形不改双网格图，每一笔都重读是白算；换季那一步重着色之后调同一个方法就行。PRD 那一句跟着改了。

### 权衡

无。CPU 预先合成那条路为什么没走，理由在 PRD「技术考虑」。

### 待确认

- **着色器读到的颜色与 PNG 里逐位相同、放大一档不错位**：只有实机看得出来，在 `ENG-39` 的作者实机清单里。下面那趟探针只证明着色器编得过、挂得上。
- **仓里那份农场的数据层还关着 `Enabled`**：运行时数据层的碰撞检查先抛，走不到纹理这一步。照指南第二步「让水挡住人」那一小节改过之后才看得到纹理，而 `ENG-27` 那一趟实机本来就要先改它。
