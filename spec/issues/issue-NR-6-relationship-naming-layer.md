# NR-6：关系的命名层与五档阶梯

## 目标

让关系只有一个量名、一条档位阶梯、一套档名，任意两个角色之间共用它；关系到了哪一步由档名本身说出来。

## 来源

- PRD：[`spec/prd-relationship-system.md`](../prd-relationship-system.md) 的 `US-001`
- 起因是同一件事有三个词：[角色与成长 · 人际与日记](../../canon/gameplay/角色与成长.md)写「师生信任度」与「学生之间的好感度」当成两个量，而[战斗与关卡](../../canon/gameplay/战斗与关卡.md)又把「默契」用作队友 AI 行为档的最高档名。
- **本条原本还包含队友 AI 那一半，已拆给 `GP-37`** —— 那一侧不再只是改名（加了一档、还把基础 AI 从阶梯里搬出来），属玩法结构改动。

## 依赖

无。**本条是其余六条的用词前提** —— `GP-38` 的接口表要用这套词写，先按旧说法写完再回头改是两次工，而只改一半会留下两种说法并存（`DOC-18` 那一批已经吃过这个亏）。

## 验收标准

- [x] [角色与成长 · 人际与日记](../../canon/gameplay/角色与成长.md)写明**只有一套关系机制、一条档位阶梯**，任意两个角色之间共用它；这个量**就叫「关系」**，「信任度」与「好感度」是它的两个旧说法，不再作为量名使用。
- [x] 档位阶梯逐档列出，**五档**：陌生 → 了解 → 熟悉 → 认可 → 信赖。
- [x] 写明**显示刻度是十颗爱心，每档两颗，逐颗连续填充** —— 玩家看得见「这一颗填了一半」，不是攒够了突然多一颗。
- [x] 写明**爱心是刻度、档位是接口**：任何机制分叉一律读档位，**没有任何机制读爱心或填充量**。理由写明 —— 按填充量分叉等于要为每个零点几各配一份内容，而那是配不出来的。
- [x] 写明**为什么这里给填充量、[`活跃失衡系统`](../../design/活跃失衡系统.md)那边只给档位**：那个是全城统计量，露出细粒度会把「帮谁」变成算术；关系是一对一个人的进展，玩家要看得见「在往前走」，那份反馈本身就是这套系统的目的。**不写这条理由会被当成前后矛盾。**
- [x] 写明**最高档在恋爱成立时显示为「托付」** —— 同一档换一个标签，不是第六档。理由写明：阶梯不分对象，所以「这是什么样的关系」只能由档名承载，而恋爱是唯一需要在档名上看得出来的差别。
- [x] 写明**「师生」与「同学」的差别不由档名承担**，而由各自的规则承担 —— 师生那一侧有红线（[人物 · 教师权力、同意与关系红线](../../canon/characters/人物.md)），同学那一侧才有恋爱。理由：做成两套档名等于把同一个刻度维护两遍，而它们的阈值、涨法与读口本来就是同一套。
- [x] 写明**档数是接口的一部分，不是显示细节** —— 改一档就要改小事件、气泡语料与索取结果三套内容；理由与[`活跃失衡系统` · 对外只有档位，没有精确值](../../design/活跃失衡系统.md)同源，本页只引不复述。
- [x] 写明**关系对外只给档位与填充量，不给数字**。
- [x] 「默契」不再出现在关系档位里（阶梯到「信赖」为止）。
- [x] 增长途径、信任度的作用范围与日记那几条**原样保留**，只把量名换掉。
- [x] `python tools/check_docs.py` 0 项必须修复。

## 实现笔记

### 设计决策

- **模糊点**：「爱心是刻度、档位是接口」没说清**档位边界与爱心边界是不是重合** —— 也就是第二颗爱心填满是不是立刻升档，还是档位另有一套阈值。
- **选择**：**重合。** 「每档两颗」就是严格对应，第二颗填满即升档。
- **理由**：两套边界会让玩家看着爱心满了却没升档，而那正是「查不到原因的变化」—— 与[时间与经营 · 精力](../../canon/gameplay/时间与经营.md)那条「上限变化必须有可见的原因」是同一条纪律。这条是可判定的（档位边界与爱心边界一一对应），**该由 `GP-38` 在结构那一节钉成不变式**，本条只在正典把「每档两颗」写死。

另一处：**「陌生」当最低档**意味着新加入的学生从零起步。这与剧情不冲突 —— 主角招他们进来是收人，不是已经认识；正典本来就把关系的增长途径挂在相处上（同队出征、上课、对话），而不是挂在加入上。

### 偏离

- **方案怎么说**：恋爱那一侧的规则（一人一段、资格是角色定义上的字段、主角与灯火不参与）全归 `GP-38`。
- **实际怎么做**：在正典这一节补了一句「**可以恋爱不是全体学生的默认属性**」，并点名[灯火](../../canon/narrative/学生群像.md)是养父女而非师生、不走这条线。资格字段的形状仍归 `GP-38`。
- **为什么**：不补这句，正典「学生之间可以恋爱」会被读成「全体学生都能」，而 `GP-38` 要写的是「灯火不参与」—— 两处当场矛盾。**同名不同物与自相矛盾都是这一批要修的东西，不该自己造一处新的。**

第二处：同一文件[角色与成长 · 战利品归属](../../canon/gameplay/角色与成长.md)里那几处旧词一并改了（付酬不改关系、索取结果由关系档位决定、索取被拒不降低关系）。`DOC-22` 的清单没点 `角色与成长`，因为本条拥有这个文件 —— 但**同一份文件半新半旧比全旧更糟**，读者会以为那是两个不同的量。

### 权衡

考虑过给师生与同学各一套档名（我原先的推荐就是两套）。取一套，因为**「师生」与「同学」的差别不在刻度上，在规则上** —— 师生有红线、同学有恋爱，那些差别各有自己的家；而两套档名会让同一个刻度有两处定义，阈值、涨法与读口全要维护两遍。代价是 NPC 与学生共用同一批档名，玩家在手环里看到的刻度是同一套 —— 但那本来就是事实，它们是同一个量。

考虑过只给档位、不给填充量（照抄[`活跃失衡系统`](../../design/活跃失衡系统.md)那条纪律）。取给填充量，因为**关系只升不降，填充是这套系统唯一的正反馈出口** —— 没有它，玩家做完一件事看不出有没有用。两处纪律不同的理由写进了正典，免得被当成前后不一致。

### 待确认

**一处只能实机看**：16px 图标里画「半颗爱心」是有下限的。按 [`UI-1`](../../archive/spec/UI-1-ui-framework/prd.md)（**历史背景·非依据**）定下的图标档位（16／32），一颗 16px 爱心大概只分得出空、半、满三态，更细的填充看不出来。文档这一侧只承诺「填充量是连续的」，怎么画成像素归作者（[ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md) 的分工）。**本条不判它** —— 挂进来会让这条永远勾不满。
