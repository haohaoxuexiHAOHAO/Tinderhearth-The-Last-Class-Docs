# GP-49：ADR —— 一个战斗片段就是一屏，清干净才能往前

## 目标

让「凭什么一关是一串一屏大小的房间、凭什么必须清干净才能往前」有一处查得到的来历，并写清为什么不选「走到某处才锁住打一场」那种形状。

## 来源

- PRD：[`spec/prd-enemy-ai-and-ally-tiers.md`](../prd-enemy-ai-and-ally-tiers.md) 的 `US-001`
- 起因：本批要接住[`关卡系统` · 关卡系统只持有配额，不持有敌人](../../design/关卡系统.md)交出来的敌人预算，而「一屏装多少」是那个预算的单位；房间模型定下来之后才知道预算、脱战两个条件与队友站位各该多大。
- 它跨四处又难撤销：改[`关卡系统` · 片段之间是转场，不是无缝滚动](../../design/关卡系统.md)那条「三个方向同一条规则」、收窄[战斗与关卡 · 完成标准](../../canon/gameplay/战斗与关卡.md)那条的**理由**、定下战斗中相机不平移、让敌人预算以一屏为单位。有了片段内容之后改回去等于重做全部战斗片段。

## 依赖

无。它是本批其余各条的依据 —— `GP-50` 要按它改正典的理由、`GP-36` 要按它算敌人预算、`DOC-36` 要按它改 [`关卡系统`](../../design/关卡系统.md)。

## 验收标准

- [x] 按 [ADR 模板](../../templates/ADR.md)写，落 `decisions/`，接进 [ADR 索引](../../decisions/README.md)。
- [x] 背景写清它跨了哪几处：[`关卡系统` · 片段之间是转场，不是无缝滚动](../../design/关卡系统.md)现在写着往前、往回与撤离**三个方向同一条规则**；[战斗与关卡 · 完成标准](../../canon/gameplay/战斗与关卡.md)那条「不用清空全部敌人」的理由是「漏掉一两只杂兵会让玩家满地图找」；[战斗与关卡 · 48px 是怎么算出来的](../../canon/gameplay/战斗与关卡.md)那笔几何账是按一屏的宽度算的。
- [x] 决定写成三句：**战斗片段就是恰好一屏**；**当前片段还有活着的敌人时往前的转场被拒，往回与撤离不锁**；**战斗片段内相机不平移**（震动与推镜照旧），非战斗片段可以比一屏长、相机照常跟随。
- [x] 写明**往回与撤离为什么不能锁** —— 打不过的房间要退得出来，而[战斗与关卡 · 失败判定](../../canon/gameplay/战斗与关卡.md)要求玩家能返回入口撤出。
- [x] 候选与被放弃的方案都摆出来，至少含 **arena lock**（战斗片段比一屏宽、走到某处触发一群再锁住）与**软门**（不加门，靠转场读条受击中断天然成立），各写代价。
- [x] arena lock 那条写出两个代价：多一套「走到哪里触发哪一群」的声明；那笔 48px 几何账只覆盖片段的一部分，于是 `ENG-16` 那个「满编挤不挤」没有固定取景可验。
- [x] 软门那条写出它**不保证清干净** —— 跑得过敌人的玩家能连跳几屏，然后在目标片段前面装备与等级都不够。
- [x] 后果那一节写明连带改哪几处：[`关卡系统`](../../design/关卡系统.md)转场那一节、正典完成标准那条的**理由**（结论不变，剩下的意思是「不要求走遍全部分支」）、敌人预算从此以一屏为单位、感知兑现的是一屏之内的分批处理而不是绕开房间。
- [x] 写明它**没有**改的东西：`UI-12` 的相机手感（震动、推镜与演出归还照旧）、非战斗片段的相机跟随、[`关卡系统` · 节奏约束写成形式，值归 `GP-2`](../../design/关卡系统.md)那条战斗片段间隔（它与一屏一清是同一套节奏，不是两条独立约束）。
- [x] 文档里一个玩法数值都没有。**一屏的宽度写链接，不复述数字** —— 它的家在[战斗与关卡 · 48px 是怎么算出来的](../../canon/gameplay/战斗与关卡.md)。
- [x] `python tools/check_docs.py` 0 项必须修复。
