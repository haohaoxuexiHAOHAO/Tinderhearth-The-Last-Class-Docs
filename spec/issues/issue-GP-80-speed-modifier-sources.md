# GP-80：攻速与移速退出属性派生之后，剩下谁能改它们

## 目标

这两个量不再由任何属性派生之后，文档里说得出它们还能被什么改、不能被什么改，以及为什么。

## 来源

- PRD：[`spec/prd-attribute-payoff-rebalance.md`](../prd-attribute-payoff-rebalance.md) 的 `US-004`

## 依赖

`GP-76` —— 这条规则要写在属性分法已经改完的正典旁边，否则读者会同时看到「敏捷给攻速」与「攻速只由天赋和状态改」。

**它与属性分法是两件事**，所以单独一条：这两个量剩下谁能改，不依赖它们原先挂在哪项属性上。

## 验收标准

- [x] [角色与成长 · 四项属性的作用方向](../../canon/gameplay/角色与成长.md) 写明战斗动作的时长（攻击速度、移动速度、施法读条速度）只由天赋与状态修改，不由任何属性派生
- [x] 那条判据写成通用形式（属性可以改「你还能不能做下一次」，不可以改「战斗里做一次要花多久」），并写明经营侧不受它管
- [x] 写明它们不进宝物与宝石的随机副词条，并给出理由 —— 随机的连续系数会把逐帧或逐技能调过的时序拉走，而天赋与状态给的是离散的、作者亲手挑过的档
- [x] 写明宝石换掉施放形态（瞬发与读条互换）不受这条管 —— 那是换一个字段，不是乘一个系数
- [x] [`成长系统`](../../design/成长系统.md) 派生表那几行的「其余来源」栏与正文都反映这条收窄，并有一条结构约束验收**同时钉住反面**（闪避冷却与体力条回复速度照常收副词条）
- [x] [`装备系统`](../../design/装备系统.md) 的词条那一节写出「不进副词条候选池」，上游约束加了对应的引，验收里有一条载入校验、一条反向反证、一条反面确认
- [x] [`技能系统`](../../design/技能系统.md) 的挂载点写明全局施法读条速度是派生量、各技能自己的读条时长归 `GP-6`
- [x] 攻速与施法读条都有下限、都归 `GP-6`，并写明它们现在挡的是天赋与状态叠起来的总量
- [x] 写明代码仓 `rules/Combat/CombatFeel.cs` 里的移速常量本轮不动，以及为什么（移速本来就没有属性来源，参数表里也没有对应的键）

## 实现笔记

### 设计决策

- **模糊点**：这条边界写在正典还是写在派生表旁边 —— 它既是产品规则也是派生表的一格。
- **选择**：规则的原句写在正典（它是「玩家能靠什么变强」这一类事实），派生表与装备系统各写自己那一半的落点并指回去。
- **理由**：正典那一节已经在讲「属性给什么、不给什么」，这条是同一个判据的另一半；写在设计侧会让一条产品规则藏在两份系统文档里。

- **模糊点**：「不进随机副词条」要不要做成一条新的副词条类型限制。
- **选择**：不做。它落在装备系统既有的「词条的量有家」那条校验的同一处 —— 那个量声明了自己不接受这条来源。
- **理由**：正典排掉「孔位分类型」时给的理由（再加一层约束，收益不抵复杂度）对这里同样成立。

- **模糊点**：第一版判据写成「属性不可以改一个动作内部各帧的相对时序」，而作者评审时问敏捷要不要再给施法读条速度 —— 按那句的字面，读条是一段没有内部时序的等待，它合格。
- **选择**：不给施法读条速度，并把判据收紧成「属性可以改『你还能不能做下一次』，不可以改『战斗里做一次要花多久』」。
- **理由**：施法读条速度是攻速的魔法侧同构物，乘的是智力那一路的量 —— 给了敏捷就是把刚拿走的乘数换个名字装回来。而第一版判据判不了这一题，只有推理判得了；判不了就意味着下一个读者会照字面把它加回来，所以改的是判据而不是只加一条例外。

### 偏离

- **方案怎么说**：`US-004` 只说这两个量（攻速与移速）剩下谁能改。
- **实际怎么做**：扩到三个量，并把判据改成通用形式；顺带在[`技能系统`](../../design/技能系统.md)加了一条挂载点，在成长系统与装备系统各加了一条反面确认（闪避冷却与体力条回复速度照常收副词条）。
- **为什么**：作者在评审中定了不给施法读条速度。只加一条「施法读条也不给」而不动判据，等于承认判据判不了自己管的事；反面确认是为了让那条校验判的是「做一次要多久」而不是被读成「凡带『速度』二字的都不收」。

### 权衡

考虑过让这几个量彻底退出可修饰派生量（谁都不能改，动画速度按动作写死）。放弃了：那会把「急速／缓速」这一整类效果一起删掉，而几个作者亲手挑过的离散档并不构成「连续拉伸帧数」—— 要防的是玩家能连续堆的那种。

### 待确认

装备系统那条载入校验**本轮只写进验收清单，没有实现** —— 它跟着 `GP-24` 落地。
