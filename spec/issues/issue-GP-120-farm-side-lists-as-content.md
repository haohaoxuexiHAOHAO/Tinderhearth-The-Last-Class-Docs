# GP-120：建筑类别、生产渠道与委托类型改成加一种只要多一条数据

## 目标

这三样各加一种只是多一条数据；其中「带新功能的建筑」那一半仍然归代码，而两者在文档里分得开。

## 来源

- PRD：[`prd-extensible-lists`](../prd-extensible-lists.md) 的 `US-002`
- 判据：[ADR-0025](../../decisions/ADR-0025-取值集的家由加一个的代价决定.md)

## 依赖

无。

## 验收标准

### 建筑类别

- [ ] [`建造系统`](../../design/建造系统.md)写明**类别本身是内容**，正典那一行改成只写起步量与选取判据
- [ ] 同一处写明**功能读口是代码** —— 一类建筑带一个别人没见过的功能（例如自动浇水）时要写代码，那不是填一条数据
- [ ] 这条分线沿用那一份已有的判据（「它是什么」还是「它能干什么」），**不新造判据**
- [ ] 可测试：外置数据里加一类只带已有功能读口的建筑，载入成功且代码零改动
- [ ] 可测试：一类建筑声明了一个没有实现的功能读口时载入被拒，并说清是哪一个

### 生产渠道

- [ ] [`生产系统`](../../design/生产系统.md)的渠道表写明加一条要填哪几格，名字不当封闭清单
- [ ] 工位清单与渠道名共用同一个词那条口径不变，但**那份清单只留一个家**，另一处写链接不复述
- [ ] **优势维那张在册表答掉「校验读哪一份」** —— 它现在一处说读本页这张表、一处说这张册要外置得下，两句对不上
- [ ] 可测试：外置数据里加一条渠道并加一维，载入成功且代码零改动
- [ ] 可测试：一条渠道声明了不在册的维、或与别人撞维时载入被拒

### 委托类型

- [ ] [`任务系统`](../../design/任务系统.md)写明加一类要填哪几格
- [ ] 那条按名字写的编队规则（哪一类允许主角单人出征）改成**由委托类型自己声明**
- [ ] 可测试：加第四类委托时那条编队规则答得出来，不需要改代码
- [ ] 可测试：一类委托缺「允不允许单人」时载入被拒

### 收口

- [ ] 三处的归类按 [ADR-0025](../../decisions/ADR-0025-取值集的家由加一个的代价决定.md) 显式写在各自那份系统文档里
- [ ] 按词搜两个仓加 `.kiro`，旧的封闭清单说法零残留
- [ ] `python tools/check_docs.py` 0 FAIL
