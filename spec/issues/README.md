# 待办台账

全库**唯一**待办索引。一条待办一个编号，编号是跨文档引用的稳定标识 —— 系统文档、制作规格、ADR 与代码注释都会引它，所以**不重编号、不复用已删除的号**。

条目详情写成 `issue-<ID>-<slug>.md` 放本目录，由 `/to-issues` 产出。只有一句话就说得完的条目可以只留本表一行，不建文件。

**本页是全库唯一的状态所在处**，理由见 [WORKFLOW §3](../../WORKFLOW.md)：散文只写理由，状态只写在这里，别处写链接不复述。一格写不下就把解释移进该行链接的条目文件。**只写结果** —— 已完成的行不留日期、测试条数与提交号，那些会静默过期，而且 git 里查得到。

## 状态词

**下面各域表里，每一行备注都以这张表里的一个词开头。** 取值互斥且穷尽，不许自造第六个。

| 状态词 | 它说什么 | 关闭了吗 |
| --- | --- | --- |
| **已完成** | 该做的都做完了，没有剩余动作 | 关闭 |
| **设计已交付** | 文档那一半交了，落地或实机那一半还没做 | 开着 |
| **进行中** | 已经动手，还有写得出来的剩余动作 | 开着 |
| **未开始** | 还没动手 | 开着 |
| **明确后置** | 刻意先不做，没有排期 | 开着 |

**为什么要固定成一张词表**：这一列是「这个编号还开着吗」唯一机器读得出的地方，活文档里指向已关闭编号的指针靠它才查得出来（`tools/check_docs.py` 的 `check_closed_issue_refs`）。

**「设计已交付」与「已完成」必须分开。** 文档交付之后落地往往还差一大截，合成一个词会让守卫把一批还开着的编号判成关闭，而那比没有守卫更坏。

**关闭一个编号**（做完了，或被后来的决定取代而作废，都算没有剩余动作）：域表那一行删掉，在最下面「已关闭编号」那张表登一行，写一句话 —— 做完了什么，作废的写明作废。那张表本身就是状态，所以那里的行不带状态词。它的条目文件随之删掉（[WORKFLOW §4](../../WORKFLOW.md)）。**词表里刻意没有「已作废」这个值**：作废与做完对「它还开着吗」给的是同一个答案；留在域表填「未开始」是错的，作废的那件事不会再有人做。

## 依赖那一格

**还开着的行，备注末尾带一格「卡在」**，写的是这件事在等谁。取值有三种形状：某个还开着的编号、「不卡任何人」、「只卡作者」。**它只许指还开着的编号** —— 指已关闭的那种指错由 `DOC-108` 那条守卫判。

**空着的意思是「还没判过」，不是「不卡人」。** 这两者差别很大：前者要人读一遍那份设计才答得出，后者是一个结论。所以看到空格不要当成可以动手的信号 —— 要动手先把那一格判出来。

## 域表里的行不是同一种东西

**所以行数不等于活数。** 这一节存在的理由是它被问过：打开域表看到一长串，很自然会读成「这么多事排着队」，而实际上「还开着」的行至少有这几类，性质差得很远：

- **一个系统的落地。** 一个系统一行，记的是做到哪、卡在谁；还没开工的，开工时先从 desc 写一份短的系统文档（[ADR-0036](../../decisions/ADR-0036-游戏是什么只在desc写一份.md)）。它的条数大致等于**系统数**，不是积压数 —— 系统清单在[系统文档与提案 · 系统清单](../../design/README.md)。
- **别人的影子。** 备注写着「落地跟着某个编号走」的那些（界面侧占大头）。它们**自己动不了**，存在的意义是「那一半别忘了、而且归谁」。
- **明确后置的决定。** 状态词是「明确后置」的那些。**它们不是待办，是「为什么游戏里没有这个」的答案** —— 删掉它，同一个问题会被重新问一遍，而理由要重新推一次。
- **超边界记账。** 做别的事时撞到、当时明确排出那一轮范围的。价值在于下次撞到时查得到，不在于排队。
- **内容清单。** 「要写多少条作物／技能／敌人」那一类，量的家在[内容规模基准](../../design/数值模型.md)。
- **真正排着队的活。** 剩下的才是。

**怎么看出某一行属于哪一类**：读它的状态词与「卡在」那一格就够了 —— 「明确后置」是决定，「卡在」指着另一个编号的是影子或被挡住的，「不卡任何人」的才是现在动得了的。

**本节刻意不写各类的条数。** 那些数每关一条就变，写进散文就是又开一个会过期的家（WORKFLOW §3）；要数就现数。
