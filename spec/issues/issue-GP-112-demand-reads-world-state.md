# GP-112：需求系数读世界状态，价格在一季之内会动

## 目标

「今天卖不卖」每天都值得重新想一次，而玩家在手环里查得到价格为什么变。

## 来源

PRD：`spec/prd-richness-and-feel.md` 的 `US-012`。

立项理由：需求系数现在只做季度偏好，**一季之内是常量** —— 所以经营的一天里没有任何价格侧决策，最优卖法一旦被发现就再无变化。[`经济系统`](../../design/经济系统.md)已经写好了这层扩展（需求应该是世界状态的函数，不是随机数），本条把它接上。

**这是经营侧本轮唯一加的一条。** 轮作、派工组合、浇水取舍都按作者定的判据排掉了：不靠增加繁琐度换耐玩性。选它的理由是它不新增机制，只是把已有的扩展点接起来。

## 依赖

无。落地跟 `GP-43` 走，事件那一侧的入口跟 `GP-52` 走。

## 验收标准

- [ ] 需求系数那一层写明它读哪些世界状态，且[`事件系统`](../../design/事件系统.md)那张后果表里「改价格」那一格指向它
- [ ] 「价格必须可预测、可解释、可规划」那条总约束不受影响 —— 每次波动在手环里查得到当前值与一条原因引用
- [ ] 三层仍然是三层：波动进的是需求那一层，**不新增第四个乘数**（交易点差照旧落在乘法链之外）
- [ ] 判据 P6（偏好溢价足以让按偏好种优于按最高基础价种）在波动之后重算一遍并仍成立
- [ ] 波动幅度与频率登记进[数值模型](../../design/数值模型.md)的尚未给值表，归属列写 `GP-7`，并立一条约束形式：**幅度不得大到让「囤着不卖」成为通用最优解**
