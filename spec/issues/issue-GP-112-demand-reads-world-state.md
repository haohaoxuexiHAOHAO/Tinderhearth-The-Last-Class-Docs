# GP-112：需求系数读世界状态，价格在一季之内会动

## 目标

「今天卖不卖」每天都值得重新想一次，而玩家在手环里查得到价格为什么变。

## 来源

PRD：`spec/prd-richness-and-feel.md` 的 `US-012`。

立项理由：需求系数现在只做季度偏好，**一季之内是常量** —— 所以经营的一天里没有任何价格侧决策，最优卖法一旦被发现就再无变化。[`经济系统`](../../design/经济系统.md)已经写好了这层扩展（需求应该是世界状态的函数，不是随机数），本条把它接上。

**这是经营侧本轮唯一加的一条。** 轮作、派工组合、浇水取舍都按作者定的判据排掉了：不靠增加繁琐度换耐玩性。选它的理由是它不新增机制，只是把已有的扩展点接起来。

## 依赖

无。落地跟 `GP-43` 走，事件那一侧的入口跟 `GP-52` 走。

## 验收标准

- [x] 需求系数那一层写明它读哪几样世界状态：**季节、主线推进、当天的天气、随机事件**，各指到一个既有读口（[`经济系统` · 需求系数读哪几样世界状态](../../design/经济系统.md)）。同一处写明**明确不读的两样**与理由（活跃失衡、侵袭档）
- [x] [`事件系统`](../../design/事件系统.md)那张后果表里「改价格」那一格**原先就指向那个入口**，一个字没改 —— 它指的是[`经济系统` · 事件调价从哪进来](../../design/经济系统.md)，而本条把那一节改成「事件是几个输入之一，不是唯一一个」
- [x] 那条总约束不受影响，而且落点比原先细：需求系数的原因**从「一条引用」改成「在场的每一条偏移各一行、各带自己的原因」加一行合起来的当前值** —— 合成一个数再展示就等于把可解释性丢掉
- [x] 三层仍然是三层：几条偏移都进需求那**一个**输入，乘法链一项没多；点差照旧在链外。验收里另加了一条反证钉「需求不认区」（它与商店上架读的不是同一层）
- [x] `P6` 重算了并仍成立（按偏好种谷物一季胜过按最高基础价种药草）。**但这一条现在弱**：除季度偏好之外那几条偏移一个值都没有，所以重算读的还是原来那一个输入 —— 见下面「偏离」第三处

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：几条偏移怎么合成一个系数 —— 相乘还是相加。
- **选择**：**相加，然后钳在上下限之间**，基线是一。
- **理由**：两条各给同一个幅度时，相加的结果玩家算得清、相乘算不清；更要紧的是钳位需要一个明确的对象，而「和」是一个数、相乘时那个对象是一串括号。**而且[`事件系统`](../../design/事件系统.md)那条既有约束正是按「和」写的** —— 「一个钩子一次触发多条时，它们各自的后果加起来也不得越过被调用那一侧自己的上限（例如需求系数那一层的幅度上限）」。改成相乘要连那一条一起改。
- **第二处（承重的一处）：需求系数不读活跃失衡。** 那个量已经有三个读者，而喂给它们的推力与递减系数之间那条刹车**至今只是一条约束形式、没落成判据**。让价格也读它就是给同一个正反馈再加一条推力（境况好 → 卖得贵 → 玩家更强 → 境况更好），而[`活跃失衡系统`](../../design/活跃失衡系统.md)写明这个环不刹住会滑向完美结局。**写进边界那一节是为了以后没人顺手接上** —— 真要接就得先把那条刹车落成判据。
- **第三处：也不读侵袭档。** 那一档存在的理由是给穹盾天气保护改造一个被削减的对象；让价格读它等于把那项改造变成一次涨价。需求读的是「今天是哪一种天气」，两者不是一个量。
- **第四处：需求不认「哪一区」。** 生产队替整个避难所采购，所以需求是全城一份；**商店上架读的才是所在那一区的档位**。两处都是「读哪一层」，最容易被合成一个 —— 所以配了一条反证：两家不同区的店，同一件货的需求系数相同。

### 偏离

- **方案怎么说**：`US-012` 写「**事件与世界状态**改需求系数」，读起来像是只要把事件那个入口接上。
- **实际怎么做**：接了**四个**输入（季节、主线推进、当天的天气、随机事件），而且把原先那唯一一层（季度偏好）降成其中一条偏移。
- **为什么**：**只由事件驱动修不了这条缺陷** —— 没有事件在场时需求又变回一季之内的常量，而那正是要修的东西。事件是随机的、还带冷却，指望它撑起「每天都值得重新想一次」是指望不上的。天气（一天一种）与推进标记（剧情节点上跳）是两个一直在动、又都查得到原因的输入，接上它们之后那句话才成立。

- **第二处（`事件系统` 一个字没改）**：验收要求「那张后果表里『改价格』那一格指向它」，而**它原先就指着**（指[`经济系统` · 事件调价从哪进来](../../design/经济系统.md)，并写明必须带原因引用、不给「直接改成交价」开口子）。本条改的是被指的那一节 —— 把事件从「唯一的输入」改成「几个输入之一」，并写明事件那几条偏移与别的输入进同一个和、受同一个钳位。**指向关系没动，所以那一份不用改。**
- **第三处（`P6` 这一条现在弱，如实写下来）**：验收说「在波动之后重算一遍并仍成立」。实际重算是真跑了、也通过了，**但它读的还是原来那一个输入** —— 除季度偏好之外那几条偏移一个值都没有，所以「波动之后」这四个字今天还没有对象。真正的复核要等给值那一轮，而那一轮的要求已经写进尚未给值表的第三条约束形式：季度偏好那一条的幅度仍要让 `P6` 成立，别的偏移按货物分组给、不分「按偏好种还是按最高基础价种」。
- **第四处（多立了两条约束形式）**：验收只点了「囤着不卖」那一条。另加两条：**钳位的上下限必须存在且下限大于零**（下限为零等于「今天这一组货一文不值」，而正典点名要避开「卖不掉只是卡住」）；**季度偏好那一条仍要让 `P6` 成立**（它是那条判据的唯一输入，别的偏移动不到它）。少了前一条，波动会有一头没有封顶。

### 权衡

**也可以让玩家能动这一层** —— 例如向生产队申报下一季想卖什么。那是一条影响力线，与「帮这座城」那条长期线同向，听着也好玩。否决理由是它会让价格从「世界的状态」变成「玩家的按钮」，而三层里玩家已经有两个按钮（出货量与点差）；需求这一层的全部价值正是它不由他决定 —— 否则「今天卖不卖」的答案又变成了他自己昨天填的那张表。

**另一条被放弃的是让天气只改产出、不改价格**（怕同一场雨被收两次）。否决理由是两侧量的不是同一件事：产出那一侧改的是玩家收多少，价格那一侧改的是市场缺不缺 —— 而「恶劣天气那几天外区补给进不来」在正典里本来就有依据（收购队被袭、道路被封、灵场异常导致延误那几样）。**代价写明并登记了**：天气那条偏移的幅度要等恶劣天气的产出修饰先给值，否则同一场雨在两侧各调一次、加起来多重。

### 待确认

无。

**核过没改**：

- **正典一个字没动。** 那两层扩展是正典自己留的（「需求应该是世界状态的函数，不是随机数」），本条接的就是它 —— 所以没有上游指纹要复核。三层的形状、每个因子要查得到原因、三层之外不许再加乘数，三条都没碰。
- **`--check-doc` 先报了一次失败，是真报对了**：新写的那句「基线 1 加上……」把一个裸的数字放进了 `pricing.supply_step_decay` 所在那一行，于是值校验拿 `1` 去比参数表的 `0.08`。**这不是误报** —— 那条判定的本意就是「路径旁边写的数字必须对得上」，而它分不出「这个 1 说的不是这个参数」。改法是把那句拆成单独一段，路径那一行不留裸数字。
- [`活跃失衡系统`](../../design/活跃失衡系统.md)与[`天气系统`](../../design/天气系统.md)**都没改**：本条只读它们已有的读口，而且刻意各少读一样（失衡整个不读、天气只读「今天是哪一种」不读侵袭档），所以那两侧没有新增读者要登记进它们的正反馈账。
- [`物品系统`](../../design/物品系统.md)没改：货物分组照旧是类别轴更粗的一层，**没有新字段** —— 几条偏移都按分组给。
