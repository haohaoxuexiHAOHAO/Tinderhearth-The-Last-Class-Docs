# ART-5：下载素材里的柔和投影怎么处理

## 目标

定一次「下载来的素材带柔和投影时怎么办」，让它不必在每个素材包上重新决定一遍。

## 来源

收 `fantansy lands` 那套俯视素材时撞出来的。[像素绘制原则 §9](../../production/像素绘制原则.md) 把「透明度只使用完全透明或完全不透明」定为**绝对规则**。

实测五张图全带软 alpha，值是 77／102／148／163，最多的一张 8,371 处。那些像素是屋檐、门与雨棚底下的柔和投影，不是脏点。

**这会在每个下载包上复发**，带柔和投影是现成像素素材的常见做法。所以要定一次 —— 每次临时决定的后果是判据漂移：这次放行、下次拦下，而两次的理由都记不住。

## 裁定

**借来的素材放行软 alpha，自绘件不放行。**

条件单一：素材不得进发行包。下载件既然一定会被替换，满不满足 §9 只影响开发期观感，而 §9 要守的是成品质量。

被否决的三条：

| 做法 | 为什么不选 |
| --- | --- |
| **阈值化**（alpha ≥128 → 255，<128 → 0） | 77 与 102 的投影整片消失，148 与 163 变成实心灰块 —— 观感比原图差，而且不可逆 |
| **抖动**成 50% 棋盘格的实心投影色 | 像素画伪造半透明的传统做法，读感与硬 alpha 都能满足，但每张都要人看一眼效果。对一定会被扔掉的素材花这个工夫不合比例 |
| 把 §9 降级为「建议」 | 代价不成比例，而且降级之后没有任何东西挡住软 alpha 进入**自绘件** |

## 现状

原先这条由 `check_assets.py` 按登记表字段自动放行，那条链已随 [ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md) 删除。**裁定本身不变**，现在是人工标准，靠作者实机看 —— 投影糊不糊是一眼的事。例外说明写在 `production/像素绘制原则.md` §9。
