# GP-42：`design/关卡系统.md`，出征采集收进去

## 目标

把片段拼装从「正典说要这么做」变成「照这个就做得出来」—— 片段分几类、凭什么接得上、一关怎么排节奏、资源点是什么，都在一处。

## 来源

- PRD：[`spec/prd-quest-and-level.md`](../prd-quest-and-level.md) 的 `US-003`
- 起因：[战斗与关卡 · 关卡由手工片段按规则拼装](../../canon/gameplay/战斗与关卡.md)把拼装标成**防重构点**（先做成整张图以后再改等于重做关卡系统与全部关卡资源），但规则本身还是空的。
- 同批收一件散落的事：采集的规则散在[战斗与关卡](../../canon/gameplay/战斗与关卡.md)各处（三类委托之一、读条且受击中断不消耗、场景采集归采集者、背包满停止自动采集、采集关与战斗关同为侧视），没有集中的家。**它归本条，不另立一份采集系统** —— 资源点是片段上的东西，离了关卡没有容器。

## 依赖

`GP-40`（用词与边界）、`GP-41`（目标条目的类型要引得到）。**`GP-39` 不阻塞本条** —— 本条只要求「每类资源点指得到一项生活技能」，表里有哪几项归那一条。

## 验收标准

- [x] 按 [SYSTEM 模板](../../templates/SYSTEM.md)八节写全，`type: system`、文件名以「系统」结尾、`upstream` 指[战斗与关卡](../../canon/gameplay/战斗与关卡.md)，**并在本条这一轮就被正典链接到**。
- [x] **片段按两条正交的轴声明**：结构（正典点名的那几种形状）与**职责**（战斗／非战斗／目标／入口）。理由：节奏约束读职责、接得上读结构，合成一条会让「有敌人的走廊」无处声明。
- [x] **片段之间是转场，不是无缝滚动** —— 每次换片段都要按交互键并走一段读条，受击中断；**往前、往回与撤离三个方向同一条规则**。写明三个后果：接缝处不需要视觉连续、敌人不跨片段追击、加载时只需要当前那一个片段。
- [x] 写明**按键与读条各干一件事**：按键防误操作，读条让脱离可被打断。并写明往回退也读条的理由 —— 清理区域不要求全歼，往回走很可能是带着活着的敌人走。
- [x] 转场读条的时长写成**约束形式**：长到让被追击时无法脱离，短到不至于让清过的路变成罚站。形式与[战斗与关卡 · 读条与打断](../../canon/gameplay/战斗与关卡.md)那条同源，值归 `GP-6`。
- [x] **接得上的条件写成可判定的清单**：纵深带宽度一致（家在[战斗与关卡 · 48px 是怎么算出来的](../../canon/gameplay/战斗与关卡.md)，**写链接不复述那个数**）、转场点按方向声明且成对匹配。不满足时**加载当场报错**（[ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md)）。
- [x] 写明**为什么不要求接缝处地面高度对齐** —— 那是无缝滚动才需要的条件。显式写出来，否则会被当成漏做。
- [x] **入口片段唯一，且它同时是撤离点**，理由是撤离与撤退都要求返回入口点。
- [x] 节奏约束写成**约束形式**，逐条覆盖：一关的场景数、目标片段的位置、分支的数量、相邻两个战斗片段之间至少隔一个非战斗片段、同一块片段在一关里不得重复出现。同一处写明**拼不出合法关卡时先放宽哪一条**。
- [x] 写明**没有时间限制**，理由指回正典，免得以后被当成漏掉的一条节奏约束。
- [x] 写明**「布局要随机」与「节奏要成立」的张力与解法**：约束只划掉不合法的排列，重复感来自可选的块太少 —— 所以变化量靠池子规模撑，判据是「同一类委托连打若干次，排列不重样」。
- [x] 写明**随机要有逻辑，载体是片段上的标签**：战斗片段之前优先排一块**带战斗预兆的非战斗片段**。标签是接口，暗示长什么样是片段内容、归作者。
- [x] **拼装结果由一个种子决定，种子进临时续玩点**；理由指回[玩法定位 · 存档](../../canon/gameplay/玩法定位.md)（关卡内退出要恢复到关卡入口且已获物品保留，图若重抽就是换了一张）。同一处写明**拼装规则不许读任何会变的外部状态**。
- [x] 写明**关卡进度也进续玩点**（已采的点、已清的目标、已开的容器），理由是只保留物品、整关重置等于一条静默的无限资源路径。
- [x] 写明**关卡系统只持有配额，不持有敌人种类与行为** —— 档位喂进来的是敌人预算。
- [x] 写明**三类委托与采集关共用同一个片段池子，只在配额上不同**，并写明「这一关能挑哪些」的筛选规则（按职责取配额、按结构取接得上的）。
- [x] **「采集」在本页一律是总称**，具体作业各有名字，对灌木与敌人尸体搜刮的那一类叫**搜刮**。写明理由 —— 让总称同时当技能名就是又造一处同名不同物。
- [x] **资源点分类型，每类各声明产出表与「品质读哪一项生活技能」**；**生活技能表本身不在本页**（归 `GP-39`），本页只要求「指得到一项」，缺了**载入时报错**。
- [x] 写明**分类型的判据是作业对象**（对着灌木与尸体、对着矿脉、对着树），不是手上的操作 —— 各类在手上都是走过去按一下读条。
- [x] 写明**各类资源点共用同一条动作管道**（走过去、按键、读条、产出入背包），差别只在类型、产出表、读哪一项技能与读条时长；**不做工具与耐久**。
- [x] 采集那一节其余各条写全：读条走[战斗与关卡 · 读条与打断](../../canon/gameplay/战斗与关卡.md)那一套、**稀有点复用[`生产系统` · 钓鱼是世界里的动作，不是一个界面](../../design/生产系统.md)那条时机条**、归属指回[角色与成长 · 战利品归属](../../canon/gameplay/角色与成长.md)、背包满时只拒不丢且物品留在世界里（[`背包系统`](../../design/背包系统.md)）、队友自动采集且背包满就停。
- [x] 写明资源点**按遗址分组是加法**（[世界观 · 外域](../../canon/world/世界观.md)那张表是开口的），加一处遗址等于加一组资源点与一类敌人来源。
- [x] 写明**资源点受视野约束**（[战斗与关卡 · 感知与视野](../../canon/gameplay/战斗与关卡.md)）—— 没被感知到的点不显形，所以摸黑绕过去会漏采。
- [x] 边界那一节写明**不持有**：片段本身的地形与摆位（作者在 Godot 里搭）、敌人 AI 与感知视野的实现、纵深带够不够（`ENG-16`）、物品定义与容器、奖励定价、地图与导航、生活技能表。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：节奏约束拼不出合法关卡时怎么办 —— 验收只要求「写明先放宽哪一条」，没说放宽到底还是不行该怎么办。
- **选择**：**放宽顺序写死，放宽到底仍拼不出就报错。** 顺序按「玩家最不容易察觉」排：先放宽同一块片段的出现次数，再放宽分支数量；**战斗片段间隔与目标片段位置永不放宽。**
- **理由**：报错不是失败处理，是一条有用的信息 —— 它说的是「池子不够，该加片段了」。静默拼一张不合法的图出来，症状是玩家觉得这关很怪，而没人查得到原因。那两条永不放宽是因为放宽之后关卡就不是关卡了（一进门就打完目标，或者连着两场没有喘息）。

第二处：**「布局要随机」拆成了两件事。** 变化量靠池子规模，逻辑性靠片段上的预兆标签。合起来写会得出一个错的结论 —— 「少加约束能换来变化」。约束只划掉不合法的排列，重复感来自可选的块太少。

### 偏离

- **方案怎么说**：验收里写「接得上的条件：纵深带宽度一致、**接缝处地面高度对齐**、转场点成对匹配」。
- **实际怎么做**：**「接缝处地面高度对齐」这条删掉了**，而且在文档里显式写明为什么不要它。
- **为什么**：作者定下「换片段要按键加读条」之后，片段之间就是**转场**而不是无缝滚动 —— 两块各是独立场景，玩家不会同时看见接缝两侧。留着那条要求只会让作者搭片段时多一个必须对上的数，换不来任何东西。**显式写出来是必须的**，否则它读起来像漏做。

第二处：**「按遗址分组」原本只写了片段，补上了资源点。** 验收要求的是「资源点按遗址分组是加法」，只写片段等于漏了半句。

### 权衡

「出征采集另立一份 `采集系统`」考虑过 —— 它承载的东西不少（挖矿、宝物、燃料、高级物品的来源）。没选：资源点是片段上的东西，离了关卡它没有容器；而[`生产系统` · 什么时候拆出去单独成篇](../../design/生产系统.md)那条判据问的是「它有没有自己的状态机」，资源点没有（采完就是采完，不像地块有流转）。

「把整张拼好的图写进续玩点」考虑过，比种子直观。没选：续玩点会随关卡规模涨，而且片段数据一改旧续玩点就废。种子加上「拼装规则是纯函数」这条约束之后重建是确定的 —— 代价是那条约束成了承重件，所以给它配了反证。

「往回退免读条」考虑过（回程更顺）。没选：清理区域不要求全歼，往回走很可能带着活着的敌人 —— 免读条就是一条免费的脱离路线。清过的路上那份等待用时长压住，不用开例外。

### 待确认

**一处推断，未实测**：「加载时只需要当前那一个片段」是从转场这个形状推出来的**结论**，不是量过的内存数字。真到了片段很大或转场要预载下一块时，这条可能要让步 —— 那时它是实现细节，不推翻文档里任何一条规则。
