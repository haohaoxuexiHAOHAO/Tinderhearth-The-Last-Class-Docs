# GP-45：生活技能的档位与专长，五档、后四档各三选一

## 目标

让练一项生活技能变成一串选择而不只是数字变大：五个档位，第二档起每升一档挑一条永久专长，四次选下来攒出「这个角色是怎么干这活的」。

## 来源

- PRD：[`spec/prd-economy-and-building.md`](../prd-economy-and-building.md) 的 `US-002`
- 起因：[`成长系统` · 生活技能：档位制，每档解锁一件看得见的事](../../design/成长系统.md)写着「每档解锁一件看得见的事」，但**解锁什么是空的**；[角色与成长](../../canon/gameplay/角色与成长.md)那张表里生活技能只有「一个熟练度等级」这一句，所以「谁去干这活」在经营侧没有除数字以外的答案。

## 依赖

`GP-39`（它改的是同一张表与同一节，**两条必须紧挨着做**；重排先落地，档位与专长才知道自己挂在哪几项上）。

## 验收标准

- [x] [角色与成长 · 技能分两类：放出来的动作，与做事的熟练度](../../canon/gameplay/角色与成长.md)那张表里生活技能那一列改写 —— 它不再只是「一个熟练度等级」，而是**等级加一条构筑线**；档名与档数在这里定。
- [x] 档名**不与已占词撞名**：队友 AI 的技艺档、关系档、活跃失衡档、稀有度与品质的取值都不许复用。同一处写明这条命名约束，免得下一套档位又撞。
- [x] 写明**第一档是地板，不给分支**，理由写清（生活技能刻意没有门槛 —— 战斗技能要书与前置属性，生活技能只在真的做成那件事时涨；加一个「未入门」档就得回答「怎么入门」。而且开局就选等于做一次无信息的选择）。
- [x] 写明**档数与选择次数是两个数**，理由是不写死会长出两个说法。
- [x] [`成长系统` · 生活技能：档位制，每档解锁一件看得见的事](../../design/成长系统.md)那一节按新结构改写：档位阶梯、每个节点三选一、**选定即永久且不可更改**。
- [x] 写明**专长走[`状态效果系统`](../../design/状态效果系统.md)的永久项**，与失衡增益、宝物词条同一个载体，**不新建承载结构**。
- [x] 写明**专长不是「特质」**：不占特质的条数上限、不进特质那张表。理由写清（那个上限是正典用来限制构筑面的数，而专长的量级会直接撑破它；「存在纯负面特质」那条也会串味 —— 三选一里三条都该值得选）。
- [x] 写明**专长按「角色 × 技能」记**，与实战值同一条记法，**不新建存储形状**。
- [x] **谁来选写清**：主角的由玩家选；学生的**自动选，但玩家可以覆盖**。理由指回[角色与成长 · 战利品归属](../../canon/gameplay/角色与成长.md)那条「学生会自动装备自己持有的宝物，玩家手动配的优先」—— 同一条形状，不新造规则。
- [x] 写明**不可更改**的理由（不花点数、没有可退的资源；「不可逆才有身份感」在这里成立），并**同一处配一条硬约束**：三个选项的效果必须说全，不许藏 —— 不可逆加信息不足才是惩罚。
- [x] 写明**升档那一刻不弹界面**，选择攒着、回手环里选。理由指回[玩法定位 · 弹界面接管输入就暂停世界，世界里的动作不暂停](../../canon/gameplay/玩法定位.md)与[玩法定位 · 手环的管理功能在关卡内不可用](../../canon/gameplay/玩法定位.md) —— 关卡里升档当场弹面板等于一次免费暂停。
- [x] 写明**没选的节点不给任何加成**，拖着不选只是没拿到、**不受任何惩罚**。
- [x] **专长能改哪几类量按技能各自声明，不做一张全局轴表**，判据写明是「这项技能实际参与的那条管道上有哪些量」；同一处写明**关卡侧的作业既不消耗精力也不消耗体力条**（所以「省力」那类专长只对基地侧的作业成立）。
- [x] 三组轴各写出来并各给理由：进产出管道的那几项用耗精力、品质、数量、额外产出；关卡侧那几项补一条**读条时长**；**交易单独一组**（点差、批量递减的坡度、市场信息的可见度），并写明它为什么不共用产出那三条轴。
- [x] 写明**档名是全局一套**，而**各节点上那三个专长条目的名字与效果按技能各自声明**。两件事分开写，否则会长出多套档名。
- [x] 写明**一个专长条目要声明哪些字段**，并写明**具体条目是内容**、走[内容外置](../../canon/gameplay/玩法定位.md)（`ENG-5`）。
- [x] 档位阈值与各条专长的幅度登记进[`数值模型` · 尚未给值的量，各自写明校准办法](../../design/数值模型.md)；**档数与节点数是接口常量、不进那张表**，归属写明。
- [x] `python tools/check_docs.py` 0 项必须修复。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：专长的轴该不该做成一张全局表 —— 作者给的是四条（耗精力、品质、数量、额外产出）。
- **选择**：**轴按技能各自声明**，分三组：进产出管道的那几项用那四条；关卡侧的作业补一条**读条时长**；**交易单独一组**（点差、批量递减的坡度、市场信息的可见度）。
- **理由**：那四条对两项技能落不下去。**搜刮只有关卡侧的作业**，而关卡侧的采集读条不消耗精力也不消耗体力条，所以耗精力那一轴对它是空的；**交易根本不进产出管道**，所以品质、数量、额外产出三轴全空。全局表会在交易那一栏留下几个填不了的格，而填不了的格一定会被「等效物」塞满（把交易的「品质」读成「谈成的价钱」）—— 一个字段两个含义，而那种错不报错。

第二处：**升档不弹面板。** 正典那条「弹界面接管输入就暂停世界」意味着关卡里砍树升档当场弹面板等于一次免费暂停，而手环的管理功能在关卡内本来就不可用。选择攒着回手环里做，顺带还解决了「一天升好几档」时连弹几次。

第三处：**挖矿与伐木在轴表里出现两次。** 它们两侧都有活干（关卡里对着矿脉与树，基地里对着开荒要清的石头与树木），所以它们既有读条时长那一轴、也有耗精力那一轴。搜刮只有关卡侧那一行。**这条写出来是因为它读起来像重复**。

### 偏离

- **方案怎么说**：条目的验收写「档名与档数在[角色与成长](../../canon/gameplay/角色与成长.md)定」。
- **实际怎么做**：档名与阶梯确实在正典，但**「档名不与别的档位阶梯重合」这条命名约束也写进了正典**，而不只是写在 `成长系统` 里。
- **为什么**：撞名这件事已经发生过一次（[`人际系统`](../../design/人际系统.md)的边界那一节专门记着「本作有好几套档位刻度，且还在增加」）。约束写在系统文档里，下一个加档位阶梯的人可能根本不读那一份；写进正典那张表旁边，它就在所有人都会经过的地方。

第二处：**`成长系统` 里那一节用了三级标题**（「专长落成什么」挂在生活技能那一节下面）。八节骨架守卫只认二级标题，所以三级标题是唯一能把这批内容放进「结构」里的办法 —— 与上一批采集那批内容的处理一样。

### 权衡

「专长就叫特质」考虑过（作者最初的说法）。没选：特质在正典里已经是一个有上限 8 条、且含纯负面的东西，而专长的数量级会直接撑破那个上限，「纯负面」还会让人以为三选一里有坑货。载体用同一个（状态载体的永久项），只是不共用那张表与那个上限。

「给专长开一张自己的修饰表」考虑过，实现最省事。没选：那会让「同时生效的修饰」又多一个来源，而正典那条「全部临时性与持续性效果走同一套状态系统」正是为这个写的。

「第一档也给三选一」考虑过，五档五次选择更整齐。没选：开局要为每项技能各选一次，而那时玩家对这些技能一无所知 —— 无信息的选择不是选择。代价是「档数」与「选择次数」成了两个数，所以文档里把它们分开写了一句。

「专长可洗」考虑过，与天赋对齐。没选：天赋花点数所以有可退的资源，专长是做出来的、没有；而且可洗会让三十多个选择直接变成抄攻略。**配套要求写进了正典**：三个选项的效果必须在选之前说全 —— 不可逆加信息不足才是惩罚。

### 待确认

**一处是推断，未实测**：「三个选项的说明在 640×360 下读得完」这条没有量过。它写进了 `成长系统` 的实机确认清单，验法是作者摆一条最长的说明看看。
