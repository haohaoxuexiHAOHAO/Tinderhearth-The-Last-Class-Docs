# DOC-34：这一批的端到端与交叉核对

## 目标

用一条命令加一次人工对照，看出这一批的文档有没有和正典打架、有没有把某处说法改漏、**有没有踩别人写死的不变式**。

## 来源

- PRD：[`spec/prd-equipment.md`](../prd-equipment.md) 的 `US-007`
- 起因：上一批的交叉核对只按「同一件事在几处出现」核，于是漏掉一处真矛盾（订货延迟一天送到却没说货落在哪，而仓库只有一个自动写入点）。本条把「新加的动作有没有踩别人写死的不变式」列成必做项。

## 依赖

本批全部（`GP-46`、`GP-47`、`GP-48`、`GP-24`、`DOC-32`、`DOC-33`）。

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：「逐处列出处比对」怎么做才不只是把每处读一遍 —— 上一批就是这么做的，结果漏掉一处真矛盾。
- **选择**：拆成两轮。第一轮按**词**搜（饰品、宝石孔、词条与品质、强化、极品、载体与永久项），第二轮按**量级数字**搜（宝物栏格数、技能孔数、三个起步量），两轮都用一次性脚本写 UTF-8 日志再读。
- **理由**：按词搜找的是「同一件东西有两个名字」，按数字搜找的是「同一个数有两个家」—— 这是两类不同的漂移，一轮找不全。而且脚本自报扫到多少行，扫到 0 行当失败，避免「扫到 0 行却打出通过」那种假通过。

### 偏离

- **方案怎么说**：条目验收里没有「按量级数字搜」这一项。
- **实际怎么做**：加做了一轮，**并因此查出三处数字副本**（见验证结果）。
- **为什么**：本批往正典加了一个数（宝物栏格数），而那个数的家只该有一处。检查器判不了「两个数字说的是不是同一件事」，所以这一轮只能靠人 —— 不加这一轮就会留下正好那一类查不出来的债。

### 权衡

「把量级数字这一轮做成 `tools/` 下的入口」考虑过，它这一批查出了东西、下一批大概也会。没选：它要判的是「两个数字说的是不是同一件事」，而那机器判不了 —— 落成入口只会得到一个只能列候选、不能判定的东西，而[WORKFLOW](../../WORKFLOW.md)那条边界说得很清楚：留一个没有判定能力的守卫比没有守卫更坏。所以它是一次性脚本，用完即删。

### 待确认

**一处残留，未修，写明理由**：[`技能系统`](../../design/技能系统.md)的上游约束那一行仍然复述了技能孔的数字（「每个技能 2–3 孔」）。那是**上游约束那一节的既有体例** —— 它的作用是说清「正典约束了本页的哪一部分」，全仓各份系统文档的上游约束都在做同样的转述。本批把正文与字段表里的那两处数字都改成了指链接，只留这一处。真要收掉它得改所有系统文档的上游约束体例，**超出本批边界**。
