# GP-130：点一下门进出室内

## 目标

站在门口点一下门就进到室内那张图里，再点一下出来，落点与朝向都对。

## 来源

- ADR：[ADR-0027](../../decisions/ADR-0027-进出室内改成点一下门.md)（进出室内改成点一下门）——
  三条决定、被放弃的四条与残余风险都在那一份
- 系统文档：[`建造系统` · 室内：一类场景，进出是转场](../../design/建造系统.md)
- 正典：[时间与经营 · 建造](../../canon/gameplay/时间与经营.md)那条「走到门口点一下门进出」
- 引擎那一半怎么做：[`reference/godot/场景转场.md`](../../reference/godot/场景转场.md)

**它为什么单独立一条**：`GP-44`（建造系统落地）那条落地顺序里**没有转场这一步** ——
那一份排的是网格、摆位判定、施工状态机与两个挂点。转场是另一件事（它要一个场景切换器，
而那东西现在整个不存在），混进 `GP-44` 就没有自己的验收。

## 依赖

`ENG-21`（内容场景改成编辑器可编辑的节点树）。**现在没有一张室内场景可以切过去** ——
`scenes/` 下的场景每个只有一个节点，东西全在 `_Ready()` 里建出来。

`GP-91` 定拿哪一类建筑当室内样板；本条不挑那一类，只要求「有一张」。

**不依赖 `GP-44`。** 摆位判定与施工状态机是另一批东西，本条只要门口那个范围与一张目标图。
**但有一条交叉**：门口范围用的就是门前那一格，而「门前一格必须留空」那条判定在 `GP-44` ——
那条不在时本条仍然跑得起来（范围是作者画的区域），只是少了「那一格一定站得下人」这个保证。

## 验收标准

- [ ] 站在门口范围内点一下门，切到室内那张图，角色落在入口点上、朝向按入口点声明的那个方向
- [ ] 室内点一下门出来，角色落在**门外那一格**、朝外站
- [ ] **站在门口范围外点同一扇门不进去**（承重项的反证 —— 它挡的是「屏幕上点得到就进得去」那种免费传送）
- [ ] **走进门口范围但不点，一格都不发生**（它挡的是「顺手把走进去那条也留着」）
- [ ] 键鼠上触发的是**鼠标右键**；左键点在门上**不进门**（左键仍然只作用于当前操作格）
- [ ] 手柄上用交互键进门，且绑定表里那条豁免登记写着理由（已有测试盯着）
- [ ] 进出**不插入读条**，[`角色动作状态系统`](../../design/角色动作状态系统.md)的姿态清单前后一致
- [ ] 转场**不启用暂停**：`GetTree().Paused` 全程为假，导航栈在切换时被清空
- [ ] 遮罩在「卸掉旧那张图」之前就盖上（顺序按[`场景转场`](../../reference/godot/场景转场.md)那一节）
- [ ] 目标场景是作者拖进检查器的 `PackedScene`，**缺了当场报错**、没有能用的默认值
- [ ] 入口点缺了当场报错并说清是哪张图缺了它，**代码不自己补建**
- [ ] 卸掉室内那张图之后，里面的东西（设备、摆件、仓库内容）**一件不少** —— 它们在规则层，不挂在场景树上
- [ ] 转场进行中再点一次门**不触发第二次转场**
- [ ] 代码仓 `python tools/verify.py` 五步全绿
- [ ] **作者实机确认**：点门那一下顺不顺手
- [ ] **作者实机确认**：门口那个范围画得合不合手（站在看起来该进得去的地方点不点得动）
- [ ] **作者实机确认**：门看不看得出来「它是点得动的」
- [ ] **作者实机确认**：**两栋楼挨着时点到的是不是想点的那一栋** —— 这一条是
      [ADR-0027](../../decisions/ADR-0027-进出室内改成点一下门.md) 的主要残余风险，消歧挑错不报错
- [ ] **作者实机确认**：遮罩淡入淡出各多久合适；换图那一下卡不卡（这一条同时验掉那一篇里
      「同步加载够不够快」那条推断）
