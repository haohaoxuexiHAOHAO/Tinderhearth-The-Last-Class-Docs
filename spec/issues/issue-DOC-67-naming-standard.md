# DOC-67：命名口径立成规则，并按它统一现有不一致

## 目标

「这东西该起个什么样的名字」有一条查得到的规矩，而两个已经指向它的指针指得到真答案。

## 来源

- PRD：[`spec/prd-canon-hardening.md`](../prd-canon-hardening.md) 的 `US-008`
- 起因：[`物品系统`](../../design/物品系统.md)的名称字段与[`数值模型`](../../design/数值模型.md)那条「不占命名权」都写着「口径见[文案写作规范](../../production/文案写作规范.md)」，而那一页开头明写**不适用于机制说明**、全篇 R1–R10 讲的是怎么写风味散文，**一个字都没讲命名**；[人物 · 命名规则](../../canon/characters/人物.md)那两层管的是专有名的语体分层，答不了「面包该叫什么」

## 依赖

无。**它应当排在其余命名统一之前** —— 规则不先立，统一完下一批内容又会各写一套。

## 验收标准

### 先立规则

- [ ] 可核对：[文案写作规范](../../production/文案写作规范.md)新增一节「命名口径」，写下两类与判据「它是不是这个世界特有的东西」：**特有之物**（状态、特质、技能、人物、地名、组织、器物级孤品）允许意名；**通用之物**（面包、啤酒、木料、石料、绳子这类现实里也有的东西）按它本来的名字叫、不修饰不雅化。
- [ ] 可核对：通用之物那一条写出理由 —— 给面包起一个世界内的雅名，玩家要多记一层换算，而那层换算不带来任何决策；**判据是「玩家看到它要不要先翻译一次」，不是「好不好听」**。
- [ ] 可核对：写下字数规矩 —— **表达需要几个字就用几个字，不为简短而缩短**；举例说明缩短会丢掉什么（「薪尽火传」砍成两字就只剩「传下去」，「烧尽」那一半没了）。
- [ ] 可核对：该页开头「不适用：机制说明」那句**扩一格**：名称是标签、不是机制说明，所以命名归本页；效果与数值的说法仍不归本页。
- [ ] 可核对：[人物 · 命名规则](../../canon/characters/人物.md)那两层**留在原处不动**，新那一节写链接引它、**不复述**；两处的分工各写一句（那边答「意名长什么样」，这边答「哪些东西可以意名」）。
- [ ] 可核对：[`物品系统`](../../design/物品系统.md)与[`数值模型`](../../design/数值模型.md)那两个指针现在指得到真答案（链接不必改，改的是被指向那一页）。
