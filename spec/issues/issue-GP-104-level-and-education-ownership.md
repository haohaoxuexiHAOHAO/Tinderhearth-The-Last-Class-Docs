# GP-104：敌人种类池与典籍去重各有一份文档持有它

## 目标

「这一关放哪几种敌人」和「这本典籍出现过没有」各有明确的持有者，实现时不必去猜谁该写。

## 来源

PRD：`spec/prd-richness-and-feel.md` 的 `US-004` 前半。

立项理由，两处都是互相推开：

- **敌人种类池**：[`关卡系统`](../../design/关卡系统.md)交出敌人预算与放置位、明说不交种类；[`战斗AI系统`](../../design/战斗AI系统.md)说有哪些敌人是内容、不反过来改配额。接口表里只出现过一次「季节影响敌人来源」，而那份数据的形状（遗址与季节两维的种类池）没有任何一页定义 —— 它同时是「同一个种子拼出同一张图」这条承诺的输入。
- **典籍去重**：[`教育系统`](../../design/教育系统.md)定了同一本全作只出现一次、判标识不判产出，却把掉落表推给关卡侧；[`关卡系统`](../../design/关卡系统.md)说箱子带着自己那份内容被摆、不判里面该不该是它。搜刮点那一侧还多一层：资源点的产出表随片段重刷，而典籍不许重刷。

## 依赖

无。文档侧可以现在就改；落地分别跟 `GP-42` 与 `GP-21` 走。

## 验收标准

- [x] 敌人种类池落[`关卡系统`](../../design/关卡系统.md)：按遗址组声明、按季节分，缺声明或引到不存在的标识都载入报错
- [x] 典籍「出现过没有」那份记录落[`教育系统`](../../design/教育系统.md)持有 —— **它原来就在那儿**，缺的是**谁执行去重**，见下面「设计决策」
- [x] 两份文档原先推走它的那几句改成指向新家，不留互相推开的说法；`战斗AI系统` 那一侧的上游约束、接口表与「它不持有」三处跟着改
- [x] 资源点产出表随片段重刷与典籍不许重刷之间的关系写明 —— **典籍不进产出表**，它是放置那一刻挂上去的
- [x] `python tools/check_docs.py` 0 FAIL（改了一处节名，引它的地方一起修过）

## 实现笔记

> 由 `/note-it` 在实现和评审之后填写。

### 设计决策

- **模糊点**：典籍去重到底缺什么。立项时写的是「记录无人持有」。
- **选择**：记录**本来就在**[`教育系统`](../../design/教育系统.md)，缺的是**执行去重那个动作** —— 本页给它定了归属：记录与读写口在教育侧，**查它与记它在放的那一侧**（关卡与委托奖励）。
- **理由**：分工按「各自知道什么」切 —— 只有关卡侧知道这一刻在往哪个容器里放什么，只有教育侧该存这笔账。合到一边则要么教育侧得知道关卡怎么拼，要么关卡侧得存一份自己的账。顺带写明**只给读口不给写口是不够的**：那样没有任何一处写得进去，而它不报错，表现是每本书永远算「没出现过」。
- **另一处**：敌人种类池归关卡侧，**理由是容器** —— 片段库本来就按遗址分组，而正典写明季节影响野外敌人构成，所以它和片段池是同一个形状的东西。分界判据写成「改它会不会改掉某一种敌人本身」。

### 偏离

- **方案怎么说**：敌人种类池「片段库按遗址分组时带一份」。
- **实际怎么做**：按遗址组声明，**而且按季节分**。
- **为什么**：正典写明季节影响野外敌人构成，所以只按遗址分的池子接不住那条。顺带要多写一条验收把确定性钉住 —— 同一个种子加同一个季节取出来的种类一字不差，**季节是出征那一刻的定值、不是会变的外部状态**，否则它会撞破「同一个种子拼出同一张图」那条承诺。

### 权衡

敌人种类池也可以挂在[`战斗AI系统`](../../design/战斗AI系统.md)那一侧（每个敌人自己声明「我出现在哪几处遗址、哪几季」）。否决理由：那样「这个遗址出得来哪几种」是把全部敌人定义扫一遍反查出来的，加一种敌人就可能悄悄改掉某个遗址的构成，而**没有任何一处看得出那个遗址现在有哪几种**。挂在遗址组上则那份名单是一处写死的声明，读得出来也审得动。

### 待确认

无。

顺带一处**没有顺手改**：典籍不进产出表这条写完之后，「委托奖励」那条来源的去重也走同一对读写口，而委托奖励的池子在[`任务系统`](../../design/任务系统.md)那一侧 —— 本轮只在教育侧与关卡侧写明了这对口，任务侧的引用等 `GP-41` 落地时接。它不构成缺口（那一侧本来就要读奖励表），所以不另立编号。
