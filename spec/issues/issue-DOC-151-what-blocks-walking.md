# DOC-151：俯视里什么挡人，写进场景绘制约定

## 目标

以后加悬崖、墙、建筑或摆件的人查一处就知道俯视里什么挡人、碰撞挂在哪。

## 来源

- PRD：[`spec/prd-terrain-blocks-walking.md`](../prd-terrain-blocks-walking.md) 的 `US-003`。那一条里改代码注释的那一格挪进了 `ENG-35`：同一个文件，跟检查一起改。

## 依赖

- `ENG-35`：新那一节要点名那条检查的代码，文件得先在。

## 验收标准

- [x] 可核对：[场景绘制约定](../../production/场景绘制约定.md)多一节，写明：挡人的一律是物理碰撞、挂同一层；地形的碰撞挂在数据层那一格的标记瓦片上，以及为什么不挂显示层、不另刷一层；数据层用 `Visible` 隐藏、不关 `Enabled`，以及为什么；同一种地形的标记瓦片碰撞要一致；布景、建筑与摆件自带碰撞。新那一节是[场景绘制约定 · 俯视里什么挡人](../../production/场景绘制约定.md)，排在「俯视布景」后面。
- [x] 可核对：那一节写明它判不了的两样：哪几种地形该挡人，与角色的掩码对不对得上。后一样附上实测读回的默认层。
- [x] 可核对：「俯视布景」那一节石头那一条指向新那一节，不复述。
- [x] 可核对：`ENG-25`、`GP-44` 的台账行各指向新那一节，不复述。
- [x] 可核对：设计仓 `python tools/check_docs.py` 0 FAIL。

## 实现笔记

### 设计决策

- **新那一节排在「俯视布景」后面**：石头那一条讲的就是「布景的碰撞归布景自己」，挡人的总规矩接在它后面读得最顺；原先最后那一节「画面不随时间换色」顺延一号，全库没有按号引它的地方。
- **改了文首那句「本文全部是人工标准，没有机器判据」**：双网格那两节早就各有一条机器判据，新那一节又多一条，那句话按字面已经不成立。改成「以人工标准为主，实机看不出错在哪的那几条有机器判据，各在那一节里写明」。
- **悬崖写进表里「不可走的地形」那一行**，不另开一行：基地现在没有悬崖，它将来是一种地形，碰撞照水的办法挂。

### 偏离

- **方案怎么说**：`US-003` 里有一格是改代码仓 `src/World/Terrain/DualGridPainter.cs` 的注释。
- **实际怎么做**：那一格随 `ENG-35` 交付。
- **为什么**：同一个文件、同一次改动，拆开会让代码那一次提交留着一句过期的注释。
