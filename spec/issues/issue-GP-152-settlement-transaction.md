# GP-152：整串是一次事务，写档成功才算数

## 目标

结算在世界状态的副本上跑，写档成功那一刻才换上去；在那之前任何一步出错或写档失败，世界一格不动，结果说得清这一天没有推进与原因。摘要在「生成结算摘要」那一步产出、在「次日 6:30 醒来」那一步交出，写档失败时交出零次。

## 实现笔记

### 设计决策

- **模糊点**：提交点由自动存档那一步自己宣布，还是由驱动判。
- **选择**：由驱动判：「自动存档」那一步正常走完，驱动就把副本换成当前那一份。那一步只管写。
- **理由**：提交点是那条事务口径的全部，放在驱动里只有一处；让每一步都能提交的话，提交点就可能悄悄挪到别的步上，而那不报错。

- **模糊点**：「换上去」换的是什么。
- **选择**：当前那一份世界由一个持有者拿着，只有驱动在提交那一刻换得了它；结算在它的副本上跑。
- **理由**：别处拿到的永远是一整天：要么睡前那一份，要么推进完的那一份。农场节点读的就是它。

- **模糊点**：提交之后的步出错怎么办。
- **选择**：照常抛出去，不变成「这一天没有推进」。
- **理由**：那时存档已经写上、世界已经换过，再说「没有推进」就是错话；那是一个缺陷，该当场看见。

- **模糊点**：摘要怎么交给界面。
- **选择**：醒来那一步调一个交出摘要的口；摘要是从这一天记下的变化算出来的一份，不另存，也不进存档。
- **理由**：交出在提交之后，写档没成的那一天它一次都不被调，玩家看到摘要就意味着这一天真的过了。

### 偏离

- **方案怎么说**：写档那一下是存档那几条的事。
- **实际怎么做**：农场节点交给结算的写法在本条只占位、什么都不写、当作写成了；读写文件随 `GP-153` 接上。
- **为什么**：读写文件在 `GP-153`；本条只到「写成了才算数」这条口径。

### 权衡

- **提交之前的出错一律接住**：哪一步的缺陷都会变成一次「这一天没有推进」，原因原样带着出错那一下的说法。没选只接住写档那一种：别的步出错时若照常抛出去，副本是丢了，可农场那一侧会以为这一天推进到一半。
