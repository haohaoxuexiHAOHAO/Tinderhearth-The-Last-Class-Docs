# GP-31：`design/技能系统.md`

## 目标

把一个战斗技能要声明的字段写在一处，让加技能变成填表而不是写代码。

## 来源

- PRD：[`spec/prd-growth-skill-damage.md`](../prd-growth-skill-damage.md) 的 `US-004`
- 已有的上游事实散在[角色与成长 · 书 → 学会 → 练熟](../../canon/gameplay/角色与成长.md)（书学会、实战值练熟、档位解锁宝石孔）与[角色与成长 · 装备：宝物与宝石](../../canon/gameplay/角色与成长.md)（每技能 2–3 孔、孔位不分类型、正负面词条并存）。

## 依赖

`GP-32`（技能要声明自己打哪一类伤害、带多少穿透，那些量的定义在伤害系统）与 `GP-34`（技能位只装主动、光环不设上限）。

## 验收标准

- [ ] 新文档按 [SYSTEM 模板](../../templates/SYSTEM.md)八节写全，`upstream` 指[角色与成长](../../canon/gameplay/角色与成长.md)，并被正典链接到。
- [ ] 字段表列全一个战斗技能要声明的东西：伤害类型、倍率、元素与施加概率、两种穿透、耗蓝量、读条形态（瞬发或读条）、冷却。
- [ ] 写明**每个技能各有自己的冷却下限值**，且下限不得为零。
- [ ] 主动、被动与光环三种形态各自占不占槽位写清，与 `GP-34` 收窄后的技能位一致 —— **只有主动占位**。
- [ ] 光环不设数量上限，取而代之的约束写全，每条各写自己防的是什么：
  - **同类只取最大，不叠加**；「同类」的判据是**它修饰哪个量**（改物理攻击的算一类、改减伤的算一类），不按技能名也不按元素 —— 不写判据的话，每加一个光环都要重新争一次它算不算同类。
  - **每个光环必须同时带正面与负面影响**，与[角色与成长 · 装备：宝物与宝石](../../canon/gameplay/角色与成长.md)对宝物宝石那条同理同因。这是替掉数量上限的主力：取舍从「装哪几个」变成「愿意吃哪些代价」，而全开等于把全部负面也一起开。
  - **负面必须可感** —— 不得是「对任何构筑都无所谓」的那一种，判据是它落在这个角色真的会用到的量上。写明这一条**只有人工验收**：能机判的只有「有没有负面项」。
  - 明确**不做总修正上限这类硬钳**（玩家看不出为什么第五个光环没效果），也**不给光环作用半径**（它不是范围效果，开着就生效）。
- [ ] 可测试：同类光环叠加被拒 —— 构造两个改同一个量的光环同时在场，生效的只有量级更大那一个。
- [ ] 可测试：无负面项的光环定义**载入时被拒**（与[`生产系统`](../../design/生产系统.md)那条「净产出自己燃料的设备载入时被拒」同一形状）。
- [ ] 宝石孔**按实战值档位解锁**、孔位不分类型；宝石改的是机制不只是数字，并给出「改机制」的判据 —— 它换掉了这个技能的某个字段或某条行为，而不是只乘一个系数。
- [ ] 边界那一节写明**生活技能不在本页**：「技能」这个词在正典里同时指两类，本页只装战斗技能，熟练度归 `成长系统`。
- [ ] 文档里一个玩法数值都没有。
- [ ] `python tools/check_docs.py` 0 项必须修复。
