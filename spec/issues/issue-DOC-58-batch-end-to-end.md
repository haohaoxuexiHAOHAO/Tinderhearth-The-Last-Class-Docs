# DOC-58：这一批的端到端与交叉核对

## 目标

用两条命令加三轮人工对照，看出这一批有没有和正典打架、有没有改漏某处说法、有没有踩别人写死的不变式。

## 来源

- PRD：[`prd-progression-and-endgame.md`](../prd-progression-and-endgame.md) 的 `US-009`
- 起因：本批同时动新文档、正典链接与好几份已交付文档，**两份以上互相引用的东西不可能各自独立跑绿** —— 所以要有一条专门在最后合并着验的条目。

## 依赖

本批其余全部条目。

## 验收标准

### 两个入口

- [x] `python tools/check_docs.py` **0 项必须修复、0 条提示**，并记下它自报的覆盖量（文档份数／节名引用／长期规格／行尾）。**收尾时最后再跑一次，用那一轮的数字** —— 上一批实测过：后续编辑会把先抄下来的覆盖量顶过期。
- [x] 动了[`数值模型`](../../design/数值模型.md)或[内容规模基准](../../canon/gameplay/玩法定位.md)就跑 `python tools/simulate_week.py` 与 `--check-doc`，**两个方向都记下自报的覆盖量**；没动就写「不适用」并说明为什么。
- [x] 代码仓 `python tools/verify.py` 记**不适用** —— 纯文档批次没有改动对象，不留空。
- [x] 本批的反证是新文档验收里的必做项，条目里记**「不适用（已记账）」而不是「通过」**。

### 交叉核对分三轮

- [x] 第一轮按**词**：搜本批新词（推进状态、标记、解锁、关闭条件、参与者名单这几组），查「同一样东西两个名字」。
- [x] 第二轮按**词**：查「同一条结论抄了理由」—— 重点是那几处「不占一步」各自的理由互不重复，以及「读当前档位不需要闩锁」与「失衡那一位只置位」两条的理由没有互抄。
- [x] 第三轮按**词**：查「等某一批」这类写成散文的状态（「还没定」「值等那边」「届时重写或删」）。
- [x] 按词那几轮**必须分区**：只有活文档（`canon/` 与 `design/` 根下）里出现过期说法才算失败；`spec/` 下的过程件在描述「从什么改成什么」，出现旧说法是应该的。
- [x] 按**量级数字**搜一轮：查「同一个数两个家」（节点数、结局条件条数、支线条数、改造项数这几个尤其容易被复述）。
- [x] 按**不变式**核一轮：列出**一串「应当一个字未改的文件」并逐份确认 `git diff` 为空**（[结算顺序（固定，不得改动）](../../canon/gameplay/时间与经营.md)所在那份的那一节、[ADR-0010](../../decisions/ADR-0010-文档体裁与系统文档归位.md)、`archive/` 下全部、以及本批不该碰的那几份系统文档）；**被改过的那几份单独看一遍 `git diff`**，确认只动了引用与本批答完的那几句。
- [x] 每一轮各自**自报扫到多少行／多少处**；扫到 0 行一律当失败。
- [x] 假命中自己判掉并在本条写明哪几处是假命中 —— 机器分不出两处说的是不是同一件事，这是人看的那一半。

### 临时资源

- [x] `temp/` 收尾时只剩 `README.md`；设计仓 `logs/` 清掉。

## 实现笔记

### 设计决策

- **模糊点**：按词那几轮怎么判「过期」—— 命中数很大（本批那几个词合起来上百处）。
- **选择**：**分区**。只有活文档（`canon/` 与 `design/` 根下，加 README、WORKFLOW 与 `decisions/`）里出现过期说法才算失败。
- **理由**：`spec/` 下的过程件在描述「从什么改成什么」，出现旧说法是应该的；`archive/` 是只读历史。不分区的话这几轮会报几十处命中，那等于没有检查。

- **模糊点**：三轮怎么分才不重复。
- **选择**：按**词**（分三遍：本批新词、容易互抄的那几组理由、写成散文的状态）、按**量级数字**、按**不变式**。
- **理由**：每一轮各自查出过东西，而且互相查不出对方那一类 —— 按词查不出「同一个数两个家」，按数字查不出「理由互抄」，两者都查不出「新加的动作踩了别人写死的东西」。

### 偏离

- **方案怎么说**：按词那一轮「跑两遍以上」。
- **实际怎么做**：跑了三遍，而**第二遍抓到一处真错**（不在方案预期的那几处里）：那份名单不只在已知那一页展开，[`统计事件总线系统`](../../design/统计事件总线系统.md)也把它逐条列了出来并各抄了一句理由 —— 而那份清单当时已经漏了一项。
- **为什么**：第二遍问的是「同一条结论的理由有没有互抄」，而第一遍只问「新词有没有第二个家」。修法与根因记在 `DOC-54`。

- **方案怎么说**：不变式那一轮「列一串应当一个字未改的文件并逐份确认为空」。
- **实际怎么做**：照做，但**有一份刻意不在那张清单里** —— `archive/spec/GP-43-economy-and-building/issue-DOC-31-batch-end-to-end.md` 被改了一处（去掉指向已删提案的链接）。
- **为什么**：那处改动是删文件带出来的断链，理由与最小动作记在 `DOC-55` 的「偏离」。把它留在清单里会让那一轮报一个已知且已解释的失败。

### 权衡

**「把按词交叉核对落成 `tools/` 入口」第四次被排掉。** 机器搜得出一个词出现在几处，**判不出那几处说的是不是同一件事** —— 本批那处真错正好又说明一次：好几页都写着「不占一步」，机器看到的是相同的短语，而要判的是那几条**理由**互不重复。留一个没有判定能力的守卫比没有守卫更坏。**按词的脚本只做一件机器做得了的事**：分区、列出命中、自报行数；判断留给人。

### 待确认

无。**有两处假命中自己判掉了**：搜「里程碑」命中[文案写作规范](../../production/文案写作规范.md)那条「不含开发术语与元信息」（它说的是台词里不许出现里程碑编号，与推进无关）；搜「闩」在活文档里的命中全在[`人际系统`](../../design/人际系统.md)与它的索引行，那是它自己在解释为什么不需要闩锁 —— 该在。**机器分不出这一类，这是人看的那一半。**
