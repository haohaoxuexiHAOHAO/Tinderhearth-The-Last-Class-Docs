# DOC-156：画石壁那几步写进指南

## 目标

作者照[一块地能种出东西](../../reference/godot/一块地能种出东西.md)的第二步就画得出、配得上石壁那一套；检查报错时照症状表改得过来。

## 来源

- PRD：[`spec/prd-shore-stone-wall.md`](../prd-shore-stone-wall.md) 的 `US-004`。

## 依赖

- `ENG-36`：外圈模板怎么出、报错长什么样，照代码写，代码得先定下来。
- `DOC-155`：说理由的地方指向场景绘制约定那一节，不复述。

## 验收标准

- [x] 可核对：第二步的素材表写明草与浅水那一套是石壁；写明先用 `--emit-ring` 出四个方向的外圈模板再画。
- [x] 可核对：「看不到就是」那张表写明检查报某一张某条边不对时怎么看、怎么改，按代码里的报错原文写。
- [x] 可核对：「跑一遍验收」加上石壁那几行，各有行名，供 `ENG-41` 的实机清单对号。
- [x] 可核对：设计仓 `python tools/check_docs.py` 0 FAIL。

## 实现笔记

### 设计决策

- **第二步末尾多一小节「把草与浅水那一套画成石壁」，排在「给地面铺上纹理」后面**：换的只是一张图，场景一格不改；「纹理铺到石壁」那一眼要先配好纹理。素材表里草与浅水那一行指过来。
- **一张表把四个岸对到图块的哪几条边、检查报错里怎么叫、声明里叫什么**：报错按两种地形谁在哪一边说（`ENG-36`），作者从一行报错就认得出是哪一岸；告诉我某一岸画什么时，我照这张表落到声明的哪一个键。
- **「做什么」那张表多一列「谁」**：写声明与提交是我这一侧的事，夹在作者那几步中间，不写进表里顺序就断了。
- **模板出到 `art-source/self-material/tiles-template/`，不出到 `temp/`**：那个目录本来就放另外几套的环形模板与 Aseprite 工程（美术源件那份说明的「还缺的素材」一节），模板是画的源件、不是用完就删的东西。出模板会把另外两套的模板重写一遍，实测与原来那几张逐像素相同。
- **把会过不了的那一段写明**：出模板时新声明判的还是旧图，检查报外圈对不上、`EXIT=1`；画完覆盖上去之前 `verify.py` 双网格那一步也过不了。不写的话，作者头一回出模板就会以为坏了。
- **症状表引的是实测出来的原文**：拿当前那一套的副本逐样改坏、跑检查，指南里引的每一种报错都对过一遍，结果在下面。
- **「跑一遍验收」的行名按 `US-002` 的格子拆**：北岸、南岸、东西两岸、拐角、纹理、停在哪各一行，`ENG-41` 的清单一行对一格。
- **顺带改的几处**：「做完是什么样」写上水边是一道石壁、人停在墙顶；铺纹理那一小节「不要用主色」那一条的例子加上石壁；「卡住了：按症状查」加一行指到新那一小节的表；[从哪里开始](../../reference/godot/从哪里开始.md)里这一篇那一格的「你搭」「我写」「怎么算做完」「台账」跟着补。那一格列的是这个里程碑要搭什么、算不算做完，漏了这一套，里程碑的说法就与这一篇对不上。

### 偏离

- **方案怎么说**：第二步「看不到就是」那张表写明检查报错怎么看、怎么改。
- **实际怎么做**：写在新那一小节自己的「看不到就是」里，「卡住了：按症状查」那张总表加一行指过去。
- **为什么**：第二步里每一小节各有一张「看不到就是」，刷地那一张管的是 Godot 里配错，画图时的报错放进画图那一小节，照着做的时候不用往回翻。

### 权衡

- **声明先写进工作区、不提交，模板用同一个入口出**：换成我拿一份临时声明另出模板，`verify.py` 中间就不会过不了；可那样作者跑不了指南里那条命令，以后别的一套要分方向时还得再想一遍怎么出。现在的代价是画图那段时间检查报对不上，指南里写明了。
