# GP-55：`design/统计事件总线系统.md`

## 目标

让「一条统计事件长什么样、谁发、没人订阅时怎么办」只写在一处，从而让成就与统计将来只订阅它，而不用回头翻遍全部系统补埋点。

## 来源

- PRD：[`prd-save-settlement-and-stats-bus.md`](../prd-save-settlement-and-stats-bus.md) 的 `US-003`
- 起因：[玩法定位 · 成就要靠统计事件总线，不能事后补埋点](../../canon/gameplay/玩法定位.md)写明**发事件这件事必须从第一天就做**，而到本批**会发埋点的系统全都已经存在了** —— 再晚一批就会出现「已经写完却没留挂点」的系统，那时补它要回头改每一份。

## 依赖

无强依赖。**与[`存档系统`](../../design/存档系统.md)（`GP-54`）、[`每日结算系统`](../../design/每日结算系统.md)（`GP-56`）互相引用，一起验**（它们各是本页的一个发出者，而本页是它们的一个出口）。

## 验收标准

**结构判断记在 `GP-54` 的实现笔记里**（四样一起判才说得清），本条只需在文档里写出结论与理由。

### 文档骨架

- [x] 按 [SYSTEM 模板](../../templates/SYSTEM.md)八节写全，`type: system`、文件名以「系统」结尾、`upstream` 指[玩法定位](../../canon/gameplay/玩法定位.md)，**并在 `DOC-48` 这一轮就被正典链接到**。
- [x] 一级标题写成一句结论，不是名词短语。
- [x] 写明它**单独成篇的理由不是状态机而是多读者无主** —— 发出者分散在十来份文档里，而成就与统计明确后置、挂在一份还不存在的文档上等于没挂。

### 一条统计事件是什么

- [x] **字段表**覆盖标识、发出者、一组带名字的量；**缺任一必填项在发出时报错**（[ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md)）。
- [x] **「一组量为空」要显式写成空**，与「没写」分得开。
- [x] 写明**发出者是必填而不是自动推断**，理由是推断出来的名字会在重构之后静默变成另一个。
- [x] **总线不自己产出事件**（没有那一格），并写明**这条与[`事件系统`](../../design/事件系统.md)那条「不许自己算」形状相同但理由不同源**。
- [x] **不跑计时器。**

### 谁发、怎么处置

- [x] **已登记的发出者列一张表**，每格指到声明它的那份文档、**本页不复述那几句**；并写明**加一处埋点填的是这张表**，不是在总线上加分支。
- [x] **订阅者不存在时丢弃、不排队**，写明理由（排队等于让它变成一份存储）与代价（上线前的事不计入）。
- [x] **一个订阅者抛出不影响别的订阅者，也不影响发出者。**

### 它与存档、与结算的关系

- [x] **给存档加零个字段**，理由是它没有状态；**并写明这条与[`气泡对话系统`](../../design/气泡对话系统.md)那个零字段结论一样、理由不同源，不许互抄**。
- [x] **成就进度不是本作存档的字段**，写明理由（跨存档）与归处（`ENG-8`）。
- [x] **「首次」类的记账不是本页的**，点明图鉴与引导各自的家。
- [x] 写死一句：**一条统计事件是「发生了」这个瞬间，不是「发生过」这个状态。**
- [x] **不占每日结算任何一步**，**理由自己写**，并把它与已有那几条的分别逐条列出来。

### 收口

- [x] 挂载点列全并写明「到此为止」；**存档那一格与作者填那一格都是「无」**，各写理由。
- [x] 边界那一节写明**不持有**：成就与统计本身、呈现、出本机、计时器、给参数表加量。
- [x] **「必须实机确认项」写明是「无」并说清为什么** —— 本页没有任何表现，空着会被读成漏写。
- [x] 「同名不同物」写明「事件」在本作的第四处，以及发出者与钩子的方向相反。
- [x] 文档里一个玩法数值都没有。
- [x] `python tools/check_docs.py` 0 项必须修复（合并之后才成立）。

## 实现笔记

### 设计决策

- **模糊点**：订阅者还不存在时（成就明确后置）发出的事件怎么处置。
- **选择**：丢弃，不排队、不缓存、不落盘。
- **理由**：排队能让上线前的事也算上，代价是总线立刻变成一份存储 —— 要回答多大、要回答进不进存档、还要回答「重建出来的进度算不算玩家真的做到过」。**那三个问题的答案都不比「不计入」更好**，而不计入是零结构。

- **模糊点**：成就进度算不算存档字段。
- **选择**：不算，归 `ENG-8`。
- **理由**：成就是跨存档的 —— 同一个玩家在哪一位存档里打到都算。写进本作存档要回答「两位存档各打到一半怎么合」，而那个问题在账号级的存储里根本不存在。**顺带划清一条容易混的边界**：图鉴的「已见过」与引导的「已给过」看起来像成就，但它们是各自系统的记账，不是总线的。

### 偏离

- **方案怎么说**：文件名以「系统」结尾。
- **实际怎么做**：叫 `统计事件总线系统.md`，读起来有点叠。
- **为什么**：正典点名的名字是「统计事件总线」，而命名规则要求 `type: system` 以「系统」结尾。改成 `统计事件系统` 会让同一样东西有两个名字，而那比名字拗口坏得多。形状与 `角色动作状态系统`（正典口语叫「动作机」）同类。

- **方案怎么说**：`check_docs` 0 FAIL。
- **实际怎么做**：本条单独跑不绿（指向另外两份新文档，正典反向链接也要等 `DOC-48`）。**那条 0 FAIL 是合并之后才成立的。**
- **为什么**：两份以上互相引用的东西不可能各自独立跑绿。

### 权衡

**「等成就系统存在再做」考虑过** —— 那时才知道要记什么。没选：正典把这条列为必须从第一天就做的事，而到本批会发埋点的系统全都写完了；再晚一批就会有系统已经定稿却没留挂点，而补它要回头改每一份。

**「让各系统自己攒统计数字、成就去读」考虑过**，那是成就系统最省的实现。没选：每个成就都要知道它读的那个系统内部长什么样，于是加一个成就要动一个玩法系统 —— 那正是正典说的「自己插桩」。

**「并进[`事件系统`](../../design/事件系统.md)」考虑过**（两者都叫「事件」）。没选：那一份是「世界里发生了一件事，它有后果」，本页是「某件事被记了一笔，它没有后果」。并进去之后那张后果调用表上会多出一类「什么都不调」的事件，而**那正好会被读成「可以有一格什么都不调」** —— 于是那一份最要紧的承诺被从旁边绕开了。

**结论被重判的条件**：成就与统计真的落地之后，如果本页仍然只有一张字段表加三条规则，那时可以重看它该不该并进成就那一份 —— 判据仍是「它有没有宿主页」。

### 待确认

- **发出者表会随系统长。** 它是索引而不是副本，所以长是对的；但如果有一天它长到比正文还长，那说明该按域分组 —— 那是排版问题，归界面无关的文档整理。
- **订阅与退订要配对**（纪律在代码仓 `CONVENTIONS.md`）。本页照它走，但「一个旁路系统的订阅者泄漏会不会被那条纪律的测试抓到」要等实现才知道。
