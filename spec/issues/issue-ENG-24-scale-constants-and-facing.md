# ENG-24：那几个尺寸常量与朝向取表按新口径落地

## 目标

让代码里的尺寸常量与朝向处理跟上正典的新口径，并把为水平翻转存在的那条路删干净。

## 来源

- [`GP-82` 那一轮的 PRD](../../archive/spec/GP-82-view-and-sprite-scale/prd.md)（**历史背景·非依据**）的 `US-007`：那一轮是纯文档批次，**刻意不改代码**，落点记账在本条。新口径的现行出处是正典与制作规格，清单在那份归档件的「归档三问」里。
- [ADR-0021](../../decisions/ADR-0021-每个朝向各画一套不做水平翻转.md)：朝向改成按朝向取表，于是为翻转存在的那条路变成死代码。

## 依赖

**依赖第一批按新尺寸画的素材。** 理由是验收手段：代码改完而素材还是旧尺寸时，角色在一屏里会显得偏小、纵深带多出一片空地 —— 那不是缺陷，但它长得像缺陷，而实机看是这件事唯一的验收方式。

## 验收标准

### 尺寸常量

- [ ] `rules/UI/UIMetrics.cs`：侧视缩放那个常量与由它派生的两个视野量按新结论处理（取消或改值），注释里写明理由
- [ ] `rules/UI/CameraRig.cs`：两种视角的缩放不再分叉；该类注释里「视角只影响缩放」那段跟着重写 —— 两种视角都不缩放之后，视角在相机这一侧不再影响任何东西
- [ ] `rules/UI/HudLayout.cs` 里乘缩放的那两处、`rules/UI/CameraFeel.cs` 死区那段注释，都按新尺度改对
- [ ] 屏幕震动那条「幅度必须被缩放整除」的检查按新缩放重新判过，并在注释里写明它现在是否还有约束力
- [ ] `rules/Combat/DepthBand.cs` 带宽改成正典重算后的值，带的前后沿与中线跟着变
- [ ] `rules/Combat/CombatFeel.cs` 的命中纵深容差改成新的半排距；单测仍钉住「同排打得到、隔一排打不到」
- [ ] `rules/Combat/DepthBlocking.cs` 的阻挡阈值按同一套关系复核过，改或不改都写明理由

### 朝向与帧框

- [ ] 动画按朝向取对应那一套，**不做水平翻转**，代码里也没有「这个角色翻不翻」的分支
      （俯视那一侧已落地：`src/World/Farm/FarmWalker.cs` 按「动作_朝向」取 SpriteFrames 里那个动画）
- [ ] **缺某一向的素材时载入报错并说清缺谁**（这是 `ADR-0021` 唯一能自动判的那一条）。
      ⚠️ **原先这一格写着「要有用例」，那个口径兑不了，已换掉**：报错必须在引擎层（朝向取的是
      `AnimatedSprite2D` 那份 `SpriteFrames`，规则层看不见它），而测试只测 `rules/`、不引用 `src/`
      （代码仓 `CONVENTIONS.md` 的「测试」一节）。所以它的执行体是**运行时守卫**而不是单元测试，
      验法是在编辑器里故意删掉一个动画、跑一次看它点不点名
- [ ] 帧框从 `src/World/PlayerActor.cs` 那三个全项目常量改成按角色各自声明，缺声明当场报错
- [ ] **俯视那一档的帧框全员同一个，照[玩法定位 · 像素基准](../../canon/gameplay/玩法定位.md)那一格填**；仍然必填、不从正典读（[ADR-0009](../../decisions/ADR-0009-编辑器主导的开发模式.md)：代码不留能用的默认值）
- [ ] **那条框尺寸校验要等素材重导之后再加。** 俯视帧框比本体大一圈是为了容接地影子，而现有俯视素材还是按本体那一档导的 —— 不重导就是本体占满整框、影子没地方画，而**这不报错**。**顺序反了会当场挡住作者重导**：校验先上线，旧素材一进编辑器就报错。所以落地是「作者先重导，代码再加校验」，两步不同时做。⚠️ **它与侧视那条校验形式不同、不能复用** —— 侧视是精灵表，现有那条核的是「高等于帧高、宽是帧宽的整数倍」（[精灵与逐帧动画](../../reference/godot/精灵与逐帧动画.md)）；俯视是逐帧 PNG，核的是「每张恰好等于那个定值」，整数倍在这里是错的判据（一张 72×36 会被放过）

**为什么俯视能全员一个值，而侧视要逐角色量。** 俯视没有伸出本体之外的动作 —— 战斗不在这个视角里，劳作时工具是独立交付的一层（[像素绘制原则 · 劳作动作分层交付，不是一套整帧](../../production/像素绘制原则.md)），不占角色那一圈。侧视要装得下挥武器与翻滚，伸多少只能量出来。所以这一组声明里**俯视那一项现在就填得出，侧视那几项要等试片**。
- [ ] 帧框声明**从三项变四项**：宽、高、地面行，**加锚点列**。原先锚点被「宽 = 2×max(左伸, 右伸+1)」钉死在正中，那条已随 [ADR-0021](../../decisions/ADR-0021-每个朝向各画一套不做水平翻转.md) 删除，所以精灵的横向偏移不能再假定居中
- [ ] 锚点列由导入器从品红锚点像素量出，不要求作者另填

### 指向改过名字的那几处注释

- [ ] `rules/UI/UIMetrics.cs` 图标两档那句注释指着[人物](../../canon/characters/人物.md)里一个**已经改名**的节名（原先叫「32×32 像素可读性规则」）。**代码注释没有守卫查得到**，所以它只能靠这一条记着
- [ ] [战斗与关卡](../../canon/gameplay/战斗与关卡.md)那笔几何账的节名也改过（原先带旧带宽那个数）。**归档时按旧节名搜过代码仓，落在四处**：`rules/Combat/CombatFeel.cs` 两处、`rules/Combat/DepthBand.cs` 一处、`tests/Combat/DepthBandTests.cs` 一处。四处都改成新节名
- [ ] `tests/Combat/DepthBandTests.cs` 那段注释里还抄着旧的「一排几人、要几排」，**按新账改或改成写链接不复述**（正典是那笔账的家）
- [ ] 死代码删干净：`rules/Combat/DepthRendering.cs` 的 `GroundSpan.Mirrored()`、`PlayerActor` 里「朝左时要镜像」那一段，连带 `tests/Combat/DepthRenderingTests.cs` 里测它的那条

### 收口

- [ ] 既有测试里钉着旧数字的那些一起改 —— 它们钉的是**两个数之间的关系**（侧视有效视野与逻辑分辨率、命中容差与排距），关系不变、输入变，所以改期望值不算绕过测试。**改完要能说出每条测试现在钉的是哪条关系**，说不出的那条要么删要么重写
- [ ] `python tools/verify.py` 五步全绿
- [ ] 作者实机确认：打开训练房看角色大小与纵深带宽窄，并看朝左朝右各一遍
