# PRD：背包改成网格 —— 大东西占一块地，图照它的大小画

## 1. 概述

背包现在是一串格子，一格放一堆，每一堆的图都是 16×16（代码仓 `rules/Economy/Bag.cs`，背包页一行四格、每格 22 像素）。作者画的物品最小 16×16，大一点的东西压到这么小就丢细节，所以背包改成 Stoneshard 那种网格：小东西占 1 格，大东西占一块长方形，图照占的格数画。为什么这样定、被放弃的几条在 [ADR-0034](../decisions/ADR-0034-背包与仓库改成网格.md)。

背包与仓库都改、规则一样；东西不能旋转；随身栏改成背包上单独一排一格大的格子，只放占 1 格的东西。

**为什么现在做**：[东西能拿在手上](./prd-items-in-bag.md)做的背包页与随身栏代码已经做完、正等实机。现在改，那一趟实机就不用看一个马上要换掉的样子；物品也还只有作物那一批，现在给每件补占地，只有作物那一批要补。

**排序**：[水边砌一道石壁](./prd-shore-stone-wall.md)那一份在等作者的地形图块表，等图的这段时间改代码的是这一份；图交来时，那一份接图的改动单独提交，不混进这一份。[东西能拿在手上](./prd-items-in-bag.md)的实机里，背包页那两条（`UI-65`、`UI-66`）不再照旧做，由这一份的背包页接替；它其余几条照旧。

**分工**（[ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)）：作者给物品配图标，大东西照它的占地画大图，并做实机；我写占地那一格与它的载入核对、网格背包的规则、随身栏那一排、背包页、存档迁移、测试，以及跟着做的指南。

**做到哪为止**：只有主角的背包。仓库与队友的背包还没做，做的时候照同一套规则（见「非目标」）。

**台账**：`GP-173` 是这一份的端到端，另拆出 `GP-166`、`GP-167`、`GP-168`、`GP-169`、`GP-170`、`GP-171`、`GP-172`、`UI-67`、`UI-68`、`ART-36`、`DOC-158`。它们各交付 `GP-23`（背包与仓库）、`UI-65`、`UI-66`（背包页）、`UI-35`（随身栏读背包）、`UI-63`（物品图标）的一部分。

## 2. 目标

- 一件大东西在背包页里画在它占的那一块上，图就是作者照那块大小画的那张，不缩放。
- 东西进背包时有地方就放进去；凑不出一块够大的空地时被拒，屏上说清是满了还是放不下这么大的，背包一件不变。
- 在背包页里点一堆拿起、点一个地方放下；那里放不下时什么都不变。
- 排序与一键整理之后东西一件不少；摆不下全部时一格不动，并说清原因。
- 随身栏那一排只放得进占 1 格的东西；播种照旧用手上那一格的种子。
- 停掉游戏再进来，每一堆还在原来的位置；改版之前的存档读进来，东西一件不少，手上那几格还在手上。

## 3. 上游约束

- [ADR-0034](../decisions/ADR-0034-背包与仓库改成网格.md)：网格、占地是长方形、不能旋转、放得下与满载的定义、随身栏一排只放占 1 格的东西、C7 的分子改成占的格数。**这是本需求全部结构的来源。**
- [时间与经营 · 背包与仓库](../canon/gameplay/时间与经营.md)：背包与仓库都是网格、一堆占一块、同种堆到上限、满时提示且不自动丢弃。**约束放不下时只拒不丢。**
- [玩法定位 · 像素基准](../canon/gameplay/玩法定位.md)：基础单位 16px，背包里的东西最小占 1 单位、大的占一块长方形。**约束一格的边长与图标尺寸都按它算。**
- [`背包系统`](../design/背包系统.md)：堆的标识是种类加品质、一堆占一块、满载只拒不丢、排序筛选与一键整理的三条硬约束、排序与整理不碰随身栏那一排。**本需求照这一页做，不改其中任何一条。**
- [`物品系统`](../design/物品系统.md)：物品定义那张字段表、每个物品一份图标资源、缺图一次全报。**约束占地是定义上的一格、缺了载入被拒**。
- [像素绘制原则 · 统一视角与光源](../production/像素绘制原则.md)：光从正上方照。**这是不能旋转的理由**。
- [`界面系统` · 手环上：背包](../design/界面系统.md)：这一页要答「我要的东西在哪、还背得下吗」，被拒的原因不许藏。**约束背包页要画出的那几项与两种被拒的说法**。
- [ADR-0015](../decisions/ADR-0015-存档的版本与缺字段口径.md)与 [ADR-0017](../decisions/ADR-0017-版本更新对旧存档的两种后果.md)：全存档一个版本号；能迁就必须迁。**约束背包那一片改形状时版本升一级、旧存档迁过来而不是作废**。
- **依赖**：每一级背包几行几列与 C7 重算归 `GP-7`（本需求先用占位值）；仓库等 `GP-44`；装备、工具这些真正的大东西各等自己的系统。

## 4. 用户故事

### US-001：物品声明占地，图标正好那么大

**描述**：作为作者，我想在物品定义上写它占几格，并且图标尺寸对不上时启动就报出来，以便大东西照大小画、画错了不会悄悄显示错。

**验收标准**：

- [x] 可测试：物品定义多一格占地，宽与高各是至少 1 的整数格；缺这一格，或宽高不是正整数，载入被拒并说清是哪一件、哪一格。
- [x] 可核对：代码仓 `data/items/` 下现有的每一件都补上占地 1×1。
- [x] 可测试：图标的宽高不等于占地乘基础单位时，启动时一次全报，一行一件，写清应有多大、实际多大；变异那一张同样核。
- [x] 可核对：[`物品系统`](../design/物品系统.md)那张字段表加上占地那一行，图标那一格改成「照占地的大小」。

### US-002：背包是网格，有地方才放得进去

**描述**：作为玩家，我想东西进背包时找得到地方就放进去、找不到就明说，以便我知道还背不背得下。

**验收标准**：

- [x] 可测试：同种同品质先合进没满的那一堆，到堆上限再放新的一块；同种不同品质各占一块。
- [x] 可测试：放新的一块时，从上到下、从左到右找第一个放得下它整块占地的位置；那一块里的每一格都必须空着、都在网格里面。
- [x] 可测试：网格里空格的数目够、却凑不出一块够大的空地时，被拒；挪开挡着的一堆之后，同一件放得进去。
- [x] 可测试：一次放进去的那一份放不下时整份被拒，背包一件不变。
- [x] 可测试：被拒有两种原因，分得开：一格空的都没有（满了），与有空格但凑不出这么大的一块。
- [x] 可测试：网格每一级几行几列从配置读，缺了当场报错；没有能用的默认值。

### US-003：随身栏是单独一排，只放占 1 格的东西

**描述**：作为玩家，我想手上那几格只放种子、吃的这类小东西，并且播种照旧用手上那一格，以便手上的东西一眼看得清。

**验收标准**：

- [ ] 可测试：随身栏是背包上单独一排格子，格数照旧与技能位条数相同；它不属于网格，网格里的位置不会挪进它。
- [ ] 可测试：占地大于 1×1 的东西放进随身栏被拒，原因说清是太大；那一堆留在原处。
- [ ] 可测试：新进来的东西先合进同标识没满的那一堆（先找随身栏、再找网格）；还要放新的一块时，占 1 格的先找随身栏的空格、再找网格，大的直接找网格。
- [ ] 可测试：播种取随身栏选中那一格的种子，扣一颗；选中的是收获物时被拒，原因是「不是种子」。随身栏那几条已有的用例照样通过。
- [ ] 可观察：屏幕底边那条随身栏照旧一格 22 像素，画的是随身栏那一排里的东西。

### US-004：在背包页里拿起、放下、合堆、丢弃

**描述**：作为玩家，我想点一堆拿起来、点一个地方放下，以便我自己摆出腾得开地方的样子。

**验收标准**：

- [ ] 可测试：点到一堆占地里的任何一格都是拿起那一堆；放下时，拿起时点的那一格对准现在指的那一格。
- [ ] 可测试：要放的那一块全空着（拿起的那一堆自己原来占的格算空），就挪过去，件数、品质、序号都不变。
- [ ] 可测试：指到一堆同种同品质的东西上时，合进那一堆，到堆上限为止；剩下的留在原处。
- [ ] 可测试：要放的那一块压到别的东西、或者有一格出了网格，就放不下，什么都不变；被压的那一堆也不动，不做互换。
- [ ] 可测试：网格与随身栏之间照同一套挪：占 1 格的两边都能放，大的进不了随身栏。
- [ ] 可测试：丢弃照旧丢整堆、先弹一道确认，取消时一件不变；声明了不可丢弃的被拒并说清。

### US-005：排序、筛选、一键整理在网格里一件不丢

**描述**：作为玩家，我想排一下、整理一下就把东西归好，以便找东西不用翻半天。

**验收标准**：

- [ ] 可测试：排序按当前的键把看得见的那些堆排好先后，再一堆一堆用「第一块够大的空地」从左上往右下摆；三个键各排一次，同键排两次结果相同。
- [ ] 可测试：一键整理先把同标识的散堆并成满堆加至多一个零头，再照排序那样摆；前后总数一件不变。
- [ ] 可测试：照新的先后摆不下全部时，整理与排序都一格不动，屏上说清是摆不下；构造一种「原来的摆法放得下、新摆法放不下」的情形，验它确实没动。
- [ ] 可测试：排序与整理不碰随身栏那一排。
- [ ] 可测试：筛选态下被筛掉的那些堆不挪位，排序与整理只在剩下的地方摆看得见的那些；挪与丢也只对看得见的做。

### US-006：背包页画成网格

**描述**：作为玩家，我想背包页是一张格子挨着格子的网格，大东西画在它那一块上，以便一眼看清每样东西在哪、还剩多少地方。

**验收标准**：

- [ ] 可观察：网格一格 16 像素、格与格之间不留缝；每一堆的图画在它占的那一块上，不缩放；件数、品质点与稀有度框画在那一块上。
- [ ] 可观察：随身栏那一排画在网格上面，每格标着它在随身栏里是第几格。
- [ ] 可观察：拿起一堆之后，指着的地方画出它要占的那一块，放得下与放不下画得不一样。
- [ ] 可观察：选中框与焦点框画在那一块的里面一圈，不压到旁边那一格。
- [ ] 可测试：配置里每一级的背包，整页都放得进手环的内容区，宽与高都算上右边那一列按钮。
- [ ] 可测试：键盘与手柄的方向键能走到每一堆、每一格空地，走不到被筛掉的那些。
- [ ] **作者实机确认**：16 像素的格子线看得清；大东西的图看得清细节；一格里的件数与品质点不把图盖掉太多；拿起、放下顺手；两种被拒的说法看得懂。

### US-007：收获与调试键照新放法进背包

**描述**：作为玩家，我想收上来的东西照新的放法进背包，满了照旧那一株还在，以便换了背包也不丢收成。

**验收标准**：

- [ ] 可测试：收获照旧走生产那条管道进主角的背包；放不下时那一格照旧待收、一件不变，屏上那一行写的是两种被拒原因里的那一种。
- [ ] 可测试：开发期调试键那一批种子照旧先落进随身栏那一排，放不下整批被拒。
- [ ] 可核对：作者画的四颗大宝石（工作区 `gem3.png`，一颗 32×32）各是一件物品：类别是宝石（新加一份类别数据），占地 2×2，声明有品质、变异那一张同原图；名字与价钱先用占位值并标明占位，正式的由作者定。
- [ ] 可测试：调试键能把这几颗大宝石放进背包，供实机看大图；放不下时被拒、说清原因。
- [ ] 可核对：作者把 `gem3.png` 放进代码仓 `assets/self-drawn/icons/` 下，在 Godot 里给四件各配一份图标资源；配完跑代码仓 `python tools/check_art.py`，最后一行 `EXIT=0`。

### US-008：背包进存档，旧存档迁过来

**描述**：作为玩家，我想退出再进来每一堆都在原位，改版之前的存档也照样打得开，以便摆好的东西不会乱、玩过的档不会废。

**验收标准**：

- [ ] 可测试：背包那一片存每一堆在网格里的位置（它左上角那一格），也存随身栏那一排；存进去读出来，每一堆的种类、品质、件数、序号与位置都不变。
- [ ] 可核对：存档版本升一级，最低兼容版本不动。
- [ ] 可测试：上一版的存档读进来：原来开头那几格（随身栏格数那么多）进随身栏那一排、原来的位置不变，其余的按原来的格号从左上往右下摆进网格；东西一件不少。
- [ ] 可测试：同一版的存档缺位置被拒；两堆的位置压在一起，或者有一堆出了网格，载入被拒并说清是哪两堆、哪一堆。
- [ ] 可测试：存档里网格的行列比现在配置的大时，载入被拒并说清两边各多大；小的照新的大小读。

### US-010：网格背包的端到端

**描述**：作为作者，我想一次走完「东西进背包、挪、整理、存档、读回」整条路，以便确认几块拼起来是通的。

## 5. 功能需求

- FR-1：系统必须要求每件物品声明占地的宽与高，单位是格。
- FR-2：系统必须在占地缺失或不是正整数时拒绝载入那件物品。
- FR-3：系统必须在启动时核对每份物品图标的宽高等于占地乘基础单位，变异那一张一样核。
- FR-4：系统必须让一堆占一块与它的物品占地一样大的长方形。
- FR-5：系统必须只在那一块的每一格都空着、都在网格内时把一堆放进那里。
- FR-6：系统必须在放新的一块时按从上到下、从左到右取第一个放得下的位置。
- FR-7：系统必须先把东西合进同种同品质、没满的那一堆，再放新的一块。
- FR-8：系统必须在一份东西放不下时整份拒收、背包一件不变。
- FR-9：系统必须把「一格空的都没有」与「凑不出够大的空地」报成两种原因。
- FR-10：系统必须不提供任何旋转物品的入口。
- FR-11：系统必须让随身栏是背包上单独一排格子，格数与技能位条数相同。
- FR-12：系统必须拒绝把占地大于 1×1 的东西放进随身栏。
- FR-13：系统必须在给占 1 格的东西放新的一块时先找随身栏的空格、再找网格。
- FR-14：系统必须在玩家放下拿起的那一堆时，让拿起时点的那一格对准放下时指的那一格。
- FR-15：系统必须在要放的那一块压到别的堆或出了网格时什么都不改。
- FR-16：系统必须在放到同种同品质的堆上时合进那一堆，到堆上限为止。
- FR-17：系统必须在排序或整理的结果摆不下全部时保持原来的摆法。
- FR-18：系统必须在排序与整理时不动随身栏那一排。
- FR-19：系统必须在筛选态下不动被筛掉的那些堆。
- FR-20：系统必须在存档里存每一堆的位置与随身栏那一排。
- FR-21：系统必须把上一版存档里开头那几格放进随身栏、其余按格号摆进网格。
- FR-22：系统必须在存档里两堆位置重叠或有一堆出了网格时拒绝载入。
- FR-23：系统必须从配置读每一级网格的行数与列数，缺了当场报错。

## 6. 非目标

- **不做旋转**、不做非长方形的占地、不做背包里再装容器、不做重量（理由在 [ADR-0034](../decisions/ADR-0034-背包与仓库改成网格.md)）。
- **不做拖拽**：照旧点一下拿起、再点一下放下，键盘、手柄与鼠标走同一套。
- **不做仓库**：仓库还没做（`GP-44`），做的时候照同一套规则。
- **不做队友的背包页**：队友还没进场。
- **不定每一级几行几列**：先用占位值，正式的值与 C7 重算归 `GP-7`。
- **不做背包升级**：背包等级从哪来仍归 `GP-23`。
- **不加别的物品内容**：除了那四颗大宝石，装备、工具这些大东西跟着各自的系统来；宝石镶进孔里那一套归[`装备系统`](../design/装备系统.md)（`GP-24`），这一份只让它们能放进背包。
- **不改屏幕底边那条随身栏的样子**：照旧 22 像素一格。
- **不做快速使用键**：[`背包系统`](../design/背包系统.md)里那条后手照旧是后手。

## 7. 界面与表现考虑

- **背包页从左到右**：随身栏那一排在网格上面，网格在左，按钮那一列在右，最下面一行写指着的那一堆是什么，与现在同一个次序。
- **格子挨着格子**：现在格与格之间留 4 像素是为了把选中框画在格子外面一圈（代码仓 `rules/UI/BagPageLayout.cs`）。网格不留缝，所以选中框、焦点框改画在那一块的里面一圈。
- **空格那一张、各种框都由界面件生成器出**，与现在的格子件同一条路，尺寸从代码仓 `rules/UI/UIMetrics.cs` 读。物品图标由作者画、作者配。
- **件数与品质点**画在那一块的角上，用迷你字；一格大的东西角上地方小，盖住多少由作者实机看。
- **两种被拒的说法**：一格空的都没有说「背包满了」，有空格但凑不出说「放不下这么大的东西」；整理摆不下说「摆不下，没整理」。都走现有的即时提示，不进手环的事件流。
- **拿起之后**，指着的地方画出要占的那一块，放得下与放不下画得不一样（形状不同，不只换颜色）。
- **背包一页放得下全部，不滚也不分页**：这一页要答「还背得下吗」，整张网格一眼看得全才答得出；挪东西也不用一边拿着一边滚。所以每一级背包的大小以一页放得下为上限，US-006 有测试管着。仓库做的时候它大一个量级（[`背包系统`](../design/背包系统.md)），放不下一页就按整行竖着滚，与[界面绘制约定](../production/界面绘制约定.md)放字那几块同一种滚法。

## 8. 技术考虑

- **现在的形状**（读过代码）：`Bag` 是一串定长的格子，一格一个 `ItemStack`，堆上没有位置；放进去先合堆、再按格号占空格（`Plan`）；排序与整理靠 `keepLeading` 跳过开头几格；随身栏是背包前几格的投影（`rules/UI/CarrySlots.cs`）；存档那一片按格号分列存四项（`rules/Economy/WorldShards.cs`），全存档版本号在 `rules/Foundation/Save/SaveFile.cs`。这几处都要改。
- **格子边长取基础单位**（代码仓 `rules/UI/UIMetrics.cs` 的 `BaseUnit`），不取 `Cell`：`Cell` 是带描边与留白的 22 像素那一档，屏幕底边的随身栏照旧用它。
- **图标尺寸现在没人核**：`rules/Economy/ItemIconCheck.cs` 只核配没配；`tools/check_art.py` 只核画布是不是 16 的整数倍，不知道每件该多大。占地写在物品定义里，所以这一条只能在启动时核。
- **焦点走不走得顺，未验证**：背包页现在靠 Godot 自带的焦点按方向找下一个控件，块大小不一时会不会跳着走，要做出来用方向键走一遍才知道。走不顺就改用按格走的光标，代码仓 `rules/UI/PanelNavigation.cs` 里有一个 `GridCursor`，现在没有人用。
- **新进来的东西先找随身栏**，与现在「先占背包开头那几格」是同一个次序，调试键那一批种子照旧落在手上；大的东西进不了随身栏，直接找网格。
- **占位值**：每一级网格宽 6 格，四级分别高 2、3、4、5 格。宽 6 格与随身栏那一排一样宽；第一级网格 12 格加随身栏 6 格共 18 格，让 C7 落在 70%–100% 里。值写在代码仓 `data/config/game.json`，标明是占位；设计仓 `design/numeric-model-params.json` 那一项跟着改形状。
- **存档迁移**：现有物品全占 1 格，所以上一版的每一格都能原样放进新形状，照 [ADR-0017](../decisions/ADR-0017-版本更新对旧存档的两种后果.md)「能迁就必须迁」，不升最低兼容版本。
- **整理怎么摆**：照排序的先后一堆一堆找第一块空地，这是最简单的摆法，摆不紧；摆不下全部就不动，所以它不会把东西摆丢。摆得更紧的办法（先放大的）会打乱排序的先后，不用。

## 9. 待确认问题（阻塞项）

无。拿着的一堆压到别的东西上时放不下、什么都不变，写在 US-004；实机看大图用作者画的那四颗大宝石，写在 US-007。

## 10. 成功判据

- 一件大东西在背包页里画在它占的那一块上，图的大小等于占地乘 16 像素。
- 空格够数却凑不出够大的空地时被拒，背包一件不变，屏上写的是「放不下这么大的东西」。
- 排序与一键整理前后，东西的种类、品质与件数一件不差；摆不下全部时一格不动。
- 大东西放不进随身栏；播种照旧从随身栏选中那一格扣一颗。
- 写档读回，每一堆的位置不变；上一版的存档读进来，东西一件不少，手上那几格还在手上。
- 设计仓 `check_docs.py` 0 项必须修复，代码仓 `python tools/verify.py` 每一步都过。
