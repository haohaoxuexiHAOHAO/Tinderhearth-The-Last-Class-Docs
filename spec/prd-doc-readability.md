# PRD：系统文档读得懂

## 1. 概述

`design/` 下那批系统文档写得准，但读不动。三个毛病叠在一起：

1. **大量自造词没有解释。** 扫一遍 `design/` 下那三十份系统文档：`判据` 出现在二十九份里，`挂载点` 二十七份，`量纲` 与 `反证` 各二十六份，`载体` 二十四份，`读口` 与 `分片` 各二十一份。这些词各有确切含义，但**全库没有一处说过它们是什么** —— 新读者只能从上下文猜，而猜错不会被任何东西纠正。
2. **该画图的地方在写散文。** 项目自己的画图约定已经是 Markdown 内嵌 Mermaid（文本源能进 Git、能 diff，而检查器只扫 `.md`），但 `design/` 下**一处 Mermaid 都没有**。最典型的是[`角色动作状态系统`](../design/角色动作状态系统.md)那张十八行的流转表 —— 它描述的是一台状态机，而状态机用表读要在脑子里自己连线。
3. **句子长、嵌套深。** 一句话里套三个从句加两个转折，信息密度高但读一遍抓不住。

后果不是「不好看」，是**查得慢、容易误读**。这批文档的用途是实现时反复回来查「这件事归谁」，读一句要回看三遍就等于没有这个用途。

## 2. 目标

一个没读过这批文档的人，打开任意一份系统文档，能做到三件事：

- **看懂每个自造词** —— 本页自己的词在本页开头的术语表里，跨页共用的词在一份共用术语表里，两处合起来无遗漏。
- **先看图再读字** —— 有状态机、有顺序链、有依赖关系的文档，各有一张图；图回答什么问题写在图旁。
- **读摘要首段就知道这页答什么** —— 不需要先读完八节才明白这页管的是哪一块。

同时守住一条硬边界：**本轮不改任何结论。** 改的是怎么说，不是说的是什么。

## 3. 上游约束

- [ADR-0010](../decisions/ADR-0010-文档体裁与系统文档归位.md)：系统文档的家在 `design/` 根、骨架固定不许多不许少不许换顺序。**约束「术语」这一节只能作为骨架的一节加进去，并要同批改检查器** —— 不能做成可选节，骨架一旦可选就等于没有骨架。它把节数写死在一份已接受的 ADR 里，所以本轮要取代那一条，见下。
- [ADR-0019](../decisions/ADR-0019-系统文档骨架加术语一节.md)：骨架加第九节「术语」，只取代上面那一份的骨架那一条。**它是本轮骨架改动的权威落点**，被放弃的四个候选与落地顺序都在那一份，本页不复述。
- [WORKFLOW §3](../WORKFLOW.md) 反漂移那五条：事实只许有一个家。**约束术语表的分家办法** —— 一个词在二十多份文档里各写一遍定义，就是给它开二十多个家。
- [WORKFLOW §6](../WORKFLOW.md) 执行体表：规则要么有守卫，要么写明为何只能人工。**约束「通俗易懂」这件事怎么验收** —— 机器量得出句长与生词覆盖，判不出一句话通不通顺。
- [ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)：表现类的东西由作者实机验收。**约束本需求每批的准出** —— 最后一道判定是作者自己读一遍说读得懂了。
- [templates/SYSTEM.md](../templates/SYSTEM.md) 那两条总纪律（不写数值、只写结果不写过程）。**约束新加的术语节与图不得夹带数值，也不得写成沿革**。

## 4. 用户故事

### US-001：共用术语表落地

**描述**：作为一个第一次读系统文档的人，我想要一处能查全部跨页共用词的地方，以便不用在二十多份文档里各找一遍。

新建 [`reference/术语表.md`](../reference/术语表.md)（`type: reference`）。放 `reference/` 的理由：它不是系统（没有实体与状态）、不是模型（没有量与判据）、不是提案也不是决策，而 `reference/` 装的正是「给人查」的东西。**名字不带「设计」二字**，那是体裁词。

**词条形状分两类，判据是「这个词在别处有没有权威定义」**：

- 有的（`载体`、`分片`、`续玩点`、`档位`、`派生表` 这类领域词）：写一句白话，**再链回定义它的那一节**，不复制那一节的正文。
- 没有的（`判据`、`反证`、`承重项`、`读口`、`量纲`、`闸门` 这类方法论词）：这份表就是它们的家。

**验收标准**：

- [ ] 可核对：该文件存在，文件头四项齐全，并已接入[总索引](../README.md)的文档地图（否则检查器报「从 README 无法到达」）。
- [ ] 可核对：每个领域词条都有一条指向权威定义那一节的链接；检查器的节名引用守卫对这些链接全部通过。
- [ ] 可核对：进这份表的判据（一个词出现在几份系统文档以上就归这里）**只在这份表里写一次**，模板与别处只链接、不复述那个数。
- [ ] 可测试：三条新守卫各有一次故意撞失败路径的记录（见 US-005）。

### US-002：SYSTEM 模板补齐

**描述**：作为下一份系统文档的作者，我想要模板直接告诉我术语怎么写、什么时候该画图、图怎么防过期，以便不用回头对着别人的文档反推规矩。

改 [templates/SYSTEM.md](../templates/SYSTEM.md)：骨架从八节变九节（「术语」插在「摘要」与「上游约束」之间）；「摘要」一节补上「首段是白话导语」这条要求；新增一段写图的规矩。

**图的规矩写四条，不列图型对照表** —— 图型怎么选是「怎么执行」，家在画图技能里，模板复述一遍就是又开一个家：

- 一张图回答一个问题，节点数有上限（上限那个数在画图技能里，模板不复述）。
- 图旁必须写它在什么改动之后需要重画，**形状固定**（模板给出那一行长什么样，守卫按它判）。
- **图不得引入正文与表里没有的事实** —— 守卫按标签子串核对。
- 同一事实由表与图各表达一次时，**表是权威**，并在图旁写明。

**验收标准**：

- [ ] 可核对：模板里九节的顺序与检查器里那份可执行副本逐字一致。
- [ ] 可核对：模板给出了重画条件那一行的固定形状，而守卫判的就是这个形状（两处不许各写一个样子）。
- [ ] 可核对：模板没有复述共用术语表的收词判据、图型对照表、节点数上限与句长上限 —— 那四个数各有自己的家。
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL。

### US-003：三份样板，覆盖三种图型

**描述**：作为作者，我想先看三份改完的文档定风格，以便不满意时返工面是三份而不是三十份。

三份的挑法是**各代表一种图型**，好让一次就看到风格全貌：

| 文档 | 它最难读的那一块 | 画什么 |
| --- | --- | --- |
| [`角色动作状态系统`](../design/角色动作状态系统.md) | 那张流转表描述的是一台状态机，用表读要自己在脑子里连线 | 状态图 |
| [`伤害系统`](../design/伤害系统.md) | 一次命中的结算顺序写死了，但顺序藏在散文里 | 流程图 |
| [`成长系统`](../design/成长系统.md) | 派生表是下游读角色数据的唯一入口，「谁读谁」现在靠通读推 | 依赖图 |

每份都做齐四样：术语节（只列本页自己的词）、白话导语、图、正文长句拆短。

**验收标准**：

- [ ] 可核对：三份各有一处术语表，表里每个词在本页正文出现过，且没有一个词与共用术语表重复。
- [ ] 可核对：三份的摘要首段不使用任何未在本页术语表或共用术语表里出现过的自造词。
- [ ] 可核对：三张图各写明了回答什么问题与什么时候重画；表与图重复的地方写明了表是权威。
- [ ] 可核对：`git diff` 逐处复核，**没有一条结论被改动**（改的只有措辞、顺序与新增内容）。
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL。
- [ ] **作者实读确认**：作者打开这三份读一遍，判定「读得懂了」并认可风格。可读性没有机器判据（[ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md) 的分工）。

### US-005：守卫收口：骨架升九节，另加六条判定

**描述**：作为半年后往这批文档里加东西的人，我想要机器拦住「忘了写术语」「术语写了两份」「图静默腐烂」，以便这次收拾完不会慢慢滑回去。

全部文档都填实之后做一次收口：把术语节从过渡期的三级标题升成二级标题，同批把检查器里的骨架从八节改成九节；另加六条新判定。

**新判定各挡一种会静默发生的错**：

| 判定 | 它挡的是 |
| --- | --- |
| 术语节里的每个词必须在本页正文出现过 | 抄一张与本页无关的表 |
| 同一个词不许同时出现在共用术语表与某份文档的术语节 | 一个词有两个家 |
| 共用术语表里的每个词条至少被一份系统文档用到 | 那份表只增不减地膨胀 |
| 每个 Mermaid 块旁必须有那一行重画条件 | **图静默腐烂** —— 它最主要的失效方式 |
| Mermaid 里的标签必须能在本页正文或表里找到 | 图偷偷引入了正文没有的事实 |
| 正文段落里的单句不超过字数上限 | 长句重新长回来 |

**验收标准**：

- [ ] 可测试：骨架判定对「缺术语节」「术语节放错位置」「多一节」各报一次失败，对九节与九节加附录不报。
- [ ] 可测试：术语那三条各撞一次失败路径（造一个不在正文里的词、造一个两处都有的词、往共用表加一个没人用的词），各自报错并说清是哪个词。
- [ ] 可测试：图那两条各撞一次失败路径（删掉一张图的重画条件行、往图里塞一个正文没有的标签），各自报错并指出是哪一张图、哪个标签。
- [ ] 可测试：句长那条撞一次失败路径，且**表格行、代码块与 Mermaid 块里的长行一条都不报**（误报面的反证）。
- [ ] 可核对：句长上限那个数只出现在守卫里一处；它是按实测分布定的，不是拍的。
- [ ] 可核对：`python tools/check_docs.py` 在全部文档上 0 FAIL。
- [ ] 可核对：`git status` 干净 —— 撞失败路径用的临时改动已全部撤回。

## 5. 功能需求

术语：

- FR-1：每份系统文档必须在「摘要」之后、「上游约束」之前有一处「术语」，用表列出**只有本页在用**的词。
- FR-2：一个词出现在多份系统文档（阈值写在共用术语表里）时，它的解释只许写在共用术语表，各页术语节不得重复。
- FR-3：本页确实没有专属词时，术语节写一行「无」并说明为什么 —— 与骨架其余各节同一条规矩。
- FR-4：共用术语表的每个词条要么自己就是权威定义，要么链回定义它的那一节，不复制被链那一节的正文。

白话：

- FR-5：每份系统文档的「摘要」首段必须是白话导语，说明这一页在解决什么问题、读完能做出什么判断。
- FR-6：导语不得使用未在本页术语节或共用术语表里出现过的自造词。
- FR-7：正文里一句话套多重从句时必须拆开；拆句不得改变这句话的结论。

图：

- FR-8：有状态机、有固定顺序链或有依赖关系的文档必须各有一张图；判定为不需要图的必须写明理由。
- FR-9：一张图只回答一个问题；图旁必须写出它回答的是哪个问题。
- FR-10：每张图旁必须写明它在什么改动之后需要重画，**写成固定的、可机检的一行**（形状定在模板里）。
- FR-11：图不得引入正文与表里没有的事实。
- FR-12：同一事实由表与图各表达一次时，图旁必须写明表是权威。
- FR-13：图一律用 Markdown 内嵌 Mermaid，不产出图片与 HTML。

守卫：

- FR-14：检查器必须按九节判系统文档与跨系统模型的骨架，顺序一并判。
- FR-15：检查器必须判术语节里的每个词在本页正文出现过。
- FR-16：检查器必须判同一个词不同时出现在共用术语表与某份文档的术语节。
- FR-17：检查器必须判共用术语表里的每个词条至少被一份系统文档用到。
- FR-18：检查器必须判每个 Mermaid 块旁有一行重画条件，缺了报失败并指出是哪一张图。
- FR-19：检查器必须判 Mermaid 块里的标签能在本页正文或表里找到（按子串匹配，所以「超时」对得上「超时自然站起」）。
- FR-20：检查器必须判正文段落里的单句不超过字数上限；表格行、代码块与 Mermaid 块不判。**上限的值只写在守卫里**，本页与模板都不复述。
- FR-21：`tools/` 下新增一个**只列不判**的入口，报出「正文里反复出现、两张术语表里都没有」的生词候选；它的退出码恒为 0，不得被当成门禁。

## 6. 非目标

- **不改任何结论。** 本轮只改怎么说。改写过程中发现的真错按「超出边界不许顺手修」记进台账，不在本轮修。
- **不给自造词改名。** `读口` 不改成「只读查询接口」这类。理由：改名要跨两个仓加 `.kiro` 按词搜改，而已归档的文件按规矩不许用今天的说法改写，于是活文档与归档件会对不上 —— 而那个对不上没有任何机器能发现。解释它比改掉它便宜。
- **不动 `canon/` 与 `archive/`。** 正典的可读性不在本轮；归档件按规矩冻结。
- **`decisions/` 只加一份、只改一行文件头。** 骨架从八节变九节要取代 [ADR-0010](../decisions/ADR-0010-文档体裁与系统文档归位.md) 已经写死的那一条，所以本轮新增 [ADR-0019](../decisions/ADR-0019-系统文档骨架加术语一节.md)，并给 ADR-0010 的文件头加一行 `superseded_by` —— **那份 ADR 的正文一个字不动**（[WORKFLOW §4](../WORKFLOW.md)：已接受的 ADR 不得用今天的理由改写当时的背景，取代关系只写进双方文件头）。除此之外不碰任何 ADR。
- **不动 DESIGN、ADR、ISSUE、PRD 四份模板。** 只动 SYSTEM。提案体裁等真有第二份提案时再说 —— 现在改它等于为一份文件定规矩。
- **不产出图片与 HTML。** 二进制图会逃出检查器管辖，而且下次要改只能重画。
- **不改 `数值模型` 的任何公式与参数值。** 它的体裁是跨系统模型、同样走本轮的骨架与术语，但值一个都不动。
- **不重排骨架的其余八节，也不合并任何节。**
- **不做自动改写。** 不写脚本批量替换句子 —— 看不到上下文，diff 也无法逐处复核。

## 7. 界面与表现考虑

不适用（纯文档需求）。唯一的「表现」是排版：图与表挨着放时先图后表，图旁那行说明与图同屏，不要滚一屏才看到它在讲什么。

## 8. 技术考虑

**骨架守卫与过渡顺序在 [ADR-0019](../decisions/ADR-0019-系统文档骨架加术语一节.md) 的「落地要求」里，本页不复述。** 一句话交代形状：过渡期术语写成「摘要」节内的三级标题，全部填实后统一升二级并同批改守卫 —— 这样门禁任何时刻都是绿的。被排掉的另外两条路与各自的代价在那一份。

**Mermaid 与既有守卫的关系是推断，不是实测。** 读了守卫代码：骨架判定只看 `## ` 开头的行；代码路径判定要求反引号；自计数判定要求「行尾冒号 ＋ 紧跟清单」；节名引用判定只看 Markdown 链接。Mermaid 块不触发这四条中的任何一条。**但这是读代码得出的推断** —— 第一份样板画完跑一次 `python tools/check_docs.py` 才算实测，第一批必须报这个结果。

**Mermaid 里的中文标签遇到括号、斜杠、引号时要不要加引号包住，待验证。** 验法：第一张图画完后在能渲染 Mermaid 的编辑器里打开看一眼，渲染不出来就给标签加引号。

**句长上限那个数按实测定，不拍。** 做法：先把那条判定跑成只列不判，看这三十份的句长分布，再把上限定在噪音可接受的位置。定之前不许开成失败 —— 一条误报多的门禁会被绕过，而被绕过的门禁比没有门禁更坏。

**画图技能里有一处过期说法要顺手改掉**：它写着本项目当前没有代码、`ENG-2` 未落地，而那个编号已归档、代码仓在跑。按「完成或归档一个编号时按编号搜两个仓加 `.kiro`」那条，本轮改掉。

**根治边界写明，不假装它已被解决。** 收口之后仍然有两件事机器判不了：

- **新写的自造词没人解释。** 机器不知道哪个词是「自造的」—— 要判它就得有一份普通词白名单，而白名单是每写一份文档就补一格的债（`ENG-18` 留下的判断方向：守卫的默认面要是「全部」）。所以只做到只列不判，由人扫一遍。
- **一句话通不通顺、这份文档该不该画图。** 归作者实读（[ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md) 的分工）。

真正让这件事不再复发的不是守卫，是**模板**：下一份文档从九节开始写，术语节是必填节，写的人当场就填了。这次量大，是因为那三十份是在没有这条规矩时写完的 —— 一次性清欠，不是以后每轮都交的税。

## 9. 待确认问题（阻塞项）

无。四个方向（术语分家、图型自选、分批推进、术语节位置）已定并写进正文；其余是有客观优劣的技术选择，理由写在第 8 节。

## 10. 成功判据

- 全部系统文档都有术语节与白话导语，且没有一个词在两处各有一份解释 —— 这三样由检查器判，不靠人记。
- 有状态机、有固定顺序链或有依赖关系的文档各有一张图，每张都写明了重画条件 —— **那一行由检查器判**，所以图腐烂时会有人知道。
- 作者挑三份没参与过讨论的文档各读一遍，**不用问人就看懂了**。这是最后一道判定，也是唯一一道机器判不了的。
- 一年后往任意一份里加一段的人，不会因为「忘了写术语」「把定义又写了一遍」「改了流转却没重画图」而悄悄把这件事退回去 —— 那几件事现在都会报错。
- **下一份新系统文档不需要再走一遍本流程**：它从九节模板开始写，术语、导语与图的规矩在写的时候就满足了。这是判断本轮有没有治到根的那一条。
