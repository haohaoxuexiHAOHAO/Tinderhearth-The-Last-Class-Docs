# PRD：天然地形铺一层底纹理

## 1. 概述

农场的天然地形现在只有几个色。双网格那几套图里，四角全同的那一张必须整张纯色（[场景绘制约定 · 双网格：一套 16 张管一种交接](../production/场景绘制约定.md)，代码仓 `tools/check_dualgrid.py` 在 `verify.py` 里判），而开阔地面每一格用的都是它；实测的色数在 `ART-21` 那一行。地面上一个个的东西（石子、花、草丛）归 `ART-21` 那一层，它们之间与交界附近照样是平涂。

这一份给每种天然地形加一张纹理图：显示层里那种地形的主色，换成纹理图在同一世界位置上的那个像素。**地面本身的纹理、阴影与高光画在纹理图上，双网格那几套只管形状与交界，一张不用重画**；整张纯色的那一张，正好是纹理该出现的地方。

**为什么现在做**：作者要开始画地面纹理，画的时候要在游戏里看得到效果。代码先到位，画一笔就能看一笔。

**排序**：这一份排在[俯视地形挡得住人](./prd-terrain-blocks-walking.md)、[东西能拿在手上](./prd-items-in-bag.md)、[睡一觉能推进一天](./prd-sleep-advances-day.md)与[作物素材表接进游戏](./prd-crop-sheet.md)前面，照[需求工作区 · 一次只做一个需求](./README.md)那条办：那几份只剩作者实机、不再改代码，改代码的只有这一份；它们实机反馈出来的修补各自单独提交。**一种纹理都没配时农场照现在的样子画地面**（见 US-002），所以那几份的实机不等这一份。

**分工**（[ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)）：作者画纹理图，在检查器里给每种地形配上一张或声明不铺，然后实机看；我写合成、配置检查、规则那一节、指南里那几步、交图核对与测试。

**做到哪为止**：农场那一层天然地形的静态纹理。水面动起来、换季与装饰层都不在这一份，见「非目标」。

**台账**：`ENG-39` 是这一份的端到端，另拆出 `ENG-37`、`ENG-38`、`DOC-153`、`DOC-154`。

## 2. 目标

- 草地、天然裸土、浅水与深水，各自整片铺上作者画的那张纹理；交界那几张图块里属于它的那一片，也一直铺到界线。界线的形状与交界那一圈影，照双网格图里画的样子显示。
- 纹理跨格连续、看不出接缝，按纹理图的边长重复，而不是每格重复一次。
- 同一种地形在哪一套交接旁边都长得一样。
- 双网格那几套图一个像素不改，它们的检查一条不改。
- 编辑器里刷地形时就看得到纹理，不用跑起来。
- 配置写错时当场说清错在哪，一次全报；一种都没配时地面照旧。
- 作者照指南就配得上。

## 3. 上游约束

- [场景绘制约定 · 双网格：一套 16 张管一种交接](../production/场景绘制约定.md)：四角全同那一张整张纯色，格边与规范边逐像素相同，同一种地形各套同色。**约束 16 张的规矩一条不改；纹理只换掉主色那些像素，不碰交界那一圈。**
- [场景绘制约定 · 交接处那些光影归谁](../production/场景绘制约定.md)：本地形自己受的影响与对方长出来的东西分开画。**约束交界处的光影仍画在 16 张里；纹理图只画一片地自己的样子，与挨着谁无关。**
- [场景绘制约定 · 地面分几层，判据是「谁决定它在哪」](../production/场景绘制约定.md)与[场景绘制约定 · 耕地要干与湿两套](../production/场景绘制约定.md)：耕地是另一层、自己画沟纹，色相要与天然裸土分得开。**约束纹理只铺天然地形那一层；天然裸土铺了纹理之后仍要与耕地一眼分得开，由作者实机判。**
- [像素绘制原则 · 本项目的色带口径](../production/像素绘制原则.md)与[像素绘制原则 · 硬边、抗锯齿与点绘](../production/像素绘制原则.md)：颜色只出自色板，像素只许全透明或全不透明。**约束纹理图只用色板色、全不透明；合成只搬像素，不算出新颜色。**
- [像素绘制原则 · 大面材质的主色取色带靠暗那一半](../production/像素绘制原则.md)：亮端留给受光面与高光。**约束纹理图的底色就是那种地形的主色，亮档只给叶尖、水纹这类受光的小片。**
- [场景绘制约定 · 画面不随时间换色](../production/场景绘制约定.md)：整屏统一变换会算出色板外的颜色。**约束合成不混色、不加光照。**
- [场景绘制约定 · 动态水：动的是水那张纹理图，不写扰动着色器](../production/场景绘制约定.md)：扰动出来的采样落在非整数像素上。**约束纹理按整像素取、不做扰动。** 那一节原先写的是水面那一格画几帧，铺了纹理之后改写成水那张纹理图画几帧，见 US-004。
- [季节换色重着色贴图](../design/proposals/季节换色重着色贴图.md)（提案，`ART-22`）：换季那一刻把贴图按色板重新着色一次，换色表从色板读。**约束纹理图要能走同一步；主色不另存一份，从双网格图里读，换季之后跟着变。**
- [ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)：素材与参数归作者，参数只在场景与资源里，缺配置当场报错。**约束哪种地形铺哪张由作者在检查器里配，代码不留能用的默认值。**
- 代码仓 `ARCHITECTURE.md` 的「两层：规则层与引擎层」：规则层不引用 Godot。**约束配置对不对的判定放规则层、有单测，合成那一半在引擎层。**
- **依赖**：无。`ENG-36`（交界的影子按方向画）与它互不依赖。

## 4. 用户故事

### US-001：每种天然地形铺上作者画的那张纹理

**描述**：作为玩家，我想看到草地、土地和水面各有质感，以便地面不是几块平涂的颜色。

**验收标准**：

- [ ] 作者实机确认：农场里刷一片草，整片显示纹理，交界那几格里的草一直铺到界线；界线的形状与交界那一圈影，与双网格图里画的一样。
- [ ] 作者实机确认：纹理跨格连续，看不出格与格之间的接缝；把窗口拉大到画面换一档整数倍放大时，纹理像素与地面像素一样清楚、对得齐。
- [ ] 作者实机确认：草挨着土那一边与挨着水那一边，草长得一样。
- [ ] 作者实机确认：编辑器里刷一笔就看得到纹理，不用按 `F6`。
- [ ] 作者实机确认：画了天然裸土那张之后，它与耕地并排仍一眼分得开。
- [ ] 可核对：双网格那几套图没有一个像素变化；`tools/check_dualgrid.py` 没改，`verify.py` 里那一步照旧通过。

### US-002：配了哪几种、配错了，都说得清

**描述**：作为作者，我想只给画好的地形配纹理、其余明确写不铺，配错时当场看到说清错在哪的报错，以便不会出现「这片有纹理、那片没有」而查不出原因。

**验收标准**：

- [ ] 可测试：给一份「数据层地形集里有哪几种地形、每种声明了什么」，判定报出没声明的地形、数据层里没有的地形、声明了两次的地形、主色与别的地形相同的地形，以及宽或高不是格边长整数倍的纹理图（说出实际多大）。几处同时错时一次报全；声明齐全、尺寸都对时不报。
- [ ] 可核对：一种地形都没声明时不铺纹理，地面照现在的样子画，输出面板说一句没配纹理；声明了任意一种，就要求每种地形都有声明（一张纹理图，或明确不铺）。
- [ ] 可核对：运行时配错当场抛出；编辑器里只警告，显示层照旧跟着刷，与 `DualGridPainter` 现有那几条同一个口径。
- [ ] 可核对：主色不另填，从双网格图里四角全同那一张读出来。

### US-003：交图核对认得纹理图

**描述**：作为作者，我想交纹理图时跑一次交图核对就知道透明度与尺寸对不对，以便画错的图不会混进游戏。

**验收标准**：

- [ ] 可核对：代码仓 `python tools/check_art.py` 核纹理图全不透明、宽高都是格边长的整数倍，不合的逐张报出。只用色板色那一条它本来就核。
- [ ] 可核对：四边接不接得上它不判；指南写明用 Aseprite 的 Tiled Mode 与实机看。

### US-004：规矩写进场景绘制约定

**描述**：作为画地面的人，我想查一处就知道纹理画在哪张图上、怎么画、为什么，以便不把纹理画进 16 张里。

**验收标准**：

- [ ] 可核对：[场景绘制约定](../production/场景绘制约定.md)「双网格」那一节写明：16 张只画形状与交界；地面本身的纹理、阴影与高光画在每种地形一张的纹理图上；纹理图的规矩（色板色、全不透明、边长是格边长的整数倍、四边接得上、底色是那种地形的主色）；交界里想保持原样的笔画不用主色；以及为什么。
- [ ] 可核对：那一节「地面与水面的细节另起一层，归 `ART-21`」那一句改成：一片地自己的质感归纹理图，一个个的东西归 `ART-21`。
- [ ] 可核对：「动态水」那一节改写：铺了纹理之后，水面那一格已经换成水的纹理图，要动就是那张图画几帧，岸线那一套照旧静止。做不做、什么时候做，台账另记一条。
- [ ] 可核对：[像素绘制原则 · 大面材质的主色取色带靠暗那一半](../production/像素绘制原则.md)末尾讲「地面本体必须是纯色」那一段，改成写清地面分在哪几张图上：双网格那几套、纹理图、装饰层。
- [ ] 可核对：`ART-21` 的台账行跟着改：它只管一个个的东西，「只盖在纯色地面与纯水内部」改成不压交界那一圈。

## 5. 功能需求

- FR-1：系统必须把显示层里某种地形主色的每一个像素，画成那种地形纹理图在同一世界位置上的像素。
- FR-2：系统必须按世界坐标取纹理图的像素，纹理图从世界原点起平铺。
- FR-3：系统必须让显示层里不是主色的像素照原样显示。
- FR-4：系统必须从双网格图里四角全同的那一张读出每种地形的主色。
- FR-5：系统必须让同一种地形在所有交接旁边用同一张纹理图。
- FR-6：系统必须只用纹理图或双网格图里已有的像素画地面。
- FR-7：在编辑器里，系统必须在数据层变化之后连纹理一起刷出显示层。
- FR-8：当一种地形都没声明时，系统必须照现在的样子画地面。
- FR-9：当一种地形都没声明时，系统必须在输出面板说明没配纹理。
- FR-10：当声明了任意一种地形时，系统必须要求数据层地形集里每一种地形都有声明，声明是一张纹理图或明确不铺。
- FR-11：当声明里出现数据层地形集里没有的地形时，系统必须报错。
- FR-12：当同一种地形声明了两次时，系统必须报错。
- FR-13：当纹理图的宽或高不是格边长的整数倍时，系统必须报错，说出是哪种地形、实际多大。
- FR-14：当两种地形读出来的主色相同时，系统必须报错。
- FR-15：系统必须把一次检查查到的全部配错一次报全。
- FR-16：运行时遇到 FR-10 到 FR-14 那几种配错，系统必须当场抛出。
- FR-17：在编辑器里，系统必须把 FR-10 到 FR-14 那几种配错报成警告，不抛出。
- FR-18：交图核对入口必须核纹理图全不透明。
- FR-19：交图核对入口必须核纹理图的宽高都是格边长的整数倍。

## 6. 非目标

- **不做水面动画。** 这一轮纹理都是静止的；「动态水」那一节只改写成铺了纹理之后的做法（US-004），动画本身记在 `ART-31`。
- **不做换季。** 换季归 `ART-22`；这一份只保证纹理图能走同一步重着色、主色跟着图走。
- **不做装饰层。** 石子、花、草丛归 `ART-21`，在 Godot 里手刷，不要代码。
- **不改 16 张的规矩与它们的检查。** 交界的影子按方向画归 `ENG-36`。
- **不给耕地那一层铺纹理**：耕地自己画沟纹。
- **一种地形只配一张纹理图**：不做几张随机挑，也不做大小不同的几张轮换。重复感压不住时再立项。
- **不做侧视关卡的地面**（`ART-24`）。
- **不加光照、不混色**（「上游约束」里「画面不随时间换色」那一条）。

## 7. 界面与表现考虑

不涉及界面。表现上只能作者实机判的几样：

- 纹理按自己的边长重复，图里的特征越显眼，重复越看得出；压不住就把图画大，或把显眼的东西挪到装饰层去点。
- 交界那一圈影是双网格图里画的，纹理铺到它为止；两者接得自不自然。
- 天然裸土与耕地分不分得开。

## 8. 技术考虑

- **合成是给显示层挂一段着色器。** 顶点阶段用 `MODEL_MATRIX` 把顶点换到世界坐标（[CanvasItem shaders](https://docs.godotengine.org/en/latest/tutorials/shaders/shader_reference/canvas_item_shader.html) 写明它是本地到世界的变换），片元阶段按世界坐标取纹理图上的那个像素，最近邻、平铺；图块颜色等于某种地形的主色时才换。做法与 jess-hammer 发的那段着色器相同（[Repeated texture overlay for tilemaps](https://godotshaders.com/shader/repeated-texture-overlay-for-tilemaps/)；示例工程用的是 Godot 4.7：[repeated-texture-on-tilemap-demo-godot](https://github.com/jess-hammer/repeated-texture-on-tilemap-demo-godot)，内容为合规做过改写），那边认的是纯红，这边认各地形的主色。
- **不在 CPU 上先合成**：那要按格子位置预先生成一批图块，往作者那份显示层 TileSet 里加代码生成的图集源；`[Tool]` 脚本在编辑器里改作者的资源，有被一起存进场景的风险。着色器不碰 TileSet，编辑器里照样画得出来。代价是每帧每个地面像素多一次取样。
- **比颜色按 8 位整数比**，不直接比浮点，理由与[季节换色重着色贴图 · 重着色就是把贴图当一张可改的网格](../design/proposals/季节换色重着色贴图.md)那段代码的注释相同。**待验证**：着色器读到的图块颜色与 PNG 里的值逐位相同。社区说法是 2D 不开 HDR 时在 sRGB 下渲染、颜色不经换算（[论坛那一帖](https://forum.godotengine.org/t/colorop-difference-result-is-wrong/47323/10)，内容为合规做过改写），代码仓 `project.godot` 没开 HDR 2D。对不上时那种地形的纹理整片不出现，实机一眼看得出（US-001）。
- **像素对得齐**：工程是 `canvas_items` 拉伸、整数倍缩放（`project.godot`）。片元虽然按窗口分辨率跑，最近邻取样仍让落在同一个世界像素里的窗口像素取到同一个纹理像素。**待验证**：放大一档时纹理不糊、不错位，作者实机看（US-001）。**相机移动那一面现在看不到**：农场还没有相机，画面不跟人走。纹理与图块走同一个变换、同一种取样，相机又只停在整数世界像素上（`ARCHITECTURE.md` 讲相机的那一段），所以推断它不会单独闪；俯视场景接上跟随相机时再看。
- **导入不用改**：纹理图照项目级默认无损导入（`ARCHITECTURE.md` 的「纹理导入的三项覆盖，为什么是这三项」），平铺与最近邻写在着色器的采样提示里。
- **换季接得上**：那份提案换季时把贴图重着色一次。纹理图走同一步；主色是进树与点「重画显示层」时从双网格图里读的，换季重着色之后再读一次，读到的就是换过的那个色，不用另存一份对照。
- **画面对不对没有机器判据**：不写图形探针（[ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)），自动测试只管配置那一半。
- **被放弃的做法**：
  - **纹理画进 16 张**：要推翻整张纯色那条；草出现在几套里就要画几遍、改几遍；而且还是每格重复一次。
  - **每格随机挑几张变体**：周期乱了，但还是按格重复，交界那几张照旧平涂。
  - **大小不同的几张轮换**：Factorio 的地面同时有 1×1、2×2、4×4 几种尺寸来打散重复（[FFF #214](https://factorio.com/blog/post/fff-214)），画量翻几倍；一张压不住时再立项。
  - **2D 灯光**：乘出来的颜色不在色板里。
