# PRD：打一场仗 —— 从基地按调试键进一场摆好的格子战斗

## 1. 概述

战斗已经改成俯视的格子回合制（[ADR-0035](../decisions/ADR-0035-战斗改成俯视的格子回合制.md)），规则都写在 desc，代码里还没有一行：代码仓 `rules/Combat/` 下现有的全是侧视即时那一套（运动、连段、纵深带、按帧算的硬直与无敌），已经没有调用方。

这一份是搭游戏框架的第一步：在基地按一个调试键，进一间摆好的屋，烬带一名学生打两名敌人，一回合一回合打到分出胜负，再回基地。只做打起来最少要的那几样，别的规则留给后面的需求（见「非目标」）。

**为什么现在做**：先把游戏搭到能玩，美术后面再盖上去。打仗是出征那一半的核心，「出一趟征」（`GP-176`）的委托、准备页与结算都接在它上面。

**排序**：搭游戏框架的那几份需求里最先做的一份，后面几份照台账一份卡着一份。别的几份需求的代码都已做完、只剩作者实机，与这一份并存，照[需求工作区 · 一次只做一个需求](./README.md)那条的例外办；它们实机反馈出来的修补各自单独提交。

**分工**（[ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)）：作者在 Godot 里管那一间屋的样子与摆位（哪几格是墙、谁站在哪）、角色与界面的图，以及实机；我写角色定义与技能定义的载入、一场仗的规则（回合、走格子、出手、AI、胜负）、战斗界面的胶水代码、调试键与测试，并先照代码要的节点名把那一间屋和战斗界面搭成灰盒、标明临时，美术画好之后作者重搭（[Godot 实现教学 · 分工线：这批文档教的是你那一半](../reference/godot/README.md)）。

**数值**：属性、换算参数与 desc 里写「待定」的几个系数都先用占位值，写在代码仓 `data/` 里并标明占位；正式的值归[数值模型](../design/数值模型.md)。

**台账**：`GP-175`。拆条目时写明各条交付现有哪几行的哪一部分。

## 2. 目标

- 在基地按一下调试键进那一间屋；打完回来，基地里的日期、地、背包与存档一件不变。
- 一轮先我方、后敌方：烬第一个动，其余按敏捷；每个人一回合走几格、做一件占回合的事。
- 走格子照 desc 的规矩：八向、不许斜穿、能穿过同伴不能停、贴着敌人走多花 1 点。
- 普通攻击打不打得中、打多少，照 desc 的命中、伤害与暴击算；防御挂「格挡」，到自己下一回合为止挨打变轻。
- 玩家每轮能接管那名学生；没接管时他与敌人都由最低一档的 AI 动。
- 敌人全死算胜利；烬倒下或学生全部倒下算失败。

## 3. 上游约束

- [ADR-0035](../decisions/ADR-0035-战斗改成俯视的格子回合制.md)：俯视格子回合制、一格一个基础单位、八向走、回合分阶段、接管一个学生、角色不画战斗动作帧、普通攻击与防御都是技能。**这是本需求全部结构的来源**；「走一格就占掉这一回合」已由那份 ADR 的后续补充改成花行动力。
- [战斗规则 · 玩家操作谁](../../desc/战斗规则.md)：每轮接管一名学生，接管不用掉主角那一件占回合的事，被接管的不拒绝。**约束 US-008。**
- [战斗规则 · 格子](../../desc/战斗规则.md)：一格一人、八向、不许斜穿、同伴可穿不可停、对面的人挡路、横竖斜各算 1 格。**约束走格子与施放距离。**
- [战斗规则 · 轮与回合](../../desc/战斗规则.md)：两个阶段、主角第一、按敏捷、每轮开始排一次、敏捷一样时次序固定。**约束出手顺序。**
- [战斗规则 · 行动力](../../desc/战斗规则.md)与[战斗规则 · 占回合的事](../../desc/战斗规则.md)：回满、走路花行动力、贴着敌人走、一回合一件、做完减半、可以换成再走满一次、自动结束与结束回合。**约束一回合里能做什么。**
- [战斗规则 · 冷却与额外回合](../../desc/战斗规则.md)：冷却按自己的回合数算。**额外回合这一份不做。**
- [战斗规则 · 防御与命中](../../desc/战斗规则.md)：防御给「格挡」、命中几率 5%–95%、隔得越远越难打中。
- [战斗规则 · 战斗智慧](../../desc/战斗规则.md)与[战斗规则 · 敌人](../../desc/战斗规则.md)：最低一档追着最近的打，敌人优先打学生。**约束 AI 只做最低那一档。**
- [战斗规则 · 倒下](../../desc/战斗规则.md)与[战斗规则 · 失败判定](../../desc/战斗规则.md)：学生倒下还占着那一格；主角 HP 到 0 或学生全部倒下就失败。
- [战斗规则 · 镜头](../../desc/战斗规则.md)、[战斗规则 · 画面上一直显示的](../../desc/战斗规则.md)与[战斗规则 · 技能栏与操作](../../desc/战斗规则.md)：镜头不缩放；画面上只留血条、状态小图标、出手顺序的小头像与瞄准时的命中和伤害；技能栏在下方一行，技能格不绑键，左键点格子和技能。**约束 US-010。**
- [各类公式计算 · 属性换算成面板](../../desc/各类公式计算.md)、[各类公式计算 · 命中](../../desc/各类公式计算.md)、[各类公式计算 · 伤害](../../desc/各类公式计算.md)、[各类公式计算 · 暴击](../../desc/各类公式计算.md)与[各类公式计算 · 行动力](../../desc/各类公式计算.md)：公式的样子。**照它们写代码，写「待定」的数用占位值。**
- [角色面板 · 面板上的每一项](../../desc/角色面板.md)：行动力起步值写在角色定义上，主角、学生、人形敌人为 5；每一项的上限。
- [状态 · 战斗里（敌我所有角色都一样）](../../desc/状态.md)：「格挡」到自己下一回合解除。
- [像素绘制原则 · 像素基准](../production/像素绘制原则.md)：没画的图写「暂无」。**约束学生、敌人、墙与地面先画暂无框。**
- **依赖**：学生名册归 `GP-177`；敌人有哪几种由作者定；正式数值归数值模型。这一份都用占位，不等它们。

## 4. 用户故事

### US-001：角色定义带上打仗要的那几项

**描述**：作为作者，我想在角色定义里写属性、行动力与会的招，以便加一个上场的人只是加一份数据。

**验收标准**：

- [ ] 可测试：角色定义多出这几格：四项属性、行动力起步值、普通攻击与防御各指一份技能定义、战斗智慧那一档；缺任一格载入被拒，并点名哪一份、哪一格。代码仓 `data/characters/jin.json` 跟着补上。
- [ ] 可测试：面板照「属性换算成面板」那张表从属性算出；每一项的初始值与每点属性给多少从配置读，缺了当场报错，没有能用的默认值。
- [ ] 可核对：一名占位学生、两名占位敌人各一份角色定义；名字、属性与换算参数都标明是占位。两名敌人的敏捷不一样，出手先后看得出来。

### US-002：技能定义：普通攻击与防御

**描述**：作为作者，我想把一招写成一份数据，以便以后加招不改代码。

**验收标准**：

- [ ] 可测试：技能定义一招一份，写：占不占回合、施放距离、冷却、物理还是魔法、技能倍率、穿透、给自己挂哪个状态、兵器种类；缺任一格载入被拒并点名。
- [ ] 可测试：冷却 N 的招用过之后，过 N 个自己的回合才能再用；冷却 1 的每回合都能用。
- [ ] 可核对：普通攻击与防御各一份，冷却 1，都占回合。兵器种类这一份只读进来，放哪段特效、配什么声音归后面的需求。

### US-003：那一间屋：格子、墙与站位

**描述**：作为作者，我想在 Godot 里摆一间屋、摆好谁站在哪，以便换一场仗只是换一个场景。

**验收标准**：

- [ ] 可核对：战斗场景里那一间屋由作者在 Godot 里摆：哪几格是墙，谁站在哪一格（每个站位指一份角色定义、写明是我方还是敌方）。框架阶段我先搭灰盒，节点的编辑器描述里写明临时。
- [ ] 可测试：站位落在墙上、两个站位同一格、站位指的角色定义不在册，载入被拒并点名哪一格。
- [ ] 可测试：我方没有烬或没有学生、敌方一个人都没有，载入被拒。
- [ ] 可观察：墙与地面没有图时画「暂无」的灰框；学生与敌人没有图时画两格高的暂无框；烬用基地那套四向图。

### US-004：走格子

**描述**：作为玩家，我想点一格就走过去，以便站到我想站的位置。

**验收标准**：

- [ ] 可测试：八个方向都能走，一步花 1 点行动力，斜着也是 1 点；两个挡路的东西斜着挨着时，从中间斜穿被拒。
- [ ] 可测试：能从同伴那一格穿过去，不能停在那一格；墙与对面的人挡路。
- [ ] 可测试：这一步走之前和走之后都挨着敌人时花 2 点，挨着几个都只多 1 点。
- [ ] 可测试：点一格，剩下的行动力走得到，就沿花得最少的那条路一格一格走过去；走不到的点了不动。花得一样少的路有几条时，同一局面每次取同一条。
- [ ] 可观察：轮到玩家操作的人时，标出能走到的格子；指着一格时画出要走的那条路。

### US-005：一轮两个阶段，一回合一件占回合的事

**描述**：作为玩家，我想清楚一轮里谁先谁后、一回合能做几件事，以便排得出打法。

**验收标准**：

- [ ] 可测试：每轮开始按当时的敏捷排一次：我方阶段烬第一个，学生按敏捷从高到低；敌方阶段敌人按敏捷从高到低；敏捷一样时按站位在场景里的先后，不掷骰。
- [ ] 可测试：自己的回合开始时行动力回满，没用完的不留到下一回合。
- [ ] 可测试：一回合只做得了一件占回合的事，第二件被拒；做完之后剩下的行动力减半、向下取整。
- [ ] 可测试：行动力用完、还没做占回合的事时，可以把那一件换成再走满一次。
- [ ] 可测试：行动力用完、占回合的事也做过了，这一回合自动结束；点结束回合也结束。
- [ ] 可测试：倒下的人不排进出手顺序。

### US-006：普通攻击与防御：打不打得中、打多少

**描述**：作为玩家，我想出手之前就知道打不打得中、打多少，以便挑目标。

**验收标准**：

- [ ] 可测试：指向一个人的招，目标要在施放距离以内，距离照走路的数法；不在距离里被拒。这一份不算视野，场上的人都看得见。
- [ ] 可测试：命中几率照「命中」那一节算：攻方命中率减守方真实闪避几率；挨着时距离倍率 50%，再远的倍率从配置读；限制在 5%–95%。掷骰走注入的随机源。
- [ ] 可测试：伤害照「伤害」那一节的先后算（技能倍率 → 防御减免 → 暴击 → 其他增减），防御减免里的 K 从配置读；算完向下取整，最少 1 点 [假设]。
- [ ] 可测试：暴击照「暴击」那一节算，暴击时乘暴击倍率；打空不掷暴击。
- [ ] 可测试：防御给自己挂「格挡」，轮到自己行动时解除；挂着时受到的伤害降低，降低多少从配置读。
- [ ] 可观察：瞄准时目标身上写命中几率与不暴击时的伤害；打中、暴击、打空的伤害数字样子各不一样，打空写「未命中」。

### US-007：倒下与胜负

**描述**：作为玩家，我想一眼知道这一仗赢了还是输了，以便知道接下来怎么办。

**验收标准**：

- [ ] 可测试：HP 降到 0 时，学生与烬倒下，还占着那一格、不再行动；敌人死亡，从格子上拿掉 [假设]。
- [ ] 可测试：敌人全部死亡判胜利；烬倒下或学生全部倒下判失败。胜负一出，不再有人行动。
- [ ] 可观察：胜负一出弹一个窗，写胜利或失败，按一下回基地。

### US-008：接管学生

**描述**：作为玩家，我想这一轮亲手操作那名学生，以便他走到我想要的位置。

**验收标准**：

- [ ] 可测试：在烬的回合里点那名学生，就接管他这一轮：轮到他时由玩家操作，技能栏换成他的招；每轮只能接管一人，接管不用掉烬那一件占回合的事。
- [ ] 可测试：没被接管的学生由 AI 动；接管只管这一轮，下一轮不点就回到 AI。
- [ ] 可观察：出手顺序那一排里标出被接管的那一个。

### US-009：AI：最低一档

**描述**：作为玩家，我想敌人和没接管的学生自己会打，以便一场仗打得起来。

**验收标准**：

- [ ] 可测试：没被接管的学生与敌人照[战斗规则 · 战斗智慧](../../desc/战斗规则.md)最低一档动：朝最近的对面的人走，进了施放距离就普通攻击。敌人先找走得到的学生，学生都够不着时才找烬。
- [ ] 可测试：走不近也打不到时防御 [假设]。
- [ ] 可测试：同一局面、同一串随机数，AI 做的是同一件事。

### US-010：画面上一直显示的

**描述**：作为玩家，我想看着画面就知道轮到谁、谁伤得重，以便不用翻面板。

**验收标准**：

- [ ] 可观察：每个人头顶一条血条；挂着「格挡」的人头顶一个状态小图标，没画写暂无。
- [ ] 可观察：一排出手顺序的小头像，标出现在轮到谁；没画的头像写名字的第一个字。
- [ ] 可观察：屏幕下方一行技能栏，放着现在操作的人会的招，旁边一个结束回合的按钮；还在冷却的招点不了。
- [ ] 可观察：镜头不动、不缩放，一屏看全那一间屋。
- [ ] 可观察：走格子一格一格挪过去，出手朝目标冲一下，挨打闪白，都由代码做。
- [ ] **作者实机确认**：看得出现在轮到谁、能走到哪、打不打得中、打了多少、谁被接管；走、打、防御顺手。

### US-011：从基地进，打完回基地

**描述**：作为作者，我想在基地里随时按一下就打一场，以便不用走完出征那一整套就能试打仗。

**验收标准**：

- [ ] 可测试：基地里一个开发期调试键进这一场；它登在调试键表里（代码仓 `rules/UI/DebugKeys.cs`），「同一个物理位不被两个动作抢」那条测试一起判它。
- [ ] 可核对：打完回到基地，日期、地、背包与存档一件不变，进去之前没存档的改动（比如刚播下的种子）也还在。
- [ ] 可核对：这一场不进存档；打到一半退出游戏，下次照存档从基地开始。
- [ ] **作者实机确认**：播一格种子、按调试键打一场、回来，那一格还在。

### US-012：删掉侧视即时那一套代码

**描述**：作为作者，我想旧的战斗代码删干净，以便以后读代码不会照着它改。

**验收标准**：

- [ ] 可核对：代码仓 `rules/Combat/` 下现有的侧视那一批、测它们的用例、`src/` 里只给它们用的那些文件删掉；删之前按类名搜过，没有别的调用方。
- [ ] 可核对：设计仓与代码仓里指着这些文件的地方跟着改；代码仓 `python tools/verify.py` 全绿。

### US-013：打一场仗的端到端

**描述**：作为作者，我想一次走完「进屋、一轮轮打、分胜负、回基地」整条路，以便确认几块拼起来是通的。

**验收标准**：

- [ ] 自动化测试走完主路径：读工程里那一份角色、技能与配置 → 摆好一间屋 → 第一轮烬先动、接管学生、走格子、普通攻击、防御 → 敌方阶段 AI 动 → 一轮轮打到敌人全死，判胜利。
- [ ] 覆盖失败路径：烬 HP 到 0 判失败；斜穿被拒；行动力不够的那一格走不过去；一回合第二件占回合的事被拒；角色定义缺普通攻击，载入被拒。
- [ ] 测试独立可重复：随机源注入，读工程里的数据只读不写。
- [ ] 作者实机确认清单写在这一份的端到端条目里：在基地按哪个键、点哪里、该看到什么 [假设]。
- [ ] 可核对：代码仓 `python tools/verify.py` 全绿；设计仓 `python tools/check_docs.py` 0 FAIL。

## 5. 功能需求

**角色与技能**

- FR-1：系统必须从角色定义读出四项属性、行动力起步值、普通攻击、防御与战斗智慧那一档，缺任一格时拒绝载入并点名。
- FR-2：系统必须从配置读出面板每一项的初始值与每点属性给多少，缺了当场报错。
- FR-3：系统必须照「属性换算成面板」那张表从属性算出面板。
- FR-4：系统必须从技能定义读出占不占回合、施放距离、冷却、物理或魔法、技能倍率、穿透、给自己挂的状态与兵器种类，缺任一格时拒绝载入。
- FR-5：用过一招之后，系统必须等过了它的冷却那么多个自己的回合才让它再用。

**那一间屋**

- FR-6：系统必须从战斗场景读出哪几格是墙，以及每个站位的格子、角色定义与阵营。
- FR-7：系统必须拒绝站在墙上、两人同一格或指向不在册角色定义的站位。
- FR-8：系统必须拒绝我方缺烬、缺学生或敌方没有人的那一间屋。

**走格子**

- FR-9：系统必须让人往八个方向走，每一步花 1 点行动力。
- FR-10：系统必须拒绝从两个斜着挨着的挡路的东西中间斜穿。
- FR-11：系统必须让人穿过同伴那一格。
- FR-12：系统必须拒绝停在同伴那一格。
- FR-13：系统必须让墙与对面的人挡路。
- FR-14：一步走之前和走之后都挨着敌人时，系统必须让这一步花 2 点。
- FR-15：玩家点一格时，系统必须在剩下的行动力走得到时沿花得最少的路把人挪过去。
- FR-16：花得一样少的路有几条时，系统必须每次取同一条。

**回合**

- FR-17：每轮开始时，系统必须按当时的敏捷排出两个阶段的出手顺序，烬排在我方第一个。
- FR-18：敏捷一样时，系统必须按站位在场景里的先后排。
- FR-19：自己的回合开始时，系统必须把行动力回满。
- FR-20：系统必须拒绝一回合里的第二件占回合的事。
- FR-21：做完占回合的事后，系统必须把剩下的行动力减半并向下取整。
- FR-22：行动力用完、还没做占回合的事时，系统必须允许把那一件换成再走满一次。
- FR-23：行动力用完且做过占回合的事时，系统必须自动结束这一回合。
- FR-24：系统必须把倒下的人排除在出手顺序之外。

**出手**

- FR-25：系统必须拒绝施放距离以外的目标。
- FR-26：系统必须照「命中」那一节算命中几率，并限制在 5%–95%。
- FR-27：系统必须用注入的随机源掷命中与暴击。
- FR-28：系统必须照「伤害」那一节的先后算伤害，最少 1 点。
- FR-29：防御时，系统必须给自己挂「格挡」。
- FR-30：轮到挂着「格挡」的人行动时，系统必须解除他的「格挡」。

**接管与 AI**

- FR-31：在烬的回合里点一名学生时，系统必须让玩家操作他这一轮的回合。
- FR-32：系统必须拒绝一轮里接管第二名学生。
- FR-33：系统必须让没被接管的学生与敌人照最低一档的战斗智慧行动。

**胜负与进出**

- FR-34：系统必须在敌人全部死亡时判胜利。
- FR-35：系统必须在烬倒下或学生全部倒下时判失败。
- FR-36：基地里按那个调试键时，系统必须进入这一场。
- FR-37：打完之后，系统必须回到基地，基地的状态与进战斗之前一样。
- FR-38：系统必须不把这一场写进存档。

## 6. 非目标

- **探路、视野与迷雾**：这一场一进去就在战斗状态里，场上的人都看得见。
- **借机攻击、协作攻击、「反击」与额外回合。**
- **准备回合、预警格与打断；破绽与「露出破绽」；击退；范围招与误伤。**
- **地形效果、掩体、门、场景物件与高低**：屋里只有地面与墙。
- **采集、尸体、宝箱与留在原地的东西**：敌人死了直接从格子上拿掉 [假设]，尸体跟采集一起做。
- **扶起、「神秘庇佑」与养伤**，所以「一个学生第二次倒下」那条失败这一份碰不到。
- **HP 与 MP 的自然恢复、MP 消耗、主角的辅助技与真实形态。**
- **自动走好几个回合、倍速、右键看说明、给学生下指令、特殊援助。**
- **镜头跟人与拖镜头**：屋子一屏放得下，镜头不动。
- **手柄与键盘的格子光标**：先做鼠标；界面从一开始就按格子光标走得到每一处来排，手柄另立一条。
- **特效、音效、兵器动画与倒下的图。**
- **经验、关系、报酬、委托与精力消耗；战斗智慧更高的档。**
- **学生名册与正式的名字**（`GP-177`）。

## 7. 界面与表现考虑

- **信息的先后**：现在轮到谁最重，其次是能走到哪、打不打得中、打多少，再次是每个人的血条与出手顺序。
- **能走到的格子分两种画**：用剩下的行动力走得到的，与要把那一件换成再走满一次才走得到的，形状不同，不只换颜色。
- **键鼠**：左键点格子（走、选目标）与技能；点一招进入瞄准，再点一次那一招或按 `Esc` 取消 [假设]；右键这一份不做事。
- **伤害数字**从被打的人头顶往上飘。
- **灰盒**：墙与地面、学生与敌人没有图时画暂无框；出手顺序的小头像没画写名字的第一个字，与背包里没画的图标同一个写法。
- **编辑器里看不到格子与像素字体**，跑起来才有，与基地那几个窗同一个情况。

## 8. 技术考虑

- **规则层与引擎层分开**：一场仗的状态、出手顺序、走格子与找路、出手结算、AI 与胜负都在规则层（不引用 Godot），有单测；引擎层只把点击翻成命令、把结果画出来。
- **找路自己写**：Godot 里做格子战棋的开源项目都是 GDScript，没有 C# 的（[GDQuest 的 2D 战棋移动演示](https://github.com/gdquest-demos/godot-2d-tactical-rpg-movement)代码 MIT、美术 CC-BY-NC-SA；[Grid-based-Tactics-Template](https://github.com/davisbrandon02/Grid-based-Tactics-Template)；[godot-tactical-rpg](https://github.com/ramaureirac/godot-tactical-rpg)），只借它们的做法：先铺出能走到的格子，再取路径画预览。Godot 自带的 [AStarGrid2D](https://docs.godotengine.org/en/4.5/classes/class_astargrid2d.html) 有一种斜走模式（`DIAGONAL_MODE_AT_LEAST_ONE_WALKABLE`：路径段旁边至少两处障碍才不走斜线），对得上「不许斜穿」，但它表达不了同伴可穿不可停、贴着敌人多花 1 点，规则层也不引用 Godot，所以不用。找路用 .NET 自带的 [PriorityQueue](https://learn.microsoft.com/dotnet/api/system.collections.generic.priorityqueue-2) 按花费从小到大铺开。
- **回基地不重载基地**：进战斗时把基地那一棵树从场景树上摘下、不释放，打完挂回去，所以没存档的改动也还在。**待验证**：摘下再挂回时基地各节点的 `_Ready` 不再跑、输入与每帧处理照旧（[Node 的 `_ready` 只跑一次，要再跑得调 `request_ready`](https://docs.godotengine.org/en/stable/classes/class_node.html#class-node-private-method-ready)）。验证办法：落地时起一次性探针，播一格、进战斗、回来，读那一格与日期。
- **数值都从数据读**：属性、行动力起步值、面板换算参数、距离倍率、防御减免的 K、格挡减多少都在代码仓 `data/` 里，缺了当场报错；desc 定了的照 desc（挨着 50%、暴击倍率基础 145%、人形行动力 5），写「待定」的标明占位。
- **随机源注入**：命中与暴击都从外面给的随机源取，测试按顺序给。
- **状态载体一起删**：[ADR-0035](../decisions/ADR-0035-战斗改成俯视的格子回合制.md)写的是侧视那一批里除状态载体之外删掉或重写；现有那个载体按帧算、只认硬直与无敌，回合制用不上，所以一起删，「格挡」按「到自己下一回合」另写。
- **那一间屋的格子与基地对齐**：一格 16 像素，与基地的图块一样大；屋子要一屏放得下，镜头才能不动（代码仓视口 640×360，横竖各放得下 40 格、22 格）。
