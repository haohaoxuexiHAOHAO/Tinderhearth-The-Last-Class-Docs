# PRD：俯视地形挡得住人

## 1. 概述

农场里现在走得进水里。[场景绘制约定 · 俯视布景](../production/场景绘制约定.md)讲跨岸线的石头时写明「水本身已经不可走」，而俯视那一侧一条地形碰撞都没有：农场数据层那份 TileSet 里没有物理层（代码仓 `scenes/farm/farm.tscn`）。农场的角色（代码仓 `src/World/Farm/FarmWalker.cs`）靠引擎的碰撞走路，却没有东西可撞。

这一份让水挡住人，并把「俯视里什么挡人、碰撞挂在哪」定成一条机制：以后的悬崖、墙、建筑与摆件都照它走，不各发明一种挡法。

**为什么现在做**：作者接下来那一趟农场实机正好顺带看它。碰撞要挂在数据层的图块上，而指南现在让作者关掉数据层的 `Enabled` —— 实测关掉之后碰撞跟着没了（见「技术考虑」）。那一下越早改，回头重做的地方越少。

**排序**：这一份与[东西能拿在手上](./prd-items-in-bag.md)、[睡一觉能推进一天](./prd-sleep-advances-day.md)、[作物素材表接进游戏](./prd-crop-sheet.md)并存，照[需求工作区 · 一次只做一个需求](./README.md)那条的例外办：前面那几份只剩作者实机、不再改代码，改代码的只有这一份；它们的实机反馈出来的修补各自单独提交。**代码落地之后，农场要先照指南第二步把数据层改成用眼睛隐藏才跑得起来**（关着 `Enabled` 会当场报错，见 US-002），所以那一趟实机从第二步新加的那一小节开始。

**分工**（[ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)）：作者在 Godot 里给数据层那份 TileSet 加物理层、给水的标记瓦片画碰撞、把数据层从关 `Enabled` 改成关眼睛，然后实机走一遍；我写配错时当场报错的那几条检查、规则的那一节、指南里那几步与测试。

**做到哪为止**：基地的两种水挡人。悬崖、墙、建筑与摆件只写明照哪条走，不做：基地的天然地形里没有悬崖，建筑归 `GP-44`。

**台账**：`ENG-27` 是这一份的端到端，另拆出 `ENG-35`、`DOC-151`、`DOC-152`；超边界记账 `GP-165`。

## 2. 目标

- 农场里朝浅水或深水走，停在岸边、走不进去；斜着贴岸走，顺着岸滑开、不卡住。
- 俯视里挡人的东西只走一条机制：一律是物理碰撞、挂在同一层；地形的碰撞挂在数据层那一格的标记瓦片上，布景、建筑与摆件各自带碰撞。这条写在一处。
- 会让水悄悄变得能走的那几种配错当场报错，并说清错在哪：数据层关了 `Enabled`、关了它的碰撞、同一种地形的几张标记瓦片碰撞没画齐。
- 作者照指南第二步就能配好；两个仓里不再有哪一句叫人关数据层的 `Enabled`。

## 3. 上游约束

- [场景绘制约定 · 俯视布景](../production/场景绘制约定.md)：水本身不可走；跨岸线的石头自带碰撞，地形层不为它开洞。**约束两种水都挡人，以及布景的碰撞归布景自己。**
- [场景绘制约定 · 双网格：一套 16 张管一种交接](../production/场景绘制约定.md)：数据层存每一格是哪种地形，显示层由代码算出来、每一格跨四个数据格的角。**约束「这一格挡不挡人」只从数据层读** —— 显示层那一格没有唯一答案。
- [场景绘制约定 · 基地要画哪几套](../production/场景绘制约定.md)：深水四周总有一圈浅水。**约束站在岸上时脚前那一格总是浅水**：两种水都挡，所以钓深水的鱼要隔着那一圈，钓鱼读哪一格归 `GP-165`。
- [玩法定位 · 内容规模基准](../canon/gameplay/玩法定位.md)里「基地的天然地形」那一行：四种，两种水是两种地形、各钓不同的鱼。**约束两种水各有自己的标记瓦片、碰撞各画各的；基地没有悬崖这种地形。**
- [`建造系统` · 两套网格，职责分清](../design/建造系统.md)：水面等周边地形在可建造区之外，摆位判定不为它们写特例。**约束这一份不给摆位判定开「这一格能不能走」的读口。**
- [ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)：碰撞区域归作者；参数只在场景与资源里；缺配置当场报错。**约束碰撞形状由作者画，代码只验配置。**
- 代码仓 `ARCHITECTURE.md` 里「实体阻挡」那一节：位置被真的挡住、贴着走、沿墙滑是 `MoveAndSlide` 的活，在规则层重写一遍就是第二份事实。**约束挡人交给引擎碰撞，角色移动前不另查格子。**
- **依赖**：无。建筑挡人等 `GP-44` 落地时接进同一层。

## 4. 用户故事

### US-001：两种水都挡住人，贴着岸走滑得开

**描述**：作为玩家，我想朝水走时停在岸边、贴着岸走时顺着岸滑开，以便水是地图上真的边界，而不是一片踩得上去的颜色。

**验收标准**：

- [ ] 作者实机确认：沿着水边朝水里走，每一次都走不进去，停下的位置看着在岸边。差几个像素要不要改碰撞形状由作者判；要改就把同一种地形的那几张改成一样。深水外面总隔着一圈浅水、岸上碰不到，它挡不挡人由下面那趟无头场景测。
- [ ] 作者实机确认：斜着按方向键贴着一段直岸走，角色顺着岸滑开，不在格与格之间卡住。
- [ ] 作者实机确认：草地与裸土照旧走得过去；数据层隐藏之后看不到标记瓦片，地面照旧。
- [ ] 可测试：一次性无头场景照指南那几步搭（数据层两种水的标记瓦片带整格碰撞、用 `Visible` 隐藏），一个用 `MoveAndSlide` 的角色朝水格走，停在水格边上；贴岸斜走时沿岸方向的位移不为零。深水另跑一趟：只给深水画碰撞，人站进浅水里朝深水走。跑完删。

### US-002：会让水悄悄能走的配错，当场报错

**描述**：作为作者，我想在数据层被停用、它的碰撞被关掉、或者同一种地形的几张标记瓦片碰撞没画齐时，当场看到一条说清错在哪的报错，以便不会出现「这片水能走、那片不能」而查不出原因。

**验收标准**：

- [ ] 可测试：给一组「哪种地形、哪一张、带不带碰撞」，同一种地形里有的带、有的不带时，判定报出那种地形与它的每一张（来源编号加图集坐标）；全带或全不带时不报。几种地形同时不齐时一次报全。
- [ ] 可核对：只看数据层那个地形集里标了地形的瓦片，没标地形的不参与。
- [ ] 可核对：数据层的 `Enabled` 关着时，运行时当场抛出，信息说清改用场景面板的眼睛隐藏、为什么不能关 `Enabled`；编辑器里只警告，显示层照旧跟着刷（与这一段接线现有那几条同一个口径）。
- [ ] 可核对：数据层的 `Collision Enabled` 关着时同上。
- [ ] 可测试：一次性无头场景各造一种配错跑一次，各报出该报的那一条；配好的那一份不报。跑完删。

**描述**：作为以后加悬崖、墙、建筑或摆件的人，我想查一处就知道俯视里什么挡人、碰撞挂在哪，以便不给每样东西各发明一种挡法。

## 5. 功能需求

- FR-1：俯视场景里，系统必须让角色走不进数据层上标为浅水的格。
- FR-2：俯视场景里，系统必须让角色走不进数据层上标为深水的格。
- FR-3：系统必须从数据层那一格的标记瓦片得出它挡不挡人，不读显示层。
- FR-4：角色贴着挡人的地形斜着走时，系统必须让它沿着那条边滑开。
- FR-5：当数据层的 `Enabled` 关着时，系统必须在运行时当场报错，信息里写明改用 `Visible` 隐藏。
- FR-6：当数据层的 `Collision Enabled` 关着时，系统必须在运行时当场报错。
- FR-7：当数据层地形集里同一种地形的标记瓦片有的带碰撞、有的不带时，系统必须在运行时报错，列出那种地形与它的每一张瓦片。
- FR-8：系统必须把一次检查里查到的全部不一致一次报全。
- FR-9：在编辑器里，系统必须把 FR-5 到 FR-7 那几种配错报成警告，不抛出。

## 6. 非目标

- **不做悬崖与墙。** 基地的天然地形里没有悬崖（「上游约束」里内容规模基准那一条），墙跟着建筑来；它们出现时照 US-003 那一节走。
- **不做建筑与摆件挡人。** 归 `GP-44`；US-003 那一节只写明它们自带碰撞、挂同一层。
- **不设地图边上那道看不见的墙。** 画过的那片地外面现在走得出去。基地地图的外圈由作者用水、布景与建筑围起来 —— 那一圈本来就要画，而看不见的墙挡住人却看不出为什么。
- **不给规则层一份「这一格能不能走」的判定。** 挡人交给引擎碰撞；学生日程的寻路（`GP-94`）与钓鱼读哪一格（`GP-28`）需要时，从同一份数据层读。
- **不定钓鱼读哪一格。** 两种水都挡之后，深水四周那一圈浅水把人隔在岸上；[`生产系统` · 边界与非目标](../design/生产系统.md)写明第一版钓鱼没有抛投落点，只读脚前那一格的话深水的鱼钓不到。那一条归 `GP-165`。星露谷也是水一律不能走、鱼看浮标离岸几格（[Fishing Zone](https://stardewvalleywiki.com/mediawiki/index.php?title=Fishing_Zone)）。
- **不改作物与耕地的可走性**：现在都走得过去，这一份不动。
- **不做涉水**：浅水减速、溅水那一类都不做。
- **不碰侧视那一侧的碰撞层**（`ENG-19`），也不给物理层起名：挡人那一层用默认的第 1 层。

## 7. 界面与表现考虑

不涉及界面。表现只有一处：碰撞是整格方块，边落在数据格的边上；双网格画出来的岸线是从显示格中间穿过去的曲线，两条线差几个像素。停下的位置看着对不对由作者实机判（US-001）。

## 8. 技术考虑

- **实测**（一次性无头场景，Godot 4.7.2）：数据层取消勾选 `Enabled` 之后，图块上的碰撞没了，格子照样读得出来；只取消勾选 `Visible`，碰撞还在；进树之前就关着，结果一样。官方文档也写明 `enabled` 为 false 时整层停用，渲染与碰撞都在内（[TileMapLayer 的 enabled](https://docs.godotengine.org/en/latest/classes/class_tilemaplayer.html#class-tilemaplayer-property-enabled)）。
- **刷地形的手顺不变**：那一层关着或隐藏着时 TileMap 面板都不让画（指南「卡住了」那张表已有这一行），要改就先打开，改完再藏。
- **角色那一侧不用改**：`FarmWalker` 已经是浮空模式的 `CharacterBody2D`、每帧 `MoveAndSlide`，碰撞一出现就被挡住；它的注释也已写明顶着障碍物推时照旧播行走。
- **沿岸会不会卡**：同一个物理分块里的格子，碰撞形状会合并（[TileMapLayer 的 physics_quadrant_size](https://docs.godotengine.org/en/latest/classes/class_tilemaplayer.html#class-tilemaplayer-property-physics-quadrant-size)，默认 16 格一块），格与格之间的接缝大多被合并掉；分块边界上还有接缝（[Catlike Coding 那一篇](https://catlikecoding.com/godot/true-top-down-2d/11-showing-best-scores/)，内容为合规做过改写）。卡不卡由 US-001 的无头场景与实机判。
- **碰撞层与掩码**：TileSet 物理层与角色都用默认的第 1 层，所以不用动。**待验证**：TileSet 新加的物理层默认在第几层，实现时用无头场景读回。两者对不上时不报错，表现就是水又能走了，US-001 那几格实机会撞上。
- **为什么要有一致性检查**：一种地形可以有不止一张标记瓦片。现在农场里浅水就有两张：`grass-shallow.png` 与 `shallow-deep.png` 里各有一张标成浅水。只给其中一张画碰撞时，用另一张刷的那几格就走得进去，而那不报错。
- **被放弃的落点**：
  - **挂在显示层的图块上**：显示层一格跨四个数据格的角，「这一格挡不挡」没有唯一答案。
  - **另刷一层专门的碰撞层**：同一片水要在两层上各刷一遍，哪一层漏刷都不报错。
  - **代码按地形编号生成碰撞**（往另一层写格子，或运行时改瓦片数据）：要多一份「哪几种地形挡人」的声明和一层节点，换来的只是把作者画的那几笔挪进代码；运行时改瓦片数据那条路，官方还警告会拖慢图层（[TileMapLayer 的 _tile_data_runtime_update](https://docs.godotengine.org/en/latest/classes/class_tilemaplayer.html)）。
  - **角色移动前自己查格子**：把 `MoveAndSlide` 的活在别处重写一遍（「上游约束」里 `ARCHITECTURE.md` 那一条），而且挡不住布景与建筑。
