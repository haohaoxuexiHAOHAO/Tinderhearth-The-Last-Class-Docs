# PRD：睡一觉能推进一天

## 1. 概述

农场里现在推进一天只有调试键 `N`：它直接调地块的按天推进（代码仓 `src/World/Farm/FarmField.cs`），不走每日结算那串步序，不推日期，也不存档。停掉游戏，地里种下的东西全没了。代码仓里没有日历、每日结算与存档的代码，按名搜的结果记在[`每日结算系统` · 下游同步](../design/每日结算系统.md)与[`存档系统` · 下游同步](../design/存档系统.md)。

这一份做的是[从哪里开始 · 睡一觉能推进一天](../reference/godot/从哪里开始.md)那个里程碑：走到床边睡一觉，日期进一天、作物过一夜，醒来弹一份摘要说清这一夜变了什么；停掉游戏再进来，进度还在。

**为什么现在做**：经营循环在这里才闭合。在它之前种地是一次性的演示，在它之后是一个每天重复的循环。作物素材表那份的代码已经做完，剩下的只有实机。

**排序**：这一份排在[作物素材表那份](./prd-crop-sheet.md)前面，两份并存，照[需求工作区 · 一次只做一个需求](./README.md)那条的例外办：作物那份只剩实机，不再改代码。**实机那一半排在作物那份的实机之后**：要先照[作物素材表那份的端到端 · 作者实机清单](./issues/issue-GP-147-crop-sheet-e2e.md)把农场搭到能种地，这里的床、弹窗与遮罩才有地方摆。

**分工**（[ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)）：作者在 Godot 里摆床的交互点、排两个弹窗（简版摘要与「这一天没有推进」）、做转场遮罩，并在检查器里把它们接上；我写日历、结算驱动、存档、引擎侧接线、测试与一份跟着做的指南。

**做到哪为止**：每日结算那串步序全部按名调到，但只有日期、作物、摘要、存档与醒来那几步有活干（逐个列在 US-002），其余是空步；存档只做一位，只存日历与地块；没有日内时钟，所以一天结束只有主动睡这一个来源。

**台账**：`GP-56`（结算）、`GP-54`（存档）、`UI-20`（结算与存档那几处界面）。这一份各交付它们的一部分，剩下的仍挂在原编号上，见「非目标」。

## 2. 目标

- 站在床边按交互键：日期进一天，地里的作物照每日结算那串步序过一夜，醒来弹一份摘要说清这一夜变了什么。
- 停掉游戏再进农场：日期与每一格地都是上一次睡醒那一刻的样子。
- 存档写不进去时：日期与地都停在睡前，弹窗说清这一天没有推进、为什么；处理好再睡一次就成了。
- 每日结算那串步序在代码里按名逐步调到、一步不增减；还没有持有者的那几步是空步，持有者落地时只填自己那一步。
- 代码里那张步名表与正典对不上时，检查器判得出来。

## 3. 上游约束

- [时间与经营 · 结算顺序（固定，不得改动）](../canon/gameplay/时间与经营.md)：那串步序，以及它为什么是这个顺序。**约束结算驱动按步名逐步调它、一步不增减、不按序号引。**
- [时间与经营 · 每日结算](../canon/gameplay/时间与经营.md)：结算在睡后展示；简版弹窗只列有变化的重要项；完整明细进手环。**约束摘要的形状。那份重要项清单里，这一份只有作物枯死与作物变异有内容**，其余各等自己的系统。
- [时间与经营 · 作息与熬夜](../canon/gameplay/时间与经营.md)：一天结束有主动睡与到点强制结束两个来源。**这一份只接主动睡**，强制结束等日内时钟。
- [时间与经营 · 时间](../canon/gameplay/时间与经营.md)：时间单位只有天、季、年三级，季长与季数写在那一节。**约束日历。**
- [玩法定位 · 存档](../canon/gameplay/玩法定位.md)：睡眠是唯一正式存档时机、没有手动存档、存档位的份数。**这一份只做一位。**
- [玩法定位 · 开局](../canon/gameplay/玩法定位.md)：开局的几条硬约束。**开局是哪一天它没写**，见「待确认问题」。
- [`每日结算系统`](../design/每日结算系统.md)：一个入口两个来源；整串加自动存档是一次事务，提交点是写入成功那一刻；摘要在提交前产出、提交后弹出；结算期间没有输入入口；不碰暂停闸门。**结算那一半的结构全部来自它**，验收从它的「验收」那一节里取这一份接得住的那几条。
- [`存档系统`](../design/存档系统.md)：分片的声明、注册与读口；写入是一次事务；先判兼容再处理缺字段；分片之间没有载入顺序；派生量不单独存。**约束存档那一半**，验收同上取法。
- [`地块系统` · 一格要存什么](../design/地块系统.md)：**地块分片存哪几项。** 那张清单缺一项，见 US-004。
- [ADR-0015](../decisions/ADR-0015-存档的版本与缺字段口径.md)：明文；全存档一个版本号；缺字段按版本分两条；多出来的字段丢弃，整个不认识的分片不丢。**约束载入。**
- [ADR-0017](../decisions/ADR-0017-版本更新对旧存档的两种后果.md)：最低兼容存档版本那道闸门排在处理缺字段之前。**约束载入的顺序。**
- [`界面系统` · 弹窗那一层：结算摘要与二次确认](../design/界面系统.md)、[`界面系统` · 手环上：日记、主线与结算完整明细](../design/界面系统.md)那条「同一天要看得出是同一天」、[`界面系统` · 主菜单那一侧：读档位列表、更新公告、设置](../design/界面系统.md)里「存档写入失败」那一段：**约束两个弹窗各自必须答出的问题。**
- [ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)：分工；参数唯一来源是场景与资源；缺配置当场报错，不悄悄兜底。
- [ADR-0027 · 明确不包含](../decisions/ADR-0027-进出室内改成点一下门.md)：只有门改成了鼠标右键，床照旧按交互键。**约束床的触发键。**
- [交互点与站位点 · 七、几种具体的交互点，各自的特别之处](../reference/godot/交互点与站位点.md)：床按键触发每日结算，那是一次转场，不是暂停。
- **依赖**：事件询问那一处等 `GP-52`，统计事件等 `GP-55`；空步各等自己的持有者（US-002）；实机等农场搭起来（见「概述」里的排序）。

## 4. 用户故事

### US-001：日历按天、季、年走，换季那天不当季的作物枯死

**描述**：作为玩家，我想每睡一觉日期进一天、一季过完进下一季，以便作物的季节真的起作用。

**验收标准**：

- [ ] 可测试：「日期推进」把日期推进一天；一季最后一天之后是下一季第一天；最后一季最后一天之后是下一年第一季第一天；年份一直往上加，没有上限。
- [ ] 可测试：换季那天，「季节更替判定」把不在新季节列表里的作物标成枯死；不换季的那天一格都不动。
- [ ] 可测试：换季那天被标成枯死的那一格，在「作物生长与枯死结算」里不再长，也不掷变异。
- [ ] 可核对：日历只有天、季、年三个量，没有「月」；季长与季数各是一个常量，注释指向[时间与经营 · 时间](../canon/gameplay/时间与经营.md)。
- [ ] 可核对：开新档时日期是开局那一天；是哪一天见「待确认问题」开局那一条。

### US-002：结算驱动：一个入口，按步名把正典那串逐步调到

**描述**：作为开发者，我想要一个按正典步序逐步调用的结算驱动，以便以后每个系统落地时只填自己那一步，不动驱动本身。

**验收标准**：

- [ ] 可测试：推进一次，步名表里每一步恰好被调到一次，顺序与表一致；用例按名字比，不按序号。
- [ ] 可测试：步数是一个常量，用例钉住它等于步名表的项数。
- [ ] 可核对：步名表与[时间与经营 · 结算顺序（固定，不得改动）](../canon/gameplay/时间与经营.md)逐项对得上：项数与顺序相同，表里每一项是正典那一条去掉加粗之后的开头。设计仓 `tools/check_docs.py` 判它；故意改错一个字、对调两项，各跑一次都判失败。
- [ ] 可核对：有活干的是「日期推进」「季节更替判定」「作物生长与枯死结算」「生成结算摘要」「自动存档」「次日 6:30 醒来」；其余每一步是空步，注释写明归设计仓台账哪一条。
- [ ] 可测试：「主动睡」与「强制结束」两个来源各推同一份世界一次，结果完全一致（熬夜档位还不存在）。
- [ ] 可核对：推进一天只有这一个入口，床与调试键 `N` 都调它；代码里推进日期与调地块按天推进的地方只在结算那几步里。
- [ ] 可测试：整串跑完之后有一处询问事件的调用点，排在最后一步之后；现在是空的，注释写明归设计仓台账 `GP-52`。

### US-003：整串是一次事务，写档成功才算数

**描述**：作为玩家，我想要睡一觉要么整天都算、要么一点都不算，以便不会出现「作物长了、存档里却没有」这种说不清的状态。

**验收标准**：

- [ ] 可测试：结算在世界状态的副本上跑；让任意一步抛出（逐步各一条用例），世界状态一格不变，写档一次都没发生。
- [ ] 可测试：让写档失败，世界状态一格不变，结果里写着这一天没有推进与失败的原因。
- [ ] 可测试：摘要在「生成结算摘要」那一步产出、在「次日 6:30 醒来」那一步交给界面；写档失败的那条用例里交出零次。
- [ ] 可测试：从睡下到摘要弹出之前，第二次推进被拒，玩家输入不起作用。
- [ ] 可核对：转场与结算都不碰世界暂停（遮罩不进导航栈）；世界只在弹窗开着时暂停，那是弹窗既有的暂停判定。
- [ ] **作者实机确认**：把存档文件设成只读再睡，弹窗说清这一天没有推进与原因，日期与地都没变；去掉只读再睡一次，这回推进了。

### US-004：存档的分片、格式与版本口径

**描述**：作为开发者，我想要一份按分片声明、按 ADR-0015 与 ADR-0017 处理版本的存档格式，以便后面每个系统加自己的分片时不动存档本身。

**验收标准**：

- [ ] 可测试：分片声明里的标识、持有者、进哪一侧与存档默认值各缺一次，都注册被拒；同一个标识注册两次被拒；「进哪一侧」只有正式存档与临时续玩点两个取值。
- [ ] 可测试：已注册分片的读口列出的正是注册过的那几个，不多不少。
- [ ] 可测试：日历与地块这两个分片存进去再读出来完全一致，地块逐格逐项比（含变异那一位）。
- [ ] 可测试：分片按逆序、乱序读，结果与顺序读一致。
- [ ] 可测试：版本口径各一条用例。比当前旧的版本缺字段，补那个分片的存档默认值；同版本缺字段被拒，并说清哪个分片缺哪一项；比当前新的版本被拒；低于最低兼容版本被拒；分片里多出来的字段被丢弃；不认识的分片不丢，载入被拒并点名它（隔离那条路归 `ENG-7`）。
- [ ] 可核对：把「同版本缺字段」临时改成补默认值跑一次，那条用例失败，再改回。这条钉的是 ADR-0015 的承重项。
- [ ] 可测试：地块分片存的项与[地块系统 · 一格要存什么](../design/地块系统.md)那张清单逐项一致。那张清单缺「这一茬实际经过了几天」：它是产量系数的分母，由别的项算不出来（代码仓 `rules/Economy/Plot.cs`），随这一份补进清单。
- [ ] 可核对：分片里没有派生量；摘要不进存档。
- [ ] 可核对：存档文件最外层只有一个版本号与各分片；明文 JSON，用文本编辑器打得开、看得懂。

### US-005：写档不会写坏，进农场时读回

**描述**：作为玩家，我想睡下时存档要么写成完整的一份、要么一字不动，进游戏时接着上一次睡醒那一刻，以便进度不会丢。

**验收标准**：

- [ ] 可核对：写档是「在同一目录写临时文件 → 落盘 → 一次带覆盖的改名」，用 .NET 的文件接口，不用 Godot 的 `DirAccess.RenameAbsolute`；代码注释写明理由（见「技术考虑」）。
- [ ] 可核对：写成功之后输出面板一行：存档的绝对路径、总字节数、各分片的字节数。
- [ ] 可核对：进农场时有存档就读回，输出面板一行写读回的日期；没有存档就按开局那一天与场景里那片地开新档，也打一行。
- [ ] 可核对：存档在、但读不出来或被拒时，当场报错说清是哪个文件、哪一条，不开新档。开了新档，下一次睡觉就会把那份存档盖掉。
- [ ] 可核对：存档里那片地与场景里那片地对不上（改过那片地的位置或大小）时，当场报错说清多了哪几格、少了哪几格。
- [ ] 可核对：存档里的作物标识在作物定义里找不到时，载入被拒并点名哪一格、哪个标识（隔离那条路归 `ENG-7`）。
- [ ] 可核对：[文件读写与存档 · 七、原子替换：写坏了不丢档](../reference/godot/文件读写与存档.md)改成「技术考虑」里那套做法；[文件读写与存档 · 二、必须用引擎的文件 API，不能用 .NET 自带的](../reference/godot/文件读写与存档.md)写明存档这一处例外与理由；[文件读写与存档 · 十四、动手练习：写一个不会写坏的存档](../reference/godot/文件读写与存档.md)跟着改；[从哪里开始 · 睡一觉能推进一天](../reference/godot/从哪里开始.md)那条判据改成「把存档文件设成只读」。
- [ ] **作者实机确认**：睡一觉，停掉游戏，再跑农场，日期与每一格地都是睡醒那一刻的样子。

### US-006：床，以及调试键 N 走同一个入口

**描述**：作为玩家，我想走到床边按一下就睡，以便用世界里的一个动作结束这一天。

**验收标准**：

- [ ] 可核对：床是作者在农场里摆的一个交互点：一个节点挂床的脚本，下面一个 `Area2D` 当范围，在检查器里接上；缺了当场报错说清缺谁。[假设] 床先摆在农场里、离开那片地，等室内场景（`GP-130`）落地再搬进去。
- [ ] 可测试：站在床的范围里按交互键是睡；不在范围里按，照旧作用在当前操作格上。这一下由规则层挑，不看引擎返回的顺序（[交互点与站位点 · 四、多个交互点同时够得着时怎么办](../reference/godot/交互点与站位点.md)）。
- [ ] 可核对：调试键 `N` 调同一个入口，所以每按一次也写一次档、也弹摘要；从睡下到摘要关掉之前按 `N` 不起作用。
- [ ] **作者实机确认**：站到床边按交互键就睡；走开几步再按，是锄地或浇水而不是睡。

### US-007：醒来弹一份简版摘要，完整明细读同一份

**描述**：作为玩家，我想醒来时一眼看到昨晚变了什么，以便知道哪几格该收、哪几格该清。

**验收标准**：

- [ ] 可核对：醒来那一刻弹出简版摘要（弹窗那一层，作者排版）：一行写结算的是哪一天，下面每个有变化的项一行，写作物枯死几格、作物变异几格；没有变化的项不列。一项变化都没有的那天怎么办，见「待确认问题」。
- [ ] 可测试：简版与完整明细读的是同一份摘要；摘要里那个日期取自日历那一处。
- [ ] 可核对：手环那一页落地之前，完整明细打在输出面板上：每一格一行，写哪一格、哪种作物、枯死还是变异。作物素材表那份「这一晚变异的每一格各打一行」由它接替。
- [ ] 可核对：存档没写上时弹的是另一个弹窗，写「存档没写上，这一天没有推进」、原因、存档路径与「处理好之后再睡一次」。
- [ ] 可核对：弹窗开着时世界暂停，关掉之后交回操作；用的是既有的暂停判定，不另写。
- [ ] 可核对：睡下时播作者做的淡出，结算完播淡入，淡入播完才弹窗；遮罩缺了当场报错。
- [ ] **作者实机确认**：两个弹窗的排版、字放不放得下，转场快慢合不合适。

### US-008：跟着做的指南：睡一觉能推进一天

**描述**：作为作者，我想照一份指南在农场里摆好床、排好两个弹窗、做好转场遮罩，以便不读代码也知道每一格接什么。

**验收标准**：

- [ ] 可核对：新写一篇跟着做的指南，形状照[一块地能种出东西](../reference/godot/一块地能种出东西.md)：每一步写摆什么节点、挂哪个脚本、检查器里填哪几格、做完该看到什么；末尾一张症状表，至少有缺床的范围、缺弹窗、缺遮罩、存档对不上那片地、存档被拒这几种。
- [ ] 可核对：[从哪里开始 · 睡一觉能推进一天](../reference/godot/从哪里开始.md)那一格指到这篇。
- [ ] **作者实机确认**：照着搭完，睡一觉看得到转场与摘要。

### US-009：睡一觉能推进一天的端到端

**验收标准**：

- [ ] 自动化测试走完主路径：开新档 → 播种 → 推进到成熟（变异必中）→ 摘要列出那一格变异 → 写出存档 → 用写出的那一份重新载入，日期与每一格地都一致。
- [ ] 覆盖失败路径：写档失败时世界与存档都不动、摘要交出零次；同版本缺字段被拒；换季那天不当季的作物枯死，并进了摘要。
- [ ] 测试独立可重复：随机源注入；写档走注入的写入口，不碰真文件。
- [ ] 两个仓的入口全绿：代码仓 `python tools/verify.py`、设计仓 `python tools/check_docs.py`。
- [ ] 作者实机确认清单：先照[作物素材表那份的端到端 · 作者实机清单](./issues/issue-GP-147-crop-sheet-e2e.md)把农场搭到能种地，再照 US-008 那篇摆床、两个弹窗与遮罩。种几格，走到床边按交互键，看转场与摘要；把变异基础值临时调高，看摘要列出变异、输出面板逐格一行；停掉游戏再跑，看进度还在。种下一种作物、睡一觉存下来，停掉游戏，用文本编辑器把存档里的日期改成这一季最后一天、把那种作物的数据文件改成只在这一季，再跑、睡一觉，看那几格枯死、摘要列出枯死（看完把作物文件改回）。最后把存档文件设成只读再睡，看「这一天没有推进」，去掉只读再睡一次。

## 6. 非目标

- **存档位那一组与存档位列表**：份数在[玩法定位 · 存档](../canon/gameplay/玩法定位.md)；这一份只做一位，进农场时自动读它。存档位那一半跟 `GP-54`，列表与存档位摘要跟 `UI-20`。
- **临时续玩点**：它要恢复到「退出时的当天当刻」，而日内时钟还不存在。跟 `GP-54`。
- **日内时钟、到点强制结束、熬夜档位与那几次预警**：拆条目时另立一条。入口已经收「强制结束」这个来源，时钟落地时只接触发那一下。
- **睡前确认**：没有日内时钟时误睡丢不掉任何东西，[ADR-0026](../decisions/ADR-0026-一道确认由误触与收益的落差决定.md)那条判据在这里答不出来；并进上一条，等时钟落地再答。
- **手环里那一页结算完整明细**：跟 `UI-20`。那一页落地时要先答一件这一份没答的事：摘要不进存档，停掉游戏再进来，昨天那份明细从哪来。
- **不可用清单与缺 mod 的隔离**（`ENG-7`）、**更新公告**（`UI-23`）：遇到对应情形，这一份一律拒绝载入并说清原因，不丢数据。

- **床搬进室内**（`GP-130`）与**床前的交互提示**：够不够得着，按一下就知道。

## 7. 界面与表现考虑

- **简版摘要**答「这一夜变了什么」：最上面一行是结算的是哪一天（第几年、哪一季、第几天），下面每个有变化的项一行，项名照[时间与经营 · 每日结算](../canon/gameplay/时间与经营.md)那份清单的写法。排版归作者。
- **「这一天没有推进」那个弹窗**答「这一天到底有没有推进」：第一句就要说没有推进，不许只说「保存失败」（[`界面系统` · 主菜单那一侧：读档位列表、更新公告、设置](../design/界面系统.md)）；后面跟原因、存档路径与「处理好之后再睡一次」。
- **两个弹窗都在弹窗那一层**（代码仓 `rules/UI/UILayer.cs`）：作者把它们摆在 `UIRoot` 下面，由它挪到那一层（代码仓 `src/UI/IPlacedUI.cs`）；打开时世界暂停、关上交回，都是既有的那一套。
- **遮罩在遮罩层**，不进导航栈，所以它不暂停世界。淡出与淡入的快慢由作者在 Godot 里做的那两段决定，代码里没有时长。
- **新增的字进文本表**（代码仓 `data/text/zh-CN.json`）：季节名、日期的写法、两个项名、「这一天没有推进」那几句。
- **字放不下**：原因与路径可能很长，照[文字与文本框 · 六、字放不下：对话框分页，别处按整行滚](../reference/godot/文字与文本框.md)办。

## 8. 技术考虑

- **落点**：日历与结算驱动落 `Rules.Economy`（时间与经营），存档的分片、格式与版本判定落 `Rules.Foundation`（跨系统基础设施），照代码仓 ARCHITECTURE 那张命名空间表。读写文件那一下、床、两个弹窗与遮罩落 `src/`。
- **世界状态要复制得出来**，这是[`每日结算系统` · 下游同步](../design/每日结算系统.md)对代码提的那条结构要求。这一份里世界状态只有日历与那片地。地块现在全是私有 setter、没有复制的口（代码仓 `rules/Economy/Plot.cs`），要加一个；那片地也从农场节点（代码仓 `src/World/Farm/FarmField.cs`）搬进规则层的世界状态，农场节点只管画它，并把玩家那一下交给它。
- **写档不用 Godot 那一套**。读的是 Godot 4.7.2-stable 的源码：
  - `DirAccess.RenameAbsolute` 在 Windows 上，目标已存在时先删目标、再 `MoveFileW`（[dir_access_windows.cpp](https://github.com/godotengine/godot/blob/4.7.2-stable/drivers/windows/dir_access_windows.cpp)）。删完、改名之前断电，盘上一份存档都没有；改名失败时旧档已经删了。
  - `FileAccess.Flush` 在 Windows 上只调 `fflush`（[file_access_windows.cpp](https://github.com/godotengine/godot/blob/4.7.2-stable/drivers/windows/file_access_windows.cpp)）：数据进了系统缓存，不保证到盘。
  - Godot 自己那套安全保存（写临时文件、关闭时 `ReplaceFileW`）只在 `backup_save` 打开时生效，它默认关（[file_access.h](https://github.com/godotengine/godot/blob/4.7.2-stable/core/io/file_access.h)）。只有编辑器进程会打开它是推断，这里也不依赖它。
  - 所以改用 .NET：`FileStream` 写临时文件、`Flush(true)` 落盘（[微软文档](https://learn.microsoft.com/dotnet/api/system.io.filestream.flush)：要保证中间缓冲写到盘上就用这个重载），再用 `File.Move` 带覆盖换上去，它在 Windows 上是一次带 `MOVEFILE_REPLACE_EXISTING` 的 `MoveFileExW`（[dotnet/runtime 源码](https://github.com/dotnet/runtime/blob/main/src/libraries/Common/src/Interop/Windows/Kernel32/Interop.MoveFileEx.cs)）。读档也走 .NET，存档只有一条路。以上几处内容为合规做过改写。
  - 这一下照代码仓 ARCHITECTURE 留在引擎层，所以它没有单测：事务的成败在规则层用注入的写入口测，真文件那一下靠 US-003 与 US-005 的实机。
- **只读那一条怎么做**（实测，本机 Windows，用 Python 的 `os.replace`，它与 `File.Move` 底下是同一个 `MoveFileExW`）：给存档目录打只读属性挡不住，替换照样成功；给存档文件打只读属性，替换被拒（拒绝访问），目标一字不动；用目录权限拒绝写入也挡得住，临时文件建不出来。所以实机写「把存档文件设成只读」，里程碑那条判据跟着改。**待验证**：.NET 那一下遇到只读目标同样被拒。验证办法：实现时在本机写一份、设只读、再写一次，看它抛 `UnauthorizedAccessException` 而目标不变。
- **杀毒软件锁文件**：Godot 自己的安全保存为此把替换重试上千次（同上那份源码里的注释）。这里不重试，失败就走「这一天没有推进」，那是安全的一侧；真撞到再加。
- **步名表与正典的对账放在设计仓** `tools/check_docs.py`：它已经读代码仓（点名已关闭编号的代码注释那条守卫就在读）。放进代码仓的测试，测试就离不开设计仓。
- **步名取正典那一条的开头**：正典那张表的条目长短不一、加粗的位置也不统一，没有一条规则能直接把条目变成名字；取开头不改正典一个字，增删、调序与开头改字都判得出来。
- **随机源**：变异仍由引擎侧注入系统随机数，规则层只收「这一次中没中」，与作物素材表那份同一条。
- **输入**：从睡下到摘要弹出之前不收输入，闸在输入门面（代码仓 `src/UI/InputRouter.cs`）与 `N`、`B` 那两个直读按键的地方；不碰 `SceneTree.Paused`。
- **结算多快**：地块按格数线性算，按推断远小于一帧；实机那一条并进转场快慢一起看。
