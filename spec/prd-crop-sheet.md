# PRD：作物素材表接进游戏，作物成熟时会变异

## 1. 概述

作物素材是一整张表：每种作物一行，从左到右是生长阶段、变异成熟、枯死、种子、收获物与变异收获物。
表在代码仓 `assets/self-drawn/crops/crop1.png`，一格 16×16：第 1–4 列是生长阶段（第 4 列是成熟），
第 5 列变异成熟，第 6 列枯死，第 7–9 列是种子、收获物与变异收获物三张物品图。规则在 [ADR-0030](../decisions/ADR-0030-作物成熟时按几率变异.md) 与[`地块系统`](../design/地块系统.md)，
代码还接不住它：

- 作物素材（代码仓 `src/World/Farm/CropArt.cs`）没有变异成熟那一格。
- 地块（代码仓 `rules/Economy/Plot.cs`）不会掷变异，收获也不带「这一株变了」。
- 工程里只有一条试验作物，而且没有素材。
- 指南[一块地能种出东西 · 第七步：画作物，配素材](../reference/godot/一块地能种出东西.md)还是「一张一个文件」那一套，不讲怎么从一整张表上取格子。

**为什么现在做**：素材已经画好。

**分工**（[ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)）：作者在 Godot 里从整张表上框格子、
给每种作物建一份作物素材、拖进 `Field`；我写规则、引擎侧接线、数据文件与指南。

## 2. 目标

- 掷中的那一株在地里显示变异成熟那张图，没掷中的显示成熟那张。
- 变异那一株收上来时带着「变异」交给产出那一手；品质落地之后它就是变异品质。
- 素材表上每一种作物都种得下去、长得出来，阶段天数、能不能反复收与季节都在数据文件里改得动。
- 变异几率在检查器里改得动，没填当场报错。
- 作者照指南从一张素材表配出全部作物，缺哪一张报错说清是哪种作物的哪一格。

## 3. 上游约束

- [ADR-0030](../decisions/ADR-0030-作物成熟时按几率变异.md)：成熟那一下掷、收上来全是变异品质、每熟一茬重掷、
  几率是基础值加两路修饰且上限小于 1。**这是本需求全部规则的来源。**
- [`地块系统` · 变异几率：一个基础值，加事件与设备两路修饰](../design/地块系统.md)、
  [`地块系统` · 一格要存什么](../design/地块系统.md)与那一份的验收：**约束合成规则、那一位存在哪、要配哪几条用例。**
- [场景绘制约定 · 作物按它声明的阶段数交付](../production/场景绘制约定.md)：一种作物的张数是阶段数加变异成熟加枯死。
  **约束作物素材那几格。**
- [ADR-0022](../decisions/ADR-0022-内容清单的家是数据文件.md)：内容清单的家是代码仓 `data/`。**约束作物数据只写在那里。**
- [玩法定位 · 内容规模基准](../canon/gameplay/玩法定位.md)：作物那一行是起步量、不是上限，归 `GP-88`。
  **本需求的作物是占位内容**，正式清单仍归那一条，跨季那一半也在那时核。
- **依赖**：品质要等 `GP-22`；简报那一项要等 `GP-56`；那一位落盘要等 `GP-54`。

## 4. 用户故事

### US-001：作物素材多一格变异成熟，缺了说清是哪一种

**描述**：作为作者，我想给每种作物配一张变异成熟图，漏配一张时载入就告诉我是哪一种，以便不用在地里一株株找。

**验收标准**：

- [x] 可核对：作物素材在检查器里多出「变异成熟」一格，排在枯死那一格前面。
- [x] 可核对：那一格空着时，载入报错写明作物标识与缺的是变异成熟那一张。
- [ ] **作者实机确认**：故意空一种作物的那一格跑一次，报错说得清缺谁。

### US-002：长成那一晚掷一次变异

**描述**：作为玩家，我想看到有的作物长成时变了样，以便地里偶尔出一株好东西。

**验收标准**：

- [x] 可测试：随机源注入成必中时，长成那一晚这一格变成「变异」；注入成必不中时不变。
- [x] 可测试：没到成熟的那几晚一次都不掷（必中也一样），掷的次数数得出来。
- [x] 可测试：能反复收的作物收完那一位清掉，下一次长成重掷（先中后不中，两茬一变一不变）。
- [x] 可测试：换季枯死与清掉枯株都清掉那一位；「变异」只在待收那一态为真。
- [x] 可核对：推进一天之后，这一晚变异的每一格各打一行输出 —— 睡后简报落地之前的替身。

### US-003：变异几率的基础值与上限在检查器里填，修饰有入口

**描述**：作为作者，我想在检查器里改变异几率的基础值与上限，以便实机种几季之后调到合适。

**验收标准**：

- [x] 可测试：几率 ＝ 基础值加修饰之和、再钳在上限以内；没有修饰时就是基础值。
- [x] 可测试：基础值不大于零、基础值大于上限、上限不小于 1，各自当场被拒并说清是哪一条。
- [x] 可测试：负的修饰被拒 —— 事件与设备那两路只往上调。
- [x] 可核对：`Field` 节点多出基础值与上限两格，都没有默认值；不填时启动当场报错。

### US-004：收上来的东西带着「变异」

**描述**：作为玩家，我想知道这一次收的是不是变异的那一株，以便它进仓库时不和普通的混在一起。

**验收标准**：

- [x] 可测试：变异那一株收获时，收获结果写着变异；件数照常按浇水算，与没变的同一套。
- [x] 可核对：输出面板那一行收获记录在变异时带一个「变异」标注。

### US-005：地里按那一位换图，作物按接地那一行排前后

**描述**：作为玩家，我想一眼看出哪一株变了，并且走到作物后面时被它挡住。

**验收标准**：

- [x] 可核对：待收且变异的那一格显示变异成熟那张，其余照旧。
- [x] 可核对：作物精灵的原点落在格子底边中点、图往上画，与角色的脚底原点同一个口径。
- [ ] **作者实机确认**：把基础值临时调高，一片地里看得到变与没变两种成熟；人站进一株作物那一格的上半截时被它挡住。

### US-006：素材表上每一种作物都有一份占位数据，启动时就解析

**描述**：作为作者，我想先拿占位数值把每一种都种起来，以后在数据文件里改天数、季节与能不能反复收。

**验收标准**：

- [x] 可核对：代码仓 `data/crops/` 下素材表每一行一份作物定义，标识按行号补零取，排序与行序一致；试验用的那一份删掉。
- [x] 可核对：每份都是三个计时阶段各 1 天、只收一次、四季都能种，文件里写明这是占位值、归 `GP-88` 与 `GP-7`。
- [x] 可核对：文本表每种作物一个名字、一个描述，占位写成「作物N」「作物描述N」；正式文案只改这一处。
- [x] 可核对：游戏启动时逐份解析作物定义并打出在册数；有一份解析失败，代码仓 `python tools/verify.py` 的跑产物那一步判失败。

### US-007：随身栏装不下全部作物，按一个键换下一批

**描述**：作为作者，我想在地里把素材表上每一种都种一遍，以便在实际尺寸下逐种看。

**验收标准**：

- [ ] 可核对：一个开发期调试键把随身栏换成下一批种子（按标识排序、每批装满随身栏），最后一批之后回到第一批。
- [ ] 可核对：它与 `N` 一样直接读按键、不进输入映射，所以不会出现在玩家能改键的那份清单里。
- [ ] **作者实机确认**：每一种都种下去、长到成熟看过一遍。

### US-008：指南那一步改成从一张素材表上框格子

**描述**：作为作者，我照指南从整张素材表配出全部作物素材，不用先切成一张张小图。

**验收标准**：

- [x] 可核对：[一块地能种出东西 · 第七步：画作物，配素材](../reference/godot/一块地能种出东西.md)改成：素材表放进 `assets/self-drawn/crops/`，每格用一个 AtlasTexture 框出来，配好第一种之后复制一份、改行号。
- [x] 可核对：那一节写清素材表每一列对应作物素材的哪一格，以及区域怎么由列号、行号与格宽算出来。
- [x] 可核对：症状表加上「缺变异成熟那张」与「框错一格」。
- [ ] **作者实机确认**：照着配完全部作物，载入不报缺。

### US-009：作物素材表接进游戏的端到端

**验收标准**：

- [ ] 自动化测试走完主路径：播种 → 推进到长成（必中）→ 待收且变异 → 收获结果带变异 → 回到已锄。
- [ ] 覆盖失败路径：上限不小于 1 被拒；没到成熟不掷；循环作物下一茬重掷、不继承上一茬。
- [ ] 测试独立可重复：随机源注入，不读真随机。
- [ ] 两个仓的入口全绿：代码仓 `python tools/verify.py`、设计仓 `python tools/check_docs.py`。
- [ ] 作者实机确认清单：打开代码仓 `scenes/farm/farm.tscn`，照[一块地能种出东西](../reference/godot/一块地能种出东西.md)搭到能种地。数字键与十字键各换几格，右下角那条随身栏的选中框跟着走；当前操作格够得到与够不到那两张照[一块地能种出东西 · 第五步：框出当前操作格](../reference/godot/一块地能种出东西.md)看。这两样要农场搭起来才看得到，所以界面素材那份需求的这两格实机放在这里。再把基础值调到一半左右，种一排按 `N` 到成熟，看得到两种成熟；收一株变异的，输出面板写着变异；按换批键把每一种都种一遍。

## 5. 功能需求

- FR-1：作物素材必须有一格变异成熟图，空着时载入报错并写明作物标识。
- FR-2：作物长到成熟那一晚，系统必须对那一格掷一次变异，而且只掷这一次。
- FR-3：系统必须把掷出的结果存在那一格上，读的时候不重算。
- FR-4：收获之后，系统必须清掉那一格的变异标记，能反复收的作物也一样。
- FR-5：作物枯死时，系统必须清掉那一格的变异标记。
- FR-6：系统必须按「基础值加修饰之和、再钳在上限以内」算这一次的几率。
- FR-7：基础值不大于零或大于上限、上限不小于 1 时，系统必须拒绝并说清是哪一条。
- FR-8：修饰为负时，系统必须拒绝。
- FR-9：变异那一株收获时，收获结果必须带着「变异」。
- FR-10：待收且变异的那一格必须显示变异成熟那张图。
- FR-11：作物精灵的原点必须落在格子底边中点。
- FR-12：游戏启动时必须逐份解析作物定义，解析失败当场报错。
- FR-13：推进一天之后，系统必须为这一晚变异的每一格打一行输出。
- FR-14：开发期调试键必须把随身栏换成下一批种子。

## 6. 非目标

- **品质本身**：变异品质要等物品定义（`GP-22`）；本需求只到「收获结果带着变异」。
- **睡后简报那一项**：等 `GP-56`，现在用输出面板那一行顶着。
- **存档**：那一位随地块状态一起存，等 `GP-54`。
- **事件与设备那两路修饰的来源**：几率规则收修饰，但现在没有谁往里写（`GP-52`、`GP-28`）。设备摆在田里、只管周围几格（[ADR-0031](../decisions/ADR-0031-作用在田地上的设备摆在田里.md)），那一侧的摆位与覆盖跟设备一起落地。
- **素材表第 7–9 列**（种子、收获物、变异收获物三张图标）：物品定义还不存在，这三列先不框，跟 `GP-22` 一起做。图标那一格引一张贴图资源，单张或表上一格的 AtlasTexture 都行（[界面绘制约定 · 文件放哪、叫什么](../production/界面绘制约定.md)）。
- **正式的作物清单与文案**：清单归 `GP-88`，名字与描述作者自己写。
- **数值**：阶段天数与几率都是占位，归 `GP-7`。

## 7. 界面与表现考虑

- 能不能收仍只靠成熟那张图的轮廓；变异成熟与成熟之间只靠颜色分也行（[场景绘制约定 · 作物按它声明的阶段数交付](../production/场景绘制约定.md)）。
- 不加悬浮图标，也不加特效。
- 随身栏里种子的图标要等物品定义的图标那一格才有来源；在那之前选中的是哪一种，看播下去的那一株。

## 8. 技术考虑

- **从素材表上取一格**：Godot 的 AtlasTexture 截另一张贴图上的一块区域（[官方文档](https://docs.godotengine.org/en/4.7/classes/class_atlastexture.html)，内容为合规做过改写）。区域是检查器里一格可直接改的矩形，所以复制一份之后只改纵坐标。
- **会不会串到邻格**：项目是最近邻过滤加整数缩放，按推断不会。**待验证**：作者配第一种时看一眼格子边缘；串了就打开它的 `filter_clip`，文档说它把区域外的像素裁掉。
- **随机源由调用方注入**，规则层只拿到「这一次中没中」，所以测试可重复；引擎那一侧用系统随机数。
- **启动时解析作物**加在主场景的脚手架里（代码仓 `src/Main.cs`），与角色同一处。理由：农场不是主场景，除了农场没有任何东西读这批文件，所以一份坏掉的作物定义只有进农场才报错。
- **精灵原点改到底边中点**靠 Sprite2D 的 `Offset`：Y 排序比的是节点位置（[官方说明](https://docs.godotengine.org/en/4.7/classes/class_canvasitem.html#class-canvasitem-property-y-sort-enabled)），而现在节点位置是图的左上角，所以人站进作物那一格的上半截时压在作物上。**这一条是读代码推断的**，实机那一格在 US-005。
- **规则层的修改面**：地块（代码仓 `rules/Economy/Plot.cs`）多一位、按天推进多一个参数、收获结果多一格；它的现有用例要跟着补上随机源。

## 9. 待确认问题（阻塞项）

无。「一茬只在长成那一晚掷一次」已写进 FR-2 与 US-002，理由的家在[`地块系统` · 变异几率：一个基础值，加事件与设备两路修饰](../design/地块系统.md)。

## 10. 成功判据

- 素材表上每一种作物都配进游戏，载入不报缺。
- 把基础值调高之后，一片地里同时看得到变与没变两种成熟；变了的那一株收上来带着变异。
- 两个仓的入口全绿。
