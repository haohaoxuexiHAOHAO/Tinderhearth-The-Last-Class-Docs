# PRD：把设计评审查出来的内容与爽感缺口按批次补上

## 1. 概述

一轮全库评审（`canon/` 与 `design/` 通读）查出三类问题：**文档内部已经打架或漏了持有者**、**玩家一侧缺东西**（一天的决策会收敛、后期没得盖、打完一关没有变强的感觉）、以及**几处设计意图需要作者重新定调**。作者已逐条定调，本 PRD 把结论按依赖顺序排成四个批次。

**为什么现在做**：批次 B 的结论是经营内容清单的输入 —— 六条生产渠道各强在哪没定下来，那批产量与内容清单就写不出来，写了也要回头改。批次 A 最便宜且不动设计意图，做完之后后面三批不会再撞上旧矛盾。

**四个批次按顺序做，不并行**：

| 批次 | 内容 | 用户故事 |
| --- | --- | --- |
| **A** | 文档内部一致性：矛盾、漏账与两处引用错误 | US-001 – US-009 |
| **B** | 生产与经济重规划：渠道优势维、二级加工链、季内价格、后期可盖的东西 | US-010 – US-013 |
| **C** | 最终战学生那条线从演出改成真打 | US-014 – US-016 |
| **D** | 反馈与界面：战后结算、升档提示、档位读口、结局之后 | US-017 – US-021 |

## 2. 目标

- 玩家在经营侧的一天里**有理由改变昨天的做法**，而不是照抄一张最优表。
- 玩家盖完功能建筑之后**仍有东西可盖**，基地的空地有用途。
- 玩家打完一趟出征**当场就能看到自己变强了什么**。
- 玩家看得见**学生变强了哪一档**，而不只是感觉他好像会闪避了。
- 最终战学生那条线**真的打一场**，而玩家整个周目的投入在那一场里看得出来。
- 文档里**没有两处说法互相打架**、没有被声明了却无人持有的东西。

## 3. 上游约束

只链接，不复制。每条写明它约束本需求的哪一部分。

- [玩法定位](../canon/gameplay/玩法定位.md)：内容规模基准那张表是全部平衡判据的算账基准，**改它要重跑推演**；「谁在等它」那一列每行必须有编号。**约束 US-013 往那张表加行的形状。** 同一页的系统清单与「明确不做的系统」约束批次 B 不得引入新的玩法子系统。
- [时间与经营](../canon/gameplay/时间与经营.md)：六条产出渠道、加工配方单层、设备不得净产出自己的燃料、定价三层模型。**约束 US-010 与 US-011 要改哪几句正典。**
- [战斗与关卡](../canon/gameplay/战斗与关卡.md)：玩家直接操作主角、队友 AI 分档的两条轴与那条判据、片段之间是转场、失败判定要求玩家能返回入口撤出。**约束 US-001、US-003、US-014 与 US-019。**
- [角色与成长](../canon/gameplay/角色与成长.md)：生活技能的档位阶梯与「升档那一刻不弹界面」、关系只升不降。**约束 US-007 与 US-018。**
- [世界观](../canon/world/世界观.md)：穹盾三项改造是什么、活跃失衡的双向性与「越低越难再降」。**约束 US-002 与 US-020。**
- [主线故事](../canon/narrative/主线故事.md)：节点 16 两条战线、节点 17 的结局判定时点、支线二的窗口。**约束批次 C 全部与 US-020。**
- [节点里的学生](../canon/narrative/节点里的学生.md)：节点 16 那批蒙太奇瞬间，判据是每个瞬间都要兑现前面几年埋的某一条。**约束 US-016 —— 那批瞬间是这条线全部的情感回报，改成真打之后必须另有载体。**
- [ADR-0013](../decisions/ADR-0013-战斗片段就是一屏.md)：往回与撤离不锁。**US-001 要修的正是它与转场读条之间那处冲突。**
- [ADR-0018](../decisions/ADR-0018-内容定义按声明扩展.md)：一种内容只有一张定义表、条目自己声明能力。**约束 US-010 的「优势维」与 US-011 的「第几级」都写成声明项，不按类型分叉。**
- [ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)：交界面是 `[Export]` 与 `Resource`，作者填值。**约束批次 C 与 D 里「我做哪部分、作者做哪部分」的分工。**
- [数值模型](../design/数值模型.md)：判据的形式与尚未给值表。**US-010 要换掉一条判据并顺带解决一直没接上的 `C10`；批次 B 与 C 新增的量一律登记进尚未给值表，不在本轮给值。**
- **依赖关系写明**：本 PRD 的落地大量卡在还没实现的系统上（队友 AI、剧情演出、状态载体扩容、场景本体、内容载入路径）。**各项当前状态一律查[待办台账](./issues/README.md)，本 PRD 不复述。** 本轮交付的是**文档侧**，落地跟各自编号走。

## 4. 用户故事

### 批次 A · 文档内部一致性

#### US-001：打不过的房间要真的退得出来

**描述**：作为玩家，我想要在一屏打不过时能退回上一屏，以便不必靠角色倒下来结束这一趟。

现在 [ADR-0013](../decisions/ADR-0013-战斗片段就是一屏.md) 保证往回与撤离不锁，而 [`关卡系统`](../design/关卡系统.md) 同一节又写明转场读条要挡住「被追着的时候走不掉」。被围住时读条完不成 —— 那条出路在最需要它的那一刻关上了。**改法：往回退的读条受击不中断，只延长。** 挡脱离的目的保住（被追着就走得慢），退路也保住。

**验收标准**：

- [ ] 可核对：[`关卡系统`](../design/关卡系统.md) 里「读条受击中断」对往前、往回与撤离三个方向不再是同一条规则，差别与理由都写明
- [ ] 可核对：那一节原先「没选让往回退免读条」那段论证跟着改 —— 它现在反对的是一个已经不成立的方案
- [ ] 可测试：延长量登记进[数值模型](../design/数值模型.md)的尚未给值表，归属列写 `GP-6`
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

#### US-002：练到老练的学生不会看起来像坏了

**描述**：作为玩家，我想要学生不闪避时有一个我看得懂的原因，以便不把它当成 bug。

[`活跃失衡系统`](../design/活跃失衡系统.md)的增益分档表在失衡很高时改行为（不再闪避与防御），而[`战斗AI系统`](../design/战斗AI系统.md)的操作档在中间那几档解锁「会闪避有预警的攻击」。两张表都改行为、都没提对方，谁优先没写，不一致时不报错。**改法：写死失衡那一档优先，并在两份文档里各写明这是有意的代价。**

**验收标准**：

- [ ] 可核对：两份文档各写明优先关系，且各指向对方那一节
- [ ] 可测试：落地那一轮要一条反证 —— 给一个高操作档角色挂上畸形那一档增益，他不执行闪避
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

#### US-003：敌人的每一招都查得出它能不能被打断

**描述**：作为实现者，我想要敌人的出手只有一份定义，以便那条「全部敌人合起来覆盖每一种对策」的载入校验有可遍历的对象。

现在[`技能系统`](../design/技能系统.md)说不碰敌人的招，而[`战斗AI系统`](../design/战斗AI系统.md)说敌人的恢复手段走技能、分级面板也给敌人一栏技能。结果是「能不能打断」那一格在攻击定义上，而要被打断的那一招在技能定义上。同一处还缺一格：**敌人定义与它的攻击定义之间没有任何引用**。

**改法**：敌人的一切出手统一走攻击定义（含恢复类），技能那一格只留给主角与队友；敌人定义上加一格「它有哪几招」。

**验收标准**：

- [ ] 可核对：两份文档对「敌人的招是什么」只有一种说法
- [ ] 可核对：敌人定义的字段表里有指向攻击定义的那一格，缺了载入报错
- [ ] 可测试：那条覆盖校验写得出遍历路径（敌人定义 → 它的招 → 每招声明的对策）
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

#### US-004：四样被声明了却无人持有的东西各归其主

**描述**：作为实现者，我想要每一样被别人引用的东西都有一份文档持有它，以便实现时不必去猜谁该写。

四样各自的现状与去处：

| 什么 | 现在的问题 | 归谁 |
| --- | --- | --- |
| 这一关放哪几种敌人 | 关卡侧交出预算不交种类，AI 侧说种类是内容不管配额 | [`关卡系统`](../design/关卡系统.md)：片段库按遗址分组时带一份敌人种类池 |
| 典籍「全作只出现一次」谁来去重 | 教育侧推给掉落表，关卡侧说不判箱子里该不该是它 | [`教育系统`](../design/教育系统.md)持有那份记录，掉落时查它 |
| 没被派工的学生去哪 | 生产、天气、节日三份都写明不做它 | 正典写一条最小版：**去他关系最好的那个人旁边待着**。完整日程仍然后置 |
| 基地那台灵分析设备 | [`天气系统`](../design/天气系统.md)的精确预报整档挂在它上面，而生产侧没有它 | [`生产系统`](../design/生产系统.md)的设备那一节补上它 |

**验收标准**：

- [ ] 可核对：四样各在指定文档里有字段或规则，且原先推走它的那几句改成指向新家
- [ ] 可核对：敌人种类池与典籍去重记录两样缺了都载入报错
- [ ] 可核对：最小版学生日程写进正典，且与完整日程的边界写明（完整版仍后置，编号照旧）
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

#### US-005：关卡里的事件不会被刷

**描述**：作为玩家，我不希望进关看一眼、退出去再进来就能把同一件好事刷第二遍。

两处口子：**关卡内触发过的事件记在哪**（[`事件系统`](../design/事件系统.md)说记账只进正式存档，而关卡内退出只写临时续玩点 —— 往返之后要么丢了可以重触发、要么那条声明不成立）；**换一条委托就是一个新种子**（「同一个种子拼出同一张图」挡住了重进同一关，挡不住换一个）。

**验收标准**：

- [ ] 可核对：事件记账在关卡内退出时落在哪一侧写明，且与那条「不进续玩点」的声明不再冲突
- [ ] 可测试：一条反证 —— 关卡内触发一条一次性事件、退出、恢复，它仍算触发过
- [ ] 可核对：换种子那条口子有一个明确处置（挡住或写明接受），不留在无人知道的状态
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

#### US-006：四个被声明的读口各有一处界面

**描述**：作为玩家，我想要看得到学生今天还吸收得进去多少、这一科考了多少、和某人的关系走到哪、这一片过得怎么样。

这四个读口被各自的系统文档写进了接口表，而[`界面系统`](../design/界面系统.md)里接住它们的页不存在：知识吸收效率、考试成绩明细、关系填充量（爱心）、境况档位。**系统在、读口在、页不在，而没有任何东西会报错。**

**验收标准**：

- [ ] 可核对：四个读口各在[`界面系统`](../design/界面系统.md)里有一页或一项接住，每处按那份文档既有的三样写（答什么问题、必须显示什么、什么不许藏）
- [ ] 可核对：那一页原先「不装本轮之外的界面」那条边界跟着改口径，说明这四项为什么现在进来
- [ ] 界面类故事：**作者实机确认** —— 打开手环与角色面板，四项都找得到且读得懂
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

#### US-007：聊天不能无限刷关系

**描述**：作为玩家，我想要「顾不上所有人」这件事是真的，以便派工与教学的选择有分量。

[`人际系统`](../design/人际系统.md)把全部压力押在每日涨幅上限（因为关系只升不降），而送礼按件、个人请求按次、教学一天一次都写了节流，**只有对话没有** —— 走过去按一下键就能对全队每人吃满上限。

**改法**：每人每天**第一次**对话涨关系，之后是普通聊天、**每人每天最多 3 次**；超出之后他不再回应新的闲聊。

**验收标准**：

- [ ] 可核对：那条涨法在[`人际系统`](../design/人际系统.md)里有自己的节流阀，与其余涨法写成同一形状
- [ ] 可测试：一条反证 —— 同一个角色当天第二次对话不产生关系增量
- [ ] 可测试：第五次闲聊被拒，且拒绝有玩家看得见的表达（不是静默无反应）
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

#### US-008：教得多，考试就看得出来

**描述**：作为玩家，我想要多上几节课能让这个学生这一科考得更好，以便教学的反馈链走完最后一步。

现在成绩 = 这一科全部书的掌握度之和，而每本典籍全作只出现一次。所以**玩家把书分给了谁，别人这一科就永远追不上，教再多也没用**；加上考差零惩罚（这条对），结果是中后期考试只剩一条播报。

**改法**：成绩 = 这一科的掌握度**除以这一科的书数**，没有书的科目不计入。

**验收标准**：

- [ ] 可核对：[`教育系统`](../design/教育系统.md)的成绩算式改成折算式，且写明没书的科目不计入
- [ ] 可测试：同一个学生在书数不同的两科上，教同样多节课得到可比的成绩
- [ ] 可核对：掌握度的上限那一格补上（现在没有声明），或写明它为什么不需要上限
- [ ] 可核对：那条硬约束「小到多上一节课看得出来」跟着新算式重述一遍
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

#### US-009：两处引用错误改掉

**描述**：作为读者，我想要文档里的引用都指得到真东西，以便不必自己去核。

- [`天气系统`](../design/天气系统.md)举例说风沙那天「看得更近」可以写成视野那个量，而[`成长系统`](../design/成长系统.md)的派生表里**没有视野这一行** —— 按天气自己那条「引用派生表里不存在的量载入被拒」，它举的例子会被自己拒掉。
- [`任务系统`](../design/任务系统.md)字段表那句「委托档位只喂给关卡系统的敌人预算，不参与奖励以外的任何计算」一句里两半互斥，而同页的消耗表与经济侧的报酬表都按档位查 —— 档位实际参与敌人预算、报酬与消耗。

**验收标准**：

- [ ] 可核对：天气那处要么换一个派生表里真有的量当例子，要么给视野在派生表里开一行
- [ ] 可核对：任务那句改成与同页三张表一致的说法
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

### 批次 B · 生产与经济重规划

#### US-010：六条生产渠道各有自己的长处

**描述**：作为玩家，我想要每条生产渠道都有一件它做得最好的事，以便我按今天缺什么去选，而不是照抄一条收益最高的。

现在那条判据是「畜牧、钓鱼、烹饪与设备的每点精力收益都不得高于种植」—— 它防住了「更省事还更赚」，代价是把六条渠道排成一条线，而排成一条线之后第二名往后没人用。

**改法**：不比总收益，比**它强在哪一维**。三维各有对应的量：每点精力的钱、到手有多快、要不要你在场。判据换成两条：**不许严格支配**（不存在一条渠道在三维上都不劣于另一条）与**每条渠道至少在一维上最强**（写不出它最强在哪的渠道不该存在）。

各渠道的长处按现有规则填：种植是**每点精力的钱最高**（它仍是尺子）、畜牧出货最稳、钓鱼到手最快且不占任何格、加工价格天花板最高、烹饪是唯一出增益的且品质上限最高、设备是唯一不用你在场的。

**验收标准**：

- [ ] 可核对：[`生产系统`](../design/生产系统.md)的渠道表多一格「优势维」，缺了载入报错
- [ ] 可核对：[时间与经营](../canon/gameplay/时间与经营.md)那句旧约束换成新的两条，且写明旧那条当初在防什么、新的怎么接住
- [ ] 可测试：[数值模型](../design/数值模型.md)里旧判据换成两条新的，其中「不许严格支配」是推演算得出来的不等式组
- [ ] 可测试：一直没接上的 `C10` 随这一轮解决，且编号不复用
- [ ] 可核对：那条「必须与产量数值同一轮落地」的配对要求跟着新判据重写
- [ ] 可核对：`python tools/check_docs.py` 0 FAIL

#### US-011：加工可以有两级，但不会长成一张网

**描述**：作为玩家，我想要有些东西能加工两次变得更值钱，以便设备这条线在后期有意义。

现在正典写着加工配方单层、只做「采集素材 → 建造材料」，所以熏鱼这类「原料 → 更值钱的成品」不成立。

**改法**：单层放宽成**最多两级，且不限于建材**。配两条护栏：**每条配方声明它是第几级，写第 3 级载入报错**；**第二级只有设备能做，人工做不了**（否则设备就没有存在理由）。

**验收标准**：

- [ ] 可核对：[时间与经营](../canon/gameplay/时间与经营.md)那句「配方单层」改成两级上限，理由与被放弃的多级链一起写明
- [ ] 可测试：配方定义上有「第几级」那一格，填 3 载入报错
- [ ] 可测试：一条反证 —— 人工尝试做第二级配方被拒

#### US-013：盖完功能建筑之后还有东西可盖

**描述**：作为玩家，我想要在基地的空地上继续盖东西，以便经营到后期还有想做的事。

建造这条线现在唯一的长期动力是仓库不够用；可建造区的尺寸在正典里，功能建筑外观有封顶，所以盖完之后空地很多而没有东西填它。装饰性建造整块被推到后置且没有内容承接。

**改法**：**摆件与实用设备两条都要**，都走[`建造系统`](../design/建造系统.md)已有的室内外摆位（不新增结构），并在内容规模基准那张表里各加一行起步量与「谁在等它」。

**摆件不给任何数值收益**（作者已定）。另两条路都要动一份已经封好口的清单 —— 让它压活跃失衡等于给那一份多开一个入口，而它写明了只有三个入口且「照护不是第三个」；让它加精力上限等于给那张加项清单多一格，而那张清单刻意只写一次。摆件换的是「这是我的基地」那份感觉，不是战力。

**起步量**：装饰摆件 **8 件**（够铺满一间室内加一片室外，也够试出摆位网格与门前留空对摆件也成立）；实用设备在现有起步量之外**再加 2 台**，两级链的两端各一台 —— 否则 US-011 那条「第二级只有设备能做」试不出来。**这两个数是起步量不是上限**，后续按内容扩展，改它们要回头看那张表的判据前提还成不成立。

**验收标准**：

## 5. 功能需求

- FR-1：往回退的转场读条受击时必须延长而不是中断。
- FR-2：系统必须对往前、往回与撤离三个方向各自声明读条的中断规则。
- FR-3：当一个角色同时持有畸形档失衡增益与解锁了闪避的操作档时，系统必须执行失衡增益那一侧的行为。
- FR-4：敌人的一切出手必须走攻击定义，包括恢复类。
- FR-5：敌人定义必须声明它有哪几招，缺了载入报错。
- FR-6：片段库按遗址分组时必须带一份敌人种类池。
- FR-7：教育侧必须持有「这本典籍出现过没有」那份记录，掉落时查它。
- FR-8：没被派工的学生必须去他关系最好的那个角色所在位置待着。
- FR-9：生产侧必须持有基地灵分析设备的定义。
- FR-10：关卡内触发过的事件在临时续玩点往返之后必须仍算触发过。
- FR-11：每人每天第一次对话产生关系增量，之后不产生。
- FR-12：每人每天的普通聊天超过三次之后，系统必须拒绝并给出玩家看得见的表达。
- FR-13：考试成绩必须按这一科的掌握度除以这一科的书数算出，没有书的科目不计入。
- FR-14：每条生产渠道必须声明一个优势维，缺了载入报错。
- FR-15：系统必须判定不存在一条生产渠道在三维上都不劣于另一条。
- FR-16：系统必须判定每条生产渠道至少在一维上最强。
- FR-17：每条加工配方必须声明它是第几级，填第三级载入报错。
- FR-18：第二级加工配方只能由设备执行，人工执行时被拒。
- FR-19：需求系数必须读世界状态，且在手环里报得出当前值与一条原因。
- FR-20：最终战学生那一场里，学生倒下必须自动以低血量起身。
- FR-21：那次自动起身不得消耗「每人每关可被救起一次」的额度。
- FR-22：那一场必须记录打完用的时长、倒下过的人数与全程未受击的角色。

- FR-24：那一场打到声明的进度点时必须触发对应的短演出。

## 6. 非目标

**经营侧只加价格波动这一条。** 作物轮作、土壤与肥料、派工的组合收益、浇水的取舍**都不做** —— 判据是作者定的那一条：**不靠增加繁琐度换耐玩性**。

其余明确不做的：

- **不做三级及更多级的加工链。** 两级是硬上限，写第三级载入报错。
- **不给摆件任何通关相关的收益。** 它换的是长期留存，不是战力。
- **不让玩家操作学生。** 批次 C 改的是「谁驱动」，不是「玩家操作谁」—— 那句正典一个字不动。
- **不靠临时增益保证学生必胜。** 保证来自自动起身那条机制；增益只负责让他们打得像样。
- **不改结局判定的时点与它读的三条条件。** 批次 C 与 US-020 只改呈现与窗口。
- **不做完整的学生日程。** US-004 只写最小版，完整日程仍按台账后置。
- **不在本轮给任何值。** 新增的量一律登记进[数值模型](../design/数值模型.md)的尚未给值表，值跟各自编号走。
- **不做装饰摆件与实用设备的具体清单。** 本轮只在内容规模基准里立起步量与「谁在等它」，清单本身是内容。
- **不动那条「不做建筑耐久与维修」。** 布局定终身这件事接受，摆件本身就会让玩家想重排。
- **不碰活跃失衡那条个体层可以被时间买光的路径。** 它是评审查出的另一处结构问题，但它牵涉教学与失衡两侧的重新校准，**超出本 PRD 范围，另记一条待办**。

## 7. 界面与表现考虑

本 PRD 有四处界面新增或改动，都复用既有分层与载体分类（[`界面系统`](../design/界面系统.md)指向代码仓 `rules/Ui/` 那一批），**不发明第二套**：

## 8. 技术考虑

**批次 C 的可行性已经核过代码，不是推断。** `rules/Foundation/Actors/ActorControl.cs` 里有 `ActorControllerRegistry`，`Assign` 的注释写着「可替换是本类存在的全部理由」，且明确写了「任何『这个角色是不是主角』的判断都不得用来决定它由谁驱动」；`ActorControllerKind` 里 `Ai` 这个取值已经占位。现有实现是 `src/Platform/LocalPlayerController.cs` 与 `src/Platform/StationaryController.cs` 两个，**AI 是第三个实现，不是一处改造**。摄影机换跟随目标走 `rules/Ui/CameraRig.cs` 与 `src/World/GameCamera.cs`。

**落地的真实成本不在本 PRD 的故事上，在它的前置上**：队友 AI、剧情演出、状态载体扩容、场景本体与内容载入路径都还没实现。**各自状态查[待办台账](./issues/README.md)。** 好消息是这些本来就要做（每次出征都要用队友 AI），所以批次 C 不额外拖工期。

**批次 A 的 US-005 有一处需要落地时才判得到**：事件记账进正式存档而关卡内退出只写临时续玩点，两种处置（记账也进续玩点 / 关卡内事件另记一处）的代价要在实现时量一次存档体积。**现在能定的是口径，不是实现。** 待验证，验证办法是按[`存档系统`](../design/存档系统.md)那个按分片分摊字节数的读口量一遍。

**批次 B 的新判据比旧的难算。** 旧那条只要两个数，新的要六条渠道的产量与耗时全都有值才判得出来 —— 而那批值现在一个都没有。**结构本轮定，判定等产量进来**，这与旧那条原本的配对要求是同一个形状。
