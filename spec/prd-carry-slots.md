# PRD：随身栏 —— 玩家选得到「这一下用什么」

## 1. 概述

**现在玩家选不了要播的种子。** 地块那台状态机已经能跑（`GP-87`），一个键按当前格的状态派发六个动作；
但「已锄的格按下去播种」里**播哪一种**是检查器里写死的一个标识，游戏里换不了 —— 想种第二种作物得停下来
改参数重跑。

更根本的是：**「玩家怎么选一个逐格动作要用的东西」在全库没有任何编号持有。** 最近的两个各答另一半 ——
`GP-23`（背包与仓库）答「东西存在哪、能存多少」，`UI-27`（当前操作格）答「作用在**哪一格**」，
中间「我手上是什么、按下去用哪个」是空的。

**现在做的理由。** 一是它已经卡着两个下游：播种那处脚手架，以及 `GP-87` 里那条改了口径的实机
验收项（原本要试「对着可耕地按播种被拒」，而上下文派发让玩家没法主动选一个不该用的动作）。二是
[那份键位提案](../design/proposals/键鼠技能位挪到右手.md)早就为它留了位置 —— 数字键那一排腾出来之后
**刻意不补**，原话是留给「将来真要一条快捷道具栏」。

## 2. 目标

- 玩家**在游戏里**选得到要播的种子与要用的道具，不改配置、不重启。
- 关卡里用道具**不必打开背包** —— 正典把「翻包」与「用道具」分在暂停判据的两边，而现在只有翻包那条路。
- **不新开 HUD 块、不动四角锚点。** 六格与现有的六个技能位同宽，于是那一块的尺寸算式一个字不改，
  「不许压角色可读区」那条既有硬判据自动仍然成立。
- 载体一次做对，**内容来源分两步接** —— 先接得到种子，背包落地后换成背包前六格，不重做载体。
- **用道具两侧不同，而差别有判据** —— 关卡里读条（买的是「什么时候喝药」这个决策点），
  基地里即时且可连按（那里没有打断源，读条买不到东西，还挡住批量使用）；
  基地里高稀有度那种先弹一次确认，**确认之后当帧生效、不再读条**。
- **经营侧的操作以鼠标为主**，不沿用战斗侧那个交互键 —— 那个键的用处在采集、开箱与片段转场。

## 3. 上游约束

只链接，不复制。每条写明它约束本需求的哪一部分。

- [玩法定位 · 弹界面接管输入就暂停世界，世界里的动作不暂停](../canon/gameplay/玩法定位.md)：
  判据落在「界面接管输入」上。**约束随身栏不许接管输入** —— 它是常驻那一层的东西，按一下就用，
  不弹面板、不暂停。
- [时间与经营 · 翻包暂停，用道具不暂停](../canon/gameplay/时间与经营.md)：两半分属同一条判据的两边。
  **这是本需求存在的硬依据**：没有一个不开背包的入口，「用道具不暂停」那一半在关卡里落不了地。
- [`背包系统` · 关卡里：翻包暂停，用道具不暂停](../design/背包系统.md)：**约束内容来源** ——
  随身栏装的是背包里的东西，它不是第二个容器，**不新增一份存储**。
- [`界面系统` · 常驻那一层：战斗与经营的抬头显示](../design/界面系统.md)：那条「一项东西进不进 HUD，
  判据是玩家在动作进行中需不需要它」。**约束本需求要论证它过得了这条判据**，而不是因为星露谷有就加。
- [`关卡系统`](../design/关卡系统.md)写明「**不做工具与耐久**」以及「不用一套工具系统」：
  **约束栏里不装工具** —— 锄头水壶不是物品，一格都不占。
- [那份键位提案](../design/proposals/键鼠技能位挪到右手.md)：数字键那一排腾出来后刻意不补，留给快捷道具栏。
  **约束键鼠那一侧用哪几个键**，也意味着本需求**依赖那份提案先落地**（`UI-14`，见技术考虑）。
- [战斗与关卡 · 读条与打断](../canon/gameplay/战斗与关卡.md)：**使用道具有读条**、受击中断且中断不消耗，
  而那张打断表写明「『什么时候喝药』正是靠它才成为决策」。**这一条管的是战斗侧**（那一册的范围就是战斗与关卡），
  **约束本需求在关卡里不许把用道具改成即时** —— 改了就把那个决策点拆掉了。
- [`角色动作状态系统` · 经营场景：另一套动作机，共用同一份状态效果](../design/角色动作状态系统.md)：
  经营侧的**劳作**动作与战斗侧的采集与用道具是同一个形状（带读条、可打断、移动即取消）。
  **它定的是劳作，没有定经营侧用道具** —— 那一页列的经营侧劳作是工位劳作、授课、钓鱼与设备添料。
  **所以「经营侧用道具怎么用」是一处空白，由本需求答；答完要回写那一页。**
- [`界面系统` · 弹窗那一层：结算摘要与二次确认](../design/界面系统.md)：那条「不许长成凡是重要动作都弹一下」，
  判据是「它改不改变整个游玩形态」，按这条**确认框只有告别那一处**。**约束本需求不许给用道具加确认框。**
- [ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)：**约束分工** —— 格子长什么样、选中框怎么画、
  图标画什么归作者在 Godot 里定；本需求只定行为与量纲。

**依赖尚未裁定的东西，写明关系**：随身栏里那六格**默认装什么**取决于背包的堆与排序（`GP-23`，
设计已交付、尚未落地）。本需求因此把内容来源分成两步，见 US-003 与 US-004 的分界。

## 4. 用户故事

### US-001：六格随身栏出现在常驻那一层

**描述**：作为玩家，我想在屏幕上一直看得到随身的那几样东西，以便不打开任何面板就知道手上有什么。

**验收标准**：

- [ ] 可观察：基地场景里屏幕上有一条六格的栏，每格能显示一个图标与一个数量。
- [ ] 可核对：它**不新增 HUD 块** —— `rules/Ui/HudLayout.cs` 里 `HudBlock` 的取值个数不变。
- [ ] 可测试：那一块的宽度与六个技能位那一块**相等**（两者都是六个 16px 图标横排）。
- [ ] 可核对：`HudLayout.BlocksOverActorBand` 在 640×360 与拉宽的窗口下都返回空 —— 这是既有的硬判据，
      本需求不许让它变红。
- [ ] **作者实机确认**：格子边框、选中框、数量角标在 16px 图标上分不分得清；一屏之内它抢不抢视线。

### US-002：按数字键选中一格，选中态看得出来

**描述**：作为玩家，我想按一下数字键就换手上那样东西，以便不中断走动。

**验收标准**：

- [ ] 可测试：按 `1`–`6` 分别选中第 1–6 格，选中序号与按的键一一对应。
- [ ] 可观察：选中的那一格与其余五格**当场分得出来**。
- [ ] 可测试：**空格子也选得中** —— 选中一个空格等于「手上没东西」，而不是拒绝换格。
- [ ] 可核对：输入一律经 `src/UI/InputRouter.cs` 那个门面，代码里没有直接轮询引擎输入。
- [ ] **作者实机确认**：左手按住移动键时右手够不够得到那六个键（那份键位提案的痛点就是这一条）。

**执行那一下以鼠标左键为主。** 键鼠那一侧的当前操作格算法本来就是「取指针所在那一格」
（[`界面系统` · 世界里那一层：当前操作格，两个设备族共用一个读口](../design/界面系统.md)）——
指针已经在指格子，执行也用鼠标才不用两只手换位。

**刻意不沿用交互键。** 那个键（现在绑在 `F` 上）在文档里的用处全部在战斗侧：片段之间转场、采集资源点、
开箱。而经营侧**不用按键**已经判过两次 —— [`建造系统`](../design/建造系统.md)那条「走到门前就进去，
不按键、不读条」，与[`地图与导航系统`](../design/地图与导航系统.md)那条「没选给城区边界也加一次按键确认」。
**两处的理由是同一条**：战斗侧有追击压力，按键与读条各买到一样东西（防误触、防脱离）；
经营侧没有压力，那两样都买不到，按键只剩多一次操作。

所以 `rules/Ui/InputBindings.cs` 的 `InputSymbol` 枚举要补鼠标左键 —— 那条「鼠标键刻意不列入」的注释
自己留了这个口子（「将来建造界面用鼠标点格子……时再加回来」）。**手柄那一侧照旧走交互键**，
它没有指针。

### US-003：播种用的是选中那一格的种子

**描述**：作为玩家，我想选中一种种子再去播，以便一块地里种得下两种作物。

**验收标准**：

- [ ] 可测试：选中作物 A 播一格、换成 B 播另一格，两格长出来的是各自那一种。
- [ ] 可测试：选中的那一格**不是种子**时，对着已锄的地按动作键**被拒且说得出原因**。
- [ ] 可测试：选中的那一格是空的时，同上被拒。
- [ ] 可核对：`src/World/Farm/FarmField.cs` 里那个写死作物标识的导出属性**被删掉** ——
      脚手架换成真实来源，不是两条路并存。
- [ ] **作者实机确认**：换一种种子再播，这一下顺不顺手。

### US-004：用一样东西 —— 基地即时，关卡读条，稀有的先问一句

**描述**：作为玩家，我想在基地里连着用掉好几样东西不用等；在关卡里「什么时候喝药」仍然是个决策；
而全游戏只有几瓶的那种药，别让我手滑一下就没了。

**三条规则，一条判据。** 读条买的是**打断** —— 正典那张打断表写明「『什么时候喝药』正是靠它才成为决策」。
关卡里有受击，所以那笔买卖成立；**基地里没有打断源，读条买不到任何东西，只剩纯等待**，而它还挡住批量。
而那道确认买的是**另一样东西**（撤不回来之前问一句），所以它与读条不互相替代 —— **基地里是确认、
关卡里是读条，两者不叠加**：关卡里正被追着时弹窗会停住世界，那是那条判据本来就在防的事。

**验收标准**：

- [ ] 可测试：基地场景里用一样**非高稀有度**的消耗品**当帧生效**，没有读条、没有弹窗。
- [ ] 可测试：基地里**连按 N 次用掉 N 个**，中间不需要等待。
- [ ] 可测试：基地里用一样**高稀有度**的消耗品先弹一次确认，确认之后**当帧生效**（确认之后不再读条）。
- [ ] 可测试：那次确认被取消时**不消耗物品**。
- [ ] 可测试：关卡场景里消耗品**走读条**，读条途中受击**中断且不消耗物品**（正典原句）。
- [ ] 可测试：关卡里读条途中移动**取消且不消耗物品**。
- [ ] 可核对：「走哪一套」读的是**当前哪一台动作机在场**（经营／战斗），不是一个新造的场景开关。
- [ ] 可核对：那道确认按 ADR 写明的判据触发，**不是每件物品各带一个开关**。
- [ ] **作者实机确认**：基地里连着吃几样东西顺不顺手；那道确认弹出来的时机与措辞读不读得清。

### US-005：随身栏的内容来自背包，不是第二个容器

**描述**：作为玩家，我想随身栏显示的就是我包里那几样，以便不用维护两份清单。

**验收标准**：

- [ ] 可核对：随身栏**不持有任何存档字段** —— 它显示的是背包前六格的投影，唯一要存的是「现在选中第几格」。
- [ ] 可测试：背包里那一堆用完之后，随身栏对应那一格当场变空。
- [ ] 可测试：背包排序之后随身栏跟着变（它是投影，不是快照）。
- [ ] 可核对：`GP-23` 落地之前这一条以「种子清单」顶着，**而接口形状不变** —— 换来源不改 US-002 与 US-003
      的任何行为。

**这一条是本需求切成两步的那一刀**：载体一次做对，来源换一次。

### US-006：手柄上也切得动那六格

**描述**：作为用手柄的玩家，我想不接键盘也能换手上那样东西。

**验收标准**：

- [ ] 可测试：手柄上有一组按键能在六格之间移动选中位，且**六格都到得了**。
- [ ] 可核对：每个新动作在两个设备族上**要么有绑定、要么有一条带理由的豁免登记**（这条已有测试盯着）。
- [ ] 可测试：手柄那套切换**不与两个扳机冲突** —— 扳机现在切两组技能位。
- [ ] **作者实机确认**：切到第 6 格要按几下、打斗中间切得不得及。

### US-007：端到端 —— 从选种子到收上来

**描述**：作为玩家，我想走完「选种子 → 播 → 长 → 收」整条链，以便确认这一套真的接通了。

**验收标准**：

- [ ] 自动化测试走完主路径：选中第 N 格 → 那一格是种子 → 对已锄的格播种 → 地里长的是那一种。
- [ ] 覆盖三条失败路径：选中格为空、选中的不是种子、那一格状态不允许播种 —— 三种**各说得出是哪一种**。
- [ ] 测试独立可重复，自己准备与清理数据（规则层测试，不启动引擎）。
- [ ] 代码仓 `python tools/verify.py` 五步全绿。
- [ ] **作者实机确认清单**：打开基地场景 → 按数字键换种子 → 各播一格 → 按推进键若干天 → 两格长出不同的东西
      → 各收一次。另在关卡场景里按一下道具那一格，确认**世界没有暂停**。

## 5. 功能需求

- FR-1：系统必须提供**恰好六格**的随身栏，格数是接口常量、与技能位个数同源。
- FR-2：系统必须始终有**恰好一格**处于选中态，包括那一格是空的时候。
- FR-3：键鼠上按数字键 `1`–`6` 必须分别选中第 1–6 格。
- FR-4：手柄上必须有一组绑定能遍历到全部六格。
- FR-5：随身栏必须**读背包的内容**，不自己存一份物品数据。
- FR-6：系统必须只持有「当前选中第几格」这一个状态，且它进正式存档。
- FR-7：播种时系统必须取**选中那一格**的物品作为要播的作物。
- FR-8：选中那一格不是可播种的东西时，播种必须被拒。
- FR-9：被拒时系统必须说得出是哪一种原因（空格、不是种子、那一格状态不允许）。
- FR-10：随身栏必须**不接管输入**，所以按它不暂停世界。
- FR-11：随身栏必须不装工具 —— 工具在本作不是物品。
- FR-12：随身栏那一块的尺寸算式必须与技能位那一块一致，不引入新的排版量。
- FR-13：执行那一下必须接既有的交互动作，**不新开一个玩法动作**。
- FR-14：键鼠上执行那一下必须**也能用鼠标左键**触发。
- FR-15：键鼠上执行那一下必须由**鼠标左键**触发。
- FR-16：系统必须**不把经营侧的执行绑在交互键上** —— 那个键的用处在战斗侧。
- FR-17：在经营场景里用一样非高稀有度的消耗品必须**当帧生效**，不走读条。
- FR-18：在经营场景里连续按必须能连续用掉多个，中间不插入等待。
- FR-19：在经营场景里用一样高稀有度的消耗品必须先弹一次确认。
- FR-20：那次确认通过之后必须**当帧生效**，不再插入读条。
- FR-21：那次确认被取消时必须不消耗物品。
- FR-22：在关卡场景里用一样消耗品必须走**既有的读条动作**，不新造一条执行路径。
- FR-23：关卡里读条被受击中断或因移动取消时，必须**不消耗物品**。
- FR-24：关卡里用道具必须**不弹确认框** —— 那会在被追击时停住世界。
- FR-25：「走哪一套」必须由当前在场的那台动作机决定，不新增一个场景开关。
- FR-26：系统必须不给物品定义新增任何「要不要确认」之类的开关 —— 触发条件读稀有度。

## 6. 非目标

- **不做背包本体。** 容器、堆、扩容、排序筛选与一键整理全在 `GP-23`，本需求只做它的投影。
- **不做工具系统。** 项目已经决定不做（`关卡系统` 那两条），所以栏里没有锄头水壶，也不画工具图标。
- **不做 12 格。** 留的键位是六个，而六格与技能位同宽换来「HUD 布局零改动」。格数要涨得先回头看那条判据。
- **不做底边一条居中的布局。** 那套候选**已经被否决过**，理由是四角贴边一个居中锚点都不用，
  于是任何逻辑宽度下四块都落在整数像素上。
- **不做拖拽排序。** 排序是背包那一页的事（`UI-13`），随身栏只是投影。
- **不改那六个技能位的任何行为。** 本需求只用它腾出来的键位，不动它的组、冷却与提示。
- **不做道具的效果。** 吃了回多少精力、药解哪条状态都是别人的内容与数值，本需求只管「按下去用得到」。
- **不给物品定义加「要不要确认」那种开关。** `物品系统` 明文警告过「再往定义里堆开关，物品定义就会长成
  全项目的配置堆」，而「贵重」已经有一条轴（稀有度）。**新增零个字段**，触发条件读那条轴。
- **不改关卡里那一侧的读条。** 它买的是「什么时候喝药」这个决策点，改成即时就把它拆掉了。
- **不在关卡里弹那道确认。** 被追着的时候停住世界正是那条判据在防的事。
- **不给读条时长定值。** 关卡侧那个时长本来就归 `GP-6`，本需求一个数都不定。
- **不在本需求里改那条弹窗判据。** 「哪些动作值得一道确认」是跨域取舍，走一份单独的 ADR ——
  本需求只在那份 ADR 被接受之后才拿得到那道确认。

## 7. 界面与表现考虑

**信息层级**：一格里只有三样 —— 图标、数量、选中框。数量为 1 时不显示数字（星露谷同做法），
否则一屏都是「1」。

**它为什么过得了「进不进 HUD」那条判据**：判据是「玩家在动作进行中需不需要它」。连着锄十格再播种时，
「我手上现在是哪种种子」正是动作进行中要知道的事 —— 看不见就得开背包，而开背包会暂停。

**本需求只做经营侧那一行。** 俯视场景里没有技能位，所以那一块的高度与现在完全一致，
「不许压角色可读区」那条判据的输入一个字没变。

**关卡里那两行明确后置。** 正典那条「用道具不暂停」在关卡里要落地就得让随身栏在场（上行技能位带冷却、
下行随身栏），而那会改那一块的高度、要重跑一次上面那条判据 —— 但**关卡里现在一个道具都还没有**，
现在排版是为一个没有内容的场合排。它跟战斗侧那一支走，届时与 `ENG-16` 那条还没答的
「满编一屏读不读得清」**同一屏看**。

**复用哪些既有组件**：格子与图标沿用背包那一页的格位形状（`UI-13`），色值走那套占位色板、等 `DOC-2` 定稿。
**排版与画法归作者**（`ADR-0009`）。

## 8. 技术考虑

**一条硬依赖**：`rules/Ui/InputBindings.cs` 里六个技能位**现在仍然绑在 `Digit1`–`Digit6` 上** ——
[那份键位提案](../design/proposals/键鼠技能位挪到右手.md)（把技能位挪到右手、腾出数字键）**还没落地**，
它是 `UI-14`。**所以本需求的键鼠那一半排在 `UI-14` 之后**，否则两套功能抢同六个键。

**手柄上用十字键左右移动选中位。** 六个技能位靠两个扳机切两组×3，键已经很紧；十字键最省键，
代价是切到最远那一格要按几下 —— 经营侧不赶时间，所以这个代价落在最便宜的地方。
**被放弃的两条**：按住某个键加右摇杆直选（六格映射八方向要留两个空位，空位按下去没反应）、
加一个第三扳机态（「我在哪一态」要常驻提示，又占屏）。

**另加鼠标左键**，所以 `InputSymbol` 枚举要补一个符号。那条「鼠标键刻意不列入」的注释自己写明
这个场合会来（建造界面用鼠标点格子、改键界面给鼠标当选项），并写着「那时是加几行的事」。

**格数与技能位同源**：`rules/Ui/HudLayout.cs` 里技能位的宽度是按 `InputActions.Skills.Count` 算的。
随身栏取同一个数，于是两块同宽这件事**由算式保证，不靠巧合**。

**存档只加一个字段**（当前选中第几格）。它跨睡眠保留，所以按[`存档系统`](../design/存档系统.md)
那条两层判据归正式存档；具体进哪个分片由 `GP-54` 落地时定。

**待验证**：手柄十字键在关卡里有没有别的用途 —— 现有绑定表里没查到冲突，但**这是从表上看的，不是按过的**。
验证办法：作者插手柄按一遍。

## 9. 待确认问题（阻塞项）

**已定的那几条写进了正文，这里不复述**：动作键始终按格状态派发（随身栏只提供材料）、手柄用十字键左右、
本需求只做经营侧那一行、载体一次做对而来源分两步接。被放弃的那几条各自的代价都记在它们落在的那一节。

**本节空了，全部取舍都有答案。** 那道确认的判据与载体在
[ADR-0026](../decisions/ADR-0026-一道确认由误触与收益的落差决定.md)（已接受）：
要不要确认由「一次误触的代价与正常收益的落差」判，落成物品定义上一格显式声明、作者逐件填。
那一份同时填了一处空白 —— 经营侧用道具**不读条**，而[`角色动作状态系统`](../design/角色动作状态系统.md)
原先只定了劳作。

**一条残余风险写在这里，因为它不是待确认问题而是已接受的代价**：那一格填错了机器判不出来
（把一件稀缺物品标成不用确认，载入照旧通过）。缓解靠作者自己维护那一列，加真人试玩兜底 ——
执行体是一条反馈回路，不是守卫。

## 10. 成功判据

- 一块地里种得下**两种以上**作物，全程不改配置、不重启。
- `src/World/Farm/FarmField.cs` 里那个写死作物标识的导出属性**不再存在**。
- 随身栏**新增零个 HUD 块**，且 `HudLayout.BlocksOverActorBand` 在 640×360 与拉宽窗口下都返回空。
- 随身栏**新增零个物品存储** —— 存档里为它加的字段恰好一个（当前选中第几格）。
- 三条被拒路径（空格、不是种子、那一格不允许）在实机上**各说得出是哪一种**。
- 基地里连按能连着用掉好几样普通东西，中间不等；高稀有度那种先问一句，答完当帧生效。
- 关卡里同一样东西走读条，受击中断且不消耗，**而且不弹任何确认**。
- 「走哪一套」读的是当前在场那台动作机，**不是一个新增的场景开关**。
- 键鼠上执行是**鼠标左键**，经营侧一处都没有绑那个战斗侧的交互键。
- 物品定义为本需求新增的字段**恰好零个**。
- 代码仓 `python tools/verify.py` 五步全绿；设计仓 `python tools/check_docs.py` 0 FAIL。
- 作者实机认可六个键够不够得到、选中态看不看得清、换种子顺不顺手。
