# 角色状态分三层：运动、动作与状态效果各管一件，控制类效果不进动作机

> **正典层级**：第 5 级（系统细化）。与[玩法正典](../canon/gameplay/玩法定位.md)冲突时以正典为准；**全部帧数与数值归 `GP-2`／`GP-6`，本页一个都不定。**
>
> 返回 [总索引](../README.md)｜[专项设计索引](./README.md)｜相关：[玩法定位](../canon/gameplay/玩法定位.md) · [战斗与关卡](../canon/gameplay/战斗与关卡.md) · [数值模型](./数值模型.md)｜台账：[`GP-18`](../spec/issues/README.md)

## 摘要

我们把角色状态拆成**三层各管一件事**，外加一个特殊的生命周期终态：**运动层**是互斥的移动相位（站/走/冲/跳），**动作叠加层**是互斥的主动动作（攻击/防御/施法/闪避/采集），**状态效果层**是可并存的修饰（硬直/无敌/失衡/异常/光环/词条/伤病）。

最重要的那个承诺：**控制类效果——冻结、眩晕、硬直、失衡——一律进状态效果层，不进动作机。** 动作机只是"看到控制类效果在场，就切到对应被控姿态、封住输入"，它不拥有这段时长。这不是新发明：代码里 `MotorState`／`ComboStateMachine`／`StatusEffects` 本来就是这三层，正典也已裁定"全部临时与持续效果走同一套状态系统"。本页把这条隐含结构写成显式契约，并给出战斗动作层的完整流转表，好让**以后每个战斗切片知道该把新状态加进哪一层**，而不是各加一台平铺状态机。

## 背景与动机

作者列角色状态时，通用状态有十四类：静止、行走、奔跑、普通攻击（轻/重多段）、防御（普通/精准）、跳跃、施放技能、受击（轻/重/失衡）、死亡（战斗倒下/真正死亡）、闪避（普通/精准）、无敌、采集、制作。

**把这十四类塞进一台平铺状态机，是这次最容易走偏的地方。** 它会立刻撞上正典点名警告过的组合问题：一个角色可以同时"被冻结 + 中毒 + 带一层光环 + 处在无敌帧里"，这些是能并存的；而"正在攻击"与"正在闪避"是互斥的。把可并存的和互斥的混进同一层，"屏障 + 光环 + 硬直 + 中毒同时生效算谁的"就没人说得清，叠加、覆盖、过期规则会各写一套。

更具体地看**受击**这一类：它既要播受击姿态（表现），又要锁住操作若干帧（时序），还要能被无敌豁免掉（一次闪避的无敌窗里不该进受击）。如果把受击做成一个动作状态，它就拿不到"可否解除""可并存""有没有无敌豁免"这些只有状态效果才有的属性；如果把它做成一个裸计时器，它又要自己重做一遍动画切换。三层分法让这三件事各归其位：**时序与豁免归状态效果层，姿态与输入归动作机，位移归运动层。**

所以真正要回答的问题不是"要不要状态机"，而是"这十四类各属哪一层"。本页给出这个归属，并逐条说明为什么。

## 当前事实与证据

**三层在代码里已经存在**，是 `GP-10`／`GP-11`／`GP-15` 已提交的事实（代码仓 `rules/Combat/`）：

- `MotorState`：`MotorPhase { Grounded, Airborne, Dodge, Dash }`。待机/行走由横速区分，上升/下落由竖速区分；闪避排他不可打断、内含无敌窗；出招时三轴一同定身。
- `ComboStateMachine`：`ComboKind { None, Light, Heavy } × AttackPhase { Startup, Active, Recovery }`；`_startedAirborne` 记录空中起手，落地即 `Reset()`（空中连击落地打断）。
- `StatusEffects`：`StatusKind { Hitstun, Invulnerable }`，两槽定长数组、**均不可解除、无量级**；`MotorState.IsInvulnerable` 的唯一依据是这个载体。

**受击/防御/失衡/死亡的美术已入仓但未接线**（[`ART-6`](../spec/issues/README.md)）：13 个动作 91 帧入仓，`PlayerActor` 只载 `idle`／`walk`／`run`／`jump`／`dodge`／`light`／`heavy`；`light_hit`／`heavy_hit`／`general_defense`／`precise_defense`／`imbalance`／`death` **入仓备用、刻意不载**，因为对应玩法还不存在。

**没有空中攻击帧**（待补）：现有 13 动作里不含空中攻击，空中攻击当前只能复用地面 `light`／`heavy` 帧。作者要求空中攻击换独立动画，所以这一帧要新增（补进 `ART-6` 或后续正式美术）。

**击倒→起身帧作者已补**：收件箱新增 `knocked_away` 5 帧（受身 → 倒 → 水平翻滚 → 趴地 → 爬起），另把轻击拆成分段 `fist_light_attack`／`_2`／`_3`（对应连段三段）；这些在 `temp/art-inbox`、**尚未接仓**（现行进仓集仍是 `ART-6` 的 13 动作），接仓走 `import_role_sheets.py`。

**以下全部标为待验证、归 `GP-2`／`GP-6`，本页不定**：任何帧数、时长、判定窗口、CC 持续时间、失衡时长、**失衡值阈值与衰减**、精准窗口、回蓝量、状态叠加规则。涉及这些的说法都是结构而非数值。

## 设计

### 三层各管一件事，外加一个终态

| 层 | 互斥性 | 管什么 | 代码落点 |
| --- | --- | --- | --- |
| 运动层 | 同一时刻恰好一个 | 角色在怎么移动：站/走/冲/跳、闪避位移 | `MotorState` |
| 动作叠加层 | 同一时刻至多一个 | 角色在主动做什么：攻击/防御/施法/闪避/采集 | `ComboStateMachine`（现仅攻击），待扩 |
| 状态效果层 | 可同时挂多个 | 角色身上有什么修饰：硬直/无敌/失衡/异常/光环/词条/伤病 | `StatusEffects`，待扩 |
| 生命周期 | 终态 | 战斗倒下（可救起）/ 真正死亡（可采集尸体） | 待建 |

作者列的十四类按此归位：静止/行走/奔跑/跳跃→运动层；攻击/防御/施法/闪避/采集→动作叠加层；受击/失衡/无敌/冻结/眩晕→状态效果层；死亡→生命周期。**制作不在战斗（作者裁定去掉），只在经营场景。**

### 运动层：三轴移动，已实现

- **静止/行走**：`Grounded` 相位按横速区分，不是两个独立状态。
- **奔跑就是冲刺**（作者确认）：`Dash`，沿横向轴的高速位移、无无敌帧、耗 SP，由移动修饰键触发；不并入一档独立的"免费奔跑"。
- **跳跃**：`Airborne`，上升/下落按竖速区分；离地锁纵深（`IsDepthAirLocked`），落地解锁。**保留**，理由见正典与下面「理由与取舍」。

### 动作叠加层：互斥的主动动作，给运动层一个"定身/忙"标志

- **攻击**：轻/重连段（`ComboStateMachine`）。**空中攻击走独立动画**（作者确认）：机制仍是 `_startedAirborne` 的空中连击、落地打断，只是取帧改用空中攻击帧而非地面帧——这是取帧分支加一张美术，状态机不变。
- **防御**：普通（持续耗 SP）/ 精准（成功免 SP + 回少量 HP 与 MP）。
- **施放技能**：分**瞬发**（像攻击一样短前后摇、生根、不可取消，太短不至被有意义打断）与**读条**（生根、可被打断、移动即取消）。**读条被打断时：我方退还一半 MP、敌人不退还**；道具（用道具）中断按正典不消耗、敌我都不丢。
- **闪避**：普通 / 精准（作者确认加入）。精准是"按下时机命中来袭判定"的判定条件，回报**低于**精准防御：免 SP + 回极少量 MP、不回 HP。
- **采集 / 用道具**：读条子类，`受击中断、不消耗`（正典）。战斗内不做制作。

这一层同一时刻至多一个，并给运动层一个"忙/定身"标志——出招时地面三轴定身（已实现），防御/施法/读条同理锁住或限制移动。

### 状态效果层：可并存的修饰，分"控制类"与"非控制类"

每条效果带正典要求的**"可否被解除"**属性。按"锁不锁操作"分两类，这个区分决定它动不动动作机：

- **控制类（锁操作）**：硬直、失衡、冻结、眩晕、（未来）睡眠等。它们会驱动动作机进入对应被控姿态、封住输入。冻结/眩晕这类 CC 就落在这里——它们与硬直/失衡同形（临时、有时长、锁操作），可解除性各异（有的能被道具/技能驱散，走读条、可打断）。
- **非控制类（只改参数）**：无敌、减速、持续伤害（中毒/灼烧）、攻击力增益、常驻光环、宝物负面词条、伤病、断粮熬夜降的体力上限。它们改数值或判定，不接管动作机。**无敌就在这里，是纯修饰**（闪避窗、失衡结束逃生窗、复活保护都靠它并存），不是一个动作节点。

载体要从 A1 的最小形态长出来（现在只有两槽、不可解除、无量级）：可扩种类、**可否解除**、量级、叠加/刷新规则、来源。多个控制类同时在场时选哪个姿态需要优先级（更重/更晚者优先），具体归 `GP-2`。

### 受击链：受击 → 失衡 → 击倒 → 起身

受击、失衡、击倒都是控制类状态效果驱动的被控姿态，串成一条链（作者补充，参考图后续入素材）：

1. **受击**（轻/重）：被打中的短暂硬直，播 `light_hit`／`heavy_hit`。受击本身累积一个**失衡值**（削韧）。
2. **失衡值累积达阈值 → 失衡**。另有一条正典路径：**SP 耗尽也进失衡**。两条进同一个失衡状态：完全锁死（不能动、不能防御）、易吃重击。
3. **失衡中再被任何攻击（轻/重/技能）击中或被击退 → 击倒**：水平摔到地上（就是"打飞出去"，**是水平击退到地面、不是浮空**——浮空仍预留不做）。
4. **击倒后自动从地上起身 → 强制回复一段 SP + 短暂无敌**，这就是正典的逃生窗口。倒地期间仍可被追打（正典"倒地追打"）。

**失衡有两条退出**（作者确认）：时间窗内没被命中 → **超时自然站起、回静止，什么都不给**（不回 SP、不给无敌）——失衡是站立的萎缩姿态（手臂下垂，对应 `imbalance` 帧）、**不是倒地**，没被压制就没有要逃的东西；失衡中被命中或被击退 → 走上面第 3–4 步的击倒链。**失衡值会随时间衰减**，不被打就回落，速率归 `GP-2`。**所以逃生窗（回 SP + 短暂无敌）只挂在"击倒 → 起身"上，不挂在"失衡结束"上。** 这把正典"失衡结束时给逃生窗"那句的触发点收窄为"被击倒后起身"，理由与正典一致——逃生窗是给被连续压制的场景兜底，而超时恢复本就没被压制。本页上升进正典时那句要一并改。

**注意区分**：这里的"击倒/起身"是受击链里的短暂倒地、自动起身给逃生窗；它**不是**生命周期里的"战斗倒下"（HP 清零、要队友救起、每关一次）。参考图画的是前者。

### 生命周期：倒下可救、死亡是终态

- **战斗倒下**（HP 清零触发，区别于受击链的击倒/起身）：友方（学员）倒下不死亡，每关可被救起一次、低血量复活；主角倒下即任务失败。倒地角色仍可被追打（正典"倒地追打"）。
- **真正死亡**：敌人的终态，转为可采集的尸体（接采集）。玩家与学员常规流程不到此。

### 层间接口：状态效果层是"能否行动"的唯一真相

这是三层能协作的关键，也是正典"受击中断读条""倒地追打"的统一落点：

1. 动作机每帧先问状态效果层有没有控制类在场。
2. **有控制类 → 动作机切到对应被控姿态、丢弃本帧主动输入；它不拥有这段时长，何时结束由该状态效果的剩余帧决定。** 这正是硬直现在的做法（`IsInvulnerable` 只查载体）。
3. 非控制类不切姿态：无敌只让命中忽略，减速只改速度目标值。
4. 因此"受击打断攻击/读条/施法""倒地仍可被打"不是各写一遍的特例，而是同一条接口的自然结果——一次命中施加控制类效果，动作机下一帧就让位。

### 战斗动作层流转表

先立五条全局规则，避免每行重复：

- **G1 抢占**：控制类状态（硬直/失衡/击倒/冻结/眩晕）与倒下/死亡可抢占几乎任何动作层状态；唯一例外是闪避无敌窗内不进受击。
- **G2 无取消**（`GP-4` 未做）：攻击段内不能主动取消到闪避/防御/跳/冲，只能连段续接或走完后摇。
- **G3 闪避排他**：闪避一旦起手走完全程、忽略输入，无敌只在窗口内（已实现）。
- **G4 落地打断**：空中动作（空中连击、空中受击）落地即打断。
- **G5 读条即走即断**：采集/用道具一旦移动就取消，受击中断且不消耗。

| 状态 | 可流转到 | 明确不可 |
| --- | --- | --- |
| 静止/行走 | 行走/静止、奔跑、跳跃、攻击、防御、施法、闪避、采集、用道具；走下台沿→下落 | 直接进除"下落"外的空中动作 |
| 奔跑(冲刺) | 静止/行走(松键)、跳跃、攻击(地面攻击、定身) | 冲刺中直接起闪避 |
| 跳跃上升 | 下落(到顶)、空中攻击、空中施法(仅瞬发且带空放标记) | 闪避/冲刺/防御/采集(均限地面) |
| 下落 | 静止/行走(落地)、空中攻击、空中施法(同上) | 同上 |
| 攻击·地面 | 同类连段下一段(衔接窗内)、后摇结束回静止/行走 | 取消到闪避/防御/跳/冲(G2) |
| 攻击·空中 | 落地即打断回静止/行走 | 同上 |
| 防御 | 静止/行走(松防御)；SP 耗尽或破防→失衡；精准防御成功→保持+回 HP/MP | 直接转攻击(需先松)；防御→闪避取消不做(作者定) |
| 施法·瞬发 | 前后摇走完→静止/行走 | 过程中取消或移动(生根) |
| 施法·读条 | 完成→静止/行走；受击→受击(打断，退 MP 待确认) | 过程中移动/取消/接他招(生根、作者定) |
| 闪避(普通/精准) | 走完→静止/行走(或落地)；无敌窗内不进受击 | 途中被任何输入打断(G3) |
| 采集/用道具 | 完成或移动→取消回静止/行走；受击→受击(不消耗) | 读条中起攻击/闪避(需先取消，G5) |
| 受击(轻/重) | 硬直结束→静止/行走；失衡值累积达阈值→失衡 | 硬直中主动出任何招 |
| 失衡 | 时间窗内未被命中→超时站起回静止(什么都不给)；被命中/被击退→击倒 | 失衡中移动、防御(完全锁死) |
| 击倒(倒地) | 自动起身→静止 + 强制回一段 SP + 短暂无敌(逃生窗)；倒地可被追打 | 倒地中主动出招 |
| 冻结/眩晕(被控) | 状态到期或被解除(可解除者)→静止 | 期间任何主动输入 |
| 战斗倒下 | 被救起→静止(低血, 每关一次)；敌方超时→真正死亡；倒地可被追打 | 主动起身出招(除被救起) |
| 真正死亡 | 终态；敌人转可采集尸体 | 无出口 |

### 经营场景：另一套动作机，共用状态效果层与角色数据

经营场景（基地/城区俯视）与战斗场景（侧视）**动作机分两套，状态效果层与角色数据共用一套**：

- **分两套动作机**：运动模型根本不同——俯视是平面两轴（x/y、无重力无跳跃无纵深带），侧视是带纵深与跳跃的三轴；可用动作也不同——经营无战斗（正典不做基地防卫战），战斗无劳作。硬塞一台机等于一台全是"if 场景"分支的机。
- **共用状态效果层**：角色是同一个实体，伤病、负面词条、增益跨场景延续（正典"伤病"跨日累积）。状态效果层必须一份，否则两处各算一套叠加。
- **经营侧动作**（据[核心循环](../canon/gameplay/玩法定位.md)）：定位/行走 + 劳作读条（种植/浇水/收获、加工、训练、读书、照护）。劳作与战斗采集/用道具是**同一个形状——带读条、可打断的持续动作**，这个"读条动作"模式两处复用，但各自的动作机分开。本页只定这条原则，经营动作细节归各自实现与[时间与经营](../canon/gameplay/时间与经营.md)。

## 理由与取舍

- **没选"单台平铺状态机"**：把可并存的（buff/CC）与互斥的（攻击/闪避）混进一层会组合爆炸，正典明确要求效果统一走一套。三层把"一次一个"和"可以好几个"物理隔开。
- **没选"CC 作为一等动作状态"**：动作状态没有"可否解除""可并存""无敌豁免"这些属性，CC 若做成动作状态就得在动作机里重造半个状态系统；而正典已把硬直/失衡点名放进状态系统，冻结/眩晕与它们同形，归同一层才一致。
- **没选删除跳跃**（作者一度考虑）：正典 2026-09-09 已裁定保留，跳跃是横扫地面攻击的对策，删掉它一种威胁就只剩纵深一种解法；且删跳跃等于拆掉整条竖轴——空中连击、离地锁纵深、影子随高度，全是已实现并验过的 `GP-12`/`GP-13`/`GP-15`，还反转一条有日期的裁定。它当前"看着没用"是因为敌人横扫攻击还没设计，价值是前瞻的，该在 A2 有真敌人时再评估，不在木桩阶段拆。
- **没选精准闪避与精准防御同回报**：闪避天生多了位移与穿多段的无敌，回报再等同会盖过精准防御，让防御那套精心设计冗余。改为精准防御回报更高（免 SP + HP + MP）、精准闪避更低（免 SP + 极少 MP）；两者都压在"进攻回蓝"之下是正典给 `GP-2` 的硬约束。
- **没选战斗内制作**：作者裁定不做，制作只在经营，避免给战斗动作层加一个没有需求的读条子类。
- **没选现在做空中受击/浮空**：作者裁定预留。现在没有把受击方打飞上天的敌人攻击，A1 只有地面受击；将来要做时受击才长出空中变体，本页先占好"这是状态效果层驱动的姿态"这个位置。

## 兼容性

**大体是增量**：三层结构与代码现状一致，已实现的 `MotorState`／`ComboStateMachine` 不动。

**有一处是破坏性的，得正面承认**：`StatusEffects` 要从"两槽定长数组、`StatusKind` 只有 Hitstun/Invulnerable、一律不可解除、无量级"长成"可扩种类 + 可否解除 + 量级 + 叠加/刷新 + 来源 + 控制类分类"。代价是 `Index(kind)` 那套固定索引与 `_remaining[2]` 存储要换成可扩结构，且 A1 的 Hitstun/Invulnerable 行为必须保持不变（回归测试盯住）。渐进路径：先给现有载体加"可否解除"字段与"控制类"标记（不改行为），再按切片逐个加种类，不一次重写。

**美术**：受击/防御/失衡/死亡帧已在仓（`ART-6`），接线即用；空中攻击帧需新增；施法/采集/CC 帧属后续。

## 实现与过渡

按未来切片推进，**不是现在全做**；每步都"把新状态加进正确的层"，并回来更新本页与流转表：

1. **A1（已完成，保持不动）**：Hitstun + Invulnerable 最小载体 + 运动 + 连段。
2. **防御与失衡切片**（对应正典防御与失衡）：动作层加防御（普通/精准），状态层加失衡（控制类）+ 失衡值累积 + 击倒/起身，接 SP 耗尽或受击累积→失衡→（再被击中）击倒→起身逃生窗，另依赖倒地爬起美术（`ART-6` 待补）；载体长出"控制类"概念与"可否解除"字段。
3. **异常状态切片**（正典第一版 2–3 种可解除）：状态层加可解除类（中毒/灼烧）与解除手段（读条、可打断）；冻结/眩晕作为控制类异常状态一并接入。
4. **技能与读条切片**：动作层加瞬发/读条技能与采集/用道具读条子类；空中施法限瞬发子集。
5. **生命周期切片**：战斗倒下（救起）与真正死亡（尸体可采集）。
6. **打磨**：精准闪避判定窗 + 回报；补空中攻击帧并按 `_startedAirborne` 取帧。

守卫/自证：状态效果层的"可否解除""控制类锁操作""无敌不切姿态"都应有纯规则层单测（参照现有 `StatusEffects` 测试）；流转表每条"明确不可"配一条反证测试。

## 边界与非目标

- **不定任何数值**：帧数、时长、判定窗、CC/失衡时长、失衡值阈值与衰减、回蓝量、叠加规则全归 `GP-2`／`GP-6`。
- **不实现**：本页只定结构与流转，代码按切片走各自 issue。
- **不做**：战斗内制作、空中受击/浮空（预留）、取消与派生（`GP-4`）。
- **经营侧只定原则**：另一套动作机 + 共用状态效果层，不铺经营动作细节。
- **角色特定状态走同一框架**：各角色/敌人的专属动作进动作叠加层（多为技能），专属修饰进状态效果层；本页只定通用状态与三层框架，专属状态随各角色设计时按此归位，不在此铺开。

## 验收

- **可自动验证项**：状态效果层长出"可否解除"与"控制类"后，规则层单测覆盖——控制类在场→动作机报被控/封输入；无敌→不切姿态；可解除类 `TryRemove` 成功、不可解除拒绝。流转表每条"明确不可"各有一条反证测试（如攻击段内按闪避无效、离地按闪避无效）。
- **必须实机确认项**：被控姿态与受击/失衡动画的切换观感、精准闪避与精准防御的手感窗口——归 `GP-6` 实机逐帧，本页不判。
- **完成边界**：本设计"落地"= 三层与流转表被后续每个战斗切片当作状态归属依据；当第一版全部战斗状态（防御/失衡/异常/技能/采集/死亡）都按此接入且回归绿、稳定部分上升进正典后，本页可从 `design/` 收缩。

## 附录：两个常问的归属

- **闪避为什么在运动层不在动作层？** 它的本体是一段带无敌窗的位移，代码就落在 `MotorState.Dodge`；它与"攻击/防御"这类动作叠加互斥，但归位在持位移的运动层更贴实现。它在流转表里按动作看待，不矛盾——分层是实现归属，流转是行为约束。
- **无敌为什么不是一个状态节点？** 因为它从不单独存在，总是伴随闪避窗、失衡逃生窗或复活保护。做成"无敌 + 当前动作"两件并存的事（状态效果层 + 动作机），比做成一个要从里面再决定"我还能不能动"的动作节点干净，代码也已经是前者。
