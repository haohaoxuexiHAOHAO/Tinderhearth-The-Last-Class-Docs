# 系统文档与提案

本目录装两个体裁，**按寿命分开放**，理由与被否决的方案见 [ADR-0010](../decisions/ADR-0010-文档体裁与系统文档归位.md)。

| 体裁 | `type` | 位置 | 回答什么 | 寿命 | 模板 |
| --- | --- | --- | --- | --- | --- |
| **系统文档** | `system` | 本目录根下 | 这个系统的结构、接口与边界（契约） | **活文档**：随实现更新，系统在它就在 | [SYSTEM](../templates/SYSTEM.md) |
| **跨系统模型** | `model` | 本目录根下 | 一套所有系统都要满足的量、公式与判据 | **活文档**：随参数更新 | 同上 |
| **提案** | `design` | `design/proposals/` 下 | 这条路为什么走得通，别的路为什么不走 | **一次性**：结论迁出后归档 | [DESIGN](../templates/DESIGN.md) |

三者都是第 5 级（系统细化），权威层级相同 —— 分家分的是寿命，不是权威。**前两个体裁的位置、骨架与寿命完全一样**，差别只在「它是什么」：一个系统有实体、状态与流转，一个模型只有量、公式与判据。

## 命名规则

- **名字必须说出它是什么，后缀写死、可机检**：`type: system` 的文件名以**「系统」**结尾（`角色动作状态系统`、`状态效果系统`、`教育系统`），`type: model` 的以**「模型」**结尾（[`数值模型`](./数值模型.md)）。**不带体裁名词**（设计、方案、规格、文档 —— 位置与 `type` 已经表明体裁）。
- **数值模型为什么不叫「数值模型系统」**：它没有实体、没有状态、没有流转，硬加「系统」二字是让名字说谎。给它一个自己的 `type` 而不是在命名规则里开一条例外，是因为**例外要靠白名单才判得了，而白名单是每加一份就补一格的债**。
- 系统文档一个系统一份，与[玩法定位的系统清单](../canon/gameplay/玩法定位.md)对得上。
- **提案**：`<slug>.md`，一句话能说清它在论证什么。
- 三者的一级标题都写成**一句结论**，不写名词短语。
- **将来出现第三、第四份模型时再考虑单独开目录。** 现在开等于为一份文件建一个目录，而搬它要改约 30 处路径引用（其中 5 处在只读归档件里）。

| [任务系统](./任务系统.md) | 一条任务是一组目标条目加一次结算。判据写在最前面：**有目标与进度、有完成与失败结算的是任务；只有「触发 → 后果」的是事件**。委托、主线任务与个人请求是它的三类，只在几格上不同（占不占额度、有没有截止、失不失败、能不能重试、谁触发）；一条任务可以有多个目标条目，采集类计数**不区分物品来源**；达成不结束关卡，返回入口撤离才结束，达成与否决定结算成成功还是撤退；进度只有一个来源，接已有的那张 HUD 目标视图；委托板的超期作废与补满各占每日结算一步，**先作废后补满**。**不定数值、不做关卡、不做定价、不实现任何效果**；立项在 [`GP-41`](../spec/issues/README.md) |

| [经济系统](./经济系统.md) | 钱从哪来往哪去，以及一件货这一刻值多少。**成交价只有三层**（基础价 × 需求 × 供给），每一层都要报得出当前值加一条原因引用；**交易技能的点差落在这条乘法链之外**（三层回答「这件货值多少」，点差回答「你和对方谈成了什么」），买卖双向对称且有上限 —— 上限受「不许原地买进卖出就赚钱」这条约束管着。钱包按角色各一个、内部只一个量纲而分级只在显示层；**支出只有一条管道，现金不足一律只拒不赊、不产生欠款**；债务是本金加**单独累计的利息**（不计复利），还款先冲利息再冲本金、只能从主角钱包出。[`任务系统`](./任务系统.md)那个报酬引用在这里解析成一笔钱；商店的**上架读所在区的境况档位、刷新间隔按店的种类**，刷新等进店时才补算、**不占每日结算任何一步**。**不定内容与系数、不碰失衡、不做欠账与抵押玩法**；立项在 [`GP-43`](../spec/issues/README.md) |

| [感知与视野系统](./感知与视野系统.md) | 一份可见性数据，两个阵营各取并集：AI 的目标选择、玩家看到的画面、资源点显形与残影全从这一份读，**一次计算、没有第二份**（那是正典点名的防重构点，靠「清空可见集后 AI 找不到目标」这条反证钉住）。视野是朝向扇形加一个**不看朝向的近身半径**（没有它，贴背后动手而对方毫无反应会被读成坏了）；**遮挡按片段声明的区域判、不走引擎射线**（`ENG-19` 实测过取错层且不报错）；残影只是记忆项的表现，**记忆项留在最后已知位置、不跟着目标走**。**不做 AI 决策、不做压暗画法、不定角度与距离、不在俯视场景生效**；立项在 [`GP-51`](../spec/issues/README.md) |
| [战斗AI系统](./战斗AI系统.md) | 一个不由玩家操作的角色这一帧决定做什么：**敌人与队友走同一条决策循环**，差别只在挂上去的门（敌人挂警戒状态机与只有一跳的警戒传播，队友挂两个行为档号与一个指令档）。**两条轴不合成一个档号** —— 操作档读实战值、配合档读关系档位，各有一条「这一档在读谁」的填表判据；地板与分档按正典那条判据重划过（收指令、扶人、不挤在一处都归地板）。预警与对策是**攻击定义上的显式声明**，并有一条载入校验要求全部敌人合起来覆盖到每一种对策 —— 正典给跳跃挂的那笔账由它兑现。分级面板是**同一套面板的两个子集**，精英装宝物走既有那条偏好轴判据，**不给敌人开专用通道**。**不做可见性计算、不做姿态与流转、不做寻路、不做学生日程 AI**；立项在 [`GP-36`](../spec/issues/README.md) |
| [剧情演出系统](./剧情演出系统.md) | 一段演出是一串按顺序推进的指令，加一台推进它的状态机（待命／推进／等输入／收尾）。**正式对话是其中一类指令**（[ADR-0014](../decisions/ADR-0014-对话是演出脚本的一类指令.md)），所以只含对话指令的脚本就是一次纯对话 —— 与 NPC 交谈不需要自己的机制；**气泡不共用这份格式**，判据落在「接不接管输入」上。指令类型是一张**开口的表**，加一类指令时填表、不在状态机上加分支。演出接管输入所以世界暂停，**由此推出决策循环不跑、AI 那一侧一个字都不用改**；摆布角色走动作机那条既有的路。跳过与快进是两件事，而**跳过必须把脚本声明的状态变更一次性全部应用**（承重项，有反证）。**不写台词、不做气泡与日记、不定镜头手感值**；立项在 [`NR-7`](../spec/issues/README.md) |
| [事件系统](./事件系统.md) | 一条事件是「钩子 ＋ 前置 ＋ 权重 ＋ 冷却 ＋ 一组后果调用」，而**后果一律是对已有入口的调用 —— 那张表里不许有「本页自己算」这一格**。钩子只在被触到那一刻被询问（不轮询），**每日结算那个钩子落在固定步序之外**（它要读结算的结果，插在中间会让「委托板补满至固定条数」静默失效）；**这条与[`活跃失衡系统`](./活跃失衡系统.md)那条不加步不同源**，两处理由不许互抄。一次性与可重复的判据是「后果可不可逆」，而**「已触发过」与冷却只有一份记账、进正式存档**。**关卡事件在拼装那一刻由种子定下来**，否则「同一个种子拼出同一张图」被静默绕掉。它同时收下**关系小事件**（按[`任务系统`](./任务系统.md)那条判据它只有触发 → 后果）与**持续引导**（与它共用那份记账；引导的可回查清单是那份记账的**读口**而不是第二份存储）。**不实现任何效果、不做气泡与日记本体、不定权重与冷却的值**；立项在 [`GP-52`](../spec/issues/README.md) |
| [气泡对话系统](./气泡对话系统.md) | 一句气泡是在额度允许时按上下文键从语料里挑出来的：**额度闸门排在挑句之前，而冷却池只记真说出口的那一条**（反过来做不报错，表现是一句从没出现过的话被标记成「说过了」）。匹配是严格的但**没声明的键视为任意**，所以通用句兜得住、专用句够细；候选集按「先优先级档、再声明的键数」两级排序，**专用句盖过通用句不需要额外字段**。丢弃就是这一次不说话 —— **没有队列，也不撤已经在显示的**。冷却池按「角色 × 条目」记、跨场景保留、**只进临时续玩点，正式存档一个字段都不加**（正式存档只在睡眠发生，那一刻重置正好对上「新的一天」）。**不做正式对话与演出脚本（[ADR-0014](../decisions/ADR-0014-对话是演出脚本的一类指令.md)）、不做引导提示、不承载必要信息、不定数值**；立项在 [`NR-8`](../spec/issues/README.md) |
| [日记系统](./日记系统.md) | 每个角色一本只追加的日记，条目按类别分（纪事记发生了什么、心声记他怎么看）。最要紧的是**记与读是两件事** —— 写入不看解锁，主角不在场的别人之间的事照样记进当事人那本；解锁只管翻不翻得开，而那**按本判不按类别判**（主角自己那本无门、别人那本读关系档位）。纪事类存「模板键 ＋ 当时的参数快照」而**不存渲染好的句子**，所以「重建出来的和当时看到的一样」有依据而不是承诺。条目**按「发生了值得一记的事」生成，没有每天一条的摘要**，于是条数是派生量。需求是**条目上的一个标记**，小事件的前置条件读那个标识而不是「读过某人的日记」。**不做小事件的触发与后果、不做气泡、不让读日记涨关系、不设条目保留上限、不定数值**；立项在 [`NR-9`](../spec/issues/README.md) |
| [存档系统](./存档系统.md) | 一份存档是**若干分片的集合**，而每个分片由持有它的系统自己声明（叫什么、进正式存档还是进临时续玩点、缺字段时补什么）—— 所以**本页不持有任何字段清单**，「一共存了什么」由一个读口回答而不是由散文回答。进哪一侧只有一条判据：**跨过一次睡眠还成立的进正式存档**。分片之间**不许有载入顺序依赖**（反证是任意顺序读出同一结果），**派生量不单独存**（反证是改基底之后派生量跟着变），写入是一次「写临时文件 → 原子替换」的事务且**不另留玩家读得到的备份**。缺 mod 的内容**隔离而不是删除**（`ENG-7`：标成不可用、不进任何计数，装回 mod 一件不少）。格式与版本口径在 [ADR-0015](../decisions/ADR-0015-存档的版本与缺字段口径.md)。**不持有任何系统自己的字段、不做云同步、不做成就进度、不定数值**；立项在 [`GP-54`](../spec/issues/README.md) |
| [统计事件总线系统](./统计事件总线系统.md) | 一条统计事件是**一次埋点**：标识、发出者、一组带名字的量，缺必填项当场报错。**总线只转发、不自己产出**（没有「本页自己发一条」这一格，理由与[`事件系统`](./事件系统.md)那条「不许自己算」不同源）；**订阅者不存在就丢弃、不排队**（排队等于让它变成一份存储）；**给存档加零个字段**，理由是它没有状态 —— 这条与[`气泡对话系统`](./气泡对话系统.md)那个零字段**结论一样、理由不同源**。成就进度是跨存档的东西、不进本作存档；「首次见到」这类**记账不是本页的**。**不做成就与统计、不呈现、不出本机、不占每日结算任何一步、给参数表加零个量**；立项在 [`GP-55`](../spec/issues/README.md) |
| [每日结算系统](./每日结算系统.md) | 那串步序**不在本页**（家在[时间与经营 · 结算顺序（固定，不得改动）](../canon/gameplay/时间与经营.md)），本页只驱动它：**一个入口、两个来源**（主动睡与到点强制结束），**整串加自动存档是一次事务**且提交点是存档写入成功 —— 所以跑一半就一步都不生效，写入失败等于整天没推进，被中断则回到睡前。**步数一个不增一个不减**（结构约束），引用某一步**按步名不按序号**。结算期间**没有输入入口**，而那**不是「弹界面暂停世界」那条判据的适用对象**（世界本来就不在跑）。本页不为自己加一步，**而「不加步」这条结论别处也有好几份写过、依据各不相同 —— 那份名单刻意不在任何一页展开**。摘要是一个读口、不是第二份账。**不复述步序、不碰每一步的业务规则、给参数表加零个量**；立项在 [`GP-56`](../spec/issues/README.md) |

## 与正典、需求文档的分工

| 文档 | 回答什么 | 生命周期 |
| --- | --- | --- |
| [正典](../canon/world/世界观.md) | 产品**意图**：这个游戏应该是什么 | 稳定，长期有效 |
| 本目录根下 | 某个系统**现在是什么**：结构、接口、边界；或一套跨系统的量与判据 | 活文档，随实现更新 |
| `proposals/` | 某个方案**为什么成立**，以及为什么不选别的 | 活跃期维护，结论迁出后归档 |
| [`spec/`](../spec/README.md) | 这**一次**改动做什么 | 一次需求，归档即结束 |

判断该写哪个：

- 只影响一次改动 → 需求文档，不要建系统文档。
- 一个系统的完整规则、会被多次改动反复引用 → **系统文档**。
- 一套所有系统都要满足的量、公式或判据（没有实体与状态）→ **跨系统模型**。
- 一条路走不走得通、要摆出被放弃的方案 → **提案**。
- 已经确定、不会再变的产品事实 → 直接进正典。
- 跨多个系统、难以撤销的取舍 → [ADR](../decisions/README.md)。

**建之前先找现有权威源。** 默认修改既有文档，不新建平行方案。真要新建就说明它的类型、上游来源、生命周期与替代关系，并接入 [README 文档地图](../README.md) —— 否则检查器会报「从 README 无法到达」。

## 上升规则按体裁分

- **提案**：结论上升进正典或系统文档之后归档。不做这一步就会出现两份说法不同的权威源，而且没有任何机制能发现 —— 检查器查断链，查不出两份文档对同一件事的描述已经分叉。
- **系统文档不整份上升。** 字段与接口按定义不进正典，所以它不会「写完」；只有个别稳定下来的结论（例如一张分类判据表）才上升，本页对应条目里写明是哪几条。
- **[数值模型](./数值模型.md)永久留在本目录**：[玩法定位](../canon/gameplay/玩法定位.md)写明「数值一律不在正典」。写在这里是为了以后没人来做一次错误的上升。
