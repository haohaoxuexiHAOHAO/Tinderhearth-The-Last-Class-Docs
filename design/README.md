# 系统文档与提案

本目录装两个体裁，**按寿命分开放**，理由与被否决的方案见 [ADR-0010](../decisions/ADR-0010-文档体裁与系统文档归位.md)。

> **系统文档只为代码开工的系统写**（[ADR-0036](../decisions/ADR-0036-游戏是什么只在desc写一份.md)）：现在有的是地块、物品、背包、每日结算、存档、界面、生产系统与数值模型。别的系统开工时，先从工作区根 desc 写一份短的系统文档；要参考的话，从 git 历史里捞回删掉的那一份。
>
> **游戏规则以工作区根 `desc/` 为准**（有哪几份见[总索引](../README.md)的「权威层级」）：本目录的系统文档写结构、字段、校验与验收，规则与给玩家看的内容不另抄一份。几份系统文档的页头写着哪几处还是侧视那一套的旧说法，与 desc 说法不一样时以 desc 为准（[ADR-0035](../decisions/ADR-0035-战斗改成俯视的格子回合制.md)）。

| 体裁 | `type` | 位置 | 回答什么 | 寿命 | 模板 |
| --- | --- | --- | --- | --- | --- |
| **系统文档** | `system` | 本目录根下 | 这个系统的结构、接口与边界（契约） | **活文档**：随实现更新；只为代码开工的系统写 | [SYSTEM](../templates/SYSTEM.md) |
| **跨系统模型** | `model` | 本目录根下 | 一套所有系统都要满足的量、公式与判据 | **活文档**：随参数更新 | 同上 |
| **提案** | `design` | `design/proposals/` 下 | 这条路为什么走得通，别的路为什么不走 | **一次性**：结论迁进 desc 或系统文档后删掉 | [DESIGN](../templates/DESIGN.md) |

三者都是第 5 级（系统细化），权威层级相同 —— 分家分的是寿命，不是权威。**前两个体裁的位置、骨架与寿命完全一样**，差别只在「它是什么」：一个系统有实体、状态与流转，一个模型只有量、公式与判据。

## 命名规则

- **名字必须说出它是什么，后缀写死、可机检**：`type: system` 的文件名以**「系统」**结尾（`地块系统`、`背包系统`、`每日结算系统`），`type: model` 的以**「模型」**结尾（[`数值模型`](./数值模型.md)）。**不带体裁名词**（设计、方案、规格、文档 —— 位置与 `type` 已经表明体裁）。
- **数值模型为什么不叫「数值模型系统」**：它没有实体、没有状态、没有流转，硬加「系统」二字是让名字说谎。给它一个自己的 `type` 而不是在命名规则里开一条例外，是因为**例外要靠白名单才判得了，而白名单是每加一份就补一格的债**。
- 系统文档一个系统一份，名字与下面「系统清单」对得上。
- **提案**：`<slug>.md`，一句话能说清它在论证什么。
- 三者的一级标题都写成**一句结论**，不写名词短语。
- **将来出现第三、第四份模型时再考虑单独开目录。** 现在开等于为一份文件建一个目录，而搬它要改约 30 处路径引用。

## 系统文档

| 条目 | 内容 |
| --- | --- |
| [物品系统](./物品系统.md) | 一个物品定义有哪些字段（标识、名称与描述的文本键、类别、占地、堆上限……；类别只回答「它是什么」，一个值、全局一致；图标是作者在 Godot 里另配的资源，不在定义上），以及稀有度与品质是两条正交的轴（难不难得到／做得好不好），四个角都要存在；**典籍、任务物品、原料与建造材料没有品质这条轴**，星与品质点只是品质的样子；品质并进基础价而不当第四个乘数、必须在物品上看得见；堆的标识是「种类 ＋ 品质」，因此判据 C7 要重新校准。**不定内容、不定价格公式、不碰所属权**；立项在 [`GP-22`](../spec/issues/README.md) |
| [生产系统](./生产系统.md) | 六条产出渠道（开荒、种植、畜牧、钓鱼、加工、烹饪）共用一条管道：**产出 → 归属 → 付酬 → 入库**，四个环节顺序固定；第一个环节问「谁干的」，答案是本页持有的那张**按天派工指派表**（一个角色一天只占一格而**后一次被拒、不是覆盖**；跨睡眠保留所以进正式存档，而清空它的两个入口都在别处）；渠道之间只在四格上不同（产什么、耗多少、品质读哪项经营技能、有没有自己的状态机）；设备买的是自动化而不是便宜，且不得净产出自己的燃料；钓鱼是世界里的动作、不是界面。**六条里唯一带状态机的那条（地块）已按篇幅判据拆出去**，见下一行。**不定数值、不定内容、不碰容器与建造、不碰地块**；立项在 [`GP-28`](../spec/issues/README.md) |
| [地块系统](./地块系统.md) | 一格地从长着杂草到收上来一筐菜会经过哪些状态：**开荒与种植共用一台状态机**，所以它们合成一页。**锄是独立的一步**（可耕格能盖房但种不了 —— 合成一步会让玩家把房子盖在犁沟上）；枯株留成一个**待清**状态而不是自动消失（否则那张枯死素材没人看得到），清它不耗精力；已锄的空格**荒置若干天退回可耕**，而退化不必记「这格原来是什么」—— 已耕地是叠加层，底下那层一直在。浇水**按天记两个量、只改产量不改品质**（品质的来源已经定在种植那项经营技能上），产量系数**下限大于零且收成取整至少 1 件**。作物定义一张表、缺字段报错，**季节是列表而不是「跨不跨季」的布尔**（单季、跨季与全年因此是同一条枯死判定的三种填法），**收获后回到哪个阶段**那一格同时表达一次性与循环收获、再生间隔不另给数。按天推进全部并进每日结算已有那一步，**不新增步骤**。**不做画法、不做数值、不做当前操作格、不碰所属权**；立项在 [`GP-87`](../spec/issues/README.md) |
| [背包系统](./背包系统.md) | 两个容器（随身背包按角色各一个、基地仓库一份）的格位与满载：两个都是网格，一堆按物品的占地占一块、不能旋转，**堆的标识是「种类 ＋ 品质」**、满了只拒不丢、翻包暂停而用道具不暂停；随身栏是背包上单独一排、只放占 1 格的东西；容量判据量的是那些堆占的格数而不是种类数。**不定格数与堆上限、不碰所属权、不做界面**；立项在 [`GP-23`](../spec/issues/README.md) |
| [存档系统](./存档系统.md) | 一份存档是**若干分片的集合**，而每个分片由持有它的系统自己声明（叫什么、进正式存档还是进临时续玩点、缺字段时补什么）—— 所以**本页不持有任何字段清单**，「一共存了什么」由一个读口回答而不是由散文回答。进哪一侧只有一条判据：**跨过一次睡眠还成立的进正式存档**。分片之间**不许有载入顺序依赖**（反证是任意顺序读出同一结果），**派生量不单独存**（反证是改基底之后派生量跟着变），写入是一次「写临时文件 → 原子替换」的事务且**不另留玩家读得到的备份**。缺 mod 的内容**隔离而不是删除**（`ENG-7`：标成不可用、不进任何计数，装回 mod 一件不少）。格式与版本口径在 [ADR-0015](../decisions/ADR-0015-存档的版本与缺字段口径.md)。**不持有任何系统自己的字段、不做云同步、不做成就进度、不定数值**；立项在 [`GP-54`](../spec/issues/README.md) |
| [每日结算系统](./每日结算系统.md) | 那串步序**不在本页**（家在[经营规则 · 结算顺序](../../desc/经营规则.md)），本页只驱动它：**一个入口、两个来源**（主动睡与到点强制结束），**整串加自动存档是一次事务**且提交点是存档写入成功 —— 所以跑一半就一步都不生效，写入失败等于整天没推进，被中断则回到睡前。**步数一个不增一个不减**（结构约束），引用某一步**按步名不按序号**。结算期间**没有输入入口**，而那**不是「弹界面暂停世界」那条判据的适用对象**（世界本来就不在跑）。本页不为自己加一步，**而「不加步」这条结论别处也有好几份写过、依据各不相同 —— 那份名单刻意不在任何一页展开**。摘要是一个读口、不是第二份账。**不复述步序、不碰每一步的业务规则、给参数表加零个量**；立项在 [`GP-56`](../spec/issues/README.md) |
| [界面系统](./界面系统.md) | 玩家看到的每一处界面答哪一个问题、必须显示哪几项、哪些不许藏 —— 而**不许藏那几项一律按名指回它自己那份系统文档的原句**，本页不复述任何一条硬约束（要改那一句就说明这一页收错了方向）。分层、载体分类、导航栈与暂停判定**已经在代码仓 `rules/UI/` 里**，本页只指路、不抄；载体归属直接用那个已有分类的取值，**不发明第二套**。每一页只写三样（答什么问题、必须显示什么、什么不许藏），**判据是「写不出它答哪一个问题的界面不该存在，答得出两个的说明它是两页」**。只存在于界面侧的那几条才写在本页 —— 未解锁的节点不列条件、**战斗评级一行两格不给总评**（挡的是把两个档号合成一个数显示，那在数据上不违反任何东西而**不报错**）、气泡与引导提示形状分得开、按住跳过要有进度反馈。**不定控件、间距、色值、图标与摆位**（作者实机）、**不定键位**、**不重排层级**、**给参数表加零个量、给存档加零个字段**；立项在 `UI-13` 起那一批 |

## 提案

**体裁规则不因为提案的多少而变**：`/to-design` 判定出「这是一条要摆出被放弃方案的论证」时，它落 `design/proposals/<slug>.md`，`type: design`、[DESIGN 模板](../templates/DESIGN.md)那 11 节，检查器那条体裁归位判定管着它（[ADR-0010](../decisions/ADR-0010-文档体裁与系统文档归位.md)）。**上面那张体裁表也不因为「此刻恰好没有一份」而删行** —— 删了，下一个写提案的人就无处可查。

## 与 desc、需求文档的分工

| 文档 | 回答什么 | 生命周期 |
| --- | --- | --- |
| 工作区根 desc（例如[经营规则](../../desc/经营规则.md)） | **游戏是什么**：规则、内容、数值、人物、剧情、世界观 | 作者维护，最高权威 |
| 本目录根下 | 某个系统**现在怎么搭**：结构、接口、边界；或一套跨系统的量与判据 | 活文档，随实现更新 |
| `proposals/` | 某个方案**为什么成立**，以及为什么不选别的 | 活跃期维护，结论迁出后删掉 |
| [`spec/`](../spec/README.md) | 这**一次**改动做什么 | 一次需求，做完删掉、台账留一句 |

判断该写哪个：

- 只影响一次改动 → 需求文档，不要建系统文档。
- 一个系统的完整规则、会被多次改动反复引用 → **系统文档**。
- 一套所有系统都要满足的量、公式或判据（没有实体与状态）→ **跨系统模型**。
- 一条路走不走得通、要摆出被放弃的方案 → **提案**。
- 游戏规则与内容 → 请作者写进 desc，系统文档只写在 desc 的哪一份。
- 跨多个系统、难以撤销的取舍 → [ADR](../decisions/README.md)。

**建之前先找现有权威源。** 默认修改既有文档，不新建平行方案。真要新建就说明它的类型、上游来源、生命周期与替代关系，并接入 [README 文档地图](../README.md) —— 否则检查器会报「从 README 无法到达」。

## 上升规则按体裁分

- **提案**：结论写进 desc（请作者）或系统文档之后删掉。不做这一步就会出现两份说法不同的权威源，而且没有任何机制能发现 —— 检查器查断链，查不出两份文档对同一件事的描述已经分叉。
- **系统文档不整份上升。** 字段与接口按定义不进 desc，所以它不会「写完」；碰到的游戏规则请作者写进 desc，本页只写在 desc 的哪一份。
- **[数值模型](./数值模型.md)永久留在本目录**：desc 只写公式的样子（[各类公式计算](../../desc/各类公式计算.md)），值与判据在这里。写在这里是为了以后没人把它挪走。
