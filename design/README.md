# 系统文档与提案

本目录装两个体裁，**按寿命分开放**，理由与被否决的方案见 [ADR-0010](../decisions/ADR-0010-文档体裁与系统文档归位.md)。

| 体裁 | `type` | 位置 | 回答什么 | 寿命 | 模板 |
| --- | --- | --- | --- | --- | --- |
| **系统文档** | `system` | 本目录根下 | 这个系统的结构、接口与边界（契约） | **活文档**：随实现更新，系统在它就在 | [SYSTEM](../templates/SYSTEM.md) |
| **跨系统模型** | `model` | 本目录根下 | 一套所有系统都要满足的量、公式与判据 | **活文档**：随参数更新 | 同上 |
| **提案** | `design` | [`proposals/`](./proposals/推进与时间轴.md) | 这条路为什么走得通，别的路为什么不走 | **一次性**：结论迁出后归档 | [DESIGN](../templates/DESIGN.md) |

三者都是第 5 级（系统细化），权威层级相同 —— 分家分的是寿命，不是权威。**前两个体裁的位置、骨架与寿命完全一样**，差别只在「它是什么」：一个系统有实体、状态与流转，一个模型只有量、公式与判据。

## 命名规则

- **名字必须说出它是什么，后缀写死、可机检**：`type: system` 的文件名以**「系统」**结尾（`角色动作状态系统`、`状态效果系统`、`教育系统`），`type: model` 的以**「模型」**结尾（[`数值模型`](./数值模型.md)）。**不带体裁名词**（设计、方案、规格、文档 —— 位置与 `type` 已经表明体裁）。
- **数值模型为什么不叫「数值模型系统」**：它没有实体、没有状态、没有流转，硬加「系统」二字是让名字说谎。给它一个自己的 `type` 而不是在命名规则里开一条例外，是因为**例外要靠白名单才判得了，而白名单是每加一份就补一格的债**。
- 系统文档一个系统一份，与[玩法定位的系统清单](../canon/gameplay/玩法定位.md)对得上。
- **提案**：`<slug>.md`，一句话能说清它在论证什么。
- 三者的一级标题都写成**一句结论**，不写名词短语。
- **将来出现第三、第四份模型时再考虑单独开目录。** 现在开等于为一份文件建一个目录，而搬它要改约 30 处路径引用（其中 5 处在只读归档件里）。

## 系统文档

| 条目 | 内容 |
| --- | --- |
| [角色动作状态系统](./角色动作状态系统.md) | 互斥的姿态与流转：运动层、动作叠加层、生命周期终态、受击链与完整流转表、经营侧另一套动作机的原则。**不定效果、不定数值**；立项在 `GP-18` |
| [状态效果系统](./状态效果系统.md) | 能并存的修饰：三类（控制／参数／纯描述）、三种时长单位（帧／天／永久）、载体字段、显示与实际分离、跨场景与存档、与动作机的唯一接缝。**不定姿态、不定数值**；与动作机共用 `GP-18` |
| [物品系统](./物品系统.md) | 一个物品定义有哪些字段（标识、名称与描述的文本键、类别、图标、堆上限……；类别只回答「它是什么」，一个值、全局一致），以及稀有度与品质是两条正交的轴（难不难得到／做得好不好），四个角都要存在；品质并进基础价而不当第四个乘数、必须在物品上看得见；堆的标识是「种类 ＋ 品质」，因此判据 C7 要重新校准。**不定内容、不定价格公式、不碰所属权**；立项在 [`GP-22`](../spec/issues/README.md) |
| [生产系统](./生产系统.md) | 六条产出渠道（开荒、种植、畜牧、钓鱼、加工、烹饪）共用一条管道：**产出 → 归属 → 付酬 → 入库**，四个环节顺序固定；渠道之间只在四格上不同（产什么、耗多少、品质读哪项生活技能、有没有自己的状态机）；设备买的是自动化而不是便宜，且不得净产出自己的燃料；钓鱼是世界里的动作、不是界面。**不定数值、不定内容、不碰容器与建造**；立项在 [`GP-28`](../spec/issues/README.md) |
| [背包系统](./背包系统.md) | 两个容器（随身背包按角色各一个、基地仓库一份）的格位与满载：一格一堆、**堆的标识是「种类 ＋ 品质」**、满了只拒不丢、翻包暂停而用道具不暂停；容量判据量的是堆数而不是种类数。**不定格数与堆上限、不碰所属权、不做界面**；立项在 [`GP-23`](../spec/issues/README.md) |
| [伤害系统](./伤害系统.md) | 一次命中怎么算出一个数字与一条状态：伤害线与状态线**互不影响**，伤害线的顺序写死（倍率 → 防御 → 暴击 → 保底 1，穿透在防御那一步且扣到 0 为止）；伤害类型只有物理与魔法、各对一份防御，**元素不是第三种类型**（它只决定附带哪种状态，所以没有火抗）；状态抗性减施加概率并钳在 0–100，两头都留一线。**不做命中判定、不做打击反馈、不实现状态、不做友军伤害**；立项在 [`GP-32`](../spec/issues/README.md) |
| [技能系统](./技能系统.md) | 一个战斗技能要声明哪些字段，以及那些字段被谁读走 —— 技能不实现效果，它只是一张表。三种形态里**只有主动技占技能位**，被动与光环不占位也不设数量上限；光环因此改用「同类只取最大 ＋ 必带可感负面」防堆叠（第三条只能人工审）；每个技能各有不为零的冷却下限；宝石只镶主动技、按实战值档位解锁，且**改的是机制不只是数字**（判据是换掉一个字段或加一条行为）。**不装生活技能、不做技能等级与技能树、不碰键位**；立项在 [`GP-31`](../spec/issues/README.md) |
| [成长系统](./成长系统.md) | 角色身上会涨的量各由什么推动，以及它们汇总成的那张**派生表** —— 那是伤害与技能两侧读角色数据的唯一入口，且**基底与来源分两栏**（基底由属性给，大头来自饰品、宝石、天赋与状态；状态抗性「无基底」是合法取值）。三条防挂机纪律是同一条的多次应用；实战值按「角色 × 技能」记，队友 AI 读的汇总量是派生的；生活技能熟练度走档位制、每档解锁一件看得见的事。**不持有装备词条、掌握度与失衡增益**；立项在 [`GP-30`](../spec/issues/README.md) |
| [人际系统](./人际系统.md) | 任意两个角色之间那一个关系值：按**无序对**记、按需创建、**只升不降**（所以没有降法白名单，也不需要「曾经到过最高档」的闩锁 —— 单调性让当前档位就够，代价是那条不变式成了承重件）；压力全在每日涨幅上限那一侧；档位是接口而爱心只是刻度，机制一律读档位；恋爱是叠在对上的状态而不是第六档，资格是角色定义上的字段、缺了报错。**不定数值、不做日记与小事件、不碰实战值、不碰队友 AI 的档位结构**；立项在 [`GP-38`](../spec/issues/README.md) |
| [活跃失衡系统](./活跃失衡系统.md) | 全作唯一的全局量怎么被持有与改动：总量是「社区组 ＋ 被点名角色 ＋ 环境项」三层之和，境况事件声明多组增减、代价付在别人身上的必须双向，越低越难再降是缩放不是硬下限，永久增益落状态载体。**不定数值、不定内容、不接战斗结算**；立项在[系统深化顺序](../spec/issues/README.md) |
| [教育系统](./教育系统.md) | 课堂、考试与书籍三个零件各自的归宿：两个新量是书籍掌握度与知识吸收效率，授课产出各接哪个已有系统，防刷靠效率连日走低而非一道开关，考试挂季末与年末。**不定数值、不定内容**；立项在 `GP-21` |

## 与正典、需求文档的分工

| 文档 | 回答什么 | 生命周期 |
| --- | --- | --- |
| [正典](../canon/world/世界观.md) | 产品**意图**：这个游戏应该是什么 | 稳定，长期有效 |
| 本目录根下 | 某个系统**现在是什么**：结构、接口、边界；或一套跨系统的量与判据 | 活文档，随实现更新 |
| `proposals/` | 某个方案**为什么成立**，以及为什么不选别的 | 活跃期维护，结论迁出后归档 |
| [`spec/`](../spec/README.md) | 这**一次**改动做什么 | 一次需求，归档即结束 |

判断该写哪个：

- 只影响一次改动 → 需求文档，不要建系统文档。
- 一个系统的完整规则、会被多次改动反复引用 → **系统文档**。
- 一套所有系统都要满足的量、公式或判据（没有实体与状态）→ **跨系统模型**。
- 一条路走不走得通、要摆出被放弃的方案 → **提案**。
- 已经确定、不会再变的产品事实 → 直接进正典。
- 跨多个系统、难以撤销的取舍 → [ADR](../decisions/README.md)。

**建之前先找现有权威源。** 默认修改既有文档，不新建平行方案。真要新建就说明它的类型、上游来源、生命周期与替代关系，并接入 [README 文档地图](../README.md) —— 否则检查器会报「从 README 无法到达」。

## 上升规则按体裁分

- **提案**：结论上升进正典或系统文档之后归档。不做这一步就会出现两份说法不同的权威源，而且没有任何机制能发现 —— 检查器查断链，查不出两份文档对同一件事的描述已经分叉。
- **系统文档不整份上升。** 字段与接口按定义不进正典，所以它不会「写完」；只有个别稳定下来的结论（例如一张分类判据表）才上升，本页对应条目里写明是哪几条。
- **[数值模型](./数值模型.md)永久留在本目录**：[玩法定位](../canon/gameplay/玩法定位.md)写明「数值一律不在正典」。写在这里是为了以后没人来做一次错误的上升。
