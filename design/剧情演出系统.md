# 一段演出是一串指令，正式对话是其中一类：所以与 NPC 交谈和剧情过场共用同一台状态机

> **正典层级**：第 5 级（系统细化）。与[玩法定位](../canon/gameplay/玩法定位.md)冲突时以正典为准；**跳过要按住多久、快进倍率与对话推进的最短间隔全归 `GP-6`，镜头手感那几个数归 `UI-12`，本页一个都不定。**

## 摘要

一段剧情演出是**一串按顺序推进的指令，加一台推进它的状态机**。本页定那串指令长什么样、谁推进它、什么时候收尾、跳过与快进各是什么。

**它持有**：演出的状态机与流转、一条指令要声明的字段、指令类型那张开口的表、**正式对话作为其中一类指令**、跳过与快进、演出与世界暂停的关系、演出怎么摆布角色、演出结束后的交还、文本按键取这条管线的用法。

**它不持有**：台词与脚本内容（内容外置，`ENG-5`）；**气泡**（它不接管输入、没有流转，家在[`气泡对话系统`](./气泡对话系统.md)）；日记（[`日记系统`](./日记系统.md)）；镜头机位与手感值（作者与 `UI-12`）；主线节点之间怎么解锁（[`主线推进系统`](./主线推进系统.md)）；AI 的决策（[`战斗AI系统`](./战斗AI系统.md)）；姿态与流转（[`角色动作状态系统`](./角色动作状态系统.md)）。

最要紧的那条承诺：**一份格式，三处用途。** 与 NPC 交谈、剧情过场、关系小事件的那一段，用的是同一台状态机与同一份数据 —— 依据是 [ADR-0014](../decisions/ADR-0014-对话是演出脚本的一类指令.md)，本页不重写它的理由。**本页也不新建时间单位、不新建暂停机制、不新建第二条取文管线。**

- [`状态效果系统` · 载体的字段](./状态效果系统.md)：载体字段含来源、三种时长单位各有推进点。**约束演出里的状态变更落已有载体，本页不新建修饰表。**
- [`关卡系统` · 一个种子，加一份关卡进度](./关卡系统.md)：关卡进度进临时续玩点，关卡内退出恢复到关卡入口。**约束关卡中途触发的演出不单独续玩。**
- [`事件系统` · 后果一律是对已有入口的调用](./事件系统.md)：事件的一条后果是点播一段演出，而「已触发过」记在它那一侧。**这是本页的一个调用者，也是「能不能跳过」那条判据读的那份记账。**
- [`数值模型` · 尚未给值的量，各自写明校准办法](./数值模型.md)：值的唯一来源是参数表，本页只写量纲与约束形式。**约束本页新增的量一律进那张表。**
- [ADR-0014](../decisions/ADR-0014-对话是演出脚本的一类指令.md)：正式对话是演出脚本上的一类指令；气泡不共用这份格式，判据落在接不接管输入上。**这是本页最核心那条结构的依据，本页照它走、不重写它的理由。**
- [ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)：参数唯一来源是场景与资源、代码不留能用的默认值；场景、镜头摆位与动画帧由作者在 Godot 里管。**约束脚本缺字段当场报错，也约束镜头指令分成「我定字段、作者摆位」两半。**

## 结构

### 一段演出是一串指令，加一台推进它的状态机

| 状态 | 进入条件 | 退出去哪 |
| --- | --- | --- |
| **待命** | 初始；上一段收尾完成 | 被点播 → 推进 |
| **推进** | 被点播，或当前指令执行完且不等玩家 | 当前指令要等玩家 → 等输入；指令串走完 → 收尾；玩家确认跳过 → 收尾 |
| **等输入** | 当前指令声明了要等玩家（一句对话读完、一组选项待选） | 玩家给了输入 → 推进（选项按它声明的跳转走） |
| **收尾** | 指令串走完，或被跳过 | 状态变更全部应用、控制交回玩家 → 待命 |

**四个状态就是全部，没有第二台状态机。** 与 NPC 交谈走的是同一台 —— 它只是一段没有镜头指令的脚本（[ADR-0014](../decisions/ADR-0014-对话是演出脚本的一类指令.md)）。

**它与[`角色动作状态系统`](./角色动作状态系统.md)那两层是正交的两台机器**：本页这台管「这段脚本走到哪」，那两层管「这个角色现在摆什么姿态」。合成一台的后果是那张流转表要为每条指令各来一遍。

**同一时刻只有一段演出。** 演出接管输入，而输入只有一份；允许并发就要回答「两段演出各推自己的镜头时镜头听谁的」，而那个问题没有好答案。一段演出进行中被点播的下一段**排队**，不打断当前那段。

### 一条指令要声明什么

| 声明项 | 说明 | 缺了怎么办 |
| --- | --- | --- |
| 指令类型 | 见下面那张开口的表 | 缺声明**载入报错** |
| 目标 | 这条指令作用在谁或什么上（角色、相机、画面） | 该类型需要而缺失时**载入报错** |
| 参数 | 按类型各自要的那几个值 | 同上 |
| 要不要等玩家 | 执行完之后是继续推进，还是停在「等输入」 | 缺声明**载入报错**（不给默认值，[ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)） |

**「要不要等玩家」必须显式声明，不许从类型推。** 一句对话通常要等，但演出里也有「主角自语一句、镜头继续推」的用法；从类型推等于把那种用法删掉，而它不报错 —— 表现是演出忽然变得很赶。

### 指令类型是一张开口的表

| 类型 | 它干什么 |
| --- | --- |
| 镜头 | 把相机移到声明的机位、或跟住某个目标 |
| 站位与移动 | 让一个角色到声明的位置去 |
| 角色动作 | 让一个角色做一个它声明过的动作 |
| **正式对话** | 一个角色说一句，可选地给一组选项 |
| 淡入淡出 | 画面转场 |
| 状态变更 | 往[状态载体](./状态效果系统.md)加减一项、或调一次别的系统的入口 |
| 等待 | 停一段时长再继续 |

**加一类指令时填的是这张表，而不是在状态机上加一个分支。** 这条是本页最要紧的一条扩展纪律：状态机上加分支会让跳过与快进的语义散进每个分支里，而它们本来只有一处。

**判据：新东西能不能写成「作用在谁身上、要哪几个参数、要不要等玩家」。** 写得出就是一条指令；写不出的说明它不是演出的一部分（例如「等玩家去把地浇完」—— 那是任务的目标条目，见[`任务系统` · 任务与事件的分界](./任务系统.md)）。

### 正式对话那一类指令

| 格 | 说明 |
| --- | --- |
| 说话者 | 哪个角色。**声线属角色**（[人物 · 台词、命名与原创表达红线](../canon/characters/人物.md)），本页不持有 |
| 文本键 | 说什么。**只存键，不存台词**，见下面「文本一律按键取」 |
| 选项表 | 可选。每个选项各有自己的文本键与**一个后续跳转** |

- **没有选项的对话指令就是一句话**；有选项的停在「等输入」，玩家选完按那个选项声明的跳转走。
- **选项的跳转是显式的，不是「往下一条」。** 隐式往下走的话，「两个选项汇到同一段」与「两个选项各走一支」在数据里长得一样，而前者是常态。
- **本页不判选项好不好、不做善恶值。** [玩法定位 · 推进与胜负](../canon/gameplay/玩法定位.md)写明不在选项上标注对错。
- **「不可逆」这件事能标，但标的是事实不是评价**：一个选项可以声明它之后没有回头的跳转，界面按这条提示玩家（界面侧的事）。

### 只含对话指令的脚本就是一次纯对话

**与 NPC 交谈不需要任何额外结构。** 它是一段只有对话指令、没有镜头与站位指令的脚本 —— 所以「与 NPC 交谈」「剧情过场」「关系小事件的那一段」在本页是同一样东西的三种用法，不是三套机制。

**由此来一条判据**：一段东西该不该走本页，问它**接不接管输入**。接管就走本页（它会暂停世界）；不接管的是气泡，不在本页。

### 文本一律按键取，日记与事件回看共用同一条

**脚本里不存台词，只存文本键。** 这一条在本页展开一次，别处写链接不复述 —— [日记](../canon/gameplay/角色与成长.md)与[`事件系统`](./事件系统.md)的回看记录用的是**同一条管线**，三处各写一套取文办法的后果是本地化与[禁译表](../canon/characters/人物.md)要维护三遍。

- **管线本体不在本页，它已经落地**（代码仓 `data/text/zh-CN.json`，`ENG-5` 那条文本外置预留）。本页只定演出与对话怎么从它取文。
- **主角的假名只能按键取**（[玩法定位 · 开局](../canon/gameplay/玩法定位.md)：那个名字由玩家起），写死就会和玩家起的名字自相矛盾。
- **文本键缺失时报错，不退化成显示键名。** 显示键名不报错，而它会一路混到发行包里。

### 演出接管输入，所以世界暂停 —— AI 不需要为它加任何东西

**演出接管输入 → 按[玩法定位 · 弹界面接管输入就暂停世界，世界里的动作不暂停](../canon/gameplay/玩法定位.md)那条判据世界暂停 → 暂停复用顿帧那个「当帧不推进」的闸门 → [`战斗AI系统`](./战斗AI系统.md)那条决策循环跟着不跑。**

**这是既有判据的适用，不是本页新加的一条规则。** 写出来是因为第 6 批让那条决策循环存在了，而「演出期间它跑不跑」现在有了具体答案：不跑，而且那一侧一个字都不用改（改的只是它补一句指回这里）。

- **关卡中途触发的演出因此不会让玩家在看剧情时被打**（正典那句）。
- **敌人的警戒状态在演出期间一个字都不改。** 它不是按帧推进的量，所以暂停管不着它 —— 要显式写，否则实现时会顺手在演出结束时「重置警戒」。

### 演出摆布角色时把动作递给动作机，绕过决策循环

**演出要让一个角色走两步、挥一下手，走的是[`角色动作状态系统`](./角色动作状态系统.md)那条既有的路** —— 与 AI 递「想做什么」是同一个入口，只是来源不同。

- **不给决策循环加「被演出接管」的态。** 决策循环本来就只是「产出想做什么」的一个来源，而它在演出期间不跑；加一个态等于要回答「演出里敌人能不能打你」，而正典已经答了（不能）。
- **引用了这个角色没声明的动作时载入报错**，并说清是哪条指令要哪个动作（[`角色动作状态系统` · 一个角色有哪些动作，是它自己声明的](./角色动作状态系统.md)）。**这与「AI 只从声明的动作集里选」是两回事**：那边是运行时的正常筛选，这边是脚本配错了 —— 混在一起会让配错静默变成「那个角色就是不做那个动作」。

### 演出结束后的交还：脚本自己声明，不做自动还原

**角色回到什么姿态与位置，由脚本自己声明。** 不做自动还原。

理由是**演出挪动角色常常正是它要的结果** —— 「演出把人送到门口」之后自动把人拉回原处，那条演出就白做了，而且它不报错。代价是脚本作者要自己写回位指令；换来的是「演出做了什么」全在脚本里看得见。

### 跳过与快进是两件事

| | 它做什么 | 边界 |
| --- | --- | --- |
| **快进** | 加速推进 | **不跳过「等输入」那一类指令** —— 否则它就是跳过 |
| **跳过** | 直接进收尾 | **脚本声明的状态变更一次性全部应用** |

**「跳过不许漏掉状态变更」是本页的承重项。** 漏了的表现是「跳过演出之后那个学生没加入」，而它**不报错**；所以状态变更不能写在每条指令的执行路径里，它要能被收尾一次性取到。**这条要有反证钉住。**

- **防误触的形状是按住而不是点一下。** 与[`关卡系统`](./关卡系统.md)那条「撤离不给确认框」同一形状：确认框会暂停世界，而按住本身就是确认。时长归 `GP-6`。
- **能不能跳过按那份触发记账判**（[`事件系统`](./事件系统.md)持有它）：没播过的不给跳，播过的给跳。**记账只有一份**，本页不另存「这段演出播过没有」。
- **对话推进有一个最短间隔**，挡的是连点把一整段点过去；值归 `GP-6`。

### 关卡中途触发演出时的边界

- **世界暂停**，所以玩家不会在看剧情时被打（正典那句）。
- **演出不单独续玩。** 关卡内退出恢复到关卡入口（[玩法定位 · 存档](../canon/gameplay/玩法定位.md)），而一段演出要么没播完（那就重播），要么已经收尾并应用过状态变更（那就不再播）。**中间态不存**，因为存了就要回答「从第三条指令接着播时镜头在哪」。
- **已播过的脚本进正式存档**，走[`事件系统`](./事件系统.md)那份触发记账。

### 镜头指令分两半：本页定字段，作者填机位

**本页定「有哪些镜头指令、各要什么参数」；具体机位、时长与曲线由作者在检查器里填**（[ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)：参数唯一来源是场景与资源）。

- **相机手感那几个数不在本页**（跟随、震动、推镜与演出归还，见 `UI-12`）。本页只定「演出期间相机听脚本的」。
- **演出结束时相机归还给谁，由脚本声明**，与角色交还同一条规则。

## 接口

### 谁点播它、它调谁

| 方向 | 对方 | 形状 |
| --- | --- | --- |
| 入 | [`事件系统`](./事件系统.md) | 点播一段脚本（随机事件与关系小事件的一条后果） |
| 入 | 剧情节点 | 点播一段脚本；节点之间怎么解锁不在本页（[`主线推进系统`](./主线推进系统.md)） |
| 出 | [`主线推进系统`](./主线推进系统.md) | 一段节点脚本播完时报一次「那个节点完成了」；**方向单向** |
| 入 | [`任务系统`](./任务系统.md) | 剧情类目标条目由脚本置位，所以它也点播得到 |

| 入 | 触发记账（[`事件系统`](./事件系统.md)） | 「这段播过没有」只有那一份，本页读它、不另存 |
| 出 | 文本管线 | 按文本键取文；**本页不存台词** |
| 出 | [`角色动作状态系统`](./角色动作状态系统.md) | 站位与角色动作都递给它；**被拒就是被拒，不绕过去** |
| 出 | 相机 | 镜头指令；机位与时长是作者填的导出参数 |
| 出 | [`状态效果系统`](./状态效果系统.md) | 状态变更类指令落它的载体项，本页不新建修饰表 |
| 出 | 别的系统的入口 | 状态变更类指令也可以调一次已有入口（给物品、改关系一类），**形状与[`事件系统`](./事件系统.md)那张后果表同源、本页不另立一张** |

**挂载点到此为止。** 将来加一样与演出有关的东西时，先问「它挂在上面哪一格」，而不是顺手插一个新钩子。

### 它不碰的四条接缝

- **气泡**：不接管输入、没有流转，按[玩法定位 · 对话：气泡与正式对话是两套东西](../canon/gameplay/玩法定位.md)与本页分家；它的约束在正典，结构在[`气泡对话系统`](./气泡对话系统.md)。
- **日记**：本页只保证它与演出共用同一条取文管线；日记自己是什么在[`日记系统`](./日记系统.md)。
- **触发与记账**：「什么时候播、播过没有」全在[`事件系统`](./事件系统.md)；本页只被点播。
- **姿态与流转**：本页只递「让他做这个动作」，姿态在[`角色动作状态系统`](./角色动作状态系统.md)。

## 边界与非目标

- **不定任何数值**：跳过要按住多久、快进倍率、对话推进的最短间隔归 `GP-6`（手感量，只能实机逐帧调）；镜头机位与时长是作者填的导出参数；相机手感那几个数归 `UI-12`。**接口常量不是数值** —— 指令类型那张表是**开口的**，所以它没有「条数」这个量；状态机那四个状态是接口常量，家在本页。
- **不定内容**：有哪些演出、哪些对话、说什么，属内容，走[内容外置](../canon/gameplay/玩法定位.md)（`ENG-5`）。**台词本身不进设计仓。**
- **不做气泡**（[`气泡对话系统`](./气泡对话系统.md)）。判据是接不接管输入；正典还明写不要把它与正式对话合成一个系统。
- **不做日记本体**（[`日记系统`](./日记系统.md)）。
- **不做预渲染视频**：正典排掉。
- **不做骨骼动画级演出**：正典把复杂度上限写死在镜头、站位、对话与简单动作。
- **不做善恶值与选项对错标注**：[玩法定位 · 推进与胜负](../canon/gameplay/玩法定位.md)排掉。
- **不做并发演出**：同一时刻只有一段，后来的排队。
- **不存演出的中间态**：关卡内退出恢复到关卡入口，演出要么重播要么不再播。
- **不做自动还原**：角色与相机回哪由脚本声明。
- **不给决策循环加「被演出接管」的态**：世界暂停已经让它不跑。
- **不做本地化流程**：禁译表与母语审校在[人物 · 台词、命名与原创表达红线](../canon/characters/人物.md)，本页只保证脚本里存的是文本键。
- **不做界面**：跳过与推进怎么按、选项怎么排、对话框长什么样归界面侧与作者实机定（进度见[待办台账](../spec/issues/README.md)）。
- **不做主线节点之间怎么解锁**：本页只做「一段演出」的结构，节点图在[`主线推进系统`](./主线推进系统.md)。
- **不设计存档序列化格式**：只定「已播过的脚本落在那份触发记账里，而演出的中间态不存」——格式与版本口径在 [ADR-0015](../decisions/ADR-0015-存档的版本与缺字段口径.md)，分片怎么声明在[`存档系统`](./存档系统.md)。
- **同名不同物，两处都要写全名**：
  - **「剧情演出」与「过场」**：同一样东西。正典那句「全部剧情与过场」用的是后者，而**正式名是剧情演出**；本页出现「剧情过场」时说的就是它，**不要按它另开一类脚本**。
  - **「对话」有两个意思**：**气泡**（不接管输入，不在本页）与**正式对话**（本页那一类指令）。两处都写全名。
  - **「状态变更」有两个意思**：本页那一类**指令**，与[`状态效果系统`](./状态效果系统.md)载体上的一**项**。前者是脚本上的一步，后者是角色身上的一条修饰。
  - **「跳过」与「快进」**：前者进收尾并一次性应用状态变更，后者只是加速推进、不跳过等输入的指令。
  - **「等待」与「等输入」**：前者是一类指令（停一段时长），后者是状态机的一个状态（停在那儿等玩家）。
  - **「选项」与[`任务系统`](./任务系统.md)的「目标条目」**：前者是对话里选一句，后者是任务要达成什么。

## 理由与取舍

- **没选让正式对话另有一份格式与状态机。** 理由与被放弃的三条候选都在 [ADR-0014](../decisions/ADR-0014-对话是演出脚本的一类指令.md)，本页不重写。
- **没选把气泡也并进来。** 正典明写不要把它与正式对话合成一个系统，而那句话有理由：气泡不接管输入、按上下文键随机挑句、说过的进冷却池还会回来。并进来之后「这条要不要暂停世界」就变成每条语料上的一个开关，而那正是那条判据要挡的。
- **没选从指令类型推「要不要等玩家」。** 演出里有「自语一句、镜头继续推」这种用法，从类型推等于把它删掉 —— 而它不报错，表现只是演出忽然变得很赶。
- **没选让选项隐式往下走。** 那样「两个选项汇到同一段」与「两个选项各走一支」在数据里长得一样，而前者是常态；显式跳转多写一格，换来的是分支结构在数据里看得出来。
- **没选在状态机上给每类指令加分支。** 跳过与快进的语义会散进每个分支，而它们本来只有一处；指令类型进表、状态机不动，加一类指令就只是填一行。
- **没选给决策循环加「被演出接管」的态。** 世界暂停已经让它不跑，加一个态等于要回答「演出里敌人能不能打你」，而正典已经答了。**更实的一处**：那个态会让「AI 现在能不能动」有两个判断处，而不一致时不报错。
- **没选演出结束时自动还原角色与相机。** 挪动角色常常正是演出要的结果，自动还原会把它悄悄撤销；代价是脚本要自己写回位指令。
- **没选让跳过按条执行完整个指令串。** 那会把一段两分钟的演出变成两秒钟的镜头乱闪，而玩家按跳过就是不想看；改成「进收尾并一次性应用状态变更」之后，要守的只剩一条 —— 状态变更不能藏在指令的执行路径里。
- **没选让快进也跳过等输入的指令。** 那样快进与跳过就是同一件事，而玩家要的是「这段我看过了，快点」而不是「别播了」。
- **没选存演出的中间态。** 存了要回答「从第三条指令接着播时镜头在哪、角色站哪」，而那份数据一改脚本就废；重播一遍的代价是玩家多看一次，而他手上有跳过。
- **没选并发演出。** 输入只有一份，镜头只有一个；允许并发就要定一套优先级，而那套优先级没有任何玩法价值。
- **没选让本页自己存「这段演出播过没有」。** 那会和[`事件系统`](./事件系统.md)那份触发记账成为同一件事的两个家，而分叉的表现是「明明播过却还能跳过」这类不报错的错。
- **没选让文本键缺失时退化成显示键名。** 不报错的降级会一路混到发行包里；报错的代价只是内容作者早一步发现。

## 验收

**可自动验证项**（纯规则层，与引擎无关）：

- 状态机：四个状态的每条流转各一条用例；**同一时刻只有一段演出**（进行中被点播的下一段排队，不打断）。
- **只含对话指令的脚本能作为一次纯对话播出**（承重项的一半）：不需要任何镜头字段，也不报错。
- **跳过之后状态变更一条不少**（承重项）：一段含若干状态变更指令的脚本，跳过前后的世界状态与完整播完一致 —— 这条是反证，它挡的是「把状态变更写在每条指令的执行路径里」那种实现。
- 快进：**不跳过「等输入」那一类指令**（一条用例：含选项的脚本在快进时仍然停下来等）。
- 缺字段当场报错：指令类型缺失、该类型需要的目标或参数缺失、「要不要等玩家」缺声明，各一条**载入被拒**（[ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md)）。
- **不从类型推「要不要等玩家」**：同一种类型的两条指令，一条等、一条不等，都合法。
- 选项：每个选项的跳转是显式的；**跳转指向不存在的指令时载入被拒**；两个选项跳到同一条也合法。
- 文本：脚本里**不存台词**（一条结构约束：对话指令只有文本键这一格）；**文本键缺失时报错**，不退化成显示键名。
- 暂停：演出进入推进时世界暂停、收尾时交回；**演出期间决策循环不产出任何动作**（与[`战斗AI系统`](./战斗AI系统.md)那条是同一件事，两边各写一次）。
- 警戒状态：演出前后敌人的警戒状态完全一致（**演出不重置它**）。
- 动作：站位与角色动作都经动作机；**动作机拒绝时演出不绕过去**；**脚本引用角色没声明的动作时载入被拒**并说清是哪条指令要哪个动作。
- 交还：**不做自动还原** —— 一段把角色挪到别处的脚本，收尾后角色仍在那里（一条测试钉住这不是漏做）。
- 能不能跳过：读的是[`事件系统`](./事件系统.md)那份触发记账；**本页没有第二份「播过没有」的存储**（读口只有一个）。
- 关卡中途：演出的中间态不进续玩点；重建后要么整段重播、要么因为已收尾而不再播，**两种各一条用例**。
- 统计事件：演出播完发一条。
- 存档往返：「已播过的脚本」存进去再读出来完全一致。

**必须实机确认项**：一段演出好不好看、镜头切得急不急、对话框读不读得清、跳过要按住多久才不烦、快进的速度合不合适、选项在像素下看不看得出哪个是不可逆的、演出结束那一下世界恢复得干净不干净。按 [ADR-0009](../decisions/ADR-0009-编辑器主导的开发模式.md) 的分工由作者实机看，本页不判。**「这段演出好不好看」永远没有机器判据** —— 机器只判得到「字段都声明全了、跳过之后状态变更一条不少」，与[`技能系统`](./技能系统.md)那条「负面疼不疼」同类。

**完成边界**：状态机落成唯一那一台且四条流转都判得到、一条指令的字段表缺一格就报错、正式对话是其中一类且纯对话脚本走得通（有反证）、跳过不漏状态变更（有反证）、演出期间世界暂停而 AI 那一侧一个字都不用改、角色与相机的交还由脚本声明、文本一律按键取。做到这些，「一个交互点或一条事件点播一段脚本 → 逐条推进 → 玩家选一次 → 收尾并应用状态变更 → 控制交回」这条链在文档层面就走得通了。

## 下游同步

- **代码**：演出的状态机与指令推进落**规则层**（它只吃指令串与文本键，不需要引擎）；镜头、淡入淡出与脚本资源的加载落引擎层。相邻的既有件是文本外置那条预留（代码仓 `data/text/zh-CN.json`）与 `rules/Ui/` 下那套界面骨架（导航栈与手环标签页）。**实现前先搜一遍代码仓确认演出与对话侧真的是空的** —— 本页写这句是因为那还是推断。**脚本资源要作者搭，所以落地排在 `ENG-21` 之后或与它同批。**
- **数值**：跳过要按住多久、快进倍率、对话推进的最短间隔进 `GP-6`（实机逐帧调）；镜头机位与时长是作者填的导出参数，不进参数表。
- **台账**：立项在 [`NR-7`](../spec/issues/README.md)；落地顺序按「状态机与四条流转 → 指令字段表与缺字段报错 → 正式对话那一类加选项跳转 → 文本按键取（含缺键报错）→ 暂停接既有闸门（含 AI 不产出动作的反证）→ 角色与相机交还由脚本声明 → 跳过与快进（含状态变更一条不少的反证）→ 接触发记账与存档」。界面归界面侧那一条。
- **该上升进正典的**：只有一条 —— **「接不接管输入」这条分家判据**（接管的走本页、不接管的是气泡），等气泡那一侧真的落地并证明这条判据够用之后，上升进[玩法定位 · 对话：气泡与正式对话是两套东西](../canon/gameplay/玩法定位.md)。其余字段与接口按定义不进正典。
