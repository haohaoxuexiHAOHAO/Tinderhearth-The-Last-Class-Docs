## 30 秒恢复上下文

1. 看 [spec/](./spec/README.md) 下有哪份 `prd-*.md` —— 那就是当前需求；再看对应 issue 文件的验收勾选情况 —— 那就是进度。会话开始时钩子会自动打印这两项。
2. 按任务只打开下表中的权威文档；不要先读 `archive/`。
3. 需要核对实现时，再按顺序读取代码仓库的 `README.md → ARCHITECTURE.md → CONVENTIONS.md`，最后以代码和测试为准。代码仓尚未建立时，这一步跳过。

## 权威层级

**游戏是什么只在工作区根 `desc/` 写一份**（[ADR-0036](./decisions/ADR-0036-游戏是什么只在desc写一份.md)）：规则、内容、数值、人物、剧情、世界观都在那里，作者维护，最高权威；有哪几份见下面文档地图「作者维护」那一行。这几份不在仓库里。

设计仓只留做游戏要用的文档：系统文档写代码怎么搭，只为代码开工的系统写；架构决策记录（Architecture Decision Record，简称 ADR）写跨域取舍为什么这样定；台账写进度。系统文档写到规则与数值时只写在 desc 的哪一份，不另抄。对不上时，游戏规则以 desc 为准，工程取舍以 ADR 为准；代码说明已经实现的现状。删掉的文档（原来的正典、代码不用的系统文档、旧指南）只在 git 历史里。

## 游戏定位

本作是 2D 像素风格的废土幻想**经营建造 + 俯视格子回合制战斗**（[ADR-0035](./decisions/ADR-0035-战斗改成俯视的格子回合制.md)）。核心主题是**守护与希望**：玩家主动帮助他人迎来高光时刻，而不是把角色当作可以替换的消耗品。基地、城区与出征都是俯视，玩家直接操作主角。上架目标是 Steam 的 Windows PC 端，买断制。

公式的样子见 [desc/各类公式计算.md](../desc/各类公式计算.md)，值与判据归[数值模型](./design/数值模型.md)。**代码里刻意没有玩法数值**；战斗手感帧数不属数值模型，归实机收敛（见[待办台账](./spec/issues/README.md) `GP-6`）。

前作《火种》的玩法明确**不予继承**，本作的回合制是重新设计的。世界观、主角设定与美术／文案方法论继承自前作，其余（剧情、九人学生名单、战斗与经营系统、任务与界面接口）一律重新设计。

经营与战斗是同一条循环的两半：经营决定带着什么去打，战斗决定能带回什么继续经营。战斗区域是出征时加载进去的图，没有无缝世界，也没有开放世界漫游。

**发行与平台**：单机，先保证 Windows PC 能正常游玩，其余设备后置。界面按 16:9 设计与验收，不为别的宽高比留设计余量；Steam Deck 是 16:10，上面的黑边归 `UI-2`。零成本的习惯现在就守住，后置才不会变成重做：代码仓 `project.godot` 的 `window/stretch/mode="canvas_items"` 与 `aspect="expand"` 保持不动；界面用锚点与容器布局，不写死绝对像素坐标。

- **目标平台只有 PC，不为移动端留设计余量。** 操作按键鼠与手柄排，触屏得另配一套；`project.godot` 里的 `mobile` 渲染方式只是 2D 项目的性能选择，与平台无关。
- **DLC 就是官方 mod。** 两者用同一套地基：内容数据外置（`ENG-5`）加存档容忍内容增减（`ENG-7`）；DLC 另走一套硬编码，就要维护两套内容管线。所以追加内容不得破坏旧存档，这与「卸掉 mod 后存档要容忍缺失的内容」是同一条要求的两个方向。
- **成就靠统计事件总线，不事后补埋点。** 值得记录的行为都向这条总线发事件，成就与统计只订阅它、不自己去各系统插桩。成就可以晚做，发事件要从第一天就做：事后补埋点要翻遍全部系统。
- **云存档**：存档落在 `user://saves/`（代码仓 `src/Platform/SaveStore.cs`），云同步冲突与 Steam 集成归 `ENG-8`。
- **联机若做，是合作不是对抗。** 玩家用自定义角色，不扮演主角或学生，剧情模式的主角固定是烬；零成本的结构预留归 `ENG-5`，其余不做。

**剧情演出**：全部剧情与过场用游戏自己的场景、角色与对话演出，不做预渲染视频。理由都不是偏好：像素画面在视频编码下必然糊掉；视频演不出玩家的选择，主角的假名是玩家起的，在场的学生是玩家养的；视频的本地化要重录，文本外置的引擎内演出改一行数据就行；引擎内演出复用已有的场景与角色，边际成本远低于另起一条美术管线。

演出系统很早就要有，教学关与开局都靠它；复杂度控制在镜头、站位、对话与简单动作，不做骨骼动画级的演出。演出接管输入，所以世界暂停（[经营规则 · 打开界面时世界暂停](../desc/经营规则.md)）：不由玩家操作的角色跟着停，AI 那一侧不为演出加任何状态；演出要摆布角色时走动作机那条既有的路，不经 AI 的决策循环。

**mod 的扩展边界**：全部内容数据外置，角色、宝物、宝石、技能、特质、天赋、作物、加工配方、委托模板、敌人都是；mod 追加数据文件来扩展，不改代码。不外置的是规则本身：循环结构、结算顺序、失败判定、所属权边界由代码保证，mod 改不了。理由是可维护性：内容可以无限加，规则一旦可改就没有任何行为可预期，存档容错与缺陷排查都无从下手。

- **一种内容只有一张定义表，条目自己声明它有哪几项能力，不按类型分叉**（[ADR-0018](./decisions/ADR-0018-内容定义按声明扩展.md)）。类型是规则结构，而 mod 只能加数据；按类型分叉的话，mod 加不了没人预见过的东西，例如会种地的怪物。
- **一格能填哪些值，判据是加一个取值要不要写新代码**（[ADR-0025](./decisions/ADR-0025-取值集的家由加一个的代价决定.md)）。要写新代码的那几格，是「不改代码」这句承诺的收窄。
- **一次版本更新对旧存档只有两种后果：兼容，或要求重开档**（[ADR-0017](./decisions/ADR-0017-版本更新对旧存档的两种后果.md)）。存档存的是标识，旧存档读不到新标识就等于没有这样东西，所以追加内容永远属于兼容那一种，上面「DLC 就是官方 mod」那条要求由此成立。
- **上面列的是类型，不是量**：每一类起步做多少在[数值模型 · 附录：内容规模基准](./design/数值模型.md)。两处的行刻意不要求相同，要不要收平归 `DOC-106`。工程落点是 `ENG-5`（数据驱动）与 `ENG-7`（存档容错）。

**明确不做的**：只装永久立场，判据是它的理由与时间无关；「现在不做、以后可能做」是状态，家在[待办台账](./spec/issues/README.md)。写下来是为了以后不用再讨论一遍。

- **宠物与坐骑**：与核心循环无关（[经营规则 · 核心循环](../desc/经营规则.md)写明没有）。
- **遥测与数据回传**：不收集玩家数据。
- **PVP 与任何在线对抗**：联机若做也是合作，见上面「发行与平台」。
- **内购、开箱、精力回复付费、赛季通行证**：买断制，DLC 是唯一的付费追加形式。

## 维护入口

以下 `python tools/...` 命令都从**设计仓库根目录**运行；从工作区根目录运行时，在路径前加 `Tinderhearth-The-Last-Class-Docs/`。

- 提需求：只说目标、现状、验收和非目标就行。执行者用 `/prd` 技能问清剩下的，产出 [PRD](./templates/PRD.md) 到 [spec/](./spec/README.md)；文件定位与上下文恢复由执行者负责。
- 需求流水线（先写文档再改）：按 [WORKFLOW §1](./WORKFLOW.md) 走 `/prd → /to-issues → 实现 → /ship-it`，提交前 `/review-it`。**PRD 未经作者确认前不改代码**，这是流水线唯一的强制闸门。
- 新系统：从 [SYSTEM 模板](./templates/SYSTEM.md) 开始，写进 `design/<系统名>.md`；方案论证：从 [DESIGN 模板](./templates/DESIGN.md) 开始，写进 `design/proposals/`；跨域取舍：从 [ADR 模板](./templates/ADR.md) 开始；拆条目：从 [issue 模板](./templates/ISSUE.md) 开始。体裁怎么选见 [ADR-0010](./decisions/ADR-0010-文档体裁与系统文档归位.md)。
- 进度不单独维护状态页：它就是 issue 文件里的验收勾选框。Git 负责变更历史，不在活文档追加流水账。
- 一个需求做完：结论写进 desc 或留下的系统文档，过程件删掉，台账那一行留一句话。准出见 [WORKFLOW §4](./WORKFLOW.md)。
- 改完文档后运行 `python tools/check_docs.py`，检查文件头、断链、归档边界、入口可达性、单一台账与工作区行尾；退出码非零表示存在必须修复的问题。**改动了仓里被上游约束引着的那一节之后它会报「引那一节的上游约束要复核」**（desc 不在仓里，引它的不钉）—— 核完跑 `python tools/check_docs.py --repin` 重录指纹（指纹在 `tools/upstream-pins.json`，进 git，所以「我看过了」留得下痕迹）。删一批文档之前先跑 `python tools/rewire_links.py <计划.json>`，把还活着的文档里指向它们的链接改掉（用法写在那个文件开头）。查看规模趋势用 `python tools/check_docs.py --report`（只打表、不判定）；行尾不合规用 `python tools/check_docs.py --fix-eol` 按 `.gitattributes` 改回来。
- 动了 `design/数值模型.md` 或 `design/numeric-model-params.json` 就跑 `python tools/simulate_week.py --check-doc`，它核对文档里的参数路径与**路径旁抄的数字**都与参数表没有分叉；不带参数跑则重算七天推演与全部平衡判据，并把文档里抄的**算出来的量**（战力差、还债天数这类）与本轮算的比一遍（条数由脚本自报，散文里不复述）。加 `--set 路径=值` 可以撞它的失败路径。
- 中文像素字体（[ADR-0008](./decisions/ADR-0008-中文像素字体选型.md)）：`python tools/audit_fonts.py` 核授权原文与上游字形来源、量字形覆盖与字宽行高；`python tools/font_preview.py` 把字渲进 Godot 看实机效果（可读性只能人判），两者都用 `--clean` 收尾。
- 本机 Godot 工具链：`python tools/setup_godot.py --check` 体检已装版本；升级用 `--version <版本号>`，下载、核对官方 SHA512、解压、装导出模板、跑 `--version` 自证一步做完；清理旧版本用 `--prune <版本号>`，默认只预演，加 `--yes` 才真删。版本基线见 [ADR-0005](./decisions/ADR-0005-技术基线.md)。
